## Списки

### 1. Противоречия

1. «Условия руками не пишутся» (`memory/layout.md:381`) и «`requires block.used > 0`» у `acquireSlot` (`memory/pointer.md:377`), `ensures result == null || (result.size >= size && …)` (`memory/pointer.md:106`), «У такого результата обязательны условия `size` и `alignment` в `ensures`» (`memory/pointer.md:552`).
2. «аннотаций нет» (о времени жизни, `memory/layout.md:318`) и `var key: read<layout.Keys> Int` (`memory/layout.md:127`), `struct ListCursor<Src: Origin>` с `read<Src>` (`memory/layout.md:660`), `-> external own self.slots.Item` (`memory/layout-algorithm.md:591`).
3. «время жизни, предусловия и постусловия функций компилятор выводит сам» (`memory/layout.md:7`) и «Блок `layout` описывает: … происхождение указателей и время их жизни» (`memory/addresses.md:55`).
4. «`Pointer` не дженерик: `Pointer<T>` нет» (`memory/pointer.md:47`) и «`fn allocate(size: Size<Type>) -> Pointer<Type> throws AllocationError`» (`memory/allocator.md:12`). Тот же `Pointer` «живёт только внутри `layout`» (`memory/pointer.md:11`), а контракт `Allocator` стоит вне `layout`.
5. «В обычной сборке ничего из этого нет: `lend` и `take` дают тот же машинный код, что и без проверки» (`memory/checking-build.md:68`) и «проверка границы у `lend` остаётся в программе» (`memory/pointer.md:254`); также «Обычная сборка проверяет заголовок найденного блока: вид, класс, `used > 0`…» (`memory/pointer.md:757`).
6. «Индекс доказан в границах или проверяется при выполнении» (`memory/layout.md:75`; таблица: «что не доказано — проверка при выполнении», `memory/layout.md:560`) и «безопасная функция, для которой FLOW не нашёл доказательства, отвергается» (`memory/layout-algorithm.md:12`), «недоказанное свойство блокирует компиляцию» (`memory/addresses.md:15`).
7. «Указатель на элемент другого множества или другого экземпляра — ошибка» (`memory/layout-algorithm.md:48`) и «Указатель из одного множества в другое объявлять особо не нужно: это обычный указатель» (`memory/layout.md:134`); `struct Edge { var to: Vertices.Item }` внутри множества `Edges` (`memory/layout-proofs.md:359`).
8. «пишущий аргумент (`mut`, `edit`, `out`) не пересекается ни с одним другим» (`memory/layout.md:570`) и `fn removeVertex(self: mut Self, v: mut Vertices.Item)` (`memory/layout-proofs.md:491`), где `v` — элемент множества внутри `Self`; в `memory/layout-algorithm.md:303` сказано, что вложенный доступ из `self: mut Self` второго права записи не создаёт, но два параметра в сигнатуре записаны отдельно.
9. «ссылка в Efen бывает только внутри функции» (`memory.md:231`; `memory/addresses-defects.md:325`) и «`mut Items.Item?`, `edit …`, `read …` (ссылка в результате): вызывающий получает доступ с этим правом» (`memory/layout-algorithm.md:592`); `models.md:83` ссылается на раздел «ссылка в результате типа функции».
10. «Межпоточная передача требует отдельной модели `shared`, которой здесь нет» (`memory/layout-algorithm.md:276`) и «Сегодня действуют правила общей памяти: … удержания … становятся областями доступа этого режима» (`memory/layout.md:634`; `models.md:55`); при этом `shared anchor` — «не продумано» (`memory/layout.md:627`).
11. «Объект без подсчёта ссылок владельца не добавляет: `box2` — второе имя того же объекта» (`memory.md:96`) и комментарий «Запрос владения» у `let box1 = Box(value: 10)` без счётчика (`memory.md:89`, `memory.md:108`).
12. «Физические описания (`set`, `one`, `area`, `struct Self`) остаются в аспекте representation; в `layout` класса они — ошибка» (`memory/layout.md:590`) и «`layout Name { ... }` задаёт область принадлежности … компоновка» с `set Particles: Particle from memory` внутри `layout World` (`representations.md:117`, `representations.md:140`); `representations.md:102` называет тот пример ненормативным, но блок `layout` в теле типа и блок `layout` в аспекте названы одним словом без разграничения.

### 2. Два способа записать одно

1. Выдача слота или куска: `lend block.slots[k]` (`memory/layout.md:394`), `lend block.bytes[a ..< b]` (`memory/pointer.md:454`), `take block.bytes[offset - LINE..]` (`memory/pointer.md:447`); слово `lend` ещё и заём части `Pointer` (`memory/pointer.md:688`), «относятся к `lend` у `Pointer`, не к выдаче слотов области» (`memory/pointer.md:458`) — одно слово, две операции с разными правилами.
2. Освобождение: `free(take n)` (`memory/layout-algorithm.md:118`), `Items.free(item: own Items.Item)` (`memory/addresses.md:227`), `e.free()` (`memory/layout-proofs.md:493`), `free(unlinkVertex(...))` (`memory/layout-proofs.md:458`); создание: `Items.new` и `Items.allocate` (`memory/layout-algorithm.md:95`).
3. Слот: «слот» (`memory/layout.md:57`), «ячейка» (`memory/addresses-defects.md:55`), `place` (`memory/addresses.md:449`), «место» в якоре `#цепочка-свободных-мест` (`memory/pointer.md:222`) и в тексте ссылки «место в результате функции» (`memory/layout-algorithm.md:592`), «строка/row» (`memory/columnar-layouts.md:131`).
4. Выбор представления: строка `representation SoA` в теле (`representations.md:17`); второй аргумент `Array<Particle, aos>` (`representations.md:55`); `use R<Element>` с `R<Target>: Representation<Target>` (`memory/addresses.md:66`); `aspect List<Target> { conforms Representation<Target> }` (`memory/addresses.md:88`); `storage columns for Particles { representation Columnar<Particle> }` (`memory/columnar-layouts.md:31`). В `representations.md:61` значение названо `form`, перечисление — `Representation` (`representations.md:42`), формы пишутся `aos` (`representations.md:43`) и `AoS` (`representations.md:33`).
5. Отношение между полями и `layout` класса: строки условий внутри `layout { … }` (`memory/layout.md:584`) и строка `invariants` в теле класса вне `layout` (`models.md:122`); раздел называется «Отношения в `invariants` класса», якорь — `отношения-в-layout-класса` (`models.md:95`, `models.md:97`).
6. Права: `read`/`write` (`memory/addresses.md:530`), `write`, `split write` (`memory/addresses-defects.md:264`, `:279`) против `read`/`edit`/`mut` (`memory/layout.md:595`); `mut` как право записи на область (`memory/layout-algorithm.md:75`) и `mut U` в поле `layout` как зависимость от внешнего объекта (`memory/layout.md:596`); `read` как невладеющий указатель (`memory/addresses.md:172`) и `read T` как удержание слота (`memory/layout.md:595`).
7. `own`: исключительная ссылка (`memory/layout.md:125`), перенос памяти между множествами (`memory/layout.md:282`), значение, забранное внешней стороной (`memory/layout.md:598`), `own other Items.Item?` с нигде не определённым `other` (`memory/addresses.md:145`), `external own` (`memory/layout-algorithm.md:69`).
8. `anchor`: поле-якорь (`memory/layout.md:128`), параметр/результат функции (`memory/layout.md:183`), `shared anchor` (`memory/layout.md:629`) и «якорь» как привязка origin в `memory/addresses-defects.md:349`.
9. `taken`: ghost-множество `x.taken` взятых слотов (`memory/pointer.md:336`) и «правая часть строки `taken`», `ensures throws E ==> taken(x)` — параметр забран (`models.md:26`, `models.md:36`).
10. «Проекция»: путь по полям `name.cString`, `.values` (`models.md:23`) и «проекция хранилища» (`representations.md:112`).
11. Проверки не из доказательства: «отладочная сборка» (`memory/pointer.md:366`, `:759`) и «проверочная сборка» (`memory/checking-build.md:6`); их связь прямо названа не закреплённой (`memory/checking-build.md:232`).
12. «Курсор»: итератор с объявленными частями (`memory/addresses.md:428`), структура `Cursor` с полем `current` внутри `layout` (`memory/layout.md:653`) и курсор раздачи `for e in Edges { e.free() }` (`memory/layout-proofs.md:492`).

### 3. Случаи без правила

1. Вызов с обоими аргументами, один из которых лежит внутри другого (правило `apart` и `mut Self`):
```efen
fn removeVertex(self: mut Self, v: mut Vertices.Item) { … }
g.removeVertex(v: g.first!)   // v внутри g: пересекаются ли self и v?
```
2. Вызов с правом `edit` у приёмника убивает ли ссылки: правило сказано только для `mut` («Вызов с правом `mut` убивает», `models.md:61`) и `read` (`models.md:62`):
```efen
edit fn reset(self)                 // у sqlite3_stmt
let e = db.errmsg                   // read<db.errmsg>
stmt.reset()                        // жива ли e?
```
3. `take` якоря через параметр `edit` (разобрано только `mut`, `memory/layout.md:179`):
```efen
fn rotate(top: edit Nodes.Item) { let p = take top.right!  top.right = take p.left }
```
4. Исключение из тела `for element in take region`, пойманное внутри тела (сказано: исключение — утечка, `memory/pointer.md:682`):
```efen
for element in take region {
    do { try fill(take element) } catch { /* element уже передан или нет? */ }
}
```
5. Индекс слота как значение, сохранённое в поле, после `reallocateArea` (разобран только локальный `let k`, `memory/layout.md:350`):
```efen
struct Self { var home: Int }
self.home = Keys.index(slot)
Keys.reallocateArea(count: 4)
print(Keys[self.home].key)
```
6. Корутина или `spawn` берёт указатель множества (`shared anchor` — «не продумано», `memory/layout.md:627`):
```efen
let n: Nodes.Item = list.head!
spawn { print(n.key) }
list.removeFirst()
```
7. Уничтожение коллекции, хранящей `external own`, без явного возврата (`memory/layout-algorithm.md:611` говорит про сохранение типа, не про уничтожение контейнера):
```efen
var held: Vector<external own pool.slots.Item> = []
held.append(pool.acquire())
// конец области: held уничтожается, release не вызван
```
8. Генератор с `yield edit` и вызов `mut` над источником в теле цикла (правила для `yield` нет в этих документах; есть лишь «курсор» `memory/addresses.md:428`):
```efen
fn rows(db: mut Db) -> generator edit Row { yield edit db.rows[0] }
for r in rows(db: db) { db.exec("DELETE …") }
```
9. Замыкание, кладущее удержание в поле, при том что у литерала замыкания модели нет (`models.md:19`), а значение-функция с удержанием не подходит ни к одному типу (`models.md:81`):
```efen
let f = { (s: read String) in self.cache[s] = s.cString }
register(f)
```
10. Два курсора по одному множеству, оба освобождают элементы (правило: освобождение через курсор этого перебора, `memory/layout-proofs.md:533`):
```efen
for a in Edges { for b in Edges { if a.to == b.from { b.free() } } }
```
11. `anchor`-результат, который вызывающий отбрасывает:
```efen
pop(list: list)          // -> anchor Nodes.Item?, результат не использован
```
12. Параметр `Pointer.Zeroed` и присваивание ему в одной ветви (`memory/pointer.md:560` говорит «нулей не несёт» после присваивания; слияние ветвей для состояний `Pointer` не описано):
```efen
fn f(m: own Pointer.Zeroed?, other: own Pointer) {
    var p = m
    if cond { p = other }
    use(p)               // нулевая ли память после слияния?
}
```
