# Списки

## 1. Противоречия

1. Ссылка в результате: вызов `mut` запрещён или гасит ссылку.
   - `glossary.md:68`: «Пока результат жив, структура источника не меняется»; `foreign.md:260`: «`epoll.add` и `epoll.remove(key)` во время обхода меняют структуру `epoll` и поэтому запрещены, пока жив курсор».
   - `foreign.md:392`: «`sqlite3_step` — `mut fn`, поэтому по общему правилу его вызов гасит ссылки от того же хендлера, и чтение строки после `step` — ошибка»; `foreign.md:398`: `st.sqlite3_step()` сам не помечен ошибкой, ошибка стоит на `echo text`; `context-and-effects.md:525`: «`store(...)` — `mut Env.cache`: entry умирает».
   - Первая группа: вызов с `mut` запрещён, пока ссылка жива. Вторая: вызов разрешён и убивает ссылку. Для одной и той же ссылки в результате обе схемы одновременно неверны.
2. `edit` и запись значения в слот.
   - `glossary.md:94`: «`edit fn` — запись значений с сохранением существующих слотов; `mut fn` — смена структуры».
   - `foreign.md:548`: на поле `foreign` «`edit` — ошибка. Буфер, который C перезаписывает, не переселяя, по общему правилу был бы записью значения»; при этом `foreign.md:526` пишет `in mut LibcThread.strerror` для той же перезаписи. По общему правилу из словаря это `edit`, но разрешён только `mut`.
3. Право `write`.
   - `structs.md:56`: «связывание располагает правом `write`».
   - `glossary.md:17`: «В исходном коде используются `read`, `edit`, `mut`, `out` и `own`»; `typestate.md:165`: «Параметр без `own`, `mut`, `edit` и `out` только читается». Права `write` нет в списке прав.
4. Права на поля контекста процесса.
   - `context-and-effects.md:650`: «права на эти поля в сводках, типах функций и интерфейсах не пишутся и не выводятся».
   - `foreign.md:527`–`528`: `in read LibcProcess.env`, `in mut LibcProcess.env` — права на поле контекста процесса пишутся и выводятся (поле `foreign`). Различие «поле Efen / поле `foreign`» стоит только в `glossary.md:48` и `context-and-effects.md:646`, правила 650 оно не оговаривает.
5. Откуда `Held` для корутины.
   - `typestate.md:362`: переход «отменяет прежние факты о его состоянии, которые держат другие участки кода»; `shared.md:1152`: «правило типов-состояний „переход рвёт чужие факты“ для осей блокировки не действует». Исключение оговорено в `shared.md` и в `typestate.md:374`, но общее правило `typestate.md:362` его не называет (сама строка `typestate.md:370`–`375` его даёт, так что противоречие формальное: правило и исключение разнесены на 8 строк).
6. Поле `shared`-структуры типа `shared readonly class`.
   - `shared.md:89`: поле допустимо, если оно «неизменяемое: `immutable T` или `shared readonly class`».
   - `shared.md:267` и `immutability.md:313`: без охраны читается только `let` типа `immutable T` или простого значения без кучи; `shared readonly class` в списке без охраны нет, а `shared.md:459` требует охрану для поля, которое пишет projection. Как читать `let` поле типа `shared readonly class` без охраны, оба места молчат (см. «Случаи без правила», 2).
7. `immutable` и `take` с живой ссылкой.
   - `immutability.md:94`: «обычный `take`, который живую ссылку сохраняет».
   - `glossary.md:103`: «`take` — … после которой исходный слот пуст либо недоступен». Ссылка на слот после `take` либо сохраняется, либо нет; словарь это не говорит. Ссылаются на `types/ownership.md`, который в мои файлы не входит.

## 2. Два способа записать одно

1. Условное владение деструктором: `disposable.md:79`–`91` пишет `ensures taken(self) == (result == SQLITE_OK)`; `foreign.md:343` пишет `self { result == SQLITE_OK ==> take }`; `foreign.md:254` пишет `item: own T? { result != null ==> take }`; `foreign.md:476` пишет `self { result == 0 ==> out }`. Один факт «владение перешло при таком результате» записан через `ensures taken(...)` и через фигурные скобки у параметра.
2. Право «писать»: `edit` (`glossary.md:17`), `write` (`structs.md:56`), «запись значений» (`glossary.md:94`).
3. Ссылка: `&x` и `&read x` (`glossary.md:67`), `read<x> T` в результате (`foreign.md:417`), `read<sql> CString?` в выходном параметре (`foreign.md:423`), `out read<sql>` как «ссылка на слот аргумента» (`foreign.md:450`), «удержание» в скобках `(Access<self> Cursor)` (`glossary.md:105`). Одна запись `read<x>` значит и ссылку в результате (источник — параметр), и ссылку, которую пишут в выходной слот.
4. Слово «указатель»: `T*` из C (`foreign.md:11`, «Что значит указатель»), невладеющий указатель `layout` (`glossary.md:70`), «Общее слово „указатель“ охватывает и владеющие формы» (`glossary.md:70`) против «`Pointer` … словом „указатель“ не называется» (`glossary.md:84`).
5. Слово «Flow/FLOW»: `flow { }` — монадический блок (`flow.md:5`, `glossary.md:47`); FLOW — анализ доступа, который «выводит из тела функции сводку» (`glossary.md:75`, `immutability.md:13`, `shared.md` и др.). Правил доступа в `flow.md` нет.
6. Одно право `mut`: смена структуры (`glossary.md:94`), право на перезапись внешнего буфера (`foreign.md:548`), «блокировка мьютекса» как `mut Pool` (`shared.md:31`), замена владеющего optional (`immutability.md:218`), запись/`take` целого `Job?` в ячейку (`shared.md:1097`).
7. Условие допуска к полям: `invariants { mutex is Mutex.Held }` у projection (`shared.md:28`), `{ state Lifecycle.Open }` у поля (`types/typestate.md:54`), `requires pool.mutex is Mutex.Free` (`shared.md:364`). Три формы для факта «ось в таком-то состоянии»; слово `invariants` у projection значит условие допуска, у структуры (`shared.md:889`) — инвариант значения.
8. «Неизменяемость»: `let` (перепривязка), `read` (запись через имя), `immutable T` (слот и значение), `readonly class` (внешние операции) — разнесены в `immutability.md:28`–`35`; поле `let` структуры (`structs.md:52`) и `let` в projection (`shared.md:267`) — разные: первое запрещает присваивание поля, второе ещё и позволяет читать без охраны только при `immutable T`.
9. Пометка «ждёт»: `in Suspending` / `in Blocking` у функции, `without Waiting` у функции или блока, `body without Waiting` у типа (`shared.md:336`, `shared.md:664`, `foreign.md:569`): `without Waiting` значит «убрать эффект из области» и, у функции C без тела, «обещание не ждать».
10. Состояние мьютекса: `Mutex.Held` и `Mutex.Lock.Held` (`shared.md:279`).

## 3. Случаи без правила

1. Ссылка на слот внутри `optional`, пока слот очищают присваиванием `null`:
   ```efen
   var name: String? = "a"
   let r = &name!          // ссылка на слот внутри optional
   name = null             // что с r?
   print(r)
   ```
   `types/optional.md` о ссылках не говорит; `immutability.md:218` называет замену владеющего optional правом `mut`, но не говорит, убивает ли она ссылку на содержимое.
2. `let` поле типа `shared readonly class` в `shared`-структуре без охраны:
   ```efen
   shared struct S { let text: Text   /* shared readonly class */ }
   fn f(s: read S) -> UInt64 { return s.text.hashValue() }
   ```
   `shared.md:89` допускает поле, `shared.md:267` и `immutability.md:313` читать без охраны разрешают другое.
3. `if let` и `guard let` над слотом, который не копируют:
   ```efen
   fn f(items: mut Vector<Item?>) {
       if let item = items[0] { items.append(null); print(item) }
   }
   ```
   `types/optional.md:139` говорит только «связывает значение с именем»: копия, перемещение или ссылка — не сказано; что с `item` после `items.append` — тоже.
4. `take` части замороженного значения через `readonly class` с `immutable` полем: `immutability.md:130` запрещает `take` части `immutable`, но не говорит, что для поля `let x: immutable T` внутри изменяемого класса.
5. `yield` в `flow generator` с правом на отдаваемое значение:
   ```efen
   flow generator rows(db: mut sqlite3) yield read String { yield db.name() }
   ```
   `flow.md:339` не называет роль `yield`; `flow generator` «пока не входит в язык» (`flow.md:330`).
6. Роль `Producer` передают в корутину через `take`, а владелец кольца пишет в `tail`:
   ```efen
   var ring = Ring(capacity: 64)
   let w = ring as Producer
   background { push(take w, job) }
   ring.tail.store(0)       // атомарный метод через имя владельца
   ```
   `shared.md:272` оставляет исходное имя доступным «для полей вне projection», но поле `tail` входит в `Producer`; про атомарную запись из владельца при живой роли правило не говорит.
7. `waitFor` в замыкании берёт `take` значения, захваченного по полям: `shared.md:535` запрещает `take` захваченного, но не говорит о `take` поля из `pool as PoolEditor` внутри `condition`.
8. `pthread_create` передаёт замыкание, которое захватывает `job: edit Job`, а `t` кладут в поле структуры:
   ```efen
   struct Worker { var t: Thread }
   var w = Worker(t: ...)      // t хранится как поле, а не локальная переменная
   ```
   `foreign.md:489` показывает удержание только для локальной переменной `t`; когда держатель — поле структуры, `foreign.md:763` («Не решено: удержания через поля структуры, которые пишет Efen») оставляет пометку `@fill`.
9. Ссылка из контекста потока в `shared layout` замыкании: `shared.md:161` и `context-and-effects.md:683` говорят «не захватывает», но не называют, что с ссылкой, полученной до `pthread_create` как `read<Scratch.buffer>`.
10. `edit` на поле структуры внутри `packed` через `as`: `foreign.md:117` запрещает `edit`/`mut` на поле `packed`, а `structs.md:282` разрешает приведение `as` между встроенными структурами; ссылка на целую встроенную структуру в `packed` не рассматривается.
11. Два `with` с одним мьютексом в одной корутине подряд в `waitFor` (`under`): `shared.md:512` проверяет тело как тело `with`, но вложенный `waitFor` другого мьютекса внутри замыкания не рассмотрен.
12. `readonly class` без `shared`, значение которого лежит в `immutable`-слоте: `immutability.md:73` запрещает заморозку `readonly class`, а `immutability.md:314` допускает его в многопоточной корутине «по FLOW»; для значения, полученного `copy` из замороженного, правило не говорит, какая сводка действует.
