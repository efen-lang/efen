# Наблюдаемость: модель и решения

Статус: проект, ноябрь 2026. В нормативную документацию не перенесён. Весь синтаксис ниже — предложение в
существующих формах языка: `optional contract`, `provide`, `mode`, атрибуты и метафункции, секции конфигурации.
Решения Эдмонда отмечены в разделе [«Решения»](#решения); остальное — проект, разобранный с критиком.

## Идея

В программе одно действие наблюдения: **место в коде сообщает о себе с полями**. Спан — место со входом и
выходом. Событие (лог) — место без длительности. Метрика — подсчёт, встроенный в место. Что можно показать в
телеметрии, решает тип значения.

Отсюда:

- один эффект `Observer` вместо отдельных `Trace`, `Log`, `Metrics`;
- метрики объявляются на месте, а не вызываются из тела;
- кардинальность метрик и утечка секретов проверяются при сборке;
- каталог всей телеметрии программы — выход сборки;
- без реализации `Observer` в программе нет ни одного вызова.

## Слои

```text
файлы lang::  →  ядро observe  →  слой lang рантайма  →  mm  →  остальной рантайм  →  std
```

Ядро `observe` — отдельная библиотека, не часть языка. Оно опирается только на файлы `lang::` и лежит ниже
слоя `lang` рантайма, поэтому сообщать о себе могут все: ловушки и `System`, `mm`, асинхронный рантайм, std,
приложение. У каждого слоя свой словарь мест, общий только канал. В ядре только объявления и постоянные данные:
имена полей — константы, которые строит метакод; часы и идентификаторы спанов даёт реализация. Метафункции,
разбор `traceparent` и экспортёры лежат в std и пакетах.

## Эффект `Observer`

```efen
public transparent optional contract Observer {
    fn enter(site: Site, fields: Fields) nofail
    fn event(site: Site, fields: Fields) nofail
    fn exit(site: Site, outcome: Outcome) nofail
}
```

- Поля, известные к концу операции (код ответа, число строк), добавляются к текущему спану (`annotate`
  или поля в `exit`; форма не выбрана).
- `Outcome` — исход только для чтения: вернула, бросила (с проверкой `is E`), отменена, брошена (генератор);
  у блока вместо «вернула» — «завершён».
- Связи спанов — поле вида `TraceContext` на входе.

### Прозрачные необязательные контракты

Изменение языка (решение 5).

- Требование `nothrows` у методов `optional contract` убирается: необязательный контракт объявляет
  исключения, как любой контракт. Пример — `Audit`, который бросает `AuditError`.
- Контракт, чьи методы `nofail`, без результата и без записи в параметры, — **прозрачный** (рабочее слово
  `transparent`, компилятор проверяет условия). Его требование не входит в тип функций и замыканий и не
  проверяется `isolated`. Компилятор знает его по всему дереву вызовов во внутренней сводке: для стирания при
  `null`, проверки рекурсии и каталога.
- Непрозрачный необязательный контракт ведёт себя как обычный эффект.
- Явный запрет — `without Observer` у функции или блока: по всему дереву вызовов нет мест наблюдения.
- Не связанный необязательный контракт означает `null`: вызовы стираются, аргументы не вычисляются.
  Побочное действие в аргументах прозрачного контракта — ошибка.
- `Observer` связывает только программа (`provide`) или тестовый фреймворк; `@default` для `Observer` —
  ошибка, иначе транзитивная зависимость включила бы вывод телеметрии наружу.
- Прецеденты в документации: `AssertionError` и `ConditionError` не входят в сводку ([throws.md](../docs/efen/throws.md),
  правила 7 и 9); счётчик в контексте процесса не меняет сигнатур
  ([контекст процесса](../docs/efen/context-and-effects.md#контекст-процесса--общая-память)).

### Несколько реализаций

`Observer` связывается по обычным правилам: секция пакета в `provide` допустима. Условия:

1. решение о выборке трассы принимается один раз, при корневом входе, и хранится флагом в `TraceContext`;
   хвостовую выборку делает внешний коллектор;
2. рекурсия проверяется по графу всех связываний;
3. у программы есть общий реестр реализаций для флагов, `flush` и записи аварии.

## Место в коде

```efen
public struct Site {
    let kind: SiteKind        // span, event
    let level: Level          // trace … fatal
    let name: String          // "checkout" или шаблон "charged {amount}"
    let role: SpanRole        // server, client, producer, consumer, internal
    let origin: Origin        // пакет, версия, модуль: знает компилятор
    let file: String
    let line: Int
}
```

`Site` строит метакод из `location` и конфигурации пакета. Шаблон сообщения отделён от значений при сборке:
`"charged ${amount}"` даёт шаблон `"charged {amount}"` и поле `amount`. Поля вычисляются только тогда, когда
событие записывается. Имя поля берётся из текста выражения, если это путь; для другого выражения имя
обязательно (`user: session.userId`).

## Что можно наблюдать

- `Observable` — значение можно записать в поле. Примитивы получают соответствие от ядра, любой `enum` — от
  компилятора, как `ImplicitlyCopyable`. Тип задаёт свою проекцию сам (`Order` → `order.id`, `order.region`).
  `Secret<T>` не соответствует `Observable` и в телеметрию не попадает. `String` наблюдаем, поэтому строка с
  секретом нуждается в отдельной пометке.
- `Dimension` — значение можно сделать измерением метрики. Автоматически получает закрытый `enum` и `Bool`;
  уточнённые типы пока нет. Бюджет кардинальности (произведение измерений) считается при сборке программы.
  Для `open enum`, динамической линковки и библиотек для C — ячейка «other».

## Метрики

```efen
@observe::span(order)
@observe::latency(by: order.region)
@observe::count(by: order.region, when: .ok)
@observe::count(when: .failed(PaymentError))
fn checkout(order: Order) -> Receipt throws PaymentError { … }

fn refund(order: Order) {
    observe::count("order.refunded", by: order.region)   // счётчик посреди кода
    observe::event("order.refunded", order)              // событие — отдельно, если нужно
}
```

- Каждый атрибут метрики встраивает свой подсчёт в выход места. Ячейки — полосы атомарных ячеек в контексте
  процесса; экспоненциальная гистограмма OTel.
- `by: order.id` — ошибка: `OrderId` не `Dimension`. `when: .failed(E)` проверяется по `throws` функции.
- Метрики не зависят от выборки трасс и от флагов: у метрик нет уровней и флагов.
- Мгновенные значения — функция с `@observe::gauge`, реализация находит их через `collect`.
- Цена latency — два чтения часов на вызов; часы — неждущий пункт рантайма.
- Метрики в отдельном файле (`observe::latency(of: checkout)`) отложены: нужен реестр времени сборки.

## Конфигурация

```efen
config server {
    provide {
        Observer: otlp::Exporter
    }

    observe {
        spans: true
        events: true
        metrics: true
        keep {                     // что вкомпилировать
            shop: .info
            "std::net": .debug
            mm: .off
        }
        live {                     // что включено с запуска
            "std::net": .info
        }
    }

    mode testing {
        provide {
            Observer: observe_test::Recorder
        }
    }
}
```

- `spans`, `events`, `metrics` включаются независимо; по умолчанию включены, если `Observer` связан.
  `spans: false` убирает только `enter` и `exit`: приём и передача `traceparent` и заполнение слова корутины
  входящим контекстом работают, пока `Observer` связан, поэтому события сохраняют `trace_id`.
- `keep` — порог сборки: места ниже не порождаются. Уровни действуют на спаны и события; `.off` выключает
  у пакета всё, включая метрики.
- `live` — что включено с запуска. Место на уровне `live` и выше включено всегда, без флага. Место между
  `live` и `keep` получает флаг. Нет `live` — нет флагов (умолчание во всех режимах).
- Метакод пакета читает свою секцию конфигурации. Пакет пересобирается, если изменилась влияющая на него
  часть: связан ли `Observer`, его `keep`, зона флагов, переключатели сигналов.

## Флаги мест

- Флаг — байт в плотном изменяемом массиве; `Site` остаётся постоянным. Метакод порождает встроенную
  проверку `observe::enabled(site)`, чтобы механизм можно было сменить (например, на замену инструкции).
- Флаги есть у событий и внутренних спанов. У спана флаг читается один раз на входе.
- Список всех мест строит компилятор при сборке программы тем же механизмом, что `collect`; раздел
  линковщика — способ реализации. Регистрации при старте нет. Список нужен только флагам и метрикам.
- Флаги меняют переменная окружения при старте и сама реализация `Observer`.

## Контекст трассы

- Текущий спан хранится в слове корутины; у потока без корутин слово одно, как слот провала `assert`.
- `Scope` с контекстом появляется вместе с группой задач (`makeTaskGroup`) и даёт корутинам наследование:
  родитель новой корутины — текущий спан создателя в момент `spawn`. Корневого `Scope` нет, и он не нужен.
- Трасса привязана к контексту `Scope`: все корутины запроса принадлежат его трассе, идентификатор трассы
  общий.
- Генератор: родитель берётся при `start()`, слово меняется на каждом возобновлении, включая очистку.
- Чтение спана не добавляет требование `in`.

## Вход и выход функции

Один примитив компилятора — входной и выходной участок функции или блока. Им пользуются метакод атрибутов и
проход E. У примитива есть служебная печатная форма в `efen::`, чтобы `amber expand` печатал его, а ядро
разбирало как обычный код. Пользовательский `defer` с исходом можно добавить позже на том же примитиве.

- Входной участок может объявить скрытые локальные (время старта); выходной видит только их, не параметры.
- Оба участка `nofail`; выходной выполняется только после завершённого входного. Изменить исход, бросить,
  поймать, вернуть участок не может. Трассу стека не читает.
- Выход: тело, все `defer`, `ensures`, участки E, участки атрибутов снизу вверх. Верхний атрибут — внешний.
  E видит тело, заменённое атрибутом, но не вставляет код в сами участки.
- Эффекты участков сверяются с ограничениями функции; несовместимый атрибут — ошибка у атрибута.
- Атрибут, который ломает хвостовой вызов, даёт предупреждение.
- `requires` проверяется у вызывающего ([условия](../docs/efen/conditions.md#обычная-сборка-и-диагностики)),
  поэтому входной участок стоит после проверки, в том числе у `@abi(c)`. Нарушение видно в спане вызывающего
  событием с местом вызова; `ConditionError` и запись аварии несут `Site` вызываемой функции.
- Нарушение `ensures` с исходом `observe` (сейчас только `Trap.observe` в stderr) дублируется событием в
  `Observer`.

## Авария

Непойманное исключение в главном потоке останавливает программу до раскрутки, выходные участки не
выполняются. Перед `UncaughtHandler` и `Trap` рантайм вызывает одну процедуру ядра `observe`:

- снимок — слово текущей корутины (через указатель в `static thread context`) и указатели на кольцевые
  буферы, которые реализации зарегистрировали заранее (атомарно, с фиксированным пределом числа буферов);
- приёмник — сегмент общей памяти или отображённый файл, который коллектор читает после смерти процесса;
- атомарный флаг повторного входа; без выделения памяти, без блокировок, ограниченная глубина стека;
- родители текущего спана остаются открытыми, экспортёр или коллектор помечает их прерванными.

Пока в компиляторе нет анализа `Allocates` и оценки глубины стека: тест запускает отдельный процесс с
настоящими `UncaughtHandler` и `Trap` и читает сегмент; в тестовой сборке выделение памяти при поднятом
флаге аварии останавливает программу; на запасном стеке — сторожевая страница.

## Память и рекурсия

- У `mm` есть входы без наблюдения; `mm` сообщает о себе только после завершения операции и снятия
  блокировок.
- Реализация `Observer` объявлена `without Observer`; её типы получают память через стратегию аллокатора
  поверх входов без наблюдения.
- Экспортёр внутри процесса пишет только локально через `System` (сокет на localhost, кольцо в общей памяти,
  файл). TLS, повторы и отправку наружу делает отдельный процесс-коллектор.
- Реализация не ждёт (`without Waiting`).

## Каталог телеметрии

Плагин вида F пишет схему всех мест, полей с типами и метрик программы. CI сравнивает её с прошлым выпуском:
удалённая метрика или поле со сменённым типом видны в ревью. Из схемы строятся дашборды, алерты и
документация; те же места можно отдавать как точки USDT.

## Решения

1. Ядро `observe` — отдельная библиотека ниже слоя `lang` рантайма, не `lang::` и не std.
2. Любой `enum` получает `Observable` и `Dimension` от компилятора; примитивы — `Observable` от ядра.
3. Метрики — отдельные атрибуты на месте; посреди кода — метафункция `observe::count`.
4. Метакод пакета читает свою секцию конфигурации.
5. `nothrows` у `optional contract` больше не требуется; прозрачные необязательные контракты не входят в
   типы функций и замыканий и в `isolated`; `Observer` — прозрачный, методы `nofail`.
6. Память и рекурсия: входы без наблюдения у `mm`, `without Observer` у реализации.
7. Не связанный необязательный контракт — `null`.
8. Трасса привязана к контексту `Scope`; текущий спан — в слове корутины; корневого `Scope` нет.
9. Метакод просит компилятор вставить участки на вход и выход функции.
10. Пакет пересобирается при изменении влияющей на него части конфигурации.
11. Два порога `keep` и `live`; флаг — опция, флаги только в зазоре.
12. Несколько реализаций `Observer` при трёх условиях.
13. Порядок участков: атрибуты снаружи, проходы E внутри (решение Fable по поручению Эдмонда).

## Открыто

- Форма полей, известных к концу операции: `annotate` или поля в `exit`.
- Пометка чувствительности для строк.
- Метрики в отдельном файле через реестр времени сборки.
- Флаг на одну трассу (состояние «спроси контекст»), буфер трассы с ошибкой, диагностический канал (отдельным
  пакетом, со сроком жизни включения и записью изменений), замена инструкций вместо байта.
- Правки в документации: «Пустое связывание» и «Гарантии этапа компиляции» в
  [context-and-effects.md](../docs/efen/context-and-effects.md), «Секции плагинов» в
  [build-config.md](../docs/efen/build-config.md), «Два уровня» в
  [compile-time/plugins.md](../docs/efen/compile-time/plugins.md), «Кто побеждает» (пакет пересобирается по
  конфигурации), точки E в [compiler-plugins.md](../docs/efen/compile-time/compiler-plugins.md).
- Риски: путь аварии требует анализов, которых в Amber нет; цена флагов, часов и ячеек не измерена на
  прототипе.
