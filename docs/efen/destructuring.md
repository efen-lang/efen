# Деструктуризация в Efen

## Концепция

Деструктуризация записывается той же формой, что и образец в `match`.
Разбор по именам полей идёт через [оператор проекции `.{ }`](types/projection.md),
кортеж по позиции — через круглые скобки.

```efen
let Point.{ x, y } = p
let .{ x, y } = p
let .{ x, y: py } = p
let (x, _) = pair
```

Имя типа перед `.{ }` ограничивает разбор этим типом. Без имени тип берётся из
выражения справа.

---

## Общие правила

1. Внутри `.{ }` поля перечисляются по именам, а не по позиции.
2. Запись `поле: имя` связывает поле с другим именем.
3. Круглые скобки разбирают кортеж по позиции.
4. `_` обозначает игнорируемое значение.
5. Связывает только `let`. В позициях объявления — `let`, `if let`, `while let` и
   образец между `for` и `in` — связываются все голые имена образца, и внутри него
   `let` не пишется. В образце `match` и `is` `let` ставится перед именем, которое
   связывается, а голое имя сравнивается со значением, которое это имя уже имеет.
6. В `let` справа должно находиться выражение, возвращающее значение
   разбираемого типа.
7. Несовпадение образца вызывает ошибку сопоставления (`MatchError`).

## Примеры

### Структуры

```efen
struct Point {
    var x: Int
    var y: Int
}

let p = Point(x: 10, y: 20)

let Point.{ x, y } = p   // тип указан явно
let .{ x, y } = p        // тип выводится из p
let .{ x, y: py } = p    // поле y связывается с именем py
```

---

### Кортежи

```efen
let pair = (10, 20)
let (x, y) = pair

let person = (name: "Alice", age: 30)
let (name, age) = person     // по позиции
let .{ name, age } = person  // по именам элементов
```

Именованный кортеж разбирается обеими формами; безымянный — только круглыми
скобками.

---

### Enum / Variant

Вариант enum в образце пишется с точкой, его поля — оператором проекции `.{ }`:

```efen
enum Result<T, E> {
    ok { value: T }
    err { error: E }
}

match result {
    .ok.{ let value }: log(value)
    .err.{ let error }: report(error)
}
```

Ненужные поля варианта можно опустить:

```efen
match result {
    .err.{ let error }: report(error)
    .ok: log("Успешно")
}
```

---

### Вложенные образцы

Значением поля может быть другой образец:

```efen
enum Response {
    ok { user: User }
    err { message: String }
}

match response {
    .ok.{ user: User.{ let name } }: greet(name)
    .err.{ let message }: log(message)
}
```

---

### Деструктуризация с пропуском полей

```efen
let (x, _) = getPosition()
```

Подчёркивание обозначает «игнорируемое значение».

---

### Деструктуризация в `for`

Элемент коллекции разбирается тем же образцом. Образец между `for` и `in` —
позиция объявления, поэтому голые имена в нём связывают и `let` не пишется:

```efen
for Point.{ x, y } in points {
    echo "(${x}, ${y})"
}
```

---

## Семантика

- Образец компилируется в проверку соответствия и извлечение полей.
- В образце `.{ }` перечисляет поля и связывает копии их значений. Представления,
  в отличие от [проекции](types/projection.md), он не создаёт: последующая запись
  в источник связанные имена не меняет.
- Все имена, связанные образцом, видимы в текущем блоке.
- Для варианта enum сначала проверяется имя варианта, затем его поля.
- Вложенные образцы раскрываются снаружи внутрь.

---

## Преимущества

- Одна форма для `let`, `match` и `for`.
- Поля разбираются по именам, поэтому порядок их объявления на разбор не влияет.
- Форма образца не конфликтует с типовыми аннотациями `x: Type`.
