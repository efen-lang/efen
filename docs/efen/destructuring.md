# Деструктуризация в Efen

## Концепция

`Efen` использует форму `Type pattern -> pattern` для деструктуризации значений.  
Стрелка отражает направление данных: тип распаковывается в переменные.

```efen
let Point -> x, y
let Point -> x, y = getPosition()
```

Такой синтаксис однозначно показывает, что `Point` — это источник структуры данных,  
а `x` и `y` — получатели значений его полей.

---

## Общие правила

1. `Type pattern ->` всегда обозначает деструктуризацию структуры, записи или variant-типа.
2. После стрелки указываются имена полей или подшаблоны.
3. В `let` справа должно находиться выражение, возвращающее значение указанного типа.
4. Несовпадение шаблона вызывает ошибку сопоставления (`MatchError`).

## Type pattern

Выражение type pattern может быть паттерном структуры данных, например:
```efen
(Int, Float, String) -> x, y, z
```

либо

```efen
User(Setting, Y) -> x, y, z
```

## Примеры

### Простая деструктуризация
```efen
let Point -> x, y = getPosition()
```

---

### Enum / Variant
```efen
match result {
    case Ok -> value
        log(value)
    case Err -> error
        report(error)
}
```

---

### Вложенные шаблоны
```efen
match response {
    case Response -> Ok -> user
        greet(user)
    case Response -> Err -> msg
        log(msg)
}
```

---

### Деструктуризация с пропуском полей
```efen
let Point -> x, _ = getPosition()
```
Подчёркивание обозначает «игнорируемое значение».

---

## Семантика

- `Type ->` компилируется в проверку соответствия и распаковку полей типа.
- Все переменные после стрелки становятся видимыми в текущем блоке.
- В случае variant-типа стрелка автоматически сопоставляет конструктор по имени.
- Вложенные формы (`A -> B -> C`) раскрываются слева направо.

---

## Преимущества

- Единообразный и легко читаемый синтаксис для `let`, `match`, `case` и `for`.
- Направление данных интуитивно: «тип → переменные».
- Упрощённая грамматика: `Type '->' pattern-list`.
- Не конфликтует с типовыми аннотациями и обычными `x: Type`.
