# Неизменяемость: `immutable` и `readonly class`

[Документация](README.md) · [Контракты](contracts.md) · [Runtime языка Efen](runtime/README.md) · [Память](memory/README.md) · [Правила доступа к памяти](memory/memory-rules.md)

В Efen различаются глубокая неизменяемость значения и запрет изменять объект
через его внешние операции:

- **`immutable T`** — свойство слота. Значение в слоте и всё, до чего оно достаёт, не меняется ни на один байт с
  момента заморозки до уничтожения. Компилятор проверяет это полностью. Такое значение отдают любому потоку без
  доказательства.
- **`readonly class`** — свойство класса. Открытые операции класса не позволяют изменять его доступные снаружи данные.
  Внутри у него может быть скрытое состояние (кэш, ленивая инициализация), которое меняют его собственные методы.
  Безопасность между потоками доказывает FLOW для каждого использования или проверяет у типа `shared readonly class`.

`let` запрещает только перепривязку имени ([владение](types/ownership.md#слоты-и-связывания)), право `read` — только
запись через это имя. Ни то, ни другое не мешает писать владельцу:

```efen
var hosts = Vector<String>()
let snapshot = hosts            // псевдоним того же вектора
hosts.append("backup")          // владелец пишет; поток, читающий snapshot, видит гонку
```

Слово `readonly` на слот не ставится, слово `immutable` у объявления класса не пишется. Состояние «только чтение»
у объекта, который до того менялся, выражает [состояния типов](types/typestate.md): изменяющие методы требуют состояние, из
которого объект выходит переходом.

## Что гарантируют разные формы

| Форма | Гарантия |
|---|---|
| `let` | Имя нельзя перепривязать к другому значению |
| `read` | Через этот доступ нельзя записывать данные |
| `readonly class` | Доступные снаружи операции сохраняют данные внешней части; внутри возможно скрытое изменение |
| `immutable T` | Неизменяемо само значение и всё, до чего оно достаёт, с момента заморозки до уничтожения |

## Термины

- **Запись в значение** — изменение памяти, которой значение владеет или до которой достаёт: присваивание поля,
  метод с `edit`, `mut` или `own self`, операция `layout`, которая пишет память, изменение счётчика.
- **Заморозка** — момент, когда значение попадает в слот `immutable T`. Обратного пути нет.
- **Скрытое состояние** `readonly class` — его поля `var` с видимостью `private` или `protected` без `family`
  ([видимость](visibility.md)) и всё, чем они владеют.
- **Внешняя часть** `readonly class` — остальные члены: поля `let` любой видимости, поля `var` с видимостью `public`,
  `internal` и `family`, методы без `private` и `protected`. Метод `private` или `protected` — скрытый помощник: он
  может писать скрытое состояние, и правила внешней части (1, 3, 4) к нему не применяются.
- **Метка метода** — право, которое видит вызывающий. **Настоящая сводка** — что метод на самом деле читает и пишет,
  включая скрытое состояние.

## `immutable T`

### Какие типы замораживаются

Тип допускает заморозку — вычисляемый контракт `Freezable`
([встроенные контракты](runtime/built-in-contracts.md#freezable)), — если в нём нет поля, элемента, захвата или поля
`layout`:

| Что внутри | Почему |
|---|---|
| `shared`-тип, атомарный тип | его смысл — запись |
| `managed` слот, объект класса со счётчиком, `readonly class` | владельцы снаружи или скрытое состояние |
| буфер с копированием при записи со счётчиком | неявная копия меняет счётчик |
| тип `ThreadBound` | его нельзя трогать из другого потока |
| заимствование, зависимость, поле с `Src: Origin` | источник пишут снаружи |
| значение функционального типа | захваты не видны в типе функции |
| значение над внешним кодом без строки доверия, `shared layout` | запись во внешнем коде компилятор не видит |
| операция `layout`, `copy` или неявная копия, которая пишет память | запись при чтении; проверяется по сводке |
| коллекция из `layout`, тип элемента которой не `ImplicitlyDestroyable` | владелец не смог бы её уничтожить: `dispose` такой коллекции компилятор не вызывает, а забрать элементы у замороженного значения нельзя |

Значение структуры из `layout` заморозке не мешает: отдельным значением хранится только публичная структура, а она
чиста ([публичная структура](memory/layout/owners.md#публичная-структура)). Значение с источником в типе
(`Vector<read<g> Vertices.Item>`) хранит заимствование и не замораживается по строке таблицы о заимствованиях.

Соответствие вычисляется, как у `ThreadBound`, строку не пишут. Поле `var` не мешает: в замороженном значении его не
пишут, как `let`.

Класс замораживается так же, как структура. Не замораживаются класс со счётчиком, открытый класс и его наследники,
`readonly class` (его объявление разрешает добавить скрытое поле в следующей версии) и класс над внешним значением
без строки доверия.

```efen
class Config {
    let hosts: Vector<String>                    // память вектора освобождает его dispose, и у замороженного Config
    let timeout: Int
}

var draft = Config(hosts: take names, timeout: 30)
let config: immutable Config = take draft
```

### Точки заморозки

Значение замораживается ровно в одной из трёх точек.

1. **Новое значение** — результат конструктора, литерала или `copy`, положенный в слот `immutable T`. Пока значение
   строится, его пишут свободно; источник `copy` только читается. `clone` точкой заморозки не бывает: клон делит
   кучу с изменяемым источником.
2. **`take` от единственного владельца** — `take x` из `own T` в `immutable T`. Это отдельное событие FLOW, сильнее
   обычного `take`, который живую ссылку сохраняет ([неизменяемый слот](types/ownership.md#неизменяемый-слот-immutable-t)):
   - ошибка, если жива структура, которая заимствует `x` или его часть;
   - ошибка, если `x` или его часть видит живая корутина, `background`, `offload` или объект `shared layout`;
   - ссылки, псевдонимы, ссылки в результатах и итераторы самой функции, которые начинаются в `x`, кончаются;
     обращение к ним после заморозки — ошибка.
3. **`const`** — значение, вычисленное при сборке. Его тип — `immutable T`, слово не пишется.

```efen
var hosts = Vector<String>()
hosts.append("primary")
let first = &hosts
let frozenHosts: immutable Vector<String> = take hosts
first.append("x")                            // ошибка: ссылка first кончилась при заморозке

with makeLocalTasks() {
    background { names.append("late") }
    let frozen: immutable Vector<String> = take names   // ошибка: names видит живая корутина
}
```

`immutable T` к `T` не приводится. Изменяемое значение получают копией: `copy` замороженного значения даёт `own T`.
Изменённая копия пишется тремя строками:

```efen
var draft = copy config
draft.timeout = 60
let next: immutable Config = take draft
```

### Что разрешено через замороженное значение

- Чтение поля, элемента, вызов метода с `read self`.
- **Путь через `immutable` — тоже `immutable`.** `config.hosts` имеет тип `immutable Vector<String>`, его элемент —
  `immutable String`. Ссылка, которую возвращает `read fn` с источником `self`, тоже `immutable`.
- Копия простого значения без кучи (`ImplicitlyCopyable`) теряет `immutable`: `var limit = config.timeout` — `Int`.
- `take` всего значения в другой слот `immutable T`. `take` части — ошибка.
- Уничтожение. Владелец `own immutable T` уничтожает значение и вызывает роль деструктора, в том числе `explicit`,
  когда FLOW доказал, что заимствований нет. Других `own` методов у замороженного значения нет.
- У структуры из `layout` деструктора нет. Её память освобождает компилятор (план и `dispose`): у
  замороженной коллекции там же, где у незамороженной, в том числе когда коллекция хранится в поле замороженного
  объекта ([освобождение структуры](disposable.md#освобождение-структуры-disposable)).

Запрещено: присваивание поля, метод с `edit`, `mut` или `own self` (кроме деструктора), заимствование `edit` и
`mut`, аргумент `out`.

### Слот и значение

`immutable` — свойство значения в слоте. Слот `var` типа `immutable T` перезаписывают целиком другим замороженным
значением, старое уничтожается:

```efen
var current: immutable RouteTable = loadDefaults()
current = take nextTable                     // замена целиком
current.routes.append(take route)            // ошибка: current.routes — immutable Vector<Route>

var names = Vector<immutable String>()       // вектор растёт, каждая строка заморожена
names.append(take line)
names[0].append("!")                         // ошибка: names[0] — immutable String
```

В `shared`-структуре слот `var` читают и меняют под охраной; без охраны читают только поле `let`.

<a id="параметры-и-generic"></a>

### Параметры обобщённых объявлений

- `own immutable T` — принять замороженное значение во владение. Одолженный параметр `immutable T` — диагностика
  стиля `S`: одолженный параметр и так только читается; каноническая запись — `T`, она принимает и `immutable T`.
- Тело с `immutable T` получает в сводку требование «`T` допускает заморозку»; тело, которое пишет значение `T`, —
  «`T` не `immutable`». Оба проверяет инстанциация, как «`T` не `ThreadBound`».
- Параметры контейнеров инвариантны относительно `immutable`: `Vector<immutable String>` не передаётся как `mut Vector<String>`.
  Снять `immutable` можно только внешним одалживанием на чтение.

### Потоки

`immutable T` отдают любому потоку без дополнительного доказательства совместимости доступов, заимствованием или владением, и кладут в контекст процесса.
Замороженную чистую структуру из `layout` читают из любого потока. Заморозка сама память не синхронизирует: другой поток видит значение через канал, который синхронизирует (запуск
корутины, мьютекс, флаг ленивого контекста процесса, публикация в std).

Значение, которое строят во время работы и публикуют всем потокам один раз, кладут в `shared`-тип std с однократной
записью в поле контекста процесса. Ленивый контекст процесса сам файл не прочитает: его начальное значение не ждёт и
не бросает ([контексты](context-and-effects.md#контексты-процесса-и-потока)).

### Внешние значения

Класс над внешним значением (C, `@asm`, бинарный пакет) замораживается, только если объявил строку
`conforms Freezable`. Компилятор её не проверяет: это точка доверия, как [`assume`](conditions.md). Пакет с ней
становится рискованным, а `efen proofs` показывает её как место без дополнительного доказательства совместимости доступов.

```efen
@abi(c) class FrozenExternalData {
    conforms Freezable  // гарантию глубокой неизменяемости даёт автор внешнего типа
}
```

Это условный пример внешнего типа. Соответствие допустимо только при наличии
гарантии, что внешняя реализация не изменяет ни само значение, ни достижимые
через него данные после заморозки.

У типа на Efen строка `conforms Freezable` не пишется: соответствие вычисляется.

## `readonly class`

### Правила объявления

```efen
readonly class Regex {
    let pattern: immutable String
    private var program: Program?

    fn find(text: String) -> Match? {        // метка read; настоящая сводка пишет program
        compileIfNeeded()
        return program!.run(text)            // Match — значение, не ссылка в program
    }

    private mut fn compileIfNeeded {
        if program == null { program = Program(pattern) }
    }
}
```

1. **Данные внешней части доступны только для чтения.** Поле внешней части — `let` типа `immutable T`, `shared`-типа или простого
   значения без кучи. Метод внешней части, который пишет поле внешней части или делает переход состояния, — ошибка.
   Метод внешней части с `edit`, `mut` или `own`, кроме конструктора и деструктора, — ошибка.
2. **Одна настоящая сводка, одна метка.** Компилятор вычисляет сводку каждого метода, как для параметра `mut`: пути
   от `self` и вид доступа у каждого. Метод внешней части, который пишет только скрытое состояние, получает метку
   `read`. Вид записи скрытого поля — по обычным правилам: замена владеющего опционального значения — `mut`.
3. **Наружу значения, не ссылки.** Результат метода внешней части не бывает ссылкой в скрытое состояние: ни итератором,
   ни срезом, ни структурой с `Src`, которая указывает в скрытое поле. Ссылка на поле внешней части допустима.
4. **Без повторного входа.** Пока метод держит ссылку на скрытое поле, он не вызывает значений-функций, колбэков,
   методов интерфейсов и контрактов, `open` методов и методов внешней части объектов этого класса.
5. **Внутри модуля — настоящая сводка, снаружи — метка.** Проверки внутри модуля класса идут по настоящей сводке.
   Снаружи в одном потоке достаточно метки: правила 3 и 4 гарантируют, что вызывающий не держит ничего, что скрытая
   запись может испортить.
6. **Заимствования и эффекты не скрываются.** Скрытой бывает только запись в память самого объекта.
7. **Иерархия.** `readonly` пишет корень; наследник его не повторяет и проверяется по тем же правилам. Наследник
   обычного класса `readonly` не бывает.
8. `readonly class` не реализует `Disposable`, не объявляет публичный переход состояния и не имеет `shared layout`.

```efen
readonly class Journal {
    let lines: Vector<String>                // ошибка: поле внешней части не immutable
    var count: Int                           // ошибка: поле внешней части var
    edit fn reset { count = 0 }              // ошибка: изменяющий метод внешней части
    private var entries: Vector<Entry>
    fn first -> read Entry? {                // ошибка: ссылка на скрытое поле entries
        return &entries[0]
    }
}
```

### Потоки: доказательство FLOW

`readonly class` сам по себе потокам ничего не разрешает. Когда объект виден из нескольких потоков (многопоточная
корутина, `offload`, поле `shared`, контекст процесса), FLOW применяет таблицу многопоточного вида
([области доступа](types/access-regions.md#корутины-spawn)) к настоящим сводкам методов, которые вызывает каждый поток:

- сводки называют доступы к скрытым полям: чтение и запись;
- чтение против записи и запись против записи одного поля — конфликт;
- без конфликта проходят только вызовы методов `shared`-типов и атомиков; присваивание, `take` и уничтожение такого
  поля — обычная запись.

```text
error[readonly.hidden-write-race]: two threads can write `Regex.program` at the same time
  --> server.efen:21:9
   |
14 |     spawn { regex.find(lineA) }
   |             ----------------- writes hidden field `program` (via `compileIfNeeded`)
21 |     regex.find(lineB)
   |     ^^^^^^^^^^^^^^^^^ writes `program` while the coroutine can run
   = help: declare `program` with a `shared` type, or declare `shared readonly class`
```

Заголовок скомпилированного модуля несёт метку `read` со скрытыми записями и устойчивые имена приватных полей.

### `shared readonly class` и границы

FLOW не видит тела там, где Efen читает только метку: метод интерфейса, метод контракта в обобщённом коде, значение
функционального типа, `open` метод при раздельной сборке, контекст процесса библиотеки (его вызывают потоки C и
программы, загрузившей библиотеку). На этих границах метод с меткой `read`, который могут вызвать из нескольких
потоков, пишет скрытое состояние только синхронизированно. Это объявляет `shared readonly class`:

```efen
shared readonly class Text {
    let bytes: immutable Vector<Byte>
    private let hash: Lazy<UInt64>           // shared-тип std: вычисляется один раз
    fn hashValue -> UInt64 { /* тело не важно для примера */ }
}
```

- Компилятор проверяет у типа, что каждая скрытая запись каждого метода внешней части — метод атомика, доступ под
  блокировкой скрытого `shared`-поля или роль. Простая запись в обычное поле — ошибка у метода.
- Такой объект проходит любую границу и лежит в контексте процесса без дополнительного доказательства совместимости доступов по месту.
- Обычный `readonly class` со скрытыми записями через границу не проходит: реализация интерфейса или контракта —
  ошибка в строке `implements` или `conforms` с подсказкой «объявите `shared readonly class` или пометьте метод
  интерфейса `mut`». В контексте процесса он допустим только в программе (с `main`), по доказательству всей
  программы, и никогда в библиотеке.

Значение интерфейса уходит в другой поток, только если интерфейс объявлен `shared interface`: все его реализации —
`shared`-типы ([общая память](shared.md#пометка-shared)).

Обобщённое тело, которое вызывает методы `T` из нескольких потоков, получает требование «`T` — `shared`-тип или его
открытые методы доказаны при инстанциации».

### Счётчик

`conforms ArcClass` у `readonly class` допустим: счётчик — скрытое состояние, `retain` выполняется у вызывающего. Пока счётчик
в общей памяти не решён ([общая память](shared.md#пометка-shared)), многопоточная корутина не берёт `managed`
слоты, и `readonly class` со счётчиком однопоточный. Атомарность счётчика выбирается один раз у корня.

### Чего `readonly` не обещает

Компилятор проверяет отсутствие гонок и висячих ссылок, но не то, что изменение невидимо снаружи. Класс, который
считает свои чтения и отдаёт число методом, для компилятора `readonly`; это нарушение обещания автором, как
неправильный `==`.

## Где применяется

| Место | Что допустимо без дополнительного доказательства совместимости доступов |
|---|---|
| поле контекста процесса, `static` | `immutable T`, `shared`-тип, атомарный тип, `shared readonly class` |
| поле `shared`-структуры без охраны | `let` типа `immutable T` или простого значения без кучи |
| многопоточная корутина, `offload` | `immutable T`; `readonly class` — по доказательству FLOW |
