# Подпись библиотек

[Документация](README.md) · [Сертификация](certification.md) · [Пакеты](packages.md) · [Конфигурация сборки](build-config.md)

Сборка Efen принимает версию библиотеки, только если её подписал владелец ключа автора, а ключ сборка знает
из конфигурации, а не от сервера, который отдал версию. Git-хостинг, реестр, CI, токены, ключи развёртывания и
пароли не хранят ничего, чем можно сделать такую подпись. Поэтому взлом сервера или кража доступа к git
версию не подменяет.

Подпись библиотек предложил Edmond 2026-10-29: «что если можно подписывать так же библиотеки?», «тот кто
пушит исходники должен их защитить», «при этом если кто-то ломает сервер или крадёт доступ на git - подменить
не может», «только тот у кого есть ключ», «добавь в фичи возможность подписи предкомпилированных файлов».
Проект, разбор атак 2018–2026 годов и источники — amber dev/plans/S90.md §14. Всё, что не приписано Edmond, —
предложения агента по этому разбору.

Подпись нужна зависимостям из реестра и git. Зависимости `path(…)`, `workspace` и члены пространства сборки
лежат в репозитории пользователя, их защищает он сам, и ключа у них нет. Правила этой страницы действуют с
версии v1 ([версии](#версии)); до неё сборка сверяет только хеш дерева.

## Выпуск — подписанное утверждение

Выпуск библиотеки — утверждение в той же оболочке, что и [сертификат](certification.md). Субъект выпуска —
хеш дерева пакета: хеш BLAKE3-256, который Amber сам считает по файлам пакета. Автор при этом — центр
сертификации с областью `package`: он заверяет только пакеты, которые называют его ключ. Зависимости выпуск называет
отдельно, по ключу автора и диапазону версий, поэтому другое разрешение зависимости не отменяет подпись
родителя.

Утверждение о выпуске лежит в подписанном аннотированном теге git, а в архиве реестра — в файле `efen.sig`
рядом с пакетом. Хеш дерева этот файл не включает, иначе подпись покрывала бы саму себя.

| Утверждение | Кто подписывает | Что значит |
|---|---|---|
| выпуск | ключ автора | слово автора: дерево, версия, потолок возможностей, зависимости по ключу и диапазону |
| проверка | центр, служба безопасности, сам пользователь | уровень `reviewed` |
| происхождение сборки | CI (SLSA, in-toto, sigstore без ключа) | только свидетельство, не подпись автора |
| сертификат | центр ([сертификация](certification.md)) | `reviewed` … `proved` |
| готовый файл | автор или любой сборщик | слово автора или свидетельство пересборки |
| смена ключа | ключ восстановления, закреплённый вместе с ключом автора | ниже |
| список отзыва | тот, кто выдал отозванное, с датой выпуска и сроком действия | ниже |

## Ключ автора

`amber key new` создаёт ключ ed25519 и ключ восстановления. Ключ подписи хранится на аппаратном токене (FIDO2:
одно касание на подпись; подпись git по SSH такой ключ принимает) или вне сети, ключ восстановления — вне сети.
Подпись без ключа через поставщика удостоверений считается только происхождением сборки: поставщик и CI — тоже
серверы.

## Ключ записан в конфигурации

Ключ автора — предмет доверия, поэтому он лежит там же, где центры сертификации: в конфигурации, которую
просматривают при ревью, а не в созданном lock-файле.

```efen
config server {
    dependencies {
        json {
            version: "^1.0"
            key: "ed25519:9f2c…"
        }
    }
}
```

- **Новый ключ.** Ключ, которого нет в конфигурации, принимается, только если его называет подписанный
  родитель: так закрепляются транзитивные зависимости. Ключ, который не закрепил никто, в режиме
  `trust: required` отклоняется, а в режиме `trust: warn` сборка сообщает о нём (Edmond, 2026-10-29). Ключ
  прямой зависимости пользователь один раз записывает в конфигурацию: с сайта автора или от центра.
- **Lock-файл — кэш.** `efen.lock` хранит для каждого пакета ключ автора, хеш дерева, версию, потолок
  возможностей, принятые утверждения по хешу и старшую принятую версию. `amber build` отклоняет lock-файл,
  который расходится с конфигурацией, поэтому правка ключа в одном lock-файле ничего не меняет.
- **`amber trust accept`.** `amber trust accept json key …` и `amber trust accept json capabilities +net` (агент:
  в S90 — `effects +net`) пишут в конфигурацию: изменение видно на ревью.
- **Смена ключа** без участия пользователя принимается, только если её подписал ключ восстановления, закреплённый
  вместе со старым ключом, и только после срока ожидания. Иначе это новый пакет, и принять его можно правкой
  конфигурации. Правило может принять смену сопровождающего, которую заверил выбранный пользователем центр
  (Edmond, 2026-10-29).
- **Срок ожидания** (`minAge`, например семь дней): версию берёт только `amber lock`, запущенный не раньше чем
  через этот срок после того, как эта машина впервые увидела версию. Время первой встречи хранится вне
  репозитория, в данных Amber на машине пользователя, а не у сервера, тега, утверждения или в lock-файле,
  поэтому ни утверждение с ранней датой, ни правка lock-файла срок не сокращают. Время включения в
  независимый журнал может заменить эту запись, если правило называет журнал. Срочное исправление
  безопасности берётся раньше срока явной записью в конфигурации: `amber trust accept json version "1.4.2"`
  (агент).
- **Списки отзыва** приходят с адреса того, кто их выдал, а не с сервера пакетов, и несут дату выпуска и
  срок действия. В режиме `trust: required` `amber lock` отклоняет список с истёкшим сроком, поэтому сервер или
  зеркало задерживают отзыв только до этого срока, и lock-файл сообщает об этом.

Подменить версию взломом сервера нельзя, если конфигурация называет ключ автора. Украденный ключ автора опасен
в ограниченной мере: его сдерживают потолок возможностей, срок ожидания, обязательные проверки и отзыв.

## Потолок возможностей

Библиотека объявляет, до каких возможностей она может дотянуться, и компилятор это проверяет.

```efen
config json {
    kind: library
    capabilities: [fs.read]
}
```

- **Источники.** Каждый системный вызов идёт через `System` рантайма, и его точки входа помечены
  возможностью: `net`, `fs.read`, `fs.write`, `process`, `clock`, `random`, `env`. Функции `@abi(c)` и `@asm` и
  готовые объектные файлы — возможность `foreign`.
- **Что засчитывается пакету.** Каждый узел, цепочка происхождения которого ведёт к пакету
  ([происхождение](compile-time/plugins.md#происхождение-и-отчёт-доверия)): его тела, код, который его метакод
  порождает в чужих модулях, его обобщённый код, подставленный в другом месте, созданные им замыкания. Контекст,
  связанный и снятый внутри пакета, тоже засчитывается.
- **Проверка.** Источник, достижимый из пакета и не названный в потолке, — ошибка компиляции с путём до него.

Потолок — не набор эффектов экспортируемых функций: функция может связать контекст у себя (`with`, `without`),
а метакод порождает код в модуле пользователя. Пока у `System` нет пометок, потолок проверяется приближённо.
Правила доверия связывают требования с возможностями: структуре данных достаточно подписи автора, `net`
требует проверки, `foreign` можно запретить.

## Готовые файлы в пакете

Пакет может нести скомпилированные модули или объектные файлы. Плагины и метакод приходят только исходником
([плагины](compile-time/plugins.md#цель-и-воспроизводимость)). Доказательства подпись не несут: доказательство
приходит в проверяемом виде, и его проверяет ядро.

- **Привязка.** Утверждение `prebuilt` называет хеш BLAKE3-256 файла, хеш дерева пакета, хеши деревьев
  зависимостей, с которыми его собрали, версию и ключ содержимого Amber и хеш всего, что из конфигурации доходит
  до компиляции: цель, режим, настройки, `patch`, `replace`, аллокатор. Из записей `provide` программы
  в хеш входят только те, о которых спросила компиляция пакета, с ответами, включая «записи нет»: запись для
  чужого типа готовый файл не отменяет. Подписанное автором, оно —
  слово автора; подписанное другим сборщиком — свидетельство пересборки: «я скомпилировал это дерево этим Amber
  с этими входами и получил эти байты».
- **Использование.** По умолчанию сборка компилирует из исходников и не смотрит на готовые файлы. Правило
  может принять слово автора для скомпилированных модулей или потребовать k независимых свидетельств
  пересборки. Объектным файлам и пакетам с `foreign` нужно свидетельство пересборки, слова автора мало.
  Расхождение или отсутствие утверждения — сборка из исходников с отметкой в реестре свойств.
- **Идентичность.** Идентичность сборки называет готовые файлы, которые она взяла, поэтому две машины, решившие
  по-разному, получают разные идентичности.
- **Подмена.** Сервер или вор доступа может заменить файл, но не утверждение о его хеше: подменённый файл не
  совпадает по хешу, и сборка идёт из исходников.

## Исходники из git

- **Закрепление по содержимому.** `amber lock` превращает `git(url, tag:)` в коммит, формат его объектов, ключ
  дерева BLAKE3-256 и хеш и подписанта объекта тега. Субъект — хеш дерева; коммит только указывает, где его
  взять, поэтому коллизия SHA-1 ничего не подменяет. Тег, который потом указывает на другой коммит, —
  отказ «тег перемещён», а не обновление. `branch:` разрешён только в режимах `trust: warn` и при `amber lock`
  закрепляется на коммите.
- **Подписи.** Утверждение о выпуске лежит в подписанном аннотированном теге. Amber сам проверяет подписи SSH, gpg и
  gitsign по ключу из конфигурации, без связки ключей машины. Зависимость из git пишется секцией с `source`:

```efen
config server {
    dependencies {
        mm {
            source: git("https://github.com/efen-lang/mm", tag: "v0.1")
            key: "ed25519:41ab…"
            submodules: false
            lfs: false
        }
    }
}
```

- **Получение.** Amber скачивает в голое хранилище и раскладывает дерево сам. Хуки git не запускаются никогда;
  подмодули, LFS и символьные ссылки за пределы дерева — только с разрешения в записи зависимости; вложенного
  `.git` нет.
- **Переписанная история** и принудительный push не меняют закреплённую сборку.
- **Зеркала.** Пакет определяют ключ подписи автора и хеш дерева, поэтому зеркало отдаёт тот же пакет, что и
  источник, а реестр — ещё одно зеркало. Подменить версию не может ни то, ни другое.

Автор защищает свой репозиторий так: ключ на токене и никогда в CI; в CI — самое большее удостоверение для
происхождения сборки; `amber release` подписывает выпуск на машине автора после `amber audit`; защищённые ветки
с подписанными коммитами; `amber audit` в CI сверяет lock-файл с конфигурацией и списками отзыва.

## Что это останавливает и что нет

У Efen нет скриптов сборки и установки, через которые прошли атаки на SolarWinds, xz, ua-parser-js и
Shai-Hulud. Компилятор проверяет потолок возможностей каждой библиотеки, метакод работает в песочнице, пакеты
собираются из исходников, поэтому сборка воспроизводима.

Не останавливает: автора, злонамеренного или принуждённого, который не выходит за потолок (colors и faker);
ошибки, которые не нарушают контрактов; украденный ключ до отзыва; первый lock-файл, если ключ ничем не
закреплён; социальную инженерию, ведущую к `amber trust accept`; взлом машины пользователя или самого Amber,
выпуски должны защищаться той же моделью с порогом подписей проекта.

## Версии

- **v0:** хеш дерева BLAKE3-256 в `efen.lock`, расхождение — отказ; Amber сам получает git без хуков, подмодули
  и LFS по разрешению; `branch:` только в режимах `warn`. Останавливает перемещённые теги, принудительный push,
  архив, который расходится со своим деревом, и подмену закреплённых версий.
- **v1:** утверждения о выпуске, `amber key new` с ключом восстановления, `amber release`, ключи в конфигурации,
  закрепление через подписанного родителя, `amber trust accept`, `minAge`; потолок возможностей — сначала
  приближённый, затем по пометкам `System`; готовые скомпилированные модули под словом автора.
- **v2:** проверки, списки отзыва со сроком, `amber audit`, смена ключа ключом восстановления, наборы ключей k
  из n, свидетельства пересборки и объектные файлы, журналы прозрачности.

## Открыто

Пока предложения:

- запись зависимости секцией: `version`, `source`, `key`, `submodules`, `lfs`;
- `amber trust accept … version` для срочного исправления;
- поле `capabilities` в `project.efen` и слова `net`, `fs.read`, `fs.write`, `process`, `clock`, `random`,
  `env`, `foreign`;
- в секции `trust`: `minAge`, правила по возможностям, `prebuilt`, слово области `package`;
- команды `amber release`, `amber trust accept`, `amber key new`, `amber audit`;
- файл подписи пакета `efen.sig`;
- формат ключа в тексте (`"ed25519:…"`).
