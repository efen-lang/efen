# Словарь Efen

[Документация Efen](README.md) · [Amber glossary](https://github.com/efen-lang/amber/blob/main/design/glossary.md)

Термины ниже описывают текущую модель языка. Физические структуры HIR и стадии
компиляции вынесены в отдельный словарь Amber.

| Термин | Значение | Подробнее |
|---|---|---|
| **ABI / двоичный интерфейс** | Соглашения о представлении данных, вызовах функций, передаче исключений и времени жизни ресурсов, необходимые для совместимости скомпилированных частей программы. | [Режимы компиляции](compilation-modes.md) |
| **Accumulator / накопитель** | Переменная, которую цикл с `@accumulators(N)` обновляет одной операцией `+`, `*`, `min`, `max`, `&`, `\|` или `^` и хранит N частичными результатами. | [Циклы](blocks/loops.md#накопители) |
| **Alias / псевдоним** | `let t = doc.title`: второе имя того же значения, не копия. Псевдоним хранит заимствование значения с правом пути, по которому оно получено. Изменение структуры значения допустимо, если псевдоним после него не используется; иначе ошибка компиляции. Копию делает только `copy x`. | [Связывание существующего значения](types/ownership.md#связывание-существующего-значения) |
| **Окружение контекстов (ambient context)** | Контекстные зависимости, доступные в текущей области. Обращение записывается через `%`, а требование отражается в сигнатуре как `in Context`. | [Контексты и эффекты](context-and-effects.md) |
| **Aspect / аспект** | Расширение времени компиляции, которое участвует в построении языковой абстракции по объявленным стадиям. | [Аспекты](aspects/aspect.md), [построение класса](aspects/compile-time/class.md) |
| **assume / факт на веру** | Инструкция `assume условие`: компилятор принимает условие без доказательства до первой записи того, что оно читает; кода не порождает; точка доверия, пакет с ним рискованный. | [Условия](conditions.md#assume-факт-без-доказательства) |
| **Attribute / атрибут** | Применение метакода к объявлению, сохранённое в исходном HIR. Может порождать код или метаданные; само применение при этом сохраняется. | [Метаданные](aspects/metadata.md), [декораторы](decorators.md) |
| **Borrow / заимствование** | Доступ к значению без передачи владения. Права и время допустимого использования проверяются компилятором. Владение передаётся явно через `take`. Бывает двух видов. Заимствование на время вызова (ссылка внутри функции) кончается вместе с вызовом. Заимствование, которое живёт в структуре, живёт дольше вызова; такую структуру (курсор, генератор, замыкание, объект с полем `layout`) называют структурой, которая заимствует. Записывается двумя способами. В типе значения — правом и источником в скобках: `(Access<self> Cursor)`, `(mut<items> generator yield Int)`; так заимствуют курсор, генератор и замыкание. У внешнего кода — моделью, которая пишет в поле `layout` слот аргумента, зависимость от внешнего объекта или значение `own`. Живёт до снятия или до уничтожения структуры, которая заимствует. В синхронном режиме (по умолчанию) владелец слота читает и пишет значения, в параллельном (многопоточная корутина, `offload`, `shared`, `shared layout`) — таблица многопоточного вида. | [Владение и доступ](types/ownership.md), [Модели поведения](models.md#заимствования), [контракты обхода](types/collections.md#контракты-обхода) |
| **Capability / право** | Разрешённые операции над значением. В исходном коде используются `read`, `edit`, `mut`, `out` и `own`; компилятор раскладывает их на составляющие права. Пометка типа `shared` рассматривается отдельно. | [Владение и доступ](types/ownership.md) |
| **Class / класс** | Тип с полями и методами. По умолчанию у объекта один владелец; собственные конструкторы, деструкторы, подсчёт ссылок и наследование подключаются контрактами. | [Классы](classes.md#определение-класса) |
| **Чистый контракт** | Объявление требований, отделённое от их реализации. Чистота контракта не означает отсутствие эффектов у требуемых методов. | [Контракты](contracts.md#чистый-контракт-и-его-реализация) |
| **Runtime языка Efen** | Готовые контракты, функции и типы, доступные в языке всегда; объявления `lang::` и требования к их исполняемым реализациям. | [Runtime](runtime/README.md) |
| **Реализация извне** | Аспект, который реализует контракт для соблюдающих его классов, не написавших реализацию сами; контракт разрешает это строкой `allow implementations`. | [Контракты](contracts.md#реализация-извне) |
| **Класс над внешним значением** | Класс, объект которого — значение, созданное внешним кодом (C, `@asm`, бинарный пакет): `representation Raw<I>` или `@abi(c) class`. Без заголовка, счётчика и хранимых полей; один владелец. | [Классы](classes.md#класс-над-внешним-значением) |
| **Код времени компиляции** | Код Efen, выполняемый компилятором для чтения, проверки и преобразования объявлений и HIR. | [Compile-time API](compile-time/index.md) |
| **CPU level / уровень процессора** | Поле `cpu` секции `target`: набор команд, которые программа использует (`x86-64-v2` по умолчанию на x86-64); `features` добавляет к нему флаги процессора или убирает их. | [Конфигурация сборки](build-config.md#процессор) |
| **Contract / контракт** | Правила, которым должны соответствовать код и его поведение: требования к операциям, правам доступа, владению, состояниям и заимствованию памяти. Проверяются компилятором; сам контракт не является типом значения и не требует таблицы виртуальных методов. | [Контракты](contracts.md) |
| **Concurrency context / асинхронный контекст** | Контекст, который реализует асинхронный контракт (`SingleThreadConcurrency` или `MultiThreadConcurrency`, общий `Concurrency`). Только внутри него разрешён `spawn`; блок `with` дожидается его корутин. Реализации — рантайм. | [Контексты и эффекты](context-and-effects.md#асинхронный-контекст) |
| **Context / контекст** | Типизированная зависимость, доступная через окружение контекстов и отражаемая в сигнатуре через `in`. | [Контексты и эффекты](context-and-effects.md) |
| **Coroutine / корутина** | Лёгкий (зелёный) поток внутри асинхронного контекста; не «задача». `spawn` запускает корутину с результатом (дескриптор `Coroutine<F>`, `F` — тип замыкания корутины, ведёт себя как `Future`, его дожидается слот ожидания), `background` — фоновую. Не переживает блок `with` контекста. | [Замыкания](closure.md#корутина-spawn) |
| **Decorator / декоратор** | Атрибут, чьё выполнение преобразует помеченную декларацию или порождает дополнительный HIR. | [Декораторы](decorators.md), [метаданные](aspects/metadata.md) |
| **Тип с параметром-значением** | Параметризованный тип, в идентичность которого входит значение, известное при компиляции: например, `User<root>` или `Matrix<3, 4>`. | [Типы с параметрами-значениями](types/value-parameterized-types.md), [параметры типов](generics.md) |
| **`@default`** | Пометка на реализации контракта: её берёт сборка, если программа не выбрала другую в `provide`. Из нескольких `@default` побеждает пакет, который включает другой; на параллельных ветках — ошибка, программа выбирает в `provide`. | [Статическое связывание](context-and-effects.md#умолчание) |
| **Контракт-зависимость** | Контракт, реализацию которого выбирает сборка, а не код: секция `provide` или `@default`. Функция, которая его вызывает, получает эффект. | [Статическое связывание](context-and-effects.md#статическое-связывание-эффектов) |
| **Dialect / диалект** | Уровень анализа исходного кода, который отображает другой исходный язык или профиль синтаксиса в семантику Efen и Amber HIR. | [Диалекты](dialects.md) |
| **Effect / эффект** | Контракт или интерфейс, который функция использует как внешнюю зависимость: `in X` или `%X.f()`; особой пометки у объявления нет. Требование статически отслеживается и идёт по графу вызовов; контракт связывает секция `provide` конфигурации или `@default`, интерфейс — значение в `with`. | [Контексты и эффекты](context-and-effects.md) |
| **Открытый enum / variant** | `open enum` или `open variant`: другие объявления добавляют к нему значения (`enum StorageReason: Reason { quota }`), как подкласс к классу. `match` по нему требует `_` или `@extended _`. | [Перечисления](types/enum.md#расширение), [variant](types/variant.md#расширение) |
| **`@extended _`** | Ветка `match` по открытому типу: ловит значения расширений, значения самого типа перечисляются. | [Match](blocks/match.md#extended-_) |
| **Размеченное объединение** | Тип с именованными случаями, у каждого из которых могут быть собственные поля. В Efen объявляется через `variant`. Различие случаев сохраняется независимо от способа хранения. | [Размеченные объединения](types/variant.md) |
| **Случай объединения** | Именованная форма значения `variant`, например `Result.ok`. Конструктор значения создаёт значение выбранного случая и заполняет его поля. | [Случаи и создание значений](types/variant.md#случаи-и-создание-значений) |
| **Перечисление** | Тип с именованными значениями без собственных полей у каждого элемента. В Efen объявляется через `enum`. | [Перечисления](types/enum.md) |
| **Внешнее значение перечисления** | Фиксированное число или строка, сопоставленные элементу `enum` в его объявлении; доступны через `rawValue`. Это не поле `variant` и не обязательно его внутренняя метка. | [Внешние значения](types/enum.md#внешние-значения-rawvalue) |
| **IndirectExtensions** | Контракт корня открытого variant: данные случаев расширений лежат в куче, размер корня не зависит от программы. | [Размеченные объединения](types/variant.md#схемы-хранения) |
| **Family / семейство видов хранения** | Механизм открытого семейства `Family<Base>` для компоновки памяти. Позволяет добавлять проверенные виды хранения; сам не является типом значения `variant`. | [Layout](memory/layout-reference.md), [колоночные layout](memory/columnar-layouts.md) |
| **Fault / сбой** | Потомок класса-корня `Fault`: `AllocationError`, `OverflowError`, `DivisionByZeroError`, `NullUnwrapError`, `BoundsError`, `OverlapError`. `nothrows` его пропускает, `nofail` — нет; общий `catch` его не ловит. | [Throws](throws.md#nofail-системная-точка-ответственности) |
| **Throwable** | Контракт всего, что можно бросить: `reason()` (кто виноват: `Reason`) и трассы. Его соблюдают только корни `Exception`, `Fault`, `Cancellation`, `AssertionError` из `lang::`. | [Throws](throws.md#иерархия) |
| **`ImplicitlyDestroyable`** | Встроенный пустой контракт, соответствие вычисляется: компилятор может уничтожить значение в точке, которую программа не называет. Не соответствуют класс только с явными деструкторами и всё, что его содержит. | [Disposable](disposable.md#implicitlydestroyable) |
| **Flow** | Последовательность зависимых вычислений в одном вычислительном контексте (монадическая последовательность). `<-` связывает значение контекста, а `return` завершает только сам `flow`. | [Flow](flow.md) |
| **Foreign field / поле `foreign`** | Поле контекста процесса или потока без памяти и значения: имя пути для прав на состояние библиотеки C (`public foreign strerror`). `shared foreign` — состояние, которое библиотека защищает сама. | [Внешний код](foreign.md#память-которую-функция-отдаёт-до-следующего-вызова) |
| **Freezable** | Вычисляемый контракт `lang::`: тип допускает заморозку в слот `immutable`. Строку пишет только класс над внешним значением, и это точка доверия, которую показывает `efen proofs`. | [Неизменяемость](immutability.md#какие-типы-замораживаются) |
| **HIR** | Высокоуровневое структурное представление программы после анализа исходного кода. Тела проходят от нетипизированных C0/C1-форм к типизированным и проверенным поздним стадиям; это не машинные инструкции. | [Compile-time API](compile-time/index.md), [Amber HIR](https://github.com/efen-lang/amber/blob/main/design/hir/README.md) |
| **Interface / интерфейс** | Тип значения с выбором реализации методов при выполнении. Интерфейс по контракту создаётся явным объявлением `interface I from C`. | [Интерфейсы](interfaces.md), [контракты](contracts.md#связь-контрактов-с-интерфейсами) |
| **Immutable / неизменяемый слот** | `immutable T`: значение в слоте и всё, до чего оно достаёт, не меняется ни на один байт с заморозки до уничтожения. Заморозка — новое значение, `take` от единственного владельца или `const`. Отдаётся любому потоку без доказательства. | [Неизменяемость](immutability.md#immutable-t) |
| **`isolated`** | Граница, запрещающая неявно расширять набор внешних эффектов функции или региона. Не означает `pure` и не запрещает повторный вход. Выведенные из тела состояния и структура памяти видны вызывающему. | [Контексты и эффекты](context-and-effects.md) |
| **Layout / компоновка** | Объявление памяти структуры данных на уровне модуля: множества и области, структуры их элементов, владение, указатели между элементами, инварианты и строки `public own` и `public lend`. Функции в `layout` не входят: они стоят рядом, в модуле или пакете. Экземпляров у `layout` нет, множество одно на программу; по объявлениям FLOW доказывает время жизни указателей. Слово `layout` в теле класса, интерфейса или контракта означает другое: поля заимствований внешней стороны (строка «Поле `layout` класса»). | [Layout: руководство](memory/layout.md), [справочник правил](memory/layout-reference.md), [примеры](memory/layout-examples/) |
| **Поле `layout` класса** | Поле в `layout { … }` тела класса, интерфейса или контракта: то, что держит внешняя сторона. В байтах объекта его нет; пишет его модель, читает FLOW. | [Компоновка](classes.md#layout-в-теле-класса) |
| **Layer / слой** | Архитектурная группа времени компиляции пакетов с отношениями `uses`, `exposes` и `provides`; значением времени выполнения не является. | [Слои](layers.md) |
| **Управляемый слот (managed slot)** | Слот, в котором операции времени жизни строит выбранная модель управления памятью, а не обычная проверка заимствований. Это режим внутреннего слота, не право доступа и не модификатор переменной. | [Владение и доступ](types/ownership.md) |
| **Metadata / метаданные** | Типизированные данные об объявлении, доступные при компиляции. Какие из них нужны при выполнении, определяется отдельно. | [Метаданные](aspects/metadata.md) |
| **Metafunction / метафункция** | Функция времени компиляции, которая возвращает `InlineClosure` или преобразует HIR. Созданный код проходит обычную проверку имён и типов. | [Метафункции](compile-time/metafunctions.md) |
| **Model / модель** | Абстрактный код `model { … }` после сигнатуры функции: что функция кладёт в поля `layout` и снимает с них. Не компилируется; у функции без тела ей верят. | [Модели поведения](models.md#модель-model) |
| **Module / модуль** | Файл `.efen` пакета; блока `module x { }` нет; область имён, `use` и `private`. Путь модуля — путь файла от папки пакета: `tax/rates.efen` — `tax::rates`. | [Пакеты и модули](packages.md#модуль) |
| **Регистр имён** | Первая буква имени обозначает его категорию: типы и контексты начинаются с заглавной; значения, поля, функции, элементы `enum` и случаи `variant` — со строчной. | [Ориентиры и границы](README.md#ориентиры-и-границы) |
| **Opaque type / тип со скрытой реализацией** | Отдельный номинальный тип, внутреннее представление которого раскрывается только в установленной области. | [Параметры типов](generics.md) |
| **Параметр типа `Access`** | Параметр обобщённого объявления, значение которого — право доступа (`read`, `edit`, `mut`, `own`). Пишется там, где стоит слово права: в поле, в типе и в пометке метода. | [Параметры типов](generics.md#право-доступа-как-параметр) |
| **Origin / источник доступа** | Статическая связь доступа со слотом или набором элементов, от которых зависит допустимость его использования. Отличается от происхождения сгенерированного HIR. | [Владение и доступ](types/ownership.md), [структура, источник, чистота](memory/layout-reference.md#структура-источник-чистота) |
| **Поля не делят память** | Основное правило доступа: два поля или два параметра указывают в одну память, только если это объявлено явно. Механизмов два: право с источником, `право<поле или параметр>` (`current: read<self.children> Node?`, `src: read<dst?> T`), и `layout`. Без объявления поле владеет своим значением, а пишущие аргументы не пересекаются. | [Владение и доступ](types/ownership.md#поля-не-делят-память) |
| **Слот** | То, где хранится значение: переменная, параметр, поле, элемент коллекции. У слота есть адрес и время жизни; изменение структуры перемещает или уничтожает слоты. Слово «место» термином не служит: доступ называют ссылкой, а то, где хранится значение, — слотом. | [Владение и доступ](types/ownership.md), [правила доступа к памяти](memory/memory-rules.md) |
| **Ссылка** | Локальный доступ к слоту с правом `read`, `edit` или `mut`: `&x` или `&read x`. Ссылка ничем не владеет. Источник определяется выражением создания ссылки. В типе параметра `&` не используется; нужен режим доступа, например `mut T`. Правила хранения и результатов функций описаны отдельно. | [Владение и доступ](types/ownership.md#ссылки-только-внутри-функции) |
| **Ссылка в результате** | Ссылка в память параметра, которую функция возвращает с правом `read`, `edit` или `mut`; источник записан в результате: `-> edit<list> Shape?`, в методе — `self` без записи или путь к части, `-> read<self.items> Item?`. Изменение структуры источника допустимо, если результат после него не используется, а структура, которая заимствует, уничтожена до него; иначе ошибка компиляции: компилятор показывает её в строке изменения структуры и отдельно строку использования. Форма `<&путь>` (`-> read<&doc.title> T`) обещает ровно слот по пути. | [Владение и доступ](types/ownership.md#место-в-результате-функции) |
| **Anchor / якорь** | Неисключительное владение: поле, которое управляет временем жизни области памяти или объекта. Пишется `anchor`: поле, параметр, локальная переменная или результат, которые уничтожают значение или передают эту обязанность, пока на значение указывают невладеющие указатели `layout`. Якорь задаёт конец времени жизни значения: после него все указатели на значение недействительны. Якорь переходит из слота в слот через `tie`. Исключительное владение — `own`. | [Layout](memory/layout-reference.md#якорь-anchor) |
| **Невладеющий указатель** | Указатель на элемент множества `Items.Item` без `own` и `anchor` (`prev`, `parent`, ребро графа). Не уничтожает цель и действителен не дольше её. Общее слово «указатель» охватывает и владеющие формы; сырой адрес — `Pointer`. | [Алгоритм работы layout](memory/layout-algorithm.md#что-описывает-layout) |
| **Держатель** | Поле структуры расширения, которое хранит указатель в множество базового `layout`: прямо или в аргументе типа. Перед вызовом, сводка которого уничтожает элемент базового множества или выводит его из структуры, ни один держатель этому элементу не равен. | [Указатели в множества базового](memory/layout-reference.md#102-указатели-в-множества-базового) |
| **Публичная функция структуры** | Функция без `private`, которая пишет поля структуры из `layout`. Инварианты структуры выполняются на её входе и выходе; вспомогательные функции `private` работают со структурой, инвариант которой может быть временно нарушен. | [Layout](memory/layout-reference.md#пространство-layout) |
| **Изменение структуры** | Операция, после которой слот перенесён или уничтожен, элемент ушёл из структуры или сменил вид, слот лишился значения: удаление элемента, перевыделение, замена значения, которое владеет памятью. Ссылки в значение после неё недействительны. | [Что делает ссылку недействительной](memory/memory-rules.md#что-делает-ссылку-недействительной) |
| **Поле-псевдоним** | Поле `право<self.путь> T?`, которое хранит связь с памятью своего же объекта: `current: read<self.children> Node?`. Не ссылка и не заимствование: запись в него считается записью значения, а код, который меняет структуру источника, записывает поле заново. | [Поле-псевдоним](types/ownership.md#поле-псевдоним) |
| **Чистая структура** | Структура из `layout`, каждый хранимый невладеющий указатель которой указывает внутрь неё. Публичная структура чиста: по правилу чистоты хранимый указатель без источника в типе указывает только внутрь своей публичной структуры. Значение с источником в типе хранит объявленное заимствование и чистоту не нарушает. Внутренняя структура (вершина внутри графа) может быть нечистой: её указатели выходят за её пределы, но остаются внутри её публичной структуры. Нечистую внутреннюю структуру отделяет только код `layout`: он переписывает указатели и доказывает, что отделённая часть чиста. | [Layout](memory/layout-reference.md#структура-источник-чистота) |
| **Множество (`set`)** | Все элементы одной формы во всей программе, объявленные строкой `set X: T` в `layout`; своей памяти у множества нет, оно задаёт тип указателя `X.Item`. | [Множества и области](memory/layout-reference.md#множества-и-области) |
| **Область (`area`)** | Непрерывные слоты одной формы с доступом по индексу, объявленные строкой `area X: T` в `layout`; областью целиком владеет поле `own X.Area`, а область, объявленная полем структуры, принадлежит элементу, в байтах которого расположена. Размер области в байтах называет `x.size`. | [Множества и области](memory/layout-reference.md#множества-и-области) |
| **Область с разным шагом** | Область, структура слота которой задаёт свой размер собственным инвариантом (`text.count == length`). Слоты имеют разный размер, номером слота служит смещение его начала в байтах, и FLOW доказывает, что слоты занимают область без промежутков. Размер области в байтах называет `x.size`, а число слотов `x.count` находит обход. Выдаётся только вложенная область слота. | [Область с разным шагом](memory/layout-reference.md#область-с-разным-шагом) |
| **`open layout`** | `layout` с именем, который разрешено расширять: `open layout Lists<T> { … }`. Имя есть только у `open layout`. Его поля `protected`, инварианты над ними и сводки функций входят в интерфейс пакета. | [Расширение layout](memory/layout-reference.md#расширение-layout) |
| **Расширение `layout`** | `layout`, который после двоеточия называет базовый `open layout` с аргументами: `layout<K, V>: lists::Lists<Entry<K, V>>`. Добавляет свои множества и структуры с указателями в множества базового и ничего в базовом не меняет. | [Расширение layout](memory/layout-reference.md#расширение-layout) |
| **`protected` в `layout`** | Пометка поля или функции в `open layout`: поле читает и пишет код базового `layout` и код его расширений, функцию вызывает тот же код. Правила `self`, как у классов, нет. Код расширения пишет такие поля только в пределах `edit`. | [protected](memory/layout-reference.md#protected-в-layout) |
| **Структура из `layout`** | Именованная структура, объявленная в `layout` (`Vector`, `List`). В правилах времени жизни «структурой элемента» называется корень цепочки владения этим элементом. | [Структура, источник, чистота](memory/layout-reference.md#структура-источник-чистота) |
| **Публичная структура** | Структура из `layout`, владелец которой находится вне значения `layout`: значение (`List`, `Graph`) со всеми элементами под ним, элемент `own S.Item` или выданный слот в переменной, параметре, поле обычного типа. Какой код хранит значение, код `layout` или внешний, для определения не важно. Она чиста, целиком переходит к другому владельцу и в другой поток, и только её помещают в поле `shared`. Её часть, элемент со всем, чем он владеет, или значение структуры из `layout` в поле другой, называется внутренней структурой. | [Структура элемента](memory/layout-reference.md#публичная-структура) |
| **Вид элемента** | Структура, которой описаны байты элемента в данный момент (`FreeBlock`, `SlotBlock`); вид меняется приведением `as`, и у каждого вида свои инварианты. | [Виды и приведение `as`](memory/layout-reference.md#виды-и-приведение-as) |
| **Выдача слота (`lend`)** | Операция `lend block.slots[k]`: слот области переходит получателю как `own`, а родитель до возврата слота остаётся без права `own`. | [Выдача и возврат](memory/layout-reference.md#выдача-и-возврат) |
| **Неинициализированный элемент** | Элемент области, в котором значения нет: после `take` или до первой записи; запись в него — инициализация, чтение — ошибка, и это не `null`. | [Множества и области](memory/layout-reference.md#множества-и-области) |
| **Источник ссылки** | Слот или путь внутрь него, от которого взята ссылка; у указателя на элемент `layout` — структура, из которой он прочитан. | [Источник, право и время действия](types/access-regions.md#источник-право-и-время-действия) |
| **Структура, которая заимствует** | Значение, которое хранит заимствование дольше вызова: курсор, генератор, замыкание, объект с полем `layout`. | [Правила доступа к памяти](memory/memory-rules.md#понятия) |

Остальной код внешний: он читает поля и вызывает функции. | [Пространство `layout`](memory/layout-reference.md#пространство-layout) |
| **Схема владения** | Строки `public own S` и `public lend T.поле` в `layout`. Они объявляют, какие элементы или слоты какой области функции кода `layout` отдают внешнему коду во владение. Владельцем множества служит владеющее поле или строка `public own S`; строка `public lend` владельцем множества не служит. | [Что уходит наружу](memory/layout-reference.md#схема-владения) |

Из тела выводится сводка действий, а не право метода. | [Контракты](contracts.md#доступ-метода-к-self), [классы](classes.md#доступ-метода-к-self) |
| **Resolver / разрешение имён членов** | Механизм времени компиляции, который преобразует обращение к члену в операции доступа или вызова в HIR. | [Разрешение членов](aspects/members-resolving.md) |
| **Risk package / рискованный пакет** | Пакет, где есть место, которое сборка принимает на веру, а не доказывает: `@asm`, `@platform`, `@abi(c)`, функция библиотеки C, `thread var x: own T`, приведение адреса к элементу множества. Пометку выводит компилятор (заметка `Trust`), пакет её не пишет. | [Кому доступно доверие](memory/system.md#кому-доступно-доверие) |
| **Shared / общая память** | Память, к которой одновременно обращаются несколько потоков; её тип помечен `shared`. Доступ — проекция через `as` под условием (например, захваченный мьютекс), атомарные методы или роль. | [Общая память](shared.md) |
| **`shared layout`** | Пометка класса без счётчика, интерфейса или контракта: внешняя сторона трогает заимствованное из другого потока в любой момент; для проверки доступа объект — многопоточная корутина. | [Общая память](shared.md#shared-layout) |
| **Strategy / стратегия** | Отдельная реализация поведения `for Type`, участвующая в статическом разрешении без добавления физического метода типу. | [Стратегии](strategies.md) |
| **Struct / структура** | Тип-значение с полями. Примитив ниже класса: конструктора и деструктора нет, вызов `T(…)` только записывает поля, а память, которой структура владеет, освобождает явный код. | [Структуры](structs.md#отличия-от-классов) |
| **Thread context / контекст потока** | `thread context`: отдельное значение у каждого потока. Создаётся при первом обращении и уничтожается при завершении потока. Ссылки на его данные становятся недействительными в точке ожидания. Поля класса с `thread` также принадлежат потоку; `static let` принадлежит процессу. | [Контексты и эффекты](context-and-effects.md#контексты-процесса-и-потока) |
| **`ThreadBound`** | Встроенный пустой контракт: значение не попадает в многопоточную корутину, тело `offload`, поле `shared` и объект `shared layout`. По умолчанию тип свободен; `conforms ThreadBound` пишет тип, привязанный к потоку сам по себе, а тип с полем, элементом, захватом или полем `layout` такого типа соответствует ему без строки. | [Контракты](runtime/built-in-contracts.md#threadbound), [общая память](shared.md#привязка-к-потоку-threadbound) |
| **`Scoped`** | Контракт с методами `enter` и `exit nofail`; блок `with` над его значением вызывает `enter` на входе и `exit` на каждом выходе. Так захватывают мьютекс. | [Общая память](shared.md#мьютекс-и-with) |
| **`take`** | Явная передача `own`, после которой исходный слот пуст либо недоступен согласно его виду; замыкание вида `own` в параметре без права `own` — тоже `take`. | [Владение и доступ](types/ownership.md#явное-извлечение) |
| **Typestate / состояния типов** | Проверяемое компилятором состояние значения, ограничивающее допустимые операции и переходы. | [Типы-состояния](types/typestate.md) |
| **`Waiting` / эффекты ожидания** | Эффект вызова, который может ждать: `Suspending` — ждёт корутина, поток свободен; `Blocking` — ждёт поток. Источники объявляет рантайм, остальное выводится; `with` мьютекса закрывает `Waiting`. | [Общая память](shared.md#эффекты-ожидания) |
| **Workspace / рабочее пространство** | Папка с `workspace.efen`: несколько пакетов, общие версии зависимостей, `efen.lock`, среда сборки и `layers.efen`. Своей версии и выхода сборки нет. | [Пакеты](packages.md#рабочее-пространство) |
| **Структурное объединение** | Тип `T \| U`, объединяющий значения существующих типов без новых именованных случаев. | [Union-типы](type-aliases.md#union-типы) |
| **Явный деструктор** | `@destructor(explicit)`: компилятор не вызывает его на обычном выходе, программа обязана вызвать его сама; на пути исключения его вызывает компилятор. | [Disposable](disposable.md#явный-деструктор) |
| **Variant / размеченное объединение** | Номинальный тип с именованными случаями и их полями. По умолчанию закрыт; для расширения используется `open variant`. Способ хранения не меняет различимость случаев. | [Размеченные объединения](types/variant.md) |
| **Witness / основание выбора реализации** | Конкретная реализация контракта или выбранная стратегия, которую компилятор сохраняет как основание разрешения при компиляции. | [Контракты](contracts.md), [стратегии](strategies.md) |
| **Whole compilation / сборка всей программы** | Режим, в котором компилятор видит код всей программы, включая наследников классов. Это позволяет уточнять сводки эффектов и действий. Объявленные права методов и границы контрактов и интерфейсов сохраняются. | [Режимы компиляции](compilation-modes.md#сборка-всей-программы) |
| **`without Context`** | Граница вывода: требование `in Context` из блока не распространяется на окружающую функцию. Доступное значение контекста не удаляется. Название конструкции ещё может измениться. | [Контексты и эффекты](context-and-effects.md) |

## Термины, которые нельзя смешивать

| Не одно и то же | Граница |
|---|---|
| Контракт и интерфейс | Контракт задаёт требования к коду и поведению, проверяемые при компиляции; интерфейс служит общим типом значений разных реализаций. |
| Компоновка и представление | Компоновка связывает логические слоты с хранилищами; представление задаёт физическую форму конкретного типа. |
| `layout` и `model` | `layout` типа объявляет всё о памяти, в том числе поля, которые держит внешняя сторона; `model` — абстрактный код после сигнатуры функции, который пишет в эти поля. |
| Источник доступа и происхождение HIR | Источник задаёт слот, с которым связан доступ; происхождение HIR показывает, какой метакод создал его узлы. |
| Стратегия и аспект | Стратегия предоставляет поведение при выборе реализации; аспект участвует в построении абстракции и её HIR. |
| `isolated` и `without Context` | `isolated` закрывает весь вывод внешних эффектов; `without Context` закрывает одно контекстное требование. |
| `variant` и структурное объединение | `variant` объявляет именованные случаи; `T \| U` объединяет существующие типы. |
| Ссылка и слот | Слот хранит значение и имеет адрес; ссылка — доступ к слоту с правом и источником, она ничем не владеет. Слово «место» ни одного из них не называет. |
| Часть, проекция, множество и область | Часть — имя памяти объекта в контракте, без типа и байт; проекция — тип с выбранными полями значения; множество и область (`set`, `area`) объявляет `layout` уровня модуля, и они описывают память элементов. Часть привязывают к полям; проекция и множество частей не объявляют. |
| Заимствование в типе и заимствование в модели | Первое пишет право и источник в скобках перед типом значения Efen; второе пишет модель внешней функции в поле `layout`. Оба значат заимствование, которое живёт в структуре. |
| `variant` и `Family<Base>` | Открытый `variant` — тип значения с расширениями; `Family<Base>` описывает открытое семейство видов хранения для компоновки. |
