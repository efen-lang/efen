# Репрезентации (Representations)

Репрезентация — именованная compile-time абстракция, которая определяет,
как логический тип существует физически. Один логический тип может иметь
несколько репрезентаций.

Репрезентация может определять:

- размещение и группировку данных;
- выделение и освобождение памяти;
- создание и уничтожение значений;
- копирование и перемещение;
- доступ, изменение и итерацию;
- преобразование в другие репрезентации.

```efen
struct Particle {
    var position: Vec3
    var velocity: Vec3
}

representation ParticleAoS for [Particle] {
    // Частицы хранятся целиком одна за другой.
}

representation ParticleSoA for [Particle] {
    // Position и Velocity хранятся отдельными колонками.
}
```

Предварительный синтаксис выбора репрезентации:

```efen
let simulation: [Particle] as ParticleSoA
let interchange: [Particle] as ParticleAoS
```

Обе переменные имеют один логический тип `[Particle]`, но различное физическое
представление. Репрезентация является частью статического типа: преобразование
между `ParticleSoA` и `ParticleAoS` не должно происходить неявно.

## Границы ответственности

- тип (`struct`, tuple, массив) задаёт логическую форму и семантику данных;
- representation задаёт алгоритм их физического хранения и жизненный цикл,
  вплоть до расположения байтов;
- layout — абстракция памяти, а не байтов: он задаёт область принадлежности,
  население блоков и происхождение ссылок, см.
  [Адреса и структуры данных](memory/addresses.md);
- allocator предоставляет память по запросу representation.

Allocator не заменяет representation: две репрезентации могут использовать
один allocator, но по-разному размещать, создавать и уничтожать данные.

## Требования

Репрезентация обязана сохранять наблюдаемую семантику логического типа.
Компилятор должен диагностировать несовместимый доступ, неявное дорогое
преобразование, скрытое выделение памяти и нарушение правил ownership.

Representation также обязана поддерживать анонимную проекцию доступных полей:

```efen
let movement = particles.{position, velocity}
```

Проекция выбирает логические поля, а representation определяет, как получить к
ним физический доступ. Проекция не меняет representation и не требует
копирования данных.

Точная грамматика объявления и обязательный контракт representation требуют
отдельной спецификации.
