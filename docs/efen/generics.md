# Обобщённый код и параметры типов

[Документация](README.md) · [Контракты](contracts.md) · [Типы и данные](types/README.md)

Обобщённое объявление описывает код для нескольких типов или значений,
известных при компиляции. Вместо конкретного типа оно использует параметр,
например `T`. Ограничения параметра определяют, какие операции допустимы
в теле. Тело, которое опирается только на записанные контракты, компилятор проверяет один раз, до выбора
конкретных аргументов. Тело, которое читает сам аргумент — члены контракта-параметра, имя, поле, блок условий,
кусок кода или раскрытый тип функции, — проверяется в каждой инстанциации
([поля, условия и код как параметры](#поля-условия-и-код-как-параметры), [контракт как параметр](#контракт-как-параметр)).
Форму значения, заимствования и ссылки решает написанное, до подстановки. Вердикт памяти, который зависит от
аргумента, тело не выводит из «обобщённый код не знает тип»: он становится требованием в сводке и проверяется у
каждой инстанциации, как «`T` не `ThreadBound`» ([общая память](shared.md#привязка-к-потоку-threadbound));
см. [генерацию кода](#генерация-кода).

Условимся различать **параметр** в объявлении (`T` в `Box<T>`) и **аргумент**
при его использовании (`Int` в `Box<Int>`). Конкретное объявление вместе
с аргументами образует экземпляр обобщённого объявления — инстанциацию.

## Два способа реализации generic

Efen поддерживает два способа реализации обобщённого кода: мономорфизацию
и стирание параметров типов. Объявление и его ограничения задают, какой код
допустим; выбранный способ определяет, как этот код представлен в программе.

| Способ | Как устроен код | Как выбирается |
|---|---|---|
| Мономорфизация | Для нужных инстанциаций создаются специализированные тела с конкретными типами | По умолчанию; явно — `@monomorphize` |
| Стирание параметров типов | Несколько инстанциаций используют общее тело и универсальное представление значений | Явно — `@erase` |

```efen
@monomorphize
fn specialized<T>(value: T) { }

@erase
fn sharedBody<T>(value: T) { }
```

У стирания есть ограничения: в частности, оно не допускает операций,
зависящих от выбранной стратегии. Если `@erase` нельзя безопасно реализовать,
компилятор выдаёт ошибку, а не меняет режим. Универсальное представление может
потребовать обёртки; её эффекты остаются видны вызывающему коду.
Подробности — в разделе [«Генерация кода»](#генерация-кода).

Для параметризованных классов построением реализации управляет
[`ClassGenericDefinition`](aspects/compile-time/class.md): несколько
инстанциаций могут использовать одну реальную реализацию.

## Обобщённые функции

Функции могут объявлять параметры обобщённого объявления ключевым словом `generic` в начале
тела объявления. Параметр типа является параметром времени компиляции со значением
типа `Type`:

```efen
fn identity<T: Movable>(value: own T) -> T {
    return value
}
```

Тело проверяется по ограничениям `T`: в нём доступны только гарантированные
этими ограничениями операции. Это правило записанных контрактов (`T: Movable`); ограничение контрактом-параметром
(`T: C`) проверку тела переносит в инстанциацию. Поэтому
`identity` берёт `value` во владение: вернуть читающий параметр без ограничения нельзя, это вернуло бы чужое значение.
`return value` переносит значение из слота параметра в слот результата, а перенос даёт `Movable`
([явное извлечение](types/ownership.md#явное-извлечение)): без
`T: Movable` тело отвергается. `T: ImplicitlyCopyable` тоже разрешил бы `return value`, но закрыл бы `identity` для
`String`.

Объявления `generic` предшествуют параметрам вызова, а объявления `param` идут
после них подряд до остальных инструкций. Имена из строк `generic` и `param` видны во всём объявлении, и в
заголовке тоже: в цели стратегии (`strategy ArrayTraversal for Array<T>`), в типах параметров и результата, в
строках `requires` и `ensures`. Список в угловых скобках остаётся
допустимой короткой формой параметров обобщённого объявления. Формы не смешиваются:
если объявление использует `generic` в теле, угловых скобок в его заголовке нет;
если использует `param`, нет круглых скобок параметров.

Полная форма обязательна, если выполняется хотя бы одно условие: параметров
больше трёх (параметры времени компиляции и параметры вызова считаются отдельно; параметр с правом перед именем, `Access T`, — один параметр), есть значение
по умолчанию, есть пакет параметров `...`, у параметра есть условие `{ }` или несколько контрактов. Внутри угловых скобок блока `{ }`
нет.
Иначе канонична короткая форма; простое ограничение `<T: Comparable>` остаётся в
заголовке. Форма одна на всё объявление: если полная форма нужна хотя бы одному виду параметров, строками
`generic` и `param` пишутся оба вида (`fn process { generic T: Readable, Writable; param data: T }`). Отклонение в любую сторону получает диагностику стиля
`S.generic-parameter-layout`. У объявлений без тела, например `alias`, есть
только короткая форма.

### Базовый синтаксис

```efen
fn identity<T: Movable>(value: own T) -> T {
    return value
}

// Использование
let num = identity(42)       // T выводится как Int
let str = identity("hello")  // T выводится как String

// Тип можно указать явно
let explicit = identity<Int>(42)
```

### Множественные параметры типа

```efen
fn map<T, U>(items: [T], transform: (T) -> U) -> [U] {
    return items.map(transform).toArray()
}

// Использование
let numbers = [1, 2, 3]
let strings = map(numbers, (n) => String(n))
```

### Вывод типов

Компилятор может автоматически выводить параметры типа из аргументов:

```efen
let result = identity(42)  // T выводится как Int
let doubled = map([1, 2, 3], (x) => x * 2)  // T=Int, U=Int
```

<a id="дженерик-методы"></a>

## Обобщённые методы

Методы классов и методы, предоставляемые стратегиями, также могут объявлять
собственные параметры обобщённого объявления.

```efen
class Transformer {
    fn apply<T, U>(value: T, transform: (T) -> U) -> U {
        return transform(value)
    }
}

// Использование
let transformer = Transformer()
let text = transformer.apply(42, (number) => String(number))
```

`T` и `U` принадлежат методу `apply`, а не классу `Transformer`. Их значения
выводятся заново для каждого вызова метода.

<a id="дженерик-классы"></a>

## Параметризованные классы

Классы могут иметь параметры типа, которые применяются ко всему классу.

```efen
class Box<T: Movable> {
    conforms Constructible

    var value: T

    @constructor
    fn init(value: own T) -> Self {
        self.value = take value
    }

    fn getValue -> read T {          // заимствование self: в методе источник без пути — self
        return value
    }

    mut fn setValue(newValue: own T) {
        value = take newValue
    }
}

// Использование
let intBox = Box<Int>(42)
let stringBox = Box<String>("hello")

echo intBox.getValue()  // 42
```

Построением обобщённого класса управляет отдельный контракт времени компиляции
`ClassGenericDefinition`. Он не является разновидностью обычного
`ClassDefinition` и не переносит на него ответственность за создание экземпляров обобщённого объявления.

Сначала `ClassGenericDefinition` строит обобщённое объявление. При раскрытии
он получает конкретные аргументы времени компиляции и решает, создавать ли новый
реальный класс или использовать уже существующую физическую реализацию. Затем
обычный `ClassDefinition` достраивает выбранный реальный класс.

При стирании может существовать несколько реальных классов для разных групп
аргументов. Эти группы выбирает `ClassGenericDefinition`; компилятор не выводит
их автоматически из ветвлений или наблюдений над `T`.

<a id="наследование-с-дженериками"></a>

### Наследование с параметрами типов

```efen
open class Container<T: Movable> {
    conforms OpenClass

    var items: Vector<T> = []

    mut fn add(item: own T) {
        items.append(take item)
    }
}

class Stack<T: Movable>: Container<T> {
    mut fn push(item: own T) {
        add(take item)
    }

    mut fn pop -> own T? {
        if items.count > 0 {
            return items.removeLast()
        }
        return null
    }
}
```

<a id="дженерик-структуры"></a>

## Параметризованные структуры

Структуры поддерживают параметризацию с композицией типов.

```efen
struct Pair<T, U> {
    var first: T
    var second: U
}

// Использование
let pair = Pair<Int, String>(first: 42, second: "answer")
```

<a id="композиция-с-дженериками"></a>

### Композиция параметризованных типов

```efen
struct RefCounted<T> {
    var refCount: Int = 0
    var value: T
}

let value = RefCounted<String>(refCount: 1, value: "hello")
```

<a id="дженерик-интерфейсы"></a>

## Параметризованные интерфейсы

Интерфейсы также могут быть параметризованными типами.

```efen
interface Equatable<T> {
    fn equals(other: T) -> Bool
}

class Person {
    implements Equatable<Person>

    var age: Int

    fn equals(other: Person) -> Bool {
        return age == other.age
    }
}
```

## Ограничения типов

Параметры типа могут иметь ограничения для указания требований к типам.

```efen
contract Comparable<T> {
    fn compareTo(other: T) -> Int
}

// Базовое ограничение
fn compare<T: Comparable<T>>(left: T, right: T) -> Int {
    return left.compareTo(right)
}

// Множественные ограничения
fn process {
    generic T: Readable, Writable
    param data: T

    // T должен соответствовать обоим контрактам
}
```

## Множественные параметры типа

Функции, классы и другие конструкции могут иметь несколько параметров типа.

```efen
fn zip<T, U>(first: [T], second: [U]) -> [(T, U)] {

    return first.zip(second).toArray()
}

// Использование
let numbers = [1, 2, 3]
let letters = ["a", "b", "c"]
let zipped = zip(numbers, letters)  // [(1, "a"), (2, "b"), (3, "c")]
```

<a id="дженерики-в-алиасах-типов"></a>

## Псевдонимы с параметрами

Алиасы типов также могут быть параметризованными типами:

```efen
alias ValueOrError<T> = (T | Error)
alias Handler<T> = (T) -> Void
alias Transformer<T, U> = (T) -> U

// Использование
fn processData<T>(handler: Handler<T>) {

    // тело не важно для примера
}
```

<a id="compile-time-значения"></a>

## Значения времени компиляции

Параметр обобщённого объявления может быть любым значением времени компиляции. `Type` является одним
из допустимых типов параметра, а не отдельным механизмом параметризации. Параметрами также
могут быть значения перечисления, числа, строки, логические значения, источники (`origin`),
атрибуты, контракты, интерфейсы, стратегии, функции и другие декларации или
значения, доступные коду времени компиляции.

Категория параметра задаётся его типом:

```efen
generic T: Type
generic Requirement: Contract
generic RuntimeAPI: Interface
generic Annotation: Attribute
generic Policy: Strategy
generic Source: Origin
generic Size: Int
generic Access: Access
generic ...Ctx: Context
generic Name: Identifier
generic ...Fields: Field
generic Rules: Conditions<x: T>
generic Body: InlineClosure<(x: T) -> R>
generic F: FunctionType
```

Последние четыре вида описаны в разделе [«Поля, условия и код как параметры»](#поля-условия-и-код-как-параметры),
`Contract`, `Interface` и `Identifier` — в разделе [«Контракт как параметр»](#контракт-как-параметр), `Strategy` — в
разделе [«Стратегия как параметр»](#стратегия-как-параметр).

Имя интерфейса может использоваться в двух разных ролях. При
`generic T: Type` передаётся тип его значений времени выполнения; при `generic I: Interface` передаётся
объект времени компиляции объявления интерфейса, доступный рефлексии и генерации.
Контракт не является типом значения времени выполнения, но является допустимым значением времени компиляции для `generic C: Contract`.

Когда значение времени компиляции является параметром объявления типа, оно входит в
идентичность конкретного экземпляра обобщённого типа. Полная семантика, включая категории, заданные перечислением,
классификацию при выполнении и HIR-ключ, описана в
[типах с параметрами-значениями](types/value-parameterized-types.md).

```efen
class Adapter<Requirement: Contract, RuntimeAPI: Interface> {

    #if Self conforms Requirement
        // compile-time формирование реализации RuntimeAPI
    #endif
}
```

Перечисление, объявленное владельцем параметризованного типа, позволяет выбрать одну из его
реализаций без отдельной глобальной конструкции:

```efen
type ParticleColumns: Array<Particle, soa>
```

Здесь `Particle` — аргумент параметра типа `Element`, а `soa` — значение перечисления
внутри `Array`.
Конкретная инстанциация имеет одну определённое представление в памяти.
Запись `[T]` сокращает `Array<T>`: остальные параметры берут умолчания.

Полная форма позволяет явно указать тип параметра и значение по умолчанию:

```efen
struct Array {
    generic Element: Type
    generic Form: Representation = .aos
    generic indirection: Indirection          // умолчание зависит от типа элемента: текст ниже

    enum Representation {
        aos
        soa
    }

    enum Indirection {
        direct
        indirect
    }
}
```

`indirection` говорит, лежит ли в ячейке само значение (`direct`) или указатель на отдельно лежащее значение
(`indirect`). Умолчания: `aos`; у `indirection` оно зависит от типа элемента: `direct` у структуры, `indirect` у класса. Как объявление `Array` записывает такое умолчание, не решено. Третий параметр
называют по имени: `Array<Row, indirection: indirect>`. Подробно — [библиотеки на C](foreign.md#массивы).

Атрибут можно передать отдельным параметром:

```efen
class AnnotatedStorage<Element: Type, Annotation: Attribute> {
}

let values = AnnotatedStorage<Int, @myattr>()
```

Это отличается от атрибута внутри типового аргумента:

```efen
Array<@myattr Int>                 // T является аннотированным типом
AnnotatedStorage<Int, @myattr>    // @myattr является отдельным generic-аргументом
```

Параметры любого допустимого типа времени компиляции можно передавать позиционно и по
имени:

```efen
Array<Particle, soa>
Array<Element: Particle, Form: soa>
```

`soa` может быть записан без квалификации, когда ожидаемый тип параметра
однозначно указывает на перечисление, объявленный `Array`. Вне такого контекста имя
квалифицируется владельцем. Две одноимённые константы, подходящие ожидаемому
типу, создают ошибку неоднозначности, а не выбираются по порядку импортов.

Любой `generic` можно опустить в месте применения, если компилятор однозначно
выводит его значение из остальных аргументов, ограничений и сигнатур. Вывод не
является отдельным видом параметра. Если решений нет или их несколько,
компилятор требует именованный аргумент:

```efen
fn consumeInts<T: Iterable<Item: Int>>(items: T) {
    // Cursor выводится из выбранного соответствия T контракту Iterable.
}

fn consume<T: Iterable>(items: T) {

    // Item и Cursor выводятся из T, если соответствие единственно.
}
```

Выведенные параметры являются частью полной инстанциации и сохраняются в её
ключе так же, как явно написанные.

Значением `generic T: Type` является полное типовое выражение. Оно сохраняет
базовый тип, права и метаданные употребления:

```efen
Array<User>
Array<read Items.Item>
Array<@myattr Int>
Array<@cached User>
```

Ссылка бывает аргументом типа, только когда называет свой источник: `Vector<&read<pool> Int>`; `&read User` без
источника аргументом не бывает. Форму параметра решает написанное до подстановки: `x: T` — не параметр-ссылка `&`,
какой бы тип ни пришёл в `T`. Ссылка бывает типом поля, только где тип называет её источник (`Src: Origin`, запись
`holds`): `let item: &edit<Src[_]> Int`. В обобщённое объявление такой тип приходит членом `type` описания поля
([поле](#поле)), вместе с источником. Прежние `ref read User` и `shared read User` из языка убраны.
Право параметра типа функции (`claim`, `&out`, ссылка `&`, отношение к другому параметру) и форма его результата — части самого
типа функции: в обобщённое объявление они приходят только с параметром `F: FunctionType` и значением `Type` не
становятся ([тип функции](#тип-функции)). Имена параметров типа функции в значение не входят:
`Array<(acc: Int, x: Int) -> Int>` и `Array<(x: Int, acc: Int) -> Int>` — один экземпляр, и у типа его элемента имён
нет.

Эти аргументы образуют разные экземпляры обобщённого объявления. Код может получить базовый
тип отдельно, но `T` по умолчанию не стирает его модификаторы и метаданные.
Метаданные задают дополнительные свойства типа и сами по себе не меняют
совместимость значений: `@myattr Int` совместим с `Int`. Разные инстанциации
нужны потому, что обобщённый код может наблюдать опции и породить разный код.

Метаданные проверяются оператором `has`. Оператор допустим и в обычном выражении,
и в директиве времени компиляции. `#if` выбирает код при построении инстанциации:

```efen
#if T has @myattr
    // Код существует только для типового аргумента с @myattr.
#endif

if value has @myattr {
    // Runtime-проверка metadata значения там, где она сохраняется в runtime.
}
```

Поскольку код времени компиляции может наблюдать метаданные, они входят в ключ
инстанциации и в зависимости её результата.

### Угловые скобки и выражения

Список аргументов обобщённого объявления открывает `<`, прижатый слева к имени: `Box<Int>`,
`identity<Int>(42)`. Сравнение отделяет `<` пробелом слева, поэтому разбор не
зависит от того, что обозначает имя, и `f(a < b, c > (d))` передаёт два
сравнения, а `f(a<b, c>(d))` — один вызов с аргументами времени компиляции.

Запись `<...`, то есть `<` и сразу три точки, лексер делит на `<` и раскрытие
`...`: `Tuple<...Elements>`. Интервал `<..` получается, только если после двух
точек нет третьей: `a<..b`.

Внутри угловых скобок списка знак, содержащий `<` или `>`, пишется только в скобках: сравнения,
сдвиги, `<=>` и диапазоны `..<`, `<..`. Первая `>` вне скобок закрывает список,
а `>>` — два вложенных списка:

```efen
Buffer<Size: (1 << 4)>
Choice<Flag: (a > b)>
Array<Array<Int>>

Buffer<Size: 1 << 4>     // ошибка синтаксиса: сдвиг без скобок
```

Угловые скобки всегда прижаты: `<` — к имени и к первому аргументу, `>` — к
последнему аргументу. Пробелы внутри списка допустимы только после запятой и
двоеточия. Пробел у скобки внутри списка смысл не меняет и получает
диагностику стиля `S`. Пробел между именем и `<` делает знак сравнением, и
такой код разбирается как сравнение:

```efen
Map<String, Int>         // каноническая запись
Array< Int >             // S: угловые скобки не прижаты
Array<Array<Int> >       // S: угловые скобки не прижаты
Box <Int>(42)            // сравнение Box < Int > (42): ошибка, цепочка сравнений
```

## Поля, условия и код как параметры

Обобщённому объявлению, которое строит код, служат четыре вида значений времени компиляции: описание поля, блок
условий, кусок кода и тип функции. Все четыре — обычные параметры: они входят в ключ инстанциации и подчиняются общим
правилам параметров. Объявление с таким параметром проверяется в два шага. У объявления проверяется то, что от
аргумента не зависит: запись, имена, места раскрытий. У каждой инстанциации — всё, что аргумент определяет: типы и
права его частей, FLOW, исключения, условия.

| Вид | Объявление | Что передают | Где применяют |
|---|---|---|---|
| поле | `generic F: Field`, `generic ...Fields: Field` | строку объявления поля | строка тела структуры, доступ `value.${F.name}` |
| условия | `generic Rules: Conditions<x: T>` | блок строк условий над названными именами | `requires`, `ensures`, `invariants`, блок `{ }` поля |
| код | `generic Body: InlineClosure<(x: T) -> R>` | кусок кода с параметрами | вызов `Body(x: e)` в теле: код встраивается |
| тип функции | `generic F: FunctionType` | тип функции | сигнатура объявления: `F.kind`, `...F.arguments`, `F.result`, `F.effects` |

### Поле

`Field` — значение времени компиляции из `lang::`: описание одного поля. Аргумент пишется строкой объявления поля в
фигурных скобках:

```efen
struct Record {
    generic ...Fields: Field
    ...Fields                                   // каждая строка пакета становится полем

    #if Fields.all(f => f.type conforms Copyable)
        conforms Copyable                       // тип каждого поля копируется
    #endif
}

alias Point = Record<{ var x: Int }, { var y: Int }>
let p = Point(x: 1, y: 2)
```

Части строки `пометки слово имя: &право<источник> Тип = значение { условие }` (`&` — у ссылки) читают члены `Field`; `T` в таблице — тип
поля:

| Член | Тип | Что это |
|---|---|---|
| `name` | `Identifier` | имя поля |
| `mutable` | `Bool` | `true` у `var`, `false` у `let` |
| `type` | `Type` | тип поля, как он записан: вместе с `&`, правом и источником. Ссылочная форма (`&edit<Src[_]> Int`) бывает здесь, у аргумента `generic T: Type` её нет |
| `access` | `Access?` | право перед типом (у ссылки — после `&`): `own`, `read`, `edit` или `mut`; `null`, когда права нет |
| `source` | `Origin?` | источник из записи `право<источник>` перед типом; `null`, когда такой записи нет |
| `default` | `InlineClosure<() -> T>?` | значение по умолчанию: [кусок кода](#код) без параметров |
| `condition` | `Conditions<value: T>?` | условие `{ }` поля: [блок условий](#условия) с именем `value`; `previous(value)` в нём — значение поля до записи |
| `attributes` | `[Attribute]` | атрибуты строки |

- `...Fields` строкой тела раскрывает пакет в объявления полей в его порядке. Имена полей в пакете различны и не
  совпадают с остальными членами типа; совпадение — ошибка у инстанциации. Объявление со своими членами, которое
  принимает поля с чужими именами, держит пакет в поле типа-записи, `var state: Record<...Fields>`: имена пакета
  тогда — члены записи, и с членами объявления они не встречаются ([пример](#код)).
- Поле читают по имени из параметра: `value.${F.name}`. Такое чтение пишется в теле объявления, у которого есть
  параметр `F`, разрешается в каждой инстанциации и имеет тип `F.type`; вне такого тела `${…}` определён только в
  цитате `efen::code { }`. Обойти пакет можно функциями времени компиляции (`map`,
  `filter`, `all`, `any`) и раскрытием в коде, который строит метафункция.
- Условие пакета — блок `{ }` у его строки. Как контракт у пакета, оно относится к каждому аргументу, и `value` в
  нём — одно поле: `generic ...Fields: Field { value.type conforms Copyable }`. Контрактом пакет полей не
  ограничивают: `Field` — описание поля, а не тип. Условие на пакет целиком — строка `invariants` или `requires`:
  `Fields.count > 0`.
- Источник поля с заимствованием или ссылкой называют так же, как аргумент параметра `Origin`, и разрешается он там, где
  аргумент написан: `{ let items: read<data> Vector<Int> }` заимствует `data`, как `Src: data`. Каждый различный
  источник в аргументах-полях, перед типом поля или внутри него (`Vector<read<g> Vertices.Item>`), — параметр-источник
  инстанциации, как `Src: Origin`, написанный в заголовке: значение не переживает источник, заимствования считаются
  по каждому источнику отдельно, а функция с таким результатом называет источник в его типе
  ([владение](types/ownership.md#ссылки-только-внутри-функции)). `self` в источнике — `self` места, где аргумент
  написан, а не структуры, которая раскроет пакет: [поле-псевдоним](types/ownership.md#поле-псевдоним) аргументом не
  пишут.
- Тега видимости у поля из пакета нет, как у любого поля структуры: поле видно там, где виден тип
  ([видимость](visibility.md)). Поля скрывает тип `opaque` ([типы со скрытой реализацией](types/type.md#opaque-типы)).
- Значение по умолчанию в аргументе — кусок кода, блок условия — блок условий, и правила у них те же: значений места,
  где аргумент написан, они не называют.
- Описание поля — всегда такая строка. Поле, которое строит компилятор или метафункция, имеет ту же форму: имя —
  идентификатор, тип — тип Efen. Имён и типов, которые нельзя написать в исходном тексте, у полей не бывает.
- Форма с полями, копирование, уничтожение и условия типа считаются по раскрытым полям, как у структуры с
  написанными полями: такой тип ничем от неё не отличается.

### Условия

`Conditions<x: T>` — блок строк условий той же формы, что `invariants { }`: строки соединяются `&&`, `if` внутри —
импликация ([условия](conditions.md#условия-значений-и-invariants)). В угловых скобках — имена, которые строки читают,
и их типы: `Conditions<i: Int, n: Int>`. Аргумент — блок с этими именами:

```efen
struct Bounded<Rules: Conditions<value: Int>> {
    var count: Int { Rules(value: value) }      // условие поля
}

var b = Bounded<{ value >= 0 }>(count: 3)
b.count = -1                                    // ошибка: условие поля count, value >= 0

fn pick<Rules: Conditions<i: Int, n: Int>>(items: read [Int]) -> Int
    ensures Rules(i: result, n: items.count)
{
    return 7
}

let at = pick<{ 0 <= i && i < n }>(items: xs)   // 7 < xs.count не доказано: заметка Proof, проверка на возврате
let x = xs[at]                                  // проверки границ нет: строку проверил возврат из pick
```

- Блок прикрепляется там, где пишут строку условия: `requires Rules(x: e)`, `ensures Rules(x: e)`, строкой
  `invariants { Rules(x: e) }`, блоком `{ Rules(value: value) }` поля. Вызов `Rules(x: e)` подставляет выражения
  вместо имён и служит строкой или её частью: `ensures throws E ==> Rules(x: e)`. `result` и значение до вызова блок
  получает аргументами, `Rules(i: result, n: previous(count))`; `taken` и `written` в блок не входят.
- `previous` пишут и в строке блока, над его именами: `{ value >= previous(value) }`. Это значение до шага, а шаг
  задаёт место, где блок прикрепили: запись поля, вызов у `ensures`, метод у строки `invariants`
  ([`previous`](conditions.md#previousx)). У `requires` шага нет: блок с `previous`, который объявление прикрепляет
  как `requires`, — ошибка у инстанциации. Ошибка у инстанциации и подстановка, которая даёт форму, запрещённую
  [условиями](conditions.md#previousx): `previous(result)` (блок `{ i >= previous(i) }` прикреплён как
  `ensures Rules(i: result)`) и вложенный `previous` (аргумент `previous(count)` в блок с `previous(n)`); диагностика
  называет строку блока и место прикрепления. Строка `invariant` цикла блоком не прикрепляется.
- Кроме своих имён, строки видят только объявления, видимые там, где блок написан: константы и чистые функции
  ([вызов функции в условии](conditions.md#вызов-функции-в-условии)). Переменных этого места и имён места, где блок
  прикрепили, они не видят.
- Подставленная строка — обычная строка этого места в инстанциации: её доказывают, проверяют и печатают по
  правилам [условий](conditions.md). `requires` доказывает вызывающий; `ensures`, строку `invariants` и условие поля —
  код инстанциации: на выходах, в точках восстановления и на записях. Недоказанная строка получает заметку `Proof` и
  проверяется при выполнении там же, где проверялась бы строка, написанная на этом месте; фактом она служит на тех
  же условиях. Ошибка называет строку в аргументе и место, где её прикрепили.
- Объявление проверяется без строк аргумента: у вызова `Rules(x: e)` сверяются только имена и типы. Его тело
  доказывается у каждой инстанциации, где строки известны.
- Своего блока `{ }` у строки `generic Rules: Conditions<x: Int>` нет. Строку, на которую опирается само объявление,
  оно пишет рядом с блоком: `requires x >= 0` и `requires Rules(x: x)`.

### Код

`InlineClosure<(x: T) -> R>` — кусок кода с параметрами и результатом. Аргумент — литерал `inline`
([синтаксис](compile-time/metafunctions.md#синтаксис)):

```efen
fn fold<Step: InlineClosure<(acc: Int, x: Int) -> Int>>(items: read [Int]) -> Int {
    var acc = 0
    for x in items {
        acc = Step(acc: acc, x: x)              // код встраивается здесь
    }
    return acc
}

let sum = fold<inline (acc: Int, x: Int) -> Int { acc + x }>(items: [1, 2, 3])
```

- Вызов `Step(acc: acc, x: x)` встраивает код, а работает как вызов функции с параметрами, которые пишет тип
  `Step`: метка — имя параметра из этого типа, аргумент без метки идёт по месту. Каждый аргумент вычисляется один
  раз, в обычном [порядке аргументов](functions.md#порядок-вычисления-аргументов), и связывается с параметром по его
  форме: `own` — перенос, `mut` и `edit` — заимствование на время работы куска (у копируемого типа — копия), `&` —
  ссылка на место аргумента. Встраивание меняет место кода, а не
  смысл вызова.
- Кусок называет свои параметры, свои локальные переменные и объявления, видимые там, где он написан: типы,
  константы, функции, параметры обобщённых объявлений. Имена разрешаются и проверяются на видимость там же, поэтому
  кусок вызывает закрытую функцию своего модуля, хотя встроен в код другого пакета.
- Локальную переменную, параметр вызова и `self` места, где он написан, кусок не читает и не пишет, и строк
  `capture` в нём нет: аргумент обобщённого объявления — значение времени компиляции, и значению времени выполнения в
  нём храниться негде. Имя такой переменной в куске бывает только источником в типе: `read<step> Int`.
- Имён места вставки, его `self` в том числе, кусок не видит, а его собственные имена в это место не попадают.
- `return` выходит из куска с его результатом. `break` и `continue` относятся только к циклам внутри куска. `yield`
  в куске вызывает ошибку: кусок — не генератор.
- Тип куска сверяется с типом параметра у инстанциации: права, типы и результат — по местам. Литерал `inline` в
  аргументе называет параметр так же, как тип параметра на этом месте, если тип пишет имя: связывание по метке и по
  месту тогда совпадает. Другое имя — ошибка у инстанциации. Параметры, которые тип получил раскрытием
  (`...F.arguments`), имён не несут, и литерал называет их сам.
- Связывание аргументов с параметрами, права, FLOW и исключения проверяются в месте вставки, у каждой инстанциации,
  как у вызова функции, тело которой видно. Ошибка называет строку куска и место вставки.
- Эффекты куска (`throws`, контексты, состояния, ожидание) — эффекты места вставки: сводка функции собирается после
  вставки. Допустим ли эффект, решают правила этого места.
- Стратегии для операций куска выбираются там, где кусок написан, как разрешаются его имена: по `provide` пакета,
  который его написал, и по строке `provide P for X` обобщённого объявления, внутри которого он написан. Строка
  `provide` объявления, в которое кусок встроен, на него не действует: `x < y` в куске сравнивает так, как сравнил
  бы код рядом с ним.

Состояние кусок получает только параметрами. Объявление, которое даёт куску своё состояние, передаёт его аргументом:

```efen
struct Machine {
    generic ...State: Field
    generic Step: InlineClosure<(state: mut Record<...State>, input: Int) -> Int>
    var state: Record<...State>                 // имена пакета — члены записи, а не Machine
}

strategy for Machine<...State, Step> {
    generic ...State: Field
    generic Step: InlineClosure<(state: mut Record<...State>, input: Int) -> Int>

    mut fn feed(input: Int) -> Int {
        return Step(state: state, input: input) // состояние передано параметром
    }
}

alias Total = Record<{ var total: Int }>

var counter = Machine<{ var total: Int }, inline (state: mut Total, input: Int) -> Int {
    state.total += input
    return state.total
}>(state: Total(total: 0))
let six = counter.feed(input: 6)
```

Пакет `State` кончается на первом аргументе другого вида, поэтому кусок кода достаётся параметру `Step`
([запись аргументов](#запись-аргументов)).

### Тип функции

`FunctionType` — вид параметра из `lang::`, аргумент которого — [тип функции](types/function-type.md). Объявление
читает части типа и повторяет его сигнатуру в своей:

```efen
contract Handler<F: FunctionType> {
    F.kind fn handle(...arguments: F.arguments) -> F.result F.effects
}

fn traced -> F.result F.effects {
    generic F: FunctionType
    generic Body: InlineClosure<(...F.arguments) -> F.result>
    param ...arguments: F.arguments             // право и тип каждого — от параметра F

    print("call")
    let result = Body(...arguments)             // каждый аргумент — по правилу параметра, которому достался
    print("done")
    return result                               // вызов и return без &: форма result приходит с F.result
}

let three = traced<(Int) -> Int, inline (x: Int) -> Int { x + 1 }>(2)
```

| Член | Тип | Что это |
|---|---|---|
| `kind` | `Access` | вид вызова: `read`, `mut` или `own` ([вид замыкания в типе](closure.md#вид-замыкания-в-типе)) |
| `parameters` | `[FunctionParameter]` | параметры по порядку |
| `receiver` | `Type?` | тип объекта, если запись `holds` называет `self` ([замыкания и память](closure.md#замыкания-и-память)); иначе `null` |
| `arguments` | `[FunctionParameter]` | что передаёт вызов: получатель, если он есть, с самым широким правом, которое запись даёт `self`, затем `parameters` |
| `result` | `FunctionResult` | результат |
| `effects` | `SignatureTail` | хвост типа целиком: слова хвоста и строки условий после результата |
| `holding` | `[HeldSource]` | запись `holds` перед типом: [что держит значение](types/function-type.md#что-держит-замыкание) этого типа |

`FunctionParameter` — описание параметра: форма, право и тип, как они записаны (`mut Pool`, `own T`, `&out Int`,
`&edit Int`), и отношение к другому параметру, если оно есть (`claim<pool> SlotBlock`, `read<dst?> T`,
`&edit<values[_]> Int`). `FunctionResult` — описание результата: форма — значение (`-> Shape?`), заимствование
(`-> edit<list> Shape?`) или ссылка (`-> &edit<list[_]> Shape?`), тип, а у заимствования и ссылки ещё право и
источник. Другой параметр той же сигнатуры назван в них номером.
Значением `Type` они не служат: право `claim`, форма `&` и отношение значат что-то только в сигнатуре, а форму
аргумент `generic T: Type` не несёт ([значения времени компиляции](#compile-time-значения)). Поэтому их ставят только раскрытием на своё место в
сигнатуре. Записать их типом в другом месте — ошибка у объявления: `Tuple<...F.parameters>`, `Array<F.result>`,
`let r: F.result`. Описанием поля параметр тоже не служит: слова `let` или `var`, значения по умолчанию и блока
условия у него нет.

Имя параметра в `F` не входит: тождества типа оно не меняет, и `(n: Int) -> Int` и `(Int) -> Int` — один `F`. Имена —
часть записи типа ([грамматика](types/function-type.md#грамматика)), и компилятор читает их там, где тип функции
записан, прямо или через псевдоним, типом переменной, поля, параметра или результата, прототипом функции или видом
параметра-кода (`InlineClosure<(acc: Int, x: Int) -> Int>`, [код](#код)). Там они дают
[неявные параметры хвостового замыкания](closure.md#неявные-параметры-хвостового-замыкания), метки в вызове значения
и имена параметров [функции из прототипа](functions.md#функция-из-прототипа). У значения
`step: (acc: Int, x: Int) -> Int` вызов `step(x: 3, acc: 10)` разбирается как вызов функции: аргументы вычисляются в
порядке записи, и метка называет параметр, которому аргумент достаётся, — `x` получает 3, `acc` — 10.

Через параметр обобщённого объявления имена параметров типа функции не проходят: тип функции, переданный значением
`Type` или `FunctionType`, их не несёт. Имя как значение передаёт параметр вида `Identifier`
([контракт как параметр](#контракт-как-параметр)). `Vector<(acc: Int, x: Int) -> Int>` и `Vector<(x: Int, acc: Int) -> Int>` — один тип, и у его элемента
имён нет, какая бы из двух записей ни встретилась первой. Нет их и у результата обобщённой функции, тип которого — её
параметр: `identity(take step)`. Вызов такого значения с метками — ошибка с подсказкой передать аргументы по местам;
молча по местам он не разбирается. Неявных параметров у хвостовой формы `=>` при таком ожидаемом типе нет: замыкание
объявляет параметры явно. Внутри обобщённого объявления имён нет и у `F`: параметры, раскрытые из `F`, меток не
несут, а правило «имена у всех параметров или ни у одного» относится к параметрам, которые тип пишет сам.

`HeldSource` — один источник из записи `holds`: `access: Access`, право, с которым значение его держит, и
`source: Origin`. Источник называют так же, как аргумент параметра `Origin`, и разрешается он там, где тип записан; у
инстанциации над `F` он — параметр-источник, как [источник поля](#поле). Источник с `self` параметром-источником не
становится: объект приходит в вызов получателем.

- Каждый член входит в тождество `F`, а с ним в ключ инстанциации: `holds mut<log> (Int) -> Void` и `(Int) -> Void` — два
  типа, как и типы одной сигнатуры, из которых один держит `self`, а другой — переменную. Хвост входит целиком:
  `(own T) -> Void nofail` и `(own T) -> Void` — разные `F`.
- `F.kind` — значение `Access`; его пишут там, где пишут право, как параметр права: `F.kind fn handle`,
  `state: F.kind Record<...Fields>`.
- Сигнатуру `F` объявление или тип повторяет раскрытием: `...F.arguments` или `...F.parameters` в списке параметров,
  `F.result` на месте результата, `F.effects` после него. Список раскрывают целиком и один раз; до и после него
  сигнатура пишет свои параметры: `(first: Int, ...F.arguments) -> F.result`. `F.result` пишут только в сигнатуре,
  которая раскрыла список той же `F`, `F.effects` — только после `F.result`. Элемент списка, его часть и список после
  `map` или `filter` на место параметра не ставят; число параметров читают: `F.parameters.count`. Нарушение — ошибка
  у объявления.
- Тело объявления над `F` проверяется у каждой инстанциации, как место вставки [куска кода](#код): права и типы
  элементов пакета, результат, исключения и строки условий известны только там. Результат вызова с типом `F.result`
  тело возвращает сразу или держит в локальной переменной без записанного типа, `let result = Body(...arguments)`.
  Вызов и `return` пишутся без `&`: `F.result` — весь результат, и форму (значение, заимствование или ссылку) он
  приносит с собой. У инстанциации переменная хранит значение, псевдоним или ссылку, и правила у неё общие
  ([что можно с результатом](types/ownership.md#что-можно-с-результатом)).
- В объявлении список раскрывают пакетом значений, `param ...arguments: F.arguments`
  ([пакеты значений](#pack-значений)): у `arguments[i]` право, отношение и тип из `F.arguments[i]`.
- `...arguments` в вызове раскрывает пакет в аргументы по порядку. Каждый связывается с параметром, которому достался,
  по общим правилам вызова, и форму аргумента задаёт этот параметр: в параметр `own` элемент переносится, как при
  `take`; в параметр `claim` передаётся записью `claim`; в параметр `&out` — записью `&out`, тем же слотом; в параметр-ссылку (`&edit T`) —
  записью `&`, тем же местом; в остальные — с правом принимающего параметра. Дать элемент может не больше, чем даёт его собственный параметр.
- Поэтому пакет одного типа передают в параметры другого, когда каждый параметр принимает то, что пакет передаёт на
  его месте. Элемент `mut` идёт в параметр `read` или `edit`. Элемент `claim<p>` идёт простым аргументом в параметр
  `mut` или `read<q>`, когда `p` передан в `q`, а элемент `claim T` — в параметр `mut T`: записью `claim` параметр
  `claim` передают только в параметр того же вида
  ([право на элемент](memory/layout/functions.md#82-право-на-элемент), правило 8), а простым аргументом — как любой
  указатель. Элемент `own`, переданный в параметр без `own`, одолжен на время вызова: он остаётся у функции, которая
  его передала, и кончается в ней по общим правилам. Элемент, который параметр принять не может, — ошибка у
  инстанциации.
- Номер параметра после раскрытия значит параметр, раскрытый из `F.parameters` под этим номером: в отношении
  (`claim<pool> SlotBlock`), в источнике результата (`-> &edit<list[_]> Shape?`), в записи `holds` параметра-функции
  (`less: holds edit<items> (Int, Int) -> Bool`) и в строках условий. Поэтому объявление с результатом `F.result`
  возвращает ссылку по общему правилу, `return` без `&`: её источник — параметр, записанный в сигнатуре
  ([ссылка в результате функции](types/ownership.md#место-в-результате-функции),
  [ссылка в результате типа функции](types/function-type.md#ссылка-в-результате-типа-функции)).
- `F.effects` — весь хвост: слова хвоста сигнатуры (`state`, `in`, `without`, `throws`, `throws only`, `nothrows`,
  `nofail`) и строки `requires` и `ensures`; ни одно из них не опускается. Раскрытый хвост — нижняя граница: вывод
  добавляет к нему требования тела, как к любому записанному хвосту непубличной функции. Собственные строки
  `requires` и `ensures` объявления добавляются к раскрытым. Блоком `Conditions` строки типа не служат: в них бывают
  `result`, посылка `throws E ==>` и `taken`.
- Рядом с `F.effects` объявление может добавить свои `throws E`, `in X` и `state`. Добавленное объединяется с
  раскрытым внутри его границ:

  | Раскрытый хвост | После добавления `throws E` |
  |---|---|
  | `throws A` | `throws A, E` |
  | `throws only A` | `throws only A, E` |
  | `nothrows` | `throws only E` |
  | `nofail` | `throws only E`; отказов по-прежнему нет |

  Добавленный `in X` при раскрытом `without X` и добавленное состояние по оси, которую раскрытый хвост уже
  называет, — ошибки у инстанциации. У публичного объявления хвост зафиксирован
  ([сводка вызова](types/function-type.md#сводка-вызова-вычисляемая-компилятором)): инстанциация, в которой
  добавление меняет `nofail`, `nothrows` или `throws only` раскрытого хвоста, — ошибка у этой инстанциации; она
  называет публичный символ.

  ```efen
  fn timed -> F.result F.effects throws TimeoutError {
      generic F: FunctionType
      generic Body: InlineClosure<(...F.arguments) -> F.result>
      param ...arguments: F.arguments
      return Body(...arguments)
  }
  ```
- `under` в хвост не входит: это не слово типа, а пометка параметра-тела блока, `condition: () -> T? under self`
  ([ожидание условия](shared.md#ожидание-условия)). Она называет параметр или получателя функции, которая этот
  параметр объявила, и задаёт правила места: аргумент — только литерал, его тело проверяется как тело блока `with`,
  а вызывают параметр только внутри такого блока. Тип с `under` бывает только у такого параметра. Аргументом
  `FunctionType`, как и любого параметра обобщённого объявления, он не служит: ошибка у записи.
- Хвост — предел для значения типа: значение с бо́льшими `throws`, контекстами или состояниями к типу не подходит
  ([сводка вызова](types/function-type.md#итоговая-compile-time-сводка-callable)). Эффекты ожидания у параметра,
  который функция только вызывает, то есть параметра без права `own`, язык из этого предела исключает. Тип, который
  их не пишет, их не ограничивает, и эффекты ожидания переданного значения получает место вызова этой функции
  ([эффекты ожидания](shared.md#эффекты-ожидания), «Функции в параметрах»). Это правило вызова, а не член `F`: `F`
  такого параметра — записанный тип, эффектов ожидания аргумента в нём нет, и в ключ инстанциации над ним они не
  входят. Контекст ожидания, записанный в типе, — слово хвоста, как остальные: `() -> Void in Suspending` и
  `() -> Void` — разные `F`.
- Имена в раскрытых строках `requires` и `ensures` значат то же, что в типе: параметр — параметр под тем же номером,
  `result` — результат сигнатуры, источник из `F.holding` — тот же источник, поле объекта у типа с получателем —
  поле получателя, первого в `F.arguments`. Сигнатура, которая раскрыла `...F.parameters`, получателя не имеет:
  строка про поле объекта в ней — ошибка у инстанциации.
- Строка про источник доказывается по общим правилам [условий](conditions.md). Проверить её при выполнении может
  только код, которому память источника видна: через поле или параметр, которые этот источник заимствуют.
  Недоказанная строка, которую проверить нечем, — ошибка, а не заметка `Proof`: у вызова для `requires`, у
  инстанциации для `ensures`. Другая сторона вызова на такую строку полагается.

### Запись аргументов

- Поле и блок условий пишут в фигурных скобках, кусок кода — литералом `inline`, тип функции — как тип. Литерал
  разбор узнаёт по записи, без объявления: одна строка объявления `let` или `var` с типом в скобках — поле, иначе в
  скобках строки блока условий.
- Фигурные скобки аргумента и тела литерала `inline` — скобки для правила
  [угловых скобок](#угловые-скобки-и-выражения): `<` и `>` внутри них список не закрывают, и сравнение там пишут без
  круглых скобок, `Bounded<{ value >= 0 }>`.
- Аргументом бывает и имя, и раскрытие пакета: `Step` и `...State` в цели `strategy for Machine<...State, Step>`. По
  записи их вид не виден: вид имени — вид того, что оно обозначает. Поэтому аргументы по параметрам распределяет не
  разбор, а проверка, когда объявление известно.
- Пакет собирает позиционные аргументы, которые принимает его вид, пока они идут подряд. Первый аргумент другого
  вида пакет заканчивает и достаётся следующему параметру: в
  `Machine<{ var total: Int }, inline (state: mut Total, input: Int) -> Int { state.total }>` кусок кода — аргумент
  `Step`.
- Параметр после пакета, аргумент которого принял бы и пакет, передают по имени. Это параметр того же вида и параметр
  `F: FunctionType` после пакета `...Ts: Type`: тип функции — тоже тип, и `Pipeline<Int, String, F: (Int) -> String>`
  без имени `F` отдал бы все три аргумента пакету.

### Идентичность и стирание

- Поле, блок условий, кусок кода и тип функции входят в ключ инстанциации нормализованной формой HIR после
  разрешения имён и подстановки аргументов объемлющего дженерика; имена сравниваются по объявлению, а не по тексту:
  `inline (x: T) -> T { x }` внутри `g<T>` даёт разные ключи у `g<Int>` и `g<String>`. Аргументы,
  которые различаются только пробелами, переносами и комментариями, дают один экземпляр. Аргументы, разные по форме,
  дают разные экземпляры, даже когда значат одно: `{ x >= 0 }` и `{ 0 <= x }`. Источник поля и источник из записи `holds`
  перед типом функции входят в ключ значением `Origin`, как аргумент `Src: data`. Имена параметров типа функции в
  ключ не входят. Аргумент `Identifier` входит в ключ текстом имени. Не входит в него и место, где аргумент
  записан: одинаковые аргументы в двух файлах дают один экземпляр.
- Диагностика компиляции об экземпляре — ошибка у инстанциации, заметка `Proof` о строке блока или куска — выдаётся
  у каждого места, где экземпляр записан, и называет строки аргументов этой записи. Тело у экземпляра одно, поэтому
  запись остановки, трасса стека и отладочные сведения о строках аргумента в этом теле называют одно из таких мест;
  какое, выбирает компилятор, и при повторной сборке той же программы выбор тот же.
- `@erase` по блоку условий допустим, когда объявление прикрепляет блок только как `requires`. Такую строку
  доказывает или проверяет вызывающий, в коде которого блок известен. Общее тело строк блока не знает: `Rules(x: e)`
  для него — условие без содержания, верное для значений, с которыми оно пришло.
- Вызвать с этим блоком общее тело может только функцию, которая тоже `@erase`, и только когда каждую её строку
  `requires` с блоком даёт строка `requires` самого тела: тот же блок над теми же значениями, как
  `requires Rules(x: v)` у тела и вызов `inner<Rules>(x: v)`. Следствий из строки тело не выводит.
- Остальное — ошибка у объявления с `@erase`. Общее тело не может ни доказать, ни проверить строку `ensures`, строку
  `invariants`, условие поля, которое оно пишет, и `requires` вызываемой функции над другими значениями. Функцию без
  `@erase` оно с этим блоком не вызывает: у такой функции своё тело на каждый блок.
- `@erase` по пакету полей и по куску кода запрещён: от полей зависят размер и раскладка значения, а код
  встраивается, и у каждой инстанциации своё тело. Так же запрещён `@erase` по типу функции у объявления, которое
  раскрывает его сигнатуру: число, права и типы параметров у каждой инстанциации свои. Скрытой таблицы операций над
  полями компилятор не строит ([генерация кода](#генерация-кода)). Общую форму для значений с разными полями пишет
  библиотека: тип, который хранит адрес значения и таблицу его операций, как значение типа функции в рантайме
  ([что компилятор берёт у рантайма](runtime/lang-roles.md)).

## Контракт как параметр

Параметр вида `Contract` принимает объявление контракта
([значения времени компиляции](#compile-time-значения)). Имя такого параметра пишут там, где пишут имя контракта.
Общее правило: всё, что компилятор видит при компиляции, видит и код — члены контракта, имена, интерфейсы.

| Вид | Объявление | Что передают | Где применяют |
|---|---|---|---|
| контракт | `generic C: Contract`, `generic ...Marks: Contract` | контракт, как справа от `:` в ограничении | ограничение `T: C`, выражение `T conforms C`, строка `conforms C` |

### Контракт

```efen
contract Persistent { }

struct Tagged {
    generic T: Type
    generic ...Marks: Contract
    var value: T

    conforms ...Marks.filter(m => T conforms m)     // пометки, которые есть у T
}

let a = Tagged<Int, Copyable, Persistent>(value: 1) // Copyable — да, Persistent — нет
```

Аргумент — контракт в той записи, какую принимает ограничение: имя или имя с аргументами, `Iterable<Item: Int>`.

- **Ограничение.** `generic T: C` и `T conforms C` требуют, чтобы тип соблюдал переданный контракт. Проверяет
  это инстанциация, с выбором стратегий пакета, который её создал
  ([тело обобщённого объявления](strategies.md#тело-обобщённого-объявления)). Ложное ограничение запрещает
  инстанциацию.
- **Члены видны.** Всё, что видит компилятор, видит и код при компиляции: тело с параметром `C` вызывает у `T` члены
  переданного контракта (`x.name()` при `C = Named`). Такое тело проверяется в каждой инстанциации, как тело с
  полем или куском кода; ошибка стоит у инстанциации и называет строку тела.
- **Одно имя в двух контрактах.** Член, который есть и в записанном контракте параметра, и в переданном
  (`T: Comparable<T>, C` при `C = Ordered`, оба с `compareTo`), тело вызвать не может: ошибка неоднозначности у
  инстанциации, она называет оба контракта и строку вызова. Записи, которая выбирает контракт у вызова, нет:
  с такой парой контрактов объявление не инстанцируется, пока его тело вызывает этот член.
- **Соответствие.** Строка `conforms C` объявляет, что тип соблюдает переданный контракт. Проверяется она у
  каждой инстанциации: члены типа, в том числе поля из пакета, выполняют каждое требование аргумента. Ошибка
  называет невыполненное требование, строку `conforms` и место, где записан аргумент. Контракт с
  `allow implementations` получает реализацию извне по общему правилу
  ([реализация извне](contracts.md#реализация-извне)).
- Аргумент для `conforms C` называет каждый параметр контракта, у которого нет умолчания; иначе ошибка у
  инстанциации. Знака `_` в аргументе нет.
- Контракт для классов, который реализуют блоком `implementation`, аргументом ограничения и соответствия не
  служит: ошибка у инстанциации ([классы в контракте](contracts.md#классы-в-контракте)).
- **Пакет.** `...Marks: Contract` собирает аргументы-контракты; `Marks` — массив `[Contract]`, его обходят `map`,
  `filter`, `all`, `any`. `conforms ...Marks` раскрывается в строку `conforms` на каждый элемент; повтор контракта
  учитывается один раз. Ограничение по пакету — условие параметра:
  `generic T: Type { Marks.all(m => value conforms m) }`. Записи `generic T: ...Marks` нет.
- Членов у значения `Contract` нет. Два контракта сравнивают: `C == D`.
- В ключ инстанциации контракт входит объявлением и каноническими аргументами: `Iterable<Int>` и
  `Iterable<Item: Int>` — одно значение. Стратегии, выбранные для ограничения с `C`, входят в ключ, как у любого
  ограничения ([идентичность и HIR](types/value-parameterized-types.md#идентичность-и-hir)).
- `@erase` по `C` допустим, когда `C` стоит только в ограничениях сигнатуры и тело не вызывает ни одного члена
  через `C`: ограничения доказывает вызывающий, а реализацию членов общее тело получить не может — стирание её не
  передаёт. Вызов члена через `C`, `#if` над `C` и строка `conforms C` в объявлении с `@erase` — ошибки у
  объявления.

- **Интерфейс-параметр.** `generic I: Interface` пишут в строке `implements I` по тем же правилам, что `conforms C`:
  проверка у каждой инстанциации.
- **Имя как параметр.** `generic Name: Identifier` принимает имя и читает член `value.${Name}`, и объявляет его:
  `var ${Name}: T` в теле структуры.
  - Аргумент — выражение времени компиляции типа `Identifier`: `Identifier.create("count")`
    ([метафункции](compile-time/metafunctions.md)) или параметр `Identifier` объемлющего объявления. Отдельной
    записи имени нет: имя без `Identifier.create` разрешается по общим правилам, поэтому `Inner<Name: Name>` передаёт
    значение параметра `Name`, а `Named<Name: count>` с локальной переменной `count` — ошибка типа аргумента.
  - Два аргумента равны, когда равен их текст: `Identifier` с одним текстом из двух файлов — одно значение и одна
    инстанциация.
  - Ключевое слово и недопустимое имя отвергает `Identifier.create`. Имя, которое совпало с членом объявления или
    с другим его полем, — ошибка у инстанциации, как имя поля из пакета `Field`.

## Стратегия как параметр

Параметр вида `Strategy` принимает имя стратегии; строка `provide Order for T` выбирает её внутри дженерика.

```efen
struct SortedSet<T: Comparable<T>, Order: Strategy> {
    provide Order for T                 // порядок элементов задаёт аргумент
    var items: Vector<T> = []
}

let byName = SortedSet<User, Order: ByName>()
let byAge = SortedSet<User, Order: ByAge>()
```

- Строка `provide P for X` в теле обобщённого типа или среди строк заголовка обобщённой функции выбирает
  стратегию-параметр `P` для типа `X`: для каждого контракта, которому `P` соответствует, как `provide` в коде
  пакета ([выбор программы](strategies.md#выбор-программы)).
- Выбор действует в инстанциации: для ограничений её сигнатуры, для тела и для инстанциаций, которые тело
  создаёт. Объявление, цель или получатель которого — этот тип, берёт выбор типа для ограничений из его
  сигнатуры. Поэтому стратегия для `SortedSet<T, Order>` сравнивает элементы по `Order` и строку не повторяет.
  Вложенная инстанциация со своей строкой для того же типа, контракта и права берёт свою: ближайшая строка
  побеждает ([порядок выбора](strategies.md#выбор-программы)).
- Ограничение `T: Comparable<T>` проверяется по `Order`. Стратегия, которая к `X` не применима или не
  соответствует ни одному контракту, — ошибка у инстанциации.
- Право применить стратегию к чужому типу даёт `allow strategies`
  ([право применить стратегию](strategies.md#право-применить-стратегию)); проверяется пакет, который записал
  аргумент.
- Стратегия входит в ключ инстанциации как аргумент. `SortedSet<User, Order: ByName>` и множество в пакете,
  который выбрал `ByName` своей строкой `provide`, — разные типы.
- `@erase` по параметру-стратегии запрещён: общее тело не выполняет операций, которые зависят от выбранной
  стратегии ([генерация кода](#генерация-кода)).
- Пакета стратегий нет, и членов у значения `Strategy` нет.

## Право доступа как параметр

Параметр типа `Access` принимает право доступа: `read`, `edit`, `mut` или
`own`. Он объявляется как остальные параметры времени компиляции и записывается там,
где обычно стоит слово права:

```efen
generic Access: Access
```

Аргумент без права значит `read`, как везде в языке: умолчания у параметра `Access` нет.

`Access` объявлен в `lang::` как обычный enum, но это особый встроенный вид,
как `Type` и `Origin`: компилятор знает его и читает значение как дескриптор
доступа.

```efen
enum Access { read, edit, mut, own }
```

Сравнение (`#if Access == own`), `match` и проверка полноты ветвей работают по
правилам для значений перечисления времени компиляции. `&` значением `Access` не бывает:
пишут слово `mut`.

Параметр обычно называют так же, как тип: `Access: Access`. Внутри объявления
имя `Access` означает параметр, а тип доступен как `lang::Access`.

### Право перед именем параметра

Право, которое приходит вместе с типом, пишут перед именем параметра типа: `Access T`. Такая запись объявляет
два параметра сразу: тип `T` без права и право `Access`, то есть строку `Access: Access`, связанную с `T`.
Двоеточие после имени остаётся ограничением, как у любого параметра: `<Access T: Comparable>`.

Право из параметра пишется в поле, в типе и в результате. Все записи ниже
читаются одинаково: имя параметра стоит вместо `read` или `edit`. Структура
держит только данные, а `next` даёт стратегия ([структуры](structs.md)):

```efen
struct ArrayIterator<Access T, Src: Origin> {
    let items: Access<Src> Array<T>     // поле: заимствование Src с правом Access, а не ссылка
    var index: Int = 0 { value >= 0 }

    invariants {
        index <= items.count
        Access == read || Access == edit
    }
}

strategy ArrayStep<Access T, Src: Origin>
for ArrayIterator<Access T, Src: Src> {
    conforms Iterator<Access T, Src: Src[_]>

    mut fn next -> &Access<Src[_]> T? {     // ссылка на слот элемента массива Src или null
        if index == items.count { return null }
        index += 1
        return &items[index - 1]
    }
}
```

Результат `next` — ссылка, записанная с правом и путём явно: `&Access<Src[_]> T?` — слот какого-то элемента массива
`Src`, `?` относится к ссылке. Ссылка всегда пишет свой путь: право без источника в методе значило бы заимствование
`self`, то есть самого итератора ([ссылка в результате функции](types/ownership.md#место-в-результате-функции)), а
`-> T?` без права дал бы значение. Вызывающий, который держит результат, пишет `&`: `while let x = &it.next()`.
Следующий вызов `next`, хотя это `mut fn`, прошлый элемент не кончает: `mut` относится к итератору, а структура
`Src` не меняется.

Аргумент такого параметра пишут с правом впереди, как тип параметра функции. Право раскладывается: `T`
получает тип без права, `Access` — право. Аргумент без права значит `read`:

```efen
ArrayIterator<edit Int, Src: numbers>    // T = Int, Access = edit
ArrayIterator<Int, Src: numbers>         // T = Int, Access = read: без пометки
```

Метка аргумента — имя параметра типа, она тоже принимает тип с правом: `ArrayIterator<T: edit Int, Src:
numbers>`. Право можно передать и отдельно, меткой права: `ArrayIterator<T: Int, Access: edit, Src: numbers>`.
Право, переданное обоими способами, — ошибка. Публичный контракт называет параметр по роли, чтобы метка читалась
у вызывающего кода: `contract Iterable<Access Item, Cursor>` принимает `Iterable<Item: edit Int>` и
`Iterable<Item: String>`. Проекция `A.Item` даёт тип без права, `A.Access` — право.

Право стоит левее всего остального в аргументе. Если тип сам несёт право, как указатель компоновки, первое слово
относится к параметру, второе — к типу: `ArrayIterator<read read Items.Item, Src: s>`.

Параметр, который объявлен с правом, внутри своего объявления передают дальше с правом: `Access T` — своё право,
`read T` — чтение. Голый `T` на месте, которое принимает право, — ошибка, если право не передано меткой рядом: без
этого правила `conforms Iterator<T>` молча значил бы `read`.

```efen
struct Counted<Access T, Src: Origin> {
    var inner: ArrayIterator<Access T, Src: Src>   // право Counted передано дальше
    var count: Int
}
```

Порядок в записи параметра один: вариантность, имя права, имя типа — `<out Access T>`.
Другое слово со строчной буквы на этом месте — ошибка. Фиксированное право в списке объявления тоже ошибка:
`struct Box<own T>` читается двояко, а `read`, `edit`, `mut` и `own` пишут только при использовании и в
ограничениях. Право перед именем бывает только у параметра типа: не у значения (`<Access N: Int>`), не у
источника, конструктора типов и пакета.

Имя права — отдельный параметр, и у двух параметров одного списка оно своё: `<Access K, Access V>` — ошибка.
Если права должны совпадать, их связывает строка `invariants`: `<KA K, VA V>` и `invariants { KA == VA }`.
Объявленное право используется в объявлении: в поле, в результате, в пометке метода, в `#if` или `match`, в метке;
у структуры — и в стратегии для неё. Неиспользованное имя права — ошибка с подсказкой «может быть, `,` или `:`?»:
так ловится `struct Pair<T U>`.

В полной форме право пишут так же, перед именем: `generic Access T: Comparable`. В условии `{ }` такой
строки `value` — тип `T`. Право параметра не меняет правил выбора формы: `Access T` — один параметр.

Пометка метода тоже бывает параметром. Одно объявление покрывает все права,
которые допускает его параметр:

```efen
Access fn iterator -> holds Access<self> ArrayIterator<Access T, Src: self>
```

Параметр права пишется и с путём к части: `Access<self.items> fn` ([пометка метода](types/parts.md#пометка-метода)).
Значение параметра контракта, в том числе права, при `conforms` выводит знак `_`
([параметры контракта](contracts.md#параметры-контракта)).

Такая пометка даёт семейство методов, по одному на каждое допустимое право:
`read fn iterator`, `edit fn iterator`. Методы с одним именем и разными
пометками различаются как перегрузки. Если получателю подходят несколько,
берётся самый узкий: у `v: edit Array<Int>` вызов `v.iterator()` берёт `read`.
Исключение — член, который уточняющий контракт повторил с более узким правом и своим условием `requires`
(`append` у `RoomAppendable`): берётся член с самым широким правом, которое даёт получатель
([наследование контрактов](contracts.md#наследование-контрактов)).
Более широкое право просят явно, той же формой, что и `take`:
`(edit v).iterator()`, `(mut v).iterator()`, `(take v).iterator()`. Получатель
без `take` метод `own fn` не выбирает.

`Access fn` берёт право, объявленное в списке типа. Незнакомое имя с заглавной буквы перед `fn` — ошибка.

### Ограничение прав

Допустимые права задаёт обычное условие ([ограничения параметров](#ограничения-параметров)). У права перед
именем параметра своей строки нет, и его условие стоит в `invariants` (`Access == read || Access == edit` у
`ArrayIterator` выше). У отдельного параметра права условие — `{ }` его строки:

```efen
strategy ArrayTraversal for Array<T> {
    generic T: Type
    generic Access: Access { value == read || value == edit }      // own и mut не подходят
    // функции стратегии не важны для примера
}
```

Ограничение обязательно там, где тело подходит не для всех прав: иначе один
параметр покрывает и `own`, и остальные права, и два объявления становятся
одинаково применимыми.

### Развилка по праву

Тип, который зависит от права, выбирается `match` по параметру
([сопоставление с типами](#сопоставление-с-типами)):

```efen
alias ArrayCursor<T, Access: Access, Src: Origin> = match Access {   // ветви mut нет: ArrayCursor<…, Access: mut> — ошибка
    own:  DrainIterator<T>
    read: ArrayIterator<read T, Src: Src>
    edit: ArrayIterator<edit T, Src: Src>
}
```

В теле право различает `#if`:

```efen
#if Access == own
    return DrainIterator(items: take self)
#elif Access == read || Access == edit
    return ArrayIterator(items: self)
#endif
```

Право входит в идентичность инстанциации: `ArrayIterator<read Int, Src: numbers>`
и `ArrayIterator<edit Int, Src: numbers>` — разные типы. Диагностика печатает право перед типом, как его пишут:
`Source<edit Int>`, а `read` — только перед типом, который сам начинается со слова права (`It<read read Items.Item>`); отдельный параметр права — меткой: `Visit<Access: mut>`.

## Конструкторы типов

Обычный параметр `generic T: Type` принимает законченный тип. Параметр с
собственным списком типовых параметров принимает конструктор типов:

```efen
interface Repository<Entity: Type, Result<T>: Type> {

    fn load(id: Id) -> Result<Entity?>
}

alias Identity<T> = T
alias DirectUsers = Repository<User, Identity>
alias DeferredUsers = Repository<User, Future>
```

`Result` сам не является типом значения. `Result<T>` является типом после
применения конструктора к аргументу. Локальное имя `T` в `generic Result<T>`
описывает сигнатуру конструктора и не добавляет параметр `Repository`.

Конструктор может иметь несколько параметров и ограничения на них:

```efen
generic PairFamily<A, B>: Type
generic Buffer<T: Movable>: Type
```

Применение `Buffer<X>` законно только при доказанном `X conforms Movable`.
Сигнатура конструктора задаёт явно передаваемые параметры. Именованное обобщённое объявление
с дополнительными параметрами совместим с ней, если при каждом применении все
остальные параметры однозначно заполняются обычным правилом значений по умолчанию и вывода аргументов.
Например, `Array<Element, Form = default>` можно передать как конструктор одного
аргумента. Полученные значения остальных параметров входят в полную
инстанциацию. Если их нельзя вывести однозначно, применение ошибочно.

Ограничения конструктора проверяются как множество допустимых аргументов. Переданный
конструктор обязан принимать каждый аргумент, разрешённый сигнатурой параметра.
Поэтому конструктор, требующий `Copyable`, нельзя передать как неограниченный
`F<T>` или как `F<T: Movable>`: `Movable` не гарантирует `Copyable`. Обратное
усиление требования пользователя законно: неограниченный конструктор можно
передать как `F<T: Copyable>`.

Анонимный конструктор записывается как лямбда-выражение над типами:

```efen
type<T> => Future<Result<T, Error>>
```

Например:

```efen
Repository<User, type<T> => Future<Result<T, Error>>>
```

Лямбда-выражение над типами принимает типы при компиляции и возвращает тип.
Значением времени выполнения оно не является.

### Требования к семейству типов

Блок параметра задаёт универсальные требования ко всем законным применениям
конструктора:

```efen
generic F<T>: Type {
    required method map<U>(transform: (T) -> U) -> F<U>
}
```

При связывании `F` компилятор должен доказать обобщённую реализацию `map`,
применимую для любого разрешённого `T` и `U`; удачный вызов только для нескольких
случайно использованных типов недостаточен. Требование может удовлетворить
физический метод либо метод стратегии, участвующей в обычном разрешении.
Несколько подходящих реализаций являются ошибкой компиляции.
Автоматического выбора «более специализированной» стратегии нет.

Выбранная реализация входит в зависимости и ключ инстанциации. Внутри одной
инстанциации разрешение не меняется от места следующего вызова этой
инстанциации.

## Ограничения параметров

Короткое ограничение `T: Contract` и полная форма с блоком параметра проверяются
при создании инстанциации:

```efen
class Matrix {
    generic Rows: Int { value > 0 }
    generic Columns: Int { value > 0 }
}
```

Условие одного параметра — `{ }` у его строки, предмет — `value`. Связь нескольких параметров у типа — строка
[`invariants`](conditions.md#условия-значений-и-invariants), у функции — строка `requires`. `T conforms C` — обычное
логическое выражение. Слова `where` нет.

```efen
class SquareMatrix {
    generic Rows: Int { value > 0 }
    generic Columns: Int { value > 0 }

    invariants { Rows == Columns }
}

fn processSameElements
    requires A.Item == B.Item
    requires A.Item conforms Equatable
{
    generic A: Iterable
    generic B: Iterable
    param left: A
    param right: B

    // left и right могут иметь разные типы, но один тип элемента.
}
```

Строка `requires` про один параметр, который объявила эта же функция, — ошибка с подсказкой перенести условие к его
строке (`generic T: C`). Про параметр типа у метода и про связанный тип (`A.Item`) — законно: своей строки у них в
этой функции нет.

`requires` у отдельного метода обобщённого типа требует только для этого метода. Так коллекции std требуют
[`ImplicitlyDestroyable`](disposable.md#implicitlydestroyable) только у методов, которые уничтожают элемент, не
возвращая его; сам тип принимает любой `T`:

```efen
mut fn removeAll
    requires T conforms ImplicitlyDestroyable
mut fn removeLast -> own T?
    ensures result == null ==> count == 0
```

Условие у строки `generic`, строки `invariants` и `requires`, которые читают только параметры обобщённого объявления, —
обязательные условия, их проверяют при сборке: ложное условие
запрещает инстанциацию. Они отличаются от `#if`, который условно формирует
состав уже законной инстанциации.

Параметр выбранного соответствия контракту доступен через проекцию, например
`A.Item`. Если один тип имеет несколько подходящих соответствий с разными
значениями `Item`, проекция неоднозначна и требует явно выбрать стратегию.

<a id="generic-параметры-с-contract"></a>

## Параметры с требованиями контрактов

Обобщённая функция всегда объявляет конкретный тип отдельно от параметра вызова:

```efen
fn printAll<Items: Iterable<Item: String>>(items: Items) {

    // тело не важно для примера
}
```

То же имя используется во всех местах сигнатуры, которым нужна эта идентичность:

```efen
fn printAll<T: Iterable<Item: String>>(first: T, second: T) {

    // тело не важно для примера
}
```

Контракт не становится типом значения времени выполнения и не выполняет стирание. Для двух
независимых конкретных типов объявляются два параметра обобщённого объявления:

```efen
fn merge<Left: Iterable<Item: String>, Right: Iterable<Item: String>>(left: Left, right: Right) {

    // left и right могут иметь разные конкретные типы.
}
```

`left` и `right` могут иметь разные конкретные типы. Когда требуется один тип,
объявляется одна общая идентичность:

```efen
fn merge<T: Iterable<Item: String>>(left: T, right: T) {

    // left и right имеют один конкретный тип T.
}
```

## Полиморфные функциональные типы

Обобщённую функцию можно передать как значение, не выбирая одну инстанциацию:

```efen
fn test<transform: <T>(T) -> T> {
    let number = transform(42)
    let text = transform("hello")
}
```

Тип `<T>(T) -> T` требует одну функцию, применимую для каждого допустимого `T`.
`generic transform` связывает её как параметр обобщённого объявления `test`. Это отличается от
именованного `generic T: Type` с `param transform: (T) -> T`, где `T` выбирается
один раз для всего вызова `test`.

<a id="variadic-generic-параметры"></a>

## Пакеты параметров

Префикс `...` собирает позиционные аргументы своего вида, которые идут подряд: первый аргумент другого вида пакет
заканчивает ([запись аргументов](#запись-аргументов)):

```efen
struct Tuple {
    generic ...Elements: Type
}
```

Тип кортежа `(Int, String, Bool)` и есть `Tuple<Int, String, Bool>`; имя `Tuple`
вручную пишется только с раскрытием пакета параметров. Для `(Int, String, Bool)` значение
`Elements` равно массиву времени компиляции `[Int, String, Bool]` типа `[Type]`. Пустой
пакет допустим. В применении `...` раскрывает массив обратно в последовательность
аргументов:

```efen
Tuple<...Elements>
```

Пакет параметров можно ограничить контрактом:

```efen
generic ...Errors: Throwable
```

Контракт у пакета параметров — ограничение каждого аргумента: каждый переданный тип должен быть совместим с `Throwable`. Внутри `Errors`
остаётся массивом типов. Поэтому отдельное слово `each` не требуется. Справа от
`:` контракт означает `conforms`, а класс или интерфейс — совместимость типа.

Пакет раскрывается в кортеже, структурном объединении или другом списке типов:

```efen
alias ValueOrErrors<Value, ...Errors> = Value | ...Errors
```

Коллекция времени компиляции типов поддерживает обычные допустимые операции над
коллекцией. В частности, `map` с лямбда-выражением над типами преобразует каждый тип:

```efen
alias OptionalTuple<...Elements> =
    Tuple<...Elements.map(type<T> => T?)>
```

<a id="pack-значений"></a>

## Пакеты значений

Пакет значений времени выполнения связывается с пакетом типов той же длины:

```efen
fn tuple -> Tuple<...Types> {
    generic ...Types: Type
    param ...values: Types

    return Tuple(...values)
}
```

В вызове `tuple(42, "hello", true)` значение `Types` равно
`[Int, String, Bool]`, а тип каждого `values[i]` равен `Types[i]`. Запись
`...values` раскрывает пакет с сохранением порядка и обычного порядка вычисления
аргументов Efen.

Однородный параметр с переменным числом аргументов `...values: Int` остаётся массивом значений
одного заранее известного типа. Форма `...values: Types` является
неоднородным пакетом, типы элементов которого задаёт связанный пакет типов.

Пакет значений связывается и со списком параметров типа функции, `param ...arguments: F.arguments`: право и тип
каждого `arguments[i]` тогда задаёт параметр `F` ([тип функции](#тип-функции)).

## Сопоставление с типами

`match` может выполняться над значением времени компиляции `Type`. Образец параметризованного типа
разбирает применённый тип и связывает его аргументы переменными времени компиляции:

```efen
alias Element<T> = match T {
    Array<let item>: item
    _: T
}
```

Имена, связанные через `let`, следуют обычному правилу переменных и начинаются
со строчной буквы. `Element<Array<String>>` равен `String`.

Образец `Array<let item>` сопоставляется также с наследником `Array<String>`,
если в его базовых типах существует ровно одно применение с номинально тем же
обобщённым объявлением `Array`. Аргументы этого применения связываются напрямую, без
вариантности и преобразований. Несколько применений с разными аргументами являются
ошибкой неоднозначности.
Прозрачные псевдонимы раскрываются перед сопоставлением. `opaque type` раскрывается
только там, где видимо его внутреннее представление.

## Условное соответствие контрактам

Параметризованный тип может соответствовать контракту только в тех инстанциациях, где
выполнено условие времени компиляции. Контрактом в условии и в строке `conforms` бывает и параметр вида `Contract`
([контракт как параметр](#контракт-как-параметр)):

```efen
class Box<T> {
    var value: T

    #if T conforms Copyable
        conforms Copyable

        fn copy -> Box<T> {
            return Box(copy value)
        }
    #endif
}
```

Ложное условие не запрещает саму инстанциацию. `Box<NonCopyable>` остаётся
законным типом, но не соответствует `Copyable` и не получает условные члены.
Это отличается от `generic T: Copyable`, где ограничение запрещает создать
`Box<T>` для неподходящего `T`.

Условие может зависеть от нескольких параметров, значений времени компиляции и
метаданных:

```efen
#if A conforms Copyable && B conforms Copyable
    conforms Copyable
#endif

#if Size > 0
    conforms NonEmpty
#endif

#if T has @serializable
    conforms Serializable
#endif
```

Результат условия, выбранные реализации и прочитанные факты времени компиляции входят
в ключ и зависимости инстанциации.

## Наблюдение параметра типа

Параметр типа доступен операциям, которые работают с типами:

```efen
fn printType<T> {
    let descriptor = typeof(T)
    print T
}
```

`typeof(T)` возвращает дескриптор `Type`. `T` приводится к `String` для обычной
печати при выполнении текущего конкретного типа.

## Генерация кода

Компилятор выбирает мономорфизацию, если объявление не закрепило режим. Явная пометка
`@erase` требует общей реализации со стиранием параметров типов. Если
компилятор не может безопасно её построить, возникает ошибка. Автоматической
замены на мономорфизацию в этом случае нет:

```efen
@monomorphize
fn specialized<T>(value: T) {
}

@erase
fn sharedBody<T>(value: T) {
}
```

При мономорфизации создаются специализированные тела для нужных
инстанциаций. При стирании одно общее тело работает с выбранным универсальным
представлением значений.

В `@erase` запрещены операции, зависящие от выбранной стратегии:
компилятор не передаёт скрытое подтверждение её выбора. Он может упаковать
значение в объект-обёртку, если этого требует универсальное представление.
Контексты и исключения такой операции остаются видны в итоговой сводке.
Представление обёртки, владение, уничтожение и извлечение из неё относятся
к реализации компилятора и не образуют отдельного выбора в синтаксисе языка.

Вердикты памяти доказываются на конкретных типах. Обобщённое тело проверяется один раз; то, что зависит от
аргумента, становится требованием в его сводке и проверяется у каждой инстанциации, как «`T` не `ThreadBound`»
([привязка к потоку](shared.md#привязка-к-потоку-threadbound)). Одна инстанциация бывает законной, другая — нет:

```efen
fn wipe<C: Iterable<Item: edit String>>(c: edit C) { for x in edit c { x = "" } }
// требование: запись элемента C целиком не разрушает объявленного члена множеств C
wipe(c: names)                 // names: Vector<String>: допустимо
```

Так же у инстанциации решаются пересечение двух элементов (без проверки, сравнение адресов или ошибка), смысл
`[index]` в пути и источник ссылки из `a: edit T` (требование «`T` не копируемый»). Форма вызова от инстанциации не
зависит: вызов с результатом `F.result` и шаг курсора любого вида пишутся без `&`. Под `@erase` требование должно
выполняться для каждого типа, который допускают ограничения; иначе код не компилируется.

Для параметризованного класса решение принимает `ClassGenericDefinition`: он может
направить несколько инстанциаций в одну реальную реализацию. Компилятор
передаёт конкретный тип аспекту как вход времени компиляции контролируемой операции.
Аспект может, например, вмешаться в построение `=` и материализовать
дескриптор времени выполнения в HIR. Такой дескриптор не обязан присутствовать, если
выбранная реализация класса его не использует.

<a id="варианс-covariancecontravariance"></a>

## Вариантность: ковариантность и контравариантность

Вариантность определяет, как совместимость аргументов влияет на совместимость
параметризованных типов. Здесь `out` и `in` относятся к параметрам типов:
это другая позиция синтаксиса, чем право выходного параметра функции `out`.

```efen
// Ковариантность (out) - тип может быть только возвращаемым значением
interface Producer<out T> {
    fn produce -> T
}

// Контравариантность (in) - тип может быть только входным параметром
interface Consumer<in T> {
    fn consume(item: T)
}

// Инвариантность (по умолчанию) - тип может быть и входным, и выходным
interface Storage<T> {
    fn get -> T
    mut fn set(item: T)
}
```

## Лучшие практики

1. **Используйте осмысленные имена**: `T`, `U`, `V` для простых случаев, но `TElement`, `TKey`, `TValue` для сложных
2. **Избегайте избыточных дженериков**: Не делайте класс параметризованным, если параметр типа используется только в одном методе
3. **Ограничивайте типы**: Используйте ограничения для явного указания требований к типам
4. **Документируйте**: Поясняйте назначение каждого параметра типа в документационных комментариях

```efen
/// Трансформирует элементы одного типа в другой
/// - TInput: Тип входных элементов
/// - TOutput: Тип выходных элементов
fn transform<TInput, TOutput>(items: [TInput], mapper: (TInput) -> TOutput) -> [TOutput] {

    return items.map(mapper).toArray()
}
```

## Ограничения

Статические поля параметризованного класса принадлежат конкретным
инстанциациям: `Cache<Int>.table` и `Cache<String>.table` — разные значения
([поля класса](classes.md#статические-методы)).
Наблюдение типа не предоставляет прав на произвольное изменение его объявления.
