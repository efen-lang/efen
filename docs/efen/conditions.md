# Условия функций и циклов

[Документация](README.md) · [Словарь](glossary.md) · [Функции](functions.md) · [Операторы](operators.md)

Функция объявляет, что она требует от вызывающего (`requires`) и что гарантирует после возврата (`ensures`).
Цикл объявляет, что верно на каждом шаге (`invariant`) и почему он кончится (`decreases`). Компилятор
доказывает условия; что он может вывести из кода сам, писать не нужно.

Решено Edmond 2026-10-29 (Amber S87 Z5): форма `requires`/`ensures` после сигнатуры, по образцу
[проекта проверяемого диалекта](memory/viper-verification-backend.md#синтаксис-контрактов-проверяемого-диалекта);
`previous(x)` вместо `old(x)`; условия функции не пишутся в `{}` у параметров и результата, кроме тех, что
являются частью типа; недоказанное условие — заметка, а безопасность, которая держалась бы на нём, проверяется при выполнении; переполнение в
условии — ошибка. Остальное — решения
агента, отмеченные «(агент)»; их проверили Мудрец и три Критика (проба на алгоритмах limelight-lang/model).

## Форма

```efen
fn withdraw(account: mut Account, amount: Int) -> Int
    requires amount > 0
    requires account.balance >= amount
    ensures account.balance == previous(account.balance) - amount
    ensures result == account.balance
{
    account.balance = account.balance - amount
    return account.balance
}
```

- Условия идут после сигнатуры, каждое с новой строки, с отступом на один уровень (агент: перенос формы и на
  циклы, и порядок строк). Порядок хвоста сигнатуры: `state`, `in`, `throws`, `where` — каждый, если есть;
  затем все `requires`, затем все `ensures`, затем `decreases`.
- Если у функции есть условия, `{` тела стоит на отдельной строке без отступа. Без условий `{` пишется как
  обычно, в конце сигнатуры; строка `throws` при этом может стоять отдельно, как в
  [условном владении](types/ownership.md#владение-которое-функция-забирает-не-всегда).
- Условия видят все параметры, и те, что объявлены `param` и `generic` в начале тела (агент):

```efen
fn tryExtendInPlace -> Bool
    requires oldSize >= 0 && newSize >= 0
    requires p >= 0 && p <= arena.limit && newSize <= arena.limit - p
    ensures result ==> arena.bump == p + newSize
{
    param arena: mut Arena
    param p: Int
    param oldSize: Int
    param newSize: Int

    // тело
}
```

  У объявления без тела (`contract`, `interface`, `@abi(c)`) места для `param` нет, поэтому правило
  [`S.function-parameter-layout`](diagnostic-groups.md#style-diagnostics-s) на него не действует (агент).
- Условие кончается переводом строки вне скобок (агент). Длинное условие пишется блоком:

```efen
fn relinkBlock(pool: mut Pool, index: Int, block: mut SlotBlock)
    requires {
        index >= 0 && index < CLASSES
        block.used > 0
        !block.linked
    }
    ensures block.linked
{
    // тело
}
```

  Это блок условий, как у [условий свойства](memory/addresses.md#декларативные-условия): каждая строка —
  отдельное условие, строки соединяются `&&`, `if` внутри означает импликацию. Это не выражение-блок: его
  значение — не последняя строка.
- Условие продолжается на следующей строке, если та начинается с бинарного оператора (`==>`, `&&`, `||`) или
  перенос стоит внутри скобок (агент). Это правило одно для строки `requires`/`ensures` и для строки блока.
- Несколько `requires` соединяются `&&`, несколько `ensures` — тоже.
- `requires`, `ensures`, `invariant`, `decreases`, `forall` и `previous` — контекстные слова (агент): особые
  только в условиях. Особое имя `result` в условиях — результат; параметр с именем `result` у функции с
  `ensures` — ошибка (агент).
- В методе имена в условиях разрешаются так же, как в теле: поле получателя пишется без `self`, если тело так
  может (агент).

## Смысл

- **`requires`** доказывает вызывающий код в каждой точке вызова. Внутри функции это известный факт, даже если
  у какого-то вызывающего он не доказан: тогда его проверяет точка вызова
  ([ниже](#обычная-сборка-и-диагностики)).
- **`ensures`** доказывает функция на каждом выходе: обычном возврате и, если у исключения нет своих условий,
  на выходе исключением ([ниже](#выход-по-исключению-и-halt)). После вызова это известный факт.
- **`result`** — результат функции: в `ensures` и в посылке [условного владения](#условия-в--только-часть-типа);
  на выходе исключением его нет, и строки с `result` там не действуют.
- Имя параметра `mut` в `ensures` значит его значение на выходе: его видит вызывающий. Значение на входе —
  `previous(x)`. Так и для `x: mut Int`, и для поля: `account.balance` — баланс на выходе (агент).
- Имя любого другого параметра на входе и на выходе значит одно и то же: функция его не меняет. Параметр `own`,
  который функция забирает, в `ensures` пишется только под `previous`, и с безусловным `take`, и с условным
  `{ … ==> take }`; без `previous` — ошибка.
- Условие не имеет побочных эффектов. Вызвать в условии можно функцию, которую компилятор признал чистой и
  завершающейся (агент): обычную функцию с телом, без записи, без `halt()`, без признака «может провалить `assert`» ([тесты](tests/tests.md#assert)) и без исключений, в том числе неявных
  (все операции её тела доказаны определёнными), рекурсивную — только с доказанным `decreases`. Отдельного вида «функции только для условий» нет: функция без тела с `ensures` была бы аксиомой,
  а две несовместные аксиомы доказывают что угодно.

### `previous(x)`

`previous(x)` — значение выражения `x` на входе в функцию. Это то же слово, что у
[условия поля](shared.md#роли) `{ value >= previous }`: там голое `previous` — значение поля до записи, здесь
`previous(x)` — значение `x` до вызова.

- Всё выражение в скобках считается на входе (агент): в `previous(cache.blocks[cache.count - 1])` и `blocks`,
  и `count` — входные. Имена, введённые в самом условии (переменная `forall`, `let` блока), сохраняют своё
  значение: в `forall i in 0 ..< n: a[i] == previous(a[i])` номер `i` тот же.
- Вложенный `previous`, `previous` в `requires` и `result` внутри `previous` — ошибки (агент).
- У параметра `own`, который функция забрала, `previous(memory)` — значение, пришедшее на вход (агент).
- В условии цикла `previous(x)` — тоже вход в функцию, а не в цикл. Значение на входе в цикл запоминается
  `let` перед циклом (агент).
- Имя `previous` у локальной переменной не мешает: в условии `previous(` всегда означает вход.

### `let`, `forall` и импликация

- В блоке условия можно назвать значение (агент):

```efen
    ensures {
        let before = previous(arena.bump)

        if before + size <= previous(arena.limit) {
            result != null
            arena.bump == before + size
        }
    }
```

- `forall i in 0 ..< n: …` — квантор по диапазону (агент); `forall k: …` без `in` остаётся для отношений
  вроде `reachable`. Тело квантора тянется до конца условия.
- `a ==> b` — импликация «если `a`, то `b`». Приоритет у неё самый низкий в выражении условия (агент):
  `a && b ==> c` значит `(a && b) ==> c`, `a ==> b && c` значит `a ==> (b && c)`, а
  `result != null || throws CopyError ==> take` — `(result != null || throws CopyError) ==> take`, как
  [условное владение](types/ownership.md#владение-которое-функция-забирает-не-всегда) и писалось. Цепочка
  `a ==> b ==> c` — ошибка. `==>` бывает только в условиях.

### Арифметика и частичные операции

Условие считается в тех же машинных типах, что и код: `Int` в условии — то же 64-битное `Int` (Edmond,
2026-10-29). Компилятор обязан доказать, что каждая операция условия определена: не переполняется, не делит на
ноль, индекс в границах, `!` не от `null`. Что из этого не доказано, решается так (Edmond, 2026-10-29):

- нарушение видно точно (`a / 0`, `Int.max + 1`, индекс за известной границей) — ошибка компиляции;
- FLOW не смог исключить нарушение — заметка в группе `Proof`, а условие проверяется при выполнении вместе с
  этой операцией: переполнение, деление на ноль или выход за границу во время проверки останавливает
  программу, как нарушенное условие ([ниже](#обычная-сборка-и-диагностики)). Сборка с решателем доказывает
  остальное; `-Werror Proof` делает такую заметку ошибкой.

У `assert` своё правило: неопределённая операция его условия при выполнении — провал этого `assert`, а не
остановка ([тесты](tests/tests.md#assert)) (агент).

Как это доказывается (агент, как в Dafny):

- слева направо и с коротким вычислением: правая часть `&&` — при истинной левой, `||` — при ложной, `==>` и
  `if` в блоке — при истинной посылке;
- из всех `requires` и строк выше в том же блоке;
- для `ensures` — ещё из фактов пути до возврата: если тело уже посчитало `balance + amount` без
  переполнения, то и `previous(account.balance) + amount` в `ensures` определено.

Поэтому порядок строк важен: `requires b != 0` должна стоять выше `requires a / b > 1`. Пример, где нужна
граница:

```efen
fn calloc(count: Int, size: Int) -> own Pointer?
    requires count >= 0 && size >= 0
    requires size == 0 || count <= MAX_RUN / size
    ensures result == null || result.size >= count * size
{
    // тело
}
```

Без второго `requires` произведение `count * size` в `ensures` могло бы переполниться: FLOW выдаст заметку
`Proof` и поставит проверку на возврате.

## Выход по исключению и `halt()`

Исключение — особый канал выполнения, и у него могут быть свои условия выхода (Edmond, 2026-10-29: «если их
нет — считается, что они совпадают, если есть — учитываются; можно на разные классы исключений свои
требования»).

- Без своих условий выход исключением обязан выполнить те же `ensures`, что и обычный возврат. Строки, которые
  называют `result`, к нему не относятся: результата нет (агент).
- Свои условия для исключения `E` пишутся посылкой `ensures throws E ==> …`, как у
  [условного владения](types/ownership.md#владение-которое-функция-забирает-не-всегда). Если у `E` есть свои
  строки, на выходе исключением `E` действуют только они, а обычные `ensures` — нет.
- Своя строка исключения — та, у которой посылка верхнего уровня состоит только из членов `throws`:
  `throws E ==> …` или `(throws E || throws F) ==> …` — строка и для `E`, и для `F`. Посылка, где `throws`
  смешан с другим условием (`result != null || throws E ==> …`), — ошибка (агент).
- Строка для класса действует и на его подклассы. Если подходят строки нескольких классов, действуют строки
  самого близкого из них, как выбирается `catch` (агент).
- `E` — исключение из объявленного или выведенного списка `throws` функции, в том числе неявное
  (`OverflowError`) (агент).

```efen
fn deposit(account: mut Account, amount: Int)
    requires amount > 0
    ensures account.balance == previous(account.balance) + amount
    ensures throws OverflowError ==> account.balance == previous(account.balance)
{
    account.balance = account.balance + amount
}
```

Без последней строки `deposit` не доказать: на выходе `OverflowError` баланс прежний, а обычное `ensures`
требует, чтобы он вырос. Компилятор выдаст заметку `Proof`, и автор либо напишет условие для исключения, либо
увидит, что функция ведёт себя не так, как он думал.

```efen
fn transfer(from: mut Account, to: mut Account, amount: Int)
    requires amount > 0
    requires from.balance <= Account.LIMIT && to.balance <= Account.LIMIT
    ensures from.balance + to.balance == previous(from.balance + to.balance)
    ensures throws LimitError ==> from.balance == previous(from.balance) && to.balance == previous(to.balance)
{
    // тело
}
```

Второе `requires` нужно для суммы в `ensures`: без границ `from.balance + to.balance` могло бы переполниться,
а это ошибка ([выше](#арифметика-и-частичные-операции)); `Account.LIMIT` — такая константа, что `2 * LIMIT`
помещается в `Int`. Здесь у `LimitError` свои условия (ничего не изменилось), а для остальных исключений действует обычное
`ensures`: сумма на двух счетах сохраняется при любом выходе.

- Условия, которые их документ требует восстановить перед `throw`
  ([условия вида](memory/pointer.md#условия-вида), [инвариант](shared.md#инвариант)), действуют на любом выходе
  сверх этого.
- Путь через `halt()` в доказанное не входит: программа остановлена. Отчёт доказательства называет такие пути
  (агент).
- На выходе по `AssertionError` `ensures` и строки с `result` не доказываются и не проверяются: в выпускной
  сборке этого пути нет. Остальные проверки выхода делаются и для него, в том числе для `AssertionError` из
  вызова; где не проходят, провал в этой точке останавливает программу, как `halt()`, и отчёт доказательства
  называет такие точки ([тесты](tests/tests.md#assert)) (агент).

## Функции без тела, контракты и интерфейсы

У метода `contract` или `interface` условия — обязательство реализации (агент). Реализация может написать свои
условия, но её `requires` не сильнее, а `ensures` не слабее объявленных; без своих условий она получает условия
объявления. Вызывающий через интерфейс видит только условия интерфейса. Нарушение этого правила — ошибка, не
заметка; если компилятор не доказал, что `requires` реализации не сильнее, а `ensures` не слабее, это тоже
ошибка, даже когда так и есть: реализация пишет условия, для которых это видно, или не пишет своих (агент).

```efen
contract System {
    const PAGE: Int

    fn map(bytes: Int, aligned: Int) -> own Pointer.Zeroed?
        requires PAGE > 0 && bytes % PAGE == 0
        ensures result == null || (result.size == bytes && result.alignment == aligned)

    fn unmap(memory: own Pointer, bytes: Int)
}
```

Без доказательства, на веру, компилятор принимает `ensures` только у `@abi(c)` без тела и у вставок `@asm`:
их кода он не читает ([system](memory/system.md#условия-результата--единственная-точка-доверия)). Писать их, как
и раньше, может только стандартная библиотека и модуль библиотеки C ([foreign](foreign.md)). Каждое такое
условие попадает в список доверия, который печатает сборка с доказательством (агент).

## Рекурсия

Рекурсивная функция, которую нужно доказать завершающейся (например, её зовут из условия), пишет меру
`decreases` так же, как цикл (агент). Недоказанная мера — заметка `Proof`, но такую функцию нельзя звать из
условия.

```efen
fn depth(node: Node?, fuel: Int) -> Int
    requires fuel >= 0
    decreases fuel
{
    // тело
}
```

## Циклы

Условия цикла стоят после заголовка, `{` тела — на своей строке (агент).

```efen
var count = 0

while let block = take pool.firstFreeBlock
    invariant count <= pool.blocks
    decreases pool.blocks - count
{
    pool.firstFreeBlock = take block.next
    System.unmap(memory: block as Pointer, bytes: BLOCK)
    count = count + 1
}
```

- **`invariant`** верен перед каждой проверкой условия цикла (у `while let` — до `take`) и после выхода из
  цикла. У `repeat { } while c` условия стоят после `repeat`, и инвариант верен перед каждым проходом тела.
  У инварианта цикла нет имени: имя есть у объявления `invariant name { }` в `shared struct`, а условие цикла
  стоит только между заголовком и `{` (агент).
- **`decreases`** — мера: целое неотрицательное, строго убывает за шаг. Без неё завершение не доказывается;
  безопасность проверяется независимо.
- У `for` по конечной коллекции, диапазону или конечной цепочке (`chained`) завершение компилятор выводит сам
  (агент).
- Инварианты из условий вида и из границ компилятор выводит сам; руками пишется только остаток.

## Условия в `{}`: только часть типа

Условия функции пишутся только `requires` и `ensures` (Edmond, 2026-10-29: «писать на параметрах {} — очень
громоздко»). Блок `{}` у параметра или результата остаётся там, где это часть типа:

- **условное владение** `own T? { посылка ==> take }`: функция забирает значение тогда и только тогда, когда
  посылка верна ([владение](types/ownership.md#владение-которое-функция-забирает-не-всегда)). В `ensures` это
  стало бы импликацией, и реализация интерфейса, которая забирает значение всегда, стала бы законной;
- **уточнение типа элемента** в типе коллекции: `[Int { value > 0 }]` — массив положительных чисел, как
  [уточняющий тип](types/refinement-types.md) без имени;
- **условие случая варианта** у результата: `-> MapResult { mapped: memory.size == bytes }`
  ([system](memory/system.md)) — условие на данные случая, которые в `ensures` назвать нечем (агент).

Признак один (агент): `{}` прямо за типом параметра или результата функции — ошибка с исправлением на
`requires`/`ensures`, кроме трёх форм выше (`==> take` в посылке, `{}` внутри `[ ]`, `случай:` у варианта).

| Было | Стало |
|---|---|
| `index: Int { value >= 0 && value < CLASSES }` | `requires index >= 0 && index < CLASSES` |
| `block: mut SlotBlock { used > 0 }` | `requires block.used > 0` |
| `-> own Pointer? { size >= size }` | `ensures result == null \|\| result.size >= size` |
| `data: read [T] { count == n }` | `requires data.count == n` |
| `memory: own Pointer? { result != null ==> take }` | без изменений |

`{}` после типа данных — свойство самого типа, как и было: `type Nat: Int { value >= 0 }`, условие поля
`var length: Size = 0 { value == Items.count }`, условия вида после `struct`.

**Состояние типа.** `requires x is State` по оси [typestate](types/typestate.md) — требование состояния, его
проверяет typestate, и нарушение — всегда ошибка, не заметка (агент):

```efen
fn release(pool: mut Pool, connection: own Connection)
    requires pool.mutex is Mutex.Free
{
    // тело
}
```

Стиль (агент): свойство одного значения, которое нужно многим функциям, — тип
(`type Slot: Int { value >= 0 && value < CAPACITY }`); связь параметров и выход — `requires`/`ensures`.
`ensures`, который пересказывает тело, не пишется: компилятор выведет его сам.

## Что выводится само

Писать не нужно (агент):

- что функция читает и меняет. Слова `reads`, `modifies`, `creates`, `removes` и `opens` проекта Viper в язык
  не входят;
- учёт взятых и возвращённых мест: Δ`used` и `taken` ([pointer](memory/pointer.md#учёт-на-выходе-функции));
- условия вида и инварианты, которые их документы требуют восстановить;
- инварианты циклов из условий вида и границ;
- для не публичной и не рекурсивной функции без `ensures` — её сводку из тела. Явное `ensures` главнее
  выведенного: правка тела не меняет доказательство у вызывающих, пока `ensures` верно. Отчёт
  `amber prove --explain` печатает выведенные сводки и тела, от которых зависит каждое доказательство.
  У публичной функции сводка не выводится: вызывающий из другого пакета видит только её условия.
- для закрытой функции — не публичной, вызываемой только прямо, не значением и не из `spawn` — факты на входе
  о её целых параметрах из всех мест вызова, как в Goose: на входе верно то, что доказал каждый вызов (Amber S95,
  Edmond 2026-10-30). Эти факты только снимают проверки при выполнении; принята ли программа, решается без них.
  Контракт открытой или экспортируемой функции — по-прежнему её `requires`.

  ```efen
  const SIZES: [Int] = [16, 32, 64, 128]

  fn sizeOf(index: Int) -> Int {
      return SIZES[index]  // оба вызова передают 0 и 3: проверки индекса нет
  }

  fn smallest -> Int {
      return sizeOf(0)
  }

  fn largest -> Int {
      return sizeOf(3)
  }
  ```

## Обычная сборка и диагностики

- FLOW доказывает `requires` в точке вызова и `ensures` на возврате, где может. Остальное доказывает сборка с
  решателем (Amber S87).
- Недоказанное условие не останавливает сборку: компилятор выдаёт заметку в группе `Proof` (Edmond,
  2026-10-29). Отчёт доказательства отмечает каждый вывод, который держится на недоказанном условии (агент).
- Недоказанное условие не считается фактом для безопасности (Edmond, 2026-10-29: «если не удаётся доказать, то
  компилятор границы обязан проверить в runtime»). Как именно (агент):
  - проверку ставит та сторона, которая должна доказательство. Недоказанный `requires` проверяется целиком в
    точке вызова, недоказанный `ensures` — на возврате. Вызываемая функция всегда полагается на свой
    `requires`, вызывающий — на `ensures`: при раздельной сборке функция не знает, доказали ли условие все,
    кто её вызывает;
  - при выполнении проверяемы: сравнения и арифметика над параметрами, полями и `result`; `forall i in a ..< b`;
    вызовы чистых функций; `previous(x)`, где `x` — значение или поле: компилятор снимает его на входе, как у
    [проверочной сборки C](foreign.md). Строка `ensures throws E ==> …` проверяется в точке выхода
    исключением;
  - остальное (`forall k:` без `in`, `reachable`, `chained`, `previous` от составного значения) не проверяется
    при выполнении. Такое условие остаётся заметкой, а проверка, которую оно сняло бы, не снимается:
    `SIZES[index]` проверяет границу, как без условия;
  - нарушение останавливает программу, как `halt()`, с сообщением, какое условие и где нарушено: это ошибка
    программы, а не исключение, которое ловят.
  Условие, которое доказано, проверок не порождает. Требование состояния `requires x is State` сюда не
  относится: его проверяет typestate, и недоказанное — ошибка ([выше](#условия-в--только-часть-типа)).
- Заметку группы `Proof` поднимают до предупреждения или ошибки флагами
  [групп диагностик](diagnostic-groups.md#управление-через-флаги) или в конфигурации сборки (Edmond,
  2026-10-29).
- Условие, которое решатель опроверг, — ошибка с контрпримером: значения параметров, на которых оно ложно
  (агент).
- Неопределённая операция в условии (переполнение, деление на ноль, индекс вне границ) — ошибка, только когда
  нарушение видно точно; если FLOW не смог её исключить — заметка `Proof` и проверка при выполнении (Edmond,
  2026-10-29, [Арифметика](#арифметика-и-частичные-операции)).
- У `assert` эти два пункта свои: в обычном коде ошибка — только `assert`, ложный или неопределённый на каждом пути
  ([тесты](tests/tests.md#assert)) (агент).

## Граница

`requires`/`ensures` описывают один вызов в одном потоке. Структура, которую меняют два потока без блокировки
(кольцо писателя и читателя), описывается [ролями и инвариантами](shared.md#роли), а не условиями функции.
Замыкания в условиях и условия у параметра-функции в первой версии не поддерживаются (агент).
