# Плагины и метакод

[Документация](../README.md) · [Метапрограммирование](README.md) · [Метафункции](metafunctions.md) · [Аспекты](../aspects/README.md) · [Диалекты](../dialects.md) · [Конфигурация сборки](../build-config.md)

Библиотека расширяет язык двумя способами. Метакод программа находит по имени или типу в тексте, плагин —
по конфигурации сборки. И то и другое — код на Efen, который компилируется в песочнице и исполняется при
сборке. Код, который они порождают, проверяется так же, как написанный человеком. Проект и обоснование —
amber dev/plans/S90.md: модель попросил Edmond 2026-10-29, ответы на два вопроса — его; остальные решения отмечены «(агент)».

```efen
use orm

@orm.table("users")            // атрибут: его реализация — метакод библиотеки orm
struct User {
    var id: Int
    var email: String
}

let limit = 10MB               // суффикс MB объявлен типом Bytes; значение считает его метакод
```

```efen
config server {
    plugins {
        efql: "^0.4"                       // файлы .efql и секция efql.sql
        audit: path("tools/audit")         // проверка каждой функции проекта
    }

    efql.sql {
        dialect: "sqlite"
        migrations: path("db/migrations")  // путь, который плагину разрешено читать
    }
}
```

## Два уровня

**Метакод** — код библиотеки, который работает при сборке и вызывается по имени или типу в месте
использования: метафункция, атрибут, аспект класса, суффикс литерала, тег диалекта. В конфигурации
метакод не указывают: читатель находит его источник по тексту.

**Плагин** — пакет, названный в секции `plugins` конфигурации. Он действует на сборку без имени в каждом
месте: проверяет все функции проекта, разбирает свои файлы, описывает секции конфигурации, добавляет
скрытые параметры. Конфигурацию читатель открывает так же, как текст программы, и она входит в идентичность сборки.

Пакет становится плагином, когда в нём ровно один публичный тип соответствует контракту
`compiler::Plugin`. Отдельного вида пакета нет. Пакет из `plugins` без такого типа — ошибка
конфигурации.

## Ядро доверия

Компилятор доверяет только своему ядру: запечатыванию тела, FLOW, эффектам и условиям. Всё, что порождают
метакод и плагины, — обычный HIR, готовый до запечатывания, и он проходит ядро как написанный код: разбор,
разрешение имён, типы, владение, эффекты, `requires` и `ensures`. Недоказанное условие проверяется при
выполнении, где это возможно ([условия](../conditions.md)). Второго набора правил для порождённого кода нет.

Единственное исключение — скрытые параметры плагина языка ([функции](../functions.md#скрытые-параметры)):
владение и эффекты их не видят. Поэтому `amber trust` перечисляет такой плагин у каждой функции, которой
он коснулся.

## Способы расширения

Каждый способ расширения либо порождает код в месте, которое его назвало, либо только читает;
исключение — плагин языка. Способа
вне этого списка нет; новый способ — решение автора языка.

| Способ | Уровень | Где назван | Что даёт |
|---|---|---|---|
| Метафункция | метакод | вызов `m(…)`, `m => …` | код на месте вызова |
| Атрибут оператора | метакод | `@a` перед оператором | подсказку генератору или замену оператора |
| Суффикс и префикс литерала | метакод | `10MB`, `path"…"` | значение типа или ошибку у литерала |
| Сбор помеченных объявлений | метакод | вызов вида `collect<@route>()` | код на месте вызова |
| Тег диалекта | метакод | `sql { … }`, `sql"…"`, `sql"""…"""` | код на месте блока |
| Атрибут объявления | метакод | `@a` перед объявлением | metadata, объявления рядом, новое тело помеченного объявления |
| Аспект | метакод | применение к классу | шаги плана класса |
| Атрибут параметра или типа | метакод | `@a` у параметра или типа | только metadata |
| Полный диалект | плагин | расширение файла | модуль HIR из файла |
| Проверка | плагин | конфигурация | диагностики; функция без кода |
| Секции конфигурации | плагин | `plugins` | настройки плагина |
| Плагин языка | плагин | конфигурация | скрытые параметры |

### Метафункция

Описана в [метафункциях](metafunctions.md). Цитата `efen::code { }` имеет тип: `Expression<Int>`,
`Statement`, `Declaration`. Подстановка `${…}` не того типа — ошибка в самом метакоде, а не в каждом
месте вызова.

### Атрибуты

Атрибут оператора получает смысл от метакода; атрибут, который никто не обработал, — ошибка
([декораторы](../decorators.md)). Он даёт подсказку генератору (`@unroll(4)`) или заменяет оператор.

Атрибут объявления добавляет metadata и объявления рядом с помеченным и может заменить тело помеченного
объявления (`@Trace`, `@Cached`). Новое публичное объявление и изменённая сигнатура объявляются при
регистрации атрибута и входят в публичный отпечаток модуля (агент). Атрибуты одного объявления выполняются
сверху вниз ([metadata](../aspects/metadata.md)).

Атрибут параметра или употребления типа только несёт metadata; действует метакод, который её читает.

### Суффикс и префикс литерала

Описаны в [типах](../type-aliases.md#суффиксы-и-префиксы-литералов). Выражение после `=>` может вызвать
метафункцию, которая разбирает текст литерала (регулярное выражение, дату) и сообщает ошибку у литерала.

### Сбор помеченных объявлений

Прогонщику тестов нужны все `test fn`, маршрутизатору — все `@route`. Вызов `collect<@route>()` возвращает
объявления с этим атрибутом из модулей, которые импортирует модуль вызова, по порядку пути модуля и места
в тексте. Маршрут зависимости попадает в список, только если вызывающий импортирует её модуль. Форма вызова
пока предложение.

### Тег диалекта

Библиотека-диалект регистрирует тег (Edmond, 2026-10-29: «Efen регистрирует способ для DSL tag {} - да»,
«sql"" - тоже»). `use dialect` вводит тег в файл.

```efen
use dialect sql
use dialect regex

let users = sql {
    SELECT id, name FROM users  -- комментарий SQL с '}' внутри
    WHERE email = ${email}
}

let pattern = regex"[^}]+"
let query = sql"SELECT 1"
```

- Диалект описывает данными свои кавычки, экранирование и комментарии. Лексер считает фигурные скобки
  вне них, поэтому `}` в строке или комментарии SQL не закрывает блок. Описание лежит в
  скомпилированном интерфейсе библиотеки и читается без запуска метакода.
- `use dialect sql` резервирует имя `sql` в файле: переменная или функция с этим именем — ошибка. Поэтому
  `for row in query { … }` не читается двояко.
- `${…}` — выражение Efen во всех формах. Своих параметров вида `$email` у диалекта нет. Диалект, в
  тексте которого встречается `${` (оболочка), объявляет другой открывающий знак.
- Строковые формы `tag"…"` и `tag"""…"""` есть у каждого тега; скобки в них не считаются.
- Метакод диалекта получает текст с позициями и типизированные выражения `${…}` и строит код через
  `efen::code`; текст не разбирается как код Efen: код строится только через `efen::code`.

### Аспект

Описан в [построении класса](../aspects/compile-time/class.md). Аспект действует при каждом обращении к
своему классу, поэтому `amber expand` показывает его код в каждом таком месте.

### Полный диалект

Плагин заявляет расширение файла (`.efql`). Компилятор передаёт ему текст файла и получает модуль HIR с
позициями в этом файле; типы и проверки — компилятора. Два плагина с одним расширением — ошибка
конфигурации с обоими именами.

### Проверка

Проход по запечатанному телу: ничего не меняет, выдаёт диагностики. Ошибка проверки значит то же, что
ошибка компилятора: функция не компилируется ([философия](../philosophy.md#линтеры-и-плагины--часть-компилятора)).
Проверка работает только на пакетах проекта, не на зависимостях: новая проверка не ломает чужой код
(агент).

```efen
use compiler

/// Требует причину у каждого вызова функции C.
struct Audit {
    conforms compiler::Plugin

    fn register(doors: mut compiler::Doors) {
        doors.check(name: "audit.foreign-call", run: checkForeignCalls)
    }
}

fn checkForeignCalls(body: compiler::SealedBody, report: mut compiler::Diagnostics) {
    for call in body.calls where call.target.isForeign {
        if !call.attributes.has("reason") {
            report.error(at: call.span, "вызову функции C нужна причина: @reason(\"…\")")
        }
    }
}
```

Описаны в [конфигурации сборки](../build-config.md#секции-плагинов).

## Чего метакод и плагин не могут

- Выйти из песочницы. Все плагины и весь метакод компилируются в режиме песочницы (Edmond, 2026-10-29:
  «все плагины компилируются под песочницей»). Им доступно только то, что песочница импортирует: сети,
  часов, случайных чисел и окружения по умолчанию нет.
- Расширить ядро: породить `@asm`, функцию `@abi(c)` без тела вне внешнего модуля, допущение, отключённую
  проверку, свой вид узла HIR.
- Заменить код, который их не называл. Заменяется только место, назвавшее метакод: вызов, помеченный
  оператор, литерал, тело помеченного объявления, класс аспекта.
- Изменить неизменяемое: файлы `lang::`, связь знака операции (`+`) с контрактом, правила типов, владения, эффектов,
  исключений, пометки ролей рантайма.
- Выбрать рантайм, аллокатор, std, цель или режим: это поля программы.
- Изменить объявление зависимости без разрешения её владельца и `provide` сборки.
- Зависеть от порядка или хранить состояние: метакод на разных узлах не видит результата друг друга,
  порядок в `plugins` ничего не значит, каждый запуск получает новый экземпляр.

## Чтение мира и внешние программы

Метакод видит мир только через `compiler::`, и каждое чтение становится входом сборки
([Q32](../../../dev/language-design-questions.md)). Файл или каталог читается только внутри пакета, который сейчас компилируется, и
по путям, которые конфигурация программы выдала плагину в его секции (агент). Атрибут транзитивной зависимости
поэтому не прочтёт `~/.aws/credentials`.

Плагин может запустить внешнюю программу (protoc, проверку схемы по базе), если песочница это
разрешает (Edmond, 2026-10-29: «да конечно может в целом... хотя это может быть запрещено песочницей»).
Разрешение даёт конфигурация программы в секции плагина: плагину и программе по имени. Плагин
зависимости без разрешения сверху ничего не запускает, а режим сборки «песочница» отклоняет любое
разрешение. Результат запуска хранится по содержимому программы, аргументам и переданным
файлам. Программа, которая читает невидимое компилятору (живую базу, сеть), помечается в разрешении;
её результат не переиспользуется, а сборка помечается как невоспроизводимая.

## Цель и воспроизводимость

Метакод считает с моделью данных цели: `Int` шириной цели, `sizeOf` и выравнивание цели, переполнение по
ширине цели. `4GB` при 32-битной цели — ошибка переполнения у литерала. Цель называет `compiler::target`.

Одинаковые входы дают одинаковый результат. Метакод и плагин приходят исходником и компилируются тем же
компилятором; готовые двоичные файлы не принимаются. Исчерпанный предел шагов — ошибка компиляции в месте
вызова.

## Гигиена

Фрагмент кода замкнут: он называет только свои параметры, подстановки и имена, видимые там, где объявлен
метакод. Имя, которое фрагмент объявляет, коду пользователя не видно, если регистрация его не объявила.
Видимость проверяется в месте вставки: порождённый код зовёт только то, что мог бы позвать модуль
пользователя. Вспомогательные функции библиотеки для порождённого кода публичны, в своём пространстве
имён (`orm.generated`).

## Одно имя — один владелец

Два атрибута, суффикса, тега, расширения файла или секции с одним видимым именем — ошибка, которая
называет оба. Тип с `prefix sql` и тег диалекта `sql` тоже конфликтуют.

## Происхождение и отчёт доверия

Каждый порождённый узел помнит цепочку: место в тексте пользователя, каждый метакод и плагин по пути и
строку метакода, которая его построила. Ошибка в порождённом коде указывает на текст пользователя и
добавляет примечания по цепочке.

- `amber expand <функция>` печатает функцию в том виде, в каком её компилируют, с пометкой
  происхождения у порождённого кода.
- `amber trust <функция>` перечисляет, на чём держится функция: метакод и плагины с версией и ключом
  содержимого, плагины языка, доверенные формы (`@asm`, `@abi(c)`).

## Версии API

`compiler::` — набор контрактов Efen, которые реализует компилятор; его внутренности не видны. Пакет,
который использует `compiler::`, называет версию API в своём `project.efen` (`compiler: "^1"`); несовпадение —
ошибка конфигурации до запуска. Нестабильного уровня API нет: что не стабильно, то не открыто.

## Сборка

Сначала читается конфигурация, плагины из `plugins` компилируются для машины сборки, их секции
проверяются. Затем полные диалекты превращают свои файлы в модули. Остальное идёт по требованию: метакод
— до запечатывания, проверки — после, генерация кода — последней, и ни один плагин её не касается.

Идентичность сборки содержит ключи содержимого плагинов, значения их секций и `provide`. Результат функции
в кэше хранит ключи выполненного метакода и его наблюдения. `efen.lock` закрепляет плагины и библиотеки с
метакодом по ключу содержимого.

## Открыто

Предложения, ещё не закреплённые за языком:

- имена API: `compiler::Plugin`, `Doors`, `register`, `SealedBody`, `Diagnostics`, `compiler::target`,
  `compiler::File`, `check`, `reason`;
- типизированная цитата `Expression<T>` (в [метафункциях](metafunctions.md) `Expression` без типа);
- резервирование тега диалекта в файле;
  форма регистрации имён;
- `compiler: "^1"` в `project.efen`;
- `collect<@route>()`;
- описание лексики диалекта и другой открывающий знак вместо `${`;
- форма разрешения внешней программы и пометка невоспроизводимой;
- `amber expand`, `amber trust`;
- может ли метакод менять тип результата; протокол разрешения на изменение чужого объявления;
  первый метакод при начальной сборке компилятора.

Пока не проектировались: инструментирование (покрытие, трассировка) и расширяющие диалекты с новыми
ключевыми словами.
