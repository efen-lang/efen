# Пакеты, модули и пространства имен

`Efen` организует код в пакеты, модули и пространства имен для улучшения структуры и управления зависимостями.

> Пакет -- это совокупность модулей,
> которые логически связаны между собой и могут быть совместно использованы в других проектах.

> Модуль -- это единица компиляции и развертывания,
> которая содержит код, ресурсы и метаданные.

> Пространство имен (namespace) -- это логическая группа, которая помогает избежать конфликтов имен
> и организует код в иерархическую структуру.

`Efen` явно определяет соответствие между пространствами имен и структурой каталогов.

## Правила организации пакетов

### Namespace и физическая структура

**Namespace** -- это логический идентификатор, который определяет область видимости пакета.
Namespace не обязательно совпадает с физическим путём к файлам (например, файлы могут быть в ZIP-архиве или виртуальной файловой системе).

### Правила объявления пакетов

1. **Один package на namespace**: В рамках одного namespace может быть объявлен максимум один package.

2. **Запрет повторного объявления**: Декларация `package X;` может встретиться только один раз в рамках одного namespace.

3. **Запрет вложенности**: Нельзя создавать вложенные пакеты (подпакеты) внутри другого пакета. Это следует модели Rust.

4. **Разные namespaces -- разные пакеты**: В разных namespaces могут существовать разные packages.

### Примеры

```efen
// Namespace "mylib"
package mylib;  // ✅ OK

// Тот же namespace "mylib"
package mylib;  // ❌ ОШИБКА: повторное объявление package

// Тот же namespace "mylib"
package other;  // ❌ ОШИБКА: другой package в том же namespace

// Namespace "utils"
package utils;  // ✅ OK: другой namespace
```

### Workspace и множественные пакеты

Один проект (workspace) может содержать несколько пакетов в разных namespaces:

```
myproject/
├── mylib/          # Namespace "mylib"
│   ├── package.efen # package mylib;
│   └── module1.efen
└── utils/          # Namespace "utils"
    ├── package.efen # package utils;
    └── module1.efen
```

Пакет определяется любым `efen` файлом, который содержит определение пакета и список его зависимостей.
Рекомендуется называть такой файл `package.efen`, `library.efen` или `main.efen`.

Определение пакета:
```efen

package MyPackage 
MyPackage.info = toml {
    name = "MyPackage"
    version = "1.0.0"
    description = "Описание пакета"
    authors = ["Автор <email@example.com>"]
    license = "MIT"
}

MyPackage.dependencies = [
    "AnotherPackage": ">=1.0.0 <2.0.0",
    "SomeLibrary": "^3.2.1"
]
```

Модуль определяется файлом с расширением `.efen` внутри каталога пакета, 
и не требует явного объявления, кроме случая, если модуль должен быть публичным.

Пример:
```efen
// Файл: MyPackage/src/MyModule.efen
public module
```

Объявление модуля публичным делает все его абстракции (классы, интерфейсы, контракты, функции, переменные)
доступными для других пакетов, которые зависят от этого модуля.

Полное имя абстракции включает имя пакета, имя модуля и имя абстракции, разделённые двоеточиями:
```efen
MyPackage::MyModule::MyClass
MyPackage::MyModule::MyInterface
MyPackage::MyModule::myFunction
```

## Импорт модулей

Модули импортируются с помощью ключевого слова `use`.:
```efen
use MyPackage::MyModule
use AnotherPackage::AnotherModule as AliasModule
```

Импорт модуля делает все его публичные абстракции доступными в текущем пространстве имен.
Можно импортировать конкретные абстракции из модуля:
```efen
use MyPackage::MyModule::{MyClass, myFunction}
```

Можно импортировать все абстракции из модуля с помощью `*`:
```efen
use MyPackage::MyModule::*
```
