# Генераторы

Генератор — функция, которая отдаёт значения по одному и между ними стоит на месте. Каждый `yield` передаёт
значение наружу и приостанавливает тело; следующий запуск продолжает тело с этой точки. Локальные переменные
генератора хранятся в его кадре и сохраняют значения между запусками.

```efen
generator upTo(limit: Int) yield Int {
    var n = 1

    while n <= limit {
        yield n
        n = n + 1
    }
}

fn sum -> Int {
    var total = 0

    for n in upTo(5) {
        total = total + n
    }

    return total  // 15
}
```

## Заголовок

Генератор объявляется словом `generator`. После сигнатуры идут роли, каждая на своей строке, на месте `requires` и
`ensures` ([conditions.md](conditions.md)). Если есть хотя бы одна строка роли, `{` стоит на отдельной строке:

```efen
generator relay(prefix: String) -> Int
    yield String
    resume String
    requires prefix.length() > 0
{
    var msg = yield "ready"
    var count = 0

    while msg != "stop" {
        count += 1
        msg = yield "${prefix}: ${msg}"
    }

    return count
}
```

Роли без условий можно писать и на строке сигнатуры; обе формы равноправны:

```efen
generator numbers yield Int {
    yield 1
    yield 2
}
```

| Роль | Смысл | Без неё |
|---|---|---|
| `-> C` | итоговый результат, как у `fn`; его даёт `return` | `Void` |
| `yield Y` | тип каждого отданного значения; с правом и источником, `yield edit<items> Item`, — [ссылка](#отдача-ссылки) | `Void`: генератор только приостанавливается |
| `resume R` | тип значения, которое получает приостановленный `yield` при возобновлении | `Void`: `yield e` — оператор |

Порядок: хвост сигнатуры как у функции (`state`, `in`, `throws`, `where`, [conditions.md](conditions.md)), затем
`yield`, `resume`, затем `requires` и `ensures`. Каждая роль — не больше одного раза.

Тип значения генератора пишется как тип функции: это заголовок объявления без имени и параметров (параметры
переданы при создании), ключевое слово `generator`, затем роли `-> C`, `yield Y`, `resume R`, затем хвост `throws`,
`in`, `nothrows`, `nofail`, как у типа функции после результата. Отсутствующие роли — `Void`: `generator yield Int`
отдаёт `Int`, ничего не получает и ничего не возвращает. Это не обобщённый класс и не имя из библиотеки: тип
узнаётся по слову `generator`, как тип функции — по `->`. `start()`, `next()` и остальное
реализует `lang` через контракт.

Эффекты тела — те же, что у типа функции ([types/function-type.md](types/function-type.md)): их бросают и требуют
`start()`, `next()` и `for`; уничтожение бросает только то, что бросает очистка, живая у `yield`. В идентичность типа
эффекты не входят: у `let` компилятор выводит их из тела, а у `var`, поля, параметра и публичного имени записанный
тип — верхняя граница, и генератор, который бросает или требует больше, туда не присваивается. Эффекты после
результата объявления принадлежат самому объявлению, поэтому эффекты генератора-результата пишутся в скобках, как у
возвращаемой функции. У объявления `generator` после результата идут и его собственные роли, поэтому в скобках
пишется и тип генератора-результата с ролями:

```efen
generator lines(path: String) yield String { /* тело не важно для примера */ }

let g = lines("a.txt")                              // тип generator yield String; throws и in выведены из тела
var source: generator yield String throws IoError in Files
fn open -> (generator yield String throws IoError)  // throws у генератора
fn open -> generator yield String throws IoError    // throws у open
generator g -> (generator yield Int) yield Int      // результат g — генератор, который отдаёт Int
var steps: generator -> Bool yield String resume Int
```

Роли типа стоят на его строке; перенос строки внутри скобок разрешён. Строка `yield x` под `let` с таким типом — уже
оператор тела, а не роль:

```efen
var steps: (generator -> Bool
    yield String
    resume Int)
```

Роли и хвост после вложенного типа без скобок принадлежат вложенному типу, как у типа функции. Роль, которая у
вложенного типа уже есть, — ошибка: скобки говорят, чья она:

```efen
var a: generator yield () -> Int throws E           // throws у функции, которую отдаёт генератор
var b: generator yield (() -> Int) throws E         // throws у генератора
var c: generator -> generator yield Int yield Bool  // ошибка: yield записан дважды
var d: generator -> (generator yield Int) yield Bool
```

Генератор, созданный от аргумента `mut` или `read`, держит его, пока живёт. Тип пишет это, как тип функции
([closure.md](closure.md)): право и источник стоят перед типом, а возвращаемый генератор берут в скобки, как
замыкание ([тип функции](types/function-type.md)). Без скобок `-> mut<items> generator yield Int` читалось бы как
ссылка на генератор внутри `items`. Заимствование с правом `own`, `(own<x> T)`, — то же, что `T`: значение забрано, и
держать нечего. После типа права не пишутся:

```efen
fn walker(items: mut [Int]) -> (mut<items> generator yield Int)
```

Генератор, созданный от аргумента параметра типа проекции, держит только поля проекции: остальные поля значения
вызывающий меняет, пока генератор жив ([проекция в параметре](types/projection.md#проекция-в-параметре)).

Три типа различаются намеренно: отданное значение и завершение с результатом различимы даже при совпадающих типах
(асимметричные сопрограммы Lua, `Coroutine s m r` из Haskell-библиотеки monad-coroutine, эффект `Yield: A -> B` с
результатом `C`).

## Использование

| Форма | Что происходит |
|---|---|
| `let g = relay("a")` | выделяется кадр, аргументы попадают в него по виду параметра ([параметры и условия](#параметры-и-условия)); тело не выполняется |
| `g.start()` | с `resume`: тело работает до первого `yield`; результат — шаг `.yielded` или `.completed` |
| `g.next(value)` | `value` передаётся приостановленному `yield`, тело работает до следующего; результат тот же |
| `g.next()` | без `resume`: первый вызов запускает тело, следующие продолжают его |
| `for x in g { print(x) }` | только без `resume`: тело цикла выполняется для каждого отданного значения |
| `g.result` | итоговый результат после `.completed` или после `for`, дошедшего до конца; `take g.result` забирает его |

```efen
let g = relay("log")

match g.start() {
    .yielded.{ value: let greeting }: print(greeting)  // "ready"
    .completed.{ result: let count }: print(count)
}

match g.next("a") {
    .yielded.{ value: let line }: print(line)  // "log: a"
    .completed.{ result: let count }: print(count)
}
```

Шаг — вариант из двух случаев: `.yielded` с полем `value: Y` и `.completed` с полем `result: C`.

Цикл `for` видит только отданные значения. Итог читается после цикла:

```efen
generator counter -> Int
    yield Int
{
    var i = 0

    while i < 3 {
        i = i + 1
        yield i
    }

    return i
}

let c = counter()

for value in c {
    print(value)  // 1, 2, 3
}

print(c.result)  // 3
```

Ошибки. Компилятор сообщает их там, где видит порядок вызовов; в остальных случаях программа останавливается при
выполнении с сообщением.

- `start()` дважды; `next(value)` до `start()`; `start()` у генератора без `resume`; любой вызов после `.completed`
  или после исключения из тела.
- Возобновление генератора из его собственного тела.
- `g.result` до завершения, в том числе после выхода из `for` через `break`.
- Временный генератор в `for` с результатом не `Void`: «результат генератора не используется». Именованный
  генератор так не проверяется: его итог доступен через `g.result`.

## Где стоит `yield`

- `yield e` — оператор, или вся правая часть `let`, `var` и `=`: `let m = yield e`, `m = yield e`. Внутри другого
  выражения (`f(yield e)`, `while (yield e) != 0`) — ошибка.
- Только в теле самого генератора. В замыкании, в `defer` и в теле `spawn` — ошибка.
- Внутри `try` — можно; внутри `catch` — ошибка.
- Ссылку отдаёт только генератор, роль `yield` которого называет право и источник ([отдача ссылки](#отдача-ссылки));
  иначе значение перемещается или копируется наружу.

## Отдача ссылки

Генератор отдаёт ссылку в свой параметр, а не копию значения, если роль `yield` называет право и источник, как ссылка
в результате функции ([ownership.md](types/ownership.md#место-в-результате-функции)). В теле перед выражением стоит
только `&`: право ссылки берётся из роли `yield`, как у `return` из результата функции.

```efen
generator active(items: edit [Item]) yield edit<items> Item {
    for i in 0 ..< items.count {
        if items[i].active {
            yield &items[i]                  // ссылка в items; право даёт роль yield
        }
    }
}

for item in active(items: list) {
    item.count += 1                          // пишет прямо в list
}
```

**Правило.** Источник в роли `yield` — параметр генератора или путь внутрь него: `yield read<doc.title> String`. У
параметра, тип которого известен по контракту с частями, путь называет часть:
`generator each<S: Storage>(s: read S) yield read<s.Storage.items> Item` ([части объекта](types/parts.md)). Запись без
права, `yield Int`, по-прежнему отдаёт значение.

**Правило.** Каждую отданную ссылку FLOW доказывает; без доказательства `yield` — ошибка в этой строке.

| Что доказывается | Где | Чем |
|---|---|---|
| ссылка указывает в объявленный источник | у каждого `yield &items[i]` в теле | путь выражения начинается с параметра-источника и идёт по объявленному пути |
| право ссылки не шире права параметра | у каждого `yield` | из `items: read [Item]` ссылка `edit` не отдаётся |
| источник живёт не меньше генератора | при создании генератора | генератор держит параметр, пока жив; заимствование пишется в типе: `(edit<items> generator yield edit<items> Item)` |
| отданная ссылка не пережила изменение структуры источника | у потребителя, на каждом вызове `mut`, который доходит до источника | право заимствования в типе генератора |

- Ссылка на локальную переменную генератора, на временное значение и на параметр `own`, перемещённый в кадр, не
  отдаётся: её источник — кадр генератора, а кадр меняется на каждом шаге. Это ошибка в строке `yield`.
- Отданная ссылка привязана к источнику, а не к генератору, как элемент от итератора
  ([итератор как структура](types/access-regions.md#итератор-как-структура)).
- Тело меняет структуру источника между `yield`, только если параметр `mut`.
- Потребитель пользуется источником, пока генератор жив, с тем правом, которое генератор оставил: при
  заимствовании `read` и `edit` он пишет значения и добавляет только в коллекцию, добавление которой элементов не
  перемещает (связный список); существующих слотов он не двигает. При заимствовании `mut` он меняет и структуру,
  потому что на `yield` кадр теряет всё, что хранил в источнике.
- Запись владеющего значения в слот элемента источника мимо генератора с заимствованием `read` делает генератор
  недействительным, когда его кадр на `yield` может хранить ссылки или курсоры в память значений элементов.
  Объявление видно — решает сводка тела: `for i in 0 ..< v.count { yield &v[i] }` между шагами хранит только номер
  и такую запись переживает, а внутренний обход `for x in row` в генераторе над `rows` — нет. Объявления не видно —
  генератор недействителен всегда
  ([что делает ссылку недействительной](memory/memory-rules.md#что-делает-ссылку-недействительной)).

**Правило.** Убивает ли шаг генератора ссылки, отданные раньше, решает то, что шаг делает с источником
([правила доступа к памяти](memory/memory-rules.md#что-делает-ссылку-недействительной)). Отдельного правила для генератора нет: шаг
(`next`, шаг `for`) — вызов `mut` у генератора, а такой вызов убивает ссылки в то, структуру чего он меняет
([как компилятор выводит области](types/access-regions.md#как-компилятор-выводит-области)).

- Объявление генератора видно — решает сводка его тела, как у любой функции: шаг убивает ссылки в источник, только
  если тело между двумя `yield` меняет его структуру.
- Объявления не видно — генератор пришёл параметром, лежит в поле, получен из другого пакета или по требованию
  контракта — решает право заимствования в его типе: `mut` значит «шаг может изменить структуру».

**Правило.** Право заимствования генератора с телом — самое широкое право, с каким тело пользуется параметром, и не шире
права параметра. Тело, которое при параметре `mut` только читает и пишет значения, даёт заимствование `edit`. Тип,
написанный у параметра, поля и результата, — верхняя граница: генератор с заимствованием `edit` подходит туда, где
написано `mut`.

| Тип генератора | Вызов `mut` у генератора | Ссылки, отданные раньше |
|---|---|---|
| `(read<items> generator yield Int)`, `(edit<items> generator yield Int)` | при `read` до `items` не доходит; при `edit` доходит как вызов `edit` | ссылки на слоты действуют, пока цела структура `items`; ссылки в память значений элементов шаг генератора с `edit` делает недействительными |
| `(mut<items> generator yield Int)` | доходит до `items` | умирают на каждом шаге; использование после шага — ошибка у потребителя |

- Правило не знает слова `next`: ссылку убивает любой вызов `mut`, который доходит до источника, у генератора, у
  самого источника или у другого значения, которое держит источник с `mut`. Вызов `read` ссылок не затрагивает; вызов `edit` делает недействительными только ссылки в память значений элементов ([как компилятор выводит области](types/access-regions.md#как-компилятор-выводит-области)).
- `start()`, `next()` и шаг `for` — вызовы `mut` у генератора, с каким бы правом он ни держал источник. До источника
  вызов доходит с правом заимствования, не шире.
- Уничтожение значения с заимствованием `mut` считается вызовом `mut` у него: `defer` в теле генератора и завершение
  курсора могут изменить структуру источника. Ссылка, отданная раньше, после `break` из такого цикла мертва.
- Заимствование `mut` не теряется ни при каком преобразовании: в параметре, результате, поле, типе переменной, аргументе
  типа и захвате оно остаётся записанным. Значение с заимствованием `mut` передаётся только в параметр, тип которого
  пишет это заимствование: `fn drive<Src: Origin>(g: mut (mut<Src> generator yield edit<Src> Item))`. Параметр типа без
  заимствования, `g: mut G`, такой генератор не принимает: обобщённый код не увидел бы, что шаг убивает ссылки. Ошибка
  выдаётся в строке вызова.
- Имя источника в типе генератора вне его объявления — параметр источника (`Src: Origin`), как в строке выше.
- Заимствование нескольких источников с разными правами пишется как пометка метода, со словом внутри скобок:
  `(edit<index.data, read index.memo> generator yield edit<index.data> Item)`.
- Генератор в результате функции держит её параметр по правилу ссылки в результате: `-> (edit<items> generator yield Int)`
  временного аргумента для `items` не принимает ([ссылка в результате функции](types/ownership.md#место-в-результате-функции)).

**Правило.** Для тела генератора `yield` — вызов неизвестного кода, который владеет всеми правами, оставленными
потребителю. Что тело знало о заимствованных параметрах до `yield`, после него проверяется заново:

- факты о значениях каждого заимствованного параметра после `yield` забыты: потребитель мог записать значение через
  отданную ссылку `edit` или сам, с правом, которое генератор ему оставил;
- о структуре источника под заимствованием `read` или `edit` после `yield` известно одно: слоты, которые существовали,
  остались на своих адресах, и длина не уменьшилась. Верхняя граница длины, «последний» и «пусто» забыты: с правом
  `edit` потребитель создаёт новые слоты ([итератор как область](types/access-regions.md#итератор-как-область));
- если отданная ссылка или заимствование имеют право `mut`, на `yield` умирают все ссылки, курсоры и факты о структуре,
  которые кадр хранит в этом источнике; их использование после `yield` — ошибка в строке использования;
- под заимствованием `edit` после `yield` недействительны ссылки кадра в память значений элементов источника:
  потребитель мог записать владеющее значение в слот элемента. Ссылки на слоты элементов действуют.

```efen
generator linked(items: edit [Item], names: read [String]) yield edit<items> Item {
    for i in 0 ..< items.count {
        if items[i].nameIndex < names.count {
            yield &items[i]
            print(names[items[i].nameIndex])     // проверка границы повторяется: потребитель мог записать nameIndex
        }
    }
}
```

**Правило.** Параметр, названный источником в роли `yield`, временного аргумента не принимает: временное значение
переместилось бы в кадр ([параметры и условия](#параметры-и-условия)), и ссылка «в параметр» стала бы ссылкой в кадр.
Ошибка выдаётся в строке вызова; значение сначала получает имя: `let items = loadItems()`.

**Что не допускается.**

- Право в роли `resume` (`resume edit<items> Item`) — ошибка: кадр хранил бы полученную ссылку до следующего `yield`.
- Ссылку, полученную от внутреннего генератора или от курсора, тело отдаёт дальше, если её источник лежит внутри
  объявленного: `for x in walk(node: child) { yield x }` при `yield read<node> Item`,
  `for item in edit items { yield &item }` при `yield edit<items> Item`. Иначе это ошибка в строке `yield`.
- Отданную ссылку не захватывает `spawn` и сохранённое замыкание: для потребителя это ссылка из результата вызова
  ([ссылки только внутри функции](types/ownership.md#ссылки-только-внутри-функции)).

## Генератор-метод

Генератор объявляется и в теле класса или стратегии. Право на `self` стоит перед словом `generator`, как перед `fn`
([доступ метода к self](contracts.md#доступ-метода-к-self)); без пометки — `read`.

```efen
class Index {
    var data: Vector<Item>
    var memo: Map<Key, Item>

    edit generator active yield edit<self.data> Item {
        for i in 0 ..< data.count {
            if data[i].active {
                yield &data[i]
            }
        }
    }
}

for item in index.active() {
    item.count += 1
    index.memo.clear()                       // можно: генератор держит только data
}
```

**Правило.** Получатель для генератора-метода — параметр с правом пометки: генератор отдаёт ссылки в `self` по
правилам [отдачи ссылки](#отдача-ссылки). `own generator` перемещает получателя в кадр и ссылок в него не отдаёт.

**Правило.** Генератор-метод держит каждый путь внутри `self`, которым пользуется его тело, с самым широким правом,
с каким оно им пользуется. Это его сводка по `self`, а не содержимое кадра: тело, которое хранит между `yield` один
номер и на каждом шаге удаляет элементы `data`, держит `data` с `mut`. Источник роли `yield` генератор держит всегда.

| Объявление | Что держит генератор |
|---|---|
| с телом, пометка без пути | выводит FLOW из тела: поля, к которым тело обращается, с правом обращения |
| с телом, пометка с путём | то же; путь — проверяемый предел, и обращение тела к полю вне пути с правом шире чтения — ошибка в строке обращения |
| без тела (контракт, интерфейс), пометка с путём | названные части: `read<self.items> generator each yield read<self.items> Item` |
| без тела, пометка без пути; `open generator` | весь `self` с правом пометки |

- В примере выше тело обращается только к `data` и пишет в него значения, поэтому `index.active()` имеет тип
  `(edit<index.data> generator yield edit<index.data> Item)`, и `memo` потребитель меняет. Генератор, который обходит
  `memo` и отдаёт ссылки из `data`, держит оба поля: `(edit<index.data, read index.memo> generator yield edit<index.data> Item)`.
- Пометка с путём пишется так же, как у метода: `mut<self.data> generator`, `mut<self.data, edit self.memo> generator`
  ([части объекта](types/parts.md#пометка-метода)). У генератора путь пишется и с `read`: пометка называет не только
  то, что он изменяет, но и то, что держит. Чего пометка с путём не называет, генератор не держит.
- Источник в роли `yield` — `self` или путь внутрь него; в классе путь называет настоящее поле. Роль с правом без
  источника, `yield read Item`, у генератора-метода означает ссылку во весь `self`, как результат метода без пути. У
  генератора вне типа такая роль — ошибка: источника нет.
- Реализация требования контракта пишет в роли `yield` настоящее поле из названной части.
- Получатель, названный источником, временным значением не бывает: `makeIndex().active()` — ошибка в строке вызова.
- `open generator` и `override generator` подчиняются правилам `open fn`.

## Исключения

Исключение из тела выходит из `start()`, `next()` или `for`. Генератор тогда завершён без результата, его очистка
уже выполнена. `start()`, `next()` и `for` бросают то же, что тело. После исключения вызовы генератора и `g.result` —
ошибка.

## Уничтожение приостановленного генератора

Приостановленный генератор владеет своим кадром. Когда исчезает последний владелец, тело не возобновляется: код после
последнего `yield` не выполняется, а `defer` и очистка живых владельцев выполняются, как при выходе из области.
Затем кадр освобождается. Так `for` с `break` освобождает генератор, созданный в заголовке цикла:

```efen
generator countdown(from: Int) yield Int {
    defer {
        print("countdown done")
    }

    var n = from

    while n > 0 {
        yield n
        n = n - 1
    }
}

for n in countdown(10) {
    if n == 7 {
        break  // печатается "countdown done"; код после `yield` не выполняется
    }
}
```

Очистка при уничтожении может бросить исключение (`defer` с бросающим вызовом), поэтому конец области, где
уничтожается приостановленный генератор, бросает то же, что очистка у его `yield`.

Именованный генератор, которому одолжена переменная, освобождается раньше конца области в двух случаях. Первый:
`take` этой переменной требует свободного слота — значение уходит из функции, замораживается или переносится в
существующий слот. Второй: вызов меняет структуру переменной, а генератор заимствует её с `read` или `edit`
([ownership.md](types/ownership.md#явное-извлечение)). Приостановленный генератор освобождается прямо перед этим `take`
или вызовом, и его `defer` выполняется там же; использовать генератор после этого — ошибка. Генератор с заимствованием
`mut` изменение структуры источника между шагами допускает и раньше не освобождается. `take` в новую локальную переменную слот сохраняет,
и генератор живёт до конца своей области.

```efen
generator walk(items: [Int]) yield Int {
    defer {
        print("walk done")
    }

    for item in items {
        yield item
    }
}

fn consume(items: own [Int]) {
    print(items.count)
}                                    // конец области: область массива возвращает его dispose

fn main {
    var items = [5, 6]
    let walker = walk(items: items)
    for item in walker {
        break
    }
    consume(take items)  // сначала "walk done", затем "2"
}
```

`for` по именованному генератору берёт его как `mut` на время цикла: шаг — вызов `mut`. Слово права в заголовке при
этом не пишется. После `break` генератор остаётся приостановленным, его можно продолжить через `next()` или ещё
одним `for`.

## Генератор как итератор

Генератор без `resume` отдаёт курсор методом `iterator()`. Курсор нужен коду, который ждёт итератор по контракту;
цикл `for` шагает генератором сам.

```efen
generator upTo(n: Int) yield Int { /* тело не важно для примера */ }

fn total<I: ValueIterator<Int>>(it: mut I) -> Int { /* тело не важно для примера */ }

let g = upTo(5)
var cursor = g.iterator()          // курсор держит g с правом mut
let sum = total(it: cursor)
```

**Правило.** `iterator()` — метод `mut` генератора. Курсор держит генератор с `mut`, а через него — источники
генератора с правом его заимствования. Это заимствование правила «заимствование `mut` не теряется» не касается:
курсор идёт в параметр `it: mut I`; до источников генератора шаг доходит с правом его заимствования (следующий
список). `next()` курсора делает шаг генератора и возвращает значение шага `.yielded` или `null` на шаге `.completed`;
после конца он возвращает `null` снова.

| Роль `yield` генератора | Курсор соблюдает |
|---|---|
| `yield Y` | `ValueIterator<Y>` |
| `yield R<источник> Y` | `Iterator<R Y, Src: источник>` |
| есть роль `resume` | метода `iterator()` нет |

- Генератор курсором не является и контрактов обхода не соблюдает: его `next()` возвращает шаг, а не `Y?`.
- Курсор нового обхода не начинает: он продолжает генератор с того `yield`, на котором тот стоит.
- Итог генератора курсор не отдаёт. После уничтожения курсора его читает `g.result`, если генератор дошёл до конца.
  `iterator()` у временного генератора с результатом не `Void` — ошибка «результат генератора не используется».
- Курсор генератора с заимствованием `mut` сам имеет заимствование `mut` и идёт только в параметр, где оно написано
  ([отдача ссылки](#отдача-ссылки)).
- Курсор бросает и требует то же, что тело генератора. Курсор, `next` которого бросает, не соблюдает контракт,
  где `next` объявлен без `throws`: исключения в контракте пишутся, и такое соблюдение вызывает ошибку на `conforms`,
  как реализация, которая ждёт, у метода контракта без `Waiting` ([эффекты ожидания](shared.md#эффекты-ожидания)).
- Второй `for` над генератором, который дошёл до конца, вызывает ошибку: любой вызов после `.completed` запрещён
  ([использование](#использование)).

Это соответствует `Dispose` у итератора C#. Отдельная операция отмены из уничтожения не следует.

## Параметры и условия

Аргументы попадают в кадр при создании генератора, по виду параметра ([ownership.md](types/ownership.md)):

- `own` — перемещается в кадр;
- `read` типа `Copyable` — одалживается, как другие типы; копию даёт `copy` в аргументе;
- `read` или `edit` другого типа: временный аргумент перемещается в кадр; именованное значение одалживается на время
  жизни генератора. Кадр владеет перемещённым значением и уничтожает его вместе с собой: массив из
  `walk(items: [5, 6])` освобождает его `dispose` при уничтожении генератора
  ([освобождение структуры](disposable.md#освобождение-структуры-disposable));
- генератор с таким заёмом покидает функцию только результатом, тип которого называет источник; сохранить его в
  поле или в переменной, которая живёт дольше источника, нельзя.

`requires` без посылки проверяется при создании, по аргументам.

## Условия генератора

Условия пишутся на каждый `yield` и на всё множество отданных значений; форму проверили три прогона
Критика (amber S92, проект `amber/s92/conditions-proposal-v4.md`). Остальные правила [conditions.md](conditions.md).

```efen
generator upTo(limit: Int) -> Int
    yield Int
    requires limit >= 0
    ensures yield ==> value == yielded.count + 1 && value <= limit
    ensures yielded.count == limit
    ensures result == limit
{
    var n = 0

    while n < limit
        invariant yielded.count == n && n <= limit
    {
        n += 1
        yield n
    }

    return n
}

let g = upTo(5)
var sum = 0

for v in g
    invariant g.yielded.count == sum
{
    sum += 1
}

assert g.result == 5
```

- **`ensures yield ==> P`** — условие каждого `yield`, посылка верхнего уровня, как `ensures throws E ==>`. `value` —
  отдаваемое значение. Доказывается у каждого `yield`; у переменной `for` и у шага `.yielded` это факт.
- **`requires resume ==> P`** — условие значения, которое передаёт `next(value)`. В теле это факт в точке после
  `yield`. Проверяет вызывающий: `next(v)` проверяет условие, если не доказал его сам, и при нарушении
  останавливает программу с указанием своей строки. В типе генератора условия нет.

```efen
generator lookup(table: read [Int])
    yield Int
    resume Int
    requires resume ==> value >= 0 && value < table.count
{
    var i = yield 0

    while true {
        i = yield table[i]  // проверки границ нет: условие resume её доказывает
    }
}
```

- **История.** `yielded` и `resumed` — последовательности отданных и полученных значений, такими, какими они были
  при передаче. Они существуют только для доказательства и в кадре не хранятся.
  - в условии `yield`: `yielded` — значения до текущего, `resumed.last` — значение, после которого он отдан;
  - в условии `resume`: `yielded.last` — значение, на которое это ответ, `resumed` — полученные до него;
  - в обычном `ensures` — все значения; в теле (в `invariant`, `assert`) — переданные к этой точке;
  - у вызывающего `g.yielded` и `g.resumed` — все переданные, текущее тоже.
- **Встроенные факты:** у первого `yield` `resumed.count == 0`; у каждого `yield` `resumed.count == yielded.count`;
  у каждого возобновления `yielded.count == resumed.count + 1`. Возобновление без значения (`Void`) тоже считается.
- **Где вызывающий видит историю:** генератор создан в этом теле и не одолжен как `edit` никому, кроме своих
  `start()`, `next()`, шага `for` и `result` (эти вызовы берут его как `mut`). Курсор `iterator()` видимость прекращает. После `let h = g` факты
  переходят к `h`. Вне видимости факты с историей отбрасываются.
- **Что получает вызывающий:** условие `yield` — у переменной `for` и шага `.yielded`; обычные `ensures` — у шага
  `.completed` и у `g.result` после `for`, дошедшего до конца. Аргументы в фактах — их значения при создании.
- **`ensures`** проверяются при `return`. Строки с `result`, `yielded` или `resumed` на выходе исключением не
  действуют; `ensures throws E ==> P` может называть историю, и P верно на ребре исключения из самого генератора
  (`start()`, `next()`, шаг `for`), а не из тела цикла вызывающего. Брошенный приостановленный генератор `ensures` не
  проверяет: каждое полученное значение уже выполнило условие `yield`.
- **Что можно назвать в посылке:** `value`, `yielded`, `resumed`, `previous(x)` параметра, константы, функции без
  эффектов и параметры, которые тело не меняет: `read` или `own`, ни один слот которого не пишется, не перемещается,
  не забирается и не одалживается как `edit`/`mut` (в том числе получателем метода). Другой параметр — ошибка с
  исправлением на `previous(x)` или обычный `ensures`. `previous(x)` — значение при создании генератора.
- **При выполнении:** `count` и `last` хранятся в кадре, только если их требует условие, которое проверяется при
  выполнении; `last` — только для копируемого типа. Проверяемое условие `resume` с ними хранит их всегда. Прочие
  недоказанные условия истории (`forall` по ней доказывает только сборка с решателем) — заметка `Proof` без
  проверки, и фактом они не становятся.
- **Грамматика.** Только голая посылка: условная строка пишется `ensures yield ==> (value > 3 ==> P)`; после посылки
  можно блок условий в фигурных скобках; посылка внутри блока — ошибка. Ошибки: `ensures resume ==>`, `requires yield ==>`, посылка
  `resume` без роли `resume`, посылка `yield` при `yield Void`, смешанная посылка. У генератора с условиями параметр
  `value`, `yielded`, `resumed` или `resume` и локальная переменная `yielded` или `resumed` — ошибки; локальная `value`
  разрешена. Голое `previous` в посылке — ошибка с исправлением на `yielded.last`.

## Контексты

Тело видит контексты `with`, действующие там, где генератор создан, как замыкание видит `capture`
([closure.md](closure.md)). Генератор не переживает `with`, который дал нужный ему контекст: если компилятор видит,
что генератор живёт дольше, это ошибка компиляции.

```efen
with fileLog {
    for line in lines() {  // можно: генератор живёт внутри with
        print(line)
    }
}

fn outlived -> generator yield String {
    with fileLog {
        return lines()  // ошибка: генератор переживает with, а lines() нужен его контекст
    }
}
```

Контексты процесса и потока генератор не захватывает: тело находит их заново при каждом шаге. Шаг генератора
(`next`, `start`, шаг `for`) несёт права тела на пути контекстов у потребителя, как вызов замыкания, и это точка, в
которой умирают ссылки из контекста потока ([контексты процесса и
потока](context-and-effects.md#ссылка-из-контекста-потока)).

## Чего пока нет

`yield from`, `flow generator` ([flow.md](flow.md)), отдача ссылки на
собственную память генератора (буфер, который переписывается на каждом шаге).

## Сравнение с функцией

| Конструкция | Поведение |
|---|---|
| `fn` | выполняется один раз и возвращает результат |
| `generator` | отдаёт значения по одному, между ними стоит на месте |
| `return` в генераторе | завершает его и задаёт итоговый результат |
| `yield` | отдаёт значение и приостанавливает тело |
