# Генераторы

Генератор — функция, которая отдаёт значения по одному и между ними стоит на месте. Каждый `yield` передаёт
значение наружу и приостанавливает тело; следующий запуск продолжает тело с этой точки. Локальные переменные
генератора хранятся в его кадре и сохраняют значения между запусками.

```efen
generator upTo(limit: Int) yield Int {
    var n = 1

    while n <= limit {
        yield n
        n = n + 1
    }
}

fn sum -> Int {
    var total = 0

    for n in upTo(5) {
        total = total + n
    }

    return total  // 15
}
```

## Заголовок

Генератор объявляется словом `generator`. После сигнатуры идут роли, каждая на своей строке, на месте `requires` и
`ensures` ([conditions.md](conditions.md)). Если есть хотя бы одна строка роли, `{` стоит на отдельной строке:

```efen
generator echo(prefix: String) -> Int
    yield String
    resume String
    requires prefix.length() > 0
{
    var msg = yield "ready"
    var count = 0

    while msg != "stop" {
        count += 1
        msg = yield "${prefix}: ${msg}"
    }

    return count
}
```

Роли без условий можно писать и на строке сигнатуры; обе формы равноправны:

```efen
generator numbers yield Int {
    yield 1
    yield 2
}
```

| Роль | Смысл | Без неё |
|---|---|---|
| `-> C` | итоговый результат, как у `fn`; его даёт `return` | `Void` |
| `yield Y` | тип каждого отданного значения | `Void`: генератор только приостанавливается |
| `resume R` | тип значения, которое получает приостановленный `yield` при возобновлении | `Void`: `yield e` — оператор |

Порядок: хвост сигнатуры как у функции (`state`, `in`, `throws`, `where`, [conditions.md](conditions.md)), затем
`yield`, `resume`, затем `requires` и `ensures`. Каждая роль — не больше одного раза.

Тип значения генератора повторяет заголовок: `Generator -> Int yield String resume String`. Отсутствующие роли —
`Void`. Как тип функции, он несёт `in …` и `throws …` тела: их бросают `start()`, `next()`, `for` и уничтожение.
Два генератора с одинаковыми ролями, контекстами и `throws` дают значения одного типа.

Три типа различаются намеренно: отданное значение и завершение с результатом различимы даже при совпадающих типах
(асимметричные сопрограммы Lua, `Coroutine s m r` из Haskell-библиотеки monad-coroutine, эффект `Yield: A -> B` с
результатом `C`).

## Использование

| Форма | Что происходит |
|---|---|
| `let g = echo("a")` | выделяется кадр, в него копируются аргументы; тело не выполняется |
| `g.start()` | с `resume`: тело работает до первого `yield`; результат — шаг `.yielded` или `.completed` |
| `g.next(value)` | `value` передаётся приостановленному `yield`, тело работает до следующего; результат тот же |
| `g.next()` | без `resume`: первый вызов запускает тело, следующие продолжают его |
| `for x in g { … }` | только без `resume`: тело цикла выполняется для каждого отданного значения |
| `g.result` | итоговый результат после `.completed` или после `for`, дошедшего до конца; `take g.result` забирает его |

```efen
let g = echo("log")

match g.start() {
    .yielded.{ value: let greeting }: print(greeting)  // "ready"
    .completed.{ result: let count }: print(count)
}

match g.next("a") {
    .yielded.{ value: let line }: print(line)  // "log: a"
    .completed.{ result: let count }: print(count)
}
```

Шаг — вариант из двух случаев: `.yielded` с полем `value: Y` и `.completed` с полем `result: C`.

Цикл `for` видит только отданные значения. Итог читается после цикла:

```efen
generator counter -> Int
    yield Int
{
    var i = 0

    while i < 3 {
        i = i + 1
        yield i
    }

    return i
}

let c = counter()

for value in c {
    print(value)  // 1, 2, 3
}

print(c.result)  // 3
```

Ошибки. Компилятор сообщает их там, где видит порядок вызовов; в остальных случаях программа останавливается при
выполнении с сообщением.

- `start()` дважды; `next(value)` до `start()`; `start()` у генератора без `resume`; любой вызов после `.completed`
  или после исключения из тела.
- Возобновление генератора из его собственного тела.
- `g.result` до завершения, в том числе после выхода из `for` через `break`.
- Временный генератор в `for` с результатом не `Void`: «результат генератора не используется». Именованный
  генератор так не проверяется: его итог доступен через `g.result`.

## Где стоит `yield`

- `yield e` — оператор, или вся правая часть `let`, `var` и `=`: `let m = yield e`, `m = yield e`. Внутри другого
  выражения (`f(yield e)`, `while (yield e) != …`) — ошибка.
- Только в теле самого генератора. В замыкании, в `defer` и в теле `spawn` — ошибка.
- Внутри `try` — можно; внутри `catch` — ошибка.
- Отдать ссылку (`read T`, `edit T`) нельзя: значение перемещается или копируется наружу.

## Исключения

Исключение из тела выходит из `start()`, `next()` или `for`. Генератор тогда завершён без результата, его очистка
уже выполнена. `start()`, `next()` и `for` бросают то же, что тело. После исключения вызовы генератора и `g.result` —
ошибка.

## Уничтожение приостановленного генератора

Приостановленный генератор владеет своим кадром. Когда исчезает последний владелец, тело не возобновляется: код после
последнего `yield` не выполняется, а `defer` и очистка живых владельцев выполняются, как при выходе из области.
Затем кадр освобождается. Так `for` с `break` освобождает генератор, созданный в заголовке цикла:

```efen
generator countdown(from: Int) yield Int {
    defer {
        print("countdown done")
    }

    var n = from

    while n > 0 {
        yield n
        n = n - 1
    }
}

for n in countdown(10) {
    if n == 7 {
        break  // печатается "countdown done"; код после `yield` не выполняется
    }
}
```

Очистка при уничтожении может бросить исключение (`defer` с бросающим вызовом), поэтому конец области, где
уничтожается приостановленный генератор, бросает то же, что очистка у его `yield`.

`for` по именованному генератору берёт его как `edit` на время цикла. После `break` генератор остаётся
приостановленным, его можно продолжить через `next()` или ещё одним `for`.

Это соответствует `Dispose` у итератора C#. Отдельная операция отмены из уничтожения не следует.

## Параметры и условия

Аргументы попадают в кадр при создании генератора, по виду параметра ([ownership.md](types/ownership.md)):

- `own` — перемещается в кадр;
- `read` типа `Copyable` — копируется, заём не нужен;
- `read` или `edit` другого типа: временный аргумент перемещается в кадр; именованное место одалживается на время
  жизни генератора;
- генератор с таким заёмом не покидает функцию, которая его создала: его нельзя вернуть, сохранить в поле или во
  внешней переменной.

`requires` проверяется при создании, по аргументам. Что означают `ensures` и `result` у генератора, пока не решено.

## Контексты

Тело видит контексты `with`, действующие там, где генератор создан, как замыкание видит `capture`
([closure.md](closure.md)). Генератор не переживает `with`, который дал нужный ему контекст: если компилятор видит,
что генератор живёт дольше, это ошибка компиляции.

```efen
with fileLog {
    for line in lines() {  // можно: генератор живёт внутри with
        print(line)
    }
}

fn outlived -> Generator yield String {
    with fileLog {
        return lines()  // ошибка: генератор переживает with, а lines() нужен его контекст
    }
}
```

## Чего пока нет

Генератор как метод класса или структуры, `yield from`, `flow generator` ([flow.md](flow.md)), отдача ссылок.

## Сравнение с функцией

| Конструкция | Поведение |
|---|---|
| `fn` | выполняется один раз и возвращает результат |
| `generator` | отдаёт значения по одному, между ними стоит на месте |
| `return` в генераторе | завершает его и задаёт итоговый результат |
| `yield` | отдаёт значение и приостанавливает тело |
