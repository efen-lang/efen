# Flow

[Документация](index.md) · [Словарь](glossary.md) · [Генераторы](generators.md) · [Контексты и эффекты](context-and-effects.md)

Flow — это синтаксис для описания монадических последовательностей вычислений в языке Efen.

## Концепция

`flow { ... }` — это базовая конструкция языка `Efen`.  
Она описывает монадическую последовательность зависимых вычислений, 
где каждый шаг возвращает значение в вычислительном контексте.
Итог блока задаёт `return` последней инструкцией.

`return` внутри `flow` завершает сам блок и задаёт его значение в текущем
вычислительном контексте. Он не возвращает из окружающей обычной функции.

Один `flow` использует один вычислительный контекст. Все операции `<-`, ветви и
итоговый `return` должны принадлежать ему. Компилятор не смешивает, например,
`Future<T>` и `U?` автоматически:

```efen
flow {
    user <- loadUser()        // Future<User>
    token <- findToken(user)  // Token?: ошибка контекста
    return token
}
```

Переход между контекстами выполняется явной операцией или явно выбранной
стратегией преобразования до соответствующего шага `flow`.

## Базовый синтаксис

```efen
flow {
    x <- getUser()
    y <- fetchScore(x)
    return y
}
```

Каждый шаг внутри блока `flow` представляет отдельное вычисление, которое может зависеть от предыдущих, но не обязано.  
Компилятор самостоятельно определяет зависимости и порядок выполнения на основе используемых значений.

## Операция связывания `<-`

Оператор `<-` используется для извлечения значения из монадического контекста.  
Он связывает результат вычисления с переменной, позволяя использовать её в последующих шагах.

```efen
flow {
    x <- getUser()          // getUser() возвращает значение в контексте (
    y <- fetchScore(x)     // fetchScore зависит от x
    return y
}
```

Если функция возвращает значение в контексте `Future`, `IO`, `Option` и т.д.,
операция `<-` извлекает это значение для дальнейшего использования.

## Оператор зависимого выполнения `|-`

Оператор `|-` позволяет выполнять действия в монадическом контексте без извлечения значения.
Он работает строго после ближайшего шага с `<-`:

```efen
flow {
    x <- getUser()
    |- log("Пользователь получен: ${x.name}")
    
    y <- fetchScore(x)
    |- log("Баллы пользователя: ${y}")
    return y
}
```

Оператор `|-` используется по-умолчанию, поэтому следующее выражение эквивалентно:

```efen
flow {
    x <- getUser()
    log("Пользователь получен: ${x.name}")
    
    y <- fetchScore(x)
    log("Баллы пользователя: ${y}")
    return y
}
```

## Оператор catch `catch Err`

Оператор `catch Err` позволяет обрабатывать ошибки, возникающие в предыдущем шаге с `<-`.
Общий вид:

```efen
flow {
    x <- someOperation()
    catch Err handleError(x)    
    |- catch Err log("Ошибка при выполнении someOperation: ${$error}")
    return x
}
```

## Условные фильтры и ветвления

Условные выражения внутри `flow` позволяют управлять ходом вычислений в рамках монадического контекста.  
Поддерживаются формы `if`, `if else`, `else if`, а также управляющие операторы `continue` и `break`.

---

### Простое условие

```efen
flow {
    x <- getUser()
    if x > 5 continue
    y <- fetchScore(x)
    return y
}
```

`continue` пропускает оставшиеся шаги текущей итерации и переходит к следующей.  
Если условие ложно — выполнение продолжается как обычно.

---

### Прерывание вычислений

```efen
flow {
    x <- getUser()
    if x == null break
    y <- fetchScore(x)
    return y
}
```

`break` немедленно завершает выполнение текущего блока `flow`.  
Результат предыдущих вычислений может быть возвращён как частичный или `none`, в зависимости от контекста.

---

### Условие с альтернативой

```efen
flow {
    x <- getUser()
    if x > 5
        y <- fetchScore(x)
    else
        y <- fetchDefault()
    return y
}
```

Обе ветки остаются в том же вычислительном контексте.  
`return` возвращает результат выбранной ветви.

---

### Составное ветвление

```efen
flow {
    x <- getUser()
    if x > 10
        y <- fetchPremium(x)
    else if x > 5
        y <- fetchRegular(x)
    else
        y <- fetchDefault()
    return y
}
```

Каждое условие проверяется последовательно.  
Как только одно выполняется — используется соответствующая ветка.

---

### Вложенные условия

```efen
flow {
    x <- getUser()

    if x != null
        if x.isAdmin()
            y <- fetchAdminData(x)
        else
            y <- fetchUserData(x)
    else
        y <- fetchGuestData()

    return y
}
```

Вложенные `if` позволяют уточнять логику без выхода из контекста.  
Каждое условие проверяется последовательно, а результат каждой ветви остаётся частью общего монадического потока.

## Циклы в монадическом `flow`

Циклы внутри `flow` — часть монадического потока вычислений.  
Они не императивны: каждое повторение — отдельный шаг, выполняемый в том же контексте.

---

### Цикл `while`

```efen
flow {
    x <- fetchNext()
    while x != null {
        process(x)
        x <- fetchNext()
    }
    return done()
}
```

`while` продолжает вычисления, пока условие истинно.  
Каждое тело цикла выполняется в том же контексте, что и окружающий `flow`.  
Если в теле есть `<-`, оно создаёт новую точку связывания внутри итерации.

---

### Цикл `repeat`

```efen
flow {
    repeat 5 {
        log("tick")
    }
    return done()
}
```

`repeat N` выполняет тело указанное количество раз, не покидая контекста.  
Все вызовы внутри тела (`await`, `<-`, `if`, `match`) остаются частью общей монадической цепочки.

---

### Цикл `loop`

```efen
flow {
    loop {
        x <- fetchNext()
        if x == null break
        process(x)
    }
    return done()
}
```

`loop` — бесконечный цикл, завершающийся при `break`.  
`break` и `continue` не разрывают контекст, а лишь управляют внутренним потоком итераций.

---

### Семантика

- Все формы (`while`, `repeat`, `loop`) компилируются в монадические операции связывания.
- Циклы не создают новых областей выполнения и не нарушают контекст.
- Операторы `break` и `continue` действуют только внутри текущего `flow`, сохраняя чистую модель вычислений.

## Монадический `match`

`match` в Efen — это часть монадического потока, аналогичная `if` и `flow`.  
После образца через двоеточие указывается тело ветки.
`Result<T, E>` в примере — [variant type](types/variant.md).

```efen
flow {
    result <- fetchData()
    y <- match result {
        .ok.{ let value }: handle(value)
        .err.{ let error }: recover(error)
    }
    return y
}
```

Каждая ветка выполняется в том же контексте (`Future`, `IO`, `Option` и т.д.)  
и может содержать собственные `if`, `loop`, `break` и `continue`.

## Flow-функции

Функции могут быть объявлены с использованием `flow`, что позволяет создавать монадические функции-генераторы.

```efen
flow fetchAndProcess() -> Result<Data, Error> {
    user <- getUser()
    data <- fetchData(user)
    processed <- processData(data)
    
    return processed
}
```

Все синтаксические правила для функций применимы, включая параметры, возвращаемые значения и обработку ошибок.
Смотреть также раздел [Функции](functions.md).

Flow-функция конечно же может использовать эффекты и контексты:

```efen
flow generator ticketsPrinter(ticket: Ticket) in Logger, Queue, Account {
    
    user <- Account.getUser(ticket.userId)
    |- Logger.log("Печать билета для пользователя ${user.name}")
    |- Err Logger.log("Ошибка получения пользователя: ${$error}")
    
    // Сформировать письмо с описанием билета
    email <- Storage.Email(to: user.email, subject: "Ваш билет", body: "Билет на событие ${ticket.eventName}")
    
    // Отправить письмо
    Queue.enqueue(email) 
    |- Logger.log("Письмо с билетом отправлено на ${user.email}")
    |- Ticket.markAsSent(ticket.id)    
}

```

## Flow генераторы

Генераторы на основе `flow` позволяют создавать ленивые последовательности значений в монадическом контексте.

```efen
flow generator numberStream -> Int {
    var n = 0
    loop {
        n = n + 1
        // передаём текущее значение n в поток
        yield n
    }
}

fn main {
    gen = numberStream()
    print(gen.next()) // 1
    print(gen.next()) // 2
    print(gen.next()) // 3
}

```

Значение, отданное через `yield`, может быть использовано в монадическом контексте, позволяя строить сложные ленивые вычисления.
