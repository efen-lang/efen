# Что компилятор берёт у рантайма

[Runtime API](index.md) · [Контракты](../contracts.md) · [Операторы](../operators.md) · [Исключения](../throws.md)

Компилятор Efen знает правила языка и не знает ни одной функции, которую выполняет программа. Сравнение строк,
склейка, выделение памяти, раскрутка стека написаны на Efen и лежат вне компилятора. Этот документ перечисляет всё,
что компилятор обязан найти снаружи, и свойства, которые каждый пункт обязан иметь. По нему второй компилятор или
проверяющий узнаёт, что должен дать рантайм, а автор рантайма — что он обязан реализовать.

```efen
let greeting = "При" + "вет"     // `+` вызывает функцию контракта lang::Addable; её реализует String рантайма
if greeting == "Привет" { … }    // `==` вызывает lang::Equatable; своего сравнения компилятор не пишет
```

## Где что лежит

| Часть | Что в ней | Кто может заменить |
|---|---|---|
| Файлы `lang::` | Объявления контрактов языка на Efen: операторы, `Copyable`, `Throwable`, интерполяция; корни `Exception`, `Fault`, `Cancellation`, `AssertionError` и исключения без полей, которые бросает компилятор | Никто: идут вместе с компилятором и не меняются |
| Слой `lang` рантайма | Реализации контрактов для примитивов, тип строкового литерала с `==`, ловушки, раскрутка, системные вызовы, интерполяция примитивов в буфер вызывающего | Только версия рантайма целиком |
| Аллокатор | Выделение и освобождение памяти. Отдельная библиотека над `lang`, их может быть много | Конфигурация сборки называет один; рантайм несёт свой по умолчанию |
| Остальной рантайм | Склейка и копия строк, массивы литералов, поля исключений, хранение классов с одним владельцем | Части заменяются через конфигурацию сборки |
| std | Классы со счётчиком (`retain`, `release`), словарь `[K: V]`, алгоритмы, коллекции, файлы, сеть, `print` | Подключается по умолчанию, программа может отказаться; класс со счётчиком без std — ошибка сборки |

Корни и исключения без полей объявлены в файлах `lang::`, а не в рантайме: заменять в них нечего, и компилятор знает
их по имени, как `lang::Equatable`. В Amber файлы `lang::` лежат в `frontend/efen/lang/` и ставятся рядом с
компилятором.

Слой `lang` не берёт память из кучи: выделение внутри него — ошибка сборки. Поэтому аллокатор и путь «память
кончилась» стоят на коде, который ничего не выделяет, а программа без кучи (ядро, прошивка) берёт только `lang`.
В такой программе есть строковые литералы и исключения без полей, но нет склейки строк:

```efen
// allocator: none
let name = "boot"            // постоянные байты
if name == "boot" { … }      // сравнение байтов, без выделения
throw OverflowError()        // без полей, вечное
let full = name + "!"        // ошибка сборки: `+` строк требует аллокатора
```

Словарь `[K: V]` лежит в std: программа без std, в которой есть словарь, не компилируется.

Рантайм — обязательная часть программы, std — по желанию. Пространства имён: `lang::` — контракты языка,
`runtime::` и `std::` — библиотеки, `efen::` и `compiler::` — расширение компилятора.

## Контракты операторов

Какой контракт вызывает оператор, знает компилятор. Сами контракты объявлены в файлах `lang::`. Для `Int`, `Bool` и
других примитивов операторы встроены в компилятор; их соответствие контрактам нужно generic-коду.

| Оператор | Контракт | Обязательные свойства |
|---|---|---|
| `==` `!=` | `lang::Equatable` | Аргументы только читаются; `nothrows`; `!=` — отрицание `==` |
| `<` `>` `<=` `>=` `<=>` | `lang::Comparable` | Аргументы только читаются; `nothrows` |
| `+` | `lang::Addable` | Аргументы только читаются; результат — новое значение во владении вызывающего |
| `copy x` | `lang::Copyable` | Источник только читается; результат независим от источника ([контракты](../contracts.md#оператор-copy)) |
| `"${x}"` | `lang::Interpolatable` | `fn writeText(buffer: mut TextBuffer) -> Int`: пишет в буфер столько текста, сколько входит, и возвращает, сколько байт нужно всему тексту. Текст примитивов пишет рантайм через `lang::PrimitiveText`; `TextBuffer` объявлен в `lang::` |

Пока `String` — встроенный тип компилятора, а не тип рантайма, `==` строк вызывает временный контракт
`lang::StringEquality` (`fn equal(left: String, right: String) -> Bool nofail`). Его реализует рантайм на Efen,
читая байты строки по одному: `s.utf8[i]` — байт, значение, а не место. Когда `String` станет типом рантайма, `==` пойдёт через `lang::Equatable`, и `StringEquality`
уйдёт.

```efen
if name == "Привет" { … }    // пока String встроен: lang::StringEquality.equal(left: name, right: "Привет")
```

Законы, которые нельзя доказать в общем виде (`a == b` влечёт `b == a`), автор типа соблюдает сам. Компилятор не
опирается на них ради корректности программы, только на форму и эффекты.

Остальные операторы (`-`, `*`, `/`, `%`, побитовые) получат свои контракты тем же способом; их список и имена ещё
не выбраны.

## Что компилятор берёт у рантайма

У каждого пункта есть форма (поля и раскладка типа или сигнатура функции) и обязательные эффекты. Все пункты, кроме
отмеченных, лежат в слое `lang` и ничего не выделяют.

Пункт объявлен в файле `lang::` как контракт с атрибутом `@unique`, а рантайм даёт его реализацией контракта. Компилятор
находит её по контракту, а не по имени: в сборке действует ровно одна реализация каждого пункта: рантайма по умолчанию или та, которую связала программа.

```efen
// lang/items.efen
@unique
contract Trap {
    fn stop(record: StopRecord) -> Never nofail
}

// рантайм
implementation Trap {
    fn stop(record: StopRecord) -> Never nofail { … }
}
```

Класс, поля и тела которого даёт рантайм, объявлен в файле `lang::` как [класс в контракте](../contracts.md#классы-в-контракте):
контракт задаёт имя, базу и подписи, `implementation` рантайма — поля и тела.

### Типы литералов

| Пункт | Форма | Свойства |
|---|---|---|
| Тип строкового литерала | `String` | В слое `lang`; раскладка — часть версии рантайма; литерал — постоянные байты, которые никогда не освобождаются; `+` и `copy` — выше аллокатора |
| Тип литерала массива `[1, 2]` | базовый массив | Выше аллокатора; раскладка — часть версии рантайма |

### Память

| Пункт | Свойства |
|---|---|
| Выделить | Нехватка памяти — `AllocationError`, без выделения на этом пути |
| Освободить | `nofail` |
| Хранение объекта класса с одним владельцем | Выше аллокатора |

### Исключения языка

| Пункт | Когда бросает компилятор | Свойства |
|---|---|---|
| `Throwable`, `Reason` | Контракт всего брошенного и его `reason()` ([иерархия](../throws.md#иерархия)) | В файлах `lang::`; соблюдают только четыре корня ниже; `Reason` — `open enum`, тег 16 бит ([расширение](../types/enum.md#расширение)) |
| `Exception` | Корень ошибок | Класс с одним владельцем; корень без полей объявлен в файлах `lang::`, поля — в подклассах рантайма выше аллокатора |
| `Fault` | Корень сбоев ([исключения](../throws.md)) | В файлах `lang::`, без полей |
| `Cancellation` | Отмена задачи | В файлах `lang::`, без полей; бросает рантайм, ловит только контекст задач |
| `AllocationError` | Нехватка памяти | `Fault`; в файлах `lang::`; без полей, вечный: бросок ничего не выделяет |
| `OverflowError` | Переполнение | `Fault`; в файлах `lang::`; без полей, вечный |
| `DivisionByZeroError` | Деление на ноль | `Fault`; в файлах `lang::`; без полей, вечный |
| `NullUnwrapError` | `x!` на `null` | `Fault`; в файлах `lang::`; без полей, вечный |
| `BoundsError` | Недоказанный индекс или диапазон вне коллекции | `Fault`; в файлах `lang::`; без полей, вечный |
| `StackExhaustedError` | Исчерпание стека | `Fault`; в файлах `lang::`; без полей, вечный |
| `UncaughtHandler` | Брошенное, которому некуда идти ([исключения](../throws.md#исключение-которое-никто-не-ловит)) | `@unique` контракт, `fn handle(thrown: Throwable) -> Never nofail`; реализация по умолчанию — рантайма, программа связывает свою в `effects`; вызывается до раскрутки, ничего не выделяет, работает на запасном стеке |
| `AssertionError` | Ложный `assert` ([тесты](../tests/tests.md)) | Свой корень, `CatchRestriction`, бросок без кучи: провал лежит в месте своей задачи (поток без задач — одна задача); место выделяет `spawn`, запись переносят `await` и конец блока `with` — обязанность контракта асинхронного контекста, место и текст условия — постоянные данные, значения сторон и сообщение контракт интерполяции пишет в постоянный буфер. На `nofail`, `deinit`, `dispose`, входе из C и в точках броска, где проверка выхода не прошла ([тесты](../tests/tests.md#assert)), — остановка, как `halt()`. Доставка провала задачи (`await`, конец блока) — тоже точка броска. В том же месте лежит счётчик выполненных проверок `assert` и `assert throws`: компилятор прибавляет к нему единицу после каждой, функция случая теста обнуляет его в начале и читает в конце (`assertsChecked`); `await` и конец блока прибавляют счёт задачи к счёту ждущей (агент) |

### Тесты

Тестовая сборка передаёт таблицу тестов прогонщику фреймворка тестов ([тесты](../tests/tests.md)). Типы записи
таблицы, областей значений параметров и контракт прогонщика объявлены в файле `lang::`, который идёт с
компилятором, вместе с номером версии их формы. Сам прогонщик — не часть рантайма: программа выбирает фреймворк в
конфигурации сборки.

### Раскрутка

| Пункт | Свойства |
|---|---|
| Бросить исключение | `nofail`, ничего не выделяет |
| Процедура разбора кадров (personality) | `nofail`, ничего не выделяет; своя для каждой платформы (на Windows — системная SEH, а не `.eh_frame`) |
| Трасса стека: захват | `nofail`, ничего не выделяет; своя для каждой платформы |
| `Throwable.stackTrace(limit:frames:)` и `Throwable.throwTrace(limit:frames:)` | Исключение только читается; результат — `Trace` ([трасса стека](../throws.md#трасса-стека)). По этим пунктам компилятор находит `catch`, которому нужна трасса |
| `Trace`, `TraceFrame` | Раскладка — часть версии рантайма |

### Проверки и ловушки

| Пункт | Свойства |
|---|---|
| Ловушка (остановка программы) | `nofail`, `-> Never`; принимает запись о причине остановки (`StopRecord` из файла `lang::` тестов), которую компилятор строит в месте остановки; в тестовой сборке её подставляет фреймворк тестов ([тесты](../tests/tests.md)) |
| Рантайм проверок | Сам рантайм собирается с проверками-ловушками, поэтому никогда не проверяет себя |

### Системные вызовы

| Пункт | Свойства |
|---|---|
| `System` | Своя реализация для каждой платформы; песочница подменяет её через конфигурацию сборки |

## Проверки в начале сборки

Компилятор в начале сборки находит каждый нужный ему пункт и сверяет его с образцом из своих файлов `lang::`.
Ошибка всегда названа и указывает на пункт:

- **пункта нет** — например, рантайм без типа строкового литерала, а в программе есть строка;
- **пункт объявлен дважды** — два рантайма или пакета дают один пункт, и конфигурация не говорит, какой взять;
- **не та форма** — другая сигнатура или раскладка;
- **не те эффекты** — например, освобождение может бросить, хотя обязано быть `nofail`.

Тела рантайма — обычный код на Efen, FLOW доказывает их как код программы. Места, которые FLOW ещё не доказывает
(сырая память в аллокаторе и раскрутке), рантайм перечисляет явно, с причиной.

## Замена и версии

- Аллокатор, `System` песочницы, обработчик непойманных и другие пункты рантайма заменяются одной строкой
  конфигурации программы: связыванием `@unique` контракта в `effects` (`UncaughtHandler: CrashReporter`). Без такой
  строки два объявления одного пункта — ошибка (Edmond, 2026-10-31).
- Компилятор и рантайм выпускаются одной версией: компилятор называет версию рантайма, которую читает.
- Раскладка каждого типа из этого документа — часть версии рантайма. Программа хранит хеш рантайма, с которым
  собрана, поэтому хозяин песочницы или чужой код могут отказаться от несовпадающего. Хеш — xxHash64 текстов единиц
  рантайма в порядке чтения, каждый после своей длины в 8 байтах; в программе это постоянное слово
  `efen.runtime.hash`, которое компоновщик не выбрасывает.
- Результаты проверки рантайма кешируются по версии компилятора, хешу рантайма и набору скрытых параметров
  (песочница и обычная сборка различаются).
