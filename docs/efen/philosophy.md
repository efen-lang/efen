## Один канонический способ

Каждое действие в Efen записывается ровно одним каноническим способом. Язык не
даёт программисту выбирать между двумя формами одного смысла. Это уменьшает
число вариантов, которые нужно помнить, читать, форматировать, проверять и
порождать инструментам.

Вторая форма либо удаляется из грамматики, либо остаётся разбираемой и получает
[диагностику стиля `S`](diagnostic-groups.md#style-diagnostics-s), по умолчанию
ошибку. Разница между двумя видами ошибок:

- ошибка синтаксиса — смысл записи неясен, у неё больше одного прочтения;
- диагностика стиля — смысл ясен, но запись не каноническая.

Если каноническая форма зависит от условия, условие записано правилом стиля, а
не оставлено вкусу автора: объявление больше трёх параметров использует
`param`, перенос выражения ставит оператор в начало строки.

Принцип не требует делать разные операции внешне одинаковыми. Различие
сохраняется, когда оно сообщает семантику, правила владения, эффекты или границу
выражения.

Первое нормативное применение принципа — объявления функций без параметров.
Пустой список `()` не несёт информации, поэтому он не записывается:

```efen
fn reset {
    // ...
}

fn count -> Size {
    return items.count
}
```

Форма с пустыми скобками является синтаксической ошибкой:

```efen
fn reset() { } // Ошибка: в объявлении функции без параметров `()` запрещены.
```

При вызове скобки сохраняются:

```efen
reset()
let size = count()
```

Вызов должен отличаться от получения функции как значения. Поэтому отсутствие
параметров устраняет скобки только из объявления, а не из вызова.

## Остальные ориентиры

- Логическая семантика отделяется от представления и преобразования в
  низкоуровневый код.
- Владение и эффекты видны в типах и контрактах, когда они влияют на
  вызывающий код.
- Один механизм переиспользуется вместо нескольких специальных конструкций,
  когда он сохраняет ясность и проверяемость.
- Неявное поведение допускается только через явно объявленный контракт, который
  компилятор может проверить и показать инструментам.
- Канонический синтаксис является частью языка, а не рекомендацией
  форматировщика.
