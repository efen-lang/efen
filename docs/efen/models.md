# Модели поведения функций

[Документация](README.md) · [Условия функций](conditions.md) · [Layout и память](memory/layout-reference.md) · [Правила доступа к памяти](memory/memory-rules.md)

## Модель `model`

Модель — абстрактный код после сигнатуры функции: `model { … }`. Её не компилируют; FLOW читает её как сводку того,
что функция кладёт в поля `layout` и что с них снимает. Сами поля и всё остальное о памяти объявляет `layout` типа
([`layout` в теле класса](classes.md#layout-в-теле-класса)); модель только пишет в них.

```efen
mut fn sqlite3_bind_text(index: Int32, text: read CString, length: Int32,
                         destructor: sqlite3_destructor_type) -> Int32
model { if destructor == SQLITE_STATIC { self.bound[index] = text } else { self.bound.remove(index) } }
```

- **Место.** После хвоста сигнатуры и после `requires`/`ensures`, перед телом, если оно есть. Модель бывает у
  внешних функций и методов (`@abi(c)`, `@asm`, `@intrinsic`, функции бинарного пакета), у методов контрактов и
  интерфейсов и у любой функции с телом. У литерала замыкания, типа функции и генератора модели нет.
- **Содержимое — закрытый список.** Параметры, `self`, `result` (состояние после вызова), поля `layout` и настоящие
  поля `self` и параметров; `if`, `if let`, `match` по параметру или `result`; `==` и `!=` с константой или `null`;
  `=` в поле `layout`; `take` параметра `own` в поле; на абстрактных коллекциях `[k] = v`, `remove(k)`, `clear()`,
  `append(v)`, `remove(v)`. Проекции (`name.cString`, путь по полям, `.values`, `[k]` у настоящей коллекции) вызовами
  не считаются. Других вызовов, циклов и арифметики в модели нет.
- **Проверка модели.** Права: заимствование не шире права параметра. Владение: параметр забирается ровно на путях, где
  верна правая часть его строки `taken`, безусловный `own` — на каждом пути. Живость: в поле кладут параметр или путь через него, никогда
  временное значение. Сравнение с константой решается, только когда аргумент — эта константа; макрос C без
  параметров переносится как `const` типа указателя ([библиотеки на C](foreign.md#что-amber-переносит-сам)).
- **Модель и тело.** Тело заимствует не больше модели: ничего сверх неё, не дольше, не с более широким правом, и не
  снимает того, что заимствует модель. Модель уже тела — ошибка; модель шире тела — предупреждение с названием лишнего
  заимствования.
- **Умолчания.** Функция без модели и без тела после вызова ничего не заимствует. У функции с телом и без модели сводку
  выводит компилятор и кладёт в заголовки пакета. Чего модель не называет, то не меняется: заимствования остаются.
  Снятие пишется явно, под тем условием, при котором внешняя сторона действительно отпускает.
- **Исключение.** Внешняя функция исключений не бросает. Модель функции Efen описывает обычный возврат; при
  `throws E` новых заимствований нет, если строка `ensures throws E ==> taken(x)` не говорит, что параметр забран.

Модели функции без тела компилятор верит, как её `ensures`: она попадает в список доверия
([кому доступно доверие](memory/system.md#кому-доступно-доверие)), а проверочная сборка сверяет с ней поведение
внешней стороны, когда может. Модель метода контракта или интерфейса — сводка каждого вызова через него; каждая
реализация проверяется там, где написана ([контракты](models.md#модели-контрактов-и-интерфейсов)).

<a id="удержания"></a>
### Заимствования

Заимствование, которое живёт в структуре, — то, что модель записала в поле `layout`: слот аргумента, сведённый к корню и пути (`name.cString` заимствует
`name`; `row` цикла `for row in rows` заимствует `rows[i]` с корнем `rows`), зависимость от внешнего объекта за аргументом
класса над внешним значением или значение `own`. Заимствование живёт, пока его не снимут (перезапись, `remove`,
`clear`, `null`), или пока объект не уничтожен. Использование заимствованного не моделируется.

- **Синхронный режим** — по умолчанию: внешняя сторона трогает заимствованное только во время вызовов с объектом.
  Пока объект держит слот `read` или `edit`, владелец слота читает его и пишет значения, но не меняет структуру,
  не перемещает, не уничтожает и не отдаёт — как при ссылке внутри функции
  ([что ссылке можно и нельзя](types/ownership.md#что-ссылке-можно-и-нельзя)). При зависимости `mut U` или
  `read U` владелец `U` вызывает всё, кроме уничтожения и передачи.
- **Параллельный режим.** Структура, которая заимствует и попала в тело многопоточной корутины (`capture … = take` или
  заимствованное имя), в тело `offload`, в поле `shared` или в объект `shared layout`, везёт туда свои заимствования: каждое
  становится областью доступа этого режима с правом заимствования (`read`, `edit`; `mut U` — вызовы с `U`), и до конца
  режима или снятия заимствования действует таблица многопоточного вида
  ([корутины `spawn`](types/access-regions.md#корутины-spawn), [общая память](shared.md#пометка-shared)).
- **Ссылки умирают.** Вызов с правом `mut` убивает каждую ссылку с источником в объекте и в каждом объекте,
  достижимом через поля `layout` с правом `mut`: `read<db.errmsg>` умирает на `s.sqlite3_step()`, потому что `s.db` —
  `mut sqlite3`. Вызов `read` не убивает ничего.
- **Сильное и слабое обновление.** `obj.field = v` у параметра и `self` заменяет прежнее заимствование. У абстрактного
  словаря запись сильная при ключе, равном константе при сборке, иначе слабая: прежнее заимствование остаётся.
  `remove(k)` с неизвестным `k` ничего не снимает, `clear()` снимает всё. `null` в элемент неoptional-типа — ошибка.
- **Живость.** Слот, область которого кончается, пока его заимствует живой объект, — ошибка с именем этого объекта и вызова,
  который положил заимствование. Заимствования едут с объектом: `take`, `capture … = take`, запись в поле или контейнер,
  передача в функцию.
- **Кто заимствует.** Заимствование лежит только на объекте, слот которого видит FLOW: локальная переменная, параметр, поле
  `own` или элемент, достижимые из них через обычные слоты. Структура, которая заимствует, в `managed`-слоте (поле класса со счётчиком,
  элемент коллекции внутри него) при записи и на каждом выходе метода этого класса держит только внешние объекты,
  названные отношением в `invariants` класса; заимствований слотов Efen на нём нет. Сам `managed`-слот заимствовать нельзя.
- **Настоящие поля.** Модель, которая называет настоящее поле параметра или `self` (`pool.items.append(take s)`,
  `self.cache[sql].bound[1] = name.cString`), переносит заимствование на этот объект. Заимствование из параметра в `self`
  допустимо: это сводка метода, и вызывающий отвечает за то, чтобы слот жил не меньше `self`.
- **Контейнер заимствующих структур** с одним владельцем держит объединение заимствований своих элементов. Удаление элемента
  снимает их слабо; `removeAll()`, уничтожение контейнера и доказанный факт `count == 0` (из `ensures` коллекции,
  например `removeLast`) — сильно.
- **Результат, который заимствует.** `-> own sqlite3_stmt?` с `model { if let r = result { r.bound[1] = name.cString } }`
  заимствует `name`; голое `result.bound` у возможно пустого результата — ошибка.
- **Значение-функция.** Функция или замыкание, модель или сводка которой кладёт заимствование между параметрами или из
  параметра в результат, не подходит ни к одному типу функции
  ([тип функции](types/function-type.md#ссылка-в-результате-типа-функции)).

```efen
class Pool { var items: Vector<own sqlite3_stmt> }

fn park(pool: mut Pool, s: own sqlite3_stmt)
model { pool.items.append(take s) }              // заимствования s переходят к pool
{
    pool.items.append(take s)
}
```

<a id="отношения-в-layout-класса"></a>

### Отношения в `invariants` класса

Строка [`invariants`](conditions.md#условия-значений-и-invariants) класса связывает его настоящие поля с полями `layout`
элементов: `forall s in cache.values: s.db == db`. Отношение пишет любой класс с настоящими полями. У класса со счётчиком
строк `var` в `layout` нет, но отношение есть: структура, которая заимствует, в его `managed`-слоте держит только внешние объекты, которые
отношение называет ([заимствования](#заимствования)). Отношение верно в каждой
[точке восстановления](conditions.md#когда-условие-проверяется): к ней FLOW доказывает его по всем записям полей, которые оно
называет, настоящих и `layout`, по любому пути от `self`, включая записи, которые делает модель вызванной функции:

- вставка в `cache` доказывает `s.db == db` по происхождению элемента: его `db` записала модель
  `sqlite3_prepare_v2` из того же `db`;
- модель, которая пишет `e.multi` у элемента, достижимого через `easies`, обязана заново доказать отношение;
- после замены, `take` или отдачи `db` адреса `s.db` в `cache` висячие: чтение через них (`sqlite3_finalize` при
  удалении из `cache`) — ошибка FLOW. Поэтому `cache` очищают до замены `db`;
- порядок уничтожения полей следует из отношения: `cache` раньше `db`
  ([порядок уничтожения](classes.md#layout-в-теле-класса)).

Связанное поле можно передать функции (`mut self.cache`), если её модель или сводка не добавляет элемент и не пишет
связанное поле `layout`; иначе ошибка называет отношение. Это правило условия поля
([ниже](conditions.md#условие-поля-и-состояние-типа)) для отношений.

```efen
class Connection {
    var db: own sqlite3
    var cache: Dictionary<String, own sqlite3_stmt>
    invariants { forall s in cache.values: s.db == db }

    mut fn evict(sql: read String) { cache.remove(sql) }   // удаление сохраняет forall
    mut fn reopen(path: read CString) {
        cache.removeAll()                                  // сильное обновление: cache пуст
        var opened: sqlite3? = null
        let rc = sqlite3.sqlite3_open(filename: path, self: opened)
        guard let d = opened, rc == SQLITE_OK else { return }
        db = take d                                        // можно: cache доказанно пуст
    }
}
```

## Модели контрактов и интерфейсов


Контракт может объявить `layout { var … }` и [модели](models.md#модель-model) у методов. Поля такого `layout` — не
поля, хранящиеся в объекте: их нет в байтах, их пишут только модели и читает только FLOW
([`layout` в теле класса](classes.md#layout-в-теле-класса)). Обобщённый код над контрактом берёт модель
метода как сводку вызова; каждая реализация проверяется там, где написан `conforms`, как пометки `edit fn`. `layout`
и модели входят в объявление контракта. При выполнении они ничего не стоят: вызов остаётся статическим, таблицы
методов нет.

```efen
contract Sink {                                  // хранит буферы между write и flush
    layout { var kept: [read [UInt8]] }
    mut fn write(data: read [UInt8])
    model { self.kept.append(data) }
    mut fn flush
    model { self.kept.clear() }
}

fn dump<S: Sink>(out: mut S, lines: read [String]) {
    for line in lines {
        let buf = line.utf8()
        out.write(data: buf)
        out.flush()                              // без него ошибка: buf умирает, пока out его держит
    }
}

public class File {
    conforms Sink
    representation Raw<Descriptor>
    mut fn write(data: read [UInt8]) { … }       // копирует: заимствований нет, модель Sink уточнена
    mut fn flush { }
}
```

**Реализация сравнивается с моделью по заимствованиям, а не по полям.** Заимствование определяют метод, который его положил,
путь параметра и право; имена полей — учёт каждого объявления. После каждого метода заимствования реализации входят в
заимствования модели: реализация не кладёт ничего сверх модели, не берёт более широкого права и не заимствует того, что
модель снимает. Реализация, которая копирует, не заимствует ничего и уточняет любую модель.

`shared layout` реализации ([общая память](shared.md#shared-layout)) уточняет только `shared layout` контракта.
Реализация без `shared` под объявлением `shared layout` обещает меньше объявления, и это допустимо.

```efen
contract AsyncSink {                             // ядро читает буферы, когда захочет
    shared layout { var kept: [read [UInt8]] }
    mut fn write(data: read [UInt8])
    model { self.kept.append(data) }
    mut fn drain
    model { self.kept.clear() }
}

class Ring {
    conforms AsyncSink
    representation Raw<Descriptor>
    shared layout { var inflight: [read [UInt8]] }   // своё имя поля: сравниваются заимствования
    mut fn write(data: read [UInt8])
    model { self.inflight.append(data) }       // то же заимствование, что у AsyncSink.write
    {
        …
    }
    mut fn drain
    model { self.inflight.clear() }
    {
        …
    }
}
```

Контракт, у которого `write` всегда копирует, `layout` и моделей не объявляет: это другой контракт.
