# Доказательство структур на `layout`

[Layout](layout.md) · [Каталог структур](layout-catalogue.md) · [Условия](../conditions.md) · [Чужой опыт](prior-art.md)

Статус: разбор на бумаге (2026-11-08). FLOW этих доказательств ещё не строит; что ему для этого не хватает, названо в
каждом разделе и сведено в [итоге](#итог).

Структура на `layout` доказывается индукцией по событиям: закон верен в начальном состоянии, каждое событие его
сохраняет, а уничтожение, перемещение и смена вида не оставляют висячих ссылок. Остальные состояния выводятся из
начального цепочкой событий и отдельно не доказываются. Так доказывается и произвольный граф: память
узлов держит множество, рёбра — имена, а владелец узла — функция, которая его освобождает. Не доказывается локально
только владение, которое зависит от достижимости по графу: цикл якорей, который держится одними именами.

## Правила доказательства

Доказательство структуры складывается из четырёх частей.

| Часть | Что доказывается | Кто пишет |
|---|---|---|
| закон | форма структуры: где лежат якоря и имена | программист, в `layout` |
| база | закон верен в начальном состоянии: пустая структура, только что рождённый элемент | FLOW |
| шаг | каждое событие, меняющее структуру, сохраняет закон | FLOW |
| крайнее состояние | уничтожение, перемещение, смена вида не оставляют [висячих ссылок](layout.md#общий-принцип) | FLOW |

**Шаг проверяется по окрестности события.** Закон раскрывается только на узлах, которых событие касается: на узлах,
названных в коде, и на местах, куда указывает сам закон (`next!.prev`). Для остальной части структуры закон верен,
потому что событие её не тронуло. Так устроены natural proofs (Qiu, Garg, Ştefănescu, Madhusudan, PLDI 2013, логика
Dryad): рекурсивное определение раскрывается на следе кода, и Z3 получает формулу без рекурсии. По пересказу авторов,
так автоматически доказаны списки, деревья поиска, AVL и красно-чёрные деревья, кучи и функции glib; статья здесь не
перепроверялась.

**Закон фиксирует обе стороны каждого имени.** Dryad получает обратное направление даром: рекурсивное определение
списка в логике разделения делает предшественника единственным. Закон первого порядка над множеством этого не даёт:
`next!.prev == self` говорит, что следующий смотрит назад, но не говорит, что узел с `prev == p` — это `p.next`. Поэтому
у каждого имени в законе есть обратная сторона (`prev == null || prev!.next == self`), или имя лежит в поле, которое
читается через якорь: якорь у значения один, значит, и предшественник по нему один. Без обратной стороны закон не
отвечает на вопрос «где имена», и окрестность события не ограничена.

**Держатели имён считаются от входа в функцию.** Внутри тела закон бывает нарушен, его проверяют в точках передачи.
Поэтому на событии уничтожения FLOW ищет имена не по закону в этой точке, а по состоянию на входе в функцию и записям
тела до события. Пример: в `A→B→C` после `n.next = take old.next` у `C` осталось `C.prev == B`; закон в этой точке
нарушен и о нём не говорит, но запись тела видна, и `destroy(take old)` до починки `C.prev` — ошибка.

**Отсутствие висячих ссылок делится между структурой и кодом.** Закон говорит, где имена на значение могут лежать;
код события показывает, что каждое из них мертво, переписано или верно. Чем точнее закон, тем больше работы в шагах,
которые его поддерживают, и тем меньше в событии.

| Где доказательство | Закон говорит | Код события делает | Раздел |
|---|---|---|---|
| в структуре | имён нет | ничего | [односвязный](#односвязный-список) |
| смешанное | имя одно, в известном месте, или имена — в одной цепочке узла | переписывает это имя или опустошает цепочку | [двусвязный](#двусвязный-список), [дерево](#дерево-с-родителем), [пара](#пара-и-кольцо), [граф со входящими](#граф-со-входящими-рёбрами) |
| в коде | имена — где угодно среди элементов множества | проходит всех держателей | [граф с исходящими](#граф-только-с-исходящими-рёбрами), [произвольный граф](#произвольный-граф-владелец--функция) |

**Что выводится.** Законы пишутся. Пометки сводок (уничтожает, отдаёт, оставляет), условия функций и инварианты типовых
циклов FLOW выводит сам. Типовой цикл — проход по цепочке до `null` или по счётчику; инвариант необычного цикла не
выводится, и такой цикл — ошибка с подсказкой.

**Граница локальности.** Обязательство события должно зависеть от ограниченной окрестности: от узлов, названных в
коде, и от мест, указанных законом. Если ответ зависит от путей произвольной длины через произвольные узлы, локально
он не доказывается ([раздел](#произвольный-граф-владелец--функция)).

Такое обязательство есть у каждой записи якоря `t.f = take r`: `t` не лежит в дереве якорей `r`, иначе цикл замкнётся
и его никто не уничтожит. Локально оно доказывается в трёх случаях: `r` только что оторван от структуры (`take x.right`
и запись спуска), `r` пришёл параметром `anchor` и у него нет детей-якорей, или `t` сам только что взят как корень.
В остальных случаях запись — ошибка. Это отвергает и часть верного кода:
`fn graft(x: mut Nodes.Item, s: anchor Nodes.Item) { x.left = take s }` не доказуема, если о `x` и `s` ничего не
известно, и FLOW выводит ей предусловие «`x` не лежит в дереве `s`», которое доказывает вызывающий.

## Односвязный список

```efen
layout {
    set area Nodes: Node

    struct Node {
        var next: anchor Nodes.Item? = null
    }

    struct List {
        var head: anchor Nodes.Item? = null
    }
}
```

**Закон.** Владение — цепочка от `head` по `next`. Имён на узлы нет, потому что в `layout` нет ни одного поля типа
`Nodes.Item`; это проверяемое условие, а не следствие якоря: `anchor` хранимые имена допускает.

**База.** `head == null`.

**Шаги.**

```efen
fn push(list: mut List, n: anchor Nodes.Item) {
    n.next = take list.head      // n пришёл якорем: он не в цепочке, цикла нет
    list.head = take n
}

fn pop(list: mut List) -> anchor Nodes.Item? {
    guard let first = take list.head else { return null }
    list.head = take first.next  // take пишет null в first.next
    return first
}
```

В `push` два обязательства. `n` не лежит в цепочке, иначе `n.next = take list.head` замкнёт цикл; это даёт
происхождение: `n` пришёл параметром `anchor`, его якорь был у вызывающего. И `n.next == null`: иначе запись
перепишет якорь собственного хвоста `n`, а если в этом хвосте лежит узел списка, цикл замкнётся с другой стороны.
Второе обязательство FLOW выводит в предусловие `push`.

**Крайнее состояние.** `destroy(take first)` после `pop`: имён на узел нет, висячих ссылок нет. Доказательство целиком в
структуре.

## Двусвязный список

```efen
layout {
    set area Nodes: Node

    struct Node {
        var next: anchor Nodes.Item? = null
        var prev: Nodes.Item? = null                    // имя
        invariants {
            next == null || next!.prev == self
            prev == null || prev!.next == self          // обратная сторона: предшественник единственный
        }
    }

    struct List {
        var head: anchor Nodes.Item? = null
        invariants { head == null || head!.prev == null }
    }
}
```

**Закон.** Имя на узел одно: `prev` его следующего соседа. Закон говорит, где оно лежит: `n.next!.prev`. Обратная
сторона `prev!.next == self` нужна, чтобы узел со «случайным» `prev` вне списка не прошёл: без неё узел, вынутый из
списка, сохранил бы `prev` на бывшего соседа, и уничтожение соседа этого имени не увидело бы.

**База.** Пустой список; узел, только что вставленный в голову, с `prev == null`.

**Шаг: вставка после узла `a`.** Предусловие `n.next == null` выводится, как в `push`.

```efen
fn insertAfter(a: mut Nodes.Item, n: anchor Nodes.Item) {
    n.prev = a
    n.next = take a.next
    if let b = n.next { b.prev = n }
    a.next = take n
}
```

Окрестность события — `a`, `n` и бывший сосед `b`. Закон проверяется на трёх узлах: `a.next!.prev == a`,
`n.next!.prev == n`, у `b` он не меняется. Остальные узлы событие не тронуло.

**Крайнее состояние: удаление из середины.**

```efen
fn remove(n: mut Nodes.Item) {
    guard let p = n.prev else { return }        // голову удаляет removeHead
    guard let node = take p.next else { return }   // якорь n: по закону p.next == n
    p.next = take node.next
    if let b = p.next { b.prev = p }           // единственное имя на n переписано
    destroy(take node)
}
```

На `destroy` FLOW спрашивает, где имена на `n`. Закон отвечает: только в `n.next!.prev`, то есть в `b.prev`. Оно
переписано на `p`. Собственное поле `n.prev` умирает вместе с `n`. То, что `take p.next` вынимает именно `n`, даёт
обратная сторона закона: `n.prev == p`, значит, `p.next == n`. Доказательство смешанное, но окрестность
ограничена тремя узлами.

## Дерево с родителем

```efen
layout {
    set area Nodes: Node

    struct Node {
        var left: anchor Nodes.Item? = null
        var right: anchor Nodes.Item? = null
        var parent: Nodes.Item? = null
        invariants {
            left == null || left!.parent == self
            right == null || right!.parent == self
        }
    }
}
```

**Закон.** Имя на узел одно: `parent` каждого его ребёнка. Владение — дерево по `left` и `right`.

**База.** Пустое дерево; лист с `parent`, указывающим на узел, в который его вставили.

**Шаг: левый поворот.**

```efen
fn rotateLeft(x: anchor Nodes.Item) -> anchor Nodes.Item {
    guard let y = take x.right else { return x }
    x.right = take y.left
    if let b = x.right { b.parent = x }
    y.parent = x.parent
    x.parent = y
    y.left = take x          // y вынут из x.right: в поддереве x его нет, цикла нет
    return y
}
```

Окрестность — `x`, `y`, `b`. Закон на трёх узлах: `x.right!.parent == x`, `y.left!.parent == y`; у `y` новый
родитель тот же, что был у `x`. FLOW выводит условие результата `result.parent == old(x.parent)`. По нему вызывающий
доказывает закон в узле, куда кладёт `y` вместо `x`. Цикла нет по записи спуска: `y` взят из `x.right`, значит,
оторван от поддерева `x`.

**Крайнее состояние: уничтожение поддерева.**

```efen
fn destroyTree(t: anchor Nodes.Item) {
    if let l = take t.left { destroyTree(t: take l) }
    if let r = take t.right { destroyTree(t: take r) }
    destroy(take t)
}
```

Имена на `t` по закону лежат только в `parent` его детей, а дети уже уничтожены. Имя на `t` из его родителя — это
якорь, его забрал вызывающий. Висячих ссылок нет. Рекурсия конечна: идёт по якорям, а якоря образуют дерево.

## Пара и кольцо

**Пара.** Цикл двух узлов строится из имён, якоря лежат снаружи.

```efen
layout {
    set area Nodes: Node

    struct Node {
        var peer: Nodes.Item? = null
        invariants { peer == null || peer!.peer == self }
    }
}

fn makePair(a: mut Nodes.Item, b: mut Nodes.Item) {
    a.peer = b
    b.peer = a               // база закона пары
}

fn dropPeer(a: mut Nodes.Item, b: anchor Nodes.Item) {
    a.peer = null            // закон: единственное имя на b — a.peer
    destroy(take b)          // b.peer умирает вместе с b
}
```

FLOW выводит предусловие `dropPeer`: `a.peer == b`. Без него `a.peer = null` нарушило бы закон у настоящего соседа
`a`. Время жизни `b` кончается в точке вызова `dropPeer`.

**Кольцо.** Узлы кольца держит реестр (цепочка якорей), связи кольца — имена `next` под законом «цепочка по `next` от
узла возвращается в него». Шаг «вставить после `a`» меняет два имени, но закон касается каждого узла кольца: цепочка
любого узла проходит через `a`. Довод корзин хеш-таблицы («произвольная цепочка, два случая») здесь не работает: у корзин есть
нетронутые цепочки, а в кольце через `a` проходит цепочка каждого узла. Обязательство — достижимость по пути любой
длины, а это за границей локальности. Удаление из кольца ищет предыдущее звено проходом, который кончается не на
`null`, а на исходном узле, и такой цикл не типовой. Кольцо поэтому остаётся открытым: нужен закон-счётчик
(`count` звеньев) или признание прохода до исходного узла типовым циклом.

## Граф только с исходящими рёбрами

```
══▶  якорь              to┆X  имя: ребро ведёт в узел X

 Graph.first
     ║
     ▼
  ┌─────┐ nextInGraph ┌─────┐ nextInGraph ┌─────┐
  │  A  │════════════▶│  B  │════════════▶│  C  │════▶ null
  └─────┘             └─────┘             └─────┘
     ║ out               ║ out               ║ out
     ▼                   ▼                   ▼
  ┌─────┐ nextOut ┌─────┐┌─────┐          ┌─────┐ nextOut ┌─────┐
  │ e1  │════════▶│ e2  ││ e3  │          │ e4  │════════▶│ e5  │
  └─────┘         └─────┘└─────┘          └─────┘         └─────┘
   to┆B            to┆C   to┆C             to┆A            to┆C   ← петля
```

```efen
layout {
    set area Vertices: Vertex
    set area Edges: Edge

    struct Vertex {
        var nextInGraph: anchor Vertices.Item? = null
        var out: anchor Edges.Item? = null
    }

    struct Edge {
        var to: Vertices.Item
        var nextOut: anchor Edges.Item? = null
    }

    struct Graph {
        var first: anchor Vertices.Item? = null
        invariants { forall e in Edges: Vertices.contains(e.to) }
    }
}
```

**Закон.** Владение — дерево глубины два: реестр узлов и цепочка рёбер каждого узла. Циклы графа идут только по
именам `to`. Закон замкнутости: каждое ребро ведёт в живой узел. Где лежат имена на узел, закон не говорит.

**Шаги.** Добавить узел и добавить ребро — `take` в голову цепочки; закон верен, потому что `to` пришёл из `Vertices`.
Удалить ребро — рёбер стало меньше.

**Крайнее состояние: удаление узла.**

```efen
fn removeVertex(g: mut Graph, v: Vertices.Item) {
    var u = g.first
    while let w = u {
        removeEdgesTo(from: w, target: v)   // все рёбра w с to == v
        u = w.nextInGraph
    }
    destroyOwnEdges(v: v)
    destroy(unlinkVertex(g: g, v: v))
}
```

Закон не сужает поиск, поэтому доказательство целиком в коде. Оно верно, только если все рёбра множества `Edges`
принадлежат этому графу: закон `Vertices.contains(e.to)` допускает ребро другого `Graph` того же `layout` или ребро в
локальной переменной вызывающего, которое ведёт в `v`, и проход по реестру `g` его не увидит. Поэтому закон привязывает
рёбра к графу («каждое ребро лежит в `out` узла этого графа, и его `to` — узел этого графа»), или проход идёт по всему
множеству, как в [последнем разделе](#произвольный-граф-владелец--функция). Инвариант прохода «в пройденной части реестра рёбер в
`v` нет» FLOW выводит как для типового цикла. Проход кончается на `null`, значит, пройден весь реестр, и на `destroy`
верно `forall e in Edges: e.to != v`. Без прохода или с проходом, который останавливается раньше `null`, — ошибка.
Цена — обход всех рёбер графа на каждом удалении узла.

## Граф со входящими рёбрами

```efen
layout {
    set area Vertices: Vertex
    set area Edges: Edge

    struct Vertex {
        var nextInGraph: anchor Vertices.Item? = null
        var out: anchor Edges.Item? = null
        var inbound: Edges.Item? = null
    }

    struct Edge {
        var from: Vertices.Item
        var to: Vertices.Item
        var nextOut: anchor Edges.Item? = null
        var nextIn: Edges.Item? = null
    }

    struct Graph {
        var first: anchor Vertices.Item? = null
        invariants {
            forall e in Edges:
                Edges.chain(from: e.from.out, by: Edge.nextOut, until: null).contains(e) &&
                Edges.chain(from: e.to.inbound, by: Edge.nextIn, until: null).contains(e)
        }
    }
}
```

**Закон.** Каждое ребро лежит в двух цепочках: исходящих своего источника и входящих своей цели. Этого мало:
`nextIn` — имя, и две цепочки входящих могут сойтись в общий хвост или замкнуться (`e1.nextIn = e1`), не нарушая
закона. Тогда удаление ребра из чужой цепочки оставит висячее имя в цепочке `v`. Поэтому к закону добавляются
однородность цепочки и её конечность:

```efen
struct Vertex { invariants { inbound == null || inbound!.to == self } }
struct Edge   { invariants { nextIn == null || nextIn!.to == to } }
```

Конечность здесь — свойство самой записи `chain(… until: null)`: цепочка обязана дойти до `null`. С этими законами
имена на узел `v` лежат только в рёбрах двух его цепочек.

**Шаги.** Добавление ребра вставляет его в голову двух цепочек; окрестность — `from`, `to` и само ребро. Удаление ребра
вынимает его из двух цепочек, а в односвязной цепочке для этого нужен проход до предыдущего звена, так что окрестность
удаления — вся цепочка. Закон проверяется для произвольного ребра в три случая: ребро события, другое ребро той же
цепочки и ребро чужой цепочки, которой событие не коснулось.

База закона над всем множеством `Edges` неверна для только что рождённого ребра: пока оно в локальной переменной,
его нет ни в одной цепочке. Поэтому закон относится к рёбрам, достижимым из графа, а не ко всему множеству, или
рождённое ребро вставляется до первой точки, где закон проверяется.

**Крайнее состояние: удаление узла.**

```efen
fn removeVertex(g: mut Graph, v: Vertices.Item) {
    while let e = v.inbound { removeEdge(e: e) }
    while let e = v.out { removeEdge(e: e) }
    destroy(unlinkVertex(g: g, v: v))
}
```

Закон сузил поиск до двух цепочек самого `v`. Когда обе пусты, рёбер с именем на `v` нет. Доказательство смешанное:
цену платит каждая вставка и каждое удаление ребра, которые поддерживают закон.

Нужно FLOW: `forall` по множеству и цепочка с головой, зависящей от ребра (`e.from.out`), — [открытый вопрос
5](layout.md#открытые-вопросы).

## Произвольный граф: владелец — функция

Граф с любыми циклами и петлями доказывается без якорных рёбер. Память узлов держит множество `Vertices`; все рёбра —
имена; конец жизни узла задаёт функция, которая его освобождает. Точка её вызова — конец жизни узла, а её тело —
доказательство того, что висячих ссылок не осталось.

```efen
layout {
    set area Vertices: Vertex
    set area Edges: Edge

    struct Vertex {
        var label: Int
    }

    struct Edge {
        var from: Vertices.Item
        var to: Vertices.Item                   // to == from — петля
    }
}

fn removeVertex(g: mut Graph, v: Vertices.Item) {
    for e in g.edges {                          // курсор по всем рёбрам множества
        if e.from == v || e.to == v { e.free() }   // освобождает текущее и сдвигается
    }
    g.vertices.free(v)                          // конец жизни v
}
```

Множества здесь принадлежат экземпляру `Graph` (`g.vertices`, `g.edges`), и функция получает его как `mut`: без `mut`
параметр только читает. Записи `free` и перебор — наброски: освобождение здесь — переход места из множества в его
свободную память ([выделение и освобождение](layout.md#выделение-и-освобождение--переход-между-множествами)).

**Проверка по свойствам.**

| Свойство | Почему выполняется |
|---|---|
| нет обращения к мёртвому узлу | проход убрал все рёбра с именем на `v`; у вызывающего имена на `v` умирают в точке вызова |
| нет двойного освобождения | после `free(v)` имя `v` мертво, второй вызов — ошибка |
| узлы не пересекаются | места раздаёт множество |
| нет потерянной памяти | узел, на который нет рёбер, остаётся в множестве: его видно перебором, и он умирает вместе с множеством |

Ненужный узел, который программа забыла удалить, — ошибка логики программы, а не памяти: адрес не потерян, и
обращение к нему безопасно.

**Условия.** Каждое нарушение — ошибка FLOW в названном месте.

1. **Все держатели имён известны.** Имя на `Vertices.Item` или `Edges.Item` лежит в полях этого типа внутри `layout`
   (`Edge.from`, `Edge.to`, `Cursor.current`), в переменных функций, в коллекциях (`Vector<Vertices.Item>`), в
   захватах замыканий и в состоянии сопрограмм. Полей конечное число. Хранимые держатели (`Cursor` в множестве) функция
   освобождения обходит сама; держатели в переменных вызывающего проверяются у вызывающего по условию 2. Учтён
   только `Edge.to`, а в `layout` есть множество `Cursor`, — ошибка «поле `Cursor.current` может указывать на `v`».
   Требование относится и к рёбрам: `removeVertex` освобождает их тоже.
2. **Сводка называет освобождённые элементы, и у вызывающего умирают имена, которые могут на них указывать.** Сводка
   `removeVertex` — «освобождает `v` и рёбра множества `g.edges` с `from == v || to == v`». Имя `b` после
   `removeVertex(v: a)` живо, только если доказано `b != a`; имя ребра `e0` — только если доказано `e0.from != a` и
   `e0.to != a`. Проверка при выполнении (`if b != a`) даёт этот факт. Коллекция имён, которая может содержать `a`,
   после вызова мертва целиком; поэтому удаление пачкой — отдельная функция (`removeVertices(g, doomed)`), которая
   получает коллекцию и освобождает всё за один вызов.
3. **Пока жив перебор множества, вызов, который освобождает элементы этого множества, — ошибка,** кроме освобождения
   через курсор этого перебора. Это правило «пока результат жив» из `layout.md`: цикл
   `for e in g.edges { if e.to.label < 0 { removeVertex(g: g, v: e.to) } }` отвергается, потому что `removeVertex`
   освобождает рёбра, по которым идёт внешний перебор.
4. **Освобождённое место не путается с новым.** Элементы `set area` не переносятся, поэтому адрес не устаревает при
   росте. Если имя — индекс, место после освобождения может занять новый элемент, и устаревший индекс молча попадёт в
   него; индекс безопасен только вместе с условием 2.

Нужно FLOW: перебор и `forall` по множеству, вывод инварианта прохода «в пройденной части рёбер с именем на `v` нет»,
перечень держателей имён из объявлений, сводки с освобождёнными элементами по условию. Перебор `set area` требует
учёта живых элементов при множестве; сегодня его нет, и его цена в памяти не оценена.

**Почему не годится владение по рёбрам.** Если бы узлы держались якорями-рёбрами, у каждого узла было бы не больше
одного входящего якоря. Цикл якорей тогда не может иметь внешнего якоря: он дал бы одному из узлов второй. Значит,
цикл якорей ничей с момента, когда замкнулся, и утечка случается на замыкающей записи. Имена в этой модели ничего не
держат: их запись утечки не даёт. Вопрос в другом: доказать, что запись `t.f = take r` не замыкает цикл, значит
доказать, что `t` не лежит в дереве `r`, а для произвольного графа владения это достижимость по пути любой длины.
Локально FLOW доказывает её только в трёх случаях из [правил](#правила-доказательства), остальное — ошибка.

Достижимость не выражается законом первого порядка, но у неё есть разрешимые кодировки для решателя: отношение
«между» в эффективно пропозициональной логике (Itzhaky и соавторы, CAV 2013 и POPL 2014), достижимость при изменении
указателей (Lahiri и Qadeer, POPL 2008). Это уже не проверка по окрестности события, а отдельный механизм, и FLOW его
не применяет. Шорр — Уэйт доказан в Isabelle и в Dafny с Z3 (Leino, 2010) с инвариантами, написанными руками.
Ссылки приведены по памяти и здесь не перепроверялись.

## Итог

| Структура | Где доказательство | Окрестность события | Что нужно FLOW |
|---|---|---|---|
| односвязный список | в структуре | голова и узел | есть |
| двусвязный список | смешанное, одно имя | три узла | закон `next!.prev` на событии |
| дерево с родителем | смешанное, одно имя | три узла | условие результата поворота, рекурсия по якорям |
| пара | смешанное, одно имя | два узла | вывод предусловия |
| кольцо | открыто | цепочка любой длины | закон-счётчик или проход до исходного узла |
| граф с исходящими | в коде | весь реестр, типовой проход | привязка рёбер к графу, инвариант прохода |
| граф со входящими | смешанное | две цепочки узла | однородность цепочек, цепочка с параметром |
| произвольный граф, владелец — функция | в коде | все рёбра, курсор | перебор по множеству, держатели имён, сводки освобождения |
| граф с владением по рёбрам | только три случая записи якоря | путь любой длины | — |
