# Layout и описание памяти

[Память](README.md) · [Сырая память](pointer.md) · [Таблица правил](memory-rules.md) ·
[Модели поведения](../models.md) · [Условия и доказательства](../conditions.md)

`layout` — объявленная схема памяти структуры данных: из каких множеств она состоит, кто чем владеет, кто на что
может ссылаться и что отдаётся наружу. Это один из двух способов сказать, что поля смотрят в одну память; второй —
право с источником, `право<поле или параметр>` ([поля не делят память](../types/ownership.md#поля-не-делят-память)).
Всё, чего схема не объявила, запрещено: элементы разных структур друг на друга не ссылаются, и наружу уходит только
то, что названо. По схеме компилятор сам доказывает, что каждый указатель живёт не дольше своей цели и каждый выданный
кусок памяти возвращается; на слово принимается только помеченное точкой доверия.

Статус: разделы описывают модель целиком. Что из неё сегодня реализовано в Amber, перечислено в разделе
[Состояние в компиляторе](#состояние-в-компиляторе); остальное — нормативный текст, который компилятор ещё не проверяет.

## Вопросы, на которые отвечает layout

Описание памяти отвечает на восемь вопросов. Каждый ответ даёт FLOW отношение «это живёт не дольше того»:

1. **Какие множества есть.** Каждый элемент живёт не дольше своего множества.
2. **Как устроено множество.** Непрерывная область слотов по индексу или независимые экземпляры. От этого зависит, что
   кончает жизнь указателей внутри.
3. **Какое множество лежит внутри какого.** Элемент живёт не дольше элемента, внутри которого лежит.
4. **Как указатель одного множества относится к другому.** Указатель может пережить цель, но со смерти цели он недействителен: использовать его — ошибка в месте использования.
5. **Кто владеет элементом.** У элемента одно владеющее ребро; по нему FLOW считает, когда элемент умирает.
6. **Что выдано наружу.** Пока элемент выдан, у его родителя нет владельца.
7. **Что кончает жизнь.** Возврат элемента, смена вида, возврат памяти, изменение структуры области.
8. **Где доверие.** Место, где отношение принимается на слово, а не выводится.

Законы над числами (`used == slots.taken.count`), порядок и физическая форма времени жизни не задают. Они нужны Z3 и
генератору кода и описаны в разделах [виды](#виды-и-приведение-as) и [законы](#законы-и-цепочки).

## Пространство `layout`

`layout { }` — логическое пространство памяти: множества, формы их элементов, законы и функции, которые меняют
структуру. Блок говорит компилятору, как указатели одного множества связаны с указателями другого, и по нему
компилятор доказывает операции с памятью. Экземпляров у `layout` нет. Слово `Self` в нём ничего не обозначает:
`struct Self` в нём и параметр `self: mut Self` — ошибка.

**Множество одно на программу.** `set Items: Item` — все элементы этой формы во всей программе. Структур, которые
ими пользуются (`List`), сколько угодно. Указатель `Items.Item` знает своё множество; какому списку узел
принадлежит сейчас, видно из владения: под чьим якорем он лежит. Поэтому узел, вынутый из одного списка,
вставляется в другой обычным `tie`.

**Кто пишет поля.** У `layout` обычный модификатор видимости языка ([видимость](../visibility.md)), и он
говорит, какому коду разрешено писать поля его структур:

| Запись | Кто пишет поля элементов |
|---|---|
| `private layout { … }` | функции этого модуля |
| `layout { … }` (по умолчанию `internal`) | функции пакета |
| код другого пакета | никто: он читает поля и вызывает функции |

Функции, которым модификатор разрешает писать поля, дальше называются кодом блока: модуль у `private layout`,
пакет у `layout`. Остальной код — внешний: другой пакет, а у `private layout` ещё и другие модули пакета. Что
внешний код получает во владение, блок объявляет строками [схемы владения](#схема-владения).

Блок содержит только описание памяти: множества, структуры, законы и строки схемы владения. Функции стоят в модуле рядом с ним. FLOW
проверяет каждую функцию, которая пишет поля, поэтому доказательству безразлично, где она стоит; модификатор
задаёт, насколько широк круг кода, который автор держит согласованным с законами.

- Функция без `private`, которая пишет поля `layout`, — публичная функция структуры: законы структуры верны на её входе и выходе.
- Функция `private` — помощник: она работает со структурой, закон которой открыт, по своему выведенному контракту.
  Слово права проверяется у публичной функции: сводка помощника («узел ушёл из `list` в результат») передаётся наверх, и слово
  публичной функции выводится из сводок всех помощников, которых она вызывает.

**Закон стоит на каждом владеющем поле.** Чтобы удаление доказывалось локально, каждое поле `own` или `anchor`
множества несёт закон об обратном указателе своей цели: `next!.prev == self` у `Item.next`, `head!.prev == null`
у `List.head`. Тогда `prev` узла задан тем, кто узлом владеет, и запись в `prev`, для которой функция не знает
владельца узла, — ошибка.

Функция получает то, с чем работает, параметрами. Методы структуры записываются
[стратегией](../strategies.md):

```efen
layout {
    set Items: Item

    struct Item {
        var next: anchor Items.Item? = null
        var prev: Items.Item? = null
        invariants { next == null || next!.prev == self }
    }

    struct List {
        var head: anchor Items.Item? = null
        invariants { head == null || head!.prev == null }
    }
}

private fn setPrev(a: Items.Item, b: edit Items.Item) {
    b.prev = a                           // запись невладеющего указателя: хватает edit на b
}

strategy for List {
    public mut fn removeFirst { … }      // метод списка
}
```

**Тип коллекции — структура `layout`.** Блок стоит на уровне модуля, со своим модификатором видимости. Тип,
которым пользуется программа (`Vector`, `List`, `Map`), — именованная структура этого блока; обёртки и `Self`
нет. Своих методов у структуры нет: функции извне, которые вызываются как методы, даёт стратегия того же модуля: `mut fn m` в стратегии для структуры `S` — то же, что
`fn m(self: mut S)`, и метод, который пишет поля, — публичная функция структуры. Модификаторы структуры и её полей говорят, кто их
называет и читает; модификатор блока — кто пишет. Класс пользуется памятью `layout` через поля, тип которых —
структура `layout`; сам класс структурой `layout` не бывает. Строка `part Contract.имя = поля` стоит в теле
структуры `layout`, строка `conforms` — в стратегии.

**Параметры блока.** Обобщённый блок объявляет параметры у самого `layout`: `layout<T> { area Items: T … }`.
Параметры — типы и значения времени компиляции; для каждого набора аргументов множества свои (`Items` при
`T == Int` и при `T == String` — разные множества), а экземпляров у блока по-прежнему нет. Снаружи блока имена
пишутся с аргументами: `Vector<Int>`, `Items<Int>.Item`. Ограничение пишется у параметра, как у обобщённой
структуры: `layout<T: Movable> { … }`; оно действует на все объявления блока и на стратегии его структур, и
повторять его у стратегии не нужно. Стратегия может добавить своё ограничение сверх него:
`strategy<T: Copyable> for Vector<T>` даёт функции только для копируемых `T`.

```efen
private layout<T: Movable> {
    area Items: T

    public struct Vector {
        private var items: own Items.Area? = null { value == null || value.count == capacity }
        private var capacity: Int = 0 { value >= 0 }
        public  var count: Int = 0 { value >= 0 && value <= capacity }
    }
}

strategy<T> for Vector<T> {
    public mut fn removeLast -> own T? {
        guard count > 0 else { return null }
        count -= 1
        return take items![count]        // элемент вне 0 ..< count: пуст
    }
}
```

**Уничтожение структуры `layout`.** У структуры нет деструктора и инициализатора: этим она отличается от класса.
Память структуры освобождает явный код: публичная функция структуры (`v.release()`), сводка которой оставляет все владеющие поля
`null`. Публичная функция с получателем `own` (`own fn release`) забирает структуру целиком и освобождают в том числе поля `let`.
Выход из области со структурой, у которой владеющее поле может быть не `null`, — ошибка компиляции; выход через
исключение — тоже выход. Правило закрывает `defer v.release()`: это явный код на каждом пути. Структура, которая
прямо или через поля держит владеющее поле `layout`, не `ImplicitlyDestroyable` ([деструкторы](../disposable.md)).
Класс, который держит такую структуру полем, освобождает её в своём деструкторе; класс без деструктора с таким полем
— ошибка. `shared struct` с таким полем освобождает его явной функцией под своей блокировкой.

Публичные функции, которые уничтожают элементы типа `T`, требуют `T conforms ImplicitlyDestroyable`
([деструкторы](../disposable.md)); для остальных `T` структура отдаёт элементы вызывающему, и он уничтожает их сам.
Запись в владеющее поле `layout` требует, чтобы поле было доказанно `null`: перезаписать непустое — ошибка.

**Права.** Внутри `layout` действуют права языка ([владение](../types/ownership.md)): `own` — владение,
единственное в своём множестве; `anchor` — владение, при котором на элемент смотрят хранимые указатели; `edit` и
`mut` — заимствования с правом записи; указатель без слова только читает. Что из них нужно операции, говорит
раздел [«`edit` и `mut` в `layout`»](#edit-и-mut-в-layout). Право на элемент действует и на элементы, до которых от
него можно дойти по указателям `layout`. Досягаемость даёт право писать, но в проверку непересечения не входит: два
пишущих параметра одного множества по общему правилу `apart` сравниваются как два названных элемента. Функция,
которой нужен случай «оба параметра — один элемент», разбирает его отдельной веткой.

**Тело не делает больше, чем разрешает слово.** Запись или освобождение через параметр `S.Item` без слова — ошибка
в строке записи. Что функция делает с одиночным `one X`, параметром не записывается: это её эффект. С телом он
выводится и попадает в прототип, без тела пишется как право на контекст, `in edit Registry` или `in mut Registry`
([контекст и эффекты](../context-and-effects.md)). Вызывающий проверяется по сводке: вызов, который через `one`
меняет структуру памяти, куда смотрят его ссылки и заимствования, для них — изменение структуры.

**Откуда право на элемент.** Указатель берёт право значения, через которое он получен: прочитанный через
параметр `mut` передаётся в параметр `mut S.Item`, через `edit` — в `edit S.Item`. Результат функции несёт право,
которое в нём записано (`-> mut Items.Item?`). Право на изменение структуры — уход элемента из структуры, освобождение — даёт
право на саму структуру, которую называет источник указателя: функция должна держать её параметром с этим правом.
Указатель, полученный с `edit`, не даёт `mut`, даже если структура у функции есть. У множества без поля-владельца значения с правом нет: источник
указателя — само множество, и передать его в параметр `mut S.Item` может любой код, которому видна функция.

### `edit` и `mut` в `layout`

`edit` гарантирует, что ни один существующий элемент или слот не перенесён и не уничтожен; `mut` этой гарантии не
даёт ([права](memory-rules.md#права)). Право читается по итогу функции, а не по тексту. Функция с параметром `edit`
к каждому своему выходу оставляет каждый элемент, который до неё был в структуре этого параметра, в той же
структуре, на том же адресе и в том же виде ([структура](#структура-источник-чистота)). Выход через
исключение — тоже выход. Между `tie` из структуры и `tie` обратно функция `edit` не вызывает ничего, что может
бросить исключение или приостановиться (`yield`, точка ожидания).

| Операция | Право на элемент или владельца | Что со ссылками и указателями |
|---|---|---|
| чтение поля | без слова | живут |
| запись поля-значения, которое ничем не владеет (`length`, `key`, `state`) | `edit` | живут |
| запись невладеющего указателя `S.Item?` (`prev`, `parent`, `older`, `tail`) | `edit` | живут: ни один элемент не перенесён |
| запись в неинициализированный элемент области вместе с полями счёта, которые называет закон (`count`) | `edit` | живут: слот создан |
| `lend` вместе с полями счёта (`used`, `frontier`, `firstFree`) | `mut` на родителя: слот ушёл из его структуры владением | ссылки, срезы и курсоры, которые могут пересекаться с выданным слотом, умирают; остальные живут |
| новый элемент в пустое владеющее поле (`list.head = tie node`, когда `head == null`) | `edit` | живут |
| `tie` якоря, когда к выходу функции элемент снова лежит в той же структуре (вставка в начало списка, поворот дерева, разворот списка) | `edit` | живут: изменилась только точка уничтожения |
| `tie` якоря, после которого элемент ушёл из структуры: в результат, в другую структуру, в уничтожение | `mut` на структуру, из которой он ушёл | умирают указатели и ссылки с источником в этой структуре на него и на всё, что под ним ([изменение структуры](#структура-источник-чистота)) |
| элемент пришёл в структуру владением (`b.pushFirst(a.pop())`) | `edit` на структуру, в которую он пришёл | на остальные элементы живут |
| `take` значения `own` из поля, `take` элемента области | `mut` | ссылки и указатели в прежнее содержимое умирают |
| возврат выданного слота (`block.slots[k] = take slot`) | `mut` на родителя | указатели на слот умирают |
| `as own`, освобождение (`mm.free`) | `mut` на элемент | все указатели и ссылки на элемент умирают |
| смена вида `as` | `mut` | указатели прежнего вида умирают или переведены на новый вид |
| перевыделение области, замена области (`table.buckets = take fresh`) | `mut` на владельца | ссылки и указатели внутрь прежней области умирают |

Переноса как отдельной операции нет: значение переносит код — `take` из старого элемента и запись в новый
([неинициализированный элемент области](#множества-и-области)). Ссылки на старый элемент умирают в строке `take`.

Метка в поле-значении для компилятора — запись значения. Таблица с открытой адресацией, которая снимает запись
строкой `state = DELETED`, делает это с `edit`; слово `mut` у её `remove` даёт контракт коллекции, и реализация
вправе делать меньше, чем слово разрешает.

**Условия функций.** `requires` и `ensures` у функции `layout` писать можно. Условия о памяти, которых программист
не написал (что пусто, что выдано, кто владеет), FLOW выводит из тела и добавляет в прототип.

**Обход множества.** Встроенного перебора всех элементов множества нет. Структура, которой нужно обойти свои
элементы, ведёт их цепочку через поле элемента и закон «каждый элемент лежит на цепочке»
(`forall b in Blocks: b.linked == chain.contains(b)`).

## Множества и области

Память описывают дескрипторы. Дескриптор объявляет форму элемента и то, как элементы лежат; сколько их, говорит
владелец области.

| Дескриптор | Что это |
|---|---|
| `area X: T` | одна непрерывная область слотов одной формы; слоты по индексу `0 ..< count` |
| `set area X: T` | множество независимых непрерывных областей (блоки менеджера памяти, слэбы); каждый байт памяти принадлежит элементу |
| `set X: T` | множество экземпляров без обещания непрерывности; так пишутся списки, деревья и графы |
| `one X` | один экземпляр на всю программу, как `static`; единственность объявлена, и FLOW на неё опирается |

```efen
layout {
    set area Blocks: Block            // блоки по 64 КБ
    area Classes: Class               // 32 класса размеров подряд

    struct Pool {
        var classes: own Classes.Area? { value == null || value.count == CLASSES }
    }
}
```

Число слотов области указывает её владелец (`value.count == CLASSES` или `value.count == capacity` у поля) или
строка `invariants` вида (`slots.count == PAYLOAD / SIZES[sizeClass]`). Слот области — значение:
`table[i].size = 16` пишет поле слота `i`. Индекс доказан в границах или проверяется при выполнении.

**Неинициализированный элемент области.** Какие элементы заняты, говорит закон владельца (`0 ..< count` у вектора). `take`
элемента области ничего не делает с памятью: он объявляет, что значения по этому адресу больше нет, и требует `mut`.
Для этого элемента `take` — изменение структуры: ссылки и указатели на него умирают, использованные после — ошибка, хранимые
указатели `layout` на него переписаны до `take`. К выходу публичной функции неинициализированный элемент лежит вне занятых по закону.
После `take` элемент не инициализирован (это не `null`): запись в него — инициализация, чтение — ошибка. Перенос значения в другую область — `take` из
старого элемента и запись в новый.

**Владение по множествам.** Владение считается отдельно в каждом множестве. Область целиком принадлежит своему
владельцу; слот области может быть якорем элемента другого множества (корзина хеш-таблицы — якорь первой записи своей
цепочки), а элемент множества — якорем элемента своего множества (узел дерева). Это разные владения, и каждое
проверяется в своём множестве. Связывает их граф зависимостей FLOW: пока из множества что-то выдано или его слоты
держат якоря живых элементов, его нельзя уничтожить, а слот нельзя перезаписать целиком.

Элементы `set area` не индексируются; набор раздаётся целиком циклом
[`for element in take region`](pointer.md#раздача-набора-for-element-in-take-region).

Дескрипторы принято писать в начале блока. Порядок объявлений на разрешение имён не влияет: весь блок — одна общая
область имён.

### Частичная инициализация и очистка

Занятые слоты области определяет закон владельца (`0 ..< count` у вектора), а не сама область: указатель `Items.Area`
не хранит ни числа занятых слотов, ни таблицы инициализации. Поэтому конструкция, которая заполняет область по одному
элементу, записывает поля владельца до первой операции, способной бросить исключение (`items`, `capacity`, `count = 0`),
и увеличивает `count` после каждой записи в пустой слот.

Если следующая запись бросила исключение, очистка на исключительном выходе освобождает ровно инициализированный
префикс `0 ..< count`: каждый занятый элемент уничтожается один раз, неинициализированные слоты не трогаются, затем возвращается
память области. Элемент, который код уже перенёс `take`, в префикс не входит. Очистку не обязательно писать руками, но
после lowering она обязана существовать как исключительные рёбра графа потока управления; закон «слоты вне
`0 ..< count` пусты» без этих рёбер не доказательство. Механизм генерации очистки в Amber не реализован.

У блочной структуры каждый блок (`Chunk`) хранит собственную область и собственный `count`. Уничтожение каталога сначала
освобождает префикс каждого живого блока, затем сам каталог; ни один элемент не уничтожается второй раз.

## Вложенность

Множество физически лежит внутри элементов другого множества, если оно — поле структуры этих элементов:

```efen
@align(BLOCK)
struct SlotBlock {
    Header
    @align(LINE) area slots: Slot     // слоты внутри блока
    invariants {
        sizeOf(slots.Item) == SIZES[sizeClass]
        slots.count == PAYLOAD / SIZES[sizeClass]
    }
}

struct Slot {
    var next: Int = NONE
    var key: Int = SLOT_KEY
    area rest: Byte                   // хвост слота внутри слота
}
```

Память блока выдана из множества `Blocks`; область `slots` лежит в байтах блока, хвост `rest` — в байтах слота.
Вложенность задаёт два правила:

1. Элемент живёт не дольше элемента, внутри которого лежит: слот не дольше блока, блок не дольше памяти, из которой он
   взят.
2. Родителя нельзя вернуть, пока выданное из него держат снаружи его памяти. Возврат родителя — то же изменение структуры, что
   возврат элемента, только уходит вся его память: слот, у которого все владельцы и указатели лежат в памяти
   самого родителя, уходит вместе с ним. Первый `lend` превращает `own SlotBlock` в `mut SlotBlock`; `own`
   восстанавливается, когда вернулись все слоты (`used == 0`). Компилятор сегодня не доказывает, что указатель лежит
   в памяти родителя, и требует вернуть все слоты.

Множество как целое живёт, пока жива память его родителя: `slots` — пока блок остаётся `SlotBlock`.

## Ссылки

Указатель внутри `layout` — невладеющий указатель на элемент множества, слот области по индексу или владеющий указатель.

| Запись | Что это |
|---|---|
| `var next: Blocks.Item?` | невладеющий указатель на элемент `Blocks`; цель обязана быть живой |
| `var reserve: own SlotBlock?` | исключительная владеющая ссылка: она уничтожает цель, других ссылок нет |
| `var next: Int` с концом `NONE` | слот своей области по индексу (цепочка свободных слотов) |
| `var key: Keys.Item` | слот области `Keys` того же `layout` |
| `var left: anchor Nodes.Item?` | якорь: элемент уничтожает элемент того же множества, а указатели на него у других допустимы |
| `own block.slots.Item` | слот, выданный из `block.slots`, у получателя |

Поле структуры внутри `layout` называет элемент множества или слот области типом `Множество.Item`; источник
`<layout.Area>` в типе поля не пишется.

Строка в `invariants` вида уточняет поле для этого вида: `next: SlotBlock?` — цель есть `SlotBlock`;
`next: own FreeBlock?` — в виде `FreeBlock` поле владеет, в других видах оно только указатель.

Указатель из одного множества в другое объявлять особо не нужно: это обычный указатель, и FLOW видит каждую его
запись. Куда он может смотреть, ограничивает [чистота](#структура-источник-чистота): только внутрь своей
структуры или в множество без поля-владельца.
Обратные указатели (`prev`, `parent`) разрешены только внутри `layout`. Указатель на обычное поле (`next`, `used`)
не существует: тип указателя есть только у того, что объявлено словом `set` или `area`.

Указатель на элемент из адреса без множества получается только на доверии:
`(address(m) & ~(BLOCK - 1)) as Blocks.Item` — блок, в котором лежит адрес из C.

### Структура, источник, чистота

Эти пять определений — единственное место, где они даны; остальные разделы на них ссылаются.

1. **Структура.** Структура элемента — корень цепочки его владения. Цепочка идёт вверх по `anchor`, `own`, по
   вложенности в область и по полю, которое хранит структуру `layout` значением, пока держатель не окажется вне
   значения `layout`: локальная переменная, параметр, поле обычного типа, `one`. Таблица хеш-таблицы с областью
   корзин — одна структура; два `List` в полях одного объекта — две. У элемента, цепочка которого кончается на
   элементе без владельца, структура — его множество.
2. **Источник.** Источник указателя или ссылки на элемент — структура, из которой он прочитан, как тождество, а не
   путь внутри неё (`list` для `list.first()`). Указатель, прочитанный через любое поле элемента, имеет тот же
   источник. Указатель на элемент множества без поля-владельца всегда имеет источником это множество, через какое
   бы поле он ни прочитан.
3. **Чистота.** Закон чистоты: каждый невладеющий указатель, хранимый в структуре (в элементе или в самом корне, как
   `Queue.tail`), смотрит в ту же структуру или в элемент множества без поля-владельца. Поле элемента такого
   множества смотрит только в множества без поля-владельца. Это закон каждого `layout`: внутри тела он бывает
   нарушен и доказывается на каждом выходе публичной функции, обычном и через исключение, и перед вызовом или приостановкой,
   которым нужны закрытые законы. Элемент под локальным якорем лежит во временной структуре этой переменной;
   ошибка ставится у записи, которая создала указатель за границу. Элемент переходит между структурами только
   владением, и переход тоже доказывает чистоту: в старой структуре не остаётся указателя в уходящее поддерево,
   а в поддереве — указателя за его пределы. Держателей FLOW находит по закону или обходом; поле без закона,
   который его находит, делает переход ошибкой.
4. **Изменение структуры.** Уничтожение элемента X, его уход из структуры, смена вида и перенос
   убивают в любом коде каждый указатель и каждую ссылку с источником в структуре X, которые могут быть равны X или чему-то, чем X
   владеет или что в нём лежит. Уход корня структуры из его слота (`take` в существующий слот, `swap`, `replace`,
   передача `own`, возврат) убивает указатели с этим источником; `take` целой локальной переменной в новую меняет
   источник на новую переменную. Те же указатели и ссылки убивают ещё два изменения: корень ушёл в другой поток
   ([переход между потоками](#переход-между-потоками)) и отпущена блокировка, которая охраняет поле с корнем
   ([структура под блокировкой](#структура-под-блокировкой)).
5. **Чистая структура.** Структура чиста, если ни один хранимый невладеющий указатель в её корне и в
   любом типе элемента, достижимом по владению, не называет множество без поля-владельца. Множество блоков менеджера
   памяти с `used > 0` (исключение раздела [«Время жизни по полю и по функциям»](#время-жизни-по-полю-и-по-функциям))
   считается множеством без владельца. Свойство читается из объявлений с подставленными аргументами: `Vector<Int>`
   чист, `Vector<Vertices.Item>` — нет. Только чистая структура лежит в поле
   `shared` ([пометка `shared`](../shared.md#пометка-shared)); это точный смысл слов «без указателей layout за пределы
   значения».

```efen
let p = a.first()                   // Items.Item, источник — a
freeAll(b)                          // освобождает узлы b; a и b общей памяти не объявляли
print(p.value)                      // допустимо
moveFirst(a, b)                     // mut для a: узел ушёл из a
print(p.value)                      // ошибка: p умер в строке moveFirst
```

Источник указателя-результата у функции с телом выводится. У объявления без тела он пишется:
`-> read<list> Items.Item?`; результат без записанного источника имеет источником множество. Такой указатель
умирает на любом вызове, сводка которого освобождает или переносит элемент множества, и на любом вызове `mut` без
тела над значением того же `layout`. Вызов без тела с параметром `mut S.Item` или с правом `mut` на структуру
убивает указатели с источником в структуре аргумента и указатели в множества без поля-владельца того же `layout`.

Цена определения 1: внутри одной структуры источник не различает её цепочки, поэтому вызов, который освобождает
элементы структуры, убивает в ней каждый указатель, который может быть равен освобождённому.

## Якорь `anchor`

Владение бывает двух видов, и они дают FLOW разные алгоритмы.

| | `own` — исключительное | `anchor` — неисключительное |
|---|---|---|
| смысл | единственная ссылка на значение | крайняя точка времени жизни; на значение смотрят хранимые указатели |
| перенос | `take`: следить не за чем, других ссылок нет; нужен `mut` | `tie`: указатели множества на значение остаются в силе; `edit`, если элемент остался в той же структуре, иначе `mut` ([таблица](#edit-и-mut-в-layout)) |
| уничтожение | безопасно всегда | ни один указатель после него не используется |
| факт для Z3 на входе | «ничего не одолжено» | такого факта нет |
| пример | `var pending: own Job?`, слот, выданный пользователю | узел дерева с `parent`, блок на списке класса mm |

```efen
layout {
    set Nodes: Node

    struct Node {
        var left: anchor Nodes.Item? = null      // точка уничтожения; указатели на узел допустимы
        var right: anchor Nodes.Item? = null
        var parent: Nodes.Item? = null           // невладеющий указатель
    }
}
```

У значения ровно одна точка уничтожения, поэтому якорь у него один: два поля `anchor` на одно значение — ошибка, как и
`anchor` вместе с `own`. `own` — это якорь без указателей: всё, что гарантирует `anchor`, и вдобавок ссылок на значение нет.

Указатель на значение под якорем действителен не дольше якоря: в точке, где якорь уничтожает значение или отдаёт его, все указатели
недействительны, а хранимый указатель к выходу функции указывает на живой элемент. Отдать значение наружу владением можно только после явного перехода
[`as own`](#переход-к-владению-as-own).

**Передача якоря.** Якорь переходит из одного слота в другой через `tie`: получатель привязывает значение к себе, а
старый слот пустеет; в каждый момент у значения якорь один. Внутри одной структуры указатели на значение при
передаче живы: меняется только точка уничтожения. При уходе в другую структуру действует правило
[изменения структуры](#структура-источник-чистота). `take` остаётся для `own`: `take` слота под якорем — ошибка. Значение `own` через `tie` кладётся в поле `anchor` и
становится якорем: на него ещё никто не смотрит. Обратно, к `own`, ведёт только [`as own`](#переход-к-владению-as-own).

```efen
struct Tree {
    var root: anchor Nodes.Item? = null
}

fn rotateRootLeft(tree: edit Tree) {          // edit: все узлы остались в дереве, ни один не перенесён
    guard let top = tie tree.root else { return }
    guard let pivot = tie top.right else { tree.root = tie top; return }
    top.right = tie pivot.left              // якорь левого поддерева pivot перешёл в top.right
    if let l = top.right { l.parent = top }
    top.parent = pivot
    pivot.parent = null
    pivot.left = tie top
    tree.root = tie pivot                   // к выходу каждый узел снова в tree
}
```

`tie` из поля, якоря которого у функции нет, — ошибка: из параметра `top: edit Nodes.Item` нельзя написать
`pivot.left = tie top`, потому что якорь `top` лежит у вызывающего.

**Функция как якорь.** Якорем бывает не только поле, но и функция: параметр, результат или локальная переменная с
`anchor`. Функция с параметром `anchor` отвечает за уничтожение значения: до выхода она его уничтожает или передаёт
якорь дальше, а указатели на значение у других остаются в силе, пока она этого не сделала.

```efen
fn release(pool: mut Pool, node: anchor Nodes.Item) {
    unlink(pool: pool, node: node)          // указатели на node в цепочках пула сняты
    mm.free(node as own Pointer)            // anchor → own, память возвращается в mm
}

fn pop(list: mut List) -> anchor Nodes.Item? {
    guard let first = tie list.head else { return null }
    list.head = tie first.next
    return first                            // якорь переходит к вызывающему
}
```

FLOW по телу функции сам определяет, что она делает с якорем, и помечает её в сводке: **уничтожает** значение,
**отдаёт** его вызывающему (результатом или параметром `out`) или **оставляет** в `layout` (в поле
того же множества); пометка «оставляет» называет параметр, в структуру которого элемент попал. Якорь переходит
только между функциями, которым модификатор блока разрешает писать поля. Внешний код якоря не получает: функция,
видимая внешнему коду, с `anchor S.Item` в сигнатуре — ошибка ([схема владения](#схема-владения)). Пометка бывает «на всех путях» и «на
некоторых»: функция, уничтожающая значение только на одном пути, помечается «может уничтожить», и указатели после её
вызова мертвы. Пометка говорит не только о параметре `anchor`: функция, которая через параметр `mut` уничтожает
элемент, достижимый из него (`pool.head`), помечается так же, с путём от параметра. По этим пометкам время жизни считается по точкам вызова: вызов уничтожающей или отдающей функции — точка,
где умирают указатели вызывающего на значение; после вызова оставляющей функции они живы. Руками пометки не пишут.

## Время жизни по полю и по функциям

Время жизни элементов множества задаётся одним из трёх способов, и способ виден из объявлений `layout`: из полей
и из строки `own S` [схемы владения](#схема-владения).

| Поле `own` или `anchor` с типом `S.Item` | Строка `own S` | Способ | Кто владеет элементом `S` |
|---|---|---|---|
| есть | нет или есть | по полю | поле-владелец или функция кода блока; при строке `own S` ещё и внешний код, который получил элемент как `own S.Item`; потерянный владелец — ошибка |
| нет | есть | множество выдано целиком | только внешний код, через `own S.Item`; `layout` указателей на элемент не хранит |
| нет | нет | по функциям | никто: одна функция вводит память в множество, другая выводит и доказывает, что указателей на элемент не осталось |

У множества, выданного целиком, хранимое поле типа `S.Item` — ошибка: `own` значит, что на элемент никто не
смотрит. Элемент под `own` у внешнего кода — отдельная структура с корнем в его держателе (определение 1 раздела
[«Структура, источник, чистота»](#структура-источник-чистота)). Слова «множество без поля-владельца» в остальных
разделах означают множество «по функциям»: только у него структура элемента и источник указателя — само множество.
Множество «по функциям» наружу владением не уходит: внешний код получает на его элемент указатель или заимствование
с правом, а освобождает элемент функция, которая выводит его из множества. Блок, в котором у такого множества нет
функции вывода, — ошибка: память, которая вошла, не может выйти.

Способ один на множество. Исключение — блоки менеджера памяти: блок, из которого выданы слоты (`used > 0`),
владельца не имеет, и его структура — множество `Blocks`; переход между владением и множеством безопасен, потому что
под `own` указателей нет. Структура, которой нужны оба способа, описывается двумя множествами.

Локальная переменная `anchor` или `own` с элементом `layout` неявно не уничтожается: на каждом выходе, обычном и
через исключение, её значение привязано в структуру, возвращено или освобождено явно. Вызов, который может бросить
исключение, пока такая переменная жива, — ошибка, если на этом пути нет обработчика, который её освобождает. В одной структуре поля на
разные множества сочетаются свободно:

```efen
layout {
    set Vertices: Vertex
    set Edges: Edge

    struct Vertex {
        var neighbors: Vector<Vertices.Item>      // на Vertices никто не владеет: время жизни по функциям
        var firstEdge: anchor Edges.Item? = null  // вершина владеет своими рёбрами: время жизни по полю
    }

    struct Edge {
        var to: Vertices.Item
        var next: anchor Edges.Item? = null
    }
}
```

При освобождении вершины её поля-владельцы пусты: функция сначала освобождает рёбра вершины.

**Утечка в множестве «по функциям».** Указатель на элемент, только что вошедший в множество, на каждом пути
записан в поле `layout` или передан функции, которая выводит элемент из множества; иначе — ошибка в конце
функции. Элемент, на который позже стёрли последний хранимый указатель, компилятор не находит: главная гарантия
`layout` — отсутствие висячих указателей.

**Вход и выход памяти.** Операции «создать элемент» в `layout` нет. Память входит в множество преобразованием
указателя и возвращается тем же путём, каким пришла:

1. из внешнего `layout`: менеджер памяти отдаёт `own Pointer`, приведение `as` делает из него элемент;
2. из другого множества этого же `layout`: большой кусок, взятый у ОС, нарезается выдачей `lend` или раздачей
   `for element in take region` ([выдача и возврат](#выдача-и-возврат)).

```efen
fn newNode -> own Items.Item {
    return mm.allocate(…) as Item           // own Pointer → own Items.Item
}

fn addVertex -> Vertices.Item {
    return mm.allocate(…) as Vertex         // множество «по функциям»: владеть некому
}
```

Приведение сохраняет право указателя: из `own Pointer` получается владеющий указатель на элемент. `own` — якорь
без указателей, поэтому значение `own` кладётся в поле или результат `anchor` без отдельного шага: при `tie` в такое
поле оно становится якорем. Обратно, к `own`, ведёт только `as own`. Функция, которая держит элемент `own` или
`anchor`, может забрать `take` его поля перед освобождением (`let value = take node.value`); после этого элемент
только освобождается. Когда памяти нет, `mm.allocate` бросает `AllocationError`, и ничего не меняется
([аллокатор](allocator.md)). В множестве
«по функциям» возврат такого значения через результат `-> Vertices.Item` передаёт элемент множеству. В множестве
с полем-владельцем и в множестве, выданном целиком, та же строка — ошибка «владелец потерян». Имена `mm.allocate` и `mm.free` в примерах обозначают
функции внешнего менеджера памяти ([аллокатор](allocator.md)).

## Переход к владению `as own`

Освободить память, на которую смотрят несколько указателей, можно только после перехода к `own`. Переход пишется
приведением с правом: `v as own Pointer`. К этой точке код уже нашёл все указатели на элемент и обнулил или
уничтожил их; компилятор проверяет это по законам и объявлениям `layout` и выдаёт право `own`. Без доказательства
приведение — ошибка.

```efen
fn removeVertex(v: mut Vertices.Item) {
    // … код убирает v из neighbors каждой вершины, которая на него ссылается
    mm.free(v as own Pointer)               // доказано: указателей на v нет; память возвращается в mm
}
```

`as own` применяется к указателю `mut` в множестве «по функциям» и к значению под `anchor`, которое функция
вынула из поля. В множестве со строкой `own S` указатель `mut` владения не даёт: элемент, которым владеет внешний
код, освобождает только функция, принявшая его как `own S.Item`. Приведения элемента — `as own`, стирание
`as Pointer`, смена вида — пишет только код блока; во внешнем коде они — ошибка
([схема владения](#схема-владения)). Промежуточная переменная не нужна. `tie` и `take` невладеющего указателя владения не дают.

## Время жизни

### Общий принцип

Указатель допустим в любом месте программы, если компилятор доказывает две вещи: **источник** — из какого
множества, области или памяти пришёл указатель, и **отношение** — указатель действителен не дольше того, на что
указывает.
Все правила этого документа — частные случаи: закон связывает указатель с якорем, структура с параметром источника держит
заимствование и вложенность привязывают держателя к элементу, курсор `layout` объявляет
множество своего указателя. Если принцип доказан,
комбинация форм значения не имеет; если не доказан — ошибка в месте, где доказательство обрывается.

**Алгоритм.** FLOW строит граф указателей и для каждой точки программы проверяет его рёбра.

| Вершина | Что это |
|---|---|
| значение | элемент множества, слот области, область, память ОС |
| держатель | поле, переменная, параметр, результат, захват замыкания |

| Ребро | Откуда известно |
|---|---|
| владеет (`own`, `anchor`) | тип поля или параметра; в каждый момент одно на значение |
| лежит внутри | вложенность `layout`: поле-область, вид элемента, выдача из родителя |
| указывает (указатель) | запись указателя; источник — по коду: из какого множества пришло значение |
| держит заимствование | структура с параметром источника, ссылка внутри функции |

Шаги:

1. **Источник.** У каждого указателя FLOW ведёт, из какого множества или источника он пришёл: из поля
   с объявленным типом `S.Item`, из выдачи, из результата функции по её сводке. Указатель без доказанного
   источника — ошибка, кроме точек доверия.
2. **События.** Рождение, передача якоря и смерть каждого значения — по телу и по пометкам сводок вызванных функций.
3. **Проверка ребра «указывает».** В каждой точке, где значение умирает, каждый держатель его указателя мёртв, переписан или
   не используется дальше. Где лежат держатели, FLOW знает из закона, из объявленного множества указателя или из заёма;
   держатель, которого он найти не может, — ошибка в месте, где указатель положили.
4. **Проверка ребра «держит заимствование».** В точке, где источник меняет структуру или умирает, заимствование мертво
   или не используется дальше; держатель, который используется дальше, — ошибка, основная метка у события.
5. **Проверка ребра «лежит внутри».** Родитель не умирает, пока внутри что-то живо.
6. **Сводка.** Что функция делает с источником и временем жизни своих параметров и результата, FLOW записывает в её
   прототип; вызывающий проверяется по прототипу.

**Направления, по которым принцип проверен.**

| Направление | Как доказывается | Состояние |
|---|---|---|
| локальная переменная | ссылка внутри функции; события тела | есть в FLOW |
| параметр и результат | сводка: источник и пометки уничтожения | частично |
| поле внутри `layout` | закон или объявленное множество указателя | модель |
| поле вне `layout` | структура с параметром источника `Src: Origin` | есть в FLOW (S109) |
| захват замыкания | заимствование замыкания (S102) | есть в FLOW |
| вложенные множества | ребро «лежит внутри», `lend`/`take` | есть в FLOW |
| память ОС и функции C | точка доверия: условие результата, код `model` | частично |
| цикл, произвольный граф | указатели под законом; владелец — функция освобождения | модель |
| потоки | структура — одна область; события «корень в другой поток» и «блокировка отпущена» | модель |

**Отсутствие висячих указателей.** Событие, которое уничтожает, физически переносит значение в другую память или меняет
его вид, требует ответа на вопрос «выполнена ли гарантия: все ли указатели на значение приведены в актуальное
состояние». Передача якоря через `tie` к таким событиям не относится: указатели при ней верны. Закон структуры говорит,
где указатели могут лежать, и его доказывает код, меняющий структуру, на каждом своём событии; внутри тела закон бывает
нарушен, поэтому держателей FLOW считает по состоянию на входе в функцию и записям тела до события. Код события
показывает, что каждый указатель недействителен или переписан; при переносе и смене вида указатель может остаться верным, если
переведён на новое место или вид. Доказательство бывает целиком в структуре (`own`: указателей нет), целиком в
коде (проход по всем держателям) или смешанным (закон сужает поиск, код проходит узкое место). Чем точнее закон, тем
больше работы в коде, который строит структуру, и тем меньше в коде события.

### Выделение и освобождение — переход между множествами

Выделения и освобождения памяти как особых операций нет: память переходит из одного множества в другое, и только
направление перехода делает его выделением или освобождением.

- **Каждый `layout` — своя область памяти.** Менеджер памяти живёт внутри своего `layout`, пользовательская структура —
  внутри своего. Функцию чужого `layout` FLOW видит как работу с другой областью памяти.
- **Память ОС — тоже множество.** Страницы принадлежат множеству ОС; взять страницы — выдача из него, вернуть —
  возврат в него. На слово принимается только то, что ОС выдаёт страницы нужного размера и выравнивания: условие
  результата у вставки `@asm` ([системные вызовы](system.md)).
- **`own` переносит память между множествами.** `take` из множества `A` в множество `B` — для `B` выделение, для `A`
  освобождение. Блок, взятый менеджером у ОС, для ОС ушёл, для менеджера пришёл; слот, отданный пользователю, для
  блока выдан, для пользователя получен.
- **Правила одни на всех уровнях.** ОС → регион → блок → слот: каждое множество живёт внутри предыдущего, родителя
  нельзя вернуть, пока внутри что-то выдано, и FLOW видит, что каждая страница, взятая у ОС, вернулась или осталась у
  владельца.

```efen
fn newRegion -> own Region? {
    guard let memory = System.map(bytes: REGION, aligned: BLOCK) else { return null }   // из множества ОС
    return memory as Region                                                              // в множество регионов
}

fn dropRegion(region: own Region) {
    System.unmap(memory: take region as Pointer, bytes: REGION)                          // из регионов — в ОС
}
```

Стирание вида `block as Pointer` даёт `own Pointer` той же памяти, а не новой: вид умер, память жива и уходит дальше.
Множество ОС в `layout` не объявляется: его описывают сигнатуры контракта `System`
([системные вызовы](system.md#контракт-system)). `map` отдаёт `own Pointer.Zeroed?` с размером и выравниванием
в условии результата; `unmap` принимает `own Pointer` и требует `memory.size == bytes`. FLOW ведёт `own Pointer`
линейно: каждая страница, взятая у ОС, на каждом пути возвращается в `unmap` или остаётся у владельца, и размер
возврата он берёт из условия результата `map`, а не из памяти. Условие результата `map` — единственная точка
доверия на этой границе.

### Как FLOW вычисляет время жизни

Время жизни не объявляется, а выводится из кода по точкам уничтожения:

1. Поле, параметр или переменная с `own` или `anchor` — владелец значения.
2. FLOW находит, где владелец уничтожает значение: в теле функции или через вызов функции, которая, как видно по её
   сводке, значение уничтожает или отдаёт наружу.
3. Эта точка — конец времени жизни значения и всех указателей, привязанных к нему: указателей, ссылок внутри функции,
   элементов множеств, лежащих внутри него.
4. Так FLOW собирает жизненный цикл каждой структуры данных и каждого указателя — от рождения через вызовы функций до
   точки уничтожения — и проверяет, что цикл не нарушает правил: ни один указатель не используется после своей точки,
   ни одно значение не уничтожается дважды и не остаётся без владельца.

Время жизни привязывает к вызову функции не функция и не программист, а FLOW: он видит, что функция уничтожает
память, и связывает с её вызовом конец жизни всего, что от этой памяти зависит. В отличие от Rust, где время жизни
ссылок пишется в сигнатурах (`'a`) и проверяется по ним, здесь оно выводится из кода целиком, и аннотаций нет.

Время жизни элемента выводится из вложенности и событий выдачи и возврата; создание (`new`) и освобождение (`free`) —
это вход памяти в множество и выход из него ([время жизни по полю и по функциям](#время-жизни-по-полю-и-по-функциям)). Для множества, лежащего внутри другого, FLOW знает четыре события:

1. Память родителя создана: приведение `Pointer` к виду, `System.map`.
2. Число слотов известно формально: строка числа у держателя или у вида.
3. Элемент выдан: `lend block.slots[k]`, раздача `for element in take region`.
4. Элемент вернулся через `own`: `block.slots[k] = take slot`.

Элемент рождается при выдаче и умирает при возврате в свой слот. При возврате умирает каждый указатель на него, в том числе
указатель, хранимый в поле другой структуры; использовать его после возврата — ошибка в месте использования.

У множества верхнего уровня (`Blocks`) родителя нет: элемент рождается при приведении памяти к виду и умирает при
стирании `as Pointer` или возврате памяти системе.

**Передача внутри `layout` — не возврат.** Элемент, перешедший владением в другую структуру, жив: его указатели
множества внутри новой структуры законны. Указатели и ссылки с источником в прежней структуре умирают, в любом коде
([источник указателя](#источник-указателя)). Исключение одно: в функции, которая сама передала элемент, её
локальный указатель получает источником новую структуру, если она известна в этой функции: `tie` в её теле или
вызов, пометка «оставляет» которого называет принимающий параметр. После вызова без тела или с пометкой «может»
указатель мёртв. Получатель не знает, что на элемент никто не смотрит:
другие указатели множества могут его видеть.

```efen
fn move(pool: mut Pool, block: anchor Blocks.Item) {
    let name = block
    keep(pool, tie block)                  // block перешёл в pool; источник name теперь pool
    print(name.kind)                       // допустимо
}
```

**Изменение структуры области.** Перевыделение кончает указатели внутрь области. Указатель, который после него не
используется, ему не мешает; использованный после — ошибка: основная метка стоит у перевыделения, вторая — у
использования (модель §13.5):

```efen
fn shrink(table: mut Table, n: mut Nodes.Item) {
    let k = n.key
    table.keys = take smallerKeys()        // ошибка: k используется ниже и указывает в старую область
    print(k)
}
```

**Карта жизни элемента.** По телам функций FLOW строит путь каждого вида элемента: рождение, повторная выдача, смена
вида (`SlotBlock` → `FreeBlock` → `SlotBlock`), возврат памяти. Из карты выводится время жизни через вызовы:

```
slot жив  от  результата acquireSlot(block)
          до  входа в releaseSlot(block: block, slot: slot)
```

**Полнота карты.** FLOW доказывает:

1. каждый выданный элемент на каждом пути возвращается или передаёт владельца дальше; иначе — утечка в конце пути.
   Память берётся явно и возвращается явно: возврат при выходе процесса не считается, у глобального `layout` есть
   явная функция завершения.
   Элемент под множеством — его не держит ни `own`, ни `anchor` — возвращает функция освобождения или код, который
   уничтожает источник его памяти;
2. ничего не возвращается дважды и не возвращается в чужой слот;
3. исходная память множества умирает, только когда выданное из него не держат снаружи его памяти: перед возвратом блока или
   уничтожением экземпляра вернулось всё, что держат снаружи; элементы под множеством умирают вместе с источником
   ([уничтожение источника](layout-algorithm.md#что-описывает-layout));
4. элемент покидает множество только событиями карты или через точку доверия.

**Условия функций выводятся.** Из тела функции FLOW выводит её предусловия и постусловия о выданных и возвращённых
элементах и добавляет их в прототип: у `acquireSlot` — «результат — слот, выданный из `block.slots`», у `releaseSlot`
— «`slot` выдан из `block.slots`». Вызывающий код проверяется по прототипу. У функции без тела (интерфейс, контракт,
функция C) пишется код [модели](../models.md#модель-model), и условия выводятся из него. Программист вправе написать
`requires` и `ensures` сам; FLOW добавляет только то, чего не хватает.

## Выдача и возврат

```efen
fn reuse(block: own SlotBlock) {
    let a = lend block.slots[0]         // block теперь mut SlotBlock
    let b = lend block.slots[1]
    block.slots[0] = take a             // слот 0 вернулся
    freeBlock(take block)               // ошибка: слот 1 выдан, own SlotBlock не восстановлен
}
```

1. `lend block.slots[k]` выдаёт слот `k`: `own block.slots.Item` с одним владельцем; байты не переносятся, `k` входит
   в `slots.taken`. Выдать выданный слот — ошибка.
2. `block.slots[k] = take slot` возвращает слот; `k` выходит из `slots.taken`. Вернуть можно только в свой слот.
3. Поля выданного слота через блок не читаются и не пишутся: память держит получатель.
4. На каждом выходе функции изменение `used` равно числу выдач минус число возвратов.
5. Переменная становится владельцем блока (`take block`), только если блок пришёл с `used > 0` и `used` стало 0 возвратами в
   этой функции.
6. Диапазон: `lend block.bytes[a ..< b]` и возврат тем же куском.
7. Раздача `for element in take region`: каждый элемент тело передаёт дальше; `break`, `continue` и `return` в теле —
   ошибка; оставленный элемент — утечка.

Подробно: [иерархия владения](pointer.md#иерархия-владения).

## Выдача наружу

Внешний код получает память `layout` одним из трёх способов. Способ зависит от того, что `layout` делает с этой
памятью, пока она снаружи.

| Что делает `layout` | Запись | Что получает внешний код |
|---|---|---|
| не трогает содержимое; помнит только, какой слот занят | `lend block.slots[k]` | `own` на слот; доступ действительно один |
| держит в элементе свои поля (`next`, `prev`, счётчики), наружу отдаёт остальное | поля остаются у `layout`, выдаётся вложенная область: `lend block.data[0]` | `own` на байты области; указатели `layout` смотрят на другие байты |
| продолжает читать или писать те же байты | результат с правом `mut`, `edit` или `read` | заимствование: живёт, пока источник не изменил структуру ([что убивает ссылку](memory-rules.md#что-убивает-ссылку)) |

Четвёртого способа нет: якорь внешнему коду не выдаётся. Целиком наружу уходят значение структуры `layout`
(`Graph`, `List`) и элемент, выданный как `own S.Item`. Выдачу слота и выдачу элемента блок объявляет строками
`lend` и `own` [схемы владения](#схема-владения); значение структуры и заимствование строки не требуют.

Тип выданного слота называет область, из которой он выдан. Когда родитель — параметр, тип пишется через него:
`own block.data.Item`. В результате функции, где родитель вызывающему не виден, тип пишется через структуру:
`own Block.data.Item` — «слот из области `data` какого-то блока». Привести такое значение к `Pointer` и отдать
менеджеру памяти нельзя: слот возвращается туда, откуда выдан.

```efen
layout {
    set area Blocks: Block

    public lend Block.data                       // публичные функции выдают слоты области data и принимают их обратно

    struct Block {
        var next: anchor Blocks.Item? = null     // цепочка занятых блоков: поля layout
        var prev: Blocks.Item? = null
        area data: Byte                          // память для внешнего кода
        invariants { next == null || next!.prev == self }
    }

    struct Pool { var busy: anchor Blocks.Item? = null }
}

public fn acquire(pool: mut Pool) -> own Block.data.Item? {
    guard let block = takeFree(pool: pool) else { return null }
    let data = lend block.data[0]            // выдан слот из block.data
    linkBusy(pool: pool, block: tie block)  // блок остался в цепочке пула
    return data
}

public fn release(block: mut Blocks.Item, data: own block.data.Item) {
    block.data[0] = take data                // слот вернулся туда, откуда взят
}
```

**Блок для возврата находит код.** Основная форма — блок передаёт вызывающий, и тип связывает его со слотом, как
в `release` выше. Если алгоритм вычисляет блок по адресу, это строка кода:
`(address(data) & ~(BLOCK - 1)) as Blocks.Item`. Компилятор ничего не подставляет; он проверяет написанное по
`@align(BLOCK)` и вложенности области. Недоказанная строка — ошибка, пока перед ней не написан `assume`: точка
доверия бывает только объявленной.

**Что разрешено, пока память снаружи.** Правило одно: после каждого вызова FLOW доказывает, что указатель,
оставшийся у внешнего кода, актуален. Недоказанный случай — ошибка.

- Вызов, сводка которого освобождает или переносит память под указателем, — ошибка в месте вызова.
- Вызов, который пишет только другие байты (переставляет `next` и `prev` в цепочке блоков, пока область `data`
  блока выдана), разрешён. Запрещено вернуть или освободить блок, пока его слот выдан.
- Заимствование с правом (`mut`, `edit`, `read` в результате) живёт по правилу языка
  ([что убивает ссылку](memory-rules.md#что-убивает-ссылку)): вызов `edit` его не трогает, вызов, который меняет
  структуру источника, его кончает, и использовать его после такого вызова — ошибка.

```efen
fn example(list: mut List) {
    let node = list.first()             // указатель на узел, источник — list
    list.insertFirst(value: 7)          // допустимо: edit, узлы на своих адресах
    print(node.value)
    list.removeFirst()                  // ошибка: узел освобождён, а node используется ниже
    print(node.value)
}
```

## Указатели вне `layout`

Вне `layout` указатель на элемент хранит только структура с параметром источника:

```efen
struct ListCursor<Src: Origin> {
    var list: read<Src> List
    var current: read<Src> Items.Item? = null
}

let cursor = ListCursor<Src: list>(list: list)
```

У элемента множества без поля-владельца `Src` — само множество: `ListCursor<Src: Vertices>`, и вызов, сводка
которого освобождает элемент множества, — изменение структуры для такого курсора.

Поле `current` — заимствование в структуре: курсор заимствует `list` с правом `read`, и указатель в поле имеет источником `list`
([источник указателя](#источник-указателя)). Действует правило заимствований языка
([что убивает ссылку](memory-rules.md#что-убивает-ссылку)): вызов `edit` у списка (вставка, перестановка узлов)
курсор переживает; перед вызовом, который освобождает узлы или уводит их из списка, неиспользуемый дальше курсор
уничтожается, а используемый — ошибка. Исключение — функция, которая принимает сам курсор и переставляет его
`current`. Поле типа `S.Item` в обычной структуре вне `layout` — ошибка, с любым словом: `own S.Item` и
`own Block.data.Item` в поле класса или обычной структуры тоже. Элемент и слот, полученные владением, внешний код
держит в локальной переменной, параметре и результате, а дольше одного вызова — в обобщённом контейнере `layout`
(`Vector<own Nodes.Item>`) ([держатели у внешнего кода](#схема-владения)). Структуры со взаимными указателями (LRU над хеш-таблицей, индекс над таблицей) описываются одним `layout`.

## Виды и приведение `as`

Одни и те же байты бывают разными видами. Блок mm бывает `PoolBlock`, `FreeBlock`, `SlotBlock`, `LargeBlock`; первым
полем у каждого идёт общий `Header`, и у каждого свои `invariants`. Смена вида — приведение:

```efen
let spare = block as SlotBlock(slots: Slot(size: SIZES[index]))
```

Приведение `Pointer` к виду поглощает `Pointer`. Компилятор доказывает, что размер памяти не меньше вида и
выравнивание не меньше `@align` вида.

**Инициализация после приведения — явная.** У структуры все операции явные. Приведение с аргументами
(`as Item(next: NONE)`) работает как вызов `Item(…)`: записывает названные поля, а поле со значением по умолчанию
(`var next: … = null`) получает его. Поле без значения по умолчанию, которое не записано в приведении, не общее с
прежним видом той же памяти и не записано кодом после приведения, не инициализировано; обращение к нему — ошибка
компиляции: сперва инициализируйте. «Не инициализировано» и `null` — разное: `null` — значение.

Грязный инициализатор `_` пишется только явно и всегда виден по имени поля в строке приведения:
- на поле-числе (целом или с плавающей точкой) оставляет прежние байты и при выполнении ничего не делает;
- на опциональном поле (указатель `S.Item?`, `own …?`, `anchor …?`) записывает `null`;
- на неопциональном указателе, поле `own` или `anchor`, логическом поле, варианте и поле типа-параметра `T` — ошибка:
  такое поле записывается явно.

```efen
let a = memory as Item(value: 0, next: NONE)    // все поля записаны в приведении
let b = memory as Item(value: _, next: NONE)    // value — прежние байты, явно; next записан

let c = memory as Item                          // поля пусты
print(c.value)                                  // ошибка: value не инициализирован
c.value = 0
c.next = NONE
print(c.value)                                  // можно
```

Обычный путь — записать поля в приведении или кодом после него; `_` — для поля, байты которого программе не
важны или уже верны по устройству памяти. Записи «остальные поля грязные» нет. Стирание `block as Pointer`
возвращает память без вида; размер, с которым её брали, FLOW помнит как факт о значении, и `unmap` доказывает своё
условие по нему.

## Законы и цепочки

Строки `invariants` вида — законы, которые держатся в каждой точке передачи вида дальше. На входе функции FLOW
принимает их верными; в точке передачи (`return` публичной функции, аргумент вызова публичной функции или функции без тела, запись в поле,
выход параметра `mut` публичной функции) доказывает. Закрытый помощник получает структуру с открытым законом и сводкой передаёт
наверх, что он с законом сделал.
Внутри функции закон можно временно нарушить.

```efen
invariants {
    used == slots.taken.count
    frontier <= slots.count
    forall k in frontier ..< slots.count: !slots.taken.contains(k)
    let freeSlots = slots.chain(from: firstFreeSlot, by: Slot.next, until: NONE)
    forall k in freeSlots: 0 <= k && k < frontier && !slots.taken.contains(k)
}
```

Цепочка `A.chain(from: H, by: T.L, until: END)` — узлы, достижимые от головы по полю-ссылке до конца. Какие узлы на
цепочке после каждой записи головы и ссылки, FLOW знает сам: снятие головы, вставка, вырезание из середины. Программист
пишет только законы о её узлах. Ключевого слова под каждую структуру нет: список, очередь, стек и дерево
описываются одной формой цепочки и законами. Подробно: [цепочка](../conditions.md#цепочка).

**Точки восстановления закона.** Закон структуры верен в каждой точке, где её видит чужой код:

- `return`;
- `throw`;
- приостановка;
- вызов кода, способного обратиться к изменяемой структуре;
- публикация указателя на изменяемое состояние.

Зависимости закона FLOW выводит из прочитанных слотов. Между точками восстановления соседние безотказные шаги могут
временно нарушить затронутый закон, к ближайшей точке он снова верен.

Исключение — курсор обхода. Курсор, который объявил, какие части источника он держит, оставляет закон открытым на этих
частях между шагами обхода: `next()` возвращается, тело цикла выполняется, но обратиться к объявленным частям мимо
курсора тело не может, а закон закрывает `exit` на любом выходе из цикла
([области доступа](../types/access-regions.md#итератор-как-структура)). Приостановка внутри такого обхода допустима,
только если ничто возобновляемое не держит путь к источнику. Отдельного блока доказательства и копии структуры в
исходной программе не нужно: промежуточное состояние строит проверяющий модуль.

Закон списка с хвостом читается по строкам: `nodes` — элементы от `head` по `next` до `null`; каждый элемент `Items`
стоит на цепочке; хвост — последний; длина — число элементов. Повторов в цепочке нет, поэтому каждый элемент стоит в
ней ровно один раз, а `(head == null) == (tail == null)` следует из того, что `last` пуст только у пустой цепочки.
Призрачных строк в операциях нет: какие элементы на цепочке после записи `head` или `next`, FLOW знает сам и проверяет
закон в точке восстановления.

```efen
layout {
    set Items: Item

    struct Item {
        var value: Int
        var next: anchor Items.Item? = null
    }

    struct List {
        var head: anchor Items.Item? = null
        var tail: Items.Item? = null
        var length: Int = 0 { value >= 0 }

        invariants {
            let nodes = Items.chain(from: head, by: Item.next, until: null)
            forall n in Items: nodes.contains(n)
            tail == nodes.last
            length == nodes.count
        }
    }
}
```

Цепочка может связывать не всё множество, а его часть: свободные элементы, свободные слоты области. Тогда закон
говорит, какие элементы на ней стоят:

```efen
layout {
    set area Cells: Cell

    struct Cell {
        var kind: Int
        var next: Cells.Item? = null
    }

    struct Pool {
        var firstFree: Cells.Item? = null
        invariants {
            let freeCells = Cells.chain(from: firstFree, by: Cell.next, until: null)
            forall c in Cells: (c.kind == FREE) == freeCells.contains(c)
        }
    }
}
```

Над областью вида то же пишется номерами слотов ([указатели](pointer.md#цепочка-свободных-мест)).

Условие множества может назвать вид элемента: `value is V` значит, что у элемента верны все условия вида `V`; `V`
встраивает тип элемента первым полем.

```efen
set area Boxes: Box {
    value.kind == STACKED ==> value is Stack
}
```

Имя элемента условий вида не несёт; после проверки `box.kind == STACKED` они верны, и `box` можно передать как `Stack`.
Функция, которая меняет то, что читают условия `Stack` (поля, `taken`), доказывает их у элементов, которые меняет.
`x is V` с видом справа допустимо только в условиях. Несколько выражений одного блока соединяются логическим `&&`.

Закон о множестве с полем-владельцем (`forall n in Items: …`) — закон каждой структуры о её собственных элементах.
Функция опирается на него только для структур, к которым у неё есть доступ; иначе поток A полагался бы на закон,
который у потока B открыт ([многопоточность](#многопоточность)).

### Локальное доказательство законов

Статус: гипотеза, проверена на бумаге на mm и проверочных структурах; в компиляторе не реализована.

Закон, который держится на входе функции, на выходе нужно доказать только для того, что функция тронула. FLOW
доказывает его сам, своей линейной арифметикой, за число шагов, равное числу событий в теле; Z3 для этого не нужен.

**Какие законы локальны.** Закон `forall k in c: P(k)` или `forall k in a ..< b: P(k)` локален, если `P` читает только:

1. поля самого узла `k` и, для двусвязной формы, поля его соседа по ссылке (`k.next.prev == k`);
2. поля вида, которые функция меняет только в сторону, сохраняющую `P` (`k < frontier` при росте `frontier`);
3. принадлежность `k` множеству, которое ведёт FLOW (`slots.taken.contains(k)`).

Закон о числе узлов (`freeSlots.count == frontier - slots.taken.count`, `length == nodes.count`) локален, если обе
стороны меняются на известные величины: вставка даёт `+1`, снятие — `-1`.

**Алгоритм.** На входе закон принят. FLOW проходит тело и для каждого события записывает обязательство:

| Событие | Обязательство на выходе |
|---|---|
| вставка узла `k` в цепочку | `P(k)` |
| снятие головы, вырезание узла | нет: остальные узлы те же, повторов нет |
| запись поля узла `k`, которое читает `P` | `P(k)`, если `k` на цепочке, и `P` соседа для двусвязной формы |
| запись поля вида, которое читает `P` | новое значение сдвинуто в сохраняющую сторону; иначе закон не локален |
| выдача слота `m` (`m` входит в `taken`) | `m` не на цепочке: снят с неё или взят у границы |
| возврат слота `m` (`m` выходит из `taken`) | нет: условие `!taken.contains(k)` только усиливается |
| сдвиг границы диапазона (`frontier + 1`) | `P` у узлов, вошедших в диапазон; вышедшие свободны от закона |

Внутри тела закон может быть нарушен: обязательства проверяются на выходе по итоговым значениям. Каждое обязательство —
линейное неравенство над полями узла и вида, и его доказывает тот же доказатель, что и границы индексов.

**Проверка на структурах.**

| Структура | Закон | Локален |
|---|---|---|
| `SlotBlock` mm, `Region` mm, пул объектов | `forall k in freeSlots: 0 <= k && k < frontier && !slots.taken.contains(k)` | да: `frontier` только растёт, выдача — после снятия или у границы |
| те же | `forall k in frontier ..< slots.count: !slots.taken.contains(k)` | да: выданный у границы слот выходит из диапазона тем же сдвигом |
| односвязный список | `length == nodes.count` | да: `+1` при вставке, `-1` при снятии |
| двусвязный список | `k.next == null \|\| k.next.prev == k` | да, с соседом |
| хеш-таблица | каждая запись в цепочке своей корзины | да, если FLOW ведёт цепочку каждой корзины отдельно: вставка в корзину `b` требует `e.home == b` |
| дерево поиска | ключ левого меньше ключа правого по всему поддереву | нет: связывает узел со всем поддеревом — Z3 |

**Цикл со счётчиком.** Цикл, где переменная `i` начинается с 0, растёт на 1 за итерацию и кончается на `N`, а тело
делает `P(i)` верным и не трогает других слотов, даёт закон `forall k in 0 ..< i: P(k)`: перед циклом диапазон пуст,
итерация добавляет в него ровно слот `i`, после цикла `i == N`. Это тот же сдвиг границы в сохраняющую сторону, что
и рост `frontier`. Раздача `for element in take region` даёт то же без счётчика: тело получает каждый слот ровно
один раз.

**Пример: рост хеш-таблицы.** Записи переходят из старых корзин `A` в новые `B`; освободить `A` можно, только если
пусты все её слоты.

```efen
layout {
    set Entries: Entry

    struct Entry {
        var key: Int
        var home: Int
        var next: anchor Entries.Item? = null       // якорь следующей записи цепочки
    }

    struct Bucket {
        var head: anchor Entries.Item? = null       // якорь первой записи корзины
    }
}

fn grow(table: mut Table) {
    var fresh = newBuckets(count: 2 * BUCKETS)
    var i = 0
    while i < BUCKETS {
        while let e = tie table.buckets![i].head {      // снять первую запись старой корзины i
            table.buckets![i].head = tie e.next
            let b = hash(e.key) % (2 * BUCKETS)
            e.home = b
            e.next = tie fresh![b].head                 // вставить в голову новой корзины b
            fresh![b].head = tie e
        }
        i = i + 1                                        // закон: корзины 0 ..< i пусты
    }
    freeBuckets(take table.buckets)                      // все слоты A пусты: освобождение разрешено
    table.buckets = take fresh
}
```

Каждая запись в любой момент под одним якорем, в `A` или в `B`; переход — `tie`, указатели на записи живы: таблица вместе с областью корзин — одна
[структура](#структура-источник-чистота). Закон «запись
в цепочке своей корзины» внутри функции нарушен и восстановлен на выходе.

**Где нужен Z3.** Нелинейные выражения (`slots.count == PAYLOAD / SIZES[sizeClass]`), порядок по всей структуре, сумма
или перестановка узлов, закон, связывающий две цепочки, и поле вида, сдвинутое в несохраняющую сторону.

## Диагностика времени жизни

FLOW не только доказывает, но и объясняет. Ошибка времени жизни называет конфликт: где значение умерло, где его указатель
использовано после этого и путь между ними.

```
error[flow.slot-left]: указатель `node` использован после конца жизни узла
  --> list.efn:12:11   print(node!.key)
note: узел уничтожен вызовом release (сводка: уничтожает node)
  --> list.efn:11:5    release(pool: pool, node: tie list.head)
note: указатель взят здесь
  --> list.efn:10:16   let node = list.head
```

В режиме подробной печати FLOW выдаёт жизненный цикл значения целиком в виде графа: рождение, передачи якоря, вызовы
с их пометками из сводок, точку уничтожения и каждый указатель с местом, где он становится недействительным. По графу видно, на каком пути
цикл нарушен.

Отдельный режим печатает граф времени жизни всех объектов одного `layout`: каждое множество и область, их
вложенность, якоря и владельцев, функции, которые рождают, передают и уничтожают элементы, с их пометками из сводок, и
все указатели между множествами. Это карта жизни элементов (раздел [время жизни](#время-жизни)) целиком, а не для одного
значения: по ней видно, как устроена память структуры данных и где у элемента нет пути к уничтожению.

Указатели ключей или команд для этих режимов задаёт реализация.

## Что доказывается

| Описано | Доказывается | Кто |
|---|---|---|
| вид и `as` | размер, выравнивание, запись полей до чтения | FLOW |
| число слотов области | индекс в границах | FLOW, Z3; что не доказано — проверка при выполнении |
| `lend` / `take` в свой слот | один владелец слота, нет повторной выдачи, возврат только в свой слот | FLOW |
| `used == slots.taken.count` | счёт сходится на каждом выходе; блок не отдаётся, пока внутри есть выданное | FLOW |
| `for element in take region` | каждый элемент отдан дальше | FLOW |
| вложенность и выдача | время жизни каждого указателя, полнота карты жизни элемента | FLOW |
| `invariants` вида | закон держится в каждой точке передачи | FLOW, Z3 |
| цепочка и её законы | форма цепочки по записям; законы о её узлах и предпосылки событий | FLOW; Z3 |
| указатель из адреса C | принадлежность к множеству | точка доверия |

Каждый факт несёт метку того, кто его установил: FLOW, Z3, точка доверия или проверка при выполнении. Правило
`apart` одно: пишущий аргумент (`mut`, `edit`, `out`) не пересекается ни с одним другим; пара, которую проверяет
`OverlapError` при выполнении, помечается «проверено при выполнении».

**Сырая память линейна:** владеющий корень передаёт её дальше на каждом выходе, оставленная память — `flow.leak`.
Область, заполненная не целиком, очищается по занятому диапазону
([частичная инициализация](#частичная-инициализация-и-очистка)).

## `layout` в теле класса

Блок `layout { … }` бывает и в теле класса, интерфейса или контракта. Там он описывает не байты, а то, что держит
внешняя сторона ([класс над внешним значением](../classes.md#класс-над-внешним-значением)), и содержит только:

- объявления `var` — поля `layout`. Их нет в памяти объекта, их не исполняют, их читает только FLOW; пишет их
  [модель](../models.md#модель-model);
- строки условий в форме [законов](#законы-и-цепочки): `forall`, `==`, `if` как импликация
  ([отношения в `layout`](../models.md#отношения-в-layout-класса));
- у контракта и интерфейса — строки `part`: имена частей объекта без типа и без значения, которые называют пометки
  методов ([части объекта](../types/parts.md)). В `layout` класса строки `part` нет: класс привязывает части к
  своим полям строками `part Contract.name = …` в теле, вне `layout`.

Физические описания (`set`, `one`, `area`, `struct`) пишет только блок `layout` уровня модуля; в `layout` класса они —
ошибка. Два блока не вкладываются друг в друга: класс пользуется памятью `layout` через поля, тип которых — структура
`layout`.

Тип поля `layout`:

- `read T`, `edit T` — заимствование слота Efen;
- `mut U`, `read U`, где `U` — класс над внешним значением, — зависимость от внешнего объекта: пока жив объект,
  `U` нельзя уничтожить и отдать;
- `own T` — значение, которое забрала внешняя сторона. Замыкание `own` вида `own` упаковывает сгенерированный вход
  и освобождает после единственного вызова. Другому значению `own` нужна память Efen, а поле `layout` её не занимает
  ни в каком классе, — ошибка. Класс с настоящими полями хранит такое значение в настоящем поле: модель пишет его туда
  ([заимствования](../models.md#заимствования));
- коллекция или optional из таких типов;
- простое значение (`errmsg: CString`) — только как источник ссылок, которые возвращают методы.

Поля `layout` бывают у класса без счётчика (класс над внешним значением — один из таких классов), у интерфейса и у
контракта. Класс со счётчиком пишет в `layout` только строки условий: его поля — `managed`, и внешняя сторона держит
через них только то, что называет отношение ([заимствования](../models.md#заимствования)).

`obj.field` вне модели и вне условия `layout` — ошибка. Исключения — строка привязки части и путь в пометке метода
у класса над внешним значением: там поле `layout` называют по имени
([привязка в реализации](../types/parts.md#привязка-в-реализации)). Настоящее поле и поле `layout` с одним указателем — ошибка.
Настоящие поля класса пишутся вне `layout`, как обычно; у класса над внешним значением их нет.

**Порядок уничтожения — опубликованная гарантия.** Объект уничтожается раньше каждого слота, который заимствует, и
раньше каждого объекта, от которого зависит; остальное идёт в порядке, обратном объявлению. Круг заимствований в
конце области — ошибка с указателями обоих объектов. Среди полей класса порядок тот же, и отношение `forall` его
задаёт: при `forall s in cache.values: s.db == db` поле `cache` уничтожается раньше `db`.

**Жизнь заимствования.** Заимствование живёт, пока модель его не снимет или пока объект не уничтожен. В синхронном режиме
владелец заимствованного слота читает его и пишет значения, но не меняет структуру, не перемещает, не уничтожает и не
отдаёт.

## Многопоточность

Структура `layout` переходит в другой поток целиком, а делится между потоками только под блокировкой. Нового синтаксиса
для этого нет: структура — уже чистое значение ([чистота](#структура-источник-чистота)), и поле `shared`
принимает её, пока она [чиста](#структура-источник-чистота). Указатель
живёт только в потоке, у которого есть доступ к его источнику, поэтому указатель, живой в двух потоках без блокировки,
не возникает. Раздел — текст правил; Amber их пока не проверяет.

«Поток» здесь — поток выполнения (корутина, тело `offload`, замыкание `shared layout`), а не поток ОС: корутина может
сменить поток ОС ([области доступа](../types/access-regions.md#корутины-spawn)).

### Структура и поток

Для таблицы многопоточного вида структура — одна область: корень вместе с каждым элементом под ним. Право, которое
выполняют через любой указатель с этим источником, считается доступом к области с этим правом.

Указатель, ссылка или заимствование в структуре, живые на любом участке отрезка многопоточной корутины, считаются `read` своего
источника на весь отрезок. Корутина, которая правит или перестраивает этот источник, — ошибка компиляции: основная
метка у `spawn`, вторая у последующего использования ([правила доступа](memory-rules.md#два-доступа-сразу)).

Указатель, источник которого — структура в контексте потока, умирает в каждой непрозрачной точке, как ссылка из него
([ссылка из контекста потока](../context-and-effects.md#ссылка-из-контекста-потока)). В однопоточном контексте нового
нет: в точке ожидания действуют сводки живых корутин, как при вызове, поэтому их изменения структуры убивают там
указатели, а законы закрыты до приостановки (см. [чистота](#структура-источник-чистота)).

### Переход между потоками

Структура меняет поток только целиком, владением корня: `capture x = take x`, параметр `own`, результат корутины или
`take` в поле `shared` и из него. Такой переход — изменение структуры «корень ушёл из слота» из определения 4: в отправителе
умирает каждый указатель и каждая ссылка с этим источником. Держатель, который дальше не используется, уничтожается
до перехода; используемый — ошибка. Переход ещё и точка передачи: законы и чистота доказываются в ней.

Выданный слот (`own block.data.Item`) — отдельное значение `own` и может жить в другом потоке, чем родитель:
правило 3 раздела [«Выдача и возврат»](#выдача-и-возврат) уже делает их байты непересекающимися. Вернуть слот
можно только с `mut` на родителя, то есть с доступом к его структуре; пока слот выдан, правило 2 раздела
[«Вложенность»](#вложенность) держит родителя живым.

```efen
fn work(list: own List) {
    let p = list.first()                       // Items.Item, источник — list
    with makeTaskGroup() {
        let h = spawn { sum(list) }            // области h: read list, вся структура
        print(p.value)                         // можно: чтение против чтения
        list.insertFirst(value: 7)             // ошибка: правка против чтения h
        await(take h)
    }
    with makeTaskGroup() {
        background { capture var l = take list; l.removeFirst(); l.release() }   // корень ушёл из слота
        print(p.value)                         // ошибка: p умер в `take list`
    }
}
```

Корутина не захватывает `S.Item` ([замыкания](../closure.md#что-корутина-может-взять)): она называет структуру и
читает указатели внутри неё.

### Структура под блокировкой

В поле `shared`-структуры кладут только чистую структуру. Под охраной поля проекция даёт на корень `mut`, если
поле `var`, и `read`, если `let`. Внутри одной блокировки `edit` и `mut` работают, как в одном потоке, и важны только
для указателей той же области блокировки.

Отпускание блокировки — изменение структуры каждого охраняемого поля: каждый указатель, ссылка и заимствование с источником в таком
поле умирает на `exit`. Значение, которое хранит такой указатель, ссылку или заимствование и дальше не используется, уничтожается до `exit`, даже переменная верхнего
уровня тела `with`; используемый — ошибка ([проекция](../shared.md#доступ-через-projection)).

Законы и чистота охраняемых структур принимаются верными после захвата и доказываются при каждом отпускании: на
обычном выходе, при исключении и в конце каждого вызова замыкания `waitFor`, вместе с `invariants` самой общей структуры
([инвариант](../shared.md#инвариант)). Элемент, взятый под локальным `anchor`, может выйти из области блокировки:
чистота на `exit` доказывает, что внутри на него ничто не указывает. Под блокировкой хватает обычного `anchor`.

Поток, который ждёт завершения другого (`await`, конец `with`), опирается на существующий конец областей корутины.

```efen
shared struct Jobs {
    var mutex: Mutex
    var queue: List                            // чистая структура layout
}
projection JobsEditor for Jobs { var queue; invariants { mutex is Mutex.Held } }

fn peek(jobs: mut Jobs) -> Int requires jobs.mutex is Mutex.Free {
    var node: Items.Item? = null
    with jobs.mutex {
        let editor = jobs as JobsEditor
        node = editor.queue.first()            // источник — jobs.queue
        editor.queue.insertFirst(value: 7)     // правка: node жив
    }                                          // exit: здесь node умер
    return node!.value                         // ошибка: использован после отпускания блокировки
}
```

### Роли

Роль делит между потоками целые поля или диапазоны индексов `area`, у которой тип слота и всё, чем слот владеет, не
хранят невладеющего `S.Item`. Элементы `set` роль не делит: структура-множество целиком принадлежит одной роли
([роли](../shared.md#роли)).

### Множества без владельца и `one`

Множество без поля-владельца и `one X` — память всей программы. Каждое из них — одна область, названная множеством или
`one`. Доступ через указатель, источник которого — множество, и эффект `in read|edit|mut X` — доступы к этой области;
таблица многопоточного вида проверяет их по всей программе. У вызова без тела слово записи на любом параметре этого
`layout` — то же право на всех его множествах без владельца. Нечистая структура может перейти в другой поток,
но доступы получателя к ней попадают в область множества.

В этой редакции такое множество и `one` под блокировку не кладут. Общее состояние под блокировкой записывают
структурой с полем-владельцем в `shared struct`: граф с вершинами на цепочке `anchor` от корня и соседями в виде
невладеющих указателей.

```efen
let v = addVertex(label: 1)                    // источник — множество Vertices
with makeTaskGroup() {
    background { addVertex(label: 2) }         // эффект: in edit Registry, правка Vertices
    print(v.label)                             // ошибка: чтение Vertices против записи корутины
}
```

### Чего `layout` не описывает

- Структуры без блокировок, где ячейки делят больше двух потоков, — примитивы стандартной библиотеки, доказанные один
  раз. Указатели в нескольких потоках без блокировки (эпохи, указатели опасности) требуют механизма времени
  выполнения, а не доказательства FLOW; их место — те же примитивы стандартной библиотеки.
- Освобождение блока менеджера памяти из чужого потока. Структура, перешедшая в другой поток, возвращает узлы в кучу
  этого потока ([указатель](pointer.md#не-решено)). `mm.allocate` и `mm.free` потокобезопасны по объявлению: это
названная точка доверия, её перечисляет `efen proofs`, и слот возвращается в кучу того потока, из которой выдан; выданный
  слот в любом потоке уже доказывает, что его блок жив (правило 2 раздела [«Вложенность»](#вложенность)).
- Объекты со счётчиком (`conforms ArcClass`): `shared class` со счётчиком ждёт решения об атомарном счётчике.

## Открытые вопросы

Модель времени жизни строится по шагам; эти вопросы ещё не решены.

1. **Жизнь множества целиком.** Решено так: множество логическое, своей памяти у него нет, и оно не рождается и не
   умирает; оно задаёт только источник указателя (`Blocks.Item` — «из `Blocks`»). Живёт и умирает память элементов:
   она взята из источника (у ОС через `System.map`, из области родителя, из экземпляра) и возвращается в него явно
   (`free`, `System.unmap`, уничтожение экземпляра, которое обязано вернуть все элементы). Возврат при выходе процесса
   не считается.
2. **Хранимые указатели.** Решено так: внутри `layout` хранимый указатель связан законом, из которого FLOW знает, где он лежит
   (`next!.prev == self`, членство в цепочке), или объявлен как указатель на элемент одного из множеств `layout`
   (`var current: Nodes.Item?` в структуре `Cursor` внутри `layout`). Во втором случае FLOW по коду доказывает, из
   какого множества пришёл каждый такой указатель, и проверяет его время жизни: к уничтожению элемента указатель переписан
   или недействителен. Указатель на сам список курсору тогда не нужен, но курсор обязан быть структурой этого `layout`.
   Вне `layout` указатель на элемент хранит только структура с параметром источника
   ([правило](#указатели-вне-layout)):

   ```efen
   struct ListCursor<Src: Origin> {
       var list: read<Src> List
       var current: read<Src> Nodes.Item? = null
       invariants {
           let nodes = Nodes.chain(from: list.head, by: Node.next, until: null)
           current == null || nodes.contains(current!)
       }
   }
   ```

   Сегодня читатель принимает поле `Nodes.Item?` в структуре вне `layout` без ошибки — расхождение со спецификацией.
3. **Цикл якорей.** Решено так: цикл строится из указателей под законом, а не из якорей. Память элементов держит множество,
   конец жизни элемента задаёт функция, которая его освобождает: точка её вызова — конец жизни, её тело доказывает,
   что висячих указателей не осталось. Так доказывается и произвольный граф. По умолчанию запись владельца
   запрещена. Запись якоря `t.f = tie r` принимается,
   только если доказано, что `t` не лежит в дереве `r`: `r` только что оторван, `r` пришёл параметром без детей-якорей
   или `t` сам только что взят как корень, и во всех трёх случаях `t != r`; иначе FLOW выводит предусловие, а без
   него — ошибка. Цикл якорей ничей с
   момента замыкания, и в общем случае его исключение требует достижимости, которую локально не доказать
   ([доказательство структур](layout-proofs.md#произвольный-граф-узел-освобождает-функция)).
4. **Уничтожение значения с якорями и рождение элемента.** Решено так: память входит в множество приведением
   `Pointer` или выдачей из другого множества и выходит тем же путём
   ([вход и выход памяти](#время-жизни-по-полю-и-по-функциям)). Элемент, у которого обязательные указатели
   связывают его с другим новым элементом (пара полурёбер DCEL), вводится одной операцией вместе с ним. Память по
   указателю `anchor` или `mut` возвращается только после перехода [`as own`](#переход-к-владению-as-own). К этой
   точке владеющие поля элемента — `own` и якоря — `null`: их освобождает явный код до освобождения элемента.
5. **Законы с головой, зависящей от переменной.** «Запись лежит в цепочке своей корзины»
   (`forall e in entries: entries.chain(from: buckets[e.home].head, …).contains(e)`) доказывается для произвольной
   корзины `i` в два случая: `i == b` — корзина, которую событие изменило (вставка `e` требует `e.home == b`), и
   `i != b` — её цепочка не тронута. Раз корзина произвольная, закон верен для всех. Открыто только то, что FLOW сегодня
   ведёт цепочку с одной фиксированной головой, а не цепочку с параметром.
6. **Многопоточность.** Решено так: структура — одна область для таблицы многопоточного вида, переходит между потоками
   целиком и делится только под блокировкой ([раздел](#многопоточность)).
7. **`layout` у типа и в теле класса.** Решено так: блок стоит на уровне модуля, тип коллекции — его структура,
   методы даёт стратегия ([пространство `layout`](#пространство-layout)); блок в теле класса описывает только
   заимствования и физических описаний не содержит ([`layout` в теле класса](#layout-в-теле-класса)).
8. **Ещё не решено.** Исходная память множества как отдельное понятие в записи `layout`; область с элементами разного размера;
   слабые указатели и поколения элементов; перенос всех элементов множества одной операцией. Функция `@abi(c)` с
   телом, которую вызывают чужие потоки; захват корутиной элемента `layout` владением.

Проверочные структуры для этих вопросов: [layout-examples/checks](layout-examples/checks/README.md).

## Схема владения

Что функции блока `layout` отдают внешнему коду во владение, блок объявляет явно. Строк две: `own S` — элемент
множества `S` уходит целиком, `lend Структура.область` — выдаются слоты области (Edmond 2026-11-12). Якорь
внешнему коду не выдаётся, и строки `anchor` нет.

```efen
private layout {
    set Nodes: Node
    set Vertices: Vertex
    set area Blocks: Block

    public own Nodes           // узел уходит наружу целиком: own, на него никто не смотрит
    public lend Block.data     // наружу выдаются слоты области data; поля блока остаются у layout

    public struct Node  { var next: own Nodes.Item? = null; public var value: Int }
    public struct Queue { var head: own Nodes.Item? = null }

    struct Block { var next: anchor Blocks.Item? = null; area data: Byte }
    public struct Pool { var busy: anchor Blocks.Item? = null }

    struct Vertex {
        var nextAll: anchor Vertices.Item? = null    // цепочка владения графа
        var neighbors: Vector<Vertices.Item>         // соседи: указатели внутри того же графа
    }
    public struct Graph { var first: anchor Vertices.Item? = null }
}

public fn newNode(value: Int) -> own Nodes.Item { … }
public fn freeNode(node: own Nodes.Item) { … }
public fn push(queue: edit Queue, node: own Nodes.Item) { … }
public fn pop(queue: mut Queue) -> own Nodes.Item? { … }
public fn release(queue: mut Queue) { … }        // освобождает узлы очереди; такие же функции у Pool и Graph

public fn acquire(pool: mut Pool) -> own Block.data.Item? { … }
public fn giveBack(block: mut Blocks.Item, data: own block.data.Item) { … }
```

**Код блока и внешний код.** Код блока — функции, которым модификатор блока разрешает писать поля; остальной
код — внешний ([кто пишет поля](#пространство-layout)). Между функциями кода блока владение элементом, `own` и
`anchor`, переходит без строки: это движение внутри `layout`. Строка нужна там, где владение получает или
возвращает внешний код.

**Что требует строки.**

| Что получает внешний код | Строка |
|---|---|
| элемент целиком: `own S.Item` | `видимость own S` |
| слот или диапазон слотов области, выданный `lend`: `own Block.data.Item` | `видимость lend Block.data` |
| значение структуры `layout` (`Queue`, `Graph`, `Vector<Int>`) | не нужна: владение значением — его тип |
| указатель без слова, заимствование `read`, `edit`, `mut` | не нужна: владение не переходит |
| якорь `anchor S.Item` | не выдаётся: ошибка при любой строке |

Строка `lend` называет область так же, как тип выданного слота: структура и её поле-область. `lend Block.data`
относится к слотам типа `own Block.data.Item` и `own block.data.Item`, выданным по одному или диапазоном. На одно
множество и на одну область строка одна.

Множество, которое строка не называет, наружу владением не уходит. Его элементы внешний код читает и правит через
структуру, которая ими владеет (`Vertices` через `Graph`), или через указатель множества «по функциям»
([три способа](#время-жизни-по-полю-и-по-функциям)). Граф, который живёт дольше одного вызова, описывается
структурой с цепочкой якорей, как `Graph` выше: наружу уходит значение `Graph`, соседи — указатели внутри той же
структуры, и строка для `Vertices` не нужна.

**Видимость строки.** Видимость строки — самая широкая видимость функций, которым она разрешает отдавать и
принимать владение. `public own S` покрывает функции `public` и `internal`; `internal own S` покрывает только
`internal`, и функция `public`, которая отдаёт `own S.Item`, при ней — ошибка. Строка шире модификатора блока: у
блока `layout` (пакет) имеет смысл только `public`, у `private layout` — `internal` и `public`. Строка не шире
блока — ошибка: ей нечего разрешать. Строка `public` подчиняется общему правилу видимости: она стоит в модуле
`public module`, и структура множества (`Node`) тоже `public` ([видимость](../visibility.md)). Слова видимости у
строки по умолчанию нет: строка без него — ошибка.

**Проверка функций.** FLOW проверяет каждую функцию кода блока, видимую внешнему коду, по её сводке, а не по
словам в сигнатуре:

1. Позиции. Владение элементом или слотом ищется в типе каждой позиции: параметр, параметр `out`, результат, и
   внутри опционала, кортежа, варианта, аргумента обобщённого типа (`-> Vector<own Nodes.Item>`) и типа функции
   (`-> () -> own Nodes.Item?`). Позиция с `own S.Item` требует строки `own S`, позиция со слотом — строки `lend`
   его области; видимость строки не уже видимости функции. Ошибка ставится у позиции и называет недостающую
   строку.
2. Якорь. `anchor S.Item` в любой позиции такой функции — ошибка. `own` — якорь без указателей, поэтому код блока
   кладёт принятый `own S.Item` в поле `anchor` без отдельного шага; обратно, к выдаче, ведёт только
   [`as own`](#переход-к-владению-as-own).
3. Уничтожение. Элемент, которым владеет внешний код, уничтожает только функция, принявшая его как `own S.Item`.
   Пометка «уничтожает» через параметр `mut` относится к элементам под полями структуры этого параметра
   (`clear(queue: mut Queue)`): до элемента в чужих руках от неё не дойти, потому что на `own` никто не смотрит.
4. Обратный путь. У строки `видимость own S` есть функция той же видимости, сводка которой принимает `own S.Item` и
   уничтожает его или оставляет в структуре (`freeNode`, `push`). У строки `видимость lend Block.data` есть функция
   той же видимости, которая возвращает слот в его область (`giveBack`). Строка без такой функции — ошибка у
   строки: внешний код получил бы владение, от которого не может избавиться.
5. Лишняя строка. Строка, по которой ни одна функция ничего не отдаёт, — ошибка: объявленная схема совпадает с
   тем, что делает код.
6. Значение структуры. У структуры блока с владеющим полем, видимой внешнему коду, есть функция той же видимости,
   которая оставляет все её владеющие поля `null` ([уничтожение структуры](#пространство-layout)). Структура без
   такой функции — ошибка у объявления структуры, а не в каждой точке, где внешний код выходит из области.
7. Обобщённый код. Блок `layout<T>` о своём `T` ничего не объявляет: `-> own T?` у `Vector<T>` отдаёт значение
   `T`, а не элемент своего множества. Тип с аргументом `own S.Item` (`Vector<own Nodes.Item>`) проверяется там,
   где он написан: назвать его может код блока `S` и внешний код, которому видна строка `own S`. Тот же предел
   действует на любую запись типа `own S.Item` и типа слота во внешнем коде.

Функции `private` и функции, не видимые внешнему коду, строкам не подчиняются: их сводки передаются наверх, и
проверяется функция, через которую владение выходит.

**Держатели у внешнего кода.** Элемент `own S.Item` и выданный слот внешний код держит в локальной переменной,
параметре и результате. Неявно они не уничтожаются: на каждом выходе, обычном и через исключение, значение
возвращено функции блока или передано дальше ([локальный владелец](#время-жизни-по-полю-и-по-функциям)). Дольше
одного вызова значение лежит в структуре `layout`: в обобщённом контейнере (`Vector<own Nodes.Item>`,
`SinglyList<own Nodes.Item>`), который стоит в локальной переменной или в поле класса; деструктор класса вынимает
элементы и возвращает каждый функции блока. Поле `own S.Item` в классе или в обычной структуре — ошибка
([указатели вне `layout`](#указатели-вне-layout)). Сохраняемое замыкание `own S.Item` не захватывает: уничтожить
его неявно нельзя. Приведения элемента (`as Pointer`, `as own`, смена вида) во внешнем коде — ошибка: память
возвращает функция блока, и перед возвратом она доказывает, что владеющие поля элемента пусты.

**Печать схемы.** По запросу компилятор печатает схему каждого блока пакета — вместе с точками доверия в
`efen proofs` и в документации пакета. Схема выводится из объявлений и сводок; расхождение со строками — ошибка
компиляции, поэтому напечатанное всегда совпадает с кодом.

```
private layout, модуль queue

Nodes       по полю, с выдачей: Queue.head, Node.next (own)
            public own: отдают newNode, pop; принимают push, freeNode
Blocks      по полю: Pool.busy, Block.next (anchor); наружу не уходит
Block.data  public lend: выдаёт acquire; возвращает giveBack
Vertices    по полю: Graph.first, Vertex.nextAll (anchor); наружу не уходит

Queue       значение; освобождает release(queue:); чистая
Pool        значение; освобождает release(pool:); чистая
Graph       значение; освобождает release(graph:); чистая
```

**Переход между потоками по схеме.** Схема показывает всё, что блок отдаёт, и для каждой структуры — чиста ли она
([определение 5](#структура-источник-чистота)). Из неё читается, что внешний код может передать в другой поток
([переход между потоками](#переход-между-потоками)): значение чистой структуры и элемент `own S.Item` уходят целиком,
владением; выданный слот уходит отдельно от родителя; структура, помеченная «нечистая: называет `X`», при
переходе оставляет доступы в области множества `X`. Новых правил здесь нет: печать собирает в одной таблице то,
что иначе выводится из объявлений по всему блоку.

**Схема — часть интерфейса пакета.** Строки `public` и напечатанные функции выдачи и возврата входят в публичный
интерфейс. Убрать строку, сузить её видимость или убрать последнюю функцию обратного пути — несовместимое
изменение; добавить строку — совместимое.
