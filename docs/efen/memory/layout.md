# Layout: руководство

[Память](README.md) · [Справочник правил](layout-reference.md) · [Таблица правил](memory-rules.md) ·
[Примеры](layout-examples/README.md) · [Каталог структур](layout-catalogue.md)

`layout` описывает память структуры данных со связями между узлами: списка, дерева, пула. По этому описанию
компилятор доказывает два свойства. Ни один указатель не используется после уничтожения своей цели. Вся взятая
память возвращена. Руководство рассчитано на программиста, знакомого с Rust или C++. Полные правила собраны в
[справочнике](layout-reference.md), и каждое утверждение руководства взято оттуда.

Статус: руководство описывает модель целиком. Что из неё сегодня проверяет Amber, перечислено в разделе
справочника [«Состояние в компиляторе»](layout-reference.md#состояние-в-компиляторе). Примеры показывают проект
синтаксиса: существующим компилятором они не компилировались.

## Зачем нужен `layout`

В структуре со связями на один узел указывает несколько указателей. Когда узел освобождён, остальные указатели на
него становятся висячими. В двусвязном списке на каждый узел указывают `next` предыдущего узла и `prev` следующего:

```c
struct Node { struct Node *next, *prev; int value; };

void remove_first(struct List *list) {
    struct Node *first = list->head;
    list->head = first->next;
    free(first);                  // list->head->prev по-прежнему хранит адрес first
}
```

Компилятор C эту функцию принимает: он не знает, что `prev` связан с `next`. В безопасном Rust такая связь не
выражается, потому что у узла один владелец. Второй указатель на узел там пишут двумя способами.
`Rc<RefCell<Node>>` добавляет счётчик и проверку при выполнении. Сырой указатель в `unsafe` оставляет
доказательство программисту.

В Efen программист объявляет связь. Он пишет, что `next` владеет узлом, а `prev` только указывает на него. Он
пишет и условие, верное для каждого узла: `next!.prev == self`. Из этой записи компилятор знает, где хранится
каждый указатель на узел. Функцию удаления он принимает, только если до освобождения узла она переписала все эти
указатели. Счётчик, проверка при выполнении и `unsafe` не нужны.

## Идея

`layout` объявляет схему памяти структуры данных. Схема говорит, кто чем владеет, кто на что может указывать и
что отдаётся внешнему коду. Всё, чего схема не объявила, запрещено. Например, узлы разных структур не указывают
друг на друга. Остальное компилятор доказывает сам по схеме и по телам функций: время жизни каждого указателя,
отсутствие висячих указателей, возврат всей взятой памяти.

По общему правилу языка поля не делят память ([владение](../types/ownership.md#поля-не-делят-память)). Есть два
способа сказать, что два поля указывают на одну память: `layout` и право с источником,
`право<поле или параметр>`. Руководство описывает первый.

## Первый пример: односвязный список

Список хранит значения типа `T` в узлах, и каждый узел владеет следующим. Пример состоит из четырёх частей:
объявление, вставка, снятие первого узла с обходом, освобождение.

### Объявление

```efen
private layout<T: Movable> {
    set Nodes: Node

    struct Node {
        var value: T
        var next: anchor Nodes.Item? = null
    }

    public struct List {
        private var head: anchor Nodes.Item? = null
        public  var count: Int = 0 { value >= 0 }

        invariants {
            let nodes = Nodes.chain(from: head, by: Node.next, until: null)
            count == nodes.count
        }
    }
}
```

- `private layout<T: Movable>`. `layout` стоит на уровне модуля. Модификатор говорит, какому коду разрешено писать
  поля его структур. У `private layout` это функции модуля, у `layout` без модификатора это функции пакета.
  Остальной код читает поля и вызывает функции. Параметр `T` объявлен у `layout` и действует на все его объявления.
  Снаружи `layout` имена пишутся с аргументом: `List<Int>`, `Nodes<T>.Item`.
- `set Nodes: Node` объявляет множество: все узлы формы `Node`. Указатель на узел имеет тип `Nodes.Item`.
- `var next: anchor Nodes.Item?` объявляет владеющее поле: узел уничтожает следующий за ним. Слово `anchor`
  разрешает другим указателям указывать на тот же узел ([подробнее](#own-и-якорь-anchor)).
- `public struct List` объявляет тип, которым пользуется программа. Поле `head` владеет первым узлом, поэтому
  список владеет всей цепочкой.
- `{ value >= 0 }` после поля задаёт условие на значение этого поля.
- `invariants { … }` содержит инварианты: правила, которые программист задаёт, а компилятор проверяет
  ([подробнее](#инвариант)). Выражение `Nodes.chain(from: head, by: Node.next, until: null)` даёт узлы, достижимые от
  `head` по полю `next` до `null`. Инвариант `count == nodes.count` связывает счётчик с длиной цепочки. Компилятор
  доказывает его на выходе каждой публичной функции списка.

### Вставка в начало

```efen
private fn newNode<T>(value: own T) -> anchor Nodes<T>.Item {
    return mm.allocate(…) as Node<T>(value: take value)
}

strategy<T> for List<T> {
    public edit fn pushFirst(value: own T) {
        let node = newNode(take value)
        node.next = tie head
        head = tie node
        count += 1
    }
}
```

- Операции «создать узел» в языке нет. `mm.allocate(…)` возвращает сырую память `own Pointer`. Приведение
  `as Node<T>(…)` делает из неё узел: записывает `value`, а полю `next` даёт значение по умолчанию `null`. Имя `mm`
  обозначает внешний менеджер памяти ([аллокатор](allocator.md)).
- `private fn newNode` служит помощником модуля. Результат `anchor` значит, что узлом теперь владеет вызывающая
  функция: она привязывает узел в структуру или освобождает его.
- `strategy<T> for List<T>` даёт списку методы. `edit fn` в стратегии равносильна функции с параметром
  `self: edit List<T>`.
- `node.next = tie head`. `tie` передаёт владение из одного поля в другое: `head` становится `null`, а прежним
  первым узлом владеет `node.next`. Указатели на этот узел остаются верными, потому что изменился только его
  владелец.
- `head = tie node`. Владеющее поле записывается, только когда доказано, что оно равно `null`. После предыдущей
  строки это так.
- `count += 1` восстанавливает инвариант. Между `tie head` и `count += 1` он нарушен. Это допустимо:
  проверка идёт на выходе.
- Слово `edit` обещает, что ни один существующий узел не перенесён и не уничтожен. К выходу каждый прежний узел
  находится в том же списке по тому же адресу. Поэтому указатели и ссылки вызывающего на узлы после `pushFirst`
  действительны.
- `newNode` вызывается до `tie head`, потому что `mm.allocate` бросает `AllocationError`. Функция `edit` между `tie`
  из структуры и `tie` обратно не вызывает ничего, что может бросить исключение.

### Снятие первого узла и обход

```efen
strategy<T> for List<T> {
    public mut fn popFirst -> own T? {
        guard let node = tie head else { return null }
        head = tie node.next
        count -= 1
        let value = take node.value
        mm.free(node as own Pointer)
        return value
    }
}

strategy<T: Copyable> for List<T> {
    public fn read(index: Int) -> T
        requires index >= 0 && index < count
    {
        var current = head!
        var position = 0
        while position < index {
            current = current.next!
            position += 1
        }
        return copy current.value
    }
}
```

- `guard let node = tie head`. Первым узлом теперь владеет локальная переменная `node`. Такой узел неявно не
  уничтожается: до каждого выхода функция привязывает его в структуру, возвращает или освобождает.
- `head = tie node.next`. Остатком цепочки снова владеет `head`, а владеющее поле узла `node` равно `null`.
- `let value = take node.value`. Значение `T` забрано из узла. После этого узел можно только освободить.
- `mm.free(node as own Pointer)`. Память, на которую могут указывать указатели, освобождается только после перехода
  к `own`. В строке приведения `as own` компилятор проверяет по объявлениям `layout` два условия: указателей на узел не
  осталось, его владеющие поля пусты. Приведение без такого доказательства компилятор отвергает.
- Слово `mut` обязательно, потому что узел ушёл из списка в уничтожение. В строке вызова у вызывающего становятся
  недействительными указатели и ссылки с источником в этом списке, которые могут указывать на снятый узел.
- `read` ничего не меняет, поэтому слова права у неё нет. Переменная `current` хранит невладеющий указатель: через
  него поля узла читаются, но не записываются. Функция возвращает копию, поэтому стратегия с ограничением
  `T: Copyable` даёт `read` только спискам копируемых значений. Копия написана словом `copy`: тихой копии у типа
  `Copyable` нет.

### Освобождение

```efen
strategy<T> for List<T> {
    public mut fn release
        requires T conforms ImplicitlyDestroyable || count == 0
    {
        while let node = tie head {
            head = tie node.next
            let dead = take node.value
            mm.free(node as own Pointer)
        }
        count = 0
    }
}

var list = List<Int>()
defer list.release()
list.pushFirst(1)
list.pushFirst(0)
let second = list.read(1)
```

- У структуры из `layout` нет деструктора. Память возвращает явный код: публичная функция, после которой все владеющие
  поля равны `null`.
- `requires T conforms ImplicitlyDestroyable || count == 0`. Функция сама уничтожает значения `T`, поэтому требует,
  чтобы их можно было уничтожить неявно ([деструкторы](../disposable.md)). Для остальных `T` список отдаёт значения
  вызывающему, как `popFirst`, и `release` вызывается у пустого списка: условие `count == 0` разрешает такой вызов
  при любом `T`.
- `defer list.release()` стоит сразу после создания. Выход из области со списком, у которого `head` может быть не
  `null`, компилятор отвергает. Выход через исключение тоже считается выходом. `defer` вызывает `release` на каждом
  пути.

## Понятия

Права в сигнатурах ниже пишутся с источником: `read<list> Nodes.Item` значит «указатель на узел из списка
`list`, только чтение». Все формы записи `право<путь>` с примерами собраны в статье
[об областях доступа](../types/access-regions.md#источник-право-и-время-действия).

### Множество и область

Множество и область говорят компилятору, как расположены в памяти элементы одной формы. Множество `set X: T`
объединяет экземпляры, которые не обязаны идти подряд: узлы списка, дерева, графа. Область `area X: T` состоит из
непрерывных слотов одной формы с доступом по индексу `0 ..< count`.

```efen
private layout<T: Movable> {
    area Items: T

    public struct Vector {
        private var items: own Items.Area? = null { value == null || value.count == capacity }
        private var capacity: Int = 0 { value >= 0 }
        public  var count: Int = 0 { value >= 0 && value <= capacity }
    }
}
```

Множество одно на программу: `set Nodes: Node` включает все узлы этой формы, сколько бы списков ими ни
пользовалось. Своей памяти у множества нет. Оно задаёт тип указателя (`Nodes.Item`), а принадлежность узла списку
видна из владения. Число слотов области задаёт её владелец (`value.count == capacity`). Какие слоты заняты, говорит
инвариант владельца. Есть ещё два объявления: `set area X: T` объявляет множество независимых областей (участки
менеджера памяти), `one X` объявляет один экземпляр на программу
([множества и области](layout-reference.md#множества-и-области)).

Слоты области обычно одного размера. Область, структура слота которой задаёт свой размер собственным инвариантом
(`text.count == length`), состоит из слотов разного размера. Номером слота в ней служит смещение его начала в
байтах, а компилятор доказывает, что слоты занимают область без промежутков
([область с разным шагом](layout-reference.md#область-с-разным-шагом)).

### Структура из `layout`

Программа пользуется коллекцией через именованную структуру из `layout`: `List`, `Vector`.

```efen
var list = List<Int>()            // поля получили значения по умолчанию: head == null, count == 0
defer list.release()              // память возвращает явный вызов
list.pushFirst(1)
```

Структура хранится по значению: в локальной переменной, параметре или поле. Своих методов, инициализатора и деструктора
у неё нет. Методы даёт стратегия того же модуля или пакета, память возвращает явный вызов. Класс с полем такой структуры
освобождает её в своём деструкторе. Класс без деструктора с таким полем компилятор отвергает
([деструкторы](../disposable.md)).

### `own` и якорь `anchor`

Владение бывает двух видов. `own` означает исключительное владение: владеющая ссылка единственная, других
указателей на значение нет. Якорь `anchor` означает неисключительное владение: поле отвечает за уничтожение
значения, а на само значение указывают хранимые указатели.

```efen
struct Job  { var next: own Jobs.Item? = null }          // других указателей на задание нет
struct Node {
    var left: anchor Nodes.Item? = null                   // на узел указывает parent его детей
    var parent: Nodes.Item? = null
}

let job = take queue.head                                 // own переносится через take
guard let top = tie tree.root else { return }             // якорь переносится через tie
```

Владелец у значения один. Два поля `anchor` на одно значение запрещены, как и `anchor` вместе с `own`. Значение
`own` переносит `take`: указателей на него нет, и переписывать нечего. Якорь переносит `tie`. В каждый момент якорь
у значения один, а указатели на значение при переносе внутри одной структуры остаются верными. `take` слота под
якорем запрещён. Значение `own` записывается в поле `anchor` через `tie` без отдельного шага, потому что на него ещё
никто не указывает. Обратный переход, от якоря к `own`, делает только приведение `as own`. К этой строке код уже
переписал все указатели на значение ([якорь](layout-reference.md#якорь-anchor)).

### Невладеющий указатель

Невладеющим указателем называется поле типа `S.Item` без слова владения. Оно хранит адрес элемента, которым владеет
другое поле.

```efen
public struct Queue {
    private var head: anchor Nodes.Item? = null
    private var tail: Nodes.Item? = null                  // указатель на последний узел
}
```

Цель хранимого указателя существует на каждом выходе публичной функции. Для этого функция, которая уничтожает узел,
сначала переписывает каждый указатель на него. Хранимый указатель указывает только внутрь своей публичной
структуры, то есть той, владелец которой находится вне значения `layout`: `tail` одной очереди не указывает на узел
другой, а вершина графа указывает только на вершины того же графа
([структура, источник, чистота](layout-reference.md#структура-источник-чистота)). Множество, у которого нет ни
владеющего поля, ни строки `public own`, вызывает ошибку
([способы владения](layout-reference.md#владелец-множества)).

Указатель в локальной переменной (`let node = list.head`) помнит источник, то есть структуру, из которой он
прочитан. Он становится недействительным, когда эта структура теряет узел, на который он может указывать.

### Инвариант

Инвариантом называется формальное правило, которое программист даёт компилятору, чтобы тот проверял: код соблюдает
алгоритм работы с памятью. Он записывается строкой в `invariants`. Инвариант утверждает нечто о полях структуры и верен
всякий раз, когда структуру видит чужой код.

```efen
struct Node {
    var next: anchor Nodes.Item? = null
    var prev: Nodes.Item? = null

    invariants { next == null || next!.prev == self }
}
```

На входе публичной функции структуры компилятор считает инварианты верными. Доказывает он их в пяти местах: на
выходе публичной функции, перед `throw`, перед приостановкой, перед вызовом кода, способного обратиться к структуре,
и при записи значения структуры в поле другого значения или публикации указателя на неё. Между этими местами
инвариант можно нарушить. Вспомогательная функция `private` получает структуру, инвариант которой может быть
нарушен ([места, где инвариант верен](layout-reference.md#инварианты)).

Инвариант решает две задачи. Первая: он связывает значения полей, например `count == nodes.count`. Вторая: он
говорит компилятору, где хранятся указатели. По `next!.prev == self` компилятор знает, что `prev` узла указывает на
владельца этого узла. Поэтому при удалении узла он проверяет только двух соседей и не обходит весь список. Функция,
которая пишет `prev` и не знает, кто владеет узлом, доказать инвариант не может. Компилятор её отвергает
([инварианты и цепочки](layout-reference.md#инварианты)).

### `edit` и `mut`

`edit` и `mut` сообщают вызывающему, какие его указатели останутся верными после вызова. Оба слова дают право
записи. `edit` гарантирует, что ни один существующий элемент или слот не перенесён и не уничтожен. `mut` этой
гарантии не даёт. Право определяется по итогу функции, а не по отдельным строкам.

| Операция | Право | Указатели и ссылки вызывающего |
|---|---|---|
| запись поля-значения, запись невладеющего указателя | `edit` | действительны |
| новый элемент в пустое владеющее поле | `edit` | действительны |
| `tie`, после которого элемент снова находится в той же структуре | `edit` | действительны |
| `tie`, после которого элемент ушёл: в результат, в другую структуру, в уничтожение | `mut` | на ушедший элемент и всё под ним недействительны |
| `take` значения `own` из поля, `take` элемента области | `mut` | в прежнее содержимое недействительны |
| перевыделение или замена области | `mut` | внутрь прежней области недействительны |

```efen
let node = list.first()
list.insertFirst(value: 7)          // edit: узлы на своих адресах, node действителен
print(node.value)
```

Слово права работает как контракт перед вызывающим. После вызова `edit` его указатели верны. После вызова `mut`
нельзя использовать те из них, что могут указывать на изменённое. Вставка в список требует `edit`. `append` вектора
требует `mut`, потому что худший путь перевыделяет область. Полная таблица операций приведена в разделе справочника
[«`edit` и `mut` в `layout`»](layout-reference.md#edit-и-mut-в-layout).

### Публичная функция структуры и помощник

Публичной функцией структуры называется функция без `private`, которая пишет поля `layout`. Инварианты верны на её входе
и выходе. Функция `private` служит помощником. Помощник может получить и вернуть структуру в промежуточном состоянии,
когда инвариант ещё не восстановлен.

```efen
private fn unlinkFirst<T>(list: mut List<T>) -> anchor Nodes<T>.Item? {
    guard let first = tie list.head else { return null }
    list.head = tie first.next
    return first                      // count ещё не уменьшен: инвариант не восстановлен
}
```

Что помощник сделал со структурой и её инвариантом, компилятор выводит из тела помощника. Здесь вывод такой: «узел ушёл
из `list` в результат». Публичная функция, которая вызывает `unlinkFirst`, уменьшает `count` и освобождает узел. Её
слово права компилятор проверяет по выводам обо всех помощниках, которых она вызывает. Функции стоят в модуле рядом
с `layout`, а не внутри него: `layout` содержит только описание памяти.

### Инициализация после `as` и `_`

Приведение `as` делает из сырой памяти элемент. Инициализация при нём явная. Приведение с аргументами работает как
вызов `Item(…)`: записывает названные поля, а полю со значением по умолчанию даёт это значение.

```efen
let a = memory as Item(value: 0, next: NONE)    // все поля записаны в приведении
let b = memory as Item(value: _, next: NONE)    // value: прежние байты, явно
let c = memory as Item                          // value и next не инициализированы
c.value = 0                                     // запись инициализирует поле
```

Поле не инициализировано, если у него нет значения по умолчанию и оно не записано ни в приведении, ни после него.
Чтение такого поля компилятор отвергает. `null` считается значением, поэтому поле со значением `null`
инициализировано. Инициализатор `_` пишется только явно, для поля, байты которого программе не важны. На числовом
поле он оставляет прежние байты, на опциональном записывает `null`. На неопциональном указателе, поле `own` или
`anchor`, логическом поле, варианте и поле типа `T` он запрещён
([виды и приведение](layout-reference.md#виды-и-приведение-as)).

## Второй пример: двусвязный список

В двусвязном списке каждый узел хранит указатель `prev` на предыдущий. Владение остаётся цепочкой якорей по `next`.
`prev` и `tail` объявлены невладеющими указателями, и их значения задают инварианты.

```efen
private layout<T: Movable> {
    set Nodes: Node

    struct Node {
        var value: T
        var next: anchor Nodes.Item? = null
        var prev: Nodes.Item? = null

        invariants { next == null || next!.prev == self }
    }

    public struct DoublyList {
        private var head: anchor Nodes.Item? = null
        private var tail: Nodes.Item? = null
        public  var count: Int = 0 { value >= 0 }

        invariants {
            let nodes = Nodes.chain(from: head, by: Node.next, until: null)
            count == nodes.count
            head == null || head!.prev == null
            (head == null) == (tail == null)
            tail == null || tail!.next == null
        }
    }
}
```

Инвариант об обратном указателе написан у каждого владеющего поля: `next!.prev == self` у `Node.next` и
`head!.prev == null` у `DoublyList.head`. Поэтому `prev`, равный узлу, хранит только тот узел, которым владеет его
`next`. Цикла владения нет: якоря идут только вперёд.

### Вставка в конец

```efen
strategy<T> for DoublyList<T> {
    public edit fn append(value: own T) {
        let node = newNode(take value)
        if let last = tail {
            node.prev = last
            last.next = tie node
        } else {
            head = tie node
        }
        tail = node
        count += 1
    }
}
```

Строка `node.prev = last` стоит раньше, чем `last.next = tie node`, но инварианту порядок строк безразличен. Инвариант
`last.next!.prev == last` проверяется на выходе, а к выходу обе записи сделаны. Строка `tail = node` после
`tie node` допустима: `tie` передал владение, а имя `node` осталось невладеющим указателем на тот же узел, и его
источником служит список, в который узел записан
([перенос владения](layout-reference.md#64-перенос-владения), правило 1). Функции
достаточно `edit`: новый узел записан в пустое владеющее поле, прежние узлы остались на своих адресах.

### Удаление узла

```efen
private fn unlinkAt<T>(list: mut DoublyList<T>, index: Int) -> anchor Nodes<T>.Item? {
    if index == 0 {
        guard let first = tie list.head else { return null }
        list.head = tie first.next
        if let newHead = list.head {
            newHead.prev = null
        } else {
            list.tail = null
        }
        list.count -= 1
        return first
    }

    let before = nodeAtMut(list, index: index - 1)
    guard let victim = tie before.next else { return null }
    before.next = tie victim.next
    if let after = before.next {
        after.prev = before
    } else {
        list.tail = before
    }
    victim.prev = null
    list.count -= 1
    return victim
}

strategy<T> for DoublyList<T> {
    public mut fn remove(index: Int) -> own T? {
        guard index >= 0 && index < count else { return null }
        guard let node = unlinkAt(self, index: index) else { return null }
        let value = take node.value
        mm.free(node as own Pointer)
        return value
    }
}
```

`nodeAtMut` служит помощником модуля: проходит по `next` от `head` и возвращает `mut Nodes<T>.Item`. Указатель
получает право значения, через которое он получен, поэтому `before` несёт `mut` списка-параметра. С указателем
`edit` строка `tie before.next` была бы ошибкой: после неё узел уходит из списка.

Вторая ветка `unlinkAt` по строкам:

1. `guard let victim = tie before.next`. Узлом владеет локальная переменная, `before.next` пуст.
2. `before.next = tie victim.next`. Остатком цепочки владеет `before`; владеющее поле `victim` теперь `null`.
3. `after.prev = before`. Инвариант `before.next!.prev == before` восстановлен. До этой строки `after.prev` хранил адрес
   `victim`.
4. `list.tail = before` выполняется, когда `victim` был последним: `tail` хранил его адрес.
5. `victim.prev = null`. Узел уходит из списка, и указателя из него обратно в список не остаётся.

### Почему компилятор это принимает

Компилятор проверяет приведение `node as own Pointer` в `remove`: к этой строке ни один хранимый указатель не
указывает на узел. Искать по всей памяти ему не нужно, потому что схема называет все поля, где такой указатель
может храниться.

- Владеющий указатель один, это якорь. Он перешёл в `victim`, затем в результат `unlinkAt`, затем в `node`.
- `prev`, равный узлу, по инварианту `next!.prev == self` хранит только тот узел, которым владеет его `next`. Это
  `after`, и строка 3 его переписала.
- `tail` принадлежит самому списку. Строка 4 переписала его в единственном случае, когда он мог быть равен узлу.
- Владеющее поле самого узла пусто после строки 2, значение `T` забрано строкой `take node.value`.

Без строки 3 инвариант `before.next!.prev == before` не доказывается на выходе `remove`. Не доказывается и `as own`:
`after.prev` остаётся указателем на освобождаемый узел. Ошибка та же, что в функции на C из первого раздела, но
здесь её находит компилятор.

Для вызывающего `remove` требует `mut`. Его указатели и ссылки с источником в этом списке, которые могут указывать
на удалённый узел, недействительны со строки вызова. Источник не различает узлы внутри одного списка, поэтому
недействителен каждый указатель, который может быть равен удалённому.

## Что уходит наружу

Внешним называется код, которому `layout` не разрешает писать поля. Память `layout` он получает пятью
способами. Два из них `layout` объявляет строкой [схемы владения](layout-reference.md#схема-владения).

| Что получает внешний код | Запись | Строка в `layout` |
|---|---|---|
| значение структуры (`List<Int>`, `Graph`) | тип структуры | не нужна |
| элемент целиком | `own S.Item` | `public own S` |
| слот области | `own Block.data.Item` | `public lend Block.data` |
| заимствование | `-> read T?`, `-> edit<list> T?` | не нужна |
| указатель без права записи | `S.Item` | не нужна |

### Значение структуры

Значение структуры ведёт себя как обычное значение: его хранят в переменной, передают параметром `own`, записывают
в поле класса. Вместе со значением переходят все элементы, которыми оно владеет. Структура с владеющим полем,
видимая внешнему коду, имеет функцию той же видимости, которая оставляет все владеющие поля равными `null`. Без
такой функции компилятор отвергает объявление структуры.

### Элемент целиком: `public own S`

```efen
private layout {
    set Nodes: Node

    public own Nodes

    public struct Node  { var next: own Nodes.Item? = null; public var value: Int }
    public struct Queue { var head: own Nodes.Item? = null }
}

public fn newNode(value: Int) -> own Nodes.Item { … }
public fn push(queue: edit Queue, node: own Nodes.Item) { … }
public fn pop(queue: mut Queue) -> own Nodes.Item? { … }
public fn freeNode(node: own Nodes.Item) { … }
```

Строка `public own Nodes` разрешает публичным функциям отдавать и принимать `own Nodes.Item`. Без неё
`own Nodes.Item` в сигнатуре функции, видимой внешнему коду, даёт ошибку в этой позиции. Строка требует обратного
пути: функции той же видимости, которая принимает элемент и уничтожает его или оставляет в структуре (`freeNode`,
`push`).

Внешний код хранит элемент в локальной переменной, параметре и результате. На каждом выходе он возвращает элемент
функции из модуля `layout` или передаёт дальше. Поле `own Nodes.Item` в классе или обычной структуре запрещено.
Дольше одного вызова элемент хранится в контейнере `layout`, например в `Vector<own Nodes.Item>`.

### Выданный слот: `public lend T.поле`

```efen
layout {
    set area Blocks: Block

    public lend Block.data

    struct Block {
        var next: anchor Blocks.Item? = null     // поля участка остаются у layout
        var prev: Blocks.Item? = null
        var used: Int = 0                        // число выданных слотов
        area data: Byte                          // память для внешнего кода
    }

    public struct Pool {
        var busy: anchor Blocks.Item? = null     // участки с выданным слотом
        var free: anchor Blocks.Item? = null     // участки без выданных слотов
    }
}

public fn acquire(pool: mut Pool) -> own Block.data.Item? { … }
public fn release(pool: mut Pool, data: own Block.data.Item) {
    let block = blockOf(pool, data)              // участок пула pool, из которого выдан data
    let n = block.data.count
    block.data[0 ..< n] = take data              // диапазон вернулся туда, откуда выдан
    block.used -= n
    let cut = unlinkBusy(pool, block)            // участок вырезан из Pool.busy
    linkFree(pool, tie cut)                      // и привязан к Pool.free
}
```

Участками владеет `Pool`: строка `public lend` относится к слотам области `data` и владельцем множества `Blocks` не
служит.

`lend block.data[0 ..< n]` выдаёт диапазон слотов области. Получатель владеет байтами диапазона, а поля участка
(`next`) остаются у `layout` и занимают другие байты. Тип слота называет область, из которой он выдан, поэтому
вернуть его можно только в свой слот. Внешний код не приводит его к `Pointer` и не отдаёт менеджеру памяти. Пока
слот выдан, участок нельзя вернуть или освободить. Выдача и возврат требуют `mut` на участок.

### Заимствование с источником

```efen
strategy<T> for List<T> {
    public fn first -> read T? {
        guard let node = head else { return null }
        return &read node.value
    }
}

fn firstOf<T>(list: List<T>) -> read<list> T? { … }
```

Заимствование даёт доступ к памяти, которой `layout` продолжает пользоваться; владение не переходит. Источник
записан в результате. В методе источником служит `self`, и он не пишется (`-> read T?`). В свободной функции
источник стоит в угловых скобках (`-> read<list> T?`).

Заимствование действует, пока источник не изменил структуру. Вызов `edit` его не затрагивает. Использовать его
после вызова, который освобождает или уводит узлы, нельзя
([что делает ссылку недействительной](memory-rules.md#что-делает-ссылку-недействительной)). Форма с `&`,
`-> read<&doc.title> T`, обещает ссылку ровно на слот по пути, и путь в ней не проходит через указатель `layout`
([ссылка ровно на слот](../types/ownership.md#ссылка-ровно-на-слот)). Дольше одного вызова указатель на элемент вне
`layout` хранит только значение, которое заимствует: структура с параметром источника (курсор) или коллекция с
источником в типе элемента (`Vector<read<g> Vertices.Item>`, путь по графу)
([указатели вне `layout`](layout-reference.md#указатели-вне-layout)).

### Якорь наружу не уходит

`anchor S.Item` в сигнатуре функции, видимой внешнему коду, запрещён при любой схеме владения. Якорь означает, что на
элемент указывают хранимые указатели, и перед уничтожением элемента каждый из них нужно переписать. Хранятся они в
полях `layout`, а писать эти поля внешний код не может. Поэтому якорь переходит только между функциями, которым
`layout` разрешает писать поля. Чтобы отдать элемент внешнему коду, такая функция сначала убирает
указатели на него и делает переход `as own`. Внешний код получает `own`, на который никто не указывает.

## Частые ошибки

Текст диагностики в первом примере взят из справочника
([диагностика времени жизни](layout-algorithm.md#диагностика-времени-жизни)). В остальных примерах комментарий
пересказывает правило, а точный текст задаёт реализация. Примеры 1, 3–7 показывают код модуля, в котором стоит
`layout`, пример 2 показывает внешний код.

**1. Указатель использован после освобождения узла.**

```efen
fn broken(list: mut List<Int>) {
    guard let node = list.head else { return }   // указатель с источником list
    let dropped = list.popFirst()                // освобождает первый узел
    print(node.value)                            // error[flow.slot-left]: указатель `node` использован после конца жизни узла
}
```

Если `node` после `popFirst` не используется, ошибки нет.

**2. Выход из области с неосвобождённым списком.**

```efen
fn build {
    var list = List<Int>()
    list.pushFirst(1)
}                                // ошибка: list выходит из области, а владеющее поле head может быть не null
```

Исправление: `defer list.release()` сразу после создания.

**3. Чтение поля до инициализации.**

```efen
let node = memory as Node<Int>   // next получил значение по умолчанию, value не записан
print(node.value)                // ошибка: value не инициализирован
```

**4. Указатель из одного списка записан в другой.**

```efen
fn share(a: edit DoublyList<Int>, b: DoublyList<Int>) {
    a.tail = b.head              // ошибка: хранимый указатель списка a указывает на узел списка b
}
```

Узел переходит между структурами только владением: `tie` из одной и `tie` в другую.

**5. Наружу отдано то, чего не называет ни одна строка.**

```efen
public fn popNode(list: mut List<Int>) -> own Nodes<Int>.Item? { … }      // ошибка: нет строки `public own Nodes`
public fn peekNode(list: mut List<Int>) -> anchor Nodes<Int>.Item? { … }  // ошибка: якорь внешнему коду не выдаётся
```

**6. Изменение структуры под `edit`.**

```efen
public edit fn dropFirst {       // ошибка: узел ушёл из списка в уничтожение, нужен mut
    guard let node = tie head else { return }
    head = tie node.next
    count -= 1
    let dead = take node.value
    mm.free(node as own Pointer)
}
```

**7. `take` якоря и запись в непустое владеющее поле.**

```efen
let first = take list.head       // ошибка: take слота под якорем; якорь переносит tie
list.head = tie node             // ошибка: поле head не доказано пустым, прежний первый узел потерял бы владельца
```
