# Layout: руководство

[Память](README.md) · [Справочник правил](layout-reference.md) · [Таблица правил](memory-rules.md) ·
[Примеры](layout-examples/README.md) · [Каталог структур](layout-catalogue.md)

`layout` — способ написать список, дерево или пул со связями между узлами так, чтобы компилятор доказал: ни один
указатель не используется после смерти своей цели и вся взятая память возвращена. Руководство читается сверху вниз
и рассчитано на программиста, знакомого с Rust или C++. Полные правила — в [справочнике](layout-reference.md);
каждое утверждение руководства взято оттуда.

Статус: руководство описывает модель целиком. Что из неё сегодня проверяет Amber, перечислено в разделе
справочника [«Состояние в компиляторе»](layout-reference.md#состояние-в-компиляторе). Примеры — проект синтаксиса,
существующим компилятором они не компилировались.

## Зачем нужен `layout`

Структура со связями хранит несколько указателей на один узел, и освобождение узла оставляет остальные указатели
висячими. В двусвязном списке на каждый узел смотрят `next` предыдущего и `prev` следующего:

```c
struct Node { struct Node *next, *prev; int value; };

void remove_first(struct List *list) {
    struct Node *first = list->head;
    list->head = first->next;
    free(first);                  // list->head->prev по-прежнему хранит адрес first
}
```

Компилятор C эту функцию принимает: о том, что `prev` связан с `next`, он не знает. Rust такую связь в безопасном
коде не выражает: у узла один владелец, и второй указатель на него пишется либо через `Rc<RefCell<Node>>` со
счётчиком и проверкой при выполнении, либо сырым указателем в `unsafe`, где доказательство остаётся за
программистом.

В Efen связь объявляется. Программист пишет, что `next` владеет узлом, `prev` только указывает на него и что для
каждого узла верно `next!.prev == self`. Из этой записи компилятор знает, где хранится каждый указатель на узел, и
функцию удаления принимает, только если до освобождения узла она переписала их все. Счётчика и проверки при
выполнении нет, `unsafe` нет.

## Идея

`layout` — объявленная схема памяти структуры данных: кто чем владеет, кто на что может указывать и что отдаётся
наружу. Всё, чего схема не объявила, запрещено: узлы разных структур друг на друга не указывают, и наружу уходит
только названное. Остальное компилятор доказывает сам по этой схеме и по телам функций: время жизни
каждого указателя, отсутствие висячих указателей, возврат каждого взятого куска памяти.

По общему правилу языка поля не делят память ([владение](../types/ownership.md#поля-не-делят-память)). Сказать,
что два поля смотрят в одну память, можно двумя способами: блоком `layout` и правом с источником,
`право<поле или параметр>`. Руководство описывает первый.

## Первый пример: односвязный список

Список хранит значения типа `T` в узлах; каждый узел владеет следующим. Пример собран из четырёх частей:
объявление, вставка, снятие первого узла и обход, освобождение.

### Объявление

```efen
private layout<T: Movable> {
    set Nodes: Node

    struct Node {
        var value: T
        var next: anchor Nodes.Item? = null
    }

    public struct List {
        private var head: anchor Nodes.Item? = null
        public  var count: Int = 0 { value >= 0 }

        invariants {
            let nodes = Nodes.chain(from: head, by: Node.next, until: null)
            count == nodes.count
        }
    }
}
```

- `private layout<T: Movable>`. Блок стоит на уровне модуля. Модификатор говорит, какому коду разрешено писать поля
  его структур: у `private layout` это функции модуля, у `layout` без модификатора — функции пакета. Остальной код
  поля читает и вызывает функции. Параметр `T` объявлен у блока и действует на все его объявления; снаружи блока
  имена пишутся с аргументом: `List<Int>`, `Nodes<T>.Item`.
- `set Nodes: Node` — множество: все узлы формы `Node`. Тип указателя на узел — `Nodes.Item`.
- `var next: anchor Nodes.Item?` — владеющее поле: узел уничтожает следующий за ним. Слово `anchor` разрешает
  другим указателям смотреть на тот же узел; подробно — [ниже](#own-и-якорь-anchor).
- `public struct List` — тип, которым пользуется программа. Поле `head` владеет первым узлом, значит, список
  владеет всей цепочкой.
- `{ value >= 0 }` после поля — условие на значение этого поля.
- `invariants { … }` — законы структуры. `Nodes.chain(from: head, by: Node.next, until: null)` — узлы, достижимые от
  `head` по полю `next` до `null`. Закон `count == nodes.count` связывает счётчик с длиной цепочки; компилятор
  доказывает его на выходе каждой публичной функции списка.

### Вставка в начало

```efen
private fn newNode<T>(value: own T) -> anchor Nodes<T>.Item {
    return mm.allocate(…) as Node<T>(value: take value)
}

strategy<T> for List<T> {
    public edit fn pushFirst(value: own T) {
        let node = newNode(take value)
        node.next = tie head
        head = tie node
        count += 1
    }
}
```

- Операции «создать узел» нет. `mm.allocate(…)` отдаёт сырую память `own Pointer`, приведение `as Node<T>(…)` делает
  из неё узел: записывает `value`, а `next` получает значение по умолчанию `null`. `mm` — внешний менеджер памяти
  ([аллокатор](allocator.md)).
- `private fn newNode` — помощник модуля. Результат `anchor` значит, что узлом теперь владеет вызывающая функция:
  она привязывает его в структуру или освобождает.
- `strategy<T> for List<T>` даёт списку методы. `edit fn` в стратегии — то же, что функция с параметром
  `self: edit List<T>`.
- `node.next = tie head`. `tie` передаёт владение из одного поля в другое: `head` становится `null`, прежний первый
  узел лежит под `node.next`. Указатели на этот узел остаются верными: изменилось только то, кто его уничтожит.
- `head = tie node`. Владеющее поле записывается, только когда оно доказанно `null`; после предыдущей строки это
  так.
- `count += 1` восстанавливает закон. Между `tie head` и `count += 1` закон нарушен, и это допустимо: закон
  проверяется на выходе.
- Слово `edit` обещает, что ни один существующий узел не перенесён и не уничтожен. К выходу каждый прежний узел
  лежит в том же списке по тому же адресу, поэтому указатели и ссылки вызывающего на узлы после `pushFirst` живы.
- `newNode` вызывается до `tie head`. `mm.allocate` бросает `AllocationError`, а функция `edit` между `tie` из
  структуры и `tie` обратно не вызывает ничего, что может бросить исключение.

### Снятие первого узла и обход

```efen
strategy<T> for List<T> {
    public mut fn popFirst -> own T? {
        guard let node = tie head else { return null }
        head = tie node.next
        count -= 1
        let value = take node.value
        mm.free(node as own Pointer)
        return value
    }
}

strategy<T: Copyable> for List<T> {
    public fn read(index: Int) -> T
        requires index >= 0 && index < count
    {
        var current = head!
        var position = 0
        while position < index {
            current = current.next!
            position += 1
        }
        return current.value
    }
}
```

- `guard let node = tie head`. Первый узел переходит под локальную переменную `node`. Узел под локальной переменной
  неявно не уничтожается: до каждого выхода функция привязывает его в структуру, возвращает или освобождает.
- `head = tie node.next`. Остаток цепочки возвращается под `head`; у `node` владеющее поле теперь `null`.
- `let value = take node.value`. Значение `T` забирается из узла; после этого узел можно только освободить.
- `mm.free(node as own Pointer)`. Освободить память, на которую могут смотреть указатели, можно только после
  перехода к `own`. В строке приведения `as own` компилятор проверяет по объявлениям блока, что указателей на узел
  не осталось и его владеющие поля пусты. Без доказательства приведение — ошибка.
- Слово `mut` обязательно: узел ушёл из списка в уничтожение. У вызывающего в строке вызова умирают указатели и
  ссылки с источником в этом списке, которые могут смотреть на снятый узел.
- `read` не меняет ничего, поэтому слова права у неё нет. `current` — невладеющий указатель: он читает поля узла, а
  записать через него нельзя. Стратегия с ограничением `T: Copyable` даёт `read` только спискам копируемых
  значений: функция возвращает копию.

### Освобождение

```efen
strategy<T> for List<T> {
    public mut fn release
        requires T conforms ImplicitlyDestroyable
    {
        while let node = tie head {
            head = tie node.next
            let dead = take node.value
            mm.free(node as own Pointer)
        }
        count = 0
    }
}

var list = List<Int>()
defer list.release()
list.pushFirst(1)
list.pushFirst(0)
let second = list.read(1)
```

- Деструктора у структуры из `layout` нет. Память возвращает явный код: публичная функция, после которой все владеющие
  поля равны `null`.
- `requires T conforms ImplicitlyDestroyable`: функция сама уничтожает значения `T`, поэтому требует, чтобы их можно
  было уничтожить неявно ([деструкторы](../disposable.md)). Для остальных `T` список отдаёт значения вызывающему, как
  `popFirst`.
- `defer list.release()` стоит сразу после создания. Выход из области со списком, у которого `head` может быть не
  `null`, — ошибка компиляции, и выход через исключение — тоже выход; `defer` даёт вызов `release` на каждом пути.

## Понятия

### Множество и область

Множество и область — два способа сказать, как лежат элементы одной формы. Множество `set X: T` — экземпляры без
обещания непрерывности: узлы списка, дерева, графа. Область `area X: T` — непрерывные слоты одной формы с доступом
по индексу `0 ..< count`.

```efen
private layout<T: Movable> {
    area Items: T

    public struct Vector {
        private var items: own Items.Area? = null { value == null || value.count == capacity }
        private var capacity: Int = 0 { value >= 0 }
        public  var count: Int = 0 { value >= 0 && value <= capacity }
    }
}
```

Множество одно на программу: `set Nodes: Node` — все узлы этой формы, сколько бы списков ими ни пользовалось. Своей
памяти у множества нет; оно задаёт тип указателя (`Nodes.Item`), а какому списку узел принадлежит, видно из
владения. Число слотов области называет её владелец (`value.count == capacity`); какие слоты заняты, говорит его
закон. Есть ещё два дескриптора: `set area X: T` — множество независимых областей (блоки менеджера памяти) и
`one X` — один экземпляр на программу ([множества и области](layout-reference.md#множества-и-области)).

### Структура `layout`

Тип коллекции, которым пользуется программа, — именованная структура блока: `List`, `Vector`.

```efen
var list = List<Int>()            // поля получили значения по умолчанию: head == null, count == 0
defer list.release()              // память возвращает явный вызов
list.pushFirst(1)
```

Структура хранится по значению: в локальной переменной, параметре или поле. Своих методов, инициализатора и
деструктора у неё нет: методы даёт стратегия того же модуля, а память возвращает явный вызов. Класс, который держит
такую структуру полем, освобождает её в своём деструкторе; класс без деструктора с таким полем — ошибка
([деструкторы](../disposable.md)).

### `own` и якорь `anchor`

Владение бывает двух видов. `own` — исключительное: владеющая ссылка единственная, других указателей на значение
нет. Якорь `anchor` — неисключительное: поле отвечает за уничтожение значения, а на само значение смотрят хранимые
указатели.

```efen
struct Job  { var next: own Jobs.Item? = null }          // на задание никто больше не смотрит
struct Node {
    var left: anchor Nodes.Item? = null                   // на узел смотрит parent его детей
    var parent: Nodes.Item? = null
}

let job = take queue.head                                 // own переносится через take
guard let top = tie tree.root else { return }             // якорь переносится через tie
```

Владелец у значения один: два поля `anchor` на одно значение — ошибка, как и `anchor` вместе с `own`. Значение `own`
переносит `take`: следить не за чем. Якорь переносит `tie`: в каждый момент якорь у значения один, а указатели на
значение при переносе внутри одной структуры остаются верными. `take` слота под якорем — ошибка. Значение `own`
кладётся в поле `anchor` через `tie` без отдельного шага: на него ещё никто не смотрит. Обратно, от якоря к `own`,
ведёт только приведение `as own`, и к нему код уже переписал все указатели на значение
([якорь](layout-reference.md#якорь-anchor)).

### Невладеющий указатель

Поле типа `S.Item` без слова владения — невладеющий указатель: адрес элемента, которым владеет кто-то другой.

```efen
public struct Queue {
    private var head: anchor Nodes.Item? = null
    private var tail: Nodes.Item? = null                  // указатель на последний узел
}
```

Цель хранимого указателя жива на каждом выходе публичной функции: функция, которая уничтожает узел, сначала
переписывает каждый указатель на него. Хранимый указатель смотрит только внутрь своей структуры: `tail` одной
очереди не указывает на узел другой. Исключение — множество без поля-владельца, например вершины графа, которые
освобождает функция ([структура, источник, чистота](layout-reference.md#структура-источник-чистота)). Указатель в
локальной переменной (`let node = list.head`) помнит источник — структуру, из которой он прочитан, — и умирает,
когда эта структура теряет узел, на который он может смотреть.

### Закон

Закон — строка блока `invariants`, написанная программистом: утверждение о полях структуры, которое верно всякий раз,
когда структуру видит чужой код.

```efen
struct Node {
    var next: anchor Nodes.Item? = null
    var prev: Nodes.Item? = null

    invariants { next == null || next!.prev == self }
}
```

На входе функции компилятор принимает законы верными; на выходе публичной функции, перед `throw`, приостановкой и
вызовом кода, способного обратиться к структуре, доказывает их. Между этими точками закон можно нарушить. У закона
две работы. Первая — обычный инвариант (`count == nodes.count`). Вторая — закон говорит компилятору, где хранятся
указатели: по `next!.prev == self` он знает, что `prev` узла смотрит на владельца этого узла, и при удалении узла
проверяет только двух соседей, без обхода всего списка. Функция, которая пишет `prev`, не зная, кто владеет узлом,
доказать закон не может, и это ошибка ([законы и цепочки](layout-reference.md#законы-и-цепочки)).

### `edit` и `mut`

`edit` и `mut` — два права записи. `edit` гарантирует, что ни один существующий элемент или слот не перенесён и не
уничтожен; `mut` этой гарантии не даёт. Право читается по итогу функции, а не по отдельным строкам.

| Операция | Право | Указатели и ссылки вызывающего |
|---|---|---|
| запись поля-значения, запись невладеющего указателя | `edit` | живут |
| новый элемент в пустое владеющее поле | `edit` | живут |
| `tie`, после которого элемент снова лежит в той же структуре | `edit` | живут |
| `tie`, после которого элемент ушёл: в результат, в другую структуру, в уничтожение | `mut` | на ушедший элемент и всё под ним — умирают |
| `take` значения `own` из поля, `take` элемента области | `mut` | в прежнее содержимое — умирают |
| перевыделение или замена области | `mut` | внутрь прежней области — умирают |

```efen
let node = list.first()
list.insertFirst(value: 7)          // edit: узлы на своих адресах, node жив
print(node.value)
```

Выбор слова — контракт перед вызывающим: после вызова `edit` его указатели верны, после вызова `mut` те из них, что
могут смотреть на изменённое, использовать нельзя. Вставка в список — `edit`; `append` вектора — `mut`, потому что
худший путь перевыделяет область. Полная таблица операций — в разделе справочника
[«`edit` и `mut` в `layout`»](layout-reference.md#edit-и-mut-в-layout).

### Публичная функция структуры и помощник

Функция без `private`, которая пишет поля `layout`, — публичная функция структуры: законы верны на её входе и
выходе. Функция `private` — помощник: она получает структуру с открытым законом и может вернуть её в промежуточном
состоянии.

```efen
private fn unlinkFirst<T>(list: mut List<T>) -> anchor Nodes<T>.Item? {
    guard let first = tie list.head else { return null }
    list.head = tie first.next
    return first                      // count ещё не уменьшен: закон открыт
}
```

Что помощник сделал со структурой и её законом, компилятор выводит из тела и записывает в его сводку: здесь — «узел
ушёл из `list` в результат». Публичная функция, которая вызывает `unlinkFirst`, уменьшает `count` и освобождает узел;
её слово права проверяется по сводкам всех помощников, которых она вызывает. Функции стоят в модуле рядом с блоком, а
не внутри него: блок содержит только описание памяти.

### Инициализация после `as` и `_`

Приведение `as` делает из сырой памяти элемент, и инициализация при нём явная. Приведение с аргументами работает как
вызов `Item(…)`: записывает названные поля, а поле со значением по умолчанию получает его.

```efen
let a = memory as Item(value: 0, next: NONE)    // все поля записаны в приведении
let b = memory as Item(value: _, next: NONE)    // value — прежние байты, явно
let c = memory as Item                          // value и next не инициализированы
c.value = 0                                     // запись инициализирует поле
```

Поле без значения по умолчанию, не записанное в приведении и после него, не инициализировано, и чтение такого поля —
ошибка компиляции. «Не инициализировано» и `null` — разное: `null` — значение. Инициализатор `_` пишется только
явно, для поля, байты которого программе не важны. На числовом поле он оставляет прежние байты, на
опциональном записывает `null`; на неопциональном указателе, поле `own` или `anchor`, логическом поле, варианте и поле
типа `T` он — ошибка ([виды и приведение](layout-reference.md#виды-и-приведение-as)).

## Второй пример: двусвязный список

У двусвязного списка каждый узел хранит указатель `prev` на предыдущий. Владение остаётся цепочкой якорей по
`next`; `prev` и `tail` — невладеющие указатели под законами.

```efen
private layout<T: Movable> {
    set Nodes: Node

    struct Node {
        var value: T
        var next: anchor Nodes.Item? = null
        var prev: Nodes.Item? = null

        invariants { next == null || next!.prev == self }
    }

    public struct DoublyList {
        private var head: anchor Nodes.Item? = null
        private var tail: Nodes.Item? = null
        public  var count: Int = 0 { value >= 0 }

        invariants {
            let nodes = Nodes.chain(from: head, by: Node.next, until: null)
            count == nodes.count
            head == null || head!.prev == null
            (head == null) == (tail == null)
            tail == null || tail!.next == null
        }
    }
}
```

Закон об обратном указателе написан у каждого владеющего поля: `next!.prev == self` у `Node.next` и
`head!.prev == null` у `DoublyList.head`. Поэтому `prev`, равный узлу, хранит только узел под его `next`. Цикла
владения нет: якоря идут только вперёд.

### Вставка в конец

```efen
strategy<T> for DoublyList<T> {
    public edit fn append(value: own T) {
        let node = newNode(take value)
        if let last = tail {
            node.prev = last
            last.next = tie node
        } else {
            head = tie node
        }
        tail = node
        count += 1
    }
}
```

`node.prev = last` записана раньше, чем `last.next = tie node`, но порядок строк закону безразличен: закон
`last.next!.prev == last` проверяется на выходе, и к выходу обе записи сделаны. `tail = node` после `tie node`
законна: `tie` передал владение, а имя `node` осталось невладеющим указателем на тот же узел. Функция — `edit`: новый
узел пришёл в пустое владеющее поле, прежние узлы на своих адресах.

### Удаление узла

```efen
private fn unlinkAt<T>(list: mut DoublyList<T>, index: Int) -> anchor Nodes<T>.Item? {
    if index == 0 {
        guard let first = tie list.head else { return null }
        list.head = tie first.next
        if let newHead = list.head {
            newHead.prev = null
        } else {
            list.tail = null
        }
        list.count -= 1
        return first
    }

    let before = nodeAtMut(list, index: index - 1)
    guard let victim = tie before.next else { return null }
    before.next = tie victim.next
    if let after = before.next {
        after.prev = before
    } else {
        list.tail = before
    }
    victim.prev = null
    list.count -= 1
    return victim
}

strategy<T> for DoublyList<T> {
    public mut fn remove(index: Int) -> own T? {
        guard index >= 0 && index < count else { return null }
        guard let node = unlinkAt(self, index: index) else { return null }
        let value = take node.value
        mm.free(node as own Pointer)
        return value
    }
}
```

`nodeAtMut` — помощник модуля: он проходит по `next` от `head` и возвращает `mut Nodes<T>.Item`. Указатель берёт
право значения, через которое получен, поэтому `before` несёт `mut` списка-параметра; с указателем `edit` строка
`tie before.next`, после которой узел уходит из списка, была бы ошибкой.

Вторая ветка `unlinkAt` по строкам:

1. `guard let victim = tie before.next`. Узел переходит под локальную переменную, `before.next` пуст.
2. `before.next = tie victim.next`. Остаток цепочки переходит под `before`; владеющее поле `victim` теперь `null`.
3. `after.prev = before`. Закон `before.next!.prev == before` восстановлен. До этой строки `after.prev` хранил адрес
   `victim`.
4. `list.tail = before` — случай, когда `victim` был последним: `tail` хранил его адрес.
5. `victim.prev = null`. Узел уходит из списка, и указателя из него обратно в список не остаётся.

### Почему компилятор это принимает

Компилятор проверяет приведение `node as own Pointer` в `remove`: к этой строке ни один хранимый указатель не
смотрит на узел. Искать по всей памяти ему не нужно: держателей называет схема.

- Владеющий указатель один — якорь. Он перешёл в `victim`, затем в результат `unlinkAt`, затем в `node`.
- `prev`, равный узлу, по закону `next!.prev == self` хранит только узел под его `next`. Это `after`, и строка 3 его
  переписала.
- `tail` — поле самого списка; строка 4 переписала его в единственном случае, когда он мог быть равен узлу.
- Владеющее поле самого узла пусто после строки 2, значение `T` забрано строкой `take node.value`.

Если убрать строку 3, закон `before.next!.prev == before` не доказывается на выходе `remove`, и `as own` не
доказывается: `after.prev` остаётся указателем на освобождаемый узел. Это та же ошибка, что в функции на C из первого
раздела, и здесь она — ошибка компиляции.

У вызывающего `remove` — вызов `mut`: его указатели и ссылки с источником в этом списке, которые могут смотреть на
удалённый узел, умирают в строке вызова. Источник не различает узлы внутри одного списка, поэтому умирает каждый
указатель, который может быть равен удалённому.

## Что уходит наружу

Внешний код — код, которому модификатор блока не разрешает писать поля. Он получает память `layout` четырьмя
способами; два из них блок объявляет строкой [схемы владения](layout-reference.md#схема-владения).

| Что получает внешний код | Запись | Строка в блоке |
|---|---|---|
| значение структуры (`List<Int>`, `Graph`) | тип структуры | не нужна |
| элемент целиком | `own S.Item` | `public own S` |
| слот области | `own Block.data.Item` | `public lend Block.data` |
| заимствование или указатель без владения | `-> read T?`, `-> edit<list> T?`, `S.Item` | не нужна |

### Значение структуры

Значение структуры — обычное значение: его держат в переменной, передают параметром `own`, кладут в поле класса.
Вместе со значением переходят все элементы, которыми оно владеет. У структуры с владеющим полем, видимой внешнему коду, есть функция
той же видимости, которая оставляет все владеющие поля `null`; без неё объявление структуры — ошибка.

### Элемент целиком: `public own S`

```efen
private layout {
    set Nodes: Node

    public own Nodes

    public struct Node  { var next: own Nodes.Item? = null; public var value: Int }
    public struct Queue { var head: own Nodes.Item? = null }
}

public fn newNode(value: Int) -> own Nodes.Item { … }
public fn push(queue: edit Queue, node: own Nodes.Item) { … }
public fn pop(queue: mut Queue) -> own Nodes.Item? { … }
public fn freeNode(node: own Nodes.Item) { … }
```

Строка `public own Nodes` разрешает публичным функциям отдавать и принимать `own Nodes.Item`. Без неё `own Nodes.Item`
в сигнатуре функции, видимой внешнему коду, — ошибка у этой позиции. У строки есть обратный путь: функция той же
видимости, которая принимает элемент и уничтожает его или оставляет в структуре (`freeNode`, `push`). Внешний код
держит элемент в локальной переменной, параметре и результате и на каждом выходе возвращает его функции блока или
передаёт дальше. Поле `own Nodes.Item` в классе или обычной структуре — ошибка; дольше одного вызова элемент лежит в
контейнере `layout`, например в `Vector<own Nodes.Item>`.

### Выданный слот: `public lend S.area`

```efen
layout {
    set area Blocks: Block

    public lend Block.data

    struct Block {
        var next: anchor Blocks.Item? = null     // поля блока остаются у layout
        area data: Byte                          // память для внешнего кода
    }
}

public fn acquire(pool: mut Pool) -> own Block.data.Item? { … }
public fn release(block: mut Blocks.Item, data: own block.data.Item) {
    block.data[0] = take data                    // слот вернулся туда, откуда выдан
}
```

`lend block.data[0]` выдаёт слот области: получатель владеет его байтами, а поля блока (`next`) остаются у `layout`
и смотрят на другие байты. Тип слота называет область, из которой он выдан, поэтому вернуть его можно только в свой
слот; привести к `Pointer` и отдать менеджеру памяти нельзя. Пока слот выдан, блок нельзя вернуть или освободить.
Выдача и возврат требуют `mut` на блок.

### Заимствование с источником

```efen
strategy<T> for List<T> {
    public fn first -> read T? {
        guard let node = head else { return null }
        return &read node.value
    }
}

fn firstOf<T>(list: List<T>) -> read<list> T? { … }
```

Заимствование — доступ к памяти, которой `layout` продолжает пользоваться; владение не переходит. Источник записан в
результате: в методе это `self` и не пишется (`-> read T?`), в свободной функции он стоит в угловых скобках
(`-> read<list> T?`). Заимствование живёт, пока источник не изменил структуру: вызов `edit` его не трогает, а
использовать его после вызова, который освобождает или уводит узлы, — ошибка
([что убивает ссылку](memory-rules.md#что-убивает-ссылку)). Форма с `&`, `-> read<&doc.title> T`, обещает ссылку
ровно на слот по пути; путь в ней не проходит через указатель `layout`
([ссылка ровно на слот](../types/ownership.md#ссылка-ровно-на-слот)). Дольше одного вызова указатель на элемент
вне `layout` хранит только структура с параметром источника, например курсор
([указатели вне `layout`](layout-reference.md#указатели-вне-layout)).

### Якорь наружу не уходит

`anchor S.Item` в сигнатуре функции, видимой внешнему коду, — ошибка при любой строке схемы. Якорь означает, что на
элемент смотрят хранимые указатели, и перед уничтожением элемента каждый из них переписывается. Хранятся они в полях
`layout`, а писать эти поля внешний код не может. Поэтому якорь переходит только между функциями, которым
модификатор блока разрешает писать поля. Чтобы отдать элемент наружу, такая функция сначала убирает указатели на него
и делает переход `as own`: внешний код получает `own`, на который никто не смотрит.

## Частые ошибки

Текст диагностики в первом примере взят из справочника
([диагностика времени жизни](layout-reference.md#диагностика-времени-жизни)); в остальных комментарий пересказывает
правило, а точный текст задаёт реализация. Примеры 1, 3–7 — код модуля, в котором стоит блок; пример 2 — внешний код.

**1. Указатель использован после освобождения узла.**

```efen
fn broken(list: mut List<Int>) {
    guard let node = list.head else { return }   // указатель, источник — list
    let dropped = list.popFirst()                // освобождает первый узел
    print(node.value)                            // error[flow.slot-left]: указатель `node` использован после конца жизни узла
}
```

Если `node` после `popFirst` не используется, ошибки нет.

**2. Выход из области с неосвобождённым списком.**

```efen
fn build {
    var list = List<Int>()
    list.pushFirst(1)
}                                // ошибка: list выходит из области, а владеющее поле head может быть не null
```

Исправление — `defer list.release()` сразу после создания.

**3. Чтение поля до инициализации.**

```efen
let node = memory as Node<Int>   // next получил значение по умолчанию, value не записан
print(node.value)                // ошибка: value не инициализирован
```

**4. Указатель из одного списка записан в другой.**

```efen
fn share(a: edit DoublyList<Int>, b: DoublyList<Int>) {
    a.tail = b.head              // ошибка: хранимый указатель списка a смотрит на узел списка b
}
```

Узел переходит между структурами только владением: `tie` из одной и `tie` в другую.

**5. Наружу отдано то, чего не называет ни одна строка.**

```efen
public fn popNode(list: mut List<Int>) -> own Nodes<Int>.Item? { … }      // ошибка: нет строки `public own Nodes`
public fn peekNode(list: mut List<Int>) -> anchor Nodes<Int>.Item? { … }  // ошибка: якорь внешнему коду не выдаётся
```

**6. Изменение структуры под `edit`.**

```efen
public edit fn dropFirst {       // ошибка: узел ушёл из списка в уничтожение, нужен mut
    guard let node = tie head else { return }
    head = tie node.next
    count -= 1
    let dead = take node.value
    mm.free(node as own Pointer)
}
```

**7. `take` якоря и запись в непустое владеющее поле.**

```efen
let first = take list.head       // ошибка: take слота под якорем; якорь переносит tie
list.head = tie node             // ошибка: поле head не доказано пустым, прежний первый узел потерял бы владельца
```
