# Layout и описание памяти

[Память](README.md) · [Компоновка и дескрипторы](addresses.md) · [Модели поведения](../models.md)

`layout` описывает память и связи, которые проверяет компилятор. Работа с ним
включает физическое хранение, владение, адресацию и удержания внешней стороны.
Вид объявления определяет, какие сведения в нём допустимы.

Физическое описание в аспекте representation и поля удержаний в теле класса
имеют разные правила. Поля удержаний не занимают байты объекта; `model`
описывает их изменение при вызове. Модель метода не определяет физическое хранение.

## `layout` в теле класса

Блок `layout { … }` бывает и в теле класса, интерфейса или контракта. Там он описывает не байты, а то, что держит
внешняя сторона ([класс над внешним значением](../classes.md#класс-над-внешним-значением)), и содержит только:

- объявления `var` — поля `layout`. Их нет в памяти объекта, их не исполняют, их читает только FLOW; пишет их
  [модель](../models.md#модель-model);
- строки условий в форме [декларативных условий](addresses.md#декларативные-условия): `forall`, `==`, `if` как импликация
  ([отношения в `layout`](../models.md#отношения-в-layout-класса)).

Физические описания (`set`, `one`, `area`, `struct Self`) остаются в аспекте representation; в `layout` класса они —
ошибка.

Тип поля `layout`:

- `read T`, `edit T` — удержание слота Efen;
- `mut U`, `read U`, где `U` — класс над внешним значением, — зависимость от внешнего объекта: пока держатель жив,
  `U` нельзя уничтожить и отдать;
- `own T` — значение, которое забрала внешняя сторона. Замыкание `own` вида `own` упаковывает сгенерированный вход
  и освобождает после единственного вызова. Другому значению `own` нужна память Efen, а поле `layout` её не занимает
  ни в каком классе, — ошибка. Класс с настоящими полями хранит такое значение в настоящем поле: модель пишет его туда
  ([удержания](../models.md#удержания));
- коллекция или optional из таких типов;
- простое значение (`errmsg: CString`) — только как источник ссылок, которые возвращают методы.

Поля `layout` бывают у класса без счётчика (класс над внешним значением — один из таких классов), у интерфейса и у
контракта. Класс со счётчиком пишет в `layout` только строки условий: его поля — `managed`, и внешняя сторона держит
через них только то, что называет отношение ([удержания](../models.md#удержания)).

`obj.field` вне модели и вне условия `layout` — ошибка. Настоящее поле и поле `layout` с одним именем — ошибка.
Настоящие поля класса пишутся вне `layout`, как обычно; у класса над внешним значением их нет.

**Порядок уничтожения — опубликованная гарантия.** Объект уничтожается раньше каждого слота, который держит, и
раньше каждого объекта, от которого зависит; остальное идёт в порядке, обратном объявлению. Круг удержаний в
конце области — ошибка с именами обоих объектов. Среди полей класса порядок тот же, и отношение `forall` его
задаёт: при `forall s in cache.values: s.db == db` поле `cache` уничтожается раньше `db`.
