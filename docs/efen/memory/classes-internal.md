# Классы не то, чем кажутся

> Этот документ описывает концептуальное внутреннее представление компилятора,
> а не синтаксис исходного языка Efen. Псевдокод IR ниже не принимается обычным
> parser-ом и может изменяться без сохранения совместимости.

Классы не просто так являются абстракциями более высокого уровня, 
чем структуры или типы данных. 

Мы попробуем рассмотреть классы с точки зрения компилятора, как 
на самом деле компилятор изнутри видит класс.

Рассмотрим простой класс.

```efen
class Point {
    var x: Float = 0
    var y: Float = 0
    
    @constructor
    fn init(x: Float, y: Float) -> Self {
        self.x = x
        self.y = y
    }
}
```

Концептуально компилятор может представить класс следующим образом:

```text
struct Point {

    projection Raw as None
    projection NonInit as Nullable

    var x: Float = 0.0
    var y: Float = 0.0
}

fn init(x: Float, y: Float) -> Self in Self {
    %self.x = x
    %self.y = y
}
```

Здесь `Raw`, `NonInit`, `%self` и `-> Self in Self` — условные обозначения
внутреннего IR. Они не объявляют новые конструкции пользовательского языка.

Компилятор рассматривает класс как высокоуровневую абстракцию над внутренним
представлением данных. Проекции `Raw` и `NonInit` моделируют промежуточные
состояния, необходимые при выполнении конструктора и деструктора. Конкретный
layout и форма IR выбираются компилятором и не должны менять наблюдаемое
поведение программы.
