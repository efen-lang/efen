## Схема разбора

| Вопрос | Что записывается |
|---|---|
| множества | объявления `set`, поля `Area` и их вложенность |
| владение | `own`, `anchor`, указатели |
| что уходит внешнему коду | значение структуры; элемент по строке `public own Nodes`; слот по строке `public lend Block.data` ([схема владения](layout/owners.md#схема-владения)) |
| инварианты | строки `invariants` |
| события | рождение, передача якоря, смерть |
| FLOW | что доказывает сам: время жизни, локальные инварианты |
| Z3 | что остаётся решателю |
| не закрыто | чего модели не хватает |
| права | каким операциям хватает `edit` и каким нужен `mut` ([таблица операций](layout/operations.md#edit-и-mut-в-layout)) |

Структуры каталога отдают внешнему коду значение структуры (`Vector`, `List`, `Table`) и значения `own T`;
элемент множества не отдаёт ни одна, поэтому строк `public own` в них нет. Функции, которые другим пакетам не видны,
строкам не подчиняются: `anchor` и `own` в их сигнатурах строки не требуют
([публичная функция структуры](layout/functions.md#81-публичная-функция-структуры-и-вспомогательная-функция),
правило 3). Функция, видимая внешнему коду, проверяется по строкам, и `anchor` в её сигнатуре вызывает ошибку
([что уходит наружу](layout/owners.md#выдача-наружу), «Запрещено»). Пул объектов и менеджер памяти
выдают слоты; когда функция выдачи видна внешнему коду, `layout` объявляет `public lend PoolBlock.cells`.

## Динамический массив

```efen
layout {
    struct Vector {
        var items: own Area<Item>? { value == null || value.count == capacity }
        var capacity: Int { value >= 0 }
        var count: Int { value >= 0 && value <= capacity }
        invariants { items == null || items!.initialized == count }
    }
}
```

- **Множества.** Одна область `Area<Item>`, её держит `Vector.items`.
- **Владение.** `own` области; слоты — значения.
- **Инварианты.** `count <= capacity`; `items.initialized == count`: слоты `count ..< capacity` не инициализированы.
- **События.** Рост — перевыделение области: все указатели внутрь неё недействительны. Запись слота — запись в неинициализированный элемент, удаление —
  `take` элемента области ([неинициализированный элемент области](layout/declaration.md#множества-и-области)).
- **FLOW.** Индекс в `0 ..< count`; указатель слота не переживает рост; очистка по `count`
  ([частичная инициализация](layout/operations.md#частичная-инициализация-и-очистка)).
- **Z3.** Нелинейные границы, если ёмкость растёт умножением.
- **Не закрыто.** Ничего нового: модель покрывает массив целиком.
- **Права.** Запись элемента, который ничем не владеет, — `edit`. Добавление в пределах ёмкости (запись в неинициализированный слот и
  `count`) — `edit`; рост перевыделяет область, поэтому `append` по худшему пути — `mut`. Удаление (`take` элемента) — `mut`.

## Пул объектов

```efen
layout {
    set area PoolBlocks: PoolBlock

    struct Cell {
        var next: Int = NONE
        var value: Int
    }

    public struct ObjectPool {
        var first: anchor PoolBlocks.Item? = null        // владеет цепочкой участков
    }

    struct PoolBlock {
        var nextBlock: anchor PoolBlocks.Item? = null    // цепочка участков пула: владеет следующим
        var used: Int
        var frontier: Int { value >= 0 }
        var firstFree: Int = NONE
        inline cells: Area<Cell> { value.count == 16 }

        invariants {
            used == cells.taken.count
            frontier <= cells.count
            let free = cells.chain(from: firstFree, by: Cell.next, until: NONE)
            forall k in free: 0 <= k && k < frontier && !cells.taken.contains(k)
        }
    }
}
```

- **Владение.** Блок владеет областью; выданный слот — у получателя (`lend`).
- **События.** Рождение слота — `lend` после снятия с цепочки или у границы; смерть — возврат на место.
- **FLOW.** Инвариант цепочки локален (`frontier` только растёт), счёт `used`, полнота по выходам. Граница снятого слота
  в области — только если FLOW знает `frontier <= cells.count`; сегодня, как в mm, это `assume`.
- **Z3.** Ничего, если число слотов — константа.
- **Не закрыто.** Ничего: это схема mm.
- **Права.** Выдача (`lend` и поля счёта) и возврат слота — `mut` на блок: слот уходит из структуры блока владением.

## Односвязный список

```efen
layout {
    set Nodes: Node

    struct Node {
        var value: Int
        var next: anchor Nodes.Item? = null
    }

    struct List {
        var head: anchor Nodes.Item? = null
        var length: Int

        invariants {
            let nodes = Nodes.chain(from: head, by: Node.next, until: null)
            length == nodes.count
        }
    }
}

private fn pop(list: mut List) -> anchor Nodes.Item? {
    let first = tie list.head ?? return null
    list.head = tie first.next
    list.length = list.length - 1
    return first
}
```

- **Владение.** Каждый узел под одним якорем: `head` или `next` предыдущего. Цепочка без повторов следует из правила
  «якорь у значения один».
- **События.** `pop` передаёт якорь вызывающему; сводка помечает её «отдаёт».
- **FLOW.** Инвариант о числе узлов: `+1`/`-1`. Время жизни узла — до точки, где якорь его уничтожает.
- **Не закрыто.** Ничего.
- **Права.** Вставка в начало (`node.next = tie list.head`, затем `list.head = tie node`) и разворот — `edit`:
  узлы остаются под списком. `pop` отдаёт якорь наружу — `mut`.

## Двусвязный список

```efen
struct Node {
    var next: anchor Nodes.Item? = null
    var prev: Nodes.Item? = null                 // невладеющий указатель

    invariants {
        next == null || next!.prev == self
    }
}
```

- **Владение.** Якоря по `next`; `prev` — указатель, цикла владельцев нет.
- **FLOW.** Инвариант двусвязности локален с соседом: вставка и вырезание трогают два узла.
- **Хвост.** `tail` — невладеющий указатель под инвариантом `tail == nodes.last`. По инварианту FLOW знает, что `tail` может
  указывать на удаляемый последний узел, и требует переписать его до освобождения; сам инвариант после `append` и
  удаления доказывает Z3.
- **Права.** Вставка и перенос узла внутри списка — `edit`; вырезание с уничтожением — `mut`.

## Элемент в двух структурах: LRU

Кэш: хеш-таблица по ключу и список по давности использования; одна запись в обоих.

```efen
struct Entry {
    var key: Int
    var next: anchor Entries.Item? = null        // цепочка корзины: якорь
    var older: Entries.Item? = null              // список давности: невладеющий указатель
    var newer: Entries.Item? = null              // невладеющий указатель
}
```

- **Владение.** Якорь у записи один — в цепочке корзины. В списке давности она только указатель.
- **События.** Вытеснение старейшей: снять с обоих, затем уничтожить. Порядок проверяет FLOW: к точке уничтожения
  указатели `older`/`newer` соседей переписаны.
- **FLOW.** Время жизни; оба инварианта локальны.
- **Не закрыто.** Указатели `older`/`newer` связаны инвариантом двусвязности только с соседом. Если запись уничтожают, не
  переписав `newer!.older`, инвариант соседа держится, а указатель висит: нужен инвариант, связывающий каждый хранимый указатель с
  якорем. Сегодня это требование стоит в правилах: перед `as own` найден каждый указатель на запись
  ([удаление элемента](layout/operations.md#переход-к-владению-as-own)). Довод за `anchor` остаётся: при `own` запись в двух
  структурах не описать.
- **Права.** `get` переносит запись в начало списка давности записью `older`/`newer` — `edit`: ссылки на записи
  от прежних `get` живут. Новая запись без роста корзин — `edit`. Вытеснение уничтожает запись — `mut`.

## Кольцевой буфер

```efen
layout {
    public struct Ring {
        var head: Int { value >= 0 && value < CAPACITY }
        var count: Int { value >= 0 && value <= CAPACITY }
        var slots: own Area<Slot>? = null { value == null || value.count == CAPACITY }
    }
}
```

- **Инварианты.** Занятые слоты — `head ..< head + count` по модулю `CAPACITY`.
- **FLOW.** Границы индексов при явном `% CAPACITY`.
- **Z3.** Диапазон по модулю: инвариант «занятые слоты» не локален в смысле сдвига границы.
- **Не закрыто.** Форма диапазона по модулю в инварианте.
- **Права.** Запись в свободный слот и `count` — `edit`; снятие (`take` элемента) — `mut`.

## Хеш-таблица с цепочками

Разобрана в [layout](layout-proofs.md#локальное-доказательство-инвариантов): `Bucket.head` и `Entry.next` — якоря над `Entries`; слот
области корзин — якорь записи другого множества ([владение по множествам](layout/declaration.md#множества-и-области)).

- **FLOW.** Непересечение цепочек — из «якорь у значения один»; инвариант «запись в цепочке своей корзины» — для
  произвольной корзины в два случая; опустошение старых корзин при росте — правилом цикла со счётчиком.
- **Z3.** Замена области корзин (`table.buckets = take fresh`) пишет поле вида, которое читает инвариант: инвариант над новой
  областью FLOW локально не доказывает. Удаление записи требует, чтобы она вышла из `Entries` или снова встала в
  цепочку: инвариант над всем множеством, а не над цепочкой.
- **Не закрыто.** Цепочка с параметром в реализации.
- **Права.** Вставка без роста — `edit`; рост заменяет область корзин — `mut`; удаление записи — `mut`.

## Хеш-таблица с открытой адресацией

```efen
struct Slot {
    var state: Int                               // EMPTY, FULL, DELETED
    var key: Int
}

struct Table {
    var count: Int = 0
    var slots: own Area<Slot>? = null { value == null || value.count == CAPACITY }   // значение Table владеет областью
}
```

- **Владение.** Слоты — значения; якорей нет.
- **Инварианты.** Ключ лежит не дальше первого `EMPTY` от своего хеша по ходу пробы.
- **FLOW.** Границы, счёт.
- **Z3.** Инвариант пробы: он связывает слот со всеми слотами между хешем и им — не локален.
- **Не закрыто.** Ничего по времени жизни; инвариант пробы — работа Z3.
- **Права.** Вставка в слот `EMPTY` — `edit`. Снятие меткой `state = DELETED` для компилятора — запись значения,
  `edit`; слово `mut` у `remove` даёт контракт коллекции. Рост — `mut`.

## Двоичное дерево с родителем

```efen
struct Node {
    var key: Int
    var left: anchor Nodes.Item? = null
    var right: anchor Nodes.Item? = null
    var parent: Nodes.Item? = null
}
```

- **Владение.** Дерево якорей; `parent` — указатель.
- **События.** Поворот — передача якорей между полями ([передача якоря](layout/owners.md#якорь-anchor)).
- **FLOW.** Время жизни; инвариант `left == null || left!.parent == self` локален.
- **Z3.** Порядок ключей по всему поддереву.
- **Не закрыто.** Обход рекурсией по сводному узлу грубее точного (шаг 6n Amber).
- **Права.** Вставка листа и поворот — `edit`: узлы остаются под деревом. Удаление узла — `mut`.

## Граф

Вершины с рёбрами в обе стороны и циклами.

```efen
layout {
    set Vertices: Vertex
    set Edges: Edge

    struct Edge {
        var to: Vertices.Item                    // невладеющий указатель
        var next: anchor Edges.Item? = null      // список рёбер вершины
    }

    struct Vertex {
        var edges: anchor Edges.Item? = null
        var nextAll: anchor Vertices.Item? = null    // цепочка всех вершин графа: владеет следующей
    }

    public struct Graph {
        var first: anchor Vertices.Item? = null      // владеет цепочкой вершин
    }
}
```

- **Владение.** Вершинами владеет структура `Graph`: цепочка якорей идёт от `Graph.first` по полю `nextAll`
  ([пример C](layout/declaration.md#пространство-layout)). Рёбрами владеет список рёбер вершины. Ребро указывает на
  вершину без владения, поэтому циклы есть только в указателях, а в якорях их нет.
- **События.** Удаление вершины: сначала все рёбра, ведущие к ней, — иначе указатель `to` переживёт вершину.
- **FLOW.** Время жизни и полнота: к уничтожению вершины ни одно `to` на неё не указывает. Это свойство всех рёбер
  всех вершин, и доказывает его обход цепочки вершин в функции удаления
  ([свободный граф](layout-algorithm.md#свободный-граф)).
- **Z3.** Инвариант «никакое ребро не ведёт к удаляемой вершине» — квантор по двум множествам.
- **Не закрыто.** Входящие рёбра: чтобы удалить вершину локально, нужен обратный список входящих рёбер (указатели); без
  него инвариант не локален.
- **Права.** Новая вершина и новое ребро в списке рёбер требуют `edit` на граф. В варианте с вектором соседей рост
  вектора переносит его слоты и требует `mut`. Удаление вершины требует `mut` на граф
  ([свободный граф](layout-algorithm.md#свободный-граф)).

## Менеджер памяти mm

ОС → регион → блок → слот. Каждый следующий уровень занимает память предыдущего: область получена приведением
его памяти или вложена полем `inline` типа `Area` в его элемент ([переход между
множествами](layout/operations.md#выделение-и-освобождение--переход-между-множествами)). У множества своей памяти
нет.

- **Владение.** Пул владеет регионом через `own`, пока все блоки в нём. Первый `lend` блока делает это владение
  неисключительным: регион остаётся у пула под якорем (`anchor`). В `block_pool` блоки — слоты области региона; в
  `raw_allocator` блоки — множество `set area Blocks`, взятое у системы. Слоты — слоты области блока, выдаются
  `lend`. Блок с выданными слотами записан в одну из двух цепочек якорей своего класса, и обе цепочки владеют
  своими блоками ([иерархия владения](pointer.md#иерархия-владения)).
- **FLOW.** Время жизни и счёт, кроме двух `assume` на снятом слоте (FLOW не знает `frontier <= slots.count`).
- **Z3.** `slots.count == PAYLOAD / SIZES[sizeClass]` — нелинейно.
- **Не закрыто.** Список блоков класса: блок на нём и `linked` — инвариант о двух множествах (блоки и классы).
- **Права.** Выдача слота, возврат слота, смена вида блока, возврат блока и региона — `mut`.

## Сводка

| Структура | Время жизни (FLOW) | Инварианты (FLOW) | Z3 | Не закрыто |
|---|---|---|---|---|
| динамический массив | да | да | рост умножением | — |
| пул объектов | да | да | — | `frontier <= cells.count` |
| односвязный список | да | да | — | цикл якорей, рождение узла |
| двусвязный список | при инварианте о `prev` | да | `tail` | хранимые указатели |
| LRU | при инварианте о `older`/`newer` | да | — | хранимые указатели |
| кольцевой буфер | да | частично | диапазон по модулю | форма инварианта |
| хеш-таблица с цепочками | да | частично | замена корзин, удаление | цепочка с параметром |
| открытая адресация | да | частично | инвариант пробы | — |
| дерево с родителем | при инварианте о `parent` | частично | порядок ключей | цикл якорей, точность рекурсии |
| граф | да, обходом цепочки вершин | да | входящие рёбра | локальное удаление вершины: обратный список |
| mm | да | да | `PAYLOAD / SIZES[sizeClass]` | `frontier <= slots.count` |

Время жизни FLOW выводит сам там, где каждый хранимый указатель связан инвариантом с якорем. Указатели на вершину графа
находит обход цепочки вершин, которой владеет `Graph`. Внешние указатели на узлы существуют только внутри одной
публичной структуры ([указатель вне layout](layout/pointers.md#указатели-вне-layout)). Z3 нужен
для порядка, пробы, модуля, замены области и инвариантов над целым множеством.
