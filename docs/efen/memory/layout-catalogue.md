## Схема разбора

| Вопрос | Что записывается |
|---|---|
| множества | дескрипторы и вложенность |
| владение | `own`, `anchor`, указатели |
| законы | строки `invariants` |
| события | рождение, передача якоря, смерть |
| FLOW | что доказывает сам: время жизни, локальные законы |
| Z3 | что остаётся решателю |
| не закрыто | чего модели не хватает |

## Динамический массив

```efen
layout {
    area Items: Item

    struct Vector {
        var items: own Items.Area? { value == null || value.count == capacity }
        var capacity: Int { value >= 0 }
        var count: Int { value >= 0 && value <= capacity }
    }
}
```

- **Множества.** Одна область `Items`, её держит `Vector.items`.
- **Владение.** `own` области; места — значения.
- **Законы.** `count <= capacity`; места `count ..< capacity` не инициализированы.
- **События.** Рост — перевыделение области: все указатели внутрь неё умирают. Запись места — `initialize`, удаление —
  `extract` (операции дескриптора, [компоновка](addresses.md#операции-дескриптора)).
- **FLOW.** Индекс в `0 ..< count`; указатель места не переживает рост; очистка по `count`
  ([частичная инициализация](addresses.md#частичная-инициализация-и-очистка)).
- **Z3.** Нелинейные границы, если ёмкость растёт умножением.
- **Не закрыто.** Ничего нового: модель покрывает массив целиком.

## Пул объектов

```efen
layout {
    struct Cell {
        var next: Int = NONE
        var value: Int
    }

    struct PoolBlock {
        var used: Int
        var frontier: Int { value >= 0 }
        var firstFree: Int = NONE
        area cells: Cell { value.count == 16 }

        invariants {
            used == cells.taken.count
            frontier <= cells.count
            let free = cells.chain(from: firstFree, by: Cell.next, until: NONE)
            forall k in free: 0 <= k && k < frontier && !cells.taken.contains(k)
        }
    }
}
```

- **Владение.** Блок владеет областью; выданное место — у получателя (`lend`).
- **События.** Рождение места — `lend` после снятия с цепочки или у границы; смерть — возврат на место.
- **FLOW.** Закон цепочки локален (`frontier` только растёт), счёт `used`, полнота по выходам. Граница снятого места
  в области — только если FLOW знает `frontier <= cells.count`; сегодня, как в mm, это `assume`.
- **Z3.** Ничего, если число мест — константа.
- **Не закрыто.** Ничего: это схема mm.

## Односвязный список

```efen
layout {
    set area Nodes: Node

    struct Node {
        var value: Int
        var next: anchor Nodes.Item? = null
    }

    struct List {
        var head: anchor Nodes.Item? = null
        var length: Int

        invariants {
            let nodes = Nodes.chain(from: head, by: Node.next, until: null)
            length == nodes.count
        }
    }
}

fn pop(list: mut List) -> anchor Nodes.Item? {
    guard let first = take list.head else { return null }
    list.head = take first.next
    list.length = list.length - 1
    return first
}
```

- **Владение.** Каждый узел под одним якорем: `head` или `next` предыдущего. Цепочка без повторов следует из правила
  «якорь у значения один».
- **События.** `pop` передаёт якорь вызывающему; сводка помечает её «отдаёт».
- **FLOW.** Закон о числе узлов: `+1`/`-1`. Время жизни узла — до точки, где якорь его уничтожает.
- **Не закрыто.** Ничего.

## Двусвязный список

```efen
struct Node {
    var next: anchor Nodes.Item? = null
    var prev: Nodes.Item? = null                 // указатель

    invariants {
        next == null || next!.prev == self
    }
}
```

- **Владение.** Якоря по `next`; `prev` — указатель, цикла владельцев нет.
- **FLOW.** Закон двусвязности локален с соседом: вставка и вырезание трогают два узла.
- **Не закрыто.** Хвост `tail` — указатель; закон `tail == nodes.last` — Z3 или локальное правило для последнего узла.

## Элемент в двух структурах: LRU

Кэш: хеш-таблица по ключу и список по давности использования; одна запись в обоих.

```efen
struct Entry {
    var key: Int
    var next: anchor Entries.Item? = null        // цепочка корзины: якорь
    var older: Entries.Item? = null              // список давности: указатель
    var newer: Entries.Item? = null              // указатель
}
```

- **Владение.** Якорь у записи один — в цепочке корзины. В списке давности она только указатель.
- **События.** Вытеснение старейшей: снять с обоих, затем уничтожить. Порядок проверяет FLOW: к точке уничтожения
  указатели `older`/`newer` соседей переписаны.
- **FLOW.** Время жизни; оба закона локальны.
- **Не закрыто.** Указатели `older`/`newer` связаны законом двусвязности только с соседом. Если запись уничтожают, не
  переписав `newer!.older`, закон соседа держится, а указатель висит: нужен закон, связывающий каждый хранимый указатель с
  якорем ([открытый вопрос 2](layout.md#открытые-вопросы)). Довод за `anchor` остаётся: при `own` запись в двух
  структурах не описать.

## Кольцевой буфер

```efen
struct Ring {
    var head: Int { value >= 0 && value < CAPACITY }
    var count: Int { value >= 0 && value <= CAPACITY }
    area slots: Slot { value.count == CAPACITY }
}
```

- **Законы.** Занятые места — `head ..< head + count` по модулю `CAPACITY`.
- **FLOW.** Границы индексов при явном `% CAPACITY`.
- **Z3.** Диапазон по модулю: закон «занятые места» не локален в смысле сдвига границы.
- **Не закрыто.** Форма диапазона по модулю в законе.

## Хеш-таблица с цепочками

Разобрана в [layout](layout.md#локальное-доказательство-законов): `Bucket.head` и `Entry.next` — якоря над `Entries`; место
области корзин — якорь записи другого множества ([владение по множествам](layout.md#множества-и-области)).

- **FLOW.** Непересечение цепочек — из «якорь у значения один»; закон «запись в цепочке своей корзины» — для
  произвольной корзины в два случая; опустошение старых корзин при росте — правилом цикла со счётчиком.
- **Z3.** Замена области корзин (`table.buckets = take fresh`) пишет поле вида, которое читает закон: закон над новой
  областью FLOW локально не доказывает. Удаление записи требует, чтобы она вышла из `Entries` или снова встала в
  цепочку: закон над всем множеством, а не над цепочкой.
- **Не закрыто.** Цепочка с параметром в реализации.

## Хеш-таблица с открытой адресацией

```efen
struct Slot {
    var state: Int                               // EMPTY, FULL, DELETED
    var key: Int
}

struct Table {
    area slots: Slot { value.count == CAPACITY }
    var count: Int
}
```

- **Владение.** Места — значения; якорей нет.
- **Законы.** Ключ лежит не дальше первого `EMPTY` от своего хеша по ходу пробы.
- **FLOW.** Границы, счёт.
- **Z3.** Закон пробы: он связывает место со всеми местами между хешем и им — не локален.
- **Не закрыто.** Ничего по времени жизни; закон пробы — работа Z3.

## Двоичное дерево с родителем

```efen
struct Node {
    var key: Int
    var left: anchor Nodes.Item? = null
    var right: anchor Nodes.Item? = null
    var parent: Nodes.Item? = null
}
```

- **Владение.** Дерево якорей; `parent` — указатель.
- **События.** Поворот — передача якорей между полями ([передача якоря](layout.md#якорь-anchor)).
- **FLOW.** Время жизни; закон `left == null || left!.parent == self` локален.
- **Z3.** Порядок ключей по всему поддереву.
- **Не закрыто.** Обход рекурсией по сводному узлу грубее точного (шаг 6n Amber).

## Граф

Вершины с рёбрами в обе стороны и циклами.

```efen
layout {
    set area Vertices: Vertex
    set area Edges: Edge

    struct Edge {
        var to: Vertices.Item                    // указатель
        var next: anchor Edges.Item? = null      // список рёбер вершины
    }

    struct Vertex {
        var edges: anchor Edges.Item? = null
    }
}
```

- **Владение.** Вершинами владеет граф (множество `Vertices` у его держателя), рёбрами — список рёбер вершины. Ребро
  к вершине — указатель: циклы только в указателях, не в якорях.
- **События.** Удаление вершины: сначала все рёбра, ведущие к ней, — иначе указатель `to` переживёт вершину.
- **FLOW.** Время жизни и полнота: к уничтожению вершины ни одно `to` на неё не указывает. Это закон о всех рёбрах
  всех вершин.
- **Z3.** Закон «никакое ребро не ведёт к удаляемой вершине» — квантор по двум множествам.
- **Не закрыто.** Входящие рёбра: чтобы удалить вершину локально, нужен обратный список входящих рёбер (указатели); без
  него закон не локален.

## Менеджер памяти mm

ОС → регион → блок → слот. Каждый уровень — множество внутри предыдущего ([переход между
множествами](layout.md#выделение-и-освобождение--переход-между-множествами)).

- **Владение.** Пул держит регион `own`, пока все блоки в нём, иначе указателем (первый `lend` блока снимает `own`
  региона). В `block_pool` блоки — места области региона; в `raw_allocator` блоки — множество `set area Blocks`,
  взятое у системы. Слоты — места области блока, выдаются `lend`. Блоки на списке класса — указатели.
- **FLOW.** Время жизни и счёт, кроме двух `assume` на снятом слоте (FLOW не знает `frontier <= slots.count`).
- **Z3.** `slots.count == PAYLOAD / SIZES[sizeClass]` — нелинейно.
- **Не закрыто.** Список блоков класса: блок на нём и `linked` — закон о двух множествах (блоки и классы).

## Сводка

| Структура | Время жизни (FLOW) | Законы (FLOW) | Z3 | Не закрыто |
|---|---|---|---|---|
| динамический массив | да | да | рост умножением | — |
| пул объектов | да | да | — | `frontier <= cells.count` |
| односвязный список | да | да | — | цикл якорей, рождение узла |
| двусвязный список | при законе о `prev` | да | `tail` | хранимые указатели |
| LRU | при законе о `older`/`newer` | да | — | хранимые указатели |
| кольцевой буфер | да | частично | диапазон по модулю | форма закона |
| хеш-таблица с цепочками | да | частично | замена корзин, удаление | цепочка с параметром |
| открытая адресация | да | частично | закон пробы | — |
| дерево с родителем | при законе о `parent` | частично | порядок ключей | цикл якорей, точность рекурсии |
| граф | нет | нет | входящие рёбра | хранимые указатели, обратный список |
| mm | да | да | `PAYLOAD / SIZES[...]` | `frontier <= slots.count` |

Время жизни FLOW выводит сам там, где каждый хранимый указатель связан законом с якорем. Где указатель ничем не связан (граф,
внешние ссылки на узлы), модели не хватает правила ([открытые вопросы](layout.md#открытые-вопросы) 2 и 3). Z3 нужен
для порядка, пробы, модуля, замены области и законов над целым множеством.
