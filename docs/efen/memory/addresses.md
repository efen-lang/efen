# Компоновка и дескрипторы памяти

[Управление памятью](index.md) · [Примеры компоновки](layout-examples/) ·
[Владение](../types/ownership.md) · [Представления](../representations.md) ·
[Efen → Viper](viper-verification-backend.md)

Статус: текущая нормативная модель. Показанный синтаксис исходного языка ещё не
реализован компилятором; точные сигнатуры операций дескрипторов памяти остаются
кандидатами программного интерфейса при зафиксированной ниже семантике.

Безопасность памяти обязательна независимо от пользовательских условий:
компилятор всегда проверяет происхождение, живость, инициализацию, границы и
права доступа. Достижимость, форма графа, согласованность счётчиков и завершение
обхода проверяются отдельно. Если от них зависит
безопасность операции, недоказанное свойство блокирует компиляцию.

## Три уровня

Логический тип задаёт наблюдаемый смысл. Для `Array<Element, R>` это порядок
элементов, `count`, чтение и замена элемента по индексу.

Аспект `representation` выбирает `layout` памяти и реализует
операции конкретного типа.

Блок `layout` описывает:

- структуры, входящие в представление;
- количество и расположение их экземпляров;
- ссылки между ними;
- условия допустимого состояния;
- происхождение указателей и время их жизни.

Источник памяти — оперативная память, файл, графический процессор или другой
ресурс — может быть связан с дескрипторами позднее. Точная модель `source` пока
отложена.

## `Target`, `Self` и `self`

Логический тип передаёт аспекту представления исходный тип элемента:

```efen
struct Array {
    generic Element: Type
    generic R<Target>: Representation<Target>

    conforms IndexedSequence<Element>
    use R<Element>
}
```

Для `Array<User, List>`:

```text
Target = User
Self   = Array<User, List>
```

`Target` является явным обобщённым параметром аспекта. Компилятор связывает
`Self` с конкретным строящимся `Array`, внутри которого применяется
`use R<Element>`. `self` — текущий экземпляр `Self` во время выполнения.

```efen
aspect List<Target> conforms Representation<Target> {
    layout {
        // Структуры и дескрипторы памяти Self.
    }

    implementation {
        // Конструкторы и операции над self.
    }
}
```

`implementation Target` не используется: `Target` обозначает тип элемента, а
не строящийся массив.

## Структуры и дескрипторы

`struct` задаёт форму одного значения. Он не сообщает, сколько таких значений
существует и где они размещены.

`set`, `one`, `area` и `set area` называются дескрипторами памяти:

- `one` — один экземпляр структуры;
- `set` — множество экземпляров без обещания непрерывности;
- `area` — одна непрерывная область элементов одной формы;
- `set area` — множество независимых непрерывных областей.

Неоднородная область сможет перечислять допустимые типы, но её точный синтаксис
ещё не утверждён.

```efen
layout {
    set Items: Item
    one Header

    struct Item {
        // Форма одного элемента.
    }

    struct Header {
        // Форма отдельного одиночного объекта.
    }
}
```

Дескрипторы принято группировать в начале блока `layout`. Порядок не влияет на
разрешение имён: весь блок является общей декларативной областью.

Если корнем представления является сам тип, к которому применён аспект,
отдельный `one` не нужен:

```efen
layout {
    set Items: Item

    struct Item {
        Target
        var next: own other Items.Item? = null
    }

    struct Self {
        var head: own Items.Item? = null
        var length: Size = 0
    }
}
```

`struct Self` определяет поля конкретного представляемого значения.
`implementation` обязана предоставить явный конструктор, который
инициализирует эти поля.

## Производные типы дескриптора

`Items.Item` — типизированный указатель на отдельный элемент, управляемый
`Items`. Он сохраняет происхождение из конкретного дескриптора и конкретного
экземпляра `layout`.

`Items.Area` — типизированный указатель на начало одной непрерывной области
`Item`.
Это чистый указатель. Он не хранит:

- ёмкость выделенной области;
- число инициализированных мест;
- длину логической коллекции;
- таблицу частичной инициализации.

Эти значения находятся в обычных полях `Self`, `Chunk` или локальных
переменных подготовки:

```efen
struct Self {
    var root: own Items.Area? = null

    var capacity: Size = 0 {
        (value == 0) == (self.root == null)
    }

    var length: Size = 0 {
        value == Items.count
        value <= self.capacity
    }
}
```

При нулевой ёмкости используется `root == null`; область нулевого размера не
выделяется.

Логический диапазон `root[0..<0]` пуст и не разыменовывает `root`, поэтому он
допустим при `root == null`. Любой непустой диапазон требует ненулевого
корневого указателя и доказанной границы выделенной области.

## Операции дескриптора

Операции выделения принадлежат дескриптору памяти, а не `struct Item`:

```efen
Items.allocate(value: own Item) -> own Items.Item
Items.free(item: own Items.Item)

Items.allocateArea(capacity: Size) -> own Items.Area

Items.reallocateArea(
    root: &own Items.Area?,
    oldCapacity: Size,
    initializedCount: Size,
    newCapacity: Size
)

Items.free(
    root: own Items.Area,
    capacity: Size,
    initializedCount: Size
)

Items.at(root: Items.Area, index: Size) -> Items.Item
Items.initialize(
    root: Items.Area,
    index: Size,
    value: own Item
)
Items.extract(root: Items.Area, index: Size) -> Item
Items.move(
    from: Items.Area,
    fromIndex: Size,
    to: Items.Area,
    toIndex: Size
)
```

`Items.allocate` сообщает, в каком множестве появляется отдельный элемент.
`Item.allocate` было бы недостаточно: одна форма `Item` может использоваться
двумя разными дескрипторами памяти.

`Items.at` требует доказательства, что место существует и инициализировано.
Граница берётся из явных полей вызывающей структуры, а не из `Area`.

`Items.initialize` создаёт живой элемент в пустом месте. `Items.extract`
переносит `Item` наружу и оставляет место пустым. `Items.move` требует живой
источник и пустое назначение. Временные незаполненные места отслеживаются
проверочным представлением и не создают скрытой таблицы во время выполнения.

## Происхождение и разные множества

```efen
set Items: Item
set OtherItems: Item
```

`Items.Item` и `OtherItems.Item` несовместимы, даже если имеют одинаковое
машинное представление. Компилятор знает:

- дескриптор памяти;
- экземпляр `layout`;
- жив ли элемент;
- какие права доступны;
- можно ли передать указатель менеджеру памяти.

Сырой адрес не приобретает принадлежность к множеству приведением типа. Память
от внешнего интерфейса или системного распределителя требует отдельно
проверенной операции приёма. Бесплатно забыть дескриптор у живой ссылки и затем
принять адрес в другое множество нельзя.

## Поле и физическое встраивание

Обычное поле является логическим местом:

```efen
struct Item {
    var value: Target
}
```

Представление поля может хранить указатель, индекс или другую косвенную форму.
Эта запись не обещает, что байты `Target` входят в `Item`.

Голое имя типа физически встраивает его в объявленную позицию:

```efen
struct Item {
    var tag: UInt32
    Target
    var next: own other Items.Item? = null
}
```

`Target` здесь расположен после `tag`. Если он стоит первым, `Item`
начинается с `Target`.

Выражение `item.Target` обозначает встроенное место целиком:

```efen
let copy: Target = item.Target
let borrow = &item.Target
let moved: Target = take item.Target
item.Target = take replacement
```

Создание структуры с уже существующим `Target` требует копирования при `Copyable`
или явного переноса:

```efen
Items.allocate(
    Item(take value, next: null)
)
```

После `take item.Target` менеджер памяти получает состояние частичной инициализации.
`Items.free(take item)` освобождает память узла, не уничтожая перенесённый
`Target` повторно.

## Декларативные условия

Блок после `var` описывает допустимое значение свойства. `value` означает
значение именно этого свойства:

```efen
var length: Size = 0 {
    value == Items.count
}
```

Условие после `set` применяется к каждому элементу:

```efen
set Items: Item {
    value reachable from self.head by Item.next
}
```

`reachable` — логическое рефлексивное отношение пути. Оно не запускает обход во
время выполнения.

Обычный `if` внутри условия означает импликацию:

```efen
var tail: read Items.Item? = null {
    (self.head == null) == (value == null)

    if value != null {
        value reachable from self.head by Item.next
        value.next == null
    }
}
```

Несколько выражений одного блока соединяются логическим `&&`.

Компилятор выводит зависимости условия из прочитанных мест. Операция может
временно нарушить затронутое условие между соседними безотказными шагами, но
обязана восстановить его перед:

- `return`;
- `throw`;
- приостановкой;
- вызовом кода, способного обратиться к изменяемой структуре;
- публикацией ссылки на изменяемое состояние.

В исходной программе не нужны отдельный блок доказательства и вспомогательная
копия структуры. Проверяющий модуль может создавать такое состояние в
промежуточном представлении.

## Перевыделение области и корневой указатель

Динамическая структура хранит корневой указатель и служебные поля раздельно:

```efen
struct Self {
    var root: own Items.Area? = null
    var capacity: Size = 0
    var length: Size = 0
}
```

Рост вызывает:

```efen
Items.reallocateArea(
    root: &self.root,
    oldCapacity: self.capacity,
    initializedCount: self.length,
    newCapacity: nextCapacity
)
self.capacity = nextCapacity
```

Дескриптор памяти получает место поля `root` и может изменить указатель. Он
может расширить область на месте либо выделить новую, перенести
`initializedCount` элементов, заменить корневой указатель и освободить старый
блок.

Сильная гарантия при ошибке:

- при ошибке корневой указатель, служебные поля, состав множества и значения
  остаются прежними;
- `newCapacity < initializedCount` отвергается до изменения;
- после успеха логический порядок значений сохранён;
- указатели `Items.Item` на элементы старой области могут стать
  недействительными.

Поэтому живой указатель, индекс или заимствование перемещаемого места блокирует
перевыделение. Сама операция получает право изменить единственный владеющий
корневой указатель через `&self.root`.

Между успешной заменой корневого указателя и записью новой ёмкости условие
временно открыто. Там запрещены исключения, приостановка и вызовы кода,
способного обратиться к изменяемой структуре.

## Владение, живость и доступ

`own` означает обязанность уничтожить значение или передать эту обязанность.
`read` и `write` являются отдельными правами доступа.

Чтение владеющего места не переносит владение:

```efen
let borrowed = self.head
let owned = take self.head!
```

Первая строка получает невладеющий доступ. Вторая переносит владельца и
оставляет исходное место пустым.

Перед разыменованием компилятор проверяет:

1. указатель происходит из ожидаемого дескриптора и экземпляра `layout`;
2. элемент ещё жив;
3. нужный компонент инициализирован;
4. индекс находится в доказанной границе выделенной области;
5. доступны требуемые права.

`Items.free` отдельного элемента требует `own Items.Item`.
`Items.free` области требует владеющий корневой указатель, ёмкость и
`initializedCount`.
Освобождение уничтожает каждый живой компонент ровно один раз.

Живое заимствование блокирует удаление элемента, перемещение его физического
места и уничтожение экземпляра `layout`. Перемещение всего `Self` допустимо
только тогда, когда представление ссылок сохраняет их смысл либо живых зависимых
ссылок нет.

## Обход и завершение

Переход по `next` безопасен, если указатель жив, поле инициализировано и доступны
права чтения. Из этого не следует завершение обхода.

Условие:

```efen
value reachable from self.head by Item.next
```

говорит о существовании конечного пути к конкретному `value`. Для общего цикла
дополнительно требуется доказать, что повторов нет либо что число шагов
ограничено явным счётчиком.

Тестирование конечного числа списков и превышение времени ожидания проверяющего
модуля не являются доказательством. Превышение времени означает «не доказано».

## Частичная инициализация и очистка

Конструктор непрерывного массива сохраняет служебные поля до вызова
пользовательской функции:

```efen
self.root = null
self.capacity = count
self.length = 0

if count > 0 {
    self.root = Items.allocateArea(capacity: count)
}
```

После каждого успешного `Items.initialize` увеличивается `length`. Если
следующая операция бросает исключение, код очистки получает точные значения:

```efen
if self.root != null {
    Items.free(
        root: take self.root!,
        capacity: self.capacity,
        initializedCount: self.length
    )
}
```

`Area` ничего не знает о префиксе; правильность уничтожения зависит от явно
сохранённого `length`.

Для блочного `layout` каждая структура `Chunk` хранит собственный корневой
указатель, ёмкость и длину. Уничтожение каталога сначала освобождает блок каждого
живого `Chunk`, затем сам каталог. Ни один `Target` не уничтожается второй раз.

## Граница модели

Пока не определены окончательно:

- синтаксис источника памяти `source`;
- неоднородная область;
- квантор для закона общего префикса блочного `layout`;
- конкурентный доступ к одному экземпляру `layout`;
- точное представление слабых указателей и поколений;
- массовый перенос между дескрипторами памяти;
- полный контракт проверяющего модуля и диагностики.

[Аудит старой модели](addresses-defects.md) и
[сравнение с другими системами](prior-art.md) относятся к предыдущей редакции и
сохраняются как исторические материалы. Текущие обязательства проверяющего
модуля описаны в [Efen → Viper](viper-verification-backend.md); его старые
примеры не являются нормативным синтаксисом.
