# Двусвязный список

[К примерам](README.md) · [Исходник](doubly-linked-array.efen) ·
[Пространство `layout`](../layout.md#пространство-layout)

`next` владеет продолжением цепочки, `prev` — невладеющий указатель на предыдущий узел. Связь в обе стороны
держит закон узла `next!.prev == self`.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1–2 | Параметр `T` стоит на блоке; `Nodes` — множество узлов. |
| 4–10 | `Node` хранит значение, якорь следующего узла `next` и указатель `prev`. Закон узла: у следующего узла `prev` указывает назад на этот. |
| 12–15 | `DoublyList` — тип программы. `head` — якорь первого узла, `tail` — указатель на последний, `count` читает любой код. |
| 17–23 | Законы списка: `count` равен длине цепочки; у первого узла `prev == null`; `head` и `tail` пусты вместе; на `tail` цепочка кончается. |
| 27–29 | `newNode` выделяет узел вызовом `mm.allocate(…) as Node<T>(value: take value)` с пустыми связями. Узел принадлежит вызывающему как `anchor`. |
| 31–51 | `nodeAt` идёт от ближнего конца: от `head` по `next` или от `tail` по `prev`. Результат несёт право `edit` списка. |
| 53–77 | `unlinkAt` вынимает узел из цепочки и исправляет обе связи у преемника: `head`, `prev` преемника или `tail`. Якорь вынутого узла уходит в результат. |
| 79 | Стратегия для `DoublyList<T>`; `Movable` нужен для `take`. |
| 80–91 | `pushFirst` — `edit`: узлы остаются в списке. `prev` прежней головы указывает на новый узел, `next` нового — на прежнюю голову. |
| 93–103 | `append` — `edit`: новый узел получает `prev: tail` и привязывается к `tail.next` либо к `head`. |
| 105–124 | `insert` — `edit`: узел встаёт между `before` и преемником; обе пары `next`/`prev` записываются явно. |
| 126–132 | `remove` — `mut`: узел покидает структуру. Значение снимается `take node.value`, память узла возвращает `mm.free(node as own Pointer)`. Индекс вне границ — `null`. |
| 134–141 | `replace` снимает прежнее значение и записывает новое: `take` из поля — `mut`. |
| 143–154 | `release` — ворота уничтожения. У структуры `layout` деструктора нет: код вынимает узлы по одному, обнуляет `prev` новой головы и освобождает узел. |
| 157–169 | Чтение копирует значение и требует `T: Copyable`; поля оно не пишет. |
| 171–175 | Использование. Перед выходом из области `list.release()` освобождает цепочку. |

## Законы связи

Скрытого обратного поля нет: код пишет `prev` явно, а компилятор проверяет закон узла `next!.prev == self` на каждом
выходе ворот. Закон `head == null || head!.prev == null` задаёт начало цепочки, `tail!.next == null` — конец.
Закон «`tail` — последний узел цепочки» `layout.md` полностью не называет
(в [каталоге](../layout-catalogue.md#двусвязный-список) он помечен как не закрытый); записано необходимое следствие.

Поиск имеет сложность `O(min(index + 1, count - index))`; `append` и `pushFirst` — `O(1)`.

Для связывания и освобождения действует
[общее правило безотказного окна](README.md#общее-правило-применимости).
