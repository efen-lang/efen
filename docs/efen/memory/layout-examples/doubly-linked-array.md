# Двусвязный список

[К примерам](README.md) · [Исходник](doubly-linked-array.efen) ·
[Основная модель](../addresses.md)

`next` владеет продолжением цепочки, `prev` только заимствует предыдущий
узел. Обе стороны связи проверяются декларативно.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1–5 | Аспект получает `Target`; compiler-known `chained` задаёт точную конечную цепочку всех `Items` от `head` по `next`. |
| 7–8 | `Target` физически встроен в начало `Item`. |
| 10–14 | Ненулевой `prev` обязан вести к узлу, чей `next` указывает обратно; строка 14 закрывает условие. |
| 16–21 | `next` владеет следующим `Items.Item` и симметрично требует обратный `prev`; строка 21 закрывает `Item`. |
| 23–28 | `head` владеет первым узлом, у которого `prev` обязан быть равен `null`. |
| 30–37 | `tail` пуст вместе с `head`; ненулевой `tail` достижим и завершает цепочку `next`. |
| 39–43 | Длина совпадает с `Items.count`; закрываются `Self` и `layout`. |
| 45–52 | Явный конструктор создаёт пустой `Self`. |
| 54–56 | `count` возвращает длину, сохранённую в поле `self.length`. |
| 58–61 | `itemAt` проверяет индекс до обхода. |
| 63–73 | Для первой половины поиск идёт от `head` по `next`. |
| 75–84 | Для второй половины поиск идёт от `tail` по `prev`. |
| 86–90 | `read` копирует встроенный `Target` и требует `Copyable`. |
| 92–99 | `replace` требует `Movable`; атомарная операция `replace(place, value)` устанавливает новый `Target` и возвращает прежний. |
| 101–111 | `append` требует `Movable`, вычисляет длину и вызывает allocation внутри открытой structural group. |
| 113–119 | Владеющий указатель на новый узел записывается в `head` либо прежний `tail.next`; затем `tail` сдвигается. |
| 121–122 | Поле длины обновляется после связей. |
| 124–129 | `insert` требует `Movable` и проверяет позицию. |
| 131–134 | Вставка в конец вызывает `append`. |
| 136–139 | Новый узел выделяется с пустыми связями до изъятия старого суффикса. |
| 141–151 | `head` или `before.next` передаёт владение суффиксом новому узлу; оба `prev` обновляются явно. |
| 153–154 | Обновляется поле длины. |
| 156–161 | `remove` требует `Movable` и проверяет индекс. |
| 163–184 | `victim` изымается из владеющего места; суффикс занимает это место; `head.prev`, `successor.prev` или `tail` исправляются. |
| 186–190 | Длина уменьшается, `Target` переносится наружу, узел освобождается, результат возвращается. |
| 191–192 | Закрываются `implementation` и аспект. |

`tail` остаётся изменяемым полем из-за `var`. Квалификатор `read` относится к
сохранённому `Items.Item`, а не к слоту `tail`. При записи `tail!.next` указатель
задаёт identity и origin цели, а необходимое `write`-право предоставляет
реализация layout. Сам `read`-указатель такого права не создаёт.

Скрытого `inverse` нет: код явно пишет `prev`, а компилятор доказывает условия
обеих связей. `chained` создаёт конечный order, точно совпадающий с `Items`;
tail-condition отдельно связывает `tail` с последним узлом.

Owning `Item(take value, ...)` и fallible allocation сначала полностью
завершаются при закрытом layout, оставляя внутренний provisional resource. Затем
compiler открывает полную SCC: membership/`Items.count`, ghost order и
`chained`, `head`, `tail`, `length`, затронутые `next`/`prev`, owner-place
`head`/`next` и двустороннее отношение. Origin, live, initialization, unique
`Own` и отсутствие dangling strong target не открываются. Внутри group compiler
безотказно публикует provisional item, восстанавливает обе связи и служебные поля,
затем закрывает её. Failure подготовки/allocation происходит раньше и сохраняет
старый закрытый список. Открытое окно не содержит call, safepoint, suspension или
reentry; representation обязана доказать refinement publish, иначе операция
отклоняется. Новый surface provisional API не вводится.

Поиск имеет сложность `O(min(index + 1, length - index))`; `append` — `O(1)`.
