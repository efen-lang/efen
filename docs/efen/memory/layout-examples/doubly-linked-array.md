# Двусвязный список

[К примерам](README.md) · [Исходник](doubly-linked-array.efen) ·
[Пространство `layout`](../layout-reference.md#пространство-layout)

`next` владеет продолжением цепочки, `prev` хранит невладеющий указатель на предыдущий узел. Связь в обе стороны
задаёт инвариант узла `next!.prev == self`.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1–2 | Параметр `T` стоит на `layout`. `Nodes` объявлено множеством узлов. |
| 4–10 | `Node` хранит значение, якорь следующего узла `next` и указатель `prev`. У обоих связей значение по умолчанию `null`: приведение `as Node<T>(value: …)` записывает его. Инвариант узла: у следующего узла `prev` указывает назад на этот. |
| 12–15 | `DoublyList` — тип программы. `head` — якорь первого узла, `tail` — указатель на последний, `count` читает любой код. |
| 17–23 | Инварианты списка: `count` равен длине цепочки; у первого узла `prev == null`; `head` и `tail` пусты вместе; `tail` равен последнему узлу цепочки (`tail == nodes.last`). |
| 27–29 | `newNode` выделяет узел вызовом `mm.allocate(…) as Node<T>(value: take value)`; `next` и `prev` получают `null` по умолчанию поля. `mm.allocate` бросает `AllocationError` до любой связи. Узел принадлежит вызывающему как `anchor`. |
| 31–51 | `nodeAt` идёт от ближнего конца: от `head` по `next` или от `tail` по `prev`. Результат несёт право `edit` списка; его вызывает `insert`. |
| 53–73 | `nodeAtMut` — тот же обход при `list: mut`, результат несёт право `mut`. Указатель берёт право значения, через которое получен ([откуда право на элемент](../layout-reference.md#пространство-layout)), поэтому узел, который уходит из списка или чьё значение снимается, достаётся через `mut`-параметр. |
| 75–99 | `unlinkAt` — помощник с параметром `list: mut`. Он вынимает узел из цепочки и исправляет обе связи у преемника: `head`, `prev` преемника или `tail`. `before` получен от `nodeAtMut`, поэтому право на уход узла из структуры у него есть. Якорь вынутого узла уходит в результат. |
| 101 | Стратегия для `DoublyList<T>`; `Movable` нужен для `take`. |
| 102–113 | `pushFirst` — `edit`: узлы остаются в списке. `prev` прежней головы указывает на новый узел, `next` нового — на прежнюю голову, `prev` нового равен `null` по умолчанию. |
| 115–125 | `append` требует `edit`: новый узел получает `prev: tail` и привязывается к `tail.next` либо к `head`; его `next` равен `null` по умолчанию. Строка `tail = node` после `tie node` допустима: имя `node` остаётся невладеющим указателем на узел ([перенос владения](../layout-reference.md#64-перенос-владения), правило 1). |
| 127–146 | `insert` — `edit`: узел встаёт между `before` и преемником; обе пары `next`/`prev` записываются явно. |
| 148–154 | `remove` — `mut`: узел покидает структуру. Значение снимается `take node.value`, память узла возвращает `mm.free(node as own Pointer)`. Индекс вне границ — `null`. |
| 156–161 | `replace` — `mut`: компилятору известная операция `replace(node.value, take value)` отдаёт прежнее значение и записывает новое одной операцией. |
| 163–176 | `release` служит публичной функцией уничтожения. Она уничтожает элементы типа `T`, поэтому требует `T conforms ImplicitlyDestroyable \|\| count == 0`: при любом другом `T` вызывающий сначала забирает элементы, и пустая структура возвращает память. У структуры из `layout` деструктора нет: код сначала обнуляет `tail`, чтобы к освобождению узла не оставалось хранимого указателя на него, затем вынимает узлы по одному, обнуляет `prev` новой головы и освобождает узел. |
| 179–191 | Чтение возвращает копию значения, написанную словом `copy`, и требует `T: Copyable`; поля оно не пишет. |
| 193–197 | Использование. `defer list.release()` стоит сразу после создания и освобождает цепочку на каждом пути, в том числе при исключении из `append`. |

## Инварианты связи

Скрытого обратного поля нет: код пишет `prev` явно, а компилятор проверяет инвариант узла `next!.prev == self` на
каждом выходе публичной функции. Инвариант `head == null || head!.prev == null` задаёт начало цепочки, инвариант
`tail == nodes.last` задаёт её конец ([цепочка](../layout-reference.md#52-цепочка)).

Поиск имеет сложность `O(min(index + 1, count - index))`; `append` и `pushFirst` — `O(1)`.

Для связывания и освобождения действует
[общее правило безотказного окна](README.md#общее-правило-применимости).
