# Двусвязный список

[К примерам](README.md) · [Исходник](doubly-linked-array.efen) ·
[Пространство `layout`](../layout.md#пространство-layout)

`next` владеет продолжением цепочки, `prev` — невладеющий указатель на предыдущий узел. Связь в обе стороны
держит закон узла `next!.prev == self`.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1–2 | Параметр `T` стоит на блоке; `Nodes` — множество узлов. |
| 4–10 | `Node` хранит значение, якорь следующего узла `next` и указатель `prev`. У обоих связей значение по умолчанию `null`: приведение `as Node<T>(value: …)` записывает его. Закон узла: у следующего узла `prev` указывает назад на этот. |
| 12–15 | `DoublyList` — тип программы. `head` — якорь первого узла, `tail` — указатель на последний, `count` читает любой код. |
| 17–23 | Законы списка: `count` равен длине цепочки; у первого узла `prev == null`; `head` и `tail` пусты вместе; на `tail` цепочка кончается. |
| 27–29 | `newNode` выделяет узел вызовом `mm.allocate(…) as Node<T>(value: take value)`; `next` и `prev` получают `null` по умолчанию поля. `mm.allocate` бросает `AllocationError` до любой связи. Узел принадлежит вызывающему как `anchor`. |
| 31–51 | `nodeAt` идёт от ближнего конца: от `head` по `next` или от `tail` по `prev`. Результат несёт право `edit` списка; его вызывает `insert`. |
| 53–73 | `nodeAtMut` — тот же обход при `list: mut`, результат несёт право `mut`. Указатель берёт право значения, через которое получен ([откуда право на элемент](../layout.md#пространство-layout)), поэтому узел, который уходит из списка или чьё значение снимается, достаётся через `mut`-параметр. |
| 75–99 | `unlinkAt` — помощник с параметром `list: mut`. Он вынимает узел из цепочки и исправляет обе связи у преемника: `head`, `prev` преемника или `tail`. `before` получен от `nodeAtMut`, поэтому право на уход узла из структуры у него есть. Якорь вынутого узла уходит в результат. |
| 101 | Стратегия для `DoublyList<T>`; `Movable` нужен для `take`. |
| 102–113 | `pushFirst` — `edit`: узлы остаются в списке. `prev` прежней головы указывает на новый узел, `next` нового — на прежнюю голову, `prev` нового равен `null` по умолчанию. |
| 115–125 | `append` — `edit`: новый узел получает `prev: tail` и привязывается к `tail.next` либо к `head`; его `next` равен `null` по умолчанию. |
| 127–146 | `insert` — `edit`: узел встаёт между `before` и преемником; обе пары `next`/`prev` записываются явно. |
| 148–154 | `remove` — `mut`: узел покидает структуру. Значение снимается `take node.value`, память узла возвращает `mm.free(node as own Pointer)`. Индекс вне границ — `null`. |
| 156–161 | `replace` — `mut`: компилятору известная операция `replace(node.value, take value)` отдаёт прежнее значение и записывает новое одной операцией. |
| 163–176 | `release` — публичная функция уничтожения. Она уничтожает элементы типа `T`, поэтому несёт `requires T conforms ImplicitlyDestroyable`. У структуры `layout` деструктора нет: код сначала обнуляет `tail`, чтобы к освобождению узла не оставалось хранимого указателя на него, затем вынимает узлы по одному, обнуляет `prev` новой головы и освобождает узел. |
| 179–191 | Чтение копирует значение и требует `T: Copyable`; поля оно не пишет. |
| 193–197 | Использование. `defer list.release()` стоит сразу после создания и освобождает цепочку на каждом пути, в том числе при исключении из `append`. |

## Законы связи

Скрытого обратного поля нет: код пишет `prev` явно, а компилятор проверяет закон узла `next!.prev == self` на каждом
выходе публичной функции. Закон `head == null || head!.prev == null` задаёт начало цепочки, `tail!.next == null` — конец.
Закон «`tail` — последний узел цепочки» `layout.md` полностью не называет
(в [каталоге](../layout-catalogue.md#двусвязный-список) он помечен как не закрытый); записано необходимое следствие.

Поиск имеет сложность `O(min(index + 1, count - index))`; `append` и `pushFirst` — `O(1)`.

Для связывания и освобождения действует
[общее правило безотказного окна](README.md#общее-правило-применимости).
