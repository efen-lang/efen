# Двусвязный список

[К примерам](README.md) · [Исходник](doubly-linked-array.efen) ·
[Основная модель](../addresses.md)

`next` владеет продолжением цепочки, `prev` только заимствует предыдущий
узел. Обе стороны связи проверяются декларативно.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1–5 | Аспект получает `Target`; `Items` содержит узлы, достижимые из `head` по `next`. |
| 7–8 | `Target` физически встроен в начало `Item`. |
| 10–14 | Ненулевой `prev` обязан вести к узлу, чей `next` указывает обратно; строка 14 закрывает условие. |
| 16–21 | `next` владеет следующим `Items.Item` и симметрично требует обратный `prev`; строка 21 закрывает `Item`. |
| 23–28 | `head` владеет первым узлом, у которого `prev` обязан быть равен `null`. |
| 30–37 | `tail` пуст вместе с `head`; ненулевой `tail` достижим и завершает цепочку `next`. |
| 39–43 | Длина совпадает с `Items.count`; закрываются `Self` и `layout`. |
| 45–52 | Явный конструктор создаёт пустой `Self`. |
| 54–56 | `count` возвращает длину, сохранённую в поле `self.length`. |
| 58–61 | `itemAt` проверяет индекс до обхода. |
| 63–73 | Для первой половины поиск идёт от `head` по `next`. |
| 75–84 | Для второй половины поиск идёт от `tail` по `prev`. |
| 86–90 | `read` копирует встроенный `Target` и требует `Copyable`. |
| 92–97 | `replace` переносит прежний `Target` и немедленно заполняет место новым. |
| 99–107 | `append` вычисляет длину и выделяет новый узел до изменения цепочки. |
| 109–115 | Владеющий указатель на новый узел записывается в `head` либо прежний `tail.next`; затем `tail` сдвигается. |
| 117–118 | Поле длины обновляется после связей. |
| 120–123 | `insert` проверяет позицию. |
| 125–128 | Вставка в конец вызывает `append`. |
| 130–133 | Новый узел выделяется с пустыми связями до изъятия старого суффикса. |
| 135–145 | `head` или `before.next` передаёт владение суффиксом новому узлу; оба `prev` обновляются явно. |
| 147–148 | Обновляется поле длины. |
| 150–153 | `remove` проверяет индекс. |
| 155–176 | `victim` изымается из владеющего места; суффикс занимает это место; `head.prev`, `successor.prev` или `tail` исправляются. |
| 178–182 | Длина уменьшается, `Target` переносится наружу, узел освобождается, результат возвращается. |
| 183–184 | Закрываются `implementation` и аспект. |

Скрытого `inverse` нет: код явно пишет `prev`, а компилятор доказывает условия
обеих связей. Память выделяется до изменения опубликованной цепочки.

После успешного выделения перенос `Target`, запись ссылок и служебных полей и
`Items.free` не бросают исключений, не приостанавливаются и не вызывают код,
способный обратиться к изменяемой структуре.

Поиск имеет сложность `O(min(index + 1, length - index))`; `append` — `O(1)`.
