# Двусвязный список

[К примерам](README.md) · [Исходник](doubly-linked-array.efen) ·
[Пространство `layout`](../layout/declaration.md#пространство-layout)

`next` владеет продолжением цепочки, `prev` хранит невладеющий указатель на предыдущий узел. Связь в обе стороны
задаёт инвариант узла `next!.prev == self`.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1–2 | Параметр `T` стоит на `layout`. `Nodes` объявлено множеством узлов. |
| 4–10 | `Node` хранит значение, якорь следующего узла `next` и указатель `prev`. У обоих связей значение по умолчанию `null`: приведение `as Node<T>(value: take value)` записывает его. Инвариант узла: у следующего узла `prev` указывает назад на этот. |
| 12–15 | `DoublyList` — тип программы. `head` — якорь первого узла, `tail` — указатель на последний, `count` читает любой код. |
| 17–23 | Инварианты списка: `count` равен длине цепочки; у первого узла `prev == null`; `head` и `tail` пусты вместе; `tail` равен последнему узлу цепочки (`tail == nodes.last`). |
| 27–29 | `newNode` создаёт узел формой с полями `Node<T>(value: take value)`: память даёт стратегия `Allocator` множества `Nodes`, `next` и `prev` получают `null` по умолчанию поля. Форма бросает `AllocationError` до любой связи. Узел принадлежит вызывающему как `own`. |
| 31–51 | `nodeAt` идёт от ближнего конца: от `head` по `next` или от `tail` по `prev`. Результат несёт право `edit` списка; его вызывает `insert`. |
| 53–73 | `nodeAtMut` выполняет тот же обход при `list: mut`, и слово `mut` в её результате называет право, которое указатель даёт сам. Обязательной она не служит: право на узел функция берёт из своего права на список, которому узел принадлежит ([право на элемент](../layout/functions.md#82-право-на-элемент), правила 1 и 2). |
| 75–99 | `unlinkAt` служит помощником с параметром `list: mut`. Он вынимает узел из цепочки и исправляет обе связи у преемника: `head`, `prev` преемника или `tail`. Уход узла из структуры разрешает право `mut` на список, который называет источник указателя `before` ([право на элемент](../layout/functions.md#82-право-на-элемент), правило 5). Якорь вынутого узла уходит в результат. |
| 101 | Стратегия для `DoublyList<T>`; `Movable` нужен для `take`. |
| 102–113 | `pushFirst` — `edit`: узлы остаются в списке. `prev` прежней головы указывает на новый узел, `next` нового — на прежнюю голову, `prev` нового равен `null` по умолчанию. |
| 115–125 | `append` требует `edit`: новый узел получает `prev: tail` и привязывается к `tail.next` либо к `head`; его `next` равен `null` по умолчанию. Строка `tail = node` после `tie node` допустима: имя `node` остаётся невладеющим указателем на узел ([перенос владения](../layout/operations.md#64-перенос-владения), правило 1). |
| 127–146 | `insert` — `edit`: узел встаёт между `before` и преемником; обе пары `next`/`prev` записываются явно. |
| 148–154 | `remove` — `mut`: узел покидает структуру. Значение снимается `take node.value`, затем `node as own Nodes<T>.Item` доказывает, что указателей на узел нет; в конце функции компилятор возвращает его память аллокатору ([удаление элемента](../layout/operations.md#переход-к-владению-as-own)). Индекс вне границ — `null`. |
| 156–161 | `replace` — `mut`: компилятору известная операция `replace(node.value, take value)` отдаёт прежнее значение и записывает новое одной операцией. |
| 164–178 | Память структуры возвращает `dispose`: стратегия пишет `implements Disposable`, а вызывает функцию компилятор там, где значение кончается. Она сначала обнуляет `tail`, чтобы к освобождению узла не оставалось хранимого указателя на него, затем вынимает узлы по одному, обнуляет `prev` новой головы и переводит узел в `own`: в конце шага значение узла уничтожается, а память возвращается аллокатору. В теле `dispose` условие `T conforms ImplicitlyDestroyable` верно без `requires` ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), значение структуры, правила 1 и 6). Список значений, тип которых не соответствует `ImplicitlyDestroyable`, программа опустошает сама, через `remove`. Выход из области видимости допустим, когда доказано, что `head` равен `null` ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), значение структуры, правило 4). |
| 180–192 | Чтение возвращает копию значения, написанную словом `copy`, и требует `T: Copyable`; поля оно не пишет. |
| 194–199 | Использование. В конце области видимости и на выходе через исключение из `append` компилятор вызывает `dispose`. |

## Инварианты связи

Скрытого обратного поля нет: код пишет `prev` явно, а компилятор проверяет инвариант узла `next!.prev == self` на
каждом выходе публичной функции. Инвариант `head == null || head!.prev == null` задаёт начало цепочки, инвариант
`tail == nodes.last` задаёт её конец ([цепочка](../layout/invariants.md#52-цепочка)).

Поиск имеет сложность `O(min(index + 1, count - index))`; `append` и `pushFirst` — `O(1)`.

Для связывания и освобождения действует
[общее правило безотказного окна](README.md#общее-правило-применимости).
