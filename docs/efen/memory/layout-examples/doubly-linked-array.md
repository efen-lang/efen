# Двусвязный список

[К примерам](README.md) · [Исходник](doubly-linked-array.efen) ·
[Основная модель](../addresses.md)

`next` владеет продолжением цепочки, `prev` только заимствует предыдущий
узел. Обе стороны связи проверяются декларативно.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1–4 | Аспект получает `Target`; `set Items: Item` задаёт множество узлов без блока условий, форму цепочки говорят законы `invariants`. |
| 6–7 | `Target` физически встроен в начало `Item`. |
| 9 | `prev` — невладеющий указатель на предыдущий узел; блока `{ }` нет, обратная связь записана в `invariants`. |
| 10–11 | `next` владеет следующим `Items.Item`; строка 11 закрывает `Item`. |
| 13–15 | `head` владеет первым узлом, `tail` указывает на последний; условий `{ }` у них нет. |
| 16 | `length` — длина времени выполнения, условие у неё в `invariants`. |
| 17 | Призрачное поле `nodes` хранит узлы по порядку; при выполнении его нет, меняют его только строки `ghost`. |
| 19–28 | `invariants`: `head` — первый элемент `nodes`; `next` каждого — следующий, а `prev` следующего — он сам; у последнего `next == null`, у первого `prev == null`; `nodes.count == Items.count`; `tail` — последний; `length == nodes.count`. |
| 29–32 | Закрываются `Self` и `layout`, начинается `implementation`. |
| 33–39 | Явный конструктор создаёт пустой `Self`; `nodes` пуста. |
| 41–43 | `count` возвращает длину, сохранённую в поле `self.length`. |
| 45–48 | `itemAt` проверяет индекс до обхода. |
| 50–60 | Для первой половины поиск идёт от `head` по `next`. |
| 62–71 | Для второй половины поиск идёт от `tail` по `prev`. |
| 73–77 | `read` копирует встроенный `Target` и требует `Copyable`. |
| 79–86 | `replace` требует `Movable`; атомарная операция `replace(place, value)` устанавливает новый `Target` и возвращает прежний. |
| 88–98 | `append` требует `Movable`, вычисляет длину и вызывает allocation внутри открытой structural group. |
| 99 | `ghost nodes = nodes + Sequence(item)` дописывает новый узел в конец `nodes`, пока `item` ещё у функции. |
| 101–107 | Владеющий указатель на новый узел записывается в `head` либо прежний `tail.next`; затем `tail` сдвигается. |
| 109–110 | Поле длины обновляется после связей. |
| 112–117 | `insert` требует `Movable` и проверяет позицию. |
| 119–122 | Вставка в конец вызывает `append`. |
| 124–127 | Новый узел выделяется с пустыми связями до изъятия старого суффикса. |
| 128 | Ghost-строка вставляет узел в `nodes` на место `index`: префикс, `Sequence(item)`, суффикс. |
| 130–140 | `head` или `before.next` передаёт владение суффиксом новому узлу; оба `prev` обновляются явно. |
| 142–143 | Обновляется поле длины. |
| 145–150 | `remove` требует `Movable` и проверяет индекс. |
| 152–153 | Ghost-строка убирает элемент `index` из `nodes` (префикс и суффикс без него) до того, как `victim` изъят из списка. |
| 155–174 | `victim` изымается из владеющего места; суффикс занимает это место; `head.prev`, `successor.prev` или `tail` исправляются. |
| 176–180 | Длина уменьшается, `Target` переносится наружу, узел освобождается, результат возвращается. |
| 181–182 | Закрываются `implementation` и аспект. |

`tail` остаётся изменяемым полем из-за `var`. Квалификатор `read` относится к
сохранённому `Items.Item`, а не к слоту `tail`. При записи `tail!.next` указатель
задаёт identity и origin цели, а необходимое право `mut` на layout предоставляет
реализация layout. Сам `read`-указатель такого права не создаёт.

Скрытого `inverse` нет: код явно пишет `prev`, а компилятор доказывает законы
обеих связей в `invariants`: `nodes[i].next == nodes[i + 1]` и
`nodes[i + 1].prev == nodes[i]`, а на концах `nodes.last!.next == null` и
`nodes.first!.prev == null`. Призрачная последовательность `nodes` точно
совпадает с `Items`; закон `tail == nodes.last` отдельно связывает `tail` с
последним узлом. Операции `append`, `insert` и `remove` одной строкой
`ghost nodes = …` держат последовательность в ногу с узлами.

Owning `Item(take value, ...)` и fallible allocation сначала полностью
завершаются при закрытом layout, оставляя внутренний provisional resource. Затем
compiler открывает полную SCC: membership/`Items.count`, ghost-последовательность
`nodes`, `head`, `tail`, `length`, затронутые `next`/`prev`, owner-place
`head`/`next` и двустороннее отношение. Origin, live, initialization, unique
`Own` и отсутствие dangling strong target не открываются. Внутри group compiler
безотказно публикует provisional item, восстанавливает обе связи и служебные поля,
затем закрывает её. Failure подготовки/allocation происходит раньше и сохраняет
старый закрытый список. Открытое окно не содержит call, safepoint, suspension или
reentry; representation обязана доказать refinement publish, иначе операция
отклоняется. Новый surface provisional API не вводится.

Поиск имеет сложность `O(min(index + 1, length - index))`; `append` — `O(1)`.
