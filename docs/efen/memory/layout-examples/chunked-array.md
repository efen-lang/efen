# Массив из блоков

[К примерам](README.md) · [Исходник](chunked-array.efen) ·
[Пространство `layout`](../layout.md#пространство-layout)

Значения `T` лежат в блоках — областях `Items`. Каталог — область `Chunks` из структур `Chunk`: каждая хранит
владеющую ссылку на свой блок и число занятых в нём элементов. Рост каталога переносит только структуры `Chunk`;
блоки `Items` остаются на месте.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1 | Размер блока известен во время компиляции. |
| 3–5 | Параметр `T` стоит на блоке. `Items` — элементы формы `T`, `Chunks` — элементы формы `Chunk`. |
| 7–10 | `Chunk` владеет одним блоком (`root`) ёмкостью `CHUNK_SIZE`; `length` — число занятых элементов блока, они идут с начала. |
| 12 | Тип программы — именованная структура блока. |
| 13–15 | Каталог `directory` допускает `null`, его ёмкость и число записей хранятся отдельно: область их не хранит. |
| 16 | `count` — общая длина, её читает любой код. |
| 18–22 | Законы: блоков хватает на `count` элементов, а длина каждого блока определена общей длиной (закон общего префикса, ниже). |
| 26–45 | `growDirectory` растёт геометрически. Выделение идёт до изменения каталога. Записи `Chunk` переносятся `take` из старого каталога в новый, старая область возвращается `mm.free`. |
| 47–55 | `ensureChunks` добавляет недостающие блоки по одному: ёмкость каталога, затем блок `CHUNK_SIZE` элементов, затем запись `Chunk` в неинициализированный элемент каталога и рост `directoryLength`. |
| 57–60 | `movePosition` переносит значение между логическими позициями: `take` из элемента одного блока и запись в неинициализированный элемент другого. |
| 62 | Стратегия для `ChunkedArray<T>`; `Movable` нужен для `take`. |
| 63–69 | `append` — `mut`: `ensureChunks` может перевыделить каталог. Запись в неинициализированный элемент блока, затем длина блока и общая длина. |
| 71–86 | `insert` готовит блоки, сдвигает суффикс справа налево, записывает значение в освободившийся элемент. Длина растёт у блока прежнего логического конца (`end`). |
| 88–100 | `remove` возвращает `own T?`, как `remove` списков и контракт [`ResizableSequence`](array-contracts.md): индекс вне границ даёт `null`. Дальше элемент снимается, суффикс сдвигается слева направо, уменьшаются длина последнего занятого блока и общая длина. |
| 102–108 | `replace` снимает прежнее значение и записывает новое. |
| 110–131 | `release` — публичная функция уничтожения. Она уничтожает элементы типа `T`, поэтому несёт `requires T conforms ImplicitlyDestroyable`. У структуры `layout` деструктора нет: код снимает занятые элементы каждого блока, возвращает блоки, затем каталог, и обнуляет счётчики. |
| 134–140 | Чтение копирует элемент и требует `T: Copyable`. |
| 142–146 | Использование: `defer a.release()` стоит сразу после создания и освобождает каталог и блоки на каждом пути, в том числе при исключении из `append`. |

## Закон общего префикса

Для каждого индекса каталога `0 <= i < directoryLength`:

```text
directory[i].length = min(CHUNK_SIZE, max(0, count - i * CHUNK_SIZE))
```

Это строка 20–21 блока `invariants`. Блоков хватает: `count <= directoryLength * CHUNK_SIZE`. Хвост каталога после
последнего занятого блока допустим, у его записей `length == 0`. Занятые элементы блока — `0 ..< length`,
остальные не инициализированы. Закон держат записи длин в `append`, `insert` и `remove`; направление сдвигов доказывает порядок.

## Ошибки и очистка

`mm.allocate` бросает `AllocationError`. В `ensureChunks` два выделения: каталога (в `growDirectory`) и блока.
Блок нельзя выделить раньше каталога без очистки: если второе выделение бросит, первое останется локальным значением
`own`, а формы очистки локального выделения `layout.md` не даёт. Поэтому первой идёт публикация каталога, она
оставляет законы верными, и бросок выделения блока застаёт структуру в состоянии, где законы держатся
([точки восстановления закона](../layout.md#законы-и-цепочки), [правило README](README.md#общее-правило-применимости)).
Выделение блока стоит последним перед публикацией записи `Chunk`, и `root: take block` передаёт блок записи без
промежуточного выхода. Исключение из `append` оставляет массив целым, возможно с лишним пустым блоком в конце
каталога: у такой записи `length == 0`, закон общего префикса её допускает. Освобождает массив `defer a.release()`.

Индексирование имеет сложность `O(1)`, `append` — амортизированную `O(1)`, `insert` и `remove` — `O(count - index)`.

Для сдвигов, публикации блока и очистки действует
[общее правило безотказного окна](README.md#общее-правило-применимости).
