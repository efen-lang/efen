# Массив из блоков

[К примерам](README.md) · [Исходник](chunked-array.efen) ·
[Пространство `layout`](../layout/declaration.md#пространство-layout)

Значения `T` хранятся в блоках, областях `Area<T>`. Каталог — область `Area<Chunk>` из структур `Chunk`: каждая
хранит владеющую ссылку на свой блок и число занятых в нём элементов. Рост каталога переносит только структуры
`Chunk`; блоки остаются на месте.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1 | Размер блока известен во время компиляции. |
| 3 | Параметры `T` и `A` стоят на `layout`. Блок — область `Area<T>`, каталог — область `Area<Chunk>`. `A` — аллокатор обеих областей с ограничением `memory::Allocator`, по умолчанию `mm` ([коллекция и её аллокатор](../allocator.md#коллекция-и-её-аллокатор)). |
| 4–8 | `Chunk` владеет одним блоком (`root`) ёмкостью `CHUNK_SIZE`; `length` — число занятых элементов блока, они идут с начала: `root.initialized == length`. |
| 10 | Типом программы служит именованная структура из `layout`. |
| 11–15 | Каталог `directory` допускает `null` ровно при нулевой ёмкости; его ёмкость и число записей хранятся отдельно: область их не хранит. |
| 16 | `count` — общая длина, её читает любой код. |
| 17 | `set Elements: directory[_].root[_]` говорит, что элементы массива — слоты блоков; записи `Chunk` каталога в множество не входят ([множества и области](../layout/declaration.md#множества-и-области), правило 14). `a[_]` значит `a.Elements`. |
| 19–24 | Инварианты: в каталоге заняты записи `0 ..< directoryLength`, блоков хватает на `count` элементов, у каждой записи каталога есть блок, а длина каждого блока определена общей длиной (инвариант общего префикса, ниже). |
| 28–48 | `growDirectory` растёт геометрически. Память под новый каталог он берёт у `A` и приводит к области из `next` записей до изменения каталога. Записи `Chunk` переносятся `take` из старого каталога в новый; в старой области не остаётся инициализированных слотов, и код возвращает её память тому же `A` (`A.deallocate(ptr: old as Pointer)`). |
| 50–59 | `ensureChunks` добавляет недостающие блоки по одному: ёмкость каталога, затем память блока `CHUNK_SIZE` элементов у `A` и приведение к области, затем запись `Chunk` в неинициализированный элемент каталога и рост `directoryLength`. |
| 61–64 | `movePosition` переносит значение между логическими позициями: `take` из элемента одного блока и запись в неинициализированный элемент другого. |
| 66–67 | Стратегия для `ChunkedArray<T, A>`; `Movable` нужен для `take`. Стратегия соответствует `Appendable`: `v[] = x` вызывает `append`. |
| 69–75 | `append` — `edit`: `ensureChunks` переносит только каталог, элементы остаются на своих адресах: члены `Elements` — слоты блоков, а не записи каталога ([`edit` и `mut` в `layout`](../layout/operations.md#edit-и-mut-в-layout)). Запись в неинициализированный элемент блока, затем длина блока и общая длина. |
| 77–92 | `insert` готовит блоки, сдвигает суффикс справа налево, записывает значение в освободившийся элемент. Длина растёт у блока прежнего логического конца (`end`). |
| 94–106 | `remove` возвращает `own T?`, как `remove` списков и контракт [`ResizableSequence`](array-contracts.md): индекс вне границ даёт `null`. Дальше элемент снимается, суффикс сдвигается слева направо, уменьшаются длина последнего занятого блока и общая длина. |
| 108–114 | `replace` снимает прежнее значение и записывает новое. |
| 116–136 | `drain` опустошает массив для типа `T`, который не соответствует `ImplicitlyDestroyable`: забирает каждый занятый элемент, передаёт его функции `each`, возвращает аллокатору `A` память каждого блока, затем каталога, и оставляет `directory == null` и нулевые счётчики. После неё выход из области видимости допустим: владеющее поле доказанно равно `null` ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), значение структуры, правило 4). Параметр `each` объявлен `nofail` ([nofail](../../throws.md#nofail-системная-точка-ответственности)): исключение из него застало бы локальную область с заполненными слотами, а значение `T` здесь неявно не уничтожается. |
| 139–163 | Память структуры возвращает `dispose`: стратегия пишет `implements Disposable`, а вызывает функцию компилятор там, где значение кончается. Она забирает занятые элементы каждого блока, возвращает аллокатору `A` память блоков, затем каталога, и обнуляет счётчики. В теле `dispose` условие `T conforms ImplicitlyDestroyable` верно без `requires` ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), значение структуры, правила 1, 2 и 6). |
| 165–171 | Чтение возвращает копию элемента, написанную словом `copy`, и требует `T: Copyable`. |
| 173–196 | `ChunkedAccess` соответствует `Indexable` с правом `read` и `edit`. Позиция элемента вычисляется делением, поэтому путь к ровно одному слоту в результате не записан: результат `&Access<self[_]> T`, ссылка на один из элементов. Два таких результата не доказаны разными, и проверка пересечения сравнивает их адреса при вызове. Срезов нет: элементы лежат не подряд. `ChunkedSwap` соответствует `Swappable`: `swapAt` переставляет два элемента под `edit` ([контракты операторов](../../runtime/lang-roles.md#контракты-операторов), [проверка пересечения](../../types/access-regions.md#проверка-пересечения), правило 3). |
| 198–203 | Использование. `ChunkedArray<Int>()` берёт аллокатор по умолчанию, `mm`. В конце области видимости и на выходе через исключение из `append` компилятор вызывает `dispose`. |
| 205–219 | `Chunk` хранит область, слоты которой могут быть не инициализированы, поэтому пишет свой `dispose` ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), значение структуры, правило 2): он забирает занятые элементы `0 ..< length` и возвращает память блока аллокатору `A`. В `drain` и `dispose` массива запись `chunk` кончается с `root == null`, и её `dispose` ничего не делает. |
| 221–249 | Добавление нескольких элементов сразу ([контракты операторов](../../runtime/lang-roles.md#контракты-операторов)). `reserve` у `ChunkedArray` нет: место под все элементы берёт один вызов `ensureChunks`, и `append` внутри цикла уже ничего не выделяет. `append(moving:)` переносит элементы другого `ChunkedArray` с тем же аллокатором по порядку; если `ensureChunks` бросит, ничего не перенесено и `moving` хранит свои элементы. Блоки источника остаются выделенными, их длины и `count` обнулены, поэтому инвариант общего префикса у обоих массивов верен на выходе. `a.append(moving: a)` вызывает ошибку: параметры не пересекаются ([проверка пересечения](../../types/access-regions.md#проверка-пересечения)). Итератор с `CountedIterator` получает блоки заранее; лишние блоки при неверном `remaining` остаются хвостом каталога с `length == 0`. |
| 251–261 | `append(contentsOf:)` над срезом копирует элементы, поэтому стоит в стратегии для `T: Copyable`: блоки берутся один раз, затем копия каждого элемента. `count` растёт после каждой копии, и копии, сделанные до броска `copy`, остаются в массиве. |

## Инвариант общего префикса

Для каждого индекса каталога `0 <= i < directoryLength`:

```text
directory[i].length = min(CHUNK_SIZE, max(0, count - i * CHUNK_SIZE))
```

Это строки 22–23 в `invariants`. Блоков хватает: `count <= directoryLength * CHUNK_SIZE`. Хвост каталога после
последнего занятого блока допустим, у его записей `length == 0`. Занятые элементы блока — `0 ..< length`,
остальные не инициализированы. Инвариант поддерживают записи длин в `append`, `insert` и `remove`; направление сдвигов доказывает порядок.

## Ошибки и очистка

`A.allocate` бросает `AllocationError` и при неудаче ничего не меняет. В `ensureChunks` два выделения: каталога (в
`growDirectory`) и блока. Деструктора у области нет, поэтому локальная область не остаётся ни на одном пути
исключения: каталог публикуется в поле до выделения блока, а блок — сразу после своего выделения
([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), локальный владелец, правило 1). Первой идёт
публикация каталога, она оставляет инварианты верными, и бросок выделения блока застаёт структуру в состоянии, где
инварианты выполнены
([места, где инвариант верен](../layout/invariants.md#инварианты), [правило README](README.md#общее-правило-применимости)).
Выделение блока стоит последним перед публикацией записи `Chunk`, и `root: take block` передаёт блок записи без
промежуточного выхода. Исключение из `append` оставляет массив целым, возможно с лишним пустым блоком в конце
каталога: у такой записи `length == 0`, инвариант общего префикса её допускает. На этом выходе массив освобождает
`dispose`.

Индексирование имеет сложность `O(1)`, `append` — амортизированную `O(1)`, `insert` и `remove` — `O(count - index)`.

Для сдвигов, публикации блока и очистки действует
[общее правило безотказного окна](README.md#общее-правило-применимости).
