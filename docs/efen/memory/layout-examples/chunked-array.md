# Массив из блоков

[К примерам](README.md) · [Исходник](chunked-array.efen) ·
[Пространство `layout`](../layout/declaration.md#пространство-layout)

Значения `T` хранятся в блоках, областях `Area<T>`. Каталог — область `Area<Chunk>` из структур `Chunk`: каждая
хранит владеющую ссылку на свой блок и число занятых в нём элементов. Рост каталога переносит только структуры
`Chunk`; блоки остаются на месте.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1 | Размер блока известен во время компиляции. |
| 3 | Параметр `T` стоит на `layout`. Блок — область `Area<T>`, каталог — область `Area<Chunk>`. |
| 4–8 | `Chunk` владеет одним блоком (`root`) ёмкостью `CHUNK_SIZE`; `length` — число занятых элементов блока, они идут с начала: `root.initialized == length`. |
| 10 | Типом программы служит именованная структура из `layout`. |
| 11–15 | Каталог `directory` допускает `null` ровно при нулевой ёмкости; его ёмкость и число записей хранятся отдельно: область их не хранит. |
| 16 | `count` — общая длина, её читает любой код. |
| 18–23 | Инварианты: в каталоге заняты записи `0 ..< directoryLength`, блоков хватает на `count` элементов, у каждой записи каталога есть блок, а длина каждого блока определена общей длиной (инвариант общего префикса, ниже). |
| 27–45 | `growDirectory` растёт геометрически. Выделение идёт до изменения каталога. Записи `Chunk` переносятся `take` из старого каталога в новый; старая область кончается без инициализированных слотов, и компилятор возвращает её аллокатору. |
| 47–55 | `ensureChunks` добавляет недостающие блоки по одному: ёмкость каталога, затем блок `CHUNK_SIZE` элементов, затем запись `Chunk` в неинициализированный элемент каталога и рост `directoryLength`. |
| 57–60 | `movePosition` переносит значение между логическими позициями: `take` из элемента одного блока и запись в неинициализированный элемент другого. |
| 62–63 | Стратегия для `ChunkedArray<T>`; `Movable` нужен для `take`. Стратегия соответствует `Appendable`: `v[] = x` вызывает `append`. |
| 65–71 | `append` — `mut`: `ensureChunks` может перевыделить каталог. Запись в неинициализированный элемент блока, затем длина блока и общая длина. |
| 73–88 | `insert` готовит блоки, сдвигает суффикс справа налево, записывает значение в освободившийся элемент. Длина растёт у блока прежнего логического конца (`end`). |
| 90–102 | `remove` возвращает `own T?`, как `remove` списков и контракт [`ResizableSequence`](array-contracts.md): индекс вне границ даёт `null`. Дальше элемент снимается, суффикс сдвигается слева направо, уменьшаются длина последнего занятого блока и общая длина. |
| 104–110 | `replace` снимает прежнее значение и записывает новое. |
| 112–131 | `drain` опустошает массив для типа `T`, который не соответствует `ImplicitlyDestroyable`: забирает каждый занятый элемент, передаёт его функции `each`, возвращает память и оставляет `directory == null` и нулевые счётчики. После неё выход из области видимости допустим: владеющее поле доказанно равно `null` ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), значение структуры, правило 4). Параметр `each` объявлен `nofail` ([nofail](../../throws.md#nofail-системная-точка-ответственности)): исключение из него застало бы локальную область с заполненными слотами, а значение `T` здесь неявно не уничтожается. |
| 133–155 | Память структуры возвращает `dispose`: стратегия пишет `implements Disposable`, а вызывает функцию компилятор там, где значение кончается. Она забирает занятые элементы каждого блока, возвращает блоки, затем каталог, и обнуляет счётчики. В теле `dispose` условие `T conforms ImplicitlyDestroyable` верно без `requires` ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), значение структуры, правила 1 и 6). |
| 157–163 | Чтение возвращает копию элемента, написанную словом `copy`, и требует `T: Copyable`. |
| 165–186 | `ChunkedAccess` соответствует `Indexable` с правом `read` и `edit`. Позиция элемента вычисляется делением, поэтому ровно слот в результате не записан: результат `Access<self> T`. Срезов нет: элементы лежат не подряд. `ChunkedSwap` соответствует `Swappable`: `swapAt` переставляет два элемента под `edit` ([контракты операторов](../../runtime/lang-roles.md#контракты-операторов), [проверка пересечения](../../types/access-regions.md#проверка-пересечения), правило 3). |
| 188–193 | Использование. В конце области видимости и на выходе через исключение из `append` компилятор вызывает `dispose`. |
| 195–208 | `Chunk` хранит область, слоты которой могут быть не инициализированы, поэтому пишет свой `dispose` ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), значение структуры, правило 2): он забирает занятые элементы `0 ..< length` и возвращает блок. В `drain` и `dispose` массива запись `chunk` кончается с `root == null`, и её `dispose` ничего не делает. |

## Инвариант общего префикса

Для каждого индекса каталога `0 <= i < directoryLength`:

```text
directory[i].length = min(CHUNK_SIZE, max(0, count - i * CHUNK_SIZE))
```

Это строки 20–21 в `invariants`. Блоков хватает: `count <= directoryLength * CHUNK_SIZE`. Хвост каталога после
последнего занятого блока допустим, у его записей `length == 0`. Занятые элементы блока — `0 ..< length`,
остальные не инициализированы. Инвариант поддерживают записи длин в `append`, `insert` и `remove`; направление сдвигов доказывает порядок.

## Ошибки и очистка

Форма области бросает `AllocationError`. В `ensureChunks` два выделения: каталога (в `growDirectory`) и блока.
Порядок двух выделений на корректность не влияет: если второе бросит, первое останется локальным значением `own`, и
на пути исключения его освободит деструктор области
([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), локальный владелец, правило 1). Пример
выделяет каталог первым и сразу его публикует: первой идёт публикация каталога, она оставляет инварианты верными, и бросок выделения
блока застаёт структуру в состоянии, где инварианты выполнены
([места, где инвариант верен](../layout/invariants.md#инварианты), [правило README](README.md#общее-правило-применимости)).
Выделение блока стоит последним перед публикацией записи `Chunk`, и `root: take block` передаёт блок записи без
промежуточного выхода. Исключение из `append` оставляет массив целым, возможно с лишним пустым блоком в конце
каталога: у такой записи `length == 0`, инвариант общего префикса её допускает. На этом выходе массив освобождает
`dispose`.

Индексирование имеет сложность `O(1)`, `append` — амортизированную `O(1)`, `insert` и `remove` — `O(count - index)`.

Для сдвигов, публикации блока и очистки действует
[общее правило безотказного окна](README.md#общее-правило-применимости).
