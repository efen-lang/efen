# Массив из блоков

[К примерам](README.md) · [Исходник](chunked-array.efen) ·
[Основная модель](../addresses.md)

Target лежат в блоках `Items.Area`; структуры с root и размерами блоков лежат
в каталоге `Chunks.Area`. Оба Area являются чистыми указателями.

## Закон общего префикса

Для каждого блока с индексом `i`:

```text
chunk[i].length =
    min(CHUNK_SIZE, max(0, self.length - i * CHUNK_SIZE))
```

Все Items находятся ровно в диапазонах
`chunk.root[0..<chunk.length]`. Закон нормативен, хотя surface-синтаксис
квантора по блокам ещё не определён.

## Ошибки и cleanup

`growDirectory` вызывается до allocation нового блока. Если рост падает,
нового блока ещё нет. Если падает `Items.allocateArea`, выросшая capacity
каталога может сохраниться, но логическая последовательность не меняется.
`Chunks.initialize` и следующие записи metadata после успешной подготовки
безотказны и не вызывают наблюдающий код.

При уничтожении каждого Chunk вызывается:

```efen
Items.free(
    root: take chunk.root,
    capacity: chunk.capacity,
    initializedCount: chunk.length
)
```

Затем `Chunks.free` получает directory root, directoryCapacity и
directoryLength. Рост каталога переносит только структуры Chunk; allocations
Target остаются на месте.

Индексирование имеет `O(1)`, append — амортизированное `O(1)`,
insert/remove — `O(length - index)`.

Для сдвигов, публикации блока и cleanup действует
[общее правило безотказного окна](README.md#общее-правило-применимости).
