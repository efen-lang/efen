# Динамический непрерывный массив

[К примерам](README.md) · [Исходник](dynamic-array.efen) ·
[Пространство `layout`](../layout/declaration.md#пространство-layout)

`Vector` объявлена структурой в `layout<T, A>`: корневая ссылка на область, ёмкость и длина. Методы записаны стратегией.
Память области вектор берёт и возвращает сам, через контракт аллокатора `A`: при росте он берёт память под новую
область, переносит элементы и возвращает память старой.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1 | Параметры `T` и `A` стоят на `layout`. Область `Area<T>` состоит из непрерывных элементов формы `T`, и для каждого `T` она своя. `A` — аллокатор области с ограничением `memory::Allocator`, по умолчанию `mm` ([коллекция и её аллокатор](../allocator.md#коллекция-и-её-аллокатор)): `Vector<Int>` и `Vector<Int, FrameArena>` — два типа. `layout` объявлен `private`: поля пишут функции этого модуля. |
| 2 | Типом, которым пользуется программа, служит именованная структура из `layout`. Обёртки, `Self` и аспекта нет. |
| 3 | `items` владеет областью и допускает `null`: нулевая ёмкость не выделяет памяти. Инвариант поля: область есть ровно тогда, когда `capacity` больше нуля, и число её элементов равно `capacity`. |
| 4–5 | `capacity` и `count` читает любой код, пишет модуль. Инвариант `count <= capacity` верен на каждом выходе публичной функции. |
| 6 | Заняты элементы `0 ..< count`, остальные не инициализированы: так говорит инвариант `items.initialized == count` ([слоты области](../layout/operations.md#частичная-инициализация-и-очистка)). |
| 7 | Строка `set Elements: items[_]` говорит, что элементы вектора — слоты области `items`; `v[_]` значит `v.Elements`. Строка в теле структуры берёт пути и относится к одному значению ([множества и области](../layout/declaration.md#множества-и-области), правило 14). Под `edit` эти слоты не двигаются и не уничтожаются ([`edit` и `mut` в `layout`](../layout/operations.md#edit-и-mut-в-layout)). |
| 11–13 | `grow` — помощник (`private`) с правом `mut` на вектор: он заменяет область областью ёмкости `to`, которую выбирает вызывающий. Память он берёт у `A` (`A.allocate`) по контракту: условие `ensures` у `allocate` говорит, что блок не меньше `to * sizeOf(T)` байт и выровнен по `alignOf(T)`. Приведение `memory as Area<T> { value.count == to }` делает из сырой памяти область из `to` неинициализированных слотов ([создание элемента](../layout/operations.md#62-создание-элемента), правило 10). Выделение идёт до первого изменения вектора. |
| 15–20 | Старая область снимается из поля (`take v.items`). Каждый из `count` занятых элементов уходит `take` из старой области и записывается в неинициализированный элемент новой. Ссылки на старые элементы умирают в строке `take`. |
| 21 | Ни один слот старой области не инициализирован, поэтому код стирает вид (`old as Pointer`) и возвращает память тому же аллокатору: `A.deallocate(ptr:)` размера не принимает. Деструктора у области нет: путь, который оставил бы `old` без возврата, FLOW отвергает ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), локальный владелец, правило 1). Между `allocate` и записью `v.items = take fresh` нет вызова, который бросает исключение, поэтому `fresh` на пути исключения не остаётся. |
| 24–25 | Новая область и ёмкость записываются после переноса; к выходу `grow` инвариант поля `items` верен. |
| 28–29 | Стратегия для `Vector<T, A>`; вне `layout` имя пишется с аргументами. `Movable` нужен для `take` элемента. Стратегия соответствует `RoomAppendable`, а с ним `Appendable` и `Reservable`: `v[] = x` вызывает `append`, член выбирает право на объект вызова ([контракты операторов](../../runtime/lang-roles.md#контракты-операторов)). |
| 31–42 | `reserve(room:)` — публичная функция: даёт место ещё для `room` элементов. Ёмкость растёт теми же шагами, что при добавлении по одному, поэтому одно выделение заменяет несколько. Право `mut`: рост заменяет область. |
| 44–50 | `append` с правом `mut`: худший путь (`grow`) заменяет область, ёмкость растёт геометрически, поэтому `append` амортизированно `O(1)`; `nothrows`: `AllocationError` — сбой и проходит. Запись в неинициализированный элемент `count` инициализирует его; `count` растёт той же операцией. |
| 52–57 | `append` с правом `edit` выбирается, когда на объект вызова есть только право `edit`. Он требует `count < capacity`: место для него заранее берёт `reserve(room:)`. В обходе того же вектора `v[] = x` требует заголовка `for x in mut v` ([итератор как структура](../../types/access-regions.md#итератор-как-структура)). Запись в неинициализированный слот `count` не двигает ни одного слота, поэтому ссылки на слоты элементов после вызова действительны ([права](../memory-rules.md#права)). |
| 59–73 | `append(moving:)` переносит элементы другого вектора с тем же аллокатором после одного `reserve`. Источник передан как `mut`, а не `own`: если `reserve` бросит, ничего не перенесено и `source` хранит свои элементы. После `reserve` перенос не бросает; пустую область источника код возвращает аллокатору `A` (строка 68), и источник остаётся с `items == null` и нулевой ёмкостью. `v.append(moving: v)` вызывает ошибку: параметры не пересекаются ([проверка пересечения](../../types/access-regions.md#проверка-пересечения)). |
| 75–82 | `append(contentsOf:)` добавляет значения итератора. `reserve` стоит первым, только когда итератор соответствует `CountedIterator` и знает число оставшихся значений (`remaining`). Добавляет значения член `mut`, поэтому записи за границу области не бывает и при неверном `remaining`. Сам неверный `remaining` нарушает `ensures` метода `next` у `CountedIterator`: недоказанное условие проверяется на возврате из `next` и по умолчанию останавливает программу ([условия](../../conditions.md#обычная-сборка-и-диагностики)). |
| 84–95 | `insert` берёт место для одного элемента (`reserve(room: 1)`), затем сдвигает суффикс справа налево. Каждая запись попадает в неинициализированный элемент: первый неинициализированный — `items![count]`, следующий освобождён предыдущим `take`. |
| 97–107 | `remove` возвращает `own T?`, как `remove` списков и контракт [`ResizableSequence`](array-contracts.md): индекс вне границ даёт `null`. Дальше элемент снимается `take items![index]`, суффикс сдвигается слева направо в освободившиеся элементы, `count` уменьшается. Право `mut`: `take` элемента. |
| 109–115 | `replace` снимает прежнее значение и записывает новое. Между `take` и записью нет вызова, который мог бы прервать функцию. |
| 117–128 | `drain` опустошает вектор для типа `T`, который не соответствует `ImplicitlyDestroyable`: забирает каждый занятый элемент, передаёт его функции `each`, возвращает память аллокатору и оставляет `items == null`, `count == 0` и `capacity == 0`. После неё выход из области видимости допустим: владеющее поле доказанно равно `null` ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), значение структуры, правило 4). Параметр `each` объявлен `nofail` ([nofail](../../throws.md#nofail-системная-точка-ответственности)): исключение из него застало бы локальную область с заполненными слотами, которую код ещё не вернул, а значение `T` здесь неявно не уничтожается. |
| 131–146 | Память структуры возвращает `dispose`: стратегия пишет `implements Disposable`, а вызывает функцию компилятор там, где значение кончается. Она забирает занятые элементы, возвращает память области аллокатору `A` и оставляет `items == null`. В теле `dispose` условие `T conforms ImplicitlyDestroyable` верно без `requires` ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), значение структуры, правила 1, 2 и 6). |
| 71–72, 126–127, 143–144 | При пустой области `count` и `capacity` равны нулю: так инвариант поля `items` верен на выходе. |
| 148–153 | Чтение возвращает копию элемента, написанную словом `copy`, поэтому оно вынесено в стратегию для `T: Copyable`. `read` не пишет полей и права `edit` не требует. Индекс проверяет `requires`. |
| 155–164 | `append(contentsOf:)` над срезом `Slice<T>` копирует элементы, поэтому стоит в той же стратегии: один `reserve`, затем копия каждого элемента. `count` растёт после каждой копии, и копии, сделанные до броска `copy`, остаются в векторе. Для `T: ImplicitlyCopyable` копия бросить не может, и генератор кода пишет цикл одним блочным копированием. |
| 167–172 | Использование. `Vector<Int>()` берёт аллокатор по умолчанию, `mm`. В конце области видимости и на выходе через исключение из `append` компилятор вызывает `dispose`. |
| 174–189 | `VectorAccess` соответствует `Sliceable` с правом `read` и `edit`. `at` даёт ссылку ровно на слот `index` (`&Access<self.items![index]> T`), `slice` — ровно слоты `start ..< end` срезом `Slice<T>`, который хранит свою длину; индекс вне границ бросает `BoundsError`. `v[i]` в позиции чтения вызывает член `read`, в позиции записи `edit`. Ссылка из члена `edit` разрешает `mut` над значением слота, поэтому `v[i] = x` для `T`, который владеет памятью, пишется под `edit`. Проверка пересечения сравнивает `v[i]` и `v[j]` как два слота ([контракты операторов](../../runtime/lang-roles.md#контракты-операторов), [проверка пересечения](../../types/access-regions.md#проверка-пересечения), правило 3). |
| 191–202 | `VectorSwap` соответствует `Swappable`: `swapAt` переставляет два элемента под `edit`, им переставляет элементы обобщённый код, которому путь к слоту не виден. |
| 204–212 | Код, который только читает, берёт срез `Slice<Int>` и аллокатора не называет: она принимает срез вектора с любым `A`. |

## Перевыделение области

Перевыделения как особой операции нет: рост — код `grow`. Код берёт у `A` память под новую область, снимает старую
из поля, переносит каждый элемент парой «`take` из старого, запись в новый» и возвращает память старой области тому
же `A`. Таблица [«`edit` и `mut` в `layout`»](../layout/operations.md#edit-и-mut-в-layout) относит замену области к
`mut` на владельца: ссылки и указатели внутрь прежней области умирают. Поэтому `append`, чей худший путь растит
область, — `mut`. Запись в пределах ёмкости идёт членом `append` с правом `edit`, который требует `count < capacity`;
место для него заранее берёт `reserve(room:)`.

Код вектора знает контракт `memory::Allocator`, но не его реализацию. FLOW доказывает вектор против контракта один
раз, а каждый аллокатор против того же контракта отдельно; замена `mm` на другой аллокатор кода вектора не меняет.

Какие ссылки вызов делает недействительными, решает сводка его тела, а не слово `mut` в сигнатуре
([что делает ссылку недействительной](../memory-rules.md#что-делает-ссылку-недействительной)):

| Вызов | Что становится недействительным |
|---|---|
| `reserve`, `append` с правом `mut`, `append(moving:)`, `append(contentsOf:)`, `insert` | все ссылки и указатели внутрь области: худший путь заменяет область |
| `append` с правом `edit` | ни одна ссылка на слот элемента: запись идёт в неинициализированный слот `count` в пределах ёмкости |
| `remove(index:)` | ссылки на элементы с номерами от `index`: сдвиг забирает каждый из них `take` |
| `replace(index:)` | ссылки на элемент `index`: его значение забрано `take` |
| `drain` | все ссылки и указатели внутрь области: память области возвращена |
| `append(moving: source)` у источника | все ссылки и указатели внутрь области `source`: память области возвращена |

Поэтому `let r = &v[0]; v.replace(index: 1, value: x); print(r)` допустимо: `replace` забирает только слот 1.

## Ошибки и очистка

Выделение в `grow` стоит до первой записи в вектор, поэтому `AllocationError` из `A.allocate` оставляет вектор
прежним: при неудаче аллокатор ничего не меняет. Слово `throws` в сигнатурах не записано: у функции с телом список
исключений выводится ([throws](../../throws.md)). На выходе через исключение из `append` вектор освобождает
`dispose`, который вызывает компилятор.

`append` имеет амортизированную сложность `O(1)`; `insert` и `remove` — `O(count - index)`; `read` и `replace` — `O(1)`.
`append(contentsOf:)` над срезом и `append(moving:)` растят область не больше одного раза, `append(contentsOf:)` над
итератором — тоже, когда итератор соответствует `CountedIterator`.
