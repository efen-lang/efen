# Динамический непрерывный массив

[К примерам](README.md) · [Исходник](dynamic-array.efen) ·
[Основная модель](../addresses.md)

`Self` хранит корневой указатель, ёмкость и длину раздельно. При росте операция
дескриптора `Items.reallocateArea` меняет корневой указатель.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1 | Аспект получает тип элемента `Target`. |
| 2–5 | `Items` совпадает с инициализированным префиксом текущего корневого указателя. |
| 7–9 | `Item` физически встраивает `Target`. |
| 11–12 | Поле `root` допускает `null`: нулевая ёмкость не создаёт выделенной области. |
| 14–16 | `areaCapacity` хранится явно и связана с наличием корневого указателя. |
| 18–23 | Длина равна `Items.count` и не превышает ёмкость; строки 22–23 закрывают `Self` и `layout`. |
| 25–37 | Конструктор записывает служебные поля, выделяет `Area` только при положительной ёмкости и возвращает готовый `Self`. |
| 39–45 | `count` и `capacity` читают поля `Self`, а не свойства `Area`. |
| 47–53 | `itemAt` проверяет индекс и только затем вызывает `Items.at`. |
| 55–60 | `reserve` условно доступен для `Movable` и сразу возвращается, если места достаточно. |
| 62–63 | Геометрический рост обеспечивает амортизированную сложность добавления `O(1)`. |
| 65–70 | `reallocateArea` получает ссылку на корневой указатель и все размеры явно; при ошибке состояние остаётся прежним. |
| 71–72 | Ёмкость меняется после успешной замены корневого указателя. |
| 74–86 | `append` требует `Movable`, резервирует место, инициализирует первую свободную ячейку и последней строкой обновляет длину. |
| 88–93 | `insert` требует `Movable` и проверяет позицию до изменения. |
| 95–96 | Новая длина вычисляется и резервируется заранее. |
| 98–107 | Суффикс движется справа налево, поэтому каждое назначение пусто. |
| 109–115 | В освободившееся место переносится новый `Item`, затем обновляется длина. |
| 117–122 | `remove` требует `Movable` и проверяет существующую позицию. |
| 124–126 | Сохраняется старая длина, `Item` изымается, а `cursor` указывает на пустое место. |
| 128–136 | Суффикс движется слева направо и закрывает дырку. |
| 138–140 | Длина уменьшается после сдвига, а удалённый встроенный `Target` возвращается. |
| 142–146 | `read` проецирует `Target` и требует `Copyable`. |
| 148–155 | `replace` требует `Movable`; атомарная операция `replace(place, value)` устанавливает новый `Target` и возвращает прежний. |
| 156–157 | Закрываются `implementation` и аспект. |

## Перевыделение области

```efen
Items.reallocateArea(
    root: &self.root,
    oldCapacity: self.areaCapacity,
    initializedCount: self.length,
    newCapacity: nextCapacity
)
```

`Items.Area` не содержит служебных данных. Дескриптор может расширить область на
месте либо выделить новую, перенести `length` элементов, заменить `self.root` и
освободить старый блок. При ошибке корневой указатель, ёмкость, длина и элементы
остаются прежними.

Живой `Items.Item` или заимствование `Target` блокирует перевыделение. После
начала сдвига proof требует, чтобы перенос `Target` и запись служебных полей не
бросали исключений, не приостанавливались и не входили в изменяемую структуру
повторно. Compiler сам строит critical window и выносит fallible prepare раньше;
concrete representation обязана доказать refinement generated transitions, иначе
её операция отклоняется. Дополнительная аннотация Array-коду не нужна.

Уничтожение передаёт `root`, `areaCapacity` и `length` в `Items.free`.
`append` имеет амортизированную сложность `O(1)`; `insert` и `remove` —
`O(length - index)`.
