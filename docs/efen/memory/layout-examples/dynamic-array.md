# Динамический непрерывный массив

[К примерам](README.md) · [Исходник](dynamic-array.efen) ·
[Основная модель](../addresses.md)

`Self` хранит root-указатель, capacity и length раздельно. Рост меняет root
через descriptor-level `Items.reallocateArea`.

## Построчный разбор

| Строки | Почему код написан так |

| 1 | Аспект получает тип элемента Target. |
| 2–5 | Items совпадает с инициализированным префиксом текущего root. |
| 7–9 | Item физически встраивает Target. |
| 11–12 | Root optional: нулевая capacity не создаёт allocation. |
| 14–16 | `areaCapacity` хранится явно и связана с наличием root. |
| 18–23 | Length равна Items.count и не превышает capacity; строки 22–23 закрывают Self и layout. |
| 25–37 | Конструктор записывает metadata, выделяет Area только при capacity > 0 и возвращает закрытый Self. |
| 39–45 | `count` и `capacity` читают поля Self, а не свойства Area. |
| 47–53 | `itemAt` проверяет индекс и только затем вызывает `Items.at`. |
| 55–58 | Reserve быстро возвращается, если места достаточно. |
| 60–61 | Геометрический рост обеспечивает амортизированную стоимость. |
| 63–68 | Reallocate получает ссылку на root и все размеры явно; при ошибке состояние прежнее. |
| 69–70 | Capacity меняется после успешной замены root. |
| 72–82 | Append резервирует место, инициализирует первый свободный slot и последней строкой публикует length. |
| 84–87 | Insert проверяет позицию до изменения. |
| 89–90 | Новая длина вычисляется и резервируется заранее. |
| 92–101 | Суффикс движется справа налево, поэтому каждое назначение пусто. |
| 103–109 | В освободившееся место переносится новый Item, затем обновляется length. |
| 111–114 | Remove проверяет существующую позицию. |
| 116–118 | Сохраняется старая длина, Item изымается, cursor указывает на дырку. |

## Reallocation

```efen
Items.reallocateArea(
    root: &self.root,
    oldCapacity: self.areaCapacity,
    initializedCount: self.length,
    newCapacity: nextCapacity
)
```

`Items.Area` не содержит metadata. Descriptor может расширить allocation на
месте либо выделить новый, перенести `length` Items, заменить `self.root` и
освободить старый блок. При ошибке root, capacity, length и элементы прежние.

Живой `Items.Item` или borrow Target блокирует reallocation. После начала
сдвига перенос Target и metadata не бросают исключений, не приостанавливаются и
не вызывают наблюдающий код.

Уничтожение передаёт `root`, `areaCapacity` и `length` в `Items.free`.
`append` имеет амортизированное `O(1)`; insert/remove —
`O(length - index)`.
