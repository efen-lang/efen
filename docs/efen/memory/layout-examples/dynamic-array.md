# Динамический непрерывный массив

[К примерам](README.md) · [Исходник](dynamic-array.efen) ·
[Пространство `layout`](../layout-reference.md#пространство-layout)

`Vector` — структура блока `layout<T>`: корневая ссылка на область, ёмкость и длина. Методы записаны стратегией.
При росте массив выделяет новую область, переносит элементы и освобождает старую.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1–2 | Параметр `T` стоит на блоке. Область `Items` — непрерывные элементы формы `T`; для каждого `T` она своя. Блок `private`: поля пишут функции этого модуля. |
| 4 | Тип, которым пользуется программа, — именованная структура блока. Обёртки, `Self` и аспекта нет. |
| 5 | `items` владеет областью и допускает `null`: нулевая ёмкость не выделяет памяти. Закон поля связывает число элементов области с `capacity`. |
| 6–7 | `capacity` и `count` читает любой код, пишет модуль. Закон `count <= capacity` держится на каждом выходе публичной функции. Занятые элементы — `0 ..< count`; остальные не инициализированы. |
| 11–13 | `grow` — помощник (`private`) с правом `mut` на вектор: он перевыделяет область. Новая ёмкость растёт геометрически, поэтому `append` амортизированно `O(1)`. Выделение идёт до первого изменения вектора. |
| 15–22 | Старая область снимается из поля (`take v.items`). Каждый из `count` занятых элементов уходит `take` из старой области и записывается в неинициализированный элемент новой. Ссылки на старые элементы умирают в строке `take`. |
| 21 | `mm.free(old as Pointer)` возвращает старую область менеджеру памяти. |
| 24–25 | Новая область и ёмкость записываются после переноса; к выходу `grow` закон поля `items` верен. |
| 28 | Стратегия для `Vector<T>`; снаружи блока имя пишется с аргументом. `Movable` нужен для `take` элемента. |
| 29–33 | `reserve` — публичная функция: растит ёмкость, только если её не хватает. Право `mut`: рост перевыделяет область. |
| 35–39 | `append` — `mut`, потому что худший путь (`reserve`) перевыделяет область. Запись в неинициализированный элемент `count` инициализирует его; `count` растёт той же операцией. |
| 41–52 | `insert` резервирует ёмкость, затем сдвигает суффикс справа налево. Каждая запись попадает в неинициализированный элемент: первый неинициализированный — `items![count]`, следующий освобождён предыдущим `take`. |
| 54–64 | `remove` возвращает `own T?`, как `remove` списков и контракт [`ResizableSequence`](array-contracts.md): индекс вне границ даёт `null`. Дальше элемент снимается `take items![index]`, суффикс сдвигается слева направо в освободившиеся элементы, `count` уменьшается. Право `mut`: `take` элемента. |
| 66–72 | `replace` снимает прежнее значение и записывает новое. Между `take` и записью нет вызова, который мог бы прервать функцию. |
| 74–87 | `release` — публичная функция уничтожения. У структуры из `layout` деструктора нет, поэтому код сам снимает занятые элементы, возвращает область и оставляет `items == null`. Она уничтожает элементы типа `T`, поэтому несёт `requires T conforms ImplicitlyDestroyable`. |
| 85–86 | При пустой области `count` и `capacity` равны нулю: так закон поля `items` верен на выходе. |
| 90–96 | Чтение копирует элемент, поэтому оно вынесено в стратегию для `T: Copyable`. `read` не пишет полей и права `edit` не требует. Индекс проверяет `requires`. |
| 98–102 | Пример использования. `defer v.release()` стоит сразу после создания: `append` может бросить `AllocationError`, а выход через исключение — тоже выход, на котором владеющее поле не должно остаться непустым. |

## Перевыделение области

Перевыделения как особой операции нет: рост — код `grow`. Старая область снимается из поля, каждый элемент
переносится парой «`take` из старого, запись в новый», старая область возвращается вызовом `mm.free`. Таблица
[«`edit` и `mut` в `layout`»](../layout-reference.md#edit-и-mut-в-layout) относит перевыделение области к `mut` на
владельца: ссылки и указатели внутрь прежней области умирают. Поэтому `append`, чей худший путь растит область, —
`mut`, хотя запись в пределах ёмкости потребовала бы только `edit`.

Живая ссылка на элемент не переживает вызов `append`, `insert`, `remove`, `replace`, `reserve` и `release`:
каждый из них `mut`.

## Ошибки и очистка

Выделение в `grow` стоит до первой записи в вектор, поэтому `AllocationError` из `mm.allocate` оставляет вектор прежним.
Бросок в сигнатурах не записан: `layout-reference.md` не показывает формы эффекта для функций `layout`. Исключение из `append` не
освобождает вектор, это делает `defer v.release()` в месте использования.

`append` имеет амортизированную сложность `O(1)`; `insert` и `remove` — `O(count - index)`; `read` и `replace` — `O(1)`.
