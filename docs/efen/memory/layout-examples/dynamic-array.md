# Динамический непрерывный массив

[К примерам](README.md) · [Исходник](dynamic-array.efen) ·
[Пространство `layout`](../layout/declaration.md#пространство-layout)

`Vector` объявлена структурой в `layout<T>`: корневая ссылка на область, ёмкость и длина. Методы записаны стратегией.
При росте массив выделяет новую область, переносит элементы и освобождает старую.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1–2 | Параметр `T` стоит на `layout`. Область `Items` состоит из непрерывных элементов формы `T`, и для каждого `T` она своя. `layout` объявлен `private`: поля пишут функции этого модуля. |
| 4 | Типом, которым пользуется программа, служит именованная структура из `layout`. Обёртки, `Self` и аспекта нет. |
| 5 | `items` владеет областью и допускает `null`: нулевая ёмкость не выделяет памяти. Инвариант поля: область есть ровно тогда, когда `capacity` больше нуля, число её элементов равно `capacity`, а заняты байты `0 ..< count * sizeOf(T)` (`value.extent`), то есть слоты `0 ..< count` ([слоты области](../layout/operations.md#частичная-инициализация-и-очистка)). |
| 6–7 | `capacity` и `count` читает любой код, пишет модуль. Инвариант `count <= capacity` верен на каждом выходе публичной функции. Заняты элементы `0 ..< count`, остальные не инициализированы: так говорит инвариант поля `items`. |
| 11–13 | `grow` — помощник (`private`) с правом `mut` на вектор: он перевыделяет область. Новая ёмкость растёт геометрически, поэтому `append` амортизированно `O(1)`. Выделение идёт до первого изменения вектора. |
| 15–21 | Старая область снимается из поля (`take v.items`). Каждый из `count` занятых элементов уходит `take` из старой области и записывается в неинициализированный элемент новой. Ссылки на старые элементы умирают в строке `take`. |
| 21 | В конце блока старая область `old` кончается: ни один её слот не инициализирован, и компилятор возвращает область аллокатору ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется)). |
| 23–24 | Новая область и ёмкость записываются после переноса; к выходу `grow` инвариант поля `items` верен. |
| 28 | Стратегия для `Vector<T>`; вне `layout` имя пишется с аргументом. `Movable` нужен для `take` элемента. |
| 29–33 | `reserve` — публичная функция: растит ёмкость, только если её не хватает. Право `mut`: рост перевыделяет область. |
| 35–39 | `append` — `mut`, потому что худший путь (`reserve`) перевыделяет область. Запись в неинициализированный элемент `count` инициализирует его; `count` растёт той же операцией. |
| 41–52 | `insert` резервирует ёмкость, затем сдвигает суффикс справа налево. Каждая запись попадает в неинициализированный элемент: первый неинициализированный — `items![count]`, следующий освобождён предыдущим `take`. |
| 54–64 | `remove` возвращает `own T?`, как `remove` списков и контракт [`ResizableSequence`](array-contracts.md): индекс вне границ даёт `null`. Дальше элемент снимается `take items![index]`, суффикс сдвигается слева направо в освободившиеся элементы, `count` уменьшается. Право `mut`: `take` элемента. |
| 66–72 | `replace` снимает прежнее значение и записывает новое. Между `take` и записью нет вызова, который мог бы прервать функцию. |
| 73–84 | `drain` опустошает вектор для типа `T`, который не соответствует `ImplicitlyDestroyable`: забирает каждый занятый элемент, передаёт его функции `each`, возвращает память и оставляет `items == null`, `count == 0` и `capacity == 0`. После неё выход из области видимости допустим: владеющее поле доказанно равно `null` ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), значение структуры, правило 4). |
| 86–100 | Память структуры возвращает `dispose`: стратегия пишет `implements Disposable`, а вызывает функцию компилятор там, где значение кончается. Она забирает занятые элементы, возвращает область и оставляет `items == null`. В теле `dispose` условие `T conforms ImplicitlyDestroyable` верно без `requires` ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), значение структуры, правила 1 и 6). |
| 81–82, 97–98 | При пустой области `count` и `capacity` равны нулю: так инвариант поля `items` верен на выходе. |
| 102–108 | Чтение возвращает копию элемента, написанную словом `copy`, поэтому оно вынесено в стратегию для `T: Copyable`. `read` не пишет полей и права `edit` не требует. Индекс проверяет `requires`. |
| 110–115 | Использование. В конце области видимости и на выходе через исключение из `append` компилятор вызывает `dispose`. |
| 117–123 | `at` даёт ровно слот `index`: результат `edit<&self.items![index]> T`. Через него работает `v[i]` ([контракты операторов](../../runtime/lang-roles.md#контракты-операторов)), и проверка пересечения сравнивает `v[i]` и `v[j]` как два слота ([проверка пересечения](../../types/access-regions.md#проверка-пересечения), правило 3). |

## Перевыделение области

Перевыделения как особой операции нет: рост — код `grow`. Старая область снимается из поля, каждый элемент
переносится парой «`take` из старого, запись в новый», старая область кончается локальным значением, и компилятор возвращает её аллокатору. Таблица
[«`edit` и `mut` в `layout`»](../layout/operations.md#edit-и-mut-в-layout) относит перевыделение области к `mut` на
владельца: ссылки и указатели внутрь прежней области умирают. Поэтому `append`, чей худший путь растит область, —
`mut`, хотя запись в пределах ёмкости потребовала бы только `edit`.

Какие ссылки вызов делает недействительными, решает сводка его тела, а не слово `mut` в сигнатуре
([что делает ссылку недействительной](../memory-rules.md#что-делает-ссылку-недействительной)):

| Вызов | Что становится недействительным |
|---|---|
| `reserve`, `append`, `insert` | все ссылки и указатели внутрь области: худший путь заменяет область |
| `remove(index:)` | ссылки на элементы с номерами от `index`: сдвиг забирает каждый из них `take` |
| `replace(index:)` | ссылки на элемент `index`: его значение забрано `take` |
| `drain` | все ссылки и указатели внутрь области: область возвращена |

Поэтому `let r = &v[0]; v.replace(index: 1, value: x); print(r)` допустимо: `replace` забирает только слот 1.

## Ошибки и очистка

Выделение в `grow` стоит до первой записи в вектор, поэтому `AllocationError` формы `Items<T>(count: next)` оставляет вектор прежним.
Слово `throws` в сигнатурах не записано: у функции с телом список исключений выводится
([throws](../../throws.md)). На выходе через исключение из `append` вектор освобождает `dispose`, который вызывает
компилятор.

`append` имеет амортизированную сложность `O(1)`; `insert` и `remove` — `O(count - index)`; `read` и `replace` — `O(1)`.
