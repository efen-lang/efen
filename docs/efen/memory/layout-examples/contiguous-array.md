# Непрерывный массив фиксированной длины

[К примерам](README.md) · [Исходник](contiguous-array.efen) ·
[Основная модель](../addresses.md)

`Array<Target, Contiguous>` создаёт одну область ровно нужного размера,
инициализирует все места и больше не меняет длину.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1 | `Contiguous<Target>` получает тип элемента; конкретный массив доступен внутри как `Self`. |
| 2–5 | `layout` отделён от поведения. `set Items` объявляет множество живых элементов, а условие связывает каждый элемент с префиксом `root[0..<length]`. |
| 7–9 | `Item` физически встраивает `Target`. Поле `var value: Target` не гарантировало бы непосредственное размещение. |
| 11–12 | `struct Self` определяет память самого массива. Поле `root` допускает `null`, потому что пустой массив не выделяет область. `Items.Area` — только указатель. |
| 14–16 | Ёмкость хранится явно. Эквивалентность запрещает ненулевую область с нулевой ёмкостью и ненулевую ёмкость без корневого указателя. |
| 18–21 | `length` хранится отдельно, совпадает с логическим `Items.count` и с ёмкостью фиксированного массива. |
| 22–23 | Закрываются определения `Self` и `layout`; следующие строки уже не описывают память. |
| 25–32 | `implementation` содержит поведение. Конструктор получает размер и функцию создания каждого `Target`; `Movable` требуется для `take` созданного значения. |
| 33–35 | Сначала записываются точные служебные поля. Если дальнейшее создание завершится ошибкой, cleanup знает ёмкость и длину готового префикса. |
| 37–39 | Нулевая ёмкость оставляет `root == null`; для ненулевой вызывается операция дескриптора `Items.allocateArea`. |
| 41 | Цикл проходит каждую логическую позицию ровно один раз. |
| 42 | `make(index)` строит очередной элемент до публикации его места. |
| 43–47 | `Items.initialize` принадлежит дескриптору, получает корневой указатель и индекс явно и переносит непосредственно размещённый `Item` в пустое место. |
| 48 | Длина увеличивается только после успешной инициализации, поэтому всегда описывает готовый префикс. |
| 49–52 | После цикла `length == capacity`; условия `layout` закрыты, и только теперь `Self` возвращается. |
| 54–56 | Публичный `count` читает явное поле времени выполнения, а не скрытые данные указателя `Area`. |
| 58–61 | `itemAt` сначала проверяет логическую границу. Ошибка не выполняет адресную операцию. |
| 63–64 | После проверки `Items.at` получает типизированный указатель `Items.Item` на существующий элемент. |
| 66–70 | `read` копирует встроенный `Target`; поэтому операция доступна только при `Copyable`. |
| 72–79 | `replace` требует `Movable`; атомарная операция `replace(place, value)` устанавливает новый `Target` и возвращает прежний. |
| 80–81 | Закрываются `implementation` и аспект. |

Пустой массив имеет `root == null`, `capacity == 0`, `length == 0`. При ошибке
`make` compiler-generated exceptional CFG незавершённого `Self` обязан реально
вызвать:

```efen
Items.free(
    root: take self.root!,
    capacity: self.capacity,
    initializedCount: self.length
)
```

Вызов выполняется только при ненулевом корневом указателе. Размеры передаются
отдельно, потому что `Items.Area` их не хранит. Cleanup использует именно успешно
инициализированный префикс `0..<self.length`, учитывает выполненные `take` и не
может быть заменён ghost-утверждением.

На успешном `return self` тот же линейный construction-cleanup не исчезает: он
становится destructor obligation владеющего результата `Self`. На exceptional
пути он, напротив, потребляется выполненными drop/free actions.

Индексирование, чтение и замена имеют сложность `O(1)`; создание — `O(length)`.

Для `replace` и очистки действует
[общее правило безотказного окна](README.md#общее-правило-применимости).
`Movable` делает перенос допустимым. `replace(item.Target, value)` lowerится как
один атомарный переход без промежуточного exceptional или observation edge.
