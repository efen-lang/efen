# Непрерывный массив фиксированной длины

[К примерам](README.md) · [Исходник](contiguous-array.efen) ·
[Основная модель](../addresses.md)

`Array<Target, Contiguous>` создаёт одну область ровно нужного размера,
инициализирует все места и больше не меняет длину.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1 | `Contiguous<Target>` получает тип элемента; конкретный массив доступен внутри как `Self`. |
| 2–5 | `layout` отделён от поведения. `set Items` объявляет множество живых элементов, а условие связывает каждый элемент с префиксом `root[0..<length]`. |
| 7–9 | `Item` физически встраивает `Target`. Поле `var value: Target` не гарантировало бы непосредственное размещение. |
| 11–12 | `struct Self` определяет память самого массива. Поле `root` допускает `null`, потому что пустой массив не выделяет область. `Items.Area` — только указатель. |
| 14–16 | Ёмкость хранится явно. Эквивалентность запрещает ненулевую область с нулевой ёмкостью и ненулевую ёмкость без корневого указателя. |
| 18–21 | `length` хранится отдельно, совпадает с логическим `Items.count` и с ёмкостью фиксированного массива. |
| 22–23 | Закрываются определения `Self` и `layout`; следующие строки уже не описывают память. |
| 25–30 | `implementation` содержит поведение. Конструктор получает размер и функцию создания каждого `Target`, возвращая полностью построенный `Self`. |
| 31–33 | Сначала записываются точные служебные поля. Если дальнейшее создание завершится ошибкой, код очистки знает ёмкость и длину готового префикса. |
| 35–37 | Нулевая ёмкость оставляет `root == null`; для ненулевой вызывается операция дескриптора `Items.allocateArea`. |
| 39 | Цикл проходит каждую логическую позицию ровно один раз. |
| 40 | `make(index)` строит очередной элемент до публикации его места. |
| 41–45 | `Items.initialize` принадлежит дескриптору, получает корневой указатель и индекс явно и переносит непосредственно размещённый `Item` в пустое место. |
| 46 | Длина увеличивается только после успешной инициализации, поэтому всегда описывает готовый префикс. |
| 47–50 | После цикла `length == capacity`; условия `layout` закрыты, и только теперь `Self` возвращается. |
| 52–54 | Публичный `count` читает явное поле времени выполнения, а не скрытые данные указателя `Area`. |
| 56–59 | `itemAt` сначала проверяет логическую границу. Ошибка не выполняет адресную операцию. |
| 61–62 | После проверки `Items.at` получает типизированный указатель `Items.Item` на существующий элемент. |
| 64–68 | `read` копирует встроенный `Target`; поэтому операция доступна только при `Copyable`. |
| 70–74 | `replace` переносит прежний встроенный `Target`, заполняет освободившееся место новым и возвращает прежнее значение. |
| 75–77 | Закрываются операция, `implementation` и аспект. |

Пустой массив имеет `root == null`, `capacity == 0`, `length == 0`. При
ошибке `make` уничтожение незавершённого `Self` вызывает:

```efen
Items.free(
    root: take self.root!,
    capacity: self.capacity,
    initializedCount: self.length
)
```

Вызов выполняется только при ненулевом корневом указателе. Размеры передаются отдельно,
потому что `Items.Area` их не хранит.

Индексирование, чтение и замена имеют сложность `O(1)`; создание — `O(length)`.

Для `replace` и очистки действует
[общее правило безотказного окна](README.md#общее-правило-применимости).
