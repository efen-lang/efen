# Непрерывный массив фиксированной длины

[К примерам](README.md) · [Исходник](contiguous-array.efen) ·
[Пространство `layout`](../layout/declaration.md#пространство-layout)

`FixedArray` объявлена структурой в `layout<T, A>`. `fill` берёт у аллокатора `A` память под одну область ровно
нужного размера, записывает все элементы, и длина больше не меняется.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1 | Параметры `T` и `A` стоят на `layout`. Область `Area<T>` состоит из непрерывных элементов формы `T`. `A` — аллокатор области с ограничением `memory::Allocator`, по умолчанию `mm` ([коллекция и её аллокатор](../allocator.md#коллекция-и-её-аллокатор)). `layout` объявлен `private`: поля пишет модуль. |
| 2 | Типом программы служит именованная структура из `layout`, без обёртки и `Self`. |
| 3 | `items` владеет областью и допускает `null`: пустой массив памяти не выделяет. Инвариант поля: область есть ровно тогда, когда `count` больше нуля, и число её элементов равно `count`. |
| 4 | `count` читает любой код. |
| 5 | Все `count` элементов области заняты: `items.initialized == count`. |
| 6 | Строка `set Elements: items[_]` говорит, что элементы массива — слоты области `items`; `a[_]` значит `a.Elements` ([множества и области](../layout/declaration.md#множества-и-области), правило 14). |
| 10 | Стратегия для `FixedArray<T, A>`; `Movable` нужен для `take` элемента. |
| 11–13 | `fill` объявлена публичной функцией. Предусловие: массив пуст, `items == null` доказан. Запись во владеющее поле `layout` требует поля, доказанно равного `null`. Инвариант поля допускает и область нулевой длины, поэтому одного `count == 0` для этого мало. Конструктора `FixedArray` не объявляет, поэтому наполнением служит обычный метод над значением `FixedArray<Int>()`. Параметр `make` объявлен `nofail`, как `each` у `drain`: исключение из него застало бы локальную область `fresh` с заполненными слотами, которую код ещё не вернул аллокатору ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), локальный владелец, правило 1). |
| 14 | Нулевой размер оставляет `items == null`. |
| 15–16 | Память под область `fill` берёт у аллокатора `A` по контракту, а приведение `memory as Area<T> { value.count == size }` делает из неё область из `size` неинициализированных слотов ([создание элемента](../layout/operations.md#62-создание-элемента), правило 10). Аллокатора у самой области нет. `A.allocate` бросает `AllocationError` до первой записи в структуру и при неудаче ничего не меняет. |
| 17–22 | `make(i)` строит значение до записи, запись в неинициализированный элемент `fresh[i]` его инициализирует. Цикл не бросает исключений, поэтому область `fresh` на пути исключения не остаётся. |
| 23–24 | Область и длина публикуются вместе: инвариант поля `items` верен на выходе. |
| 28–34 | `replace` снимает прежнее значение и записывает новое; право `mut`, потому что `take` элемента делает ссылки на него мёртвыми. |
| 36–46 | `drain` опустошает массив для типа `T`, который не соответствует `ImplicitlyDestroyable`: забирает каждый занятый элемент, передаёт его функции `each`, стирает вид области и возвращает память аллокатору (`A.deallocate(ptr: old as Pointer)`), оставляет `items == null` и `count == 0`. После неё выход из области видимости допустим: владеющее поле доказанно равно `null` ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), значение структуры, правило 4). Параметр `each` объявлен `nofail` ([nofail](../../throws.md#nofail-системная-точка-ответственности)): исключение из него застало бы локальную область с заполненными слотами, а значение `T` здесь неявно не уничтожается. |
| 49–63 | Память структуры возвращает `dispose`: стратегия пишет `implements Disposable`, а вызывает функцию компилятор там, где значение кончается. Она забирает все `count` элементов, затем стирает вид области, в которой не осталось инициализированных слотов, и возвращает память аллокатору `A`; функция оставляет `items == null` и `count == 0`. В теле `dispose` условие `T conforms ImplicitlyDestroyable` верно без `requires` ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), значение структуры, правила 1, 2 и 6). |
| 65–71 | Чтение возвращает копию элемента, написанную словом `copy`, поэтому требует `T: Copyable`. Индекс проверяет `requires`. |
| 73–101 | `FixedArrayAccess` соответствует `Sliceable` с правом `read` и `edit`: `at` даёт ссылку ровно на слот `index` (`&Access<self.items![index]> T`), `slice` — срез `Slice<T>` ровно на слоты `start ..< end`. Индекс вне границ бросает `BoundsError`. `FixedArraySwap` соответствует `Swappable`: `swapAt` переставляет два элемента ([контракты операторов](../../runtime/lang-roles.md#контракты-операторов), [проверка пересечения](../../types/access-regions.md#проверка-пересечения), правило 3). Добавления нет: длина массива не меняется. |
| 103–111 | Использование. `number` объявлена `nofail`, как требует параметр `make`. `FixedArray<Int>()` берёт аллокатор по умолчанию, `mm`. В конце области видимости компилятор вызывает `dispose`. |

## Свойства

Пустой массив — `items == null`, `count == 0`. Индексирование, чтение и замена имеют сложность `O(1)`, наполнение — `O(size)`.

Для `replace`, `drain` и `dispose` действует [общее правило безотказного окна](README.md#общее-правило-применимости).
