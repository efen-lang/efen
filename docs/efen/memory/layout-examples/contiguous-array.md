# Непрерывный массив фиксированной длины

[К примерам](README.md) · [Исходник](contiguous-array.efen) ·
[Пространство `layout`](../layout-reference.md#пространство-layout)

`FixedArray` объявлена структурой в `layout<T>`. `fill` выделяет одну область ровно нужного размера, записывает все
элементы, и длина больше не меняется.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1–2 | Параметр `T` стоит на `layout`. Область `Items` состоит из непрерывных элементов формы `T`. `layout` объявлен `private`: поля пишет модуль. |
| 4 | Типом программы служит именованная структура из `layout`, без обёртки и `Self`. |
| 5 | `items` владеет областью и допускает `null`: пустой массив памяти не выделяет. Инвариант поля: число элементов области равно `count`. |
| 6 | `count` читает любой код. Все `count` элементов области заняты: `0 ..< count`. |
| 10 | Стратегия для `FixedArray<T>`; `Movable` нужен для `take` элемента. |
| 11–13 | `fill` объявлена публичной функцией. Предусловие: массив пуст, `items == null` доказан. Запись во владеющее поле `layout` требует поля, доказанно равного `null`. Инвариант поля допускает и область нулевой длины, поэтому одного `count == 0` для этого мало. У структуры из `layout` нет инициализатора, поэтому наполнением служит обычный метод над значением `FixedArray<Int>()`. |
| 14 | Нулевой размер оставляет `items == null`. |
| 15 | Область берётся у менеджера памяти. Размер в байтах записан в вызове (`size * sizeOf(T)`), число слотов называет условие после приведения. Выделение бросает `AllocationError` до первой записи в структуру. |
| 16–21 | `make(i)` строит значение до записи, запись в неинициализированный элемент `fresh[i]` его инициализирует. Функция `make` не бросает исключений, поэтому между выделением и публикацией выхода нет. |
| 22–23 | Область и длина публикуются вместе: инвариант поля `items` верен на выходе. |
| 27–33 | `replace` снимает прежнее значение и записывает новое; право `mut`, потому что `take` элемента делает ссылки на него мёртвыми. |
| 35–45 | `drain` опустошает массив для типа `T`, который не соответствует `ImplicitlyDestroyable`: забирает каждый занятый элемент, передаёт его функции `each`, возвращает память и оставляет `items == null` и `count == 0`. После неё выход из области видимости допустим: владеющее поле доказанно равно `null` ([ничего не теряется](../layout-reference.md#74-ничего-не-теряется), значение структуры, правило 4). |
| 48–62 | Память структуры возвращает `dispose`: стратегия пишет `implements Disposable`, а вызывает функцию компилятор там, где значение кончается. Она забирает все `count` элементов, возвращает область через `mm.free(old as Pointer)` и оставляет `items == null` и `count == 0`. В теле `dispose` условие `T conforms ImplicitlyDestroyable` верно без `requires` ([ничего не теряется](../layout-reference.md#74-ничего-не-теряется), значение структуры, правила 1 и 6). |
| 64–70 | Чтение возвращает копию элемента, написанную словом `copy`, поэтому требует `T: Copyable`. Индекс проверяет `requires`. |
| 76–80 | Использование. В конце области видимости и на выходе через исключение из `fill` компилятор вызывает `dispose`. |

## Свойства

Пустой массив — `items == null`, `count == 0`. Индексирование, чтение и замена имеют сложность `O(1)`, наполнение — `O(size)`.

Для `replace`, `drain` и `dispose` действует [общее правило безотказного окна](README.md#общее-правило-применимости).
