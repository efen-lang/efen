# Непрерывный массив фиксированной длины

[К примерам](README.md) · [Исходник](contiguous-array.efen) ·
[Пространство `layout`](../layout/declaration.md#пространство-layout)

`FixedArray` объявлена структурой в `layout<T>`. `fill` выделяет одну область ровно нужного размера, записывает все
элементы, и длина больше не меняется.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1 | Параметр `T` стоит на `layout`. Область `Area<T>` состоит из непрерывных элементов формы `T`. `layout` объявлен `private`: поля пишет модуль. |
| 2 | Типом программы служит именованная структура из `layout`, без обёртки и `Self`. |
| 3 | `items` владеет областью и допускает `null`: пустой массив памяти не выделяет. Инвариант поля: область есть ровно тогда, когда `count` больше нуля, и число её элементов равно `count`. |
| 4 | `count` читает любой код. |
| 5 | Все `count` элементов области заняты: `items.initialized == count`. |
| 9 | Стратегия для `FixedArray<T>`; `Movable` нужен для `take` элемента. |
| 10–12 | `fill` объявлена публичной функцией. Предусловие: массив пуст, `items == null` доказан. Запись во владеющее поле `layout` требует поля, доказанно равного `null`. Инвариант поля допускает и область нулевой длины, поэтому одного `count == 0` для этого мало. Конструктора `FixedArray` не объявляет, поэтому наполнением служит обычный метод над значением `FixedArray<Int>()`. Условие `T conforms ImplicitlyDestroyable || size == 0` нужно пути исключения: если `make` бросит, область `fresh` уничтожит заполненные слоты ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), значение структуры, правило 6). |
| 13 | Нулевой размер оставляет `items == null`. |
| 14 | Форма `Area<T>(count: size)` создаёт область из `size` неинициализированных слотов: память даёт стратегия `Allocator` области ([создание элемента](../layout/operations.md#выделение-и-освобождение--переход-между-множествами), правило 10). Форма бросает `AllocationError` до первой записи в структуру. |
| 15–20 | `make(i)` строит значение до записи, запись в неинициализированный элемент `fresh[i]` его инициализирует. Тип `make` не пишет `throws`, но сбой сквозь него проходит ([nofail](../../throws.md#nofail-системная-точка-ответственности)): тогда локальная область `fresh` кончается как любое значение, её деструктор уничтожает слоты `0 ..< i` и возвращает память ([слоты области](../layout/operations.md#частичная-инициализация-и-очистка), правило 6). |
| 21–22 | Область и длина публикуются вместе: инвариант поля `items` верен на выходе. |
| 26–32 | `replace` снимает прежнее значение и записывает новое; право `mut`, потому что `take` элемента делает ссылки на него мёртвыми. |
| 34–44 | `drain` опустошает массив для типа `T`, который не соответствует `ImplicitlyDestroyable`: забирает каждый занятый элемент, передаёт его функции `each`, возвращает память и оставляет `items == null` и `count == 0`. После неё выход из области видимости допустим: владеющее поле доказанно равно `null` ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), значение структуры, правило 4). Параметр `each` объявлен `nofail` ([nofail](../../throws.md#nofail-системная-точка-ответственности)): исключение из него застало бы локальную область с заполненными слотами, а значение `T` здесь неявно не уничтожается. |
| 46–59 | Память структуры возвращает `dispose`: стратегия пишет `implements Disposable`, а вызывает функцию компилятор там, где значение кончается. Она забирает все `count` элементов, в конце блока область `old` кончается без инициализированных слотов, и компилятор возвращает её аллокатору; функция оставляет `items == null` и `count == 0`. В теле `dispose` условие `T conforms ImplicitlyDestroyable` верно без `requires` ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), значение структуры, правила 1 и 6). |
| 61–67 | Чтение возвращает копию элемента, написанную словом `copy`, поэтому требует `T: Copyable`. Индекс проверяет `requires`. |
| 69–95 | `FixedArrayAccess` соответствует `Sliceable` с правом `read` и `edit`: `at` даёт ровно слот `index`, `slice` — срез `Slice<T>` ровно на слоты `start ..< end`. Индекс вне границ бросает `BoundsError`. `FixedArraySwap` соответствует `Swappable`: `swapAt` переставляет два элемента ([контракты операторов](../../runtime/lang-roles.md#контракты-операторов), [проверка пересечения](../../types/access-regions.md#проверка-пересечения), правило 3). Добавления нет: длина массива не меняется. |
| 101–105 | Использование. В конце области видимости и на выходе через исключение из `fill` компилятор вызывает `dispose`. |

## Свойства

Пустой массив — `items == null`, `count == 0`. Индексирование, чтение и замена имеют сложность `O(1)`, наполнение — `O(size)`.

Для `replace`, `drain` и `dispose` действует [общее правило безотказного окна](README.md#общее-правило-применимости).
