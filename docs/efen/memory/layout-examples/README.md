## Общее правило применимости

Перед изменением опубликованного состояния выполняются все проверки,
арифметика и выделения, способные завершиться ошибкой. После открытия условий
`layout` перенос `Target`, `Items.initialize`, `Items.extract`, `Items.move`,
`Items.free` и запись служебных полей не бросают исключений, не
приостанавливаются и не вызывают код, способный обратиться к изменяемой
структуре.

Если выбранный `Target` или менеджер памяти не выполняет этот контракт,
представление обязано использовать другой алгоритм с отдельной подготовкой и
безотказной публикацией. Приведённые прямые алгоритмы к такому типу неприменимы.

Операции, выполняющие явный `take` либо `Items.move`, условно требуют
`Target: Movable`; общий API выражает то же через `Element: Movable`. Это
ограничение делает перенос законным, но не доказывает, что physical placement не
бросает и не входит повторно. Compiler обеспечивает нужное окно через
prepare/commit/cleanup, а concrete representation обязана доказать refinement
этих generated transitions; новая аннотация в Array-коде не требуется.

`replace(place, value)` является одним compiler-known атомарным переходом layout,
который concrete representation обязана доказанно реализовать. Он
потребляет новый владеющий `value`, заменяет содержимое `place` и возвращает
прежнее владеющее значение. Compiler lowering не создаёт внутри него exceptional
или observation edge: fallible prepare происходит раньше, а возможная ошибка
доставляется только после завершения либо отката перехода и закрытия условий.
Это логическая атомарность относительно layout, не одна CPU-инструкция.
