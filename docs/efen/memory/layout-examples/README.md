## Форма примеров

- Модуль содержит один `private layout<T: Movable>`. Параметр стоит на `layout`. Вне `layout` имена пишутся с
  аргументами (`Vector<T>`, `Nodes<T>.Item`).
- Типом программы служит именованная структура из `layout` (`Vector`, `SinglyList`). Обёртки, `Self` и аспекта нет.
- Методы записаны стратегией `strategy<T> for Vector<T>`; `mut fn` в ней — то же, что функция с
  параметром `self: mut Vector<T>`. Вспомогательные функции — `private fn` модуля.
- Право читается по итогу функции ([`edit` и `mut`](../layout/operations.md#edit-и-mut-в-layout)): вставка узла в
  список — `edit`; `append` вектора — `mut`, потому что худший путь перевыделяет область; удаление — `mut`. Право на
  узел функция берёт из своего права на список, которому узел принадлежит
  ([право на элемент](../layout/functions.md#82-право-на-элемент)): `unlinkAt` получает список параметром `mut`,
  поэтому узел из него уходит. `nodeAtMut` написана для удобства: слово `mut` в её результате называет право, которое
  указатель даёт сам, и обязательным не служит (там же, правило 2).
- Форма с полями `Node<T>(value: take value)` создаёт узел и записывает названные поля, а поле со значением по
  умолчанию (`next`) получает его
  ([создание элемента](../layout/operations.md#выделение-и-освобождение--переход-между-множествами), правило 3).
- Память входит в множество формой с полями или формой области `Items<T>(count: next)`; её даёт стратегия
  `Allocator` множества. Выходит она с концом значения: узла после `node as own Nodes<T>.Item`, области без
  инициализированных слотов. Вызова освобождения в коде нет. Якоря переходят через `tie`, значения `own` — через `take`.
- Значение покидает элемент области через `take items![i]`; запись в неинициализированный элемент его инициализирует;
  перенос — `take` из старого элемента и запись в новый.
- Пользовательского деструктора у структуры из `layout` нет. Память каждой структуры возвращает функция `dispose` её
  стратегии (`implements Disposable`). Её вызывает компилятор там, где значение кончается, в том числе на выходе
  через исключение из `append` ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется)). Локальную
  область, которую `fill` ещё не записал во владельца, на выходе через исключение освобождает её деструктор
  ([слоты области](../layout/operations.md#частичная-инициализация-и-очистка), правило 7).
  `dispose` уничтожает элементы типа `T`, поэтому неявно освобождается только структура, у которой `T` соответствует
  `ImplicitlyDestroyable` ([деструкторы](../../disposable.md#implicitlydestroyable)). При любом другом `T`
  вызывающий сначала забирает элементы: у списков через `remove`, у массивов через `drain(each:)`. Функция `drain`
  отдаёт каждый элемент функции `each`, возвращает память и оставляет владеющие поля равными `null`. После этого
  выход из области видимости допустим.
- Ограничения на элемент: перенос требует `T: Movable`, и это ограничение стоит у `layout`: `layout<T: Movable>`.
  Чтение возвращает копию, написанную словом `copy`, требует `T: Copyable` и вынесено в отдельную стратегию.

## Общее правило применимости

Инварианты структуры верны в каждой точке, где возможно исключение
([места, где инвариант верен](../layout/invariants.md#инварианты)). Поэтому функция либо выполняет все проверки,
арифметику и выделения, способные завершиться ошибкой, до первой записи в поле структуры, либо оставляет после
каждой записи состояние, в котором инварианты верны. Так устроен `ensureChunks` блочного массива: каталог
публикуется с выполненными инвариантами, затем выделяется блок. Между этими границами функция не приостанавливается и не
вызывает код, способный обратиться к
изменяемой структуре. Перенос значения (`take` из элемента и запись в другой) и запись служебных полей
(`count`, `capacity`) подпадают под то же правило. `edit` дополнительно требует, чтобы между `tie` из структуры и
`tie` обратно функция не вызывала ничего, что может бросить исключение.

Если тип `T` или менеджер памяти этого не гарантирует, нужен другой алгоритм с отдельной подготовкой и безотказной
публикацией; приведённые прямые алгоритмы к такому типу неприменимы.

## Что в примерах не записано

- Слово `throws` в сигнатурах: форма с полями бросает `AllocationError` ([аллокатор](../allocator.md)), а у функции с
  телом список исключений выводится ([throws](../../throws.md)), поэтому в эскизах он не записан.
- Выбор представления у `Array`: прежний эскиз `Array` с параметром-аспектом убран из
  [`array-contracts.efen`](array-contracts.efen); как один тип выбирает форму хранения, справочник правил `layout` не описывает.
