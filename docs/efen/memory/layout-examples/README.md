Примеры показывают проект синтаксиса исходного языка. Они не компилировались существующим компилятором.

## Форма примеров

- Модуль содержит один блок `private layout<T> { … }`. Параметр стоит на блоке; снаружи имена пишутся с
  аргументами (`Vector<T>`, `Nodes<T>.Item`).
- Тип программы — именованная структура блока (`Vector`, `SinglyList`). Обёртки, `Self` и аспекта нет.
- Методы записаны стратегией `strategy<T> for Vector<T> { … }`; `mut fn` в ней — то же, что функция с
  параметром `self: mut Vector<T>`. Вспомогательные функции — `private fn` модуля.
- Право читается по итогу функции ([`edit` и `mut`](../layout.md#edit-и-mut-в-layout)): вставка узла в список —
  `edit`; `append` вектора — `mut`, потому что худший путь перевыделяет область; удаление — `mut`.
- Память входит в множество вызовом `mm.allocate(…) as …` и выходит вызовом `mm.free(x as own Pointer)` или
  `mm.free(area as Pointer)`. Якоря переходят через `tie`, значения `own` — через `take`.
- Значение покидает элемент области через `take items![i]`; запись в пустой элемент его инициализирует; перенос —
  `take` из старого элемента и запись в новый.
- Деструктора у структуры `layout` нет. Каждый пример заканчивается воротами `release`: они снимают элементы,
  возвращают память и оставляют владеющие поля пустыми. Выход из области с непустым владеющим полем — ошибка
  компиляции, поэтому в примерах использования перед концом области стоит вызов `release`.
- Ограничения на элемент: перенос требует `T: Movable`, это ограничение стоит у блока, `layout<T: Movable>`;
  чтение копией требует `T: Copyable` и вынесено в отдельную стратегию.

## Общее правило применимости

Перед изменением структуры выполняются все проверки, арифметика и выделения, способные завершиться ошибкой. После
первой записи в поле структуры функция не бросает исключений, не приостанавливается и не вызывает код, способный
обратиться к изменяемой структуре. Перенос значения (`take` из элемента и запись в другой) и запись служебных полей
(`count`, `capacity`) подпадают под то же правило. `edit` дополнительно требует, чтобы между `tie` из структуры и
`tie` обратно функция не вызывала ничего, что может бросить исключение.

Если тип `T` или менеджер памяти этого не гарантирует, нужен другой алгоритм с отдельной подготовкой и безотказной
публикацией; приведённые прямые алгоритмы к такому типу неприменимы.

## Что в примерах не записано

- Канал ошибки выделения: `layout.md` показывает `mm.allocate(…)` без него, поэтому выделение в примерах не бросает.
- Закон «`tail` — последний узел цепочки» у списков: в [каталоге](../layout-catalogue.md#двусвязный-список) он
  не закрыт; записано его следствие.
- Выбор представления у `Array`: прежний эскиз `Array` с параметром-аспектом убран из
  [`array-contracts.efen`](array-contracts.efen); как один тип выбирает форму хранения, `layout.md` не описывает.
