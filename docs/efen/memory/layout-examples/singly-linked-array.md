# Односвязный список

[К примерам](README.md) · [Исходник](singly-linked-array.efen) ·
[Основная модель](../addresses.md)

Каждый `Target` встроен в отдельно выделенный узел. Владение цепочкой идёт от
`self.head` через `Item.next`.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1 | Аспект получает исходный тип элемента `Target`; конкретный Array доступен как `Self`. |
| 2–5 | Layout отделён от поведения. `Items` содержит каждый узел, достижимый из head по next. |
| 7–10 | `Item` физически встраивает Target; nullable `next` владеет другим `Items.Item`. |
| 12–13 | `Self.head` является владеющим root списка. |
| 15–22 | Tail пуст вместе с head; ненулевой tail достижим и имеет `next == null`. Закрывающая строка 22 завершает условие свойства. |
| 24–27 | Runtime length совпадает с логическим количеством Items; строка 27 закрывает Self. |
| 28–30 | Закрывается layout и начинается implementation. |
| 31–37 | Явный конструктор создаёт пустой Self; Items в этот момент пуст. |
| 39–42 | `itemAt` проверяет индекс до разыменования head. |
| 44–50 | Cursor начинает с head и делает ровно index переходов. |
| 52–53 | Возвращается descriptor-specific `Items.Item`. |
| 55–57 | `count` читает явную length. |
| 59–63 | `read` копирует embedded-Target, поэтому требует Copyable. |
| 65–70 | `replace` переносит прежний Target, сразу заполняет место новым и возвращает прежний. |
| 72–76 | `append` сначала вычисляет длину и выделяет новый узел в descriptor Items. |
| 78–84 | Пустая и непустая ветви передают владение новому узлу в head либо старый tail.next. |
| 86–87 | Length публикуется после успешного связывания. |
| 89–92 | `insert` проверяет допустимую позицию до изменения. |
| 94–97 | Вставка в конец переиспользует уже проверенный append. |
| 99–102 | Для остальных позиций узел выделяется до изъятия опубликованных ссылок. |
| 104–111 | В начале владелец head переносится в item.next; в середине аналогично переносится before.next. |
| 113–114 | После связывания публикуется новая length. |
| 116–119 | `remove` проверяет индекс до изменения. |
| 121–138 | Владеющий victim изымается из head или before.next; суффикс занимает освободившееся место, tail исправляется при удалении последнего узла. |
| 140–144 | Length уменьшается, Target переносится наружу, descriptor освобождает частично извлечённый узел, затем возвращается результат. |
| 145–146 | Закрываются implementation и аспект. |

Все потенциально падающие проверки и allocation выполняются до изменения
опубликованной цепочки. После успешного выделения перенос Target, записи ссылок,
metadata и `Items.free` не бросают исключений, не приостанавливаются и не
вызывают наблюдающий код.

`itemAt`, `insert` и `remove` имеют `O(index)`; `append` — `O(1)`.
