# Односвязный список

[К примерам](README.md) · [Исходник](singly-linked-array.efen) ·
[Пространство `layout`](../layout.md#пространство-layout)

Значение `T` лежит в отдельно выделенном узле. Владение цепочкой начинается с `head` и идёт через `Node.next`:
каждый узел под одним якорем. Хвост `tail` — невладеющий указатель на последний узел.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1–2 | Параметр `T` стоит на блоке. `Nodes` — множество узлов без обещания непрерывности: узлы выделяет `mm.allocate`, а не нарезка области. |
| 4–7 | `Node` хранит значение и якорь следующего узла. Якорь — точка уничтожения узла: указатели на него допустимы. |
| 9 | Тип программы — именованная структура блока, без обёртки и `Self`. |
| 10–11 | `head` — якорь первого узла. `tail` — указатель в ту же структуру; замкнутость это разрешает. |
| 12 | `count` читает любой код, пишет модуль. |
| 14–19 | Законы: `count` равен длине цепочки от `head` по `next`; `head` и `tail` пусты вместе; на `tail` цепочка кончается. |
| 23–25 | `newNode` создаёт узел вызовом `mm.allocate(…) as Node<T>(value: take value)`; значение переходит в узел. Выделение — единственный отказ, он стоит раньше любой связи. Узел принадлежит вызывающему как `anchor`. |
| 27–37 | `nodeAt` обходит `index` переходов и возвращает указатель с правом `edit`: он берёт право списка и позволяет писать в узел. Ничего не переносится, поэтому хватает `edit`. |
| 39–58 | `unlinkAt` — помощник. Он вынимает узел из цепочки: `tie list.head` или `tie before.next`, затем передаёт следующий узел на место вынутого. Якорь вынутого узла уходит в результат, `tail` исправляется, если ушёл последний. |
| 60 | Стратегия для `SinglyList<T>`; `Movable` нужен для `take`. |
| 61–69 | `pushFirst` — `edit`: ни один узел не перенесён и не уничтожен, меняется только точка уничтожения. Новый узел связывается до записи в `head`. |
| 71–80 | `append` — `edit`: узел привязывается к `tail.next` (или к `head` у пустого списка), `tail` перенацеливается. |
| 82–99 | `insert` — `edit`: узел встаёт между `before` и его преемником, ни один узел не уходит. Края вызывают `pushFirst` и `append`. |
| 101–107 | `remove` — `mut`: узел покидает структуру. Значение снимается `take node.value`, память узла возвращает `mm.free(node as own Pointer)`. Индекс вне границ — `null`. |
| 109–116 | `replace` снимает прежнее значение и записывает новое: `take` из поля — `mut`. |
| 118–126 | `release` — ворота уничтожения. У структуры `layout` деструктора нет: код вынимает узлы по одному, снимает значения и освобождает память узла. |
| 129–141 | Чтение копирует значение и требует `T: Copyable`; поля оно не пишет. |
| 143–147 | Использование. Перед выходом из области `list.release()` освобождает цепочку: компилятор отвергает выход со структурой, у которой владеющее поле не пусто. |

## Форма цепочки

Форму цепочки задаёт закон: `Nodes.chain(from: head, by: Node.next, until: null)` — узлы, достижимые от `head`
по `next` до `null`. Повторов в цепочке нет: у значения один якорь. Поэтому `count` равен числу узлов, а `tail`
есть последний из них. Закон «`tail` — последний узел цепочки» полностью `layout.md` не называет
(в [каталоге](../layout-catalogue.md#двусвязный-список) он помечен как не закрытый); здесь записано необходимое
следствие: `tail == null || tail!.next == null`.

`nodeAt`, `insert`, `remove` и `replace` имеют `O(index)`; `append` и `pushFirst` — `O(1)`.

Для связывания и освобождения действует
[общее правило безотказного окна](README.md#общее-правило-применимости).
