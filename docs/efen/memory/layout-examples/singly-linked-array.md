# Односвязный список

[К примерам](README.md) · [Исходник](singly-linked-array.efen) ·
[Основная модель](../addresses.md)

Каждый `Target` встроен в отдельно выделенный узел. Владение цепочкой начинается
с `self.head` и продолжается через `Item.next`.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1 | Аспект получает исходный тип элемента `Target`; конкретный `Array` доступен как `Self`. |
| 2–4 | `set Items: Item` задаёт множество узлов без блока условий; форму цепочки говорят законы `invariants` ниже. |
| 6–9 | `Item` физически встраивает `Target`; допускающий `null` указатель `next` владеет другим `Items.Item`. |
| 11–12 | `Self.head` является владеющим корневым указателем списка. |
| 13–14 | `tail` — невладеющий указатель на последний узел, `length` — длина времени выполнения; блоков `{ }` у них нет, их условия читают чужое состояние и стоят в `invariants`. |
| 15 | Призрачное поле `nodes` хранит узлы по порядку; при выполнении его нет, меняют его только строки `ghost`. |
| 17–25 | `invariants`: `head` — первый элемент `nodes`, `next` каждого — следующий, у последнего `next == null`, `nodes.count == Items.count`, `tail` — последний, `length == nodes.count`. |
| 26–28 | Закрываются `Self` и `layout`, начинается `implementation`. |
| 29–35 | Явный конструктор создаёт пустой `Self`; `Items` и `nodes` в этот момент пусты. |
| 37–40 | `itemAt` проверяет индекс до разыменования `head`. |
| 42–48 | Курсор начинает с `head` и делает ровно `index` переходов. |
| 50–51 | Возвращается указатель `Items.Item`, связанный с конкретным дескриптором. |
| 53–55 | `count` читает явную длину. |
| 57–61 | `read` копирует встроенный `Target`, поэтому требует `Copyable`. |
| 63–70 | `replace` требует `Movable`; атомарная операция `replace(place, value)` устанавливает новый `Target` и возвращает прежний. |
| 72–78 | `append` требует `Movable`, вычисляет длину и вызывает `Items.allocate` внутри открытой structural group. |
| 79 | `ghost nodes = nodes + Sequence(item)` дописывает новый узел в конец `nodes`, пока `item` ещё у функции. |
| 81–87 | Пустая и непустая ветви записывают владеющий указатель на новый узел в `head` либо `tail.next`. |
| 89–90 | Поле длины обновляется после успешного связывания; к закрытию функции `invariants` снова верны. |
| 92–97 | `insert` требует `Movable` и проверяет допустимую позицию до изменения. |
| 99–102 | Вставка в конец вызывает уже проверенный `append`. |
| 104–107 | Для остальных позиций узел выделяется до изъятия опубликованных ссылок. |
| 108 | Ghost-строка вставляет узел в `nodes` на место `index`: префикс, `Sequence(item)`, суффикс. |
| 110–117 | В начале владеющий указатель из `head` переносится в `item.next`; в середине аналогично переносится указатель из `before.next`. |
| 119–120 | После связывания обновляется поле длины. |
| 122–127 | `remove` требует `Movable` и проверяет индекс до изменения. |
| 129–130 | Ghost-строка убирает элемент `index` из `nodes` (префикс и суффикс без него) до того, как `victim` изъят из списка. |
| 132–147 | Владеющий `victim` изымается из `head` или `before.next`; суффикс занимает освободившееся место, `tail` исправляется при удалении последнего узла. |
| 149–153 | Длина уменьшается, `Target` переносится наружу, дескриптор освобождает частично извлечённый узел, затем возвращается результат. |
| 154–155 | Закрываются `implementation` и аспект. |

`tail` объявлен как `var tail: read Items.Item?`: `var` разрешает менять само
поле, а `read` относится к сохранённому невладеющему указателю. Запись
`tail!.next` использует отдельное право `mut` реализации на layout `Items`; она не
получает это право из `read`-указателя.

Форму цепочки задаёт призрачная последовательность `nodes` и её законы в
`invariants`: первый элемент — `head`, `next` каждого — следующий, у последнего
`next == null`, элементов столько же, сколько в `Items`. Повторов нет: путь,
дошедший до `null`, не ходит по кругу. Значит, все и только `Items` стоят в
цепочке по одному разу. Отдельный закон `tail == nodes.last` связывает `tail` с
последним узлом, а `(head == null) == (tail == null)` следует из первого и
пятого законов. Каждая операция, меняющая цепочку, одной строкой `ghost nodes = …`
держит последовательность в ногу с узлами; компилятор проверяет законы в точке
восстановления.

При закрытом layout компилятор полностью готовит owning `Item(take value, ...)` и
выполняет fallible allocation во внутренний provisional resource. Только затем
он открывает общую structural group, безотказно публикует member, связывает его,
обновляет `nodes` и length и закрывает group. Все failure paths allocation происходят
раньше и видят старый закрытый список. Открытое окно compiler сам строит без
call, safepoint, suspension или reentry; representation обязана доказать
refinement безотказного publish, иначе её операция отклоняется. Новый surface API
или annotation для этого не нужен.

`itemAt`, `insert` и `remove` имеют `O(index)`; `append` — `O(1)`.
