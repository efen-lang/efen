# Односвязный список

[К примерам](README.md) · [Исходник](singly-linked-array.efen) ·
[Пространство `layout`](../layout/declaration.md#пространство-layout)

Значение `T` хранится в отдельно выделенном узле. Владение цепочкой начинается с `head` и идёт через `Node.next`:
каждый узел под одним якорем. Хвост `tail` — невладеющий указатель на последний узел.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1–2 | Параметр `T` стоит на `layout`. `Nodes` объявлено множеством узлов без обещания непрерывности: узлы создаёт форма с полями, а не нарезка области. |
| 4–7 | `Node` хранит значение и якорь следующего узла. Якорь — точка уничтожения узла: указатели на него допустимы. У `next` значение по умолчанию `null`: приведение `as Node<T>(value: take value)` его записывает. |
| 9 | Типом программы служит именованная структура из `layout`, без обёртки и `Self`. |
| 10–11 | `head` — якорь первого узла. `tail` — указатель в ту же структуру; чистота это разрешает. |
| 12 | `count` читает любой код, пишет модуль. |
| 14–19 | Инварианты: `count` равен длине цепочки от `head` по `next`; `head` и `tail` пусты вместе; `tail` равен последнему узлу цепочки (`tail == nodes.last`). |
| 23–25 | `newNode` создаёт узел формой с полями `Node<T>(value: take value)`: память даёт стратегия `Allocator` множества `Nodes`, значение переходит в узел, а `next` получает `null` по умолчанию поля ([создание элемента](../layout/operations.md#выделение-и-освобождение--переход-между-множествами)). Форма бросает `AllocationError`; это единственный отказ, он стоит раньше любой связи. Узел принадлежит вызывающему как `own`. |
| 27–37 | `nodeAt` обходит `index` переходов и возвращает указатель с правом `edit`: он берёт право списка и позволяет писать в узел. Ничего не переносится, поэтому хватает `edit`. Его вызывает `insert`. |
| 39–49 | `nodeAtMut` выполняет тот же обход при `list: mut`, и слово `mut` в её результате называет право, которое указатель даёт сам. Обязательной она не служит: право на узел функция берёт из своего права на список, которому узел принадлежит ([право на элемент](../layout/functions.md#82-право-на-элемент), правила 1 и 2). |
| 51–70 | `unlinkAt` служит помощником с параметром `list: mut`. Он вынимает узел из цепочки: `tie list.head` или `tie before.next`, затем передаёт следующий узел на место вынутого. Уход узла из структуры разрешает право `mut` на список, который называет источник указателя `before` ([право на элемент](../layout/functions.md#82-право-на-элемент), правило 5). Якорь вынутого узла уходит в результат, `tail` исправляется, если ушёл последний. |
| 72 | Стратегия для `SinglyList<T>`; `Movable` нужен для `take`. |
| 73–81 | `pushFirst` — `edit`: ни один узел не перенесён и не уничтожен, меняется только точка уничтожения. Новый узел связывается до записи в `head`. |
| 83–92 | `append` требует `edit`: узел привязывается к `tail.next` (или к `head` у пустого списка), затем `tail` получает указатель на новый узел. Имя `node` после `tie node` остаётся невладеющим указателем на узел ([перенос владения](../layout/operations.md#64-перенос-владения), правило 1). Поле `next` нового узла равно `null` по умолчанию, поэтому инвариант `tail == nodes.last` на выходе верен. |
| 94–111 | `insert` — `edit`: узел встаёт между `before` и его преемником, ни один узел не уходит. Края вызывают `pushFirst` и `append`. |
| 113–119 | `remove` — `mut`: узел покидает структуру. Значение снимается `take node.value`, затем `node as own Nodes<T>.Item` доказывает, что указателей на узел нет; в конце функции компилятор возвращает его память аллокатору ([удаление элемента](../layout/operations.md#переход-к-владению-as-own)). Индекс вне границ — `null`. |
| 121–126 | `replace` — `mut`: компилятору известная операция `replace(node.value, take value)` отдаёт прежнее значение и записывает новое одной операцией, без промежуточного пустого поля. |
| 129–140 | Память структуры возвращает `dispose`: стратегия пишет `implements Disposable`, а вызывает функцию компилятор там, где значение кончается. Она сначала обнуляет `tail`, чтобы к освобождению узла не оставалось хранимого указателя на него, затем вынимает узлы по одному и переводит каждый в `own`: в конце шага значение узла уничтожается, а память возвращается аллокатору. В теле `dispose` условие `T conforms ImplicitlyDestroyable` верно без `requires` ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), значение структуры, правила 1 и 6). Список значений, тип которых не соответствует `ImplicitlyDestroyable`, программа опустошает сама, через `remove`. Выход из области видимости допустим, когда доказано, что `head` равен `null` ([ничего не теряется](../layout/lifetime.md#74-ничего-не-теряется), значение структуры, правило 4). |
| 142–154 | Чтение возвращает копию значения, написанную словом `copy`, и требует `T: Copyable`; поля оно не пишет. |
| 156–161 | Использование. В конце области видимости и на выходе через исключение из `append` компилятор вызывает `dispose`. |

## Форма цепочки

Форму цепочки задаёт инвариант: `Nodes.chain(from: head, by: Node.next, until: null)` называет узлы, достижимые от
`head` по `next` до `null`. Повторов в цепочке нет: у значения один якорь. Поэтому `count` равен числу узлов.
Инвариант `tail == nodes.last` говорит, что `tail` указывает на последний из них
([цепочка](../layout/invariants.md#52-цепочка)). Из него следует `tail == null || tail!.next == null`.

`nodeAt`, `insert`, `remove` и `replace` имеют `O(index)`; `append` и `pushFirst` — `O(1)`.

Для связывания и освобождения действует
[общее правило безотказного окна](README.md#общее-правило-применимости).
