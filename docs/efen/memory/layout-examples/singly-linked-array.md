# Односвязный список

[К примерам](README.md) · [Исходник](singly-linked-array.efen) ·
[Пространство `layout`](../layout-reference.md#пространство-layout)

Значение `T` лежит в отдельно выделенном узле. Владение цепочкой начинается с `head` и идёт через `Node.next`:
каждый узел под одним якорем. Хвост `tail` — невладеющий указатель на последний узел.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1–2 | Параметр `T` стоит на блоке. `Nodes` — множество узлов без обещания непрерывности: узлы выделяет `mm.allocate`, а не нарезка области. |
| 4–7 | `Node` хранит значение и якорь следующего узла. Якорь — точка уничтожения узла: указатели на него допустимы. У `next` значение по умолчанию `null`: приведение `as Node<T>(value: …)` его записывает. |
| 9 | Тип программы — именованная структура блока, без обёртки и `Self`. |
| 10–11 | `head` — якорь первого узла. `tail` — указатель в ту же структуру; чистота это разрешает. |
| 12 | `count` читает любой код, пишет модуль. |
| 14–19 | Законы: `count` равен длине цепочки от `head` по `next`; `head` и `tail` пусты вместе; на `tail` цепочка кончается. |
| 23–25 | `newNode` создаёт узел вызовом `mm.allocate(…) as Node<T>(value: take value)`; значение переходит в узел, а `next` получает `null` по умолчанию поля. `mm.allocate` бросает `AllocationError`; это единственный отказ, он стоит раньше любой связи. Узел принадлежит вызывающему как `anchor`. |
| 27–37 | `nodeAt` обходит `index` переходов и возвращает указатель с правом `edit`: он берёт право списка и позволяет писать в узел. Ничего не переносится, поэтому хватает `edit`. Его вызывает `insert`. |
| 39–49 | `nodeAtMut` — тот же обход при `list: mut`; результат несёт право `mut`. Указатель берёт право значения, через которое получен ([откуда право на элемент](../layout-reference.md#пространство-layout)), поэтому узел, который уходит из списка или чьё значение снимается, достаётся через `mut`-параметр. |
| 51–70 | `unlinkAt` — помощник с параметром `list: mut`. Он вынимает узел из цепочки: `tie list.head` или `tie before.next`, где `before` получен от `nodeAtMut`, затем передаёт следующий узел на место вынутого. Право на уход узла из структуры — право на список, который называет источник указателя; `before` его несёт. Якорь вынутого узла уходит в результат, `tail` исправляется, если ушёл последний. |
| 72 | Стратегия для `SinglyList<T>`; `Movable` нужен для `take`. |
| 73–81 | `pushFirst` — `edit`: ни один узел не перенесён и не уничтожен, меняется только точка уничтожения. Новый узел связывается до записи в `head`. |
| 83–92 | `append` — `edit`: узел привязывается к `tail.next` (или к `head` у пустого списка), `tail` перенацеливается. Поле `next` нового узла равно `null` по умолчанию, закон `tail!.next == null` на выходе верен. |
| 94–111 | `insert` — `edit`: узел встаёт между `before` и его преемником, ни один узел не уходит. Края вызывают `pushFirst` и `append`. |
| 113–119 | `remove` — `mut`: узел покидает структуру. Значение снимается `take node.value`, память узла возвращает `mm.free(node as own Pointer)`. Индекс вне границ — `null`. |
| 121–126 | `replace` — `mut`: компилятору известная операция `replace(node.value, take value)` отдаёт прежнее значение и записывает новое одной операцией, без промежуточного пустого поля. |
| 128–138 | `release` — публичная функция уничтожения. Она уничтожает элементы типа `T`, поэтому несёт `requires T conforms ImplicitlyDestroyable`. У структуры `layout` деструктора нет: код сначала обнуляет `tail`, чтобы к освобождению узла не оставалось хранимого указателя на него, затем вынимает узлы по одному, снимает значения и освобождает память узла. |
| 141–153 | Чтение копирует значение и требует `T: Copyable`; поля оно не пишет. |
| 155–159 | Использование. `defer list.release()` стоит сразу после создания и освобождает цепочку на каждом пути, в том числе при исключении из `append`. |

## Форма цепочки

Форму цепочки задаёт закон: `Nodes.chain(from: head, by: Node.next, until: null)` — узлы, достижимые от `head`
по `next` до `null`. Повторов в цепочке нет: у значения один якорь. Поэтому `count` равен числу узлов, а `tail`
есть последний из них. Закон «`tail` — последний узел цепочки» полностью `layout-reference.md` не называет
(в [каталоге](../layout-catalogue.md#двусвязный-список) он помечен как не закрытый); здесь записано необходимое
следствие: `tail == null || tail!.next == null`.

`nodeAt`, `insert`, `remove` и `replace` имеют `O(index)`; `append` и `pushFirst` — `O(1)`.

Для связывания и освобождения действует
[общее правило безотказного окна](README.md#общее-правило-применимости).
