# Односвязный список

[К примерам](README.md) · [Исходник](singly-linked-array.efen) ·
[Основная модель](../addresses.md)

Каждый `Target` встроен в отдельно выделенный узел. Владение цепочкой начинается
с `self.head` и продолжается через `Item.next`.

## Построчный разбор

| Строки | Почему код написан так |
|---|---|
| 1 | Аспект получает исходный тип элемента `Target`; конкретный `Array` доступен как `Self`. |
| 2–5 | Compiler-known `chained` задаёт точную конечную цепочку: все и только `Items`, без повторов, от `head` до последнего `next == null`. |
| 7–10 | `Item` физически встраивает `Target`; допускающий `null` указатель `next` владеет другим `Items.Item`. |
| 12–13 | `Self.head` является владеющим корневым указателем списка. |
| 15–22 | `tail` пуст вместе с `head`; ненулевой `tail` достижим и имеет `next == null`. Закрывающая строка 22 завершает условие свойства. |
| 24–27 | Поле `length` времени выполнения совпадает с логическим количеством `Items`; строка 27 закрывает `Self`. |
| 28–30 | Закрывается `layout` и начинается `implementation`. |
| 31–37 | Явный конструктор создаёт пустой `Self`; `Items` в этот момент пуст. |
| 39–42 | `itemAt` проверяет индекс до разыменования `head`. |
| 44–50 | Курсор начинает с `head` и делает ровно `index` переходов. |
| 52–53 | Возвращается указатель `Items.Item`, связанный с конкретным дескриптором. |
| 55–57 | `count` читает явную длину. |
| 59–63 | `read` копирует встроенный `Target`, поэтому требует `Copyable`. |
| 65–72 | `replace` требует `Movable`; атомарная операция `replace(place, value)` устанавливает новый `Target` и возвращает прежний. |
| 74–80 | `append` требует `Movable`, вычисляет длину и вызывает `Items.allocate` внутри открытой structural group. |
| 82–88 | Пустая и непустая ветви записывают владеющий указатель на новый узел в `head` либо `tail.next`. |
| 90–91 | Поле длины обновляется после успешного связывания. |
| 93–98 | `insert` требует `Movable` и проверяет допустимую позицию до изменения. |
| 100–103 | Вставка в конец вызывает уже проверенный `append`. |
| 105–108 | Для остальных позиций узел выделяется до изъятия опубликованных ссылок. |
| 110–117 | В начале владеющий указатель из `head` переносится в `item.next`; в середине аналогично переносится указатель из `before.next`. |
| 119–120 | После связывания обновляется поле длины. |
| 122–127 | `remove` требует `Movable` и проверяет индекс до изменения. |
| 129–146 | Владеющий `victim` изымается из `head` или `before.next`; суффикс занимает освободившееся место, `tail` исправляется при удалении последнего узла. |
| 148–152 | Длина уменьшается, `Target` переносится наружу, дескриптор освобождает частично извлечённый узел, затем возвращается результат. |
| 153–154 | Закрываются `implementation` и аспект. |

`tail` объявлен как `var tail: read Items.Item?`: `var` разрешает менять само
поле, а `read` относится к сохранённому невладеющему указателю. Запись
`tail!.next` использует отдельное `write`-право реализации на `Items`; она не
получает это право из `read`-указателя.

`chained from self.head by Item.next` создаёт compiler-known конечный order,
точно совпадающий с membership `Items`. Отдельное условие `tail` не заменяется:
оно связывает конкретный tail с достижимым последним узлом.

При закрытом layout компилятор полностью готовит owning `Item(take value, ...)` и
выполняет fallible allocation во внутренний provisional resource. Только затем
он открывает общую structural group, безотказно публикует member, связывает его,
обновляет order/length и закрывает group. Все failure paths allocation происходят
раньше и видят старый закрытый список. Открытое окно compiler сам строит без
call, safepoint, suspension или reentry; representation обязана доказать
refinement безотказного publish, иначе её операция отклоняется. Новый surface API
или annotation для этого не нужен.

`itemAt`, `insert` и `remove` имеют `O(index)`; `append` — `O(1)`.
