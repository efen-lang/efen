# Проверочные структуры для `layout`

Пять структур данных, написанных по [описанию layout](../../layout.md) и прогнанных через FLOW Amber
(`amber_flow_corpus_tests`, обычное чтение, amber main на 2026-11-08). Каждая содержит правильные функции и одну
намеренную ошибку с ожидаемой находкой (`//~`). Файлы — набор для проверки модели, а не нормативный синтаксис.

| Файл | Структура | Результат на 2026-11-08 |
|---|---|---|
| `1_object_pool.efn` | область мест, цепочка свободных, граница | тип `own block.cells.Item` не понят (взят `own Pointer`, как в mm); возврат места `block.cells[k] = take cell` отклонён |
| `2_linked_list.efn` | список над `set area`, узел владеет следующим | результат `own Nodes.Item?` отклонён: `pop` не написать |
| `3_ring_buffer.efn` | область значений, голова и счёт | лишняя `flow.field-lent` при чтении места; выход индекса за область не найден |
| `4_hash_map.efn` | область корзин, множество записей | место области не владеет (по спецификации); запись `own` в поле-имя без находки; закон «запись в своей корзине» выброшен |
| `5_tree.efn` | дерево с именем родителя | результат `own Nodes.Item?` отклонён |

Сделать так, чтобы все пять ложились и находили свою ошибку, — задача модели `layout` и FLOW.

## Отдельные проверки спецификации

- [`layout-model-check.py`](layout-model-check.py) — конечные модели операций структур и отрицательные свидетели;
  запускается обычным Python, компилятор не вызывает.
- [`flow-kernel/verify.py`](flow-kernel/verify.py) — символьный проверяющий ограниченной IR с Z3: переходы владения,
  заимствования, полные конечные тела и явная очистка. Область доказательства и запуск описаны в
  [малом ядре FLOW](../../flow-kernel.md). Это также не тест реализации Amber.
