# Управление памятью

[Документация](../README.md) · [Словарь](../glossary.md) · [Ownership](../types/ownership.md) · [Representations](../representations.md)

> Статус: исторический набросок. Контракты `GarbageCollector`, `Arena`, `ObjectPool` и автоматический выбор
> контракта компилятором к структурам из `layout` не относятся: у них каждая операция с памятью явная
> ([справочник правил](layout/README.md#справочник-правил), [контракт аллокатора](allocator.md)). Действующие правила сведены в
> [таблицу правил доступа к памяти](memory-rules.md).

`Efen` является языком программирования, 
который одновременно предоставляет максимально низкий уровень управления памятью,
вместе с автоматическим управлением памятью.

Низкий уровень управления памятью реализуется 
с помощью удовлетворения контрактов.

Встроенный модуль `memory` предоставляет несколько контрактов для управления памятью:
- `Manager` - контракт менеджера памяти, 
  который отвечает за выделение и освобождение памяти во всем приложении.
- `Allocator` - контракт аллокатора памяти, 
  который отвечает за выделение и освобождение памяти для конкретных типов данных.
- `GarbageCollector` - контракт сборщика мусора, 
  который отвечает за автоматическое освобождение неиспользуемой памяти.
- `Arena` - контракт арены памяти, 
  который отвечает за выделение и освобождение памяти в рамках определенной области для объектов разного типа.
- `ObjectPool` - контракт пула памяти, 
  который отвечает за выделение и освобождение памяти для объектов одного типа.

В общем случае все типы данных в `Efen` не имеют явного способа управления памятью, 
и компилятор выбирает подходящий контракт для управления памятью автоматически. Однако, это легко изменить
с помощью `provide`-выражений.
