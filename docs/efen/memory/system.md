# Системные вызовы: `@asm`, `@platform` и `System`

[Управление памятью](index.md) · [Сырая память](pointer.md) · [Контракты](../contracts.md) ·
[Варианты](../types/variant.md)

Программа на Efen обходится без библиотеки C, системные вызовы —
код на Efen поверх функций-вставок на ассемблере. Amber реализует `@asm`, `@platform`, константы контракта, варианты
с условиями и `System` для Linux x86-64 (выполняется) и aarch64 (проверяется, не выполняется); внешние функции
`@abi(c)` ещё не реализованы.

## Функция-вставка `@asm`

Тело функции — инструкции процессора; декоратор называет архитектуру, регистр
результата и всё, что вставка портит; декоратор перед параметром называет его регистр:

```efen
@asm(x86_64, result: rax, overwrites: [rcx, r11, memory])
fn unmapX86(@in(rdi) memory: own Pointer, @in(rsi) bytes: Int) -> Int {
    xor eax, eax
    test rsi, rsi
    jz 1f
    mov eax, 11
    syscall
    1:
}
```

- Владение читается по сигнатуре, как у любой функции: `memory: own Pointer` вставка забирает.
- Вставка, которая портит `memory`, берёт параметры `Pointer` только как `own`: иначе она писала бы в память, которой
  не владеет.
- Метки `1:` и переходы `1f`/`1b` — местные, как в ассемблере GNU.
- Диалект инструкций — Intel для x86-64.
- Каждая вставка собирается для своей архитектуры в каждой сборке, даже если цель сборки другая: ошибка в инструкциях
  видна сразу.

Вставка бывает методом [класса над внешним значением](../classes.md#класс-над-внешним-значением). `self` получает
регистр так же, как параметр:

```efen
public class File {
    conforms Destructible

    representation Raw<Descriptor>              // объект — дескриптор
    @asm(x86_64, result: rax, overwrites: [rcx, r11, memory])
    @destructor own fn closeX86(@in(rdi) self) -> Int32 { … }
    @asm(x86_64, result: rax, overwrites: [rcx, r11, memory])
    read fn readX86(@in(rdi) self, @in(rsi) buffer: edit [UInt8], @in(rdx) count: Int) -> Int { … }
}
```

## Условия результата вставки

Компилятор не читает инструкции вставки. То, что она отдаёт, он берёт из условий её результата и дальше доказывает
всё остальное от них:

```efen
@asm(x86_64, result: rax, overwrites: [rcx, rdi, rdx, r8, r9, r10, r11, memory])
fn mapX86(@in(rsi) bytes: Int) -> MapResult
    ensures match result {
        .mapped.{ let memory }: memory.size == bytes && memory.alignment == 4096 && memory is Pointer.Zeroed
        .failed: true
    }
{
    mov eax, 9
    xor edi, edi
    mov edx, 3
    mov r10d, 34
    mov r8, -1
    xor r9d, r9d
    syscall
}
```

Здесь вставка сама задаёт все аргументы `mmap`, кроме размера, поэтому её условие говорит ровно то, что она
отображает: `bytes` нулевых байт, выровненных по странице. `Pointer.trusted` и другие способы объявить память
доверенной вне условий результата в языке нет.

## Вариант в одно слово

Поле случая варианта может нести условие, как любое поле, — `{ }` в конце его объявления:

```efen
variant MapResult {
    mapped { let memory: own Pointer }
    failed { let code: Int { value >= -4095 && value <= -1 } }
}
```

Условия случаев не пересекаются, поэтому вариант с одним полем на случай укладывается в одно машинное слово: так
возвращает результат системный вызов Linux. Разбор — обычный `match` с привязкой поля:

```efen
match mapX86(bytes: bytes) {
    .failed: return null
    .mapped.{ let memory }: return take memory
}
```

`MapResult` получает раскладку в одно слово выводом. Явная форма той же раскладки — `representation Packed<I>`
([`Packed`](../types/variant.md#представление-packed)): диапазоны случаев компилятор проверяет при объявлении.

## Реализация по платформе `@platform`

Форма заменяет условную компиляцию. Платформа видна на реализации контракта:

```efen
@platform(os: "linux", arch: "x86_64")
implementation System {
    const PAGE = 4096
    // map и unmap через mapX86 и unmapX86
}

@platform(os: "linux", arch: "aarch64")
implementation System {
    const PAGE = 65536
    // map и unmap через mapArm и unmapArm
}
```

Компилятор проверяет каждую реализацию, а вызывает реализацию цели сборки. Windows и Apple входят в систему через её
библиотеку (номера системных вызовов там не стабильны), Linux и Android — вставками.

## Константа контракта

Контракт объявляет константу без значения, каждая реализация даёт своё:

```efen
contract System {
    const PAGE: Int
    fn map(bytes: Int, aligned: Int) -> own Pointer.Zeroed?
        requires bytes % PAGE == 0
        ensures result == null || (result.size == bytes && result.alignment == aligned)

    fn unmap(memory: own Pointer, bytes: Int)
        requires memory.size == bytes
}
```

Условие `requires bytes % PAGE == 0` ([условия функций](../conditions.md)) вызывающий доказывает на каждом вызове,
для всех реализаций сразу.

## Внешние функции `@abi(c)`

Amber её ещё не реализует.

```efen
@abi(c) @library("kernel32")
fn VirtualAlloc(address: Int, size: Int, kind: UInt32, protect: UInt32) -> own Pointer?
```

Тела нет; владение читается по сигнатуре. Функция `@abi(c)` с телом — обратное направление: её вызывает C по
имени функции. Остальные функции программы снаружи не видны. Такие функции объявляются в модуле платформы или в модуле библиотеки C,
который создан по её заголовку ([библиотеки на C](../foreign.md)). Модуль библиотеки C не пишет `@library`: библиотеку
называют настройки сборки пакета.

Тело функции `@abi(c)` проверяется как код однопоточного контекста: компилятор принимает, что C вызывает её в одном
потоке. Вызов из другого потока происходит на стороне C, и компилятор его не видит, поэтому объявление такой
функции служит точкой доверия. Функция, которую C вызывает из нескольких потоков, объявляет это словом
`shared` перед атрибутом, `shared @abi(c) fn`, и её тело проверяется как код многопоточного контекста
([структура и поток](layout-reference.md#структура-и-поток), правило 4).

## Контракт `System`

`System.map(bytes:aligned:)` отдаёт целые страницы `PAGE`, выровненные как просили, нулевые; при отказе — `null`.
Выравнивание больше страницы получается обрезкой, как в limelight-lang/model `map_aligned`: отображается
`bytes + aligned`, голова и хвост отдаются обратно выдачами ([`lend`](pointer.md#выдача-частей-памяти-lend)).
`System.unmap(memory:bytes:)` возвращает целые страницы; если ядро отказывает, программа останавливается.

В песочнице `System` подменяется (`sandbox { replace }`), а не запрещается.

## Память ОС как множество

Выделения и освобождения памяти как особых операций нет: память переходит из одного множества в другое, и только
направление перехода делает его выделением или освобождением.

- **У каждого `layout` свои множества.** Менеджер памяти описан своим `layout`, пользовательская структура своим. Функцию другого `layout` FLOW видит как работу с другими множествами.
- **Память ОС — тоже множество.** Страницы принадлежат множеству ОС; взять страницы — выдача из него, вернуть —
  возврат в него. Без доказательства принимается только то, что ОС выдаёт страницы нужного размера и выравнивания: условие
  результата у вставки `@asm` ([системные вызовы](system.md)).
- **`own` переносит память между множествами.** Память, которая вышла из множества `A` и вошла в множество `B`,
  для `B` выделена, а для `A` освобождена. `take` и `lend` при этом действуют на поле или слот, а не на множество.
  Блок, взятый менеджером у ОС, для ОС ушёл, для менеджера пришёл; слот, отданный пользователю, для
  блока выдан, для пользователя получен.
- **Правила одни на всех уровнях.** ОС → регион → блок → слот: каждый следующий уровень занимает память
  предыдущего (область получена приведением его памяти или вложена полем `area` в его элемент), родителя
  нельзя вернуть, пока внутри что-то выдано, и FLOW видит, что каждая страница, взятая у ОС, вернулась или осталась у
  владельца.

```efen
fn newRegion -> own Region? {
    guard let memory = System.map(bytes: REGION, aligned: BLOCK) else { return null }   // из множества ОС
    return memory as Region                                                              // в множество регионов
}

fn dropRegion(region: own Region) {
    System.unmap(memory: take region as Pointer, bytes: REGION)                          // из регионов — в ОС
}
```

Стирание вида `block as Pointer` даёт `own Pointer` той же памяти, а не новой: вида больше нет, память существует и передаётся дальше.
Множество ОС в `layout` не объявляется: его описывают сигнатуры контракта `System`
([системные вызовы](system.md#контракт-system)). `map` отдаёт `own Pointer.Zeroed?` с размером и выравниванием
в условии результата; `unmap` принимает `own Pointer` и требует `memory.size == bytes`. FLOW отслеживает `own Pointer`
линейно: каждая страница, взятая у ОС, на каждом пути возвращается в `unmap` или остаётся у владельца, и размер
возврата он берёт из условия результата `map`, а не из памяти. Условие результата `map` — единственная точка
доверия на этой границе.

## Кому доступно доверие

`@asm`, `@platform`, `@abi(c)` с телом и без, вызовы C, `thread var x: own T`, приведение адреса к элементу множества
или к выданному слоту и [`assume`](../conditions.md#assume-факт-без-доказательства) пишет любой пакет, не только
стандартная библиотека: mm, runtime и std — обычные пакеты, и у пакета нет пометки, которая делала бы его доверенным.
Доверие держится на условиях результата вставки, а не на том, кто её написал. `@platform` на объявлении в модуле
библиотеки C записывает константы и структуры, которые у целей разные ([сверка с
заголовком](../foreign.md#сверка-с-заголовком)). Программе, которой вставки не нужны, память даёт `System`.

Пакет, где есть хоть одно такое место, — **рискованный**. Пометку выводит компилятор, пакет её не пишет: забыть или
скрыть её нельзя. Сборка печатает заметку группы `Trust` у первого места пакета и перечисляет места:

```text
notice: this package is a risk: the build believes 3 places of it rather than proves them [#Trust]
 --> error_number.efen:24:1
  = note: error_number.efen:24: a C library's function
  = note: error_number.efen:27: a `@platform` implementation
  = note: error_number.efen:36: a `@platform` implementation
  = note: `efen proofs` lists them
```

Те же точки доверия дают [классы над внешним значением](../classes.md#класс-над-внешним-значением) и
[модели](../models.md#модель-model):

| Объявление | Модель FLOW берёт как | Доверие |
|---|---|---|
| без тела (`@abi(c)`, `@asm`, `@intrinsic`, бинарный пакет) | сводку | да: пакет рискованный, `efen proofs` перечисляет точку |
| метод контракта или интерфейса | сводку каждого вызова через него | нет, пока реализация не доверенная |
| функция с телом | границу, проверенную по телу | нет; исключение: функция `@abi(c)` с телом, её объявление служит точкой доверия ([выше](#внешние-функции-abic)) |
| `Self(raw:)` и каждый вызов функции, где он есть; `-> Self?` от внешней функции; результат `Packed`; выходные слоты `self?` и с посылкой | — | да |

Вызов функции с `Self(raw:)` — точка доверия пакета вызывающего, а не модуля класса: принятое значение пришло
снаружи, и доказать его не может никто. Проверочная сборка проверяет каждую такую точку по таблице хендлеров
([доверие и проверочная сборка](../foreign.md#доверие-и-проверочная-сборка)).

`efen proofs` выводит каждое место строкой вида `trust` (`error_number.efen:24:1 trust a C library's function`), в
том числе с `--unproved`. Позже конфигурация сборки будет называть пакеты, которым доверяют, и рискованный пакет вне
этого списка станет ошибкой; форма списка не решена.
