## 4. Невладеющие указатели

Невладеющий указатель называет множество и имеет источник. Хранимый указатель указывает только внутрь своей
публичной структуры. Раздел опирается на структуру элемента и публичную структуру (3.3) и на способы владения (3.4).

<a id="ссылки"></a>

### 4.1 Запись и тип

**Правило.** Невладеющим указателем называется поле, переменная, параметр или результат с типом элемента множества
(`Items.Item`) без `own` и `anchor`. Он ничем не владеет и по умолчанию только читает.

| Запись | Что это |
|---|---|
| `var prev: Items.Item?` | указатель на элемент множества `Items` |
| `var key: Keys.Item` | указатель на слот области `Keys` того же `layout` |
| `var next: Int` с концом `NONE` | слот своей области по индексу (цепочка свободных слотов) |

Дополнительные правила:

1. Тип указателя называет множество, а не экземпляр коллекции. Источник в типе поля `layout` не пишется: его
   выводит FLOW.
2. Указатель из одного множества в другое особо объявлять не нужно: FLOW видит каждую его запись.
3. Указатель может существовать дольше цели. После уничтожения цели он недействителен, и ошибку вызывает только
   его использование.
4. Параметр, которому нужен узел определённого графа, пишет источник обычным способом:
   `from: read<g> Nodes.Item`.
5. Чтение слота `anchor` или `own` с элементом, поля или локальной переменной, без `tie` и `take` даёт
   невладеющий указатель `Items.Item`. Невладеющий указатель связывается с новым именем копированием адреса:
   `let q = p.next` и `let name = block` создают новый указатель, а не второе имя
   ([связывание существующего значения](../../types/ownership.md#связывание-существующего-значения)).
   Чтением не считается имя локального владельца или параметра в позиции, которая расходует значение: `return`,
   `throw` и `yield` этого имени, операнд приведения `as own`, `as Pointer` и приведения к виду. В такой позиции
   владение переходит без слова: якорь как при `tie`, значение `own` как при `take`. После неё имя недействительно.

**Пример.** В [примере A](declaration.md#2-объявление) `Item.prev` и `List.tail` объявлены невладеющими указателями на
элементы `Items`.

**Запрещено.**

- Указатель на обычное поле (`next`, `used`) не существует. Тип указателя есть только у элемента множества
  (`Nodes.Item`) и у значения в слоте области (`T.Pointer`).
- Обратные указатели (`prev`, `parent`) разрешены только внутри `layout`.
- Запись вида `g.Nodes.Node`, которая называет экземпляр, не существует.

**Почему.** Один тип на множество позволяет переносить элемент между коллекциями без смены типа. К какой
коллекции элемент относится сейчас, говорит не тип, а владение.

Куда дальше: откуда указатель прочитан, определяет раздел 4.2.

### 4.2 Источник ссылки

**Правило.** Источником ссылки или указателя на элемент служит структура элемента, из которой он прочитан. Источник
называет структуру целиком, а не путь внутри неё.

Дополнительные правила:

1. Указатель, прочитанный через любое поле элемента, имеет тот же источник, что и указатель на этот элемент.
2. Источник указателя в результате функции с телом выводится. У объявления без тела он пишется (раздел 8.5).
3. Указатель-параметр без источника в типе (`n: edit Items.Item`) может принадлежать любой структуре своего
   множества. Поэтому изменение структуры через другой параметр или через `one`, тип которого может владеть
   элементами этого множества, делает недействительными этот указатель и ссылки, прочитанные через него
   (раздел 7.1). Тип может владеть элементами множества, когда по объявлениям `layout` от него к элементу этого
   множества ведут владеющие поля и вложенные области. Параметр с источником (`n: read<list> Items.Item`) под
   правило не подпадает: его структура названа.

**Пример.**

```efen
let p = a.first()                   // Items.Item, источник: список a
let q = p.next                      // источник тот же: a

fn dropFirst(list: mut List, n: edit Items.Item) {
    let r = &n.value
    list.removeFirst()              // изменение структуры list: List может владеть элементами Items
    print(r)                        // ошибка: n мог принадлежать list, ссылка r недействительна
}
```

**Запрещено.** Указатель элемента не копируется из одной структуры в другую. Элемент меняет структуру только
владением (раздел 3.3).

**Почему.** По источнику решается, какие операции делают указатель недействительным: только те, что меняют
структуру его источника (раздел 7.1). Два списка общей памяти не объявляли, поэтому операция над `b` не затрагивает
указатель с источником `a`.

### 4.3 Правило чистоты

**Правило.** Каждый хранимый невладеющий указатель указывает на элемент своей публичной структуры: той, в которую
входит поле с этим указателем.

Дополнительные правила:

1. Правило относится к указателям в элементах и в самом корне (`List.tail`).
2. Внутренняя структура может хранить указатель за свои пределы, но только внутрь своей публичной структуры
   (раздел 4.4). Указатель из одной публичной структуры в другую не хранится нигде.
3. Внутри тела функции правило может быть нарушено. Оно доказывается на каждом выходе публичной функции
   структуры, обычном и через исключение, и перед вызовом или приостановкой, которым нужны выполненные инварианты.
4. Элемент под локальным якорем составляет отдельную структуру: её корень находится в этой переменной. Пока
   элементом владеет локальная переменная функции кода `layout`, действует правило 3: правило чистоты для него
   может быть нарушено.
5. Переход элемента между структурами доказывает правило двумя частями. Первая часть: в прежней структуре не
   остаётся указателя на уходящее поддерево. Она доказана к выходу публичной функции и к точке `as own`
   (раздел 6.5). Вторая часть: в поддереве не остаётся указателя за его пределы. Она доказана там, где поддерево
   получает владельца вне тела функции: при записи в поле другой структуры, в результате публичной функции, при
   передаче внешнему коду и при переходе в другой поток. Результат вспомогательной функции может быть нечистым,
   и это сообщает её сводка. Поддерево, которое функция освобождает, второй части не требует: его указатели
   уничтожаются вместе с ним.
6. Слоты с указателями FLOW находит по инварианту или обходом.
7. Под `one X` хранимый указатель указывает внутрь структуры этого `one` (раздел 3.3).
8. Правило относится к указателям без источника в типе. Значение с источником в типе (`read<g> Vertices.Item`,
   поле структуры с `Src: Origin`) хранит заимствование. Оно указывает в структуру своего источника и проверяется
   правилами заимствований (раздел 4.5).

**Пример.** В примере A `prev` каждого узла указывает на узел того же списка. В
[примере C](declaration.md#2-объявление) `Edge.to` и `neighbors` указывают на вершины того же графа: вершины двух
графов не смешиваются.

**Запрещено.**

- Указатель за пределы публичной структуры вызывает ошибку. Компилятор показывает её у записи, которая создала
  такой указатель.
- Поле, которое не находит ни один инвариант и ни один обход, делает переход элемента ошибкой.

**Почему.** Благодаря правилу операция над одной публичной структурой не может оставить висячий указатель в другой.
Поэтому доказательство остаётся в пределах одной структуры и её кода, а публичная структура переходит к другому
владельцу целиком.

Куда дальше: какая структура чиста и как отделяется нечистая, определяет раздел 4.4.

### 4.4 Чистая структура

**Правило.** Структура чиста, если каждый её хранимый невладеющий указатель без источника в типе указывает внутрь
неё. Публичная структура чиста в каждой точке, где доказывается правило чистоты (раздел 4.3, правило 3). Внутренняя
структура может быть нечистой: её указатели выходят за её пределы, но остаются внутри её публичной структуры.
Значение с источником в типе чистоту не нарушает: оно хранит объявленное заимствование и подчиняется правилам
заимствований (раздел 4.5).

Дополнительные правила:

1. Чистота внутренней структуры считается относительно её публичной структуры. Вершина из примера C нечиста, а
   все вершины графа вместе составляют чистый `Graph`.
2. Внешний код нечистую внутреннюю структуру от её публичной структуры не отделяет: он не получает её ни
   значением, ни владением и не передаёт в другой поток.
3. Отделяет её только код `layout`, любой своей функцией: строка `public own` для этого не нужна (раздел 3.5,
   правило 7). Пока отделённой частью владеет локальная переменная, часть может оставаться нечистой. Функция,
   которая записывает часть в другую структуру или возвращает её из публичной функции, переписывает указатели и
   доказывает, что часть чиста: в прежней структуре не осталось указателя на неё, а в ней не осталось указателя
   за её пределы (раздел 4.3, правило 5).
4. Внешнему коду отделённая часть уходит только чистой, и у него она становится отдельной публичной структурой.
   Элемент и выданный слот уходят через функцию, которой это разрешает строка `public own` или `public lend`
   (раздел 8.7). Значение структуры из `layout` и значение типа `T` уходят по своему типу, результатом или
   параметром `out` любой публичной функции, и строки не требуют (раздел 3.5): `removeLast -> own T?` у
   `Vector<Vector<Int>>` отдаёт внутренний вектор.
5. Аргумент типа считается так же, как поле (раздел 2.4, правило 4). Значение `Vector<Vertices.Item>` в поле
   вершины хранит указатели внутрь графа и входит в граф внутренней структурой.
6. Указатели на элементы публичной структуры вне её хранятся заимствованием. Путь по графу, найденный
   обходом в ширину, записывается вектором с источником в типе элемента: `Vector<read<g> Vertices.Item>`. Такой
   вектор заимствует граф `g` с правом `read` (раздел 4.5). Вектор без источника, `Vector<Vertices.Item>`,
   отдельным значением у любого кода был бы публичной структурой с указателями за её пределы, и запись такого
   указателя вызывает ошибку.

**Пример.** `List` из примера A и `Graph` из примера C чисты. Узел `Item` из примера A нечист: `prev` указывает на
соседний узел того же списка. `Vertex` из примера C нечист: `neighbors` и `Edge.to` указывают на другие вершины
графа. `removeVertex` (раздел 6.5) отделяет вершину от графа: переписывает указатели на неё во всём графе и после
этого освобождает.

**Запрещено.**

- Функция, которая отдаёт внешнему коду часть публичной структуры и не доказала, что часть чиста, вызывает
  ошибку.
- В поле `shared` помещается только публичная структура, целиком
  ([пометка `shared`](../../shared.md#пометка-shared)).

**Почему.** Публичная структура без заимствований не зависит от памяти вне себя, поэтому её можно целиком передать
другому владельцу, в другой поток или закрыть одной блокировкой (раздел 9). Нечистая внутренняя структура зависит от
соседних частей своей публичной структуры. Отделённая без переписывания указателей, она хранила бы адреса памяти,
которую меняет и освобождает другой код. Все поля с такими указателями знает только код `layout`, поэтому отделяет
её он.

### 4.5 Указатель вне layout

**Правило.** Вне `layout` указатель на элемент хранит только значение, которое заимствует: структура с параметром
источника `Src: Origin` или коллекция, в типе элемента которой записан источник (`Vector<read<g> Vertices.Item>`).

**Пример.**

```efen
struct ListCursor<Src: Origin> {
    var list: read<Src> List
    var current: read<Src> Items.Item? = null
}

let cursor = ListCursor<Src: list>(list: list)
```

Поле `current` хранит заимствование: курсор заимствует `list` с правом `read`, и указатель в поле имеет
источником `list`. Действует общее правило заимствований
([что делает ссылку недействительной](../memory-rules.md#что-делает-ссылку-недействительной)):

1. После вызова `edit` у списка (вставка, перестановка узлов) курсор действителен.
2. Перед вызовом, который освобождает узлы или забирает их из списка, курсор, не используемый дальше,
   уничтожается. Курсор, используемый дальше, вызывает ошибку.
3. Курсор, который сам освобождает или забирает узлы, пишется конкретным типом с заимствованием `mut`:
   `var list: mut<Src> List`. Пока он существует, структуру списка меняют только его функции
   ([два доступа сразу](../memory-rules.md#два-доступа-сразу)).
4. Курсор по вершинам графа из примера C пишется так же. Структура
   `struct VertexCursor<Src: Origin> { var current: read<Src> Vertices.Item? }` создаётся как
   `VertexCursor<Src: graph>`, и источником её указателя служит граф. Вызов `removeVertex(graph, v)` меняет для
   такого курсора структуру источника.

Указатели, которые внешний код собрал при обходе, тоже записываются заимствованием. Путь по графу из
примера C:

```efen
fn findPath(g: read Graph, from: read<g> Vertices.Item, to: read<g> Vertices.Item)
    -> Vector<read<g> Vertices.Item> {
    // тело не важно для примера: обход в ширину; источник указателей в результате: g
}

var path = findPath(graph, from: a, to: b)                // a и b: вершины graph; вектор заимствует graph
print(path[0].label)
addVertex(graph, label: 7)                                // edit: path действителен
print(path[0].label)
removeVertex(graph, a)                                    // меняет структуру источника: указатели в слотах недействительны
print(path.count)                                         // можно: число слотов хранит сам вектор
print(path[0].label)                                      // ошибка: слот хранит недействительный указатель
```

Вектор `path` заимствует `graph`, как курсор. Вызов `edit` у графа его не затрагивает. Вызов, который освобождает
вершины, делает недействительным каждый указатель в слотах вектора: их источник `graph`. Область вектора принадлежит
самому вектору, и этот вызов её не меняет. Поэтому после вызова ошибку вызывает чтение слота: индекс, обход,
сравнение. Функции, сводка которых значений слотов не читает (`count`), остаются допустимыми. Перед вызовом компилятор
вектор не уничтожает: компилятор освобождает его в конце области видимости (раздел 7.4). Значения в слотах вектора
проверяются теми же правилами, что поле с источником (раздел 2.4, правило 4). Так же ведёт себя коллекция структур,
которые заимствуют (`Vector<ListCursor<Src: list>>`): до конца области видимости она существует, и после вызова ошибку
вызывает чтение слота.

Право в типе элемента коллекции пишется, как в поле с источником. `Vector<edit<g> Vertices.Item>` заимствует `g` с
правом `edit`. `Vector<mut<g> Vertices.Item>` хранит заимствование `mut` и подчиняется его правилу: значение с
таким заимствованием передаётся только в параметр, тип которого это заимствование пишет
([до чего доходит вызов `mut`](../memory-rules.md#до-чего-доходит-вызов-mut)).

Структура `Cursor` с полем `var current: Items.Item?` без источника, объявленная в `layout`, хранится только
внутри публичной структуры, на элементы которой указывает: в поле `List` или в поле структуры, которая хранит
`List` значением. Отдельным значением такой курсор был бы публичной структурой с указателем за её пределы
(раздел 4.3). Отдельный курсор пишется с параметром источника, как `ListCursor` выше.

Указатель на элемент из адреса без множества получается только через точку доверия:

```efen
let block = (address(m) & ~(BLOCK - 1)) as read<pool> Blocks.Item    // элемент структуры pool, в котором находится адрес
```

Тип в приведении называет источник обычной записью: `read<pool>` значит, что элемент принадлежит структуре `pool`.
Без источника у указателя не было бы структуры, а право на элемент функция берёт из права на его структуру
(раздел 8.2). Маску в такой строке компилятор сверяет с `@align(BLOCK)` и вложенностью области и ничего не
подставляет сам. Если сверку доказать не удалось, перед строкой пишется `assume`. Два факта компилятор принимает
без доказательства: адрес указывает в элемент множества, и этот элемент принадлежит названной структуре. Поэтому
строка остаётся точкой доверия и при доказанной сверке, и её перечисляет `efen proofs`.

Тем же видом точки доверия служит приведение, которым код `layout` восстанавливает тип слота, стёртого до
`Pointer`: `(take found) as parent.slots.Item`. Тип называет родителя. Что память составляет слот, выданный из
этого родителя, компилятор принимает без доказательства
([стирание и восстановление](../pointer.md#стирание-и-восстановление)).

**Запрещено.**

- Поле типа `Items.Item` без источника в структуре или классе вне `layout` вызывает ошибку, с любым правом. Запись
  указателя без источника в коллекцию, которая хранится отдельным значением (`Vector<Items.Item>` в поле класса или в
  переменной), тоже вызывает ошибку, в коде `layout` и во внешнем коде.
- Сохраняемое замыкание не захватывает указатель `Items.Item`, если тип замыкания не называет заимствование
  структуры, из которой указатель прочитан: `read<list> () -> Void`. Замыкание с таким типом заимствует `list`, как
  курсор.
- Приведение адреса без источника в типе вызывает ошибку. Приведение, сверка которого не доказана, без `assume`
  тоже вызывает ошибку.
- Хранимые указатели на узлы без заимствования всей коллекции (таблица LRU указывает на узлы его списка, индекс
  указывает на строки таблицы) существуют только внутри одной публичной структуры. Обе части объявляет один
  `layout` или `open layout` вместе со своим расширением (раздел 10), и одна структура хранит обе значениями в
  своих полях: `struct Lru { var list: List; var table: own Area<Bucket>? }`. Класс с полями `list: List` и
  `table: Map<Key, Items.Item>` хранит две публичные структуры, и запись указателя в таблицу вызывает ошибку.
  Обычная структура вне `layout` таких указателей не хранит, и два независимых `layout` взаимных указателей не
  описывают.

**Почему.** Вне `layout` у хранимого указателя нет инварианта, по которому его можно найти перед уничтожением
цели. Заимствование с источником даёт компилятору ту же связь другим способом: по типу.

Куда дальше: как объявляется связь между указателями и владельцами, описывает раздел 5.
