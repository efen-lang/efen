## 2. Объявление

`layout` объявляет множества и области, структуры их элементов и то, какой код пишет поля. Остальные разделы
опираются только на эти объявления.

Три примера ниже используются во всех разделах. Правила называют множества именами из примеров: `Items` из
примера A, `Block.data` из примера B, `Nodes` из примера раздела 3.5. Правило с таким именем относится к любому
множеству или области с тем же объявлением.

```efen
// Пример A: двусвязный список
layout {
    set Items: Item

    struct Item {
        var value: Int
        var next: anchor Items.Item? = null
        var prev: Items.Item? = null
        invariants { next == null || next!.prev == self }
    }

    public struct List {
        var head: anchor Items.Item? = null
        var tail: Items.Item? = null
        var length: Int = 0 { value >= 0 }
    }
}

// Пример B: пул, который выдаёт память внешнему коду
layout {
    set area Blocks: Block

    public lend Block.data

    struct Block {
        var next: anchor Blocks.Item? = null
        var prev: Blocks.Item? = null
        var used: Int = 0                        // число выданных слотов
        inline data: Area<Byte>
        invariants {
            next == null || next!.prev == self
            used == data.taken.count
        }
    }

    public struct Pool {
        var busy: anchor Blocks.Item? = null     // цепочка участков с выданным слотом: used > 0
        var free: anchor Blocks.Item? = null     // цепочка участков без выданных слотов: used == 0
    }
}

// Пример C: граф, вершинами которого владеет структура Graph
layout {
    set Vertices: Vertex
    set Edges: Edge

    struct Vertex {
        var label: Int
        var neighbors: Vector<Vertices.Item>         // соседи: вершины того же графа
        var firstEdge: anchor Edges.Item? = null
        var nextAll: anchor Vertices.Item? = null    // цепочка всех вершин графа: владеет следующей
    }

    struct Edge {
        var to: Vertices.Item                        // вершина того же графа
        var next: anchor Edges.Item? = null
    }

    public struct Graph {                            // внешний код хранит граф значением
        var first: anchor Vertices.Item? = null      // владеет цепочкой вершин
        invariants {                                 // цепочку описывает раздел 5.2
            let all = Vertices.chain(from: first, by: Vertex.nextAll, until: null)
            forall v in Vertices: all.contains(v)
        }
    }
}
```

<a id="множества-и-области"></a>

### 2.1 Множества и области

**Правило.** Каждый элемент памяти `layout` принадлежит множеству, объявленному одной из трёх строк, или области:
значению обобщённого типа `Area<T>`.

| Строка | Что объявляет |
|---|---|
| `set X: T` | множество элементов структуры `T` без обещания непрерывности: узлы списков, деревьев, графов |
| `set area X: T` | множество независимых областей (участки менеджера памяти); каждый байт принадлежит элементу |
| `one X` | один экземпляр структуры `X` на программу, как `static`; на его единственность FLOW опирается |

Дополнительные правила:

1. Множество одно на программу. `set Items: Item` называет все узлы этой структуры во всей программе, а списков
   `List` сколько угодно. Поэтому узел, вынутый из одного списка, вставляется в другой обычной операцией.
2. Своей памяти у множества нет, оно не создаётся и не уничтожается. Множество даёт имя типу указателя:
   `Items.Item` значит «элемент из `Items`». Время жизни есть у памяти элементов. Она взята у стратегии
   `Allocator<Items.Item>` множества, у ОС или из области родителя (раздел 6.2) и возвращается туда же. Возврат при
   выходе процесса не считается.
3. Число слотов области задаёт её владелец условием у поля (`value.count == capacity`) или строка `invariants`
   вида (`slots.count == PAYLOAD / SIZES[sizeClass]`). Размер области в байтах называет свойство `x.size`; то же
   число даёт `sizeOf(x)`. У области, слоты которой имеют один размер, он равен `x.count * sizeOf(x.Item)`.
   Владелец области с разным шагом задаёт условием её размер: `value.size == bytes` (раздел 2.6).
4. Слот области хранит значение: `table[i].size = 16` пишет поле слота `i`. Каждое обращение к слоту FLOW
   доказывает по коду владельца области; обращение без доказательства вызывает ошибку компиляции.
5. Строки `set` и `one` принято писать в начале. Порядок объявлений на разрешение имён не влияет: у одного
   `layout` одна общая область видимости.
6. Строка множества может нести условие в фигурных скобках, как поле: `set area Boxes: Box { value.kind == STACKED ==> value is Stack }`. Условие верно
   для каждого элемента множества, имя `value` в нём называет элемент (раздел 5.3).
7. Слоты одной области имеют один размер, пока структура слота не задаёт свой размер сама. Область, структура слота
   которой задаёт размер собственным инвариантом, называется областью с разным шагом. Её правила стоят в разделе
   2.6.
8. `Area<T>` — память, в которой подряд лежит целое число значений типа `T`. Тип элемента служит и шагом области:
   отдельного параметра шага нет. `Area<T>` — обычный тип, он пишется везде, где пишется тип, и принимает любой
   `T`, в том числе структуру, которая задаёт свой размер сама (раздел 2.6). Значение типа `Area<T>` — кусок
   памяти, длины оно не хранит.
9. `Area<T>` — тип динамического размера: `sizeOf(Area<Int>)` не вычисляется, и структура с полем `inline` типа
   `Area` тоже имеет динамический размер. `x.size` и `sizeOf(x)` у значения `x` вычисляются из числа слотов,
   которое называет владелец (правило 3).
10. Область живёт полем структуры, которая хранит её длину. Область верхнего уровня — поле `own Area<T>?` с
    условием длины: `var items: own Area<T>? = null { value == null || value.count == capacity }`. Локальная
    переменная типа `Area` допустима, когда компилятор доказывает, что её значение кончается в такой структуре.
11. Выравнивание области задаёт параметр типа: `Area<Slot, align: LINE>` начинается со смещения, кратного `LINE`.
12. Тип `T.Pointer` называет указатель на значение типа `T`. Это особое свойство каждого типа. Свободно он живёт
    только в коде `layout`; вне его только как заимствование с источником, как `Nodes.Item` (раздел 4.5). На слот
    области верхнего уровня указывает `T.Pointer`; слот области-поля сохраняет имя `Block.data.Item` (раздел 2.2).

Формы типов, которым множество и область дают имена, перечисляет таблица в статье
[«Формы типов»](types.md#формы-типов).

**Пример.** В примере B `Blocks` объявлено как `set area`: участки не обязаны идти подряд, а каждый состоит из
непрерывных байтов. Область с известным числом слотов:

```efen
const CLASSES: Int = 32

layout {
    struct Class {
        var size: Int = 0                     // размер слота этого класса в байтах
    }

    struct Sizes {
        var classes: own Area<Class>? { value == null || value.count == CLASSES }   // 32 класса размеров подряд
    }
}
```

**Запрещено.** Элементы `set area` не индексируются. Множество областей раздаётся целиком циклом
[`for element in take region`](../pointer.md#раздача-набора-for-element-in-take-region): цикл передаёт телу каждый
элемент по одному (раздел 6.6). Встроенного перебора всех элементов множества нет.

**Почему.** Тип указателя называет множество, поэтому по объявлениям видно, какие поля могут хранить указатель на
элемент. На этом держится поиск всех указателей перед уничтожением элемента.

### 2.2 Вложенность

**Правило.** Поле с пометкой `inline` хранит память своего значения в самой структуре. Область, объявленная полем
`inline` типа `Area<T>`, занимает байты элемента этой структуры и существует, пока элемент сохраняет этот вид.

Пометка `inline` применяется к полю любого типа: `inline h: Header` значит, что память `Header` лежит в самой
структуре. Поле без пометки по сути указывает на своё значение. Голое имя структуры полем (`Header`) остаётся
встраиванием без имени поля (раздел 2.3).

**Пример.**

```efen
// Header, BLOCK, LINE, PAYLOAD, SIZES, NONE и SLOT_KEY объявляет менеджер памяти (статья «Сырая память»)
@align(BLOCK)
struct SlotBlock {
    Header                                  // общее первое поле видов (раздел 2.3)
    inline slots: Area<Slot, align: LINE>   // слоты занимают байты элемента SlotBlock
    invariants {
        sizeOf(slots.Item) == SIZES[sizeClass]
        slots.count == PAYLOAD / SIZES[sizeClass]
    }
}

struct Slot {
    var next: Int = NONE
    var key: Int = SLOT_KEY
    inline rest: Area<Byte>           // хвост слота занимает байты слота
}
```

Память элемента `SlotBlock` выдана из множества `Blocks`. Область `slots` занимает его байты, область `rest`
занимает байты слота.

Размер слота `Slot` задан снаружи, параметром `size` в приведении (раздел 6.7), и у всех слотов области он один.
Слот, инвариант которого сам связывает число слотов своей вложенной области со своим полем, получает собственный
размер. Область таких слотов подчиняется разделу 2.6.

**Запрещено.** Вложенность объявляется только полем `inline` типа `Area`. Два `layout` друг в друга не
вкладываются.

**Почему.** Из вложенности следуют два правила времени жизни. Слот не существует дольше элемента, в котором
расположен (раздел 7.1). Родителя нельзя вернуть, пока его слот выдан и хранится вне его памяти (раздел 6.6).

### 2.3 Структуры из layout и виды элемента

**Правило.** Структура, объявленная в `layout`, описывает байты элемента или служит корнем коллекции. Форма с
полями создаёт её значение или элемент, а память даёт и забирает стратегия `Allocator`.

Дополнительные правила:

1. Коллекция (`Vector`, `List`, `Map`) объявляется обычным `struct` внутри `layout`. Программа хранит её значением
   в переменной или в поле класса: `var v = Vector<Int>()`.
2. У структуры из `layout` нет написанных программистом инициализатора и деструктора. Структура из строки `set`
   создаётся формой с полями как элемент своего множества, и память ей даёт стратегия `Allocator` множества
   (раздел 6.2); любая другая структура создаётся как значение. Освобождает значение компилятор по плану, а там,
   где память нужно обходить, функция `dispose` из стратегии структуры (раздел 7.4).
3. Одни и те же байты в разное время описывают разные структуры. Структура, которой байты элемента описаны сейчас,
   называется видом элемента. Виды одного множества начинаются с общего первого поля (`Header`), и у каждого вида
   свои строки `invariants`.
4. Строка в `invariants` вида уточняет поле для этого вида. `next: SlotBlock?` значит, что цель имеет вид
   `SlotBlock`. `next: own FreeBlock?` значит, что в виде `FreeBlock` поле владеет, а в остальных видах только
   указывает. Само поле объявлено с типом множества (`var next: Blocks.Item?`): вид в объявлении поля не пишется.
   Уточнение до `own` или `anchor` считается владеющим полем множества (раздел 3.4).
5. Читать поля может код, которому видна структура: своего слова видимости у поля нет. Поля от внешнего кода
   скрывает тип `opaque` ([типы со скрытой реализацией](../../types/type.md#opaque-типы)). Кто пишет поля,
   определяет раздел 2.5.

**Пример.** Участок менеджера памяти бывает видами `PoolBlock`, `FreeBlock`, `SlotBlock`, `LargeBlock`. Список из
примера A хранится значением:

```efen
var list = List()                 // значение, как Int
```

**Запрещено.** Экземпляров у `layout` нет: `layout` не тип. Физические объявления (`set`, `one`, `struct` с
полями-областями) пишет только `layout` уровня модуля.

**Почему.** Структура описывает память на уровне байтов. Какой стратегией берётся и возвращается её память,
назначает тип множества, поэтому компилятор знает место возврата без строки выделения в коде.

### 2.4 Параметры

**Правило.** Параметры пишутся сразу после слова `layout`, а у `layout` с именем после имени (раздел 10.1). Для
каждого набора аргументов множества свои.

Дополнительные правила:

1. Параметры: типы и значения времени компиляции. `Items` при `T == Int` и `Items` при `T == String` составляют
   два разных множества. Экземпляров у `layout` с параметрами тоже нет.
2. Снаружи имена пишутся с аргументами: `Vector<Int>`, `Items<Int>.Item`. У `Vector<T>` с полем `own Area<T>?`
   указатель на слот называет `T.Pointer`, а результат `-> own T?` отдаёт значение `T`. Множество `layout` с
   именем снаружи пишется через это имя: `Lists<Entry>.Nodes.Item` (раздел 10.1).
3. Ограничение пишется у параметра, как у обобщённой структуры: `layout<T: Movable>`. Оно действует на все
   объявления этого `layout` и на стратегии его структур, повторять его у стратегии не нужно.
4. Аргумент типа становится частью `layout`. Значение `T` в слоте области принадлежит структуре, которая владеет
   этой областью, и проверяется теми же правилами, что её поля. Элемент или область, которыми значение `T`
   владеет, входят в цепочку владения этой структуры (раздел 3.3). Указатель в значении `T` подчиняется правилу
   чистоты (раздел 4.3), а значение `T` с источником в типе хранит заимствование (раздел 4.5).
5. Параметр структуры может быть значением любого перечисления, не только `Int` или `Access`. Поле структуры может
   стоять под `#if`, и условие называет такой параметр:

   ```efen
   struct ArrayStorage {
       generic T: Type
       generic indirection: Indirection = direct

       #if indirection == .indirect
           var items: own Area<T.Pointer>? = null { value == null || value.count == count }
       #else
           var items: own Area<T>? = null { value == null || value.count == count }
       #endif
       var count: Int = 0 { value >= 0 }
   }
   ```

**Пример.**

```efen
private layout<T: Movable> {
    public struct Vector {
        var items: own Area<T>? = null { value == null || value.count == capacity }
        var capacity: Int = 0 { value >= 0 }
        var count: Int = 0 { value >= 0 && value <= capacity }
    }
}
```

**Запрещено.** Аргумент типа правил структуры не отменяет. Тип с аргументом проверяется там, где он написан
(раздел 8.7, проверка 7). `Vector<Vertices.Item>` отдельным значением, в переменной или в поле класса, составляет
публичную структуру. Указатель на вершину в его слоте указывал бы за её пределы, и запись такого указателя вызывает
ошибку (раздел 4.4, правило 6). Структура, которая задаёт свой размер сама (раздел 2.6), аргументом типа не служит,
кроме аргумента `Area`: `Area<Record>` — область с разным шагом (раздел 2.1, правило 8).

**Почему.** Множество с разными аргументами хранит элементы разного размера, поэтому указатели таких множеств
несовместимы. Значение `T` хранится в памяти структуры, переходит к другому владельцу и уничтожается вместе с ней.
Поэтому отдельных правил для него нет: действуют правила структуры.

Куда дальше: какой код пишет поля, определяет раздел 2.5.

### 2.5 Кто пишет поля

**Правило.** Поля структур из `layout` пишет только код, которому это разрешает модификатор видимости `layout`.

| Объявление | Поля пишут | Остальной код |
|---|---|---|
| `private layout` | функции этого модуля | читает поля видимой ему структуры и вызывает функции |
| `layout` без модификатора (по умолчанию `internal`) | функции пакета | читает поля видимой ему структуры и вызывает функции |
| `open layout Lists` (с именем) | функции пакета; поля `protected` пишет ещё и код расширений (раздел 10.4) | читает поля видимой ему структуры, кроме полей `protected`, и вызывает функции без `protected` |

Из правила следуют пять определений:

1. **Код `layout`.** Функции, которым модификатор разрешает писать поля: модуль у `private layout`, пакет у
   `layout`.
2. **Внешний код.** Весь остальной код: другой пакет, а у `private layout` ещё и другие модули пакета.
3. **Публичная функция структуры.** Функция без `private`, которая пишет поля структуры из `layout`. Инварианты
   структуры верны на её входе и выходе (раздел 5.1). Функция кода `layout` без `private`, которая поля только
   читает, тоже получает инварианты верными на входе.
4. **Вспомогательная функция.** Функция `private`, которая пишет поля. Она получает структуру, инвариант которой
   может быть временно нарушен. Что она сделала, сообщает её сводка. Сводка функции: то, что FLOW выводит из тела
   функции и записывает в её прототип.
5. **Код расширения.** Код `layout`, который расширяет `open layout` (раздел 10). В базовом `layout` из другого
   пакета он пишет только поля с пометкой `protected` и вызывает функции `protected fn`. Для остальных полей
   базового он внешний код. Расширение из пакета базового `layout` относится к коду базового `layout` по
   определению 1.

Функции в `layout` не входят. `layout` содержит только описание памяти: множества, структуры, инварианты и строки
`public own` и `public lend` (раздел 3.5). Функции стоят рядом, в модуле или пакете.

**Пример.**

```efen
private fn setPrev(a: Items.Item, b: edit Items.Item) {      // вспомогательная функция
    b.prev = a
}

strategy for List {
    public fn first -> read<self> Items.Item? {
        // тело не важно для примера: возвращает head
    }
    public edit fn insertFirst(value: Int) {                 // публичная функция структуры
        // тело не важно для примера: новый узел записан в head
    }
    public mut fn removeFirst {
        // тело не важно для примера: снимает первый узел и освобождает его
    }
}

strategy for List {
    implements Disposable

    fn dispose {
        // тело не важно для примера: снимает узлы по одному и освобождает их
    }
}

strategy for Graph {
    implements Disposable

    fn dispose {
        // тело не важно для примера: снимает вершины цепочки first по одной, освобождает рёбра каждой вершины
    }
}
```

**Запрещено.** Запись поля из внешнего кода вызывает ошибку, в том числе поля видимой ему структуры: видимость
открывает внешнему коду только чтение. Слова `public` и `private` у поля структуры вызывают ошибку. Слово `protected` в `layout` без `open` вызывает ошибку (раздел 10.4).

**Почему.** FLOW проверяет каждую функцию, которая пишет поля, поэтому место функции для доказательства не важно.
Модификатор ограничивает количество кода, который автор обязан согласовать с инвариантами.

Куда дальше: область со слотами разного размера описывает раздел 2.6.

<a id="область-с-разным-шагом"></a>

### 2.6 Область с разным шагом

**Правило.** Область, структура слота которой задаёт свой размер собственным инвариантом, состоит из слотов разного
размера и называется областью с разным шагом. Номером слота в ней служит смещение его начала в байтах от начала
области.

Структура задаёт свой размер, когда её строка `invariants` связывает число слотов её последней вложенной области с
её же полем: `text.count == length`. Отдельного слова у такой области нет: компилятор узнаёт её по структуре слота.

Эти имена известны компилятору:

| Имя | Что называет |
|---|---|
| `sizeOf(x[k])` | размер слота `k` в байтах, округлённый вверх до выравнивания слота: расстояние от начала слота `k` до начала следующего |
| `sizeOf(Record(length: n))` | размер слота, который ещё не записан: его даёт инвариант структуры слота по значению поля размера |
| `x.size` | размер области в байтах; то же число даёт `sizeOf(x)` |
| `x.extent` | число байтов от начала области, занятых её слотами; `extent` без имени области называет размер памяти вида ([условия вида](../pointer.md#условия-вида)) |
| `x.count` | число слотов; у области с разным шагом его находит обход по правилу 2 |
| `x.starts` | начала слотов: `x.starts.contains(k)`. Имя [призрачное](../../conditions.md#призрачные-поля-и-цепочки), как `x.taken`, и выводится из полей размера: в него входят `0` и каждое число `k + sizeOf(x[k])` меньше `x.extent` |

Дополнительные правила:

1. Чтение и запись существующего слота `x[k]` требуют доказательства, что `k` входит в `x.starts`. Адрес слота
   равен адресу области плюс `k`.
2. Начало слота код находит двумя способами. Первый способ, обход: `0` служит началом первого слота, а после начала
   `k` следующим началом служит `k + sizeOf(x[k])`, пока это число меньше `x.extent`. Второй способ, таблица
   смещений: поле или область чисел под инвариантом вида `forall i in 0 ..< used: x.starts.contains(index[i])`.
   Внешний код называет слот порядковым номером в такой таблице, и граница номера проверяется, как у любого
   индекса, либо хранит заимствование слота. Смещение, которое пришло от внешнего кода числом, код `layout`
   принимает только после обхода, который доказал, что оно входит в `x.starts`.
3. Занятую длину называет инвариант владельца: `records.extent == top`. Новый слот записывается в конец, по номеру
   `x.extent`, вместе с полем из этого инварианта и требует `edit`. Запись требует доказательства, что слот
   помещается в область: `x.extent + sizeOf(Record(length: n)) <= x.size`. Уменьшение занятой длины требует `mut`
   и удаляет слоты за новой длиной по правилу 6.
4. `lend` и `take` применяются к вложенной области слота: `lend page.records[k].text[a ..< b]` при строке
   `public lend Record.text`. Поля слота, и среди них поле размера, остаются у `layout`.
5. `x.taken` у области с разным шагом выводится из вложенных областей: в него входит начало `k` каждого слота, у
   которого `x[k].text.taken` не пусто. `lend` и возврат меняют `taken` вложенной области, а `x.taken` следует за
   ним. Поле-счётчик владельца (`used`) считает то, что выдано из вложенных областей, а не слоты самой области.
6. Поле, через которое инвариант задаёт размер слота, относится к полям раскладки
   ([условия вида](../pointer.md#условия-вида)). Его запись в существующем слоте делит слот или сливает его с соседним
   и считается изменением структуры: она требует `mut`, и из вложенных областей затронутых слотов ничего не выдано.
   Деление состоит из двух записей, между которыми нет места проверки инварианта (раздел 5.1): записи поля размера
   в прежнем слоте и записи поля размера нового слота по номеру `k + sizeOf(x[k])`, как у парных элементов
   (раздел 6.2, правило 7). Слот, которого после записи нет, считается уничтоженным элементом. До записи каждый
   хранимый номер и указатель на него переписан, его владеющие поля равны `null`, а значения типа `T` из него
   забраны `take` (раздел 6.5, правила 3 и 4). Забирает их функция с правом `mut` на владельца области.
7. Если у слота несколько видов (раздел 2.3), поле размера стоит в их общем первом поле, и каждый вид вычисляет
   по этому полю один и тот же размер слота. Виды, инварианты которых дают по одному значению общего первого поля
   разные размеры, вызывают ошибку у своего объявления. Смена вида записывает поле размера, как любое поле нового
   вида (раздел 6.7). Инициализатор `_` оставляет его байты, и размер слота прежний. Запись другого значения делит
   слот или сливает его с соседним по правилу 6.
8. В каждом месте, где верен инвариант (раздел 5.1), FLOW доказывает четыре факта. Слоты занимают байты
   `0 ..< x.extent` без промежутков и наложений, и начало каждого слота выровнено. Каждый индекс в коде входит в
   `x.starts`. Занятая длина не больше размера области (`x.extent <= x.size`), а вложенная область помещается в
   память элемента, в котором расположена. Счёт выданного из вложенных областей сходится с полем-счётчиком
   (раздел 6.6).
9. Область с разным шагом верхнего уровня хранится под `own Area<Record>?`, и её владелец задаёт размер в байтах:
   `{ value == null || value.size == bytes }` (раздел 2.1, правило 3). Вложенная область с разным шагом получает
   остаток памяти своего элемента от смещения своего поля, как любая область, объявленная последним полем
   ([поле-область и параметр `size`](../pointer.md#поле-область-и-параметр-size)): `x.size` равен размеру памяти элемента
   без этого смещения. Вид, которому нужен меньший размер, называет его инвариантом (`records.size == E`).

**Пример.** Страница журнала хранит записи разной длины подряд.

```efen
layout {
    set area Pages: Page

    struct Record {
        var length: Int { value >= 0 }
        inline text: Area<Byte>
        invariants { text.count == length }          // слот задаёт свой размер сам
    }

    struct Page {
        var next: anchor Pages.Item? = null
        var top: Int = 0 { value >= 0 }
        inline records: Area<Record>                 // слоты разного размера
        invariants { records.extent == top }
    }

    public struct Log {
        var first: anchor Pages.Item? = null         // владеет цепочкой страниц
    }
}

fn append(page: edit Page, length: Int) -> Int
    requires page.top + sizeOf(Record(length: length)) <= page.records.size {   // новый слот помещается в область
    let k = page.top
    page.records[k] = Record(length: length)         // новый слот в конце: k == records.extent
    page.top += sizeOf(page.records[k])
    return k                                         // номер слота: смещение в байтах
}

fn total(page: read Page) -> Int {
    var k = 0
    var sum = 0
    while k < page.top {                             // FLOW: k входит в records.starts
        sum += page.records[k].length
        k += sizeOf(page.records[k])
    }
    return sum
}
```

`append` записывает новый слот в конец и увеличивает `top` на его размер. `total` обходит слоты от нуля. По
инварианту `records.extent == top` и правилу 2 FLOW доказывает, что `k` на каждом шаге входит в `records.starts`.

**Запрещено.**

- Параметр `size` в приведении и инвариант `sizeOf(x.Item) == E` у области с разным шагом вызывают ошибку: размер у
  каждого слота свой.
- Индекс, о котором не доказано, что он называет начало слота, вызывает ошибку компиляции. Проверки при выполнении
  для него нет. Без доказательства индекс принимается только после строки `assume`, а она служит точкой доверия
  (раздел 1).
- Обращения к слоту по порядковому номеру нет.
- `lend` и `take` слота целиком вызывают ошибку.
- Запись поля размера, пока из вложенной области затронутого слота что-то выдано, вызывает ошибку.
- Раздача `for element in take region` над областью с разным шагом вызывает ошибку: такую область обходят по
  правилу 2.
- Размер слота задаёт только его последняя вложенная область, а эта область стоит последним полем структуры: число
  её слотов (`text.count == length`) или, когда она сама с разным шагом, её размер в байтах (`fields.size == size`).
  Правила этого раздела действуют на каждом уровне вложенности. Инвариант, который связывает с полем слота другую
  область, размера не задаёт.
- Роль такую область не делит (раздел 9.4).

**Почему.** Структура, которая задаёт свой размер сама, уже существует как элемент `set area` с областью в конце.
Не хватало только такой структуры на месте слота. Смещение в байтах на месте номера оставляет `x[k]` одним
сложением, и компилятор не вставляет скрытого обхода. Цепочка свободных слотов и граница `frontier` записываются
через номера слотов, как у остальных областей, а `taken` выводится из вложенных областей (правило 5). Поле размера
не выдаётся и остаётся у `layout`, поэтому внешний код размер слота не меняет, и обход опирается на доказанный
инвариант.
