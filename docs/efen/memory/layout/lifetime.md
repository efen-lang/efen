## 7. Время жизни

Время жизни не объявляется: FLOW выводит его из кода. Указатель или ссылка становится недействительной в точке
изменения структуры, которое могло затронуть цель, а ошибку вызывает только использование после этой точки.
Раздел опирается на классы операций (6.1) и на источник (4.2).

Указатель допустим везде, где его разрешает раздел 4, если компилятор доказал два факта: из какого множества
указатель получен и что он не используется дольше, чем существует его цель. Все правила раздела следуют из этого
принципа. Аннотаций времени жизни в сигнатурах нет. Источник пишется в четырёх местах: у объявления
без тела (раздел 8.5), у параметра, которому нужен элемент определённой структуры (раздел 4.1), в приведении
адреса и в типе значения, которое заимствует: у структуры с `Src: Origin` и в аргументе типа коллекции
(раздел 4.5).

<a id="диагностика-времени-жизни"></a>

Как FLOW строит доказательство и как печатает ошибки времени жизни, описывает
[алгоритм работы layout](../layout-algorithm.md#вывод-времени-жизни).

### Механизм: время жизни между двумя вызовами

**Правило.** Память существует от операции, которая её даёт, до операции, которая её возвращает. Время жизни каждого
указателя FLOW доказывает по этим вызовам: он отслеживает их через сводки функций и для каждого вызова знает,
какие указатели после него недействительны.

| Память | Операция, которая её даёт | Операция, которая её возвращает |
|---|---|---|
| элемент множества | форма с полями `Item(value: 0)`: `allocate` стратегии множества (раздел 6.2) | конец значения `own Items.Item`: `deallocate` той же стратегии (раздел 6.5) |
| область коллекции | `Area<T>(count: n)`: `allocate` стратегии области | конец значения `own Area<T>`: `deallocate` той же стратегии |
| выданный слот | `lend block.data[a ..< b]` (раздел 6.6) | возврат в свой слот: `block.data[a ..< b] = take data` |
| всё, чем владеет значение структуры из `layout` | функции структуры (`append`, `pushFirst`) | план освобождения и `dispose`, которые вызывает компилятор (раздел 7.4) |
| участок памяти ОС | `System.map` ([системные вызовы](../system.md#память-ос-как-множество)) | `System.unmap` |

Дополнительные правила:

1. Между двумя вызовами у памяти в каждый момент один владелец (раздел 3.1). `take` и `tie` меняют владельца и
   времени жизни не кончают (раздел 7.2).
2. Вызов, который даёт или возвращает память, виден через любое число промежуточных функций. Сводка функции с
   телом сообщает, что она уничтожает, отдаёт и оставляет (раздел 8.4). У объявления без тела то же сообщают
   написанные право и тип (раздел 8.5).
3. После вызова, сводка которого возвращает память, недействителен каждый указатель и каждая ссылка, которые могут
   указывать в неё (раздел 7.1). Ошибку вызывает использование после такого вызова.
4. Каждая память, которую дал вызов, на каждом пути доходит до вызова, который её возвращает (раздел 7.4).

**Пример.**

```efen
fn example(list: mut List) {
    list.insertFirst(value: 7)          // сводка: внутри выделение, новый узел оставлен в list
    let node = list.first() ?? return   // указатель на первый узел, источник: list
    print(node.value)                   // допустимо: вызова, который возвращает узел, ещё не было
    list.removeFirst()                  // сводка: уничтожает первый узел, его память возвращена
    print(node.value)                   // ошибка: node использован после вызова, который вернул его память
}
```

`example` не видит ни выделения, ни возврата памяти: обе операции стоят в телах функций списка. FLOW читает их
сводки.
По сводке `removeFirst` он считает недействительным каждый указатель с источником `list`, который может быть равен
первому узлу, и вторую строку `print` отвергает.

**Запрещено.** Аннотаций времени жизни в сигнатурах нет, и объявить время жизни указателя иначе, чем вызовами,
нельзя.

**Почему.** Вызовы, которые дают и возвращают память, уже стоят в программе. Отслеживая их, компилятор получает
время жизни без дополнительных записей, а программист видит в диагностике два места: вызов, который вернул память,
и использование после него.

### 7.1 Что делает указатель недействительным

**Правило.** Изменение структуры элемента X делает недействительными в любом коде каждый указатель и каждую ссылку
с источником в структуре X, которые могут быть равны X, тому, чем X владеет, или тому, что в нём расположено.
Запись значения не делает недействительным ничего.

| Изменение структуры | Что становится недействительным |
|---|---|
| `tie` якоря, после которого элемент ушёл из структуры | указатели и ссылки с источником в этой структуре на элемент и на всё, чем он владеет |
| `take` значения `own` из поля, `take` слота области | ссылки и указатели на прежнее содержимое, со строки `take` |
| запись целого значения, которая может покинуть случай с данными опционального типа или варианта (раздел 6.1, правило 6) | ссылки и псевдонимы внутрь прежних данных; ссылка на сам слот действительна |
| `lend` | ссылки, срезы и курсоры, которые могут пересекаться с выданным слотом; остальные действительны |
| возврат выданного слота | каждый указатель на слот, в том числе хранимый в поле другой структуры |
| `as own`, освобождение | все указатели и ссылки на элемент |
| смена вида `as` | указатели прежнего вида, кроме переведённых на новый вид |
| перевыделение или замена области | ссылки и указатели внутрь прежней области |
| запись поля размера в слоте области с разным шагом | ссылки и указатели на слоты, начало или размер которых изменились, и внутрь их вложенных областей |
| запись поля раскладки вложенной области, слоты которой имеют один размер | ссылки и указатели на слоты этой области и внутрь них |
| корень структуры ушёл из своего слота: `take` в существующий слот, `swap`, `replace`, передача `own`, возврат | все указатели и ссылки с этим источником |

Дополнительные правила:

1. `take` целой локальной переменной в новую переменную ничего не делает недействительным: источником становится
   новая переменная.
2. Слот не существует дольше элемента, в котором расположен. Элемент не существует дольше памяти, из которой
   взят.
3. Указатель на значение под якорем действителен не дольше якоря. В точке, где якорь уничтожает значение или
   отдаёт его из структуры, указатели недействительны. Хранимый указатель к выходу функции указывает на
   существующий элемент.
4. Операция, которая уничтожает значение, переносит его в другую память или меняет его вид, требует
   доказательства: каждый указатель на значение недействителен или переписан. При переносе и смене вида указатель
   остаётся действительным, если переведён на новое место или вид. `tie` внутри структуры такого доказательства не
   требует.
5. Недействительный указатель, который дальше не используется, операции не мешает. Значение, которое хранит такой
   указатель (курсор) и дальше не используется, уничтожается перед операцией. Значение с владеющим полем `layout`
   (`Vector<read<g> Vertices.Item>`, `Vector<ListCursor<Src: list>>`) перед операцией не уничтожается: компилятор
   освобождает его в конце области видимости (раздел 7.4). Оно существует и после операции, и ошибку вызывает
   только чтение его слотов с недействительными указателями (раздел 4.5). `take` слота, который хранит
   недействительный невладеющий указатель, и конец такого значения использованием указателя не считаются: указатель
   не разыменовывается.

**Пример.**

```efen
let p = a.first()!                  // Items.Item, источник: a
freeAll(b)                          // освобождает узлы b; a и b общей памяти не объявляли
print(p.value)                      // допустимо
moveFirst(a, b)                     // mut для a: узел ушёл из a
print(p.value)                      // ошибка: p недействителен со строки moveFirst
```

```efen
fn shrink(table: mut Table, n: read<table> Nodes.Item) {
    let k = n.key                          // Key.Pointer: слот области table.keys
    let old = take table.keys              // ошибка: k используется ниже и указывает в прежнюю область
    // здесь код записывает в table.keys новую область меньшего размера
    print(k)
}                                          // old кончается: прежняя область возвращена аллокатору области
```

**Запрещено.** Использование недействительного указателя или ссылки вызывает ошибку. Компилятор показывает её в
строке изменения структуры и отдельно показывает строку использования.

**Почему.** Источник делит указатели программы по структурам, поэтому изменение одной структуры не затрагивает
указатели в другую. Внутри структуры компилятор считает затронутым каждый указатель, который может быть равен
изменённому элементу.

Куда дальше: когда время жизни элемента начинается и кончается, описывает раздел 7.2.

### 7.2 Начало и конец времени жизни, смена источника

**Правило.** Время жизни элемента начинается, когда память входит в множество, и кончается, когда она из него
выходит. Переход элемента в другую структуру внутри `layout` время жизни не кончает.

Дополнительные правила:

1. Для вложенной области FLOW учитывает четыре операции: память родителя создана (приведение `Pointer` к виду,
   `System.map`); число слотов известно из условия владельца или вида; слот выдан (`lend`, раздача); слот вернулся
   через `own`.
2. Владение выданным слотом начинается при выдаче и кончается при возврате в свой слот. До выдачи и после
   возврата слот хранит значение в памяти родителя.
3. У множества верхнего уровня (`Blocks`) родителя нет. Время жизни его элемента начинается, когда форма с полями
   или приведение даёт элемент, и кончается с концом значения `own` или при стирании `as Pointer`.
4. Элемент, перешедший владением в другую структуру, существует. Указатели множества на него внутри новой
   структуры допустимы. Указатели и ссылки с источником в прежней структуре становятся недействительными в любом
   коде.
5. Исключение из правила 4 одно. В функции, которая сама передала элемент, её локальные указатели на этот элемент
   и на всё, чем он владеет, получают источником новую структуру, если она известна в этой функции: по `tie` в её
   теле или по сводке вызова, которая называет параметр, в структуру которого элемент записан. Указатель, о котором
   не доказано, что он указывает в переданное дерево, подчиняется последнему абзацу правила 5 раздела 6.4.
6. После вызова без тела и после вызова, сводка которого сообщает только о возможной передаче, указатель
   недействителен.
7. Получатель элемента не считает, что на элемент ничто не указывает: на него могут указывать другие указатели
   множества.

**Пример.**

```efen
fn move(pool: mut Pool, block: anchor Blocks.Item) {
    let name = block
    keep(pool, tie block)                  // block записан в pool; источником name служит pool
    print(name.used)                       // допустимо
}
```

**Запрещено.** Использование указателя на слот после его возврата вызывает ошибку. Компилятор показывает её в
строке возврата и отдельно показывает строку использования.

**Почему.** Элемент существует, пока его память принадлежит множеству, а кому он принадлежит внутри `layout`,
может меняться. Поэтому время жизни элемента и действительность указателя различаются: первое зависит от
множества, вторая от источника.

Куда дальше: те же правила для указателей у внешнего кода описывает раздел 7.3.

### 7.3 Пока память у внешнего кода

**Правило.** После каждого вызова FLOW доказывает, что указатель, оставшийся у внешнего кода, действителен.
Недоказанный случай вызывает ошибку.

Дополнительные правила:

1. Вызов, который пишет только другие байты, разрешён. Пример: перестановка `next` и `prev` в цепочке пула, пока
   область `data` элемента выдана.
2. Заимствование с правом (`mut`, `edit`, `read` в результате) подчиняется общему правилу
   ([что делает ссылку недействительной](../memory-rules.md#что-делает-ссылку-недействительной)). После вызова `edit` оно
   действительно. Вызов, который меняет структуру источника, делает его недействительным.

**Пример.**

```efen
fn example(list: mut List) {
    let node = list.first() ?? return   // указатель на узел, источник: list
    list.insertFirst(value: 7)          // допустимо: edit, узлы на своих адресах
    print(node.value)
    list.removeFirst()                  // ошибка: узел освобождён, а node используется ниже
    print(node.value)
}
```

**Запрещено.** Вызов, сводка которого освобождает или переносит память под указателем, используемым дальше,
вызывает ошибку. Компилятор показывает её в строке вызова и отдельно показывает строку использования. Вернуть или
освободить родителя, пока его слот выдан, нельзя (раздел 6.6).

**Почему.** Внешний код не видит полей и не может сам проверить, что его указатель действителен. За него это
делает сводка вызванной функции.

Куда дальше: обязанность довести каждое владение до конца описывает раздел 7.4.

### 7.4 Ничего не теряется

**Правило.** На каждом выходе, обычном и через исключение, каждое владение доведено до конца. Значение `own`
элемента и значение структуры из `layout` освобождает компилятор: элемент через стратегию `Allocator` своего множества,
структуру по плану освобождения. Якорь `anchor` и выданный слот неявно не кончаются: такое значение
записано в структуру, возвращено или доведено до `own` явным кодом. Исключение — тип в ручном режиме выделения: его
память возвращает явный вызов ([ручное выделение](../allocator.md#ручное-выделение)).

Локальный владелец:

1. В коде `layout` локальная переменная или параметр `own` с элементом в конце своей жизни освобождается по плану.
   Поля-значения элемента уничтожаются как любое поле; для поля типа `T`, значение которого при этом уничтожается,
   доказано `T conforms ImplicitlyDestroyable` (правило 6 о значении структуры). Владеющее поле, элемент которого не может снова владеть элементом своего
   множества, освобождается так же. Каждое другое владеющее поле (`own`, `anchor`) доказанно равно `null`, иначе
   конец значения вызывает ошибку «владелец потерян». Затем компилятор вызывает `deallocate` стратегии
   `Allocator` множества. Локальная
   переменная или параметр `own Area<T>` кончается, как любое значение: компилятор вызывает деструктор области на
   каждом выходе, обычном и через исключение. Деструктор уничтожает слоты, которые FLOW в этой точке функции
   доказал инициализированными, и возвращает память стратегии `Allocator<Area<T>>`. Внутри функции FLOW знает
   состояние каждого слота, поэтому инвариант для этого не читается (раздел 6.3, правило 6). Для каждого слота типа
   `T`, который деструктор уничтожает, доказано `T conforms ImplicitlyDestroyable` (правило 6 о значении структуры);
   слот, состояние которого FLOW не знает, вызывает ошибку «владелец потерян».
2. Локальная переменная `anchor` неявно не уничтожается. Вызов, который может бросить исключение, пока она хранит
   значение, вызывает ошибку, если на этом пути нет обработчика, который значение освобождает или передаёт
   дальше.
3. То же относится к элементу `own Nodes.Item` и выданному слоту у внешнего кода: на каждом выходе значение
   возвращено функции кода `layout` или передано дальше.

Значение структуры из `layout`:

Правила ниже действуют для любой структуры: на стеке, в куче, в `static` и в поле потока. Где лежит значение,
решает компилятор: структуру, которая живёт дольше функции, он на стеке не создаёт. Значение `static` уничтожается
после возврата из `main`, значение поля потока при завершении потока
([создание и уничтожение](../../context-and-effects.md#создание-и-уничтожение)). Структура, память которой выделил другой
поток, освобождается так же (раздел 9.6, правило 2).

1. Компилятор освобождает структуру там, где значение кончается: в конце области видимости, в конце инструкции у
   временного значения, на выходе через исключение и при записи в слот целиком. Он строит план освобождения по
   объявлению: поле обычного типа и поле со структурой уничтожаются как любое поле; поле `own X.Item?`, элемент которого не может снова владеть элементом `X`, освобождается так же, по своим
   полям. Инвариантов план не
   читает. Пользовательского деструктора у структуры нет
   ([освобождение структуры](../../disposable.md#освобождение-структуры-disposable)).
2. Структуру, которую по объявлению не освободить, план не обходит: структуру с полем `anchor`, с цепочкой владения
   внутри одного множества (список, граф), с полем-областью, слоты которой могут быть не инициализированы (`Vector`).
   Такая структура пишет `implements Disposable`
   и тело `fn dispose` в своей стратегии. Компилятор вызывает `dispose` перед планом в тех же точках; обычным вызовом
   `dispose` не вызывается и исключений не бросает. `dispose` получает `self` с правом `mut`; слово права перед
   `fn dispose` не пишется. `dispose` проверяется как функция кода `layout`: на каждом его выходе поля, которые план
   не обходит, равны `null`, и после него ни один указатель в освобождённую память не используется (раздел 7.1).
3. Структура соответствует `ImplicitlyDestroyable`, когда ему соответствует каждое значение, которое уничтожают
   план и `dispose`: `Vector<Int>` соответствует, `Vector<own Nodes.Item>` нет
   ([`ImplicitlyDestroyable`](../../disposable.md#implicitlydestroyable)).
4. Структура, которой нужен `dispose`, без него вызывает ошибку у объявления (решение 2026-11-12-07, пункт 4).
   Значение структуры, которая не соответствует `ImplicitlyDestroyable`, неявно не уничтожается: на каждом выходе,
   обычном и через исключение, его расходует явный код, параметр `own` другой функции или функция структуры.
   Структура, созданная особым способом (арена, пул, отображение файла), уничтожается явным вызовом деструктора.
5. Поле класса и поле `shared struct` со структурой, которая соответствует `ImplicitlyDestroyable`, уничтожаются
   вместе со своим объектом, как любое поле такого типа. Структуру, которая не соответствует, класс расходует в
   своём деструкторе, а `shared struct` явной функцией: под своей блокировкой или, когда блокировки нет, с
   исключительным доступом, после конца всех ролей. Слот `thread var` принимает только `ImplicitlyDestroyable`: при
   завершении потока нет выхода, на котором программа освобождает значение
   ([деструкторы](../../disposable.md#implicitlydestroyable)). Запись `thread var x: own T` со значением другого типа
   служит объявленной точкой доверия ([кому доступно доверие](../system.md#кому-доступно-доверие)): компилятор не
   доказывает, что к завершению потока значение освобождено
   ([чего таблица не обещает](../memory-rules.md#чего-таблица-не-обещает)).
6. В каждой точке, где функция уничтожает значение типа `T`, доказано `T conforms ImplicitlyDestroyable`. Публичная
   функция получает этот факт условием `requires T conforms ImplicitlyDestroyable || count == 0`: при `count == 0`
   по инварианту структуры путь, который уничтожает значения, недостижим. В теле `dispose` факт верен без условия:
   компилятор вызывает `dispose` только у значения, тип которого соответствует `ImplicitlyDestroyable` (правило 3).
   Для остальных `T` структура отдаёт элементы вызывающему (`removeLast -> own T?`), и он уничтожает их сам.

Жизненный цикл элемента. По телам функций FLOW строит путь каждого вида элемента: создание, повторная выдача,
смена вида (`SlotBlock`, затем `FreeBlock`, затем снова `SlotBlock`), возврат памяти. О каждом пути он доказывает
четыре свойства:

1. Каждый выданный слот и каждый элемент с владельцем на каждом пути возвращается или передаёт владельца дальше.
   Элемент берёт память у стратегии своего множества и возвращает её туда же; экземпляр `one` освобождается при
   завершении потока, и `one`, который держит цепочку, пишет `dispose`.
2. Ничто не возвращается дважды и не возвращается в чужой слот.
3. Память родителя возвращается, только когда ничто выданное из неё не хранится вне её (раздел 6.6, правило 8).
   Области, вложенные в неё, возвращаются вместе с ней.
4. Элемент покидает множество только операциями раздела 6 или через точку доверия.

Сырая память линейна: владеющий корень передаёт её дальше на каждом выходе.

**Пример.**

```efen
fn countCopied(values: read Array<Int>) -> Int {
    var v = Vector<Int>()
    for x in values { v.append(x) }     // append может бросить исключение: на этом выходе v освобождается
    return v.count                      // обычный выход: v освобождается после чтения count
}

print(loadValues().count)               // временный Vector освобождается в конце инструкции
```

**Запрещено.**

- Потерянный локальный владелец вызывает ошибку в конце функции.
- Класс без деструктора с полем, которое хранит структуру с владеющим полем `layout`, не соответствующую
  `ImplicitlyDestroyable`, вызывает ошибку.
- `@destructor` и `conforms Destructible` у структуры вызывают ошибку. Обычный вызов `v.dispose()` тоже.
- Значение структуры, которое по правилу 4 о значении структуры неявно не уничтожается, вызывает ошибку на выходе,
  где его владеющее поле может быть не `null`.
- Оставленная сырая память вызывает ошибку компиляции с кодом `flow.leak`.

**Почему.** Освобождение на каждом выходе расставляет компилятор, поэтому выход через исключение и временное
значение памяти не теряют. Место возврата памяти элемента называет его тип: аллокатор у множества один. Обход списка
или графа — алгоритм, которого компилятор не знает, поэтому его пишет `dispose`. Выданный слот возвращается только
туда, откуда взят, и это место называет явный код.
