## 3. Владение

У каждого элемента в каждый момент один владелец, и он виден из объявлений. Раздел опирается на множества, поля и
границу между кодом `layout` и внешним кодом из раздела 2.

<a id="якорь-anchor"></a>

### 3.1 own и якорь

**Правило.** Владение бывает исключительным (`own`) и неисключительным (`anchor`, якорь). У значения ровно один
владелец, и он определяет, где значение уничтожается. Владение переносят операции `take` и `tie` (раздел 6.4),
якорь превращает в `own` приведение `as own` (раздел 6.5).

| | `own`: исключительное владение | `anchor`: якорь, неисключительное владение |
|---|---|---|
| смысл | единственный хранимый путь к значению | конец времени жизни значения; на значение указывают хранимые указатели |
| перенос | `take`; хранимых указателей на значение нет, локальные недействительны со строки `take` | `tie`; указатели множества на значение остаются действительными |
| уничтожение | безопасно всегда | после него ни один указатель не используется |
| факт на входе функции | «ничего не заимствовано» | такого факта нет |
| пример | `var pending: own Job?`; слот, выданный внешнему коду | узел дерева с `parent`; элемент `Block` в цепочке пула |

Дополнительные правила:

1. `own` равен якорю, на значение которого не указывает ни один хранимый указатель. Это доказывается там, где
   значение уходит из своей структуры (раздел 4.3, правило 5). Локальный указатель, прочитанный из слота `own`
   (раздел 4.1, правило 5), недействителен со строки `take` (раздел 7.1). Поэтому значение `own` записывается в
   поле `anchor` без отдельного шага. Обратно, от якоря к `own`, ведёт только `as own` (раздел 6.5).
2. Владеющее поле стоит в элементе того же множества (узел дерева владеет поддеревом), в слоте области другого
   множества (корзина хеш-таблицы владеет первой записью цепочки) или в корне коллекции (`List.head`).
3. Владение считается отдельно в каждом множестве. Область целиком принадлежит своему владельцу, а её слот может
   быть якорем элемента другого множества. Это два разных владения.
4. Пока из множества что-то выдано или его слоты хранят якоря существующих элементов, область нельзя уничтожить, а
   слот нельзя перезаписать целиком.

**Пример.** В примере A `Item.next` и `List.head` объявлены якорями, потому что на узел указывает `prev` соседа.

```efen
struct Node {
    var left: anchor Nodes.Item? = null      // владеет левым поддеревом
    var right: anchor Nodes.Item? = null
    var parent: Nodes.Item? = null           // невладеющий указатель
}
```

**Запрещено.** Два поля `anchor` на одно значение вызывают ошибку. `anchor` вместе с `own` на одно значение тоже
ошибка.

**Почему.** У значения одна точка уничтожения. Два вида владения дают FLOW разные проверки. У значения под `own`
хранимых указателей нет, и это доказано раньше, там, где значение ушло из структуры (правило 1). Под якорем перед
уничтожением надо найти каждый указатель.

Куда дальше: владелец бывает не только полем, это описывает раздел 3.2.

### 3.2 Владелец вне поля

**Правило.** Владельцем бывают параметр, результат и локальная переменная с `own` или `anchor`. Функция с
параметром `anchor` отвечает за уничтожение значения.

**Пример.**

```efen
fn destroyBlock(pool: mut Pool, node: anchor Blocks.Item) {
    unlink(pool, node)                       // указатели на node в цепочках пула сняты
    mm.free(node as own Pointer)             // якорь стал own, память вернулась менеджеру памяти
}

fn pop(list: mut List) -> anchor Items.Item? {
    let first = tie list.head ?? return null
    list.head = tie first.next               // first.next теперь равен null
    if let h = list.head { h.prev = null } else { list.tail = null }
    list.length -= 1                         // инварианты List восстановлены: функция публичная
    return first                             // якорь переходит к вызывающему
}
```

Имя `mm.free` здесь и далее обозначает функцию внешнего менеджера памяти, которая принимает `own Pointer`.

До выхода функция с параметром `anchor` уничтожает значение или передаёт якорь дальше. Пока она этого не сделала,
указатели на значение у остального кода действительны.

**Запрещено.** Якорь переходит только между функциями кода `layout`. Коду расширения его отдаёт и от него принимает
функция `protected fn` (раздел 10.4). Локальный владелец неявно не уничтожается (раздел 7.4).

**Почему.** Между снятием элемента с одного поля и записью в другое им кто-то владеет. Если бы владельцем считалось
только поле, такой промежуток был бы утечкой.

Куда дальше: цепочка владельцев элемента определяет его структуру, раздел 3.3.

### 3.3 Структура элемента

**Правило.** Структурой элемента называется корень цепочки его владения.

Цепочка идёт от элемента вверх по `anchor`, по `own`, по вложенности в область и по полю, которое хранит значение
структуры из `layout`. Она кончается на первом владельце вне значения `layout`: локальной переменной, параметре,
поле обычного типа, `one`.

<a id="публичная-структура"></a>

Публичной называется структура, владелец которой находится вне значения `layout`: корень цепочки вместе со всем,
что под ним. Публичных структур два вида. Первый: значение структуры из `layout` со всеми элементами под ним в
переменной, параметре, результате, поле обычного типа или поле `thread var`. Второй: элемент `own Nodes.Item` или
выданный слот в переменной, параметре или результате. Полем обычного типа, и полем `shared struct` тоже, элемент и
выданный слот не хранятся (раздел 3.5): дольше одного вызова их хранит обобщённый контейнер из `layout`, и там они
принадлежат структуре контейнера (раздел 3.4, правило 1). Определение не зависит от
того, какой код хранит значение: структура в переменной функции кода `layout` и в поле класса того же пакета тоже
публичная. Внутренней структурой называется часть публичной: элемент вместе со всем, чем он владеет, или значение
структуры из `layout` в поле элемента или в поле другой структуры из `layout`. Каждая структура относится ровно к
одному из двух видов. `one X` со всем, чем владеют его поля, составляет публичную структуру всей программы: её
хранимые указатели указывают внутрь неё (раздел 4.3), и она никуда не переходит (раздел 9.5).

**Пример.** Хеш-таблица вместе с областью корзин составляет одну структуру. Два `List` в полях одного объекта
составляют две структуры, и обе публичные. Значение `List` в поле структуры `Lru` из того же `layout` входит в
`Lru` внутренней структурой. Вершина из примера C принадлежит цепочке от `Graph.first`, поэтому её структурой
служит граф. Сама вершина со своими рёбрами и вектором `neighbors` составляет внутреннюю структуру этого графа.

**Запрещено.** Элемент не принадлежит двум структурам сразу. Он переходит из структуры в структуру только
владением, одной операцией (раздел 6.4).

**Почему.** По структуре элемента решается, какие указатели затрагивает операция. Цена определения: внутри одной
структуры её цепочки не различаются. Вызов, который освобождает элементы структуры, делает недействительным каждый
указатель в ней, который может быть равен освобождённому.

### 3.4 Два способа владеть элементами множества

**Правило.** У каждого множества есть владелец, и он виден из объявлений: владеющее поле (`own` или `anchor` с типом
элемента множества, `Nodes.Item`; у области `own Items.Area`) либо строка `public own Nodes` (раздел 3.5). Способ
владения элементами множества один. Владеющим считается и поле, в аргументе типа которого записан `own Nodes.Item`
(`var items: Vector<own Nodes.Item>`), и поле, которое вид уточняет до `own` или `anchor` (раздел 2.3, правило 4).

| Поле `own` или `anchor` с типом `Nodes.Item` | Строка `public own Nodes` | Способ | Кто владеет элементом множества |
|---|---|---|---|
| есть | нет или есть | по полю | владеющее поле или функция кода `layout`; при строке `public own Nodes` ещё и внешний код, получивший `own Nodes.Item` |
| нет | есть | множество выдано целиком | только внешний код, через `own Nodes.Item`; `layout` указателей на элемент не хранит |

Дополнительные правила:

1. Элемент под `own` у внешнего кода составляет отдельную публичную структуру. Её корень находится в переменной
   или параметре, которые хранят элемент. Элемент в слоте обобщённого контейнера (`Vector<own Nodes.Item>`)
   принадлежит структуре контейнера (раздел 2.4, правило 4).
2. Участок менеджера памяти с выданными слотами остаётся под владеющим полем. Им владеет цепочка якорей пула:
   `Pool.busy` в примере B, одна из двух цепочек класса размеров у менеджера памяти
   ([иерархия владения](../pointer.md#иерархия-владения)). Получатель слота владеет слотом и участком не владеет
   (раздел 3.5). Участок считает выданные из него слоты в поле `used`. Пока `used > 0`, участок нельзя вернуть
   или освободить. После возврата последнего слота код переносит участок в цепочку свободных (`Pool.free`) или
   вырезает его из цепочки и приводит к `own` (раздел 6.6, правило 5).
3. Коллекции, которой нужны оба способа для разных элементов, нужны два множества.
4. Область, объявленная полем структуры (раздел 2.2), принадлежит элементу, в байтах которого расположена.
5. Строка `public lend Block.data` владельцем множества не служит. Она относится к слотам области-поля, а такая область
   принадлежит элементу (правило 4). Владельца элементам структуры `T` даёт владеющее поле или строка `public own`.

**Пример.** В примере C оба множества относятся к способу «по полю». Вершинами владеет граф: цепочка идёт от
`Graph.first` по `Vertex.nextAll`. Рёбрами владеет вершина через `firstEdge`. Перед освобождением вершины её
владеющие поля равны `null`: функция сначала вырезает вершину из цепочки графа и освобождает рёбра.

**Запрещено.**

- Множество, у которого нет ни владеющего поля, ни строки `public own`, вызывает ошибку у своего объявления: у
  его элементов не было бы владельца. Пример: `layout` со строками `set area Blocks: Block` и
  `public lend Block.data`, в котором нет владеющего поля типа `Blocks.Item`.
- Потерянный владелец у множества «по полю» вызывает ошибку.
- У множества, выданного целиком, хранимое поле типа `Nodes.Item` без владения вызывает ошибку: на элемент под
  `own` у внешнего кода не указывает ни один хранимый указатель (раздел 3.1, правило 1).
- `anchor Nodes.Item` в аргументе типа (`Vector<anchor Nodes.Item>`) вызывает ошибку: обобщённый код переносит значения
  через `take`, а `take` слота под якорем запрещён (раздел 6.4).

**Почему.** Владелец даёт компилятору место, от которого он ищет указатели на элемент. При владении по полю каждый
хранимый указатель на элемент находится в той же публичной структуре, что и владелец (раздел 4.3). На элемент
множества, выданного целиком, не указывает ни один хранимый указатель. Доказательство, что указателей на элемент не
осталось, пишет функция, которая его освобождает (раздел 6.5).

### 3.5 Что уходит наружу

**Правило.** Внешний код получает память `layout` пятью способами. Два из них передают владение частью памяти, и
их `layout` объявляет в схеме владения. Строка `public own Nodes` называет множество `Nodes`: его элемент уходит
внешнему коду целиком. Строка `public lend Block.data` называет структуру `Block` и её поле-область `data`: внешнему
коду выдаются слоты этой области.

| Что получает внешний код | Запись | Строка |
|---|---|---|
| значение структуры из `layout` (`List`, `Graph`, `Vector<Int>`) вместе со всеми элементами под ним | тип структуры | не нужна: владение значением выражает его тип |
| элемент целиком | `own Nodes.Item` | `public own Nodes` |
| слот или диапазон слотов области | `own Block.data.Item` | `public lend Block.data` |
| заимствование | результат с правом `read`, `edit` или `mut` | не нужна: владение не переходит |
| указатель без права записи | `Items.Item` | не нужна |

Передача слота области во владение получателю называется выдачей слота. Её пишет операция `lend` (раздел 6.6).
Байты при выдаче остаются на месте, а `layout` запоминает только то, что слот занят.

Какой способ выбрать, зависит от того, что `layout` делает с памятью, пока она у внешнего кода:

| Что делает `layout` | Способ |
|---|---|
| не читает и не пишет содержимое | выдача слота: `lend block.slots[k]` |
| хранит в элементе свои поля (`next`, `prev`, счётчики), а отдаёт остальное | поля остаются у `layout`, выдаётся диапазон вложенной области: `lend block.data[a ..< b]` |
| продолжает читать или писать те же байты | заимствование: результат с правом |

Правила строк:

1. Строка `lend` называет область так же, как тип выданного слота: структура и её поле-область. `lend Block.data`
   относится к слотам типа `own Block.data.Item` и `own block.data.Item`, выданным по одному или диапазоном.
2. Тип выданного слота называет область, из которой слот выдан. Когда родитель передан параметром, тип пишется
   через него: `own block.data.Item`. В результате функции, где родитель вызывающему не виден, тип пишется через
   структуру: `own Block.data.Item`.
3. На одно множество и на одну область строка одна.
4. Видимость строки равна самой широкой видимости функций, которым она разрешает отдавать и принимать владение.
   `public own Nodes` покрывает функции `public` и `internal`. `internal own Nodes` покрывает только `internal`.
5. Строка шире модификатора `layout`: у `layout` с видимостью пакета имеет смысл только `public`, у
   `private layout` допустимы `internal` и `public`.
6. Строка `public` стоит в модуле `public module`, и структура множества (`Item`) тоже `public`
   ([видимость](../../visibility.md)).
7. Между функциями кода `layout` владение элементом переходит без строки.

Где внешний код хранит полученное:

1. Элемент `own Nodes.Item` и выданный слот внешний код хранит в локальной переменной, параметре и результате.
2. Дольше одного вызова значение хранится в обобщённом контейнере из `layout` (`Vector<own Nodes.Item>`), который
   стоит в локальной переменной или в поле класса. Деструктор класса вынимает элементы и возвращает каждый функции
   кода `layout`.
3. Множество, которое строка не называет, наружу владением не уходит. Его элементы внешний код читает и правит
   через структуру, которая ими владеет. Граф описывается структурой с цепочкой якорей (пример C), и наружу
   уходит значение этой структуры.

**Пример.** Пример B объявляет `public lend Block.data`. Его функции:

```efen
public fn acquire(pool: mut Pool) -> own Block.data.Item? {
    let block = unlinkFree(pool) ?? return null   // anchor Blocks.Item: первый участок из Pool.free
    let n = block.data.count
    let data = lend block.data[0 ..< n]      // выдан диапазон: все байты области block.data
    block.used += n
    linkBusy(pool, tie block)                // участок привязан к Pool.busy и остаётся у пула
    return data
}

public fn release(pool: mut Pool, data: own Block.data.Item) {
    let block = blockOf(pool, data)          // участок пула pool, из которого выдан data
    let n = block.data.count
    block.data[0 ..< n] = take data          // диапазон вернулся туда, откуда выдан
    block.used -= n
    let cut = unlinkBusy(pool, block)        // anchor Blocks.Item: участок вырезан из Pool.busy
    linkFree(pool, tie cut)                  // used == 0: участок привязан к Pool.free
}

public fn destroy(pool: own Pool) requires pool.busy == null {       // выданных слотов нет: все участки в Pool.free
    while let block = tie pool.free {
        pool.free = tie block.next
        if let next = pool.free { next.prev = null }                 // указатель на block переписан до as own
        mm.free(block as own Pointer)
    }
}
```

`acquire` выдаёт все байты области одним диапазоном (раздел 6.6, правило 6), и `used` считает выданные байты.
Внешний код получает только диапазон, участка у него нет. Поэтому `release` принимает пул и диапазон, а участок
находит вспомогательная функция `blockOf` по адресу диапазона (раздел 6.6, правило 9). Приведение адреса в `blockOf`
называет структуру `pool`. То, что участок принадлежит именно ей, компилятор принимает без доказательства
(раздел 4.5).
`destroy` требует, чтобы выданных слотов не осталось: участок с `used > 0` освободить нельзя (раздел 6.6).

Элемент целиком:

```efen
private layout {
    set Nodes: Node
    public own Nodes                          // узел уходит внешнему коду целиком: хранимых указателей на него нет

    public struct Node  { var next: own Nodes.Item? = null; public var value: Int }
    public struct Queue { var head: own Nodes.Item? = null }
}

public fn newNode(value: Int) -> own Nodes.Item {
    return mm.allocate(bytes: sizeOf(Node)) as Node(value: value)    // next равен null по умолчанию
}

public fn freeNode(node: own Nodes.Item) {
    var rest = take node.next                 // цепочка под узлом; у узла из newNode и pop она пуста
    mm.free(node as Pointer)                  // владеющее поле узла пусто, хранимых указателей на узел нет
    while let next = take rest {
        rest = take next.next
        mm.free(next as Pointer)
    }
}

public fn push(queue: edit Queue, node: own Nodes.Item) {
    if let first = queue.head {
        var last = first                      // невладеющий указатель с источником queue
        while let next = last.next { last = next }
        last.next = take node                 // владеющее поле равно null: запись значения, edit
    } else {
        queue.head = take node
    }
}

public fn pop(queue: mut Queue) -> own Nodes.Item? {
    let node = take queue.head ?? return null // первый узел ушёл из очереди: изменение структуры, mut
    queue.head = take node.next               // остаток цепочки снова под head; node.next равен null
    return node                               // own Nodes.Item переходит к вызывающему
}

public fn clear(queue: mut Queue) {
    while let node = pop(queue) { freeNode(take node) }
}

strategy for Queue {
    implements Disposable

    fn dispose { clear(self) }                // вызывает компилятор, когда значение Queue кончается (раздел 7.4)
}
```

Слово `public` у поля `value` открывает внешнему коду чтение. Пишут поле функции кода `layout` (раздел 2.5).

Внешний код, другой модуль того же пакета, берёт узел, ставит его в очередь, снимает и освобождает:

```efen
fn example {
    var queue = Queue()
    let node = newNode(value: 7)              // own Nodes.Item: узлом владеет переменная node
    let seven = node.value                    // чтение public-поля
    push(queue, take node)                    // узел перешёл в очередь; имя node недействительно
    if let first = pop(queue) {               // own Nodes.Item вернулся внешнему коду
        freeNode(take first)                  // обратный путь; без этой строки ошибка: владелец first потерян
    }
}                                             // конец области: dispose освобождает узлы, оставшиеся в queue
```

Между `newNode` и `push` узлом владеет переменная `node`, между `pop` и `freeNode` переменная `first`. На каждом
выходе внешний код возвращает узел функции кода `layout` или передаёт дальше (раздел 7.4). Полей узла он не пишет и
приведений не делает: освобождает узел только `freeNode`.

**Запрещено.**

- Якорь внешнему коду не выдаётся. `anchor Nodes.Item` в сигнатуре функции, видимой внешнему коду, вызывает ошибку при
  любой строке. Строки `anchor` нет. Функция `protected fn` из `open layout` внешнему коду не видна, и якорь в её
  сигнатуре допустим (раздел 10.4).
- Строка без слова видимости вызывает ошибку. Строка не шире модификатора `layout` тоже ошибка: ей нечего
  разрешать.
- Функция `public`, которая отдаёт `own Nodes.Item` при строке `internal own Nodes`, вызывает ошибку.
- Поле `own Nodes.Item` или `own Block.data.Item` в классе или в обычной структуре вызывает ошибку.
- Сохраняемое замыкание не захватывает `own Nodes.Item`: неявно уничтожить такой захват нельзя. Корутина захватывает его
  владением, как параметр `own` (раздел 9.2).
- Приведения элемента во внешнем коде (`as Pointer`, `as own`, смена вида) вызывают ошибку.
- Внешний код не приводит выданный слот к `Pointer` и не отдаёт его менеджеру памяти: слот возвращается туда,
  откуда выдан. Код `layout` стирает тип выданного слота (`slot as Pointer`), когда отдаёт его через контракт
  [аллокатора](../allocator.md), и восстанавливает тип приведением адреса (раздел 4.5).

**Почему.** Владение, которое получил внешний код, `layout` больше не видит. Строка делает такой выход частью
объявления, и компилятор сверяет с ней каждую функцию (раздел 8.7). Якорь не выдаётся, потому что якорь обещает
найти все указатели на значение, а внешний код этого доказать не может.

Куда дальше: указатели, которые владения не дают, описывает раздел 4.
