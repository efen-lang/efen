## 6. Изменение памяти

Каждая операция над памятью `layout` относится к одному из двух классов. Запись значения не переносит и не
уничтожает ни один элемент и требует `edit`. Изменение структуры уничтожает элемент, выводит его из структуры,
меняет его вид или лишает слот значения и требует `mut`. Раздел опирается на владение (3), источник (4.2) и
инварианты (5): к выходу публичной функции они восстановлены.

<a id="edit-и-mut-в-layout"></a>

### 6.1 edit и mut

**Правило.** `edit` гарантирует, что ни один существующий элемент или слот не перенесён и не уничтожен. `mut`
разрешает всё, что `edit`, и этой гарантии не даёт ([права](../memory-rules.md#права)).

Права внутри `layout` те же, что в языке ([владение](../../types/ownership.md)): `own` и `anchor` дают владение,
`edit` и `mut` заимствуют с правом записи, указатель без права записи только читает.

| Операция | Класс | Право |
|---|---|---|
| чтение поля | чтение | не нужно |
| запись поля-значения, которое ничем не владеет и не имеет случая с данными (`length`, `key`, `state`) | запись значения | `edit` |
| запись целого значения в поле опционального типа или варианта со случаем с данными, когда доказано, что запись не покидает случай с данными (`p = Point(x: 1, y: 2)` в поле `Point?`) | запись значения | `edit` (правило 6) |
| такая же запись, которая может покинуть случай с данными (`p = null`, `n.link = .to(other)` при `link == .slot(k)`) | изменение структуры | `mut` (правило 6) |
| запись невладеющего указателя (`prev`, `parent`, `tail`) | запись значения | `edit` |
| запись в неинициализированный слот области вместе с полями-счётчиками из инварианта (`count`) | запись значения | `edit` |
| запись нового слота в конец области с разным шагом вместе с полем из инварианта о занятой длине (`top`) | запись значения | `edit` |
| новый элемент во владеющее поле, равное `null` (`list.head = tie node`) | запись значения | `edit` |
| `tie` якоря, когда к выходу функции элемент снова принадлежит той же структуре (вставка в начало, вращение дерева, обращение списка) | запись значения | `edit` |
| элемент пришёл в структуру владением (`if let n = pop(a) { pushFirst(b, tie n) }`) | запись значения | `edit` на структуру, в которую он пришёл |
| `tie` якоря, после которого элемент ушёл из структуры: в результат, в другую структуру, в уничтожение | изменение структуры | `mut` на структуру, из которой он ушёл |
| `take` значения `own` из поля, `take` слота области | изменение структуры | `mut` |
| `lend` вместе с полями-счётчиками (`used`, `frontier`, `firstFree`) | изменение структуры | `mut` на родителя: слот ушёл из его структуры владением |
| возврат выданного слота (`block.slots[k] = take slot`) | изменение структуры | `mut` на родителя |
| `as own`, освобождение | изменение структуры | владение элементом: `as own` применяется к значению под `anchor` (раздел 6.5); `mut` на структуру, из которой элемент вырезан |
| смена вида `as` | изменение структуры | `mut` |
| запись поля размера в существующем слоте области с разным шагом (деление, слияние), уменьшение её занятой длины | изменение структуры | `mut`; из вложенных областей затронутых слотов ничего не выдано (раздел 2.6) |
| запись поля раскладки вложенной области (поле `area`), слоты которой имеют один размер (`sizeClass` при `slots.count == PAYLOAD / SIZES[sizeClass]`) | изменение структуры | `mut`; из области ничего не выдано; доказано, что новая раскладка помещается в память элемента; после записи ни один её слот не инициализирован ([условия вида](../pointer.md#условия-вида)). Поле из условия владельца области верхнего уровня (`value.count == capacity`) без замены области не пишется ([область `layout`](../pointer.md#область-layout-area-и-set-area-число-элементов-у-переменной)) |
| перевыделение или замена области: сначала `let old = take table.buckets`, затем `table.buckets = take fresh` | изменение структуры | `mut` на владельца |

Дополнительные правила:

1. Право читается по итогу функции, а не по тексту. Функция с параметром `edit` к каждому своему выходу оставляет
   каждый элемент, который до неё принадлежал структуре этого параметра, в той же структуре, на том же адресе и в
   том же виде. Выход через исключение тоже выход.
2. Между `tie` из структуры и `tie` обратно функция `edit` не вызывает ничего, что может бросить исключение или
   приостановиться.
3. Право на элемент действует и на элементы, достижимые от него по указателям `layout`.
4. Достижимость даёт право писать, но в проверку непересечения не входит. Эта проверка одна и называется `apart`:
   пишущий аргумент (`edit`, `mut`, `out`, `own`, `anchor`) не пересекается ни с одним другим аргументом вызова, если
   сигнатура не объявила отношение «внутри». Как пересечение проверяется в точке вызова и чем кончается недоказанная
   пара (сравнение слотов при вызове со сбоем `OverlapError` или ошибка компиляции), определяет раздел
   [«Совместимость»](../../types/access-regions.md#совместимость), правила 1–6; правило 6 там же задаёт пары с
   указателями `layout`.
5. Реализация вправе делать меньше, чем разрешает право. Таблица с открытой адресацией удаляет запись строкой
   `state = DELETED`. Для компилятора это запись значения, а право `mut` у её `remove` задаёт контракт коллекции.
6. Запись целого значения в слот, тип которого опционален или служит вариантом со случаем с данными, остаётся
   записью значения, когда FLOW доказал, что она не покидает случай с данными: прежнее значение равно `null` или
   случаю без данных, либо новое значение имеет тот же случай, что прежнее, и прежние данные ничем не владеют.
   Иначе запись меняет структуру и требует `mut`: ссылки и псевдонимы внутрь прежних данных после неё
   недействительны (раздел 7.1). Записью значения остаются запись опционального невладеющего указателя (`prev`,
   `tail`), поля-псевдонима и перечисления, случаи которого данных не несут. Владеющее поле пишется по правилу 6
   раздела 6.2.

**Пример.**

```efen
fn rotateRootLeft(tree: edit Tree) {          // edit: все узлы остались в дереве, ни один не перенесён
    let top = tie tree.root ?? return
    guard let pivot = tie top.right else { tree.root = tie top; return }
    top.right = tie pivot.left
    if let l = top.right { l.parent = top }
    top.parent = pivot
    pivot.parent = null
    pivot.left = tie top
    tree.root = tie pivot                     // к выходу каждый узел снова в tree
}
```

**Запрещено.**

- Операция без права, которое называет таблица, вызывает ошибку в своей строке (раздел 8.3).
- Функция, которой нужен случай «оба параметра называют один элемент», разбирает его отдельной веткой: передать
  один элемент в два пишущих параметра нельзя.

**Почему.** Гарантия `edit` позволяет вызывающему сохранить все ссылки и указатели в структуру. Поэтому вставка в
список, вращение дерева и `get` у LRU не делают недействительной ни одну ссылку.

### 6.2 Создание элемента

**Правило.** Элемент создаётся формой с полями, как объект класса: `Node<T>(value: take value)`. Что даёт форма,
решает объявление структуры. Структура из строки `set X: V` или `set area X: V` создаётся как новый элемент
`own X.Item` своего множества; любая другая структура (корень коллекции, структура слота, обычная структура)
создаётся как значение. Память элементу даёт стратегия `Allocator<X.Item>`, выбранная для множества
([аллокатор](../allocator.md)); компилятор вызывает её и приводит память к виду, выделение в коде не пишется.

Путей в множество три:

1. Из аллокатора: форма с полями.
2. Из другого множества этого же `layout`: участок, взятый у ОС, делится на элементы выдачей слота `lend` или
   раздачей `for element in take region` (раздел 6.6).
3. Из сырой памяти (`System.map`, `tryAllocate`, смена вида): приведение `own Pointer` к виду,
   `memory as Block(next: null)`.

Правила формы с полями:

1. Компилятор запрашивает у стратегии `allocate(bytes: sizeOf(V(поля)), aligned: alignOf(V))`. Условие
   `ensures result.size == bytes && result.alignment == aligned` у `allocate` доказывает, что память вмещает вид.
   У структуры, размер которой задаёт инвариант через поле (`invariants { text.count == length }`), такое поле
   среди аргументов — число, константа или неизменяемое имя.
2. Память выделяется до вычисления аргументов. Когда памяти нет, `allocate` бросает `AllocationError`: аргументы
   не вычислены, `take value` не выполнен, и ничего не меняется. Формы, которая вместо исключения даёт `null`,
   нет: код, которому нужен `null`, сам вызывает `tryAllocate` у стратегии и приводит память (путь 3).
3. Форма записывает названные поля. Поле со значением по умолчанию (`var next: anchor Items.Item? = null`)
   получает его.
4. Поле не инициализировано, если оно не имеет значения по умолчанию, не записано в форме и не записано кодом
   после неё. «Не инициализировано» и `null` различаются: `null` считается значением.
5. Инициализатор `_` пишется только явно, у имени поля в форме или в строке приведения. На поле-числе (целом или с
   плавающей точкой) он оставляет байты, которые выдал аллокатор, и при выполнении ничего не делает. На
   опциональном поле (`Items.Item?`, `own Items.Item?`, `anchor Items.Item?`) он записывает `null`.
6. Запись во владеющее поле требует доказательства, что поле равно `null`.
7. Элемент, обязательные указатели которого связывают его с другим новым элементом (пара встречных полурёбер),
   вводится одной операцией вместе с ним.
8. Элемент создаёт только код `layout`: форма записывает поля элемента. Внешний код создаёт значения публичных
   структур (`Queue()`) и получает элементы от функций `layout`.
9. Структура с хвостовой областью без инварианта размера («вся память до конца `Pointer`») формой с полями не
   создаётся: размера у неё нет, пока нет памяти. Её приводят из сырой памяти (путь 3).
10. Область верхнего уровня создаёт её конструктор с числом слотов или байтов, без `.Area`:
    `let fresh = Items<T>(count: next)` даёт `own Items<T>.Area { value.count == next }`,
    `let records = Records(size: bytes)` для области с разным шагом даёт
    `own Records.Area { value.size == bytes }`. Компилятор запрашивает у стратегии `Allocator<Items<T>.Area>`
    `next * sizeOf(Items<T>.Item)` байт с выравниванием `alignOf(Items<T>.Item)`. Как и приведение к области, форма
    стоит только начальным значением переменной, а `count` и `size` — число, константа или неизменяемое имя
    ([область layout](../pointer.md#область-layout-area-и-set-area-число-элементов-у-переменной)). Ни один слот новой
    области не инициализирован (раздел 6.3).

Правила приведения (путь 3): приведение сохраняет право указателя и поглощает `Pointer`; компилятор
доказывает, что размер памяти не меньше вида и выравнивание не меньше `@align` вида; поля записываются по правилам
3-6 выше.

Аллокатор множества один. Компилятор выбирает стратегию `Allocator<X.Item>` один раз на множество, а не на вызов,
и выбранная стратегия входит в тождество типов `layout` ([аллокатор](../allocator.md#один-аллокатор-на-множество)).

Поэтому память элемента возвращается туда, откуда пришла (раздел 6.5). Память ОС тоже множество; его описывает
контракт `System` ([системные вызовы](../system.md#память-ос-как-множество)).

**Пример.**

```efen
fn newNode -> own Items.Item {
    return Item()                                       // память выдал аллокатор множества Items; value не записан
}

fn addVertex(graph: edit Graph, label: Int) -> Vertices.Item {
    let v = Vertex(label: label, neighbors: Vector<Vertices.Item>())     // own Vertices.Item
    v.nextAll = tie graph.first             // поле пусто по умолчанию; прежней первой вершиной владеет v
    graph.first = tie v                     // вершина принадлежит графу
    return graph.first!                     // указатель без владения, источник: graph
}

let a = Item(value: 0)                          // value записан в форме, next и prev равны null по умолчанию
let b = Item(value: _)                          // value сохраняет байты аллокатора, это написано явно

let c = Item()                                  // value не инициализирован
print(c.value)                                  // ошибка: value не инициализирован
c.value = 0
print(c.value)                                  // можно
```

**Запрещено.**

- Чтение неинициализированного поля вызывает ошибку компиляции.
- Перезапись владеющего поля со значением вызывает ошибку.
- `_` на неопциональном указателе, поле `own` или `anchor`, логическом поле, варианте и поле типа-параметра `T`
  вызывает ошибку: такое поле записывается явно. Записи «остальные поля оставить как есть» нет.
- Возврат нового элемента через результат без права (`-> Items.Item`), пока элемент не записан во владеющее поле,
  вызывает ошибку «владелец потерян».

**Почему.** Размер и выравнивание вида знает компилятор, поэтому их не пишут руками. Аллокатор множества один и
входит в его тип, поэтому FLOW знает происхождение памяти каждого элемента и проверяет, что она вернётся туда же.
Обычный путь состоит в записи полей в форме или кодом после неё. `_` нужен для поля, байты которого программе не
важны.

Куда дальше: слоты области, которые ещё не получили значения, описывает раздел 6.3.

### 6.3 Слоты области

**Правило.** Какие слоты области инициализированы, называет инвариант владельца через призрачное имя
`x.extent` ([имена области](declaration.md#область-с-разным-шагом)): слоты в байтах `0 ..< x.extent` хранят значение,
остальные не инициализированы. У вектора это `items == null || items!.extent == count * sizeOf(T)`. FLOW доказывает
такой инвариант, как любой: он верен на входе и выходе публичной функции, а вызовы передают его через сводки
(раздел 5.1). План освобождения его не читает (раздел 7.4).

Дополнительные правила:

1. Указатель `Items.Area` не хранит ни числа занятых слотов, ни таблицы инициализации.
2. `take` слота области ничего не делает с памятью. Он объявляет, что значения по этому адресу больше нет, и
   требует `mut`. После `take` слот не инициализирован: запись в него его инициализирует. Так же действует `take`
   слота типа `T?`: `null` в него не записывается. Код, которому нужен `null` в слоте, пишет
   `replace(x[k], null)`.
3. `take` слота меняет структуру. Хранимые указатели `layout` на слот переписаны до `take`.
4. К выходу публичной функции неинициализированный слот по инварианту владельца не входит в занятые. Запись в
   слот, который начинается в `x.extent`, вместе с увеличением поля из инварианта сдвигает `x.extent` на размер
   слота; `take` последнего занятого слота вместе с уменьшением поля сдвигает его назад. Поэтому функция, которая
   увеличивает `count` без записи слота, вызывает ошибку у своего выхода.
5. Переноса как отдельной операции нет. Значение переносит код: `take` из старого слота и запись в новый.
6. Область заполняют по одному слоту одним из двух способов. Первый: код записывает поля владельца (`items`,
   `capacity`, `count = 0`) до первой операции, способной бросить исключение, и увеличивает `count` после каждой
   записи; исключение оставляет владельца с верными инвариантами, и заполненные слоты освобождает его `dispose`.
   Второй: код заполняет локальную область и записывает её во владельца после последней записи (`fill` у
   [массива фиксированной длины](../layout-examples/contiguous-array.md)).
7. Локальная область, которую исключение застало до записи во владельца, кончается как любое значение: компилятор
   вызывает её деструктор. Деструктор уничтожает слоты, которые FLOW в этой точке доказал инициализированными (у
   цикла со счётчиком `0 ..< i`), и возвращает память. Внутри функции FLOW знает состояние каждого слота, поэтому
   инвариант владельца для этого не читается (раздел 7.4, локальный владелец, правило 1).
8. У коллекции из нескольких областей ([массив из участков](../layout-examples/chunked-array.md)) каждый участок
   хранит свою область и свой `count`. Уничтожение сначала освобождает префикс каждого участка, затем каталог.
9. В области с разным шагом слотами заняты байты `0 ..< x.extent`, и эту длину называет инвариант владельца
   (`records.extent == top`). `take` слота целиком к такой области не применяется (раздел 2.6).

**Пример.**

```efen
strategy<T> for Vector<T> {
    public mut fn removeLast -> own T? {
        guard count > 0 else { return null }
        count -= 1
        return take items![count]        // слот вне 0 ..< count: не инициализирован
    }
}
```

**Запрещено.** Чтение неинициализированного слота вызывает ошибку. Использование ссылки или указателя на слот
после его `take` вызывает ошибку.

**Почему.** Область не хранит сведений о своих слотах, поэтому единственным источником этих сведений между
вызовами остаётся инвариант. Локальную область освобождает её деструктор (правило 7); область во владельце
освобождает его `dispose`.

Куда дальше: перенос владения существующим элементом описывает раздел 6.4.

### 6.4 Перенос владения

**Правило.** Якорь переносит `tie`, значение `own` переносит `take`. В каждый момент у значения один владелец.

Дополнительные правила:

1. При `tie` получатель привязывает значение к себе, и прежний слот им больше не владеет. После `let held = tie node`
   имя `node` остаётся невладеющим указателем, и его источником служит структура под `held`. Владеющее поле и слот
   области типа `anchor Items.Item?` после `tie` из них равны `null`; `take` слота области действует иначе
   (раздел 6.3, правило 2). Локальная переменная или параметр после `t.f = tie node` остаётся невладеющим
   указателем на элемент, и источником указателя служит структура, в которую элемент записан: `list.tail = node`
   допустима. Тот же источник получают локальные указатели функции на этот элемент и на всё, чем он владеет
   (раздел 7.2, правило 5). Когда поле `t.f` достигнуто через указатель-параметр без источника в типе
   (`b: edit Items.Item`), имя получает статус этого параметра: оно может принадлежать любой структуре своего
   множества (раздел 4.2, правило 3). Когда элемент ушёл в вызов, источник определяет раздел 7.2, правила 5 и 6.
   После `take` имя недействительно.
2. Внутри одной структуры указатели на значение при `tie` остаются действительными: меняется только точка
   уничтожения. При уходе в другую структуру действует раздел 7.1.
3. Во владеющее поле `own` значение записывается через `take`, в поле `anchor` через `tie`. Значение `own` через
   `tie` записывается в поле `anchor` и становится якорем: на него ещё ничто не указывает.
4. `take` берёт значение из опционального поля, из слота области и из неопционального поля корня, который один
   владеет значением: параметра `mut` или `own` и локального владельца (`let value = take node.value`). Пока
   такое поле пусто, действует правило [явного извлечения](../../types/ownership.md#явное-извлечение).
5. Запись якоря `t.f = tie r`, в том числе в слот области, принимается, когда поле `t.f` доказанно равно `null` и
   доказано, что `t` не входит в дерево `r`: в `r` и во всё, чем `r` владеет. К строке записи `r` находится под
   локальным владельцем и вместе со своим деревом составляет отдельную структуру (раздел 4.3, правило 4), а
   элемент принадлежит ровно одной структуре (раздел 3.3). Поэтому достаточно доказать, что `t` принадлежит другой
   структуре. Это даёт один из трёх фактов:

   а) `t` сам служит владельцем: локальная переменная или параметр `anchor` либо `own`, которые в этой строке
      владеют своим значением, и это не `r`. Два владельца владеют разными деревьями.

   б) `t` служит полем корня (`list.head = tie node`) или действительным указателем с источником `list`, где
      `list` называет параметр-структуру, `one` или другого локального владельца, и ни одна часть дерева `r` в этой
      функции структуре `list` не принадлежала: `r` получен приведением памяти, результатом вызова или параметром
      `anchor`.

   в) `t` служит полем корня или указателем с источником `list`, часть дерева `r` в этой функции отделена от
      `list`, и каждое такое отделение `tie u.g` элемент `t` не затронуло. Отделение не затрагивает: корень
      `list`; сам элемент `u`; элемент, о котором известен путь владения от корня `list`, действительный к строке
      отделения и не проходящий через поле `u.g` (предок `u`, соседнее поддерево, всё, что прочитано от корня по
      владеющим полям после отделения). Указатель, прочитанный через невладеющее поле (`tail`, `prev`, `parent`)
      или полученный результатом вызова, пути владения не имеет.

   Указатель с источником `list`, о котором факт «в» не доказан, после отделения может указывать и в `list`, и в
   отделённое дерево. Изменение структуры любой из двух делает его недействительным, а запись якоря этого дерева в
   его поле вызывает ошибку. Указатель-параметр без источника в типе может принадлежать любой структуре своего
   множества (раздел 4.2, правило 3), в том числе дереву параметра `anchor`, поэтому для него ни один факт не
   доказан. Факты пересчитываются после каждой записи: `t.f = tie r` переносит дерево `r` в структуру `t`. Когда
   ни один факт не доказан, FLOW выводит предусловие, если оно записывается через поля, которые читает
   вызывающий. Иначе запись вызывает ошибку.
6. Элемент переходит между структурами одной операцией: `mut` для структуры, из которой он уходит, `edit` для
   структуры, в которую приходит.

**Пример.**

```efen
fn pushFirst(list: edit List, node: anchor Items.Item) requires node.next == null {
    node.next = tie list.head                // факт «а»: node владеет собой; поле пусто по requires
    if let second = node.next { second.prev = node }
    list.head = tie node                     // факт «в»: head служит полем корня; узел принадлежит списку
    if list.tail == null { list.tail = list.head }
    list.length += 1
}
```

**Запрещено.**

- `take` слота под якорем вызывает ошибку.
- `tie` из поля, якоря которого у функции нет, вызывает ошибку. Из параметра `top: edit Nodes.Item` нельзя
  написать `pivot.left = tie top`: якорь `top` находится у вызывающего.
- Запись якоря, для которой не доказан ни один факт правила 5 и предусловие не выведено, вызывает ошибку.
- `tie` и `take` невладеющего указателя владения не дают.

**Почему.** Цикл якорей не имеет владельца с момента замыкания, и в общем случае его отсутствие требует
достижимости, которую локально не доказать. Поэтому цикл строится из указателей под инвариантом, а не из якорей
([доказательство структур](../layout-proofs.md#произвольный-граф-вершинами-владеет-структура)).

Куда дальше: уничтожение элемента описывает раздел 6.5.

<a id="переход-к-владению-as-own"></a>

### 6.5 Удаление элемента

**Правило.** Память, на которую указывают несколько указателей, освобождается только после перехода к `own`:
`v as own Items.Item`. К этой точке код уже нашёл все указатели на элемент и переписал или уничтожил их.

Дополнительные правила:

1. Компилятор проверяет это по инвариантам и объявлениям `layout` и выдаёт право `own`.
2. `as own` применяется к значению под `anchor`: параметру, локальной переменной или значению, которое функция
   забрала из поля. Невладеющий указатель владения не даёт, с любым правом.
3. К точке `as own` владеющие поля элемента (`own` и якоря) равны `null`: их освобождает явный код раньше, кроме
   поля, элемент которого не может снова владеть элементом своего множества. Поля-значения элемента, в том числе
   структуру из `layout`, уничтожает конец значения (раздел 7.4, локальный владелец, правило 1).
4. Функция, которая владеет элементом через `own` или `anchor`, может забрать `take` его поля-значения перед
   освобождением (`let value = take node.value`). После этого элемент только освобождается. Забранное значение
   структуры из `layout` (`let neighbors = take cut.neighbors`) освобождает компилятор в конце области видимости
   (раздел 7.4). У слота области с
   разным шагом, который удаляет запись поля размера или уменьшение занятой длины, так же действует функция с
   правом `mut` на владельца области (раздел 2.6, правило 6).
5. Стирание вида `x as Pointer` даёт `own Pointer` той же памяти: вида больше нет, память существует и передаётся
   дальше. Размер, с которым память брали, FLOW помнит как факт о значении.
6. Значение `own X.Item`, жизнь которого кончилась, освобождает компилятор; вызова не пишут. Что он уничтожает и
   что должно быть доказано к этой точке, задаёт раздел 7.4 (локальный владелец, правило 1).

**Пример.**

```efen
fn removeVertex(graph: mut Graph, v: read<graph> Vertices.Item) {
    var w = graph.first
    while let x = w {                       // цепочка графа называет каждую его вершину
        x.neighbors.removeAll(where: (n) => n == v)
        removeEdges(from: x, to: v)         // рёбра x с to == v вынуты из цепочки и освобождены
        w = x.nextAll
    }
    let cut = unlinkVertex(graph, v)        // anchor Vertices.Item: вершина вырезана из цепочки графа
    freeEdges(cut)                          // владеющее поле firstEdge равно null
    let neighbors = take cut.neighbors      // вектор забран из вершины
    let dead = cut as own Vertices.Item     // доказано: указателей на вершину нет, владеющие поля равны null
}                                           // конец области: вершина и вектор neighbors возвращают память
```

Полноту обхода дают два факта. По инварианту `Graph` из [примера C](declaration.md#2-объявление) каждая вершина графа
входит в цепочку от `graph.first`. По правилу чистоты (раздел 4.3) указатель на вершину хранится только внутри того же
графа. Запись `read<graph>` у параметра `v` требует вершину именно этого графа (раздел 4.1, правило 4).

Параметр `v` только называет вершину. Право писать в вершины и освободить `v` даёт параметр `graph: mut Graph`
(раздел 8.2). Инвариант цикла «в пройденных вершинах указателей на `v` нет» опирается на условие результата
`removeAll(where:)`: после вызова ни один элемент вектора условию не удовлетворяет
([поиск всех держателей](../layout-algorithm.md#владение-лесом-и-поиск-всех-держателей)).

Между `unlinkVertex` и `as own` вершина `cut` находится под локальным якорем и нечиста: её `neighbors` и рёбра
ещё указывают на вершины графа. Это допустимо: нового владельца вершина не получает, функция её освобождает
(раздел 4.3, правило 5).

**Запрещено.**

- `as own` без доказательства вызывает ошибку.
- `as own` невладеющего указателя вызывает ошибку: указатель `mut` владения не даёт. Элемент, которым владеет
  внешний код, освобождает только функция, принявшая его как `own Nodes.Item`.
- Приведения элемента (`as own`, `as Pointer`, смена вида) пишет только код `layout`.

**Почему.** Якорь превращается в исключительное владение только в `as own`. Поэтому доказательство того, что
указателей на элемент нет, требуется в одном месте: в функции, которая элемент освобождает.

Куда дальше: выдачу и возврат слотов описывает раздел 6.6.

<a id="выдача-и-возврат"></a>

### 6.6 Выдача и возврат слота

**Правило.** `lend` выдаёт слот во владение получателю, `take` в тот же слот возвращает его. Пока слот выдан,
родителя нельзя вернуть; исключение даёт правило 8.

Правила:

1. `lend block.slots[k]` выдаёт слот `k`: получатель владеет значением `own block.slots.Item`. Байты не
   переносятся, `k` входит в `slots.taken`.
2. `block.slots[k] = take slot` возвращает слот, `k` выходит из `slots.taken`.
3. Поля выданного слота через родителя не читаются и не пишутся: памятью владеет получатель.
4. На каждом выходе функции изменение `used` равно числу выданных слотов минус число возвращённых.
5. Первый `lend` делает владение родителем неисключительным: значение `own` становится якорем (`anchor`), и дальше
   его переносит `tie`. Родитель с выданными слотами остаётся у своего владельца. Если к выходу функции слот не
   возвращён, родитель записан в цепочку якорей (`linkBusy(pool, tie block)` в разделе 3.5). Право `own`
   возвращает приведение `as own` (раздел 6.5). Оно доказано, когда вернулись все слоты (`used == 0`) или каждый
   невозвращённый слот подпадает под правило 8, а родитель вырезан из цепочки и указатели на него в ней
   переписаны. Функция, которая вернула последний слот, оставляет родителя под якорем (`linkFree` в разделе 3.5)
   или приводит его к `own`.
6. Диапазон выдаётся так же: `lend block.bytes[a ..< b]`, и возвращается тем же диапазоном.
7. Раздача `for element in take region` передаёт каждый элемент телу цикла, и тело передаёт его дальше.
8. Возврат родителя меняет структуру так же, как возврат элемента, только уходит вся его память. Слот, у
   которого все владельцы и указатели находятся в памяти самого родителя, уходит вместе с ним.
9. Родителя для возврата находит код. Основная форма: родителя передаёт вызывающий, и тип связывает его со слотом
   (`releaseSlot(block: mut SlotBlock, slot: own block.slots.Item)`). Внешний код родителя не получает, поэтому
   функция, которая принимает слот от него, вычисляет родителя по адресу слота (`release` в разделе 3.5). Такое
   вычисление пишется строкой кода с приведением адреса. Приведение называет структуру, которой принадлежит
   родитель, и эту принадлежность компилятор принимает без доказательства (раздел 4.5).
10. В области с разным шагом выдаётся только вложенная область слота: `lend page.records[k].text[a ..< b]`. Слот
    целиком не выдаётся и не забирается, поэтому поле размера остаётся у `layout` (раздел 2.6).

**Пример.**

```efen
fn reuse(block: own SlotBlock) {
    let a = lend block.slots[0]         // после первой выдачи block имеет тип anchor SlotBlock
    let b = lend block.slots[1]
    block.slots[0] = take a             // слот 0 вернулся
    freeBlock(block as own SlotBlock)   // ошибка: слот 1 выдан, used == 1
}
```

**Запрещено.**

- Выдать выданный слот нельзя. Вернуть слот можно только в свой слот.
- `break`, `continue` и `return` в теле раздачи вызывают ошибку. Элемент, оставленный телом, считается утечкой.
- Вернуть или освободить родителя, пока его слот выдан, нельзя. Исключение составляет слот из правила 8.

**Почему.** Выданный слот и родитель не пересекаются по байтам, поэтому получатель владеет слотом исключительно,
а `layout` продолжает работать со своими полями. Счёт `used` связывает их время жизни.

### 6.7 Смена вида и замена области

**Правило.** Смена вида пишется приведением `as` и требует `mut`. Замена области пишется записью нового значения
в поле владельца и требует `mut` на владельца.

**Пример.**

```efen
let spare = block as SlotBlock(slots: Slot(size: SIZES[index]))     // тот же участок памяти в другом виде

fn grow(table: mut Table) {
    var fresh = newBuckets(count: 2 * BUCKETS)
    // записи переходят из старых корзин в новые операцией tie
    freeBuckets(take table.buckets)          // все слоты старой области равны null
    table.buckets = take fresh
}
```

Правила инициализации полей нового вида те же, что при создании (раздел 6.2). После смены вида ни одно поле не
сохраняет значение неявно, в том числе поля общего первого поля видов (`Header`): каждое поле нового вида записано в
приведении, кодом после него или инициализатором `_`. Аргумент `slots: Slot(size: SIZES[index])` задаёт раскладку
области: особый параметр `size` называет полный размер одного слота, а число слотов компилятор выводит из размера
памяти ([сырая память](../pointer.md#поле-area-и-параметр-size)). У области с разным шагом параметра `size` нет: размер
слота задаёт его собственный инвариант (раздел 2.6).

Формы роста области на месте нет. Область растёт заменой: код берёт новую область, переносит значения и
освобождает прежнюю. Рост требует `mut` на владельца, и после него ссылки и указатели внутрь прежней области
недействительны (раздел 7.1), в том числе когда менеджер памяти расширил память на месте
([аллокатор](../allocator.md), `extend`).

**Запрещено.** Освободить область, пока её слоты хранят якоря существующих элементов, нельзя (раздел 3.1).

**Почему.** Смена вида меняет то, какие поля есть у элемента и какие инварианты о нём верны. Указатель прежнего
вида после неё описывал бы память неверно.
