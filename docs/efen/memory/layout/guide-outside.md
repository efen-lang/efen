## Что уходит наружу

Внешним называется код, которому `layout` не разрешает писать поля. Память `layout` он получает пятью
способами. Два из них `layout` объявляет строкой [схемы владения](owners.md#схема-владения).

| Что получает внешний код | Запись | Строка в `layout` |
|---|---|---|
| значение структуры (`List<Int>`, `Graph`) | тип структуры | не нужна |
| элемент целиком | `own Nodes.Item` | `public own Nodes` |
| слот области | `own Block.data.Item` | `public lend Block.data` |
| заимствование | `-> read T?`, `-> edit<list> T?` | не нужна |
| указатель без права записи | `Nodes.Item` | не нужна |

### Значение структуры

Значение структуры ведёт себя как обычное значение: его хранят в переменной, передают параметром `own`, записывают
в поле класса. Вместе со значением переходят все элементы, которыми оно владеет. Структура, память которой план не
обходит ([ничего не теряется](lifetime.md#74-ничего-не-теряется), правило 2 о значении структуры), имеет `dispose`
или функцию той же видимости, которая оставляет её владеющие поля равными `null`. Без них компилятор отвергает
объявление структуры.

### Элемент целиком: `public own Nodes`

```efen
private layout {
    set Nodes: Node

    public own Nodes

    public struct Node  { var next: own Nodes.Item? = null; public var value: Int }
    public struct Queue { var head: own Nodes.Item? = null }
}

public fn newNode(value: Int) -> own Nodes.Item {
    return Node(value: value)
}

public fn pop(queue: mut Queue) -> own Nodes.Item? {
    let node = take queue.head ?? return null
    queue.head = take node.next
    return node
}
```

В строке `public own Nodes` имя `Nodes` называет множество узлов. Функции `push(queue:node:)` и `freeNode(node:)`
принимают узел обратно; их тела и `dispose` очереди приведены в справочнике
([что уходит наружу](owners.md#выдача-наружу)). Внешний код берёт узел, ставит его в очередь, снимает и
освобождает:

```efen
fn example {
    var queue = Queue()
    let node = newNode(value: 7)        // own Nodes.Item: узлом владеет переменная node
    push(queue, take node)              // узел перешёл в очередь
    if let first = pop(queue) {         // узел вернулся внешнему коду
        freeNode(take first)            // без этой строки ошибка: владелец first потерян
    }
}
```

Строка `public own Nodes` разрешает публичным функциям отдавать и принимать `own Nodes.Item`. Без неё
`own Nodes.Item` в сигнатуре функции, видимой внешнему коду, даёт ошибку в этой позиции. Строка требует обратного
пути: функции той же видимости, которая принимает элемент и уничтожает его или оставляет в структуре (`freeNode`,
`push`).

Внешний код хранит элемент в локальной переменной, параметре и результате. На каждом выходе он возвращает элемент
функции из модуля `layout` или передаёт дальше. Поле `own Nodes.Item` в классе или обычной структуре запрещено.
Дольше одного вызова элемент хранится в контейнере `layout`, например в `Vector<own Nodes.Item>`.

### Выданный слот: `public lend Block.data`

```efen
layout {
    set area Blocks: Block

    public lend Block.data

    struct Block {
        var next: anchor Blocks.Item? = null     // поля участка остаются у layout
        var prev: Blocks.Item? = null
        var used: Int = 0                        // число выданных слотов
        area data: Byte                          // память для внешнего кода
    }

    public struct Pool {
        var busy: anchor Blocks.Item? = null     // участки с выданным слотом
        var free: anchor Blocks.Item? = null     // участки без выданных слотов
    }
}

public fn acquire(pool: mut Pool) -> own Block.data.Item? {
    let block = unlinkFree(pool) ?? return null  // первый участок из Pool.free
    let n = block.data.count
    let data = lend block.data[0 ..< n]          // выдан диапазон: все байты области data
    block.used += n
    linkBusy(pool, tie block)                    // участок привязан к Pool.busy и остаётся у пула
    return data
}

public fn release(pool: mut Pool, data: own Block.data.Item) {
    let block = blockOf(pool, data)              // участок пула pool, из которого выдан data
    let n = block.data.count
    block.data[0 ..< n] = take data              // диапазон вернулся туда, откуда выдан
    block.used -= n
    let cut = unlinkBusy(pool, block)            // участок вырезан из Pool.busy
    linkFree(pool, tie cut)                      // и привязан к Pool.free
}
```

Участками владеет `Pool`: строка `public lend` относится к слотам области `data` и владельцем множества `Blocks` не
служит.

`lend block.data[0 ..< n]` выдаёт диапазон слотов области. Получатель владеет байтами диапазона, а поля участка
(`next`) остаются у `layout` и занимают другие байты. Тип слота называет область, из которой он выдан, поэтому
вернуть его можно только в свой слот. Внешний код не приводит его к `Pointer` и не отдаёт менеджеру памяти. Пока
слот выдан, участок нельзя вернуть или освободить. Выдача и возврат требуют `mut` на участок.

### Заимствование с источником

```efen
strategy<T> for List<T> {
    public fn first -> read T? {
        let node = head ?? return null
        return &read node.value
    }
}

fn firstOf<T>(list: List<T>) -> read<list> T? {
    let node = list.head ?? return null
    return &read node.value
}
```

Заимствование даёт доступ к памяти, которой `layout` продолжает пользоваться; владение не переходит. Источник
записан в результате. В методе источником служит `self`, и он не пишется (`-> read T?`). В свободной функции
источник стоит в угловых скобках (`-> read<list> T?`).

Заимствование действует, пока источник не изменил структуру. Вызов `edit` его не затрагивает. Использовать его
после вызова, который освобождает или уводит узлы, нельзя
([что делает ссылку недействительной](../memory-rules.md#что-делает-ссылку-недействительной)). Форма с `&`,
`-> read<&doc.title> T`, обещает ссылку ровно на слот по пути, и путь в ней не проходит через указатель `layout`
([ссылка ровно на слот](../../types/ownership.md#ссылка-ровно-на-слот)). Дольше одного вызова указатель на элемент вне
`layout` хранит только значение, которое заимствует: структура с параметром источника (курсор) или коллекция с
источником в типе элемента (`Vector<read<g> Vertices.Item>`, путь по графу)
([указатели вне `layout`](pointers.md#указатели-вне-layout)).

### Якорь наружу не уходит

`anchor Nodes.Item` в сигнатуре функции, видимой внешнему коду, запрещён при любой схеме владения. Якорь означает, что на
элемент указывают хранимые указатели, и перед уничтожением элемента каждый из них нужно переписать. Хранятся они в
полях `layout`, а писать эти поля внешний код не может. Поэтому якорь переходит только между функциями, которым
`layout` разрешает писать поля. Чтобы отдать элемент внешнему коду, такая функция сначала убирает
указатели на него и делает переход `as own`. Внешний код получает `own`, на который никто не указывает.

## Частые ошибки

Текст диагностики в первом примере взят из справочника
([диагностика времени жизни](../layout-algorithm.md#диагностика-времени-жизни)). В остальных примерах комментарий
пересказывает правило, а точный текст задаёт реализация. Примеры 1, 3–7 показывают код модуля, в котором стоит
`layout`, пример 2 показывает внешний код.

**1. Указатель использован после освобождения узла.**

```efen
fn broken(list: mut List<Int>) {
    let node = list.head ?? return               // указатель с источником list
    let dropped = list.popFirst()                // освобождает первый узел
    print(node.value)                            // error[flow.slot-left]: указатель `node` использован после конца времени жизни узла
}
```

Если `node` после `popFirst` не используется, ошибки нет.

**2. Выход из области со списком, который неявно не освобождается.**

```efen
fn build(worker: own Thread) {   // Thread уничтожает только явный вызов
    var list = List<Thread>()
    list.pushFirst(take worker)
}                                // ошибка: List<Thread> неявно не освобождается, а head может быть не null
```

Исправление: снять каждое значение через `popFirst` и уничтожить его явным вызовом. `List<Int>` в том же коде
освобождает `dispose`.

**3. Чтение поля до инициализации.**

```efen
let node = Node<Int>()           // next получил значение по умолчанию, value не записан
print(node.value)                // ошибка: value не инициализирован
```

**4. Указатель из одного списка записан в другой.**

```efen
fn share(a: edit DoublyList<Int>, b: DoublyList<Int>) {
    a.tail = b.head              // ошибка: хранимый указатель списка a указывает на узел списка b
}
```

Узел переходит между структурами только владением: `tie` из одной и `tie` в другую.

**5. Наружу отдано то, чего не называет ни одна строка.**

```efen
public fn popNode(list: mut List<Int>) -> own Nodes<Int>.Item? {      // ошибка: нет строки `public own Nodes`
    // тело не важно для примера
}
public fn peekNode(list: mut List<Int>) -> anchor Nodes<Int>.Item? {  // ошибка: якорь внешнему коду не выдаётся
    // тело не важно для примера
}
```

**6. Изменение структуры под `edit`.**

```efen
strategy<T> for List<T> {
    public edit fn dropFirst {       // ошибка: узел ушёл из списка в уничтожение, нужен mut
        let node = tie head ?? return
        head = tie node.next
        count -= 1
        let dead = node as own Nodes<T>.Item
    }
}
```

**7. `take` якоря и запись в непустое владеющее поле.**

```efen
let first = take list.head       // ошибка: take слота под якорем; якорь переносит tie
list.head = tie node             // ошибка: поле head не доказано пустым, прежний первый узел потерял бы владельца
```
