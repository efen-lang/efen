# Дефекты адресной модели

> Найдено 2026-09-04 двумя атакующими проходами по
> [Адресам и структурам данных](addresses.md) и четырём примерам. Ничего из
> перечисленного не исправлено; у каждого пункта есть предлагаемое решение,
> которое ждёт обсуждения.

Речь только о **первом ярусе** — о целостности ссылок, которую модель обещает
всегда и бесплатно: ссылка происходит из объявленного населения, блок жив пока
в населении, индекс не выходит за вместилище, владеющая ссылка одна,
населения разных экземпляров не смешиваются. Неверная форма структуры,
незавершающийся обход и потерянный блок сюда не входят: они ошибки программиста,
и память при них цела.

## Два корня

**К1. Изъятие принимает заимствование.** `Nodes.take(node)` объявлено с `read`, а
заимствований может быть сколько угодно и они ничем не потребляются. Отсюда Д1,
Д2, Д9 и половина Д13. Обещание «владеющая ссылка одна» из типов не следует
вовсе — оно держится на договорённости внутри примеров.

**К2. Предикат населения необязателен.** `set Entries: Entry` без скобок законен,
и тогда ничто не связывает изъятый блок со ссылками, которые его называют.

## Пробои, от самого случайного к самому нарочитому

### Д1. Двойное изъятие по заимствованию

```efen
fn dropTwice(node: read Nodes.pointer) {
    Nodes.remove(node)
    Nodes.remove(node)      // заимствование не потреблено, отвергать нечем
}
```

Ломает: владеющая ссылка одна; блок жив пока в населении.
Не хватает: изъятие обязано потреблять владеющую ссылку — `Nodes.take(cell.take())`.

### Д2. Изъятие во время обхода

```efen
for e in buckets[i] along next {
    remove(e.key)           // блок покидает население
    echo e.hash             // e повисла
}
```

Ломает: блок жив пока в населении.
Не хватает: обход держит `read`-заимствование населения, а `create` и `take`
требуют `write`; удаление по ходу — только через форму из Р3.

### Д3. Ячейка переживает замену вместилища

```efen
var cell = buckets[bucketOf(h)].slot
resize(capacity: (mask + 1) * 2)     // buckets = [...], старый массив мёртв
cell.target = fresh                  // запись через освобождённый массив
```

Ломает: блок жив пока в населении (здесь — массив, а не блок).
Не хватает: ячейка обесценивается любой записью в её вместилище и не переживает
вызов другой операции того же layout. Нынешнее правило говорит «пока держатель в
населении», а держатель ячейки массива — поле, а не блок.

### Д4. Экземпляр layout умирает или копируется под живой ссылкой

```efen
for node in l.head along next {
    l = IntList()           // источник и население умирают
    echo node.value         // чтение блока, чьей арены нет
}

var b = snapshot(a)         // экземпляр передан по значению
b.removeFirst(1)            // блок ушёл из населения b
echo a.contains(1)          // a им всё ещё владеет
```

Ломает: блок жив пока в населении; населения разных экземпляров не смешиваются.
Не хватает: экземпляр только перемещаемый; перемещение запрещено при живом
заимствовании в его население; выбранная компилятором форма ссылки объявлена
устойчивой к перемещению экземпляра.

### Д5. Хранимый индекс после уменьшения вместилища

```efen
var home: buckets.index     // хранимая форма, документ её показывает

mask = (mask + 1) / 2 - 1
buckets = [own Entries.pointer?](size: mask + 1)
buckets[e.home] = e         // home выведен против большего массива
```

Ломает: индекс не выходит за вместилище.
Не хватает: `buckets.index` не называет версию вместилища, а `buckets = …` —
обычное присваивание. В примере спасает выводимость `home`, но это свойство
примера, а не правило.

### Д6. Хранимое заимствование переживает свой блок

```efen
var favourite: read Nodes.pointer?
favourite = node
Nodes.remove(node)          // favourite повисла, никто не проверил
```

Ломает: блок жив пока в населении.
Не хватает: дисциплины обесценивания у хранимых `read`. Поколение даётся только
`weak`, значит у `read` устаревание необнаружимо.

### Д7. Обобщение стирает экземпляр

```efen
fn largest<S: set of Entry>(a: S.pointer, b: S.pointer) -> S.pointer

largest(mapA.someEntry, mapB.someEntry)     // один S, два разных населения
```

Ломает: населения разных экземпляров не смешиваются.
Не хватает: у `S` нет значимого якоря. Зависимость от экземпляра в документе есть
только для значимого параметра — `fn probe(m: HashMap, i: m.buckets.index)`.

### Д8. Обратная связь кратной связи без различителя

```efen
inverse parent of {left, right}

var cell = up == null ? root.slot : up.left.slot   // какая сторона? parent молчит
cell.target = node.left                            // перезаписана не та
```

Ломает: владеющая ссылка одна.
Не хватает: различителя в обратном поле либо доступа к ячейке владельца с детской
стороны (`node.parentSlot`).

### Д9. Две ячейки на одно место

```efen
var ca = buckets[bucketOf(a.hash())].slot
var cb = buckets[bucketOf(b.hash())].slot   // при совпадении корзин — одна ячейка

Entries.remove(read ca.target)
Entries.remove(read cb.target)              // один блок изъят дважды
```

Ломает: владеющая ссылка одна.
Не хватает: того же, что в К1. Пока изъятие не потребляет владельца, требовать
различимости двух выводов бесполезно — их равенство законно по построению.

### Д10. Чужой код внутри операции

`hash-map.efen` зовёт `e.key == key` и `key.hash()`, пока жив курсор. Повторный
вход в `insert` из сравнения вызывает `resize`, и массив под курсором
освобождается.

Ломает: блок жив пока в населении.
Не хватает: слова для чистоты. `Hashable` в документах не объявлен, синтаксиса
чистоты нет, поэтому и предикат `hash == key.hash()` недоказуем.

### Д11. Рекурсивный layout

```efen
layout Forest {
    set Trees: Tree
    struct Tree {
        var sub:  Forest                    // вложенный экземпляр того же типа
        var link: own other Trees.pointer?  // Trees — объемлющий экземпляр
    }
    fn graft(a: read Trees.pointer, b: read Trees.pointer) {
        a.link = b.sub.root                 // обе стороны пишутся одним типом
    }
}
```

Ломает: происхождение ссылки; населения разных экземпляров не смешиваются.
Не хватает: доступ `x.f`, чей объявленный тип называет член layout, обязан
перепривязываться к `x`, и синтаксиса такой привязки нет.

### Д12. Возврат из `raw`

```efen
let p: raw Node = forget(b.head)    // «забыть население бесплатно»
a.adopt(p)                          // блок b стал членом населения a
```

Ломает: происхождение ссылки; населения не смешиваются.
Не хватает: у приёма нет ни имени операции, ни предмета проверки; у забывания нет
ограничений. Проверкой диапазона адресов дело не поправить — источник
переиспользует память. Правильный ход: запретить `forget` для ссылки живого
населения.

### Д13. `weak` и переиспользование места

```efen
Entries.remove(e)                   // место свободно
last = Entries.create(value: 7)     // источник вправе выдать то же место
return pinned.value                 // pinned смотрит на новый блок
```

Помечено как держащееся на умолчании: где живёт парное поколение и кто его
двигает, документ не говорит. Не хватает двух фраз: `create` двигает поколение
выдаваемого места, и поколение хранится при месте у источника, а не в ссылке.

### Д14. Позиционное значение переживает замену вместилища через вызов

```efen
fn insert(key: Key, value: Value) {
    let i = bucketOf(key.hash())      // buckets.index против нынешнего массива

    compact()                         // соседняя операция: buckets = [...](меньший)

    buckets[i] = fresh                // i вне границ нового массива
}
```

Ломает: индекс не выходит за вместилище.
Не хватает: обесценивание `buckets.index` объявлено обязательством окна, а вызов
соседней операции окна не требует. Значения, уже лежащие в локальных переменных,
ничем не помечены: тип называет поле, а не версию его содержимого. Д5 покрывает
только хранимую форму — поле `home` внутри блока.

Решается вместе с Д3 и Д5 одной фразой: значение позиционного типа не переживает
вызов, способный присвоить его вместилищу. Корень общий с М1.

## Дефекты механизма

**М1. Вызов соседней операции того же layout не входит в точки наблюдения.**
Значит вызванная операция работает при сломанном инварианте вызывающей и вправе
на него опираться.

**М2. Исключения наследуются без объявления** (`throws.md`), поэтому точка
наблюдения «вызов наружу» в исходнике не видна: `key.hash()` бросает, а в подписи
этого нет.

**М3. Смерть экземпляра при смешанном множестве.** Тег живёт в ссылке, а обход
населения при смерти идёт без единой ссылки в руках; значит нельзя назвать ни
деструктор блока, ни его размер, а блоки разного размера документ допускает.

**М4. Окно требует изымать блок внутри себя, а операции возврата блока в
население язык не даёт.** Для единственной операции, ради которой окно
существует, требование `throw`-восстановления невыполнимо.

**М5. Массовый перенос блоков между населениями** обещает перетипование ссылок
внутри переносимых блоков и молчит о входящих рёбрах: `read` из другой структуры,
`weak`, живая переменная обхода.

## Проверено и пробоем не является

`cell.take()` без назначения нового владельца — блок остаётся в населении, ссылок
на него нет: потерянный блок, второй ярус. Двойное присваивание во владеющее
место ловится обычной дисциплиной перемещения. Чтение поля не того варианта
смешанного множества из типов не выходит: доступны общие члены, сужение через
`is`.

## Предлагаемые решения

**Р1.** Изъятие потребляет владеющую ссылку: `fn take(block: own Nodes.pointer)`,
вызывается как `Nodes.take(cell.take())`. Закрывает Д1, Д9, половину Д2.

**Р2.** Обход держит `read`-заимствование населения; `create` и `take` требуют
`write`. Правило выводится из аспектов `ownership.md`, нового понятия не нужно.
Закрывает Д2 и Д10.

**Р3.** Удаление по ходу обхода выражается аспектом курсора, а не ключевым
словом. `types/ownership.md:19` даёт `split` — право разделять владение на
под-владения, и строка 41 связывает его с `write`; курсор обхода по ячейкам
держит под-владение своей ячейкой, и этого хватает, чтобы изъять из неё блок, не
владея всем населением.

Писать аспект не нужно: компилятор видит `unlink` на курсоре и выводит из этого
три вещи сразу — курсору нужен `split write`, населению нужен `write`, поэтому
другое живое заимствование того же населения конфликтует, и шаг становится
условным: ячейка со сменившимся содержимым смотрится заново. Нет `unlink` —
курсор `read`, шаг обычный.

Вывод остаётся локальным, потому что аспект стоит в подписи: функция, которой
передали ячейку, объявляет `cell: split write Entries.slot`, и вызывающему видно,
что там изымают, без чтения тела.

`unlink` определён относительно поля шага обхода и вне обхода по ячейкам
запрещён. Возвращает владеющую ссылку, поэтому перенос блока в другую структуру
становится выразимым обычным кодом.

**Р4.** Ячейка обесценивается любой записью в её вместилище и не переживает вызов
другой операции того же layout. Закрывает Д3.

**Р5.** Экземпляр layout только перемещаемый; перемещение запрещено при живом
заимствовании в его население. Закрывает Д4.

**Р6.** Обратное поле кратной связи несёт различитель либо даёт ячейку владельца.
Закрывает Д8.

**Р7.** `forget` запрещён для ссылки живого населения. Закрывает Д12.

**Р8.** Позиционное значение — индекс, ячейка, курсор обхода — заимствует своё
вместилище. Отдельного правила про вызовы не нужно: операция, которой требуется
полное право на вместилище, не уживается с живым заимствованием, и это обычная
дисциплина аспектов из `ownership.md`.

Жёсткое следствие называется прямо: заимствование, сохранённое в поле, держало бы
вместилище вечно, поэтому позиционный тип в полях не хранится. Отсюда `home`
обязан быть вычисляемым; где вывести нельзя, поле объявляется обычным числом, а
обратный переход в индекс — проверенный.

Закрывает Д3, Д5 и Д14, и объединяет их с Р2 и Р3 в одно правило.

Без решения остаются Д6, Д7, Д11, Д13 и все пять дефектов механизма.
