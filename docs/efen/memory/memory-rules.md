# Правила доступа к памяти: сводная таблица

[Документация](../README.md) · [Словарь](../glossary.md) · [Владение и доступ](../types/ownership.md) · [Области доступа](../types/access-regions.md) · [Компоновка](layout/README.md#справочник-правил)

> Статус: сводка на 2026-11-12. Правила здесь не вводятся: каждая строка называет статью, где правило записано.
> Если статья расходится с таблицей, действует таблица, а статью исправляют.

Доступ к памяти в Efen описывают три понятия и одну главную операцию. Слот хранит значение. Ссылка даёт доступ к
слоту с правом и источником. Заимствование в структуре существует дольше вызова: его хранит курсор, генератор или
замыкание. Изменение структуры: слот перенесён или уничтожен, элемент ушёл из структуры или сменил вид, слот
лишился значения. После него ссылка и заимствование в этот слот недействительны. Память существует от вызова, который её даёт, до
вызова, который её возвращает, и FLOW отслеживает эти вызовы через сводки функций
([механизм времени жизни](layout/lifetime.md#механизм-времени-жизни)). Остальные строки таблицы
[«Что делает ссылку недействительной»](#что-делает-ссылку-недействительной) называют конец времени жизни слота,
заморозку и точку ожидания.

**Основа всех таблиц.** Два поля или два параметра указывают в одну память, только если это объявлено явно. Механизмов
объявления два: право с источником, `право<поле или параметр>`, и `layout`
([поля не делят память](../types/ownership.md#поля-не-делят-память)). Без объявления поле владеет своим значением, а
пишущие аргументы не пересекаются. На этом стоит правило «вызов, который
меняет одно поле, оставляет ссылки в другое действительными». Правило не относится к указателю-параметру `layout`
без источника в типе (`n: edit Items.Item`): он может принадлежать структуре другого параметра, и изменение этой
структуры делает его недействительным ([источник ссылки](layout/pointers.md#источник-указателя), правило 3).

## Понятия

| Понятие | Что это | Чем владеет | Где описано |
|---|---|---|---|
| слот | место, где хранится значение: переменная, параметр, поле, элемент; имеет адрес и время жизни | своим значением | [ownership.md](../types/ownership.md) |
| ссылка | доступ к слоту с правом `read`, `edit` или `mut` и с источником; существует только внутри функции | ничем | [ссылки только внутри функции](../types/ownership.md#ссылки-только-внутри-функции) |
| источник | слот или путь внутрь него, от которого ссылка взята; по нему решается, что делает её недействительной | — | [источник, право и время действия](../types/access-regions.md#источник-право-и-время-действия) |
| псевдоним | второе имя уже существующего значения, без копии: `let t = doc.title`, переменная образца; хранит заимствование значения с правом пути, по которому оно получено, и становится недействительным как ссылка | ничем | [ownership.md](../types/ownership.md) |
| срез, диапазон | ссылка на несколько соседних слотов одного источника: `&v[i..<j]`; правила те же, что у ссылки | ничем | [диапазон как цель права](../types/access-regions.md#диапазон-как-цель-права) |
| заимствование в структуре | заимствование, которое существует дольше вызова: у курсора, генератора, замыкания — право и источник в типе; у внешнего кода — запись модели в поле `layout` | ничем | [контракты обхода](../types/collections.md#контракты-обхода), [модели](../models.md#заимствования) |
| часть | имя памяти объекта в контракте; без типа и байт | привязанными полями и всем, чего они достигают владением | [части объекта](../types/parts.md) |
| проекция | тип с выбранными полями значения | ничем: это вид на значение | [проекции](../types/projection.md) |
| множество, область | `set X` — все элементы одной формы во всей программе, своей памяти у множества нет; `area X` — непрерывные слоты по индексу; у области с разным шагом размер слота задаёт его собственный инвариант, и номером слота служит смещение его начала в байтах | область — своими слотами; элементом множества владеет поле `own` или `anchor` либо внешний код по строке `public own Nodes`; множество, у которого нет ни владеющего поля, ни строки `public own`, вызывает ошибку | [компоновка](layout/README.md#справочник-правил) |
| невладеющий указатель | невладеющий адрес элемента множества (`Items.Item`): поле `layout`, локальная переменная, параметр, результат, поле структуры с `Src`; источник — структура, из которой он прочитан | ничем | [структура, источник, чистота](layout/pointers.md#структура-источник-чистота) |
| якорь | владение `anchor`: точка уничтожения значения, на которое указывают невладеющие указатели; переходит из слота в слот через `tie`. Локальное имя после `t.f = tie node` остаётся невладеющим указателем ([перенос владения](layout/operations.md#64-перенос-владения), правило 1) | значением | [компоновка](layout/owners.md#якорь-anchor) |
| поле-псевдоним | поле `R<self.путь> T?`: хранит связь с памятью своего же объекта; не ссылка и не заимствование, принадлежит части своего источника; запись в него считается записью значения | ничем | [поле-псевдоним](../types/ownership.md#поле-псевдоним) |
| структура | корень цепочки владения элемента: вверх по `anchor`, `own`, вложенности в область и полю-значению `layout`, пока владелец не окажется вне `layout`. Публичной называется структура, владелец которой находится вне значения `layout`, у любого кода: значение структуры из `layout` в переменной, параметре или поле обычного типа либо элемент `own Nodes.Item` или выданный слот в переменной, параметре или результате; её часть, элемент со всем, чем он владеет, называется внутренней структурой. Хранимый невладеющий указатель без источника в типе указывает только внутрь своей публичной структуры (правило чистоты). Поэтому публичная структура чиста, а внутренняя (вершина внутри графа) может указывать за свои пределы внутри публичной; отделяет её только код `layout` | — | [структура, источник, чистота](layout/pointers.md#структура-источник-чистота) |
| расширение `layout` | `layout<K, V>: lists::Lists<Entry<K, V>>`: добавляет к `open layout` свои множества и структуры с указателями в его множества; базовый `layout` не меняется | своими множествами; элементами базовых множеств владеет значение базовой структуры в поле структуры расширения | [расширение `layout`](layout/extension.md#расширение-layout) |

## Права

| Право | Читать | Писать значения | Создавать слоты, не двигая существующих | Перемещать и уничтожать слоты | Забрать значение |
|---|---|---|---|---|---|
| `read` (умолчание) | да | — | — | — | — |
| `edit` | да | да, если запись не уничтожает прежних данных | да | — | — |
| `mut` | да | да | да | да | `take` из опционального поля (в нём остаётся `null`) и `take` элемента области (элемент не инициализирован; к выходу публичной функции код исключает его из занятых, иначе нарушен инвариант) |
| `own` | да | да | да | да | да |
| `out` | — | первая запись в пустой слот | — | — | — |

- `edit` разрешает менять значения и гарантирует, что память структуры никуда не перенесена. `mut` разрешает всё,
  что `edit`, и этой гарантии не даёт. Гарантия относится ко всей памяти структуры, служебной тоже: рост массива из
  участков, при котором перенесён только каталог участков, требует `mut`.
- `edit` имеет смысл только у структур данных: у значения, которое не владеет памятью и не имеет случаев с данными
  (число, структура из чисел), `edit` и `mut` не различаются. Запись целого значения в слот опционального типа или
  варианта со случаем с данными требует `edit`, когда доказано, что она не покидает случай с данными, и `mut` в
  остальных случаях. Условие целиком и записи, которые остаются записью значения (невладеющий указатель,
  поле-псевдоним, перечисление без данных), называет правило 6 раздела
  [«`edit` и `mut` в `layout`»](layout/operations.md#edit-и-mut-в-layout). Запись во владеющее поле `layout`,
  которое доказанно равно `null`, тоже требует `edit`.
- Перестановка указателей, при которой ни один слот не перенесён и не уничтожен, требует `edit`: перенос узла в
  начало списка давности оставляет ссылки на узлы действительными. Это относится и к якорям: `tie`, после которого
  элемент остаётся в той же структуре, требует `edit`. Элемент переходит в другую структуру только владением: это
  `mut` для структуры, из которой он ушёл, и `edit` для той, куда пришёл; скопировать указатель в другую структуру
  нельзя.
- `mut` забирает значение из опционального поля и из элемента области. `take` неопционального поля разрешён у
  корня, который один владеет значением: у параметра `mut` или `own` и у локальной переменной,
  получившей значение от вызова, от `take` или от `tie`. Пока поле пусто, ни его, ни объект целиком не читают и не
  передают, а к выходу, на котором объект остаётся у вызывающего, поле записано снова. Локальная переменная и
  параметр `own` могут закончиться с пустым полем, если при этом не выполняется написанный деструктор. `replace` и
  `swap` сразу записывают другое значение ([явное извлечение](../types/ownership.md#явное-извлечение)).
- Элемент `layout` под локальным `own` или `anchor`, у которого забрано поле-значение, после этого только
  освобождается
  ([удаление элемента](layout/operations.md#переход-к-владению-as-own), правило 4). Функция с правом `mut` на
  владельца области с разным шагом забирает значения типа `T` из слота, который удаляет запись поля размера или
  уменьшение занятой длины ([область с разным шагом](layout/declaration.md#область-с-разным-шагом), правило 6).
- Время жизни объектов со счётчиком (`conforms ArcClass`) ведёт отдельный алгоритм, и правила владения этой таблицы
  к ним не относятся. Заимствования внутрь такого объекта FLOW проверяет, как любые
  ([классы со счётчиком](../classes.md#управление-памятью)).
- Все операции компоновки по правам разложены в таблице
  [«`edit` и `mut` в `layout`»](layout/operations.md#edit-и-mut-в-layout).
- Вне `layout` запись значения, которое владеет памятью (строка, вложенный вектор),
  уничтожила бы старую память, поэтому требует `mut` ([права](../types/access-regions.md#права)). В `layout` запись
  в владеющее поле, которое доказанно пусто, — `edit`; запись поверх непустого — ошибка.
- `anchor` называет вид владения в компоновке, а не право доступа: точку уничтожения значения, на которое указывают
  хранимые указатели ([компоновка](layout/README.md#справочник-правил)).
- Форма с полями (`Item(value: 0)`) и приведение памяти к виду (`memory as Item(value: 0)`) дают полю со значением по
  умолчанию это значение. Остальные поля не инициализированы, пока не записаны: в форме или приведении, кодом после
  них или инициализатором `_` (`Item(value: _)`), который на поле-числе оставляет прежние байты, а на опциональном
  поле записывает `null`. Чтение неинициализированного поля вызывает ошибку
  ([создание элемента](layout/operations.md#выделение-и-освобождение--переход-между-множествами)).
- `immutable T` — свойство слота, а не право: значение и всё, чего оно достигает, не меняется; заморозка `take x` в
  такой слот кончает все ссылки и псевдонимы из `x` ([неизменяемость](../immutability.md)).
- `mut` не исключителен: несколько ссылок `mut` в один источник действительны одновременно, пока структуру не изменили.
- На поле `foreign` бывает только `read` и `mut`: буфер, который C перезаписывает, старую ссылку обесценивает, и это
  считается изменением структуры ([внешний код](../foreign.md)).

## Где пишется право

| Позиция | Запись | Что называет | Несколько путей |
|---|---|---|---|
| параметр | `list: mut Vector<Shape>` | что функция делает с аргументом | — |
| отношение параметров | `src: read<dst?> T` | в память какого параметра может указывать аргумент | варианты |
| получатель метода | `mut fn`, `edit fn`, `read fn`, `own fn` | что метод делает с `self` | — |
| получатель с путём | `mut<self.cache> fn`, `mut<self.cache, edit self.items> fn` | части и поля, которые метод изменяет; остальное он читает | все названные |
| ссылка в результате | `-> edit<list> Shape?`; в методе `-> read Shape?`, `-> read<self.items> Item?` | источник отданной ссылки | нет |
| ссылка ровно на слот в результате | `-> read<&doc.title> Vector<Pair>` | сам слот по пути: ссылка остаётся действительной после изменения структуры внутри слота и записи слота целиком ([ссылка ровно на слот](../types/ownership.md#ссылка-ровно-на-слот)) | нет |
| роль `yield` | `yield edit<items> Item` | источник отданной ссылки | нет |
| заимствование в скобках | `(Access<self> Cursor)`, `(mut<items> generator yield Int)` | что значение заимствует, пока существует | все названные |
| поле структуры с источником | `let items: Access<Src> Array<T>` | то же заимствование, записанное полем; право заимствования типа — самое широкое среди таких полей | — |
| поле-псевдоним | `var current: read<self.children> Node?`, `read<self> T?` | на какую память своего объекта указывает поле; заимствования типу не даёт | — |
| указатель в параметре и результате | `v: edit Items.Item`, `v: mut Items.Item`, `node: anchor Items.Item`, `-> own Block.data.Item`, `from: read<g> Nodes.Item` | право на элемент и, с `<g>`, структуру, которой он принадлежит; через параметр с `<g>` функция пишет с тем правом, которое у неё есть на `g` ([право на элемент](layout/functions.md#82-право-на-элемент)) | — |
| эффект на одиночный `one X` | `in edit Registry`, `in mut Registry` | что функция делает с памятью за `one`; с телом выводится | — |
| владение, которое `layout` отдаёт внешнему коду | `public own Nodes`, `public lend Block.data` в `layout` | какие элементы уходят целиком (`own Nodes.Item`) и слоты каких областей выдаются (`lend`); якорь внешнему коду не выдаётся; FLOW проверяет по сводке каждую функцию, видимую внешнему коду, и требует функцию обратного пути ([схема владения](layout/owners.md#схема-владения)) | — |
| тип колбэка | `mut<items> (Int) -> Void` | память, структуру которой колбэк может менять | вся названная |
| заголовок `for` | `for x in edit v`, `for x in mut v` | право на коллекцию, с которым вызывается `iterator` | — |
| ссылка в выходном параметре | `p: out read<q> T?` | ссылку с источником `q`, которую функция пишет в слот вызывающего | нет |
| ссылка в теле | `&x`, `&read x`, `&edit x` | `&x` берёт право слота `x`: под параметром `read` это `read`, под `edit` это `edit`, под `mut`, под `own` и у своей переменной это `mut`; у привязки `for` это слово заголовка; у слота `out` после первой записи это `mut`. `&read x` сужает до `read`. `&edit x` называет право `edit` и вызывает ошибку там, где слот его не даёт | — |

Ссылка не шире права области, из которой взята. Полная таблица записи `право<путь>` — в [областях доступа](../types/access-regions.md#источник-право-и-время-действия).

## Что делает ссылку недействительной

Когда у источника меняется структура (элемент удалён, память перевыделена, значение заменено), все ссылки в него
становятся недействительными. Менять структуру можно и при действительной ссылке, если после этого ссылку больше не читают и не
пишут. Если ссылку используют после изменения, компилятор выдаёт ошибку.

```efen
let first = &v[0]
v.append(1)          // может перевыделить память v: first становится недействительной
print(first)         // ошибка: first используется после изменения v
```

Курсор и генератор, которые заимствуют источник, подчиняются тому же правилу. Если после изменения они больше не
нужны, компилятор уничтожает их прямо перед изменением, и их `defer` выполняется там же; если они нужны после — ошибка
([явное извлечение](../types/ownership.md#явное-извлечение)). Коллекция с источником в типе элемента
(`Vector<read<g> Vertices.Item>`) владеет своей областью и перед изменением не уничтожается: её освобождает компилятор
в конце области видимости. После изменения структуры источника недействительны указатели в её слотах, и ошибку вызывает
чтение слота, а `count` остаётся допустимым ([указатель вне layout](layout/pointers.md#указатели-вне-layout)). Кроме такой коллекции, исключений три, все в
таблице [«Два доступа сразу»](#два-доступа-сразу). Курсор, который из источника хранит только слот получателя (обход
`for x in mut v`), после изменения структуры остаётся действительным. Генератор с заимствованием `mut` тоже: на каждом
`yield` его кадр теряет всё, что хранил в источнике. Через курсор, который сам двигает слоты, источник меняют его
методами.

Что именно вызов меняет, решает сводка тела, когда тело видно: метод `mut fn`, который трогает одно поле, делает недействительными
ссылки только в него. Когда тела нет — метод контракта и интерфейса, `open`-метод, тип функции, значение из другого
пакета — решает написанное: слово права, путь в пометке, право заимствования в типе. У `open layout` из другого
пакета сводки функций `public` и `protected` опубликованы в интерфейсе, и вызов проверяется по ним
([интерфейс `open layout`](layout/extension.md#106-интерфейс-open-layout)).

| Операция | Что становится недействительным | Где описано |
|---|---|---|
| вызов `read` | ничего | [как компилятор выводит области](../types/access-regions.md#как-компилятор-выводит-области) |
| вызов `edit` | ничего: значения записаны, слоты на своих адресах; факты о значениях забыты | там же |

| вызов `mut<self.cache> fn` | ссылки в названные части, ссылки с источником `self` без пути, ссылки в части контракта, не связанного наследованием, и то, до чего вызов доходит через поля `layout` с `mut`; ссылки в остальные части того же контракта действительны | [что видит вызывающий](../types/parts.md#что-видит-вызывающий) |
| вызов с параметром типа проекции | ссылки в поля проекции по праву параметра; ссылки в остальные поля действительны | [проекция в параметре](../types/projection.md#проекция-в-параметре) |
| шаг курсора или генератора (`next`, шаг `for`) | это вызов `mut` у курсора. Тело шага видно — по его сводке: ссылки в то, структуру чего шаг меняет. | уничтожение значения с заимствованием `mut` | то же, что вызов `mut` у него | там же |
| `yield` в теле генератора | для тела это вызов неизвестного кода: факты о значениях забыты; при `mut` недействительны ссылки, курсоры и факты о структуре, которые кадр хранит в источнике | [отдача ссылки](../generators.md#отдача-ссылки) |
| вызов `mut fn` класса над внешним значением, в том числе через получателя `edit` | ссылки с источником во внешнем объекте: считается пометка метода, а не право получателя | [класс над внешним значением](../classes.md#класс-над-внешним-значением) |
| вызов через тип функции без пометки `mut<…>` | структура аргументов не меняется, ссылки в них действительны; эффект `in mut …` в типе и параметр `own` типа действуют по своим строкам этой таблицы | [тип функции](../types/function-type.md) |
| вызов через тип функции с пометкой `mut<p> (…) -> …` | ссылки в `p` и во всё, до чего от `p` доходит вызов `mut`, как при вызове `mut` без тела | [сохранённый колбэк](../types/access-regions.md#сохранённый-колбэк) |
| присваивание значения, которое владеет памятью; запись целого значения, которая может покинуть случай с данными опционального типа или варианта | ссылки и псевдонимы внутрь прежнего значения; ссылка на сам слот действительна; запись перечисления без данных, невладеющего указателя и поля-псевдонима ничего не делает недействительным | [`edit` и `mut` в `layout`](layout/operations.md#edit-и-mut-в-layout), правило 6 |
| `replace(slot, v)`, `swap` | то же, что присваивание: ссылки внутрь прежнего значения недействительны, ссылка на слот действительна | там же |
| точка ожидания в однопоточном контексте | всё, что по сводкам меняют живые корутины, как при вызове с такой сводкой; ссылки в контекст потока — всегда | [корутины `spawn`](../types/access-regions.md#корутины-spawn) |
| отпускание блокировки: выход из `with`, исключение, конец вызова замыкания `waitFor` | указатели, ссылки и заимствования с источником в охраняемых полях; значение, которое хранит такой указатель, ссылку или заимствование и дальше не используется, уничтожается до `exit`, используемый — ошибка | [структура под блокировкой](layout/threads.md#структура-под-блокировкой) |
| многопоточная корутина, сводка которой меняет источник указателя, ссылки или заимствования, которые используются после её отрезка | ошибка компиляции: такой доступ считается `read` источника на весь отрезок; основная метка у `spawn`, вторая у использования | [структура и поток](layout/threads.md#структура-и-поток) |
| `take x` целой локальной переменной в новую переменную | ничего: слот остался в функции, ссылка указывает на слот, а не на имя | [явное извлечение](../types/ownership.md#явное-извлечение) |
| `take x` в существующий слот | все ссылки на слот-источник | там же |
| `take` из опционального поля или из элемента коллекции типа `T?` её собственной операцией | ссылки внутрь прежнего содержимого: в слоте остался `null` | там же |
| `take` элемента области, в том числе типа `T?` | ссылки и указатели на этот элемент; элемент не инициализирован | [неинициализированный элемент области](layout/operations.md#частичная-инициализация-и-очистка) |
| запись поля размера в слоте области с разным шагом (деление, слияние слотов) | ссылки и указатели на слоты, начало или размер которых изменились, и внутрь их вложенных областей; хранимые номера и указатели на слот, которого после записи нет, переписаны до записи, иначе ошибка в её строке | [область с разным шагом](layout/declaration.md#область-с-разным-шагом) |
| конец значения структуры из `layout`: конец области видимости, конец инструкции у временного значения, выход через исключение, запись в слот целиком | компилятор освобождает значение: вызывает `dispose`, если он написан, затем план по полям; ссылки и указатели в её память недействительны. Структура, которой нужен и не написан `dispose` или которая не `ImplicitlyDestroyable`, расходуется явным кодом (раздел 7.4, правило 4 о значении структуры) | [ничего не теряется](layout/lifetime.md#74-ничего-не-теряется) |
| `tie` якоря, после которого элемент остаётся в той же структуре (перестановка) | ничего: элемент на своём адресе, изменилась точка уничтожения | [`edit` и `mut` в `layout`](layout/operations.md#edit-и-mut-в-layout) |
| элемент ушёл из структуры владением: в результат, в другую структуру | указатели и ссылки с источником в этой структуре на него и на всё, что под ним, в любом коде; в функции, которая сама передала элемент и знает, куда, её локальный указатель получает источником новую структуру | [структура, источник, чистота](layout/pointers.md#структура-источник-чистота) |
| `lend` слота (это `mut` на родителя) | ссылки, срезы и курсоры, которые могут пересекаться с выданным слотом | [выдача и возврат](layout/operations.md#выдача-и-возврат) |
| вызов без тела с параметром `mut Items.Item` или с правом `mut` на структуру | указатели с источником в структуре аргумента | [структура, источник, чистота](layout/pointers.md#структура-источник-чистота) |
| `as own`, освобождение элемента, возврат выданного слота, смена вида `as` | все ссылки и указатели на элемент; хранимые указатели переписаны до операции, иначе ошибка в её строке | [переход к владению](layout/operations.md#переход-к-владению-as-own) |

## До чего доходит вызов `mut`

| От получателя вызов доходит до | С каким правом | Пример |
|---|---|---|
| самого получателя и всего, чем он владеет | `mut` | после `v.append(x)` ссылка `&v[0]` недействительна |
| объекта за полем `layout` с правом `mut` | `mut`, транзитивно | после `s.sqlite3_step()` ссылка `read<db.errmsg>` недействительна: `s.db` — `mut sqlite3` |
| источника заимствования в скобках | с правом заимствования, не шире | после `g.next()` у `(mut<items> generator …)` без видимого тела ссылки в `items` недействительны; у `(edit<items> generator …)` действительны |
| источника в поле `R<Src> …` структуры | с правом `R` | курсор с полем `mut<Src> Array<T>` |
| источника по цепочке заимствований | с самым узким правом на цепочке | курсор хранит заимствование генератора с `mut`, генератор хранит заимствование `items` с `edit`: шаг курсора до `items` доходит с `edit` |
| объекта за полем `layout` с правом `read` или `edit`, источника заимствования `read` или `edit` | с этим правом: структуру вызов не меняет, ссылки действительны | после шага обычного курсора прежние элементы действительны |

Заимствование `mut` не теряется ни при каком преобразовании: значение с ним идёт только в параметр, тип которого это
заимствование пишет.

## Два доступа сразу

| Пара | Правило | Если не доказано |
|---|---|---|
| два поля одного объекта, поля двух объектов, два элемента коллекции, два параметра | не пересекаются, пока общая память не объявлена правом с источником или `layout` | — |
| два читающих аргумента | делят память свободно | — |
| читающий аргумент `ImplicitlyCopyable` и любой другой | передаётся копией и ни с чем не пересекается | — |
| пишущий аргумент (`edit`, `mut`, `out`, `own`, `anchor`) и другой аргумент | не пересекаются, если сигнатура не объявила отношение «внутри» | по правилам раздела [«Совместимость»](../types/access-regions.md#совместимость): сравнение слотов при вызове со сбоем `OverlapError` или ошибка компиляции |
| получатель с путём в пометке и аргумент-ссылка | сравниваются по частям | ошибка компиляции: у части нет адреса |
| два аргумента-проекции одного значения | не пересекаются, если поля `var` одной не входят в другую | проверка адресов по полям |
| захват многопоточной корутиной и остальной код | только доказательство | ошибка компиляции |
| владелец и значение с заимствованием `read` или `edit` | владелец читает и пишет значения, создаёт слоты; изменение структуры затрагивает структуру, которая заимствует, по правилу раздела [«Что делает ссылку недействительной»](#что-делает-ссылку-недействительной) | — |
| владелец и значение с заимствованием `mut`, которым реализация отвечает на заимствование из контракта | владелец меняет структуру; структура, которая заимствует, хранит только слот получателя и остаётся действительной | — |
| владелец и генератор с заимствованием `mut` | владелец меняет структуру источника между шагами; генератор остаётся действительным: на `yield` его кадр теряет ссылки, курсоры и факты о структуре, которые хранил в источнике ([отдача ссылки](../generators.md#отдача-ссылки)) | — |
| владелец и конкретный курсор, который сам двигает слоты (`removing()`, `draining()`) | менять источник можно только через курсор; изменение структуры мимо него затрагивает курсор | — |
| два параметра `edit` или `mut` одного множества (`a: mut Items.Item, b: mut Items.Item`) | `apart`: сравниваются названные элементы; досягаемость по указателям в сравнение не входит; случай «один элемент» — отдельная ветка | проверка адресов |
| владелец и курсор с полем `read<Src> Items.Item?` | после вызова `edit` у владельца (вставка, перестановка) курсор действителен; вызов, который освобождает или уводит элементы, затрагивает курсор | — |
| объект и его поле-псевдоним | объект остаётся хозяином источника и меняет его структуру; поле записывается заново | — |
| два значения с заимствованием одного источника | как две ссылки с теми же правами: действительны одновременно, изменение структуры через одно затрагивает другое | — |
| части одного контракта и его предков | не пересекаются: проверено привязкой | — |
| части двух контрактов, не связанных наследованием | считаются пересекающимися | — |
| структура и поток | структура — одна область: корень и все элементы под ним; право, выполненное через указатель с этим источником, — доступ к области с этим правом | ошибка компиляции ([структура и поток](layout/threads.md#структура-и-поток)) |
| роль над диапазоном области в поле структуры из `layout` и остальной код | пока роль существует, остальные поля этой структуры любой код только читает, и область не заменяется | ошибка компиляции ([роли](layout/threads.md#роли)) |
| `one` и поток | `one X` со всем, чем владеют его поля, составляет одну область на всю программу; эффект `in read\|edit\|mut X` и доступ через указатель с источником в `X` сверяются по таблице многопоточного вида; в другой поток `one` не переходит | ошибка компиляции ([`one` и поток](layout/threads.md#one-и-поток)) |
| поток и поток | части ссылок не разделяют потоки: метод с путём конфликтует с любым другим методом объекта | [общая память](../shared.md) |

## Обход

| Заголовок | Заимствование курсора | Тело цикла может | Прежние элементы после шага |
|---|---|---|---|
| `for x in v` | `(read<v> Cursor)` | читать `v`; владелец с правом записи пишет значения и создаёт слоты | действительны |
| `for x in edit v` | `(edit<v> Cursor)` | писать значения, создавать слоты, не двигая существующих | действительны |
| `for x in mut v` | `(mut<v> Cursor)` | менять структуру `v`; элемент действителен до первого такого изменения | недействительны, если шаг или тело меняют структуру `v`; у курсора без видимого тела `next` — всегда |
| `for x in take v` | нет: курсор владеет `v` | `x` — значение, а не ссылка | — |
| `for x in курсор` | какое записано в его типе | по праву заимствования; курсор берётся как `mut`, слово права не пишется | по праву заимствования |
| `for x in генератор` | какое записано в его типе | по праву заимствования; генератор берётся как `mut` | по праву заимствования |
| `for item in let c = items.removing()` | конкретный тип, который сам двигает слоты | менять `items` только через `c` | недействительны |

- Курсор, которым реализация отвечает на заимствование `mut` из контракта, из полей с `Src` хранит один слот получателя.
- `next` возвращает элемент или `null`; цикл снимает один уровень опционального типа, поэтому элемент `null` — не
  конец обхода ([цикл `for` с итератором](../types/collections.md#цикл-for-с-итератором)).
- Генератор контрактов обхода не соблюдает; итератор для обобщённого кода даёт его метод `iterator()`
  ([генератор как итератор](../generators.md#генератор-как-итератор)).

## Что пишет программист и что выводит компилятор

| Факт | В функции и методе с телом | В контракте, интерфейсе, объявлении без тела |
|---|---|---|
| право параметра и слово права метода | пишется | пишется |
| что именно тело изменяет (сводка, путь до поля) | выводится | пишется путём в пометке |
| источник ссылки в результате и в роли `yield` | пишется | пишется |
| источник локальной ссылки | выводится из выражения `&` | — |
| заимствование значения-результата | пишется в типе результата | пишется в скобках |
| заимствование генератора-метода | выводится из тела; путь в пометке — проверяемый предел | пишется путём в пометке |
| привязка частей к полям | пишется, включая `= none` | — |
| непересечение аргументов | доказывается; иначе проверка при вызове или ошибка компиляции | то же |
| время жизни невладеющих указателей, предусловия операций над слотами | выводится из `layout` | пишется условиями `layout` |
| эффекты и исключения | выводятся | пишутся |

## Где доказательство, где проверка при выполнении

| Свойство | Доказано | Не доказано |
|---|---|---|
| ссылка не использована после изменения структуры источника | компилируется | ошибка компиляции |
| пишущий аргумент не пересекается с другим | компилируется | проверка при вызове, `OverlapError`, или ошибка компиляции ([совместимость](../types/access-regions.md#совместимость)) |
| то же для частей и для захвата многопоточной корутиной | компилируется | ошибка компиляции |
| индекс в границах | проверки нет | проверка при выполнении |
| индекс области с разным шагом называет начало слота | компилируется | ошибка компиляции; проверки при выполнении нет, без доказательства индекс принимается только после `assume` |
| безопасность операции компоновки (освобождение, перевыделение, `tie` якоря, `as own`) | компилируется | ошибка компиляции |
| отданная генератором ссылка указывает в объявленный источник | компилируется | ошибка в строке `yield` |
| точки доверия, шесть видов: строка `assume`, условие результата `@asm`, объявление без тела (функция C с правами из `@fill`, код `model`), приведение адреса к элементу множества или к выданному слоту, объявление функции `@abi(c)` с телом, в том числе `shared @abi(c)`, запись `thread var x: own T` со значением не `ImplicitlyDestroyable` | — | принимаются на веру; их перечисляет `efen proofs` ([что такое `layout`](layout/README.md#1-что-такое-layout)) |

Что доказывается по объявлениям `layout`:

| Описано | Доказывается | Кто |
|---|---|---|
| вид и `as` | размер, выравнивание, запись полей до чтения | FLOW |
| число слотов области | индекс в границах | FLOW, Z3; что не доказано — проверка при выполнении |
| область с разным шагом | слоты занимают `0 ..< x.extent` без промежутков и наложений; каждый индекс называет начало слота | FLOW |
| `lend` / `take` в свой слот | один владелец слота, нет повторной выдачи, возврат только в свой слот | FLOW |
| `used == slots.taken.count` | счёт сходится на каждом выходе; участок не возвращается, пока из него что-то выдано | FLOW |
| `for element in take region` | каждый элемент отдан дальше | FLOW |
| вложенность и выдача | время жизни каждого указателя, четыре свойства жизненного цикла элемента | FLOW |
| `invariants` вида | инвариант верен при каждой передаче значения дальше | FLOW, Z3 |
| цепочка и её инварианты | форма цепочки по записям; инварианты о её узлах и предусловия операций | FLOW; Z3 |
| поля `protected` и сводки функций `open layout` | функция расширения восстанавливает инварианты над `protected` полями; держатели переписаны до вызова, который уничтожает их цель | FLOW |
| указатель из адреса | принадлежность к множеству и к названной структуре | точка доверия |

Для каждого факта записано, кто его установил: FLOW, Z3, точка доверия или проверка при выполнении.

## Чего таблица не обещает

Таблица описывает модель, но доказательства надёжности у модели нет: [алгоритм](layout-algorithm.md) даёт план
доказательства, а не выполненное. Два раунда Критика 2026-11-11 находили в свежих правилах принятые программы с
обращением к освобождённой памяти; правила после них исправлены, но известное отсутствие таких программ — не
доказательство. Вне модели сегодня:

| Область | Состояние |
|---|---|
| структуры без блокировок; освобождение участка менеджера памяти из другого потока; конец потока, куча которого хранит участки с выданными слотами; объекты со счётчиком | вне `layout`: примитивы стандартной библиотеки, доказанные один раз; объекты со счётчиком — отдельная тема ([что `layout` не описывает](layout/threads.md#чего-layout-не-описывает)) |

Не нарушают надёжность: проверки при выполнении (граница индекса, `OverlapError`,
порядок вызовов генератора) и отказ принять безопасную программу.
