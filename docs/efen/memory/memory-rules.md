# Правила доступа к памяти: сводная таблица

[Документация](../README.md) · [Словарь](../glossary.md) · [Владение и доступ](../types/ownership.md) · [Области доступа](../types/access-regions.md) · [Компоновка](layout/README.md#справочник-правил)

> Статус: сводка на 2026-11-27. Правила здесь не вводятся: каждая строка называет статью, где правило записано.
> Если таблица расходится со статьёй, которую называет строка, действует статья, а таблицу исправляют.

Доступ к памяти в Efen описывают три понятия и одну главную операцию. Слот хранит значение. Доступ к значению имеет
три формы: значение без источника, заимствование `read<x.y> T` (сама часть, данная на время) и ссылка `&read<x.y> T`
(ровно поле или элемент `x.y`); форму решает запись. Держание (`holds`) — запись того, что курсор, генератор или
замыкание держит дольше вызова. Изменение структуры: слот перенесён или уничтожен, элемент ушёл из структуры или сменил вид, элемент
области лишился значения. После него ссылка и заимствование в этот слот недействительны. Память существует от вызова, который её даёт, до
вызова, который её возвращает, и FLOW отслеживает эти вызовы через сводки функций
([механизм времени жизни](layout/lifetime.md#механизм-времени-жизни)). Остальные строки таблицы
[«Что делает ссылку недействительной»](#что-делает-ссылку-недействительной) называют конец времени жизни слота,
заморозку и точку ожидания.

**Основа всех таблиц.** Два поля или два параметра указывают в одну память, только если это объявлено явно. Механизмов
объявления два: заимствование или ссылка с источником, `право<путь> T` и `&право<путь> T`, и `layout`
([поля не делят память](../types/ownership.md#поля-не-делят-память)). Без объявления поле владеет своим значением, а
пишущие аргументы не пересекаются. На этом стоит правило «вызов, который
меняет одно поле, оставляет ссылки в другое действительными». Правило относится и к указателю-параметру `layout` без источника в типе
(`n: edit Items.Item`): в структуре другого параметра он не расположен. Элемент внутри структуры-параметра называет
параметр с источником, `n: read<list> Items.Item`, и изменение структуры `list` делает его недействительным
([источник ссылки](layout/pointers.md#источник-указателя), правило 3).

## Понятия

| Понятие | Что это | Чем владеет | Где описано |
|---|---|---|---|
| слот | логическое вместилище данных одного значения; его держит переменная, параметр, поле или элемент, на него указывают и псевдонимы; имеет время жизни | своим значением | [ownership.md](../types/ownership.md) |
| ссылка | доступ к слоту с правом `read`, `edit` или `mut` и с источником; в типе `&` стоит первым: `&edit<list[_]> Shape?`, `x: &edit Int`; ссылка — адрес: `&x` называет переменную и недействительна после её конца, ссылка на поле или элемент (`&x.y`, `&items[0]`) хранит его адрес: после записи его целиком читает новое значение, после записи целиком значения, которое его содержит, указывает в прежнее ([связывание](../types/ownership.md#связывание-существующего-значения), правило 5); по имени переменная-ссылка означает своё поле или элемент: `r = v` пишет его, `let x = r` связывает значение по правилу типа, `&r` — вторая ссылка туда же, `var` переводят только `r = &place`; `take` через ссылку — ошибка; хранится в переменной, а в поле — только у типа, который называет источник (`Src: Origin`, запись `holds`) | ничем | [ссылки](../types/ownership.md#ссылки-только-внутри-функции) |
| источник | слот или путь внутрь него, от которого ссылка взята; по нему решается, что делает её недействительной | — | [источник, право и время действия](../types/access-regions.md#источник-право-и-время-действия) |
| псевдоним | второе имя уже существующего значения, без копии: `let t = doc.title`, переменная образца, результат вызова с заимствованием в результате (`let t = title(doc: d)`); хранит заимствование значения с правом пути, по которому оно получено; после записи источника целиком держит прежнее значение до конца своей области видимости; после вызова, который пишет источник целиком, недействителен; не ссылка; недействителен после изменения структуры источника и там, где значение выходит из [области контроля](flow-algorithm.md#область-контроля) функции; `take` значения в локальную переменную его не кончает | ничем | [ownership.md](../types/ownership.md) |
| срез, диапазон | ссылка на несколько соседних слотов одного источника: `&v[i..<j]`; правила те же, что у ссылки; слоты среза — его элементы | ничем | [диапазон как цель права](../types/access-regions.md#диапазон-как-цель-права) |
| держание (`holds`) | то, что значение держит дольше вызова: у курсора, генератора, замыкания и параметра типа — слово `holds` и запись в типе (`holds Access<self> Cursor`, `holds mut<items> generator yield Int`, `holds edit<items> (Int, Int) -> Bool`); без `holds` запись `право<x> T` — заимствование; источники записи — ссылки; у внешнего кода — запись модели в поле `layout` | ничем | [контракты обхода](../types/collections.md#контракты-обхода), [модели](../models.md#заимствования) |
| часть | имя памяти объекта в контракте; без типа и байт | привязанными полями и всем, чего они достигают владением | [части объекта](../types/parts.md) |
| проекция | тип с выбранными полями значения | ничем: это вид на значение | [проекции](../types/projection.md) |
| множество, область | `set X: T` на уровне `layout` — все элементы типа `T` во всей программе, своей памяти у множества нет; строка `set Name: путь, …` в теле структуры или класса (и внутри `layout`) называет поля и элементы внутри значения, у каждого значения свои: `set Elements: items[_]`; `x[_]` — это `x.Elements`; рекурсия пишется (`set Nodes: left.Nodes, right.Nodes`); шаг пути `x.S` у множества `layout` — элементы `S`, которыми владеют через `x`; `Area<T>` — непрерывные слоты по индексу в поле структуры, которая хранит их число; у области с разным шагом размер слота задаёт его собственный инвариант, и номером слота служит смещение его начала в байтах | область — своими слотами; элементом множества владеет поле `own` или `anchor` либо внешний код по строке `public own Nodes`; множество, у которого нет ни владеющего поля, ни строки `public own`, вызывает ошибку | [компоновка](layout/README.md#справочник-правил) |
| невладеющий указатель | невладеющий адрес элемента множества (`Items.Item`): поле `layout`, локальная переменная, параметр, результат, поле структуры с `Src`; источник — структура, из которой он прочитан | ничем | [структура, источник, чистота](layout/pointers.md#структура-источник-чистота) |
| якорь | владение `anchor`: точка уничтожения значения, на которое указывают невладеющие указатели; переходит из слота в слот через `tie`. Локальная переменная или параметр после `t.f = tie node` остаётся невладеющим указателем ([перенос владения](layout/operations.md#64-перенос-владения), правило 1) | значением | [компоновка](layout/owners.md#якорь-anchor) |
| поле-псевдоним | поле `R<self.путь> T?`: хранит связь с памятью своего же объекта; не ссылка и не заимствование, принадлежит части своего источника; запись в него считается записью значения | ничем | [поле-псевдоним](../types/ownership.md#поле-псевдоним) |
| структура | корень цепочки владения элемента: вверх по `anchor`, `own`, вложенности в область и полю-значению `layout`, пока владелец не окажется вне `layout`. Публичной называется структура, владелец которой находится вне значения `layout`, у любого кода: значение структуры из `layout` в переменной, параметре или поле обычного типа либо элемент `own Nodes.Item` или выданный слот в переменной, параметре или результате; её часть, элемент со всем, чем он владеет, называется внутренней структурой. Хранимый невладеющий указатель без источника в типе указывает только внутрь своей публичной структуры (правило чистоты). Поэтому публичная структура чиста, а внутренняя (вершина внутри графа) может указывать за свои пределы внутри публичной; отделяет её только код `layout` | — | [структура, источник, чистота](layout/pointers.md#структура-источник-чистота) |
| расширение `layout` | `layout<K, V>: lists::Lists<Entry<K, V>>`: добавляет к `open layout` свои множества и структуры с указателями в его множества; базовый `layout` не меняется | своими множествами; элементами базовых множеств владеет значение базовой структуры в поле структуры расширения | [расширение `layout`](layout/extension.md#расширение-layout) |

## Права

| Право | Читать | Писать значения | Создавать слоты, не двигая существующих | Перемещать и уничтожать слоты | Забрать значение |
|---|---|---|---|---|---|
| `read` (умолчание) | да | — | — | — | — |
| `edit` | да | да, кроме записи, которая уничтожает объявленный элемент множества значения, на котором право (первый пункт ниже) | да | — | — |
| `mut` | да | да | да | да | `take` из опционального поля (в нём остаётся `null`), `take v[i]` (элемент удалён из коллекции; `take` привязки `for` — ошибка: она ссылка), `take` элемента области (элемент не инициализирован; к выходу публичной функции код исключает его из занятых, иначе нарушен инвариант) |
| `own` | да | да | да | да | да |
| `out` | — | запись переменной вызывающего целиком; параметр пишется `&out T`, аргумент `&out x`; `out T` без `&` — ошибка | — | — | — |

- `edit` разрешает менять значения и гарантирует только одно: объявленные элементы множеств значения остаются на
  своих адресах, ни один не перенесён и не уничтожен. Глубину гарантии задают строки `set`: рекурсивное множество
  (`set Nodes: left.Nodes, right.Nodes`) охраняет все уровни, `set Kids: left, right` — один, без множества внутри
  ничего не охраняется. Всё остальное — обычное значение: память внутри элемента может измениться, поле или
  элемент пишется целиком (`d.title = "x"`, `v[0] = "x"`), если прежнее значение не может держать объявленный
  элемент множества значения, на котором право. Заполнение доказанно пустого поля ничего не уничтожает
  (`if n.left == null { n.left = leaf }`). `mut` разрешает всё, что `edit`, и гарантии не даёт: перенос и
  уничтожение элемента (`v.remove(index: 0)`, `n.right = null` в дереве) требуют `mut`. Рост массива из участков,
  при котором перенесён только каталог участков, а элементы остаются на своих адресах, гарантию `edit` не нарушает.
  Узел, который обход отдал под `edit`, пишет своё значение, но не удаляет и не заменяет узлы под собой.
- Ссылка на слот элемента, которую дал доступ `edit` (`v[i]` через член `edit` контракта `[]`, элемент обхода
  `for x in edit v`), разрешает над значением слота `mut` с тем же исключением (пункт выше): `v[i] = x` для значения, которое владеет памятью,
  запись `null` у `T?`, `rows[0].append(1)`, `rows[0][] = 1`; такую ссылку принимает параметр `&mut T`
  (`put(x: &v[0], value: "a")`). `take v[i]` удаляет элемент: это изменение структуры `v`,
  ему нужно право `mut` на `v`. Это верно для любого доступа `edit`,
  не только для вызова члена `edit`: `fn reset(v: edit Vector<String>) { v[0] = "" }` допустима
  ([контракты операторов](../runtime/lang-roles.md#контракты-операторов)).
- `edit` имеет смысл только у структур данных: у значения, которое не владеет памятью и не имеет случаев с данными
  (число, структура из чисел), `edit` и `mut` не различаются. Запись целого значения в слот опционального
  типа или варианта со случаем с данными решает первый пункт, внутри `layout` тоже. `mut` она требует, только когда
  прежние данные — владеющий указатель `layout` или область и FLOW не доказал, что запись не покидает случай с
  данными. Условие целиком и записи, которые остаются записью значения (невладеющий указатель,
  поле-псевдоним, перечисление без данных), называет правило 6 раздела
  [«`edit` и `mut` в `layout`»](layout/operations.md#edit-и-mut-в-layout). Запись во владеющее поле `layout`,
  которое доказанно равно `null`, тоже требует `edit`.
- Перестановка указателей, при которой ни один слот не перенесён и не уничтожен, требует `edit`: перенос узла в
  начало списка давности оставляет ссылки на узлы действительными. Это относится и к якорям: `tie`, после которого
  элемент остаётся в той же структуре, требует `edit`. Элемент переходит в другую структуру только владением: это
  `mut` для структуры, из которой он ушёл, и `edit` для той, куда пришёл; скопировать указатель в другую структуру
  нельзя.
- `mut` забирает значение из опционального поля и из элемента области и удаляет элемент коллекции (`take v[i]`; `take`
  привязки `for` — ошибка: с `edit` или `mut` привязка — ссылка, а через ссылку не забирают). `take` неопционального поля разрешён у
  корня, который функция отслеживает на каждом пути: у параметра `mut` или `own`, у локальной переменной и у псевдонима; у элемента коллекции он не доказывается
  ([явное извлечение](../types/ownership.md#явное-извлечение)). Пока поле пусто, ни
  его, ни объект целиком не читают и не передают, а к выходу, на котором объект остаётся у вызывающего, к концу шага
  `for` и к каждой точке, где поле может прочесть другой код, поле записано снова. Локальная переменная и параметр `own` могут закончиться с пустым полем, если при этом не выполняется
  написанный деструктор или `dispose`. `replace` и `swap` сразу записывают другое значение ([явное извлечение](../types/ownership.md#явное-извлечение)).
- Элемент `layout` под локальным `own` или `anchor`, у которого забрано поле-значение, после этого только
  освобождается
  ([удаление элемента](layout/operations.md#переход-к-владению-as-own), правило 4). Функция с правом `mut` на
  владельца области с разным шагом забирает значения типа `T` из слота, который удаляет запись поля размера или
  уменьшение занятой длины ([область с разным шагом](layout/declaration.md#область-с-разным-шагом), правило 6).
- Время жизни объектов со счётчиком (`conforms ArcClass`) ведёт отдельный алгоритм, и правила владения этой таблицы
  к ним не относятся. Заимствования внутрь такого объекта FLOW проверяет, как любые
  ([классы со счётчиком](../classes.md#управление-памятью)).
- Все операции компоновки по правам разложены в таблице
  [«`edit` и `mut` в `layout`»](layout/operations.md#edit-и-mut-в-layout).
- Вне `layout` запись поля или элемента целиком под `edit` допустима, если прежнее значение не может держать
  объявленный элемент множества значения, на котором право (первый пункт): `struct Shelf { var books: Vector<Book>;
  set Elements: books.Elements }` и `s.books = Vector()` под `s: edit Shelf` — ошибка, уничтожены элементы
  `s.Elements`. Свободный параметр `&edit T` пишет целиком только значение, которое не владеет памятью; иначе
  функция пишет `&mut T` ([права](../types/access-regions.md#права)). Поле или элемент за параметром-ссылкой
  записан целиком к каждому выходу, к выходу исключением тоже. В `layout` запись
  в владеющее поле, которое доказанно пусто, — `edit`; запись поверх непустого — ошибка.
- `anchor` называет вид владения в компоновке, а не право доступа: точку уничтожения значения, на которое указывают
  хранимые указатели ([компоновка](layout/README.md#справочник-правил)).
- Форма с полями (`Item(value: 0)`) даёт полю со значением по умолчанию это значение. Приведение к виду записывает
  только поля, названные в нём, и значений по умолчанию не пишет; называть поля может только приведение сырой памяти
  (`memory as Item(value: 0)`). После приведения `Pointer` поле, не названное в приведении, не инициализировано, пока
  его не запишет код или инициализатор `_` (`Item(value: _)`), который на поле-числе оставляет прежние байты, а на
  опциональном поле записывает `null`. После смены вида поле хранит прежние байты, а из условий о нём известно только
  записанное после приведения. Чтение неинициализированного поля вызывает ошибку
  ([создание элемента](layout/operations.md#выделение-и-освобождение--переход-между-множествами)).
- `immutable T` — свойство слота, а не право: значение и всё, чего оно достигает, не меняется; заморозка `take x` в
  такой слот кончает все ссылки и псевдонимы из `x` ([неизменяемость](../immutability.md)).
- `mut` не исключителен: несколько ссылок `mut` в один источник действительны одновременно, пока структуру не изменили.
- На поле `foreign` бывает только `read` и `mut`: буфер, который C перезаписывает, старую ссылку обесценивает, и это
  считается изменением структуры ([внешний код](../foreign.md)).

## Где пишется право

| Позиция | Запись | Что называет | Несколько путей |

## Что делает ссылку недействительной

Список один для каждой структуры и для ссылки, псевдонима и каждого, кто держит (курсор, генератор, замыкание):

- запись значения ничего не кончает;
- своя запись целиком значения, которое содержит или может содержать поле или элемент ссылки: ссылка остаётся в
  прежнем значении, его держит скрытая переменная, пока ссылка может быть использована; ссылка на саму записанную
  переменную читает новое значение;
- запись целиком части аргумента, которую делает вызванная функция: псевдонимы и ссылки вызывающего внутрь прежнего
  значения — ошибка при следующем использовании;
- объявленный элемент множества перенесён или уничтожен (изменение структуры под `mut`: элемент удалён, память
  перевыделена): ссылки на слоты коллекции недействительны. Вызов только с `edit` не кончает ни одной ссылки на слот
  объявленного элемента; ссылки внутрь обычных значений он кончать может;
- значение уходит из функции: ссылки внутрь него недействительны.

Менять структуру можно и при действительной ссылке, если после этого ссылку больше не читают и не
пишут. Если ссылку используют после изменения, компилятор выдаёт ошибку.

```efen
let first = &v[0]
v.append(1)          // может перевыделить память v: first становится недействительной
print(first)         // ошибка: first используется после изменения v
```

Курсор и генератор, которые держат источник, подчиняются тому же правилу: источники записи `holds` — ссылки. Если после изменения они больше не
нужны, компилятор уничтожает их прямо перед изменением, и их `defer` выполняется там же; если они нужны после — ошибка
([явное извлечение](../types/ownership.md#явное-извлечение)). Коллекция с источником в типе элемента
(`Vector<read<g> Vertices.Item>`) владеет своей областью и перед изменением не уничтожается: её освобождает компилятор
в конце области видимости. После изменения структуры источника недействительны указатели в её слотах, и ошибку вызывает
чтение слота, а `count` остаётся допустимым ([указатель вне layout](layout/pointers.md#указатели-вне-layout)). Кроме такой коллекции, исключений три, все в
таблице [«Два доступа сразу»](#два-доступа-сразу). Курсор с держанием `mut`, который из источника хранит только слот получателя (обход
`for x in mut v`, `byIndex()`), после изменения структуры остаётся действительным. В обходе `for x in v` и
`for x in edit v` изменение, которое перемещает или может переместить элементы источника, допустимо, только если
курсор после него не используется (`v.append(1); break`): курсор уничтожается перед изменением. Использование
курсора после такого изменения — ошибка компиляции; режим обхода называет заголовок
([итератор как структура](../types/access-regions.md#итератор-как-структура)). Генератор с держанием `mut` тоже: на каждом
`yield` его кадр теряет всё, что хранил в источнике. Через курсор, который сам двигает слоты, источник меняют его
методами.

Что именно вызов меняет, решает сводка тела, когда тело видно: метод `mut fn`, который трогает одно поле, делает недействительными
ссылки только в него. Когда тела нет — метод контракта и интерфейса, `open`-метод, тип функции, значение из другого
пакета — решает написанное: слово права, путь в пометке, запись `holds` в типе. У `open layout` из другого
пакета сводки функций `public` и `protected` опубликованы в интерфейсе, и вызов проверяется по ним
([интерфейс `open layout`](layout/extension.md#106-интерфейс-open-layout)).

|---|---|---|

Значение, поле-ссылка которого указывает в память значения элемента, а не на слот элемента, умирает от каждой такой записи; поле-заимствование копируемого типа (`read<Src> Int`) — копия, FLOW его не отслеживает. Тела нет — по праву записи `holds`: при `mut` ссылки в источник, при `edit` — как вызов `edit` (строка выше), при `read` — ничего | [контракты обхода](../types/collections.md#контракты-обхода), [отдача ссылки](../generators.md#отдача-ссылки) |
| уничтожение значения с держанием `mut` | то же, что вызов `mut` у него | там же |
| `yield` в теле генератора | для тела это вызов неизвестного кода: факты о значениях забыты; при `edit` недействительны ссылки кадра в память значений элементов источника; при `mut` недействительны ссылки, курсоры и факты о структуре, которые кадр хранит в источнике | [отдача ссылки](../generators.md#отдача-ссылки) |

Структура, которая не `ImplicitlyDestroyable`, и тип в ручном режиме выделения ([ручное выделение](allocator.md#ручное-выделение)) расходуются явным кодом; структура, которой нужен `dispose`, без него вызывает ошибку у объявления (раздел 7.4, правило 4 о значении структуры) | [ничего не теряется](layout/lifetime.md#74-ничего-не-теряется) |
| `tie` якоря, после которого элемент остаётся в той же структуре (перестановка) | ничего: элемент на своём адресе, изменилась точка уничтожения | [`edit` и `mut` в `layout`](layout/operations.md#edit-и-mut-в-layout) |
| элемент ушёл из структуры владением: в результат, в другую структуру | указатели и ссылки с источником в этой структуре на него и на всё, что под ним, в любом коде; в функции, которая сама передала элемент и знает, куда, её локальный указатель получает источником новую структуру | [структура, источник, чистота](layout/pointers.md#структура-источник-чистота) |
| `lend` слота (это `mut` на родителя) | ссылки, срезы и курсоры, которые могут пересекаться с выданным слотом | [выдача и возврат](layout/operations.md#выдача-и-возврат) |
| вызов без тела с параметром `mut Items.Item` или с правом `mut` на структуру | указатели с источником в структуре аргумента | [структура, источник, чистота](layout/pointers.md#структура-источник-чистота) |
| `as own`, освобождение элемента, возврат выданного слота, смена вида `as` | все ссылки и указатели на элемент; хранимые указатели переписаны до операции, иначе ошибка в её строке | [переход к владению](layout/operations.md#переход-к-владению-as-own) |
| вызов функции, сводка которой освобождает элемент или уводит его из структуры | указатели и ссылки, которые могут быть равны этому элементу, — в строке вызова; так же, когда функция делает это через `one` | [сводка функции](layout/functions.md#как-flow-вычисляет-время-жизни) |
| вызов из кода расширения функции базового `layout`, сводка которой уничтожает элемент или выводит его из структуры | держатели расширения, которые могут быть равны этому элементу или тому, чем он владеет: они переписаны до вызова, иначе ошибка в строке вызова | [вызов, который уничтожает цель держателя](layout/extension.md#103-вызов-который-уничтожает-цель-держателя) |
| возврат памяти родителя (участка, области) | ссылки и указатели на всё, что в ней расположено; слот, выданный внешнему коду, или заимствование в структуре вне возвращаемой памяти вызывает ошибку в строке возврата | [выдача и возврат слота](layout/operations.md#выдача-и-возврат), правило 8 |
| изменение структуры источника поля-псевдонима | значение поля: функция, которая меняет источник, записывает поле заново до первого чтения и до каждого выхода, иначе ошибка в ней | [поле-псевдоним](../types/ownership.md#поле-псевдоним) |
| элемент перемещён (`insert`, сжатие, перевыделение); перенос пишет код: `take` из старого элемента и запись в новый | ссылка, путь которой проходит через этот элемент, в том числе ссылка в память, которой элемент владеет (буфер строки); недействительна со строки `take` | [неинициализированный элемент области](layout/operations.md#частичная-инициализация-и-очистка) |

| заморозка: `take x` в слот `immutable T` | все ссылки и псевдонимы из `x` | [неизменяемость](../immutability.md) |

## До чего доходит вызов `mut`

| От получателя вызов доходит до | С каким правом | Пример |
|---|---|---|
| самого получателя и всего, чем он владеет | `mut` | после `v.append(x)` ссылка `&v[0]` недействительна |
| объекта за полем `layout` с правом `mut` | `mut`, транзитивно | после `s.sqlite3_step()` заимствование `read<db.errmsg>` недействительно: `s.db` — `mut sqlite3` |
| источника записи `holds` | с правом держания, не шире | после `g.next()` у `holds mut<items> generator yield Int` без видимого тела ссылки в `items` недействительны; у `holds edit<items> generator yield Int` действительны ссылки на слоты элементов |
| источника в поле `R<Src> T` структуры | с правом `R` | курсор с полем `mut<Src> Array<T>` |
| источника по цепочке держаний | с самым узким правом на цепочке | курсор держит генератор с `mut`, генератор держит `items` с `edit`: шаг курсора до `items` доходит с `edit` |
| объекта за полем `layout` с правом `read` или `edit`, источника держания `read` или `edit` | с этим правом: структуру вызов не меняет, ссылки на слоты действительны; при `edit` ссылки в память значений элементов — по строке «вызов `edit`» | после шага обычного курсора прежние элементы действительны |

Держание `mut` не теряется ни при каком преобразовании: значение с ним идёт только в параметр, тип которого это
держание пишет.

## Два доступа сразу

| Пара | Правило | Если не доказано |
|---|---|---|
| два поля одного объекта, поля двух объектов, два параметра | не пересекаются, пока общая память не объявлена заимствованием или ссылкой с источником или `layout` | — |
| два читающих аргумента | делят память свободно | — |
| аргумент копируемого типа без `&` (при любом праве) и любой другой | передаётся копией и ни с чем не пересекается | — |
| пишущий аргумент (`edit`, `mut`, `own`, `anchor`, `&edit`, `&mut`, `&out`) и другой аргумент | проверяется при вызове по типам аргументов: два точных пути, которые различает доказанно разный индекс (`&v[0]`, `&v[1]` у `Vector`), — проверки нет; два места, ни одно из которых не может лежать внутри другого (`&c[i]`, `&c[j]` у блочного массива, `t.Nodes.value`), — сравнение адресов; места, одно из которых может лежать внутри другого (два целых узла одного дерева), — ошибка компиляции; в обобщённом коде случай выбирается при каждой подстановке | сравнение слотов при вызове со сбоем `OverlapError` или ошибка компиляции ([совместимость](../types/access-regions.md#совместимость)) |
| получатель с путём в пометке и аргумент-ссылка | сравниваются по частям | ошибка компиляции: у части нет адреса |
| два аргумента-проекции одного значения | не пересекаются, если поля `var` одной не входят в другую | проверка адресов по полям |
| захват многопоточной корутиной и остальной код | только доказательство | ошибка компиляции |
| владелец и значение с держанием `read` или `edit` | владелец читает и пишет значения, создаёт слоты; изменение структуры затрагивает значение, которое держит, по правилу раздела [«Что делает ссылку недействительной»](#что-делает-ссылку-недействительной) | — |
| владелец и значение с держанием `mut`, которым реализация отвечает на держание из контракта | владелец меняет структуру; значение, которое держит, хранит только слот получателя и остаётся действительной | — |
| владелец и генератор с держанием `mut` | владелец меняет структуру источника между шагами; генератор остаётся действительным: на `yield` его кадр теряет ссылки, курсоры и факты о структуре, которые хранил в источнике ([отдача ссылки](../generators.md#отдача-ссылки)) | — |
| владелец и конкретный курсор, который сам двигает слоты (`removing()`, `draining()`) | менять источник можно только через курсор; изменение структуры мимо него затрагивает курсор | — |
| два пишущих указателя-параметра одного множества (`a: edit Items.Item, b: mut Items.Item`) | `apart`: сравниваются названные элементы; досягаемость по указателям в сравнение не входит; случай «один элемент» — отдельная ветка | проверка адресов |
| владелец и курсор с полем `read<Src> Items.Item?` | после вызова `edit` у владельца (вставка, перестановка) курсор действителен; вызов, который освобождает или уводит элементы, затрагивает курсор | — |
| объект и его поле-псевдоним | объект остаётся хозяином источника и меняет его структуру; поле записывается заново | — |
| два значения с держанием одного источника | как две ссылки с теми же правами: действительны одновременно, изменение структуры через одно затрагивает другое | — |
| части одного контракта и его предков | не пересекаются: проверено привязкой | — |
| части двух контрактов, не связанных наследованием | считаются пересекающимися | — |
| структура и поток | структура — одна область: корень и все элементы под ним; право, выполненное через указатель с этим источником, — доступ к области с этим правом | ошибка компиляции ([структура и поток](layout/threads.md#структура-и-поток)) |
| роль над диапазоном области в поле структуры из `layout` и остальной код | пока роль существует, остальные поля этой структуры любой код только читает, и область не заменяется | ошибка компиляции ([роли](layout/threads.md#роли)) |
| `one` и поток | `one X` — один экземпляр на поток; со всем, чем владеют его поля, он составляет одну структуру своего потока; в другой поток `one` не переходит | ошибка компиляции ([`one` и поток](layout/threads.md#one-и-поток)) |
| поток и поток | части ссылок не разделяют потоки: метод с путём конфликтует с любым другим методом объекта | [общая память](../shared.md) |

## Обход

| Заголовок | Держание курсора | Тело цикла может | Прежние элементы после шага |
|---|---|---|---|
| `for x in v` | `holds read<v> Cursor`; `x` — `let` | читать `v`; владелец с правом записи пишет значения и добавляет в коллекцию, добавление которой элементов не перемещает (связный список) | действительны |
| `for x in edit v` | `holds edit<v> Cursor`; `x` — ссылка на элемент | писать значения (`x += 1`; узел дерева — своё значение, не узлы под ним) и добавлять в коллекцию, добавление которой элементов не перемещает (связный список) | действительны |
| `for x in mut v` | `holds mut<v> Cursor`; `x` — ссылка на элемент | менять структуру `v` вызовами коллекции (`take v[i]`, `v.remove(at: i)`); `take x` — ошибка: `x` — ссылка; элемент действителен до первого изменения структуры | недействительны, если шаг или тело меняют структуру `v`; у курсора без видимого тела `next` — всегда |
| `for x in take v` | нет: курсор владеет `v` | `x` — значение, а не ссылка | — |
| `for x in курсор`, `for x in edit курсор` | какое записано в его типе | по праву держания; курсор берётся как `mut`; слово заголовка — знак привязки | по праву держания |
| `for x in генератор`, `for item in edit active(items: list)` | какое записано в его типе | по праву держания; генератор берётся как `mut`; слово заголовка — знак привязки | по праву держания |
| `for item in let c = items.removing()` | конкретный тип, который сам двигает слоты | менять `items` только через `c`; `take item` — ошибка, элемент удаляет `c.remove()`. У курсора `draining()` привязка владеет значением, и `take` допустим | недействительны |

- Курсор, которым реализация отвечает на держание `mut` из контракта, из полей с `Src` хранит один слот получателя.
- `next` возвращает ссылку на одно из мест, которые называет `Src` (`mut fn next -> &Access<Src> Item?`), или «нет
  ссылки»; шаг вручную, результат которого сохраняют, пишется с `&`: `while let x = &it.next()`. Обобщённый код над
  курсором любого вида пишет вызов без `&`: форму даёт тип. Цикл снимает один уровень опционального типа, поэтому элемент `null` — не
  конец обхода ([цикл `for` с итератором](../types/collections.md#цикл-for-с-итератором)).
- Генератор контрактов обхода не соблюдает; итератор для обобщённого кода даёт его метод `iterator()`
  ([генератор как итератор](../generators.md#генератор-как-итератор)).

## Что пишет программист и что выводит компилятор

| Факт | В функции и методе с телом | В контракте, интерфейсе, объявлении без тела |
|---|---|---|
| право параметра и слово права метода | пишется | пишется |
| что именно тело изменяет (сводка, путь до поля) | выводится | пишется путём в пометке |
| форма и источник результата и роли `yield` (`&` или без) | пишется | пишется |
| источник локальной ссылки | выводится из выражения `&` | — |
| держание значения-результата | пишется записью `holds` в типе результата | пишется записью `holds` |
| держание генератора-метода | выводится из тела; путь в пометке — проверяемый предел | пишется путём в пометке |
| требование к аргументу типа (обобщённый код) | выводится в сводку и проверяется при каждой подстановке: одна подстановка допустима, другая нет; под `@erase` — для каждого типа, который допускают ограничения | то же |
| привязка частей к полям | пишется, включая `= none` | — |
| непересечение аргументов | доказывается; иначе проверка при вызове или ошибка компиляции | то же |
| время жизни невладеющих указателей, предусловия операций над слотами | выводится из `layout` | пишется условиями `layout` |
| эффекты и исключения | выводятся | пишутся |

## Где доказательство, где проверка при выполнении

| Свойство | Доказано | Не доказано |
|---|---|---|
| ссылка не использована после изменения структуры источника | компилируется | ошибка компиляции |
| пишущий аргумент не пересекается с другим | компилируется | проверка при вызове, `OverlapError`, или ошибка компиляции ([совместимость](../types/access-regions.md#совместимость)) |
| то же для частей и для захвата многопоточной корутиной | компилируется | ошибка компиляции |
| индекс в границах у коллекции из библиотеки и у `Slice<T>` | проверки нет | проверка при выполнении, `BoundsError` |
| индекс и отрезок `Area<T>` в границах | компилируется | ошибка компиляции (вердикт FLOW, с Z3 и без него) |
| индекс области с разным шагом называет начало слота | компилируется | ошибка компиляции; проверки при выполнении нет, без доказательства индекс принимается только после `assume` |
| безопасность операции компоновки (освобождение, перевыделение, `tie` якоря, `as own`) | компилируется | ошибка компиляции |
| отданная генератором ссылка указывает в объявленный источник | компилируется | ошибка в строке `yield` |
| точки доверия, шесть видов: строка `assume`, условие результата `@asm`, объявление без тела (функция C с правами из `@fill`, код `model`), приведение адреса к элементу множества или к выданному слоту, объявление функции `@abi(c)` с телом, в том числе `shared @abi(c)`, запись `thread var x: own T` со значением не `ImplicitlyDestroyable` | — | принимаются на веру; их перечисляет `efen proofs` ([что такое `layout`](layout/README.md#1-что-такое-layout)) |

Что доказывается по объявлениям `layout`:

| Описано | Доказывается | Кто |
|---|---|---|
| вид и `as` | размер, выравнивание, запись полей до чтения | FLOW |
| число слотов области | индекс в границах | FLOW; что FLOW не доказал — ошибка компиляции, с Z3 и без него: проверки при выполнении нет, а Z3 только снимает проверку, которую FLOW оставил |
| область с разным шагом | слоты занимают `0 ..< x.extent` без промежутков и наложений; каждый индекс называет начало слота | FLOW |
| `lend` / `take` в свой слот | один владелец слота, нет повторной выдачи, возврат только в свой слот | FLOW |
| `used == slots.taken.count` | счёт сходится на каждом выходе; участок не возвращается, пока из него что-то выдано | FLOW |
| `for element in take region` | каждый элемент отдан дальше | FLOW |
| вложенность и выдача | время жизни каждого указателя, четыре свойства жизненного цикла элемента | FLOW |
| `invariants` вида | инвариант верен при каждой передаче значения дальше | FLOW, Z3 |
| цепочка и её инварианты | форма цепочки по записям; инварианты о её узлах и предусловия операций | FLOW; Z3 |
| поля `protected` и сводки функций `open layout` | функция расширения восстанавливает инварианты над `protected` полями; держатели переписаны до вызова, который уничтожает их цель | FLOW |
| указатель из адреса | принадлежность к множеству и к названной структуре | точка доверия |

Для каждого факта записано, кто его установил: FLOW, Z3, точка доверия или проверка при выполнении.

## Чего таблица не обещает

Таблица описывает модель, но доказательства надёжности у модели нет: [алгоритм](layout-algorithm.md) даёт план
доказательства, а не выполненное. Два раунда Критика 2026-11-11 находили в свежих правилах принятые программы с
обращением к освобождённой памяти; правила после них исправлены, но известное отсутствие таких программ — не
доказательство. Вне модели сегодня:

| Область | Состояние |
|---|---|
| структуры без блокировок; освобождение участка менеджера памяти из другого потока; конец потока, куча которого хранит участки с выданными слотами; объекты со счётчиком | вне `layout`: примитивы стандартной библиотеки, доказанные один раз; объекты со счётчиком — отдельная тема ([что `layout` не описывает](layout/threads.md#чего-layout-не-описывает)) |

Не нарушают надёжность: проверки при выполнении (граница индекса, `OverlapError`,
порядок вызовов генератора) и отказ принять безопасную программу.
