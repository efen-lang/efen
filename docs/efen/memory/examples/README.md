# Примеры

Наброски к документу [Адреса и структуры данных](../addresses.md). Записаны в
модели от 2026-09-04; грамматика предварительная.

- `singly-linked-list.efen` — односвязный список без дженериков;
- `singly-linked-list-generic.efen` — он же с параметром типа;
- `doubly-linked-list.efen` — двусвязный: обратная связь, хвост, удаление за O(1);
- `hash-map.efen` — хеш-карта: производный индекс, обход по ячейкам, окно.

Порядок чтения такой же: списки показывают одно население и одну связь, карта —
всё остальное. Правила и обоснования — в документе, здесь только код.

## Что осталось за примерами

Ни один из четырёх не показывает элемент в двух структурах сразу, смешанное
множество и разбор через `is`, требование формы (`as index32`), слабую ссылку и
обобщение через `fn walk<S: set of Entry>`. Источник памяти населения не решён, и
`create` с `remove` стоят на его месте.

Заимствованная ссылка наружу из layout не выдаётся ни в одном примере
намеренно — `types/ownership.md` возврат ссылок запрещает, и вопрос открыт.
Поэтому `find` односвязного списка возвращает `Bool`, а не узел.
