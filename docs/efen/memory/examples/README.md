# Исторические примеры адресной модели 2026-09-04

[Память и layout](../README.md) · [Актуальные примеры компоновки](../layout-examples/README.md)

Эти файлы сохранены как материал старой модели. Они используют отменённые
формы `.pointer`, `inverse`, `region suspend` и старые операции membership и не
являются актуальными примерами языка.

Текущая модель и разобранные варианты находятся в
[примерах компоновки](../layout-examples/README.md).

- `singly-linked-list.efen` — односвязный список без дженериков;
- `singly-linked-list-generic.efen` — он же с параметром типа;
- `doubly-linked-list.efen` — двусвязный: обратная связь, хвост, удаление за O(1);
- `hash-map.efen` — хеш-карта: производный индекс, обход по ячейкам, окно.

Механически заменять имена в этих исходниках нельзя: для hash map отдельно
нужно заново определить rehash, вызовы hash/equality, исключения и временные
состояния.

## Что осталось за примерами

Ни один из четырёх не показывает элемент в двух структурах сразу, смешанное
множество и разбор через `is`, требование формы (`as index32`), слабый указатель и
обобщение через `fn walk<S: set of Entry>`. Источник памяти населения не решён, и
`create` с `remove` стоят на его месте.

Ссылок в Efen нет ([владение](../../types/ownership.md#в-efen-нет-ссылок)), поэтому ни один пример
не выдаёт наружу из layout доступ к узлу. `find` односвязного списка возвращает `Bool`, а не узел.
