# Управление памятью

> Статус: ранние примеры ARC/`dispose` в этом документе исторические. Текущая
> модель различает пользовательский деструктор класса и низкоуровневый
> non-throwing `Disposable`. При исчезновении последнего владельца user
> destructor запускается только внутри неявной `clean`-области, затем выполняется
> `Disposable`; обычный бросающий destructor остаётся явной операцией автора.

[Документация](README.md) · [Словарь](glossary.md) · [Тематический memory guide](memory/README.md) · [Ownership](types/ownership.md) · [Правила доступа к памяти](memory/memory-rules.md)

С одной стороны `Efen` позволяет управлять памятью напрямую, 
а с другой стороны содержит все необходимые абстракции, чтобы скрыть этот процесс.

## Выделение памяти

В общем случае программист не может управлять выделением памяти напрямую.
Классы, интерфейсы и структуры получают память от менеджера неявным образом.

```efen

class Box {
    conforms Constructible

    var value: Int

    @constructor
    fn init(value: Int) -> Self {
        self.value = value
    }
}

// Вызорв конструктора
let box1 = Box(value: 10)
```

```efen
struct Point {
    x: Float
    y: Float
}

// Инициализация структуры
let p1 = Point(x: 1.0, y: 2.0)
```

Когда выражению нужна память, компилятор сам решает по контексту и по стратегиям типа, где лежит значение: на стеке,
в слоте, в элементе множества или в куче. Память он берёт у стратегии `Allocator<Type>`, выбранной для типа:
класса, элемента множества `layout` или области. Стратегию выбирают обычные правила (`provide`, запись программы,
`Resolve`), а по умолчанию она передаёт операции менеджеру памяти `mm`. Так у каждого типа может быть свой
аллокатор ([аллокатор](memory/allocator.md)).

```efen
let box = Box(value: 10)                    // объект класса: память даёт Allocator<Box>
let node = Node<T>(value: take value)       // элемент множества Nodes: память даёт Allocator<Nodes<T>.Item>
```

## Владение и подсчёт ссылок

В `Efen` действует система владения (ownership system), которая работает независимо от стратегии памяти.
Компилятор хранит информацию о владельце объекта в его метаданных
и поддерживает следующие операции с владением:
- Запрос владения (request ownership) или retain (увеличение счетчика ссылок)
- Заимствование (borrowing)
- Клонирование (cloning)
- Освобождение (release)
- Финализация (destruction)
- Возрождение (reclaim)
- Перемещение (move)

Компилятор генерирует эти события для абстракций, которые могут по-разному отреагировать.

### Запрос владения (retain)

Возникает, когда объект создаётся и/или присваивается переменной.
Например:

```efen
class Counter {
    conforms ArcClass
    var value: Int
}

let box1 = Box(value: 10)         // Запрос владения
let box2 = box1                   // псевдоним того же объекта, владелец один
let counter1 = Counter(value: 10) // Запрос владения
let counter2 = counter1           // retain: второй владелец
```

Для объектов с подсчётом ссылок это увеличивает счётчик ссылок на 1.
Объект без подсчёта ссылок (класс по умолчанию) владельца не добавляет: `box2` — псевдоним того же объекта
([связывание существующего значения](types/ownership.md#связывание-существующего-значения)).

### Заимствование (borrowing)

Возникает, когда объект передаётся в функцию или абстракцию, 
которая живёт меньше, чем текущий scope.

```efen
fn useBox(box: Box) {
    print(box.value)
}
let box1 = Box(value: 10) // Запрос владения
useBox(box1)              // Заимствование для чтения
```

Если функция собирается изменить объект, тогда возникает заимствование для записи:

```efen
fn modifyBox(box: mut Box) {
    box.value += 1
}
let box1 = Box(value: 10) // Запрос владения
modifyBox(box1)           // Заимствование для записи
```

### Клонирование (cloning)

Возникает, когда программист явно пишет `clone` у типа со счётчиком ссылок.
```efen
let counter1 = Counter(value: 10) // Запрос владения
let counter2 = clone counter1     // Клонирование: счётчик + 1
let box2 = clone box1             // ошибка: у Box нет счётчика
```

### Освобождение (release)

Возникает, когда объект выходит из области видимости.
Для объектов с подсчётом ссылок это уменьшает счётчик ссылок на 1.
Если счётчик ссылок достигает нуля, тогда объект финализируется.
Для объектов без подсчёта ссылок освобождение происходит автоматически,
когда объект выходит из области видимости, и финализация происходит сразу.

### Финализация (destruction)
Возникает, когда объект уничтожается.
Для объектов с подсчётом ссылок это происходит, когда счётчик ссылок достигает нуля.
Для объектов без подсчёта ссылок это происходит, когда объект выходит из области видимости.

### Возрождение (reclaim)
Возникает, когда объект восстанавливается из состояния "мертв".
Для объектов с подсчётом ссылок это происходит, когда объект снова получает владельца.
Для объектов без подсчёта ссылок это может быть применимо, при условии, что объект получит нового владельца.

### Перемещение (move)

Операция перемещения возникает, когда программист явным образом перемещает объект.
```efen
let box1 = Box(value: 10)   // Запрос владения
let box2 = take box1        // Перемещение
```

Перемещение передаёт владение от одного идентификатора другому, 
и делает первый идентификатор недействительным.

Для объектов с подсчётом ссылок перемещение не влияет на счётчик ссылок.

### Вычисление владения

Компилятор привязывает владение к области видимости, 
а также запоминает строки участков кода, где происходят события,
связанные с владением.

Например:

```efen
fn example {
    let box1 = Box(value: 10)   // Box живёт в области видимости example
}                               // Освобождение box1
```

Для объектов с агрегатами, владение считается по времени жизни объекта.
Компилятор следит, чтобы время жизни агрегата не было меньшим, чем время жизни всего объекта.

```efen
class Box {
    conforms Constructible

    implements Disposable

    var point: Point

    @constructor
    fn init(value: Point) -> Self {
        self.point = value
    }
    
    fn dispose {
        print("Box is being destroyed")
    }
    
    fn print {
        print("Point(x: ${point.x}, y: ${point.y}")
    }
}

fn example {
    let p1 = Point(x: 1.0, y: 2.0) // Point живёт в области видимости example
    let box1 = Box(value: p1)      // Box живёт в области видимости example
                                   // Box владеет Point на чтение
}                                  // Освобождение box1 и p1
```

## Особые случаи

Слабые указатели пока не входят в текущую нормативную модель. Их связь с `origin`,
владением и стратегиями управления памятью остаётся отдельной отложенной темой;
ключевое слово или иной source-синтаксис для них не принят.

## Абстракции без подсчета ссылок

Класс по умолчанию не использует подсчёт ссылок: счётчик появляется только строкой `conforms ArcClass`
([классы](classes.md#управление-памятью)). Без счётчика объект тонкий, заголовка у него нет.
На такие абстракции действуют проверки владения (ownership checks).
То есть компилятор гарантирует, что правила владения не нарушаются, 
но в таком случае у объектов никогда не может быть более одного владельца.

Информация о владении записывается в метаданных идентификатора объекта, 
и может быть использована во время компиляции для оптимизаций.

## Подсчет ссылок

> Черновик. Классы со счётчиком — пакет std ([роли lang, рантайма и std](runtime/lang-roles.md));
> раздел перепишется, когда пакет будет написан.

`Efen` поддерживает подсчёт ссылок (reference counting) для управления временем жизни объектов.
Название принято по традиции: считаются владельцы объекта; ссылка в Efen не хранится в поле и не переживает функцию, которая её получила
([владение](types/ownership.md#ссылки-только-внутри-функции)).
Способ подсчёта выбирает аспект, который реализует `ArcClass`; какие пакеты могут его дать, контракт перечисляет в `from`.

Класс со счётчиком пишет `conforms ArcClass`; без этой строки счётчика у класса нет. `ArcClass` — контракт без
требований, который разрешает [реализацию извне](contracts.md#реализация-извне): поле счётчика и функции над ним
даёт аспект, по умолчанию `ArcCounter` пакета runtime. Счётчик автоматический (ARC, Automatic Reference Counting):
аспект реализует контракт `ArcOperations` с методами `retain` и `release`, а их вызовы расставляет компилятор.
Счётчик не атомарный; общий для нескольких потоков — тема [общих классов](shared.md). Соответствие `Cloneable`
классу тоже даёт аспект, поэтому `clone` у такого класса увеличивает счётчик:

```efen
@default
aspect ArcCounter {
    implements ArcClass

    // Шаг построения класса и методы, вызовы которых расставляет компилятор
    conforms ClassDefinitionHandler, ArcOperations

    // Поле, которое аспект добавляет в класс; видно только аспекту
    private var refCount: UInt

    mut fn retain {
        refCount += 1
    }

    mut fn release {
        if unlikely(refCount == 0) {
            error("Release called on object with refCount 0")
        }
        refCount -= 1
        if refCount == 0 {
            // уничтожение объекта: деструкторы, поля, память (disposable.md)
        }
    }
}
```
