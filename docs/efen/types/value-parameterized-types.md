# Типы с compile-time параметрами-значениями

[Типы](type.md) · [Generics](../generics.md) · [Enum](enum.md) ·
[Variant](variant.md)

Efen позволяет передавать в generic не только типы, но и любые значения,
доступные во время компиляции. Значение enum, число, строка, логическое значение,
origin, contract, interface, strategy и другая compile-time сущность могут быть
параметрами объявления типа.

Это обычная модель generic Efen: декларация и полный канонический список
compile-time аргументов образуют один конкретный тип. Отдельная система типов
для этого механизма не вводится.

## Тип, индексированный enum-значением

```efen
enum UserKind {
    root
    admin
    other
}

class User<Kind: UserKind> {
    let id: UserId
    let name: String
}
```

Объявление создаёт семейство конкретных типов:

```efen
User<root>
User<admin>
User<other>
```

Эти типы имеют разные identities, даже если backend выбрал для них одинаковую
физическую representation. Между ними нет неявного преобразования.

Функция может принять только определённую категорию:

```efen
fn changeSystemConfiguration(user: &read User<root>) {
    // Доступ разрешён только User<root>.
}
```

Несколько категорий выражаются обычным structural union:

```efen
fn manageUsers(user: &read (User<root> | User<admin>)) {
    // ...
}
```

Общий код объявляет тот же параметр:

```efen
fn displayProfile {
    generic Kind: UserKind
    param user: &read User<Kind>

    // ...
}
```

Внутри конкретной инстанциации `Kind` является compile-time значением. Условия
`where`, `#if`, выбор representation и генерация членов могут читать его по
обычным правилам generic.

## `other` не является скрытым wildcard

`other` — обычное значение `UserKind`, а не автоматическое дополнение множества.
Операция, которая читает более подробную runtime-роль, сама отображает `root` и
`admin` в специальные типы, а остальные значения — в `User<other>`.

Если программе нужна исходная подробная роль, она хранится обычным полем
значения. Generic-параметр выражает только статически значимую категорию.

## Граница runtime

Runtime-значение нельзя непосредственно использовать как generic-аргумент:

```efen
let kind = readUserKind()
// User<kind> — ошибка: kind не является compile-time значением.
```

Когда категория становится известна только во время выполнения, проверяющая
операция возвращает закрытый `variant`:

```efen
variant ClassifiedUser {
    root { value: User<root> }
    admin { value: User<admin> }
    other { value: User<other> }
}
```

После `match` каждая ветка получает соответствующий конкретный тип. Runtime-тег
принадлежит `ClassifiedUser`; отдельный флаг внутри уже известного
`User<root>` не требуется.

Generic-параметр сам по себе не аутентифицирует пользователя. Граница, создающая
специальный тип, обязана проверить доверенный источник, а владелец типа —
ограничить видимость constructors и factories так, чтобы внешний код не мог
обойти проверку. После такой границы наличие `User<root>` означает, что проверка
уже выполнена.

## Числовые и другие значения

Тот же механизм применим к числам и другим compile-time значениям:

```efen
class Matrix {
    generic Rows: Int { Rows > 0 }
    generic Columns: Int { Columns > 0 }
}
```

`Matrix<3, 4>` и `Matrix<4, 3>` являются разными конкретными типами. Выражение
generic-аргумента сначала вычисляется и канонизируется, поэтому два выражения с
одинаковым compile-time результатом обозначают одну инстанциацию.

Зависимость от конкретного runtime-объекта не возникает скрытно. Если свойство
runtime-значения нужно проверить, Efen использует predicate, `refine()`,
typestate, origin или proof compiler; runtime-переменная не превращается в
неявную generic identity.

## Изменение категории

Generic-аргумент является частью identity типа и не изменяется присваиванием
поля. Операция повышения или понижения категории проверяет свои условия и
возвращает значение другого конкретного типа:

```text
User<other> -> User<admin>
User<admin> -> User<root>
```

Перенос ownership, сохранение прежнего значения и возможные исключения
подчиняются обычной сигнатуре этой операции. Compiler не меняет тип существующих
aliases скрытно.

## Идентичность и HIR

Ключ concrete generic-инстанциации содержит:

1. identity generic-декларации;
2. упорядоченные канонические аргументы;
3. для аргумента-значения — его compile-time тип и `HirComptimeValueId`;
4. выбранные strategy witnesses и пакет конфигурации, если они влияют на
   инстанциацию.

Для `User<root>` enum-аргумент сохраняет identity `UserKind.root`, а не только
целочисленный tag выбранной backend representation. Межмодульный ключ обязан
быть устойчивым и типизированным.

Monomorphization и erasure являются способами lowering. Они не объединяют
наблюдаемо разные типы и не меняют их generic identity. Если значение параметра
нужно runtime-коду, compiler материализует необходимую информацию по обычным
правилам выбранного lowering и не скрывает возникающие contexts или exceptions.

## Диагностика

Frontend отклоняет:

- runtime-выражение в позиции compile-time generic-аргумента;
- аргумент неправильного compile-time типа;
- ложное ограничение параметра или `where`;
- неявное преобразование между разными инстанциациями;
- обращение к недоступному constructor или factory специальной категории;
- использование generic-инстанциации без канонического межмодульного ключа.
