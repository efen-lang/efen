# Константы

`Efen` поддерживает объявление констант с помощью ключевого слова `const`.

Константы должны быть инициализированы при объявлении и не могут быть изменены впоследствии.

```efen
const pi = 3.14159
const appName = "MyApp"
const maxUsers: Int = 1000
```

## Основные характеристики констант

### Неизменяемость

Значение константы нельзя изменить после инициализации:

```efen
const version = "1.0.0"

// Ошибка компиляции!
version = "2.0.0"
```

### Инициализация при объявлении

Константы должны быть инициализированы сразу при объявлении:

```efen
// Правильно
const timeout = 5000

// Ошибка компиляции - константа не инициализирована
const maxRetries: Int
```

### Вывод типа

Тип константы может быть выведен автоматически или указан явно:

```efen
// Автоматический вывод типа
const port = 8080              // Int
const host = "localhost"       // String
const enabled = true           // Bool

// Явное указание типа
const maxConnections: Int = 100
const timeout: Float = 30.0
const mode: String = "production"
```

### Ширина числовых типов

`Int` и `UInt` имеют ширину указателя целевой платформы: 32 разряда на
32-разрядной цели и 64 разряда на 64-разрядной. Для данных с фиксированным
форматом используются `Int8`, `Int16`, `Int32`, `Int64` и соответствующие
беззнаковые типы. Размеры коллекций и разности адресов используют `UInt` и
`Int`, если API не требует конкретной фиксированной ширины.

`Float` — IEEE 754 binary64 на всех целях, `Float32` — binary32. Поэтому
точность обычного вещественного литерала не зависит от разрядности указателя.
Как они считают — [вещественные числа](#вещественные-числа).

Для библиотек на C есть ещё `Int128`, `UInt128`, `Float128` (IEEE 754
binary128), `Float80` (расширенный формат x86) и `Complex<T>` с вещественным
`T`; `CLongDouble` — отдельный тип, который на каждой цели устроен как
`long double` её компилятора C ([библиотеки на C](../foreign.md)). Имена
предложены и ещё не утверждены.

## Целые без проверок

Обычные целые проверяются в любой сборке, отладочной и выпускной (Edmond 2026-11-02): переполнение `+`, `-`, `*`,
унарного минуса и деления `Int.min / -1` бросает `OverflowError`, деление на ноль — `DivisionByZeroError`, сдвиг
на ширину типа и больше — `OverflowError`. Сборка не меняет того, что делает программа: Efen не повторяет Rust, у
которого отладочная сборка бросает, а выпускная молча заворачивает.

Где переполнение — часть алгоритма (хеши, контрольные суммы, генераторы случайных чисел), берут целое без
проверок: `RawInt`, `RawInt8`, `RawInt16`, `RawInt32`, `RawInt64` и беззнаковые `RawUInt`, `RawUInt8`,
`RawUInt16`, `RawUInt32`, `RawUInt64` (Edmond 2026-11-02). Это не обёртка над обычным целым, а отдельный тип той
же ширины: в памяти `RawUInt32` и `UInt32` — одни и те же 32 бита, отличаются только операции.

```efen
fn fnv1a(data: [RawUInt8]) -> RawUInt32 {
    var hash: RawUInt32 = 2166136261
    for byte in data {
        hash = (hash ^ RawUInt32(byte)) * 16777619
    }
    return hash
}
```

Операции `Raw`-типов:

- `+`, `-`, `*` и унарный минус заворачиваются: результат — младшие биты точного, `RawUInt32.max + 1 == 0`,
  `-RawInt32.min == RawInt32.min`. Составное присваивание и `++` считают так же: `h += 1` заворачивается. Так же заворачивается `RawInt32.min / -1`: результат `RawInt32.min`, а
  `RawInt32.min % -1 == 0`.
- Деление и остаток на ноль бросают `DivisionByZeroError`, как у обычных целых: результата у машины нет, а
  неопределённого поведения в Efen нет нигде.
- Сдвиг берёт число сдвига по модулю ширины: `h << 33` для `RawUInt32` равно `h << 1`. Число сдвига — отдельный
  операнд любого целого типа, обычного или `Raw`, и правило смешения на него не распространяется: в `h << r` для
  `r: Int` ошибки нет. Отрицательное число читается своими младшими битами: `h << n` для `n == -1` равно `h << 31`.
  `>>` у знаковых типов арифметический, у беззнаковых логический, как у обычных целых: `RawInt32(-8) >> 1 == -4`. Так сдвигает процессор у 32- и 64-разрядных
  чисел (x86-64 берёт младшие 5 или 6 битов числа, AArch64 — остаток от деления на ширину); у 8- и 16-разрядных
  Efen берёт остаток сам, и результат на всех целях одинаков.
- Сравнения, `<=>`, `&`, `|`, `^` и `~` — те же, что у обычных целых; `<=>` даёт обычный `Int`.
- У каждого типа есть `.min` и `.max`, как у обычных целых. `Raw`-типы равны, сравнимы и хешируются так же, как
  обычные, и печатаются так же.

`Raw`-тип и обычное целое не смешиваются в одном выражении: `h + x` для `h: RawUInt32` и `x: UInt32` — ошибка
компиляции. Граница между проверяемым и непроверяемым кодом видна в тексте. Переход только явный, и гарантию даёт
тип, в который переводят:

```efen
let x: Int64 = 0x1_0000_0001
let h = RawUInt32(x)   // 1: в Raw-тип значение берётся по модулю 2³²
let r: RawInt32 = -1
let s = RawUInt32(r)   // 0xFFFFFFFF: те же биты
let u = UInt32(r)      // бросает OverflowError: UInt32 не держит -1
```

Переход в `Raw`-тип берёт значение по модулю 2ᴺ, где N — ширина типа: при сужении остаются младшие биты, при
расширении знаковое значение расширяется знаком, `RawUInt64(RawInt8(-1)) == RawUInt64.max`. «Те же биты» верно
только при одной ширине. Переход между `Raw`-типом и обычным той же ширины и знака ничего не стоит: процессор не
выполняет ни одной инструкции.

Целый литерал берёт `Raw`-тип из контекста, в том числе из преобразования `RawUInt8(300)`, и должен в нём
помещаться: `let h: RawUInt8 = 256` и `RawUInt8(300)` — ошибки компиляции, а не обрезка, потому что литерал —
текст программы, а не значение, пришедшее извне.

## Вещественные числа

`Float` и `Float32` считают по IEEE 754 (Edmond 2026-11-02): каждая операция округляет точный результат до
ближайшего числа своего типа, а из двух одинаково близких берёт то, у которого младший бит мантиссы ноль.

### Особые значения

Переполнение, деление на ноль и операция без числового результата дают особое значение, а не исключение:

```efen
let big = 1.0e308 * 10.0   // inf
let low = -1.0 / 0.0       // -inf
let bad = 0.0 / 0.0        // NaN
```

Особые значения называют константы `Float.INFINITY` и `Float.NAN` (у `Float32` так же); бесконечность со знаком
минус — `-Float.INFINITY`. Целые типы при переполнении бросают `OverflowError`, вещественные — нет. Так считают все распространённые языки,
и Rust одинаково в отладочной и выпускной сборке. Без исключений вещественный цикл векторизуется, и для него
возможен [`@accumulators`](../blocks/loops.md#порядок-вещественной-свёртки-accumulatorsn).

### Сравнение

`==`, `!=`, `<`, `<=`, `>`, `>=` сравнивают по IEEE 754: NaN не равен ничему, даже себе, и каждое сравнение с NaN
даёт `false`, кроме `!=`. `-0.0 == 0.0`. `Float` и `Float32` — `Equatable` и `Comparable` по этим правилам, но не
`Hashable`: ключ NaN не нашёлся бы в словаре, потому что не равен себе.

```efen
let nan = 0.0 / 0.0
nan == nan        // false
nan.isNaN         // true
```

`a <=> b` даёт `-1`, `0` или `1` и не бросает. Для чисел без NaN ответ совпадает с `<` и `==`, поэтому
`-0.0 <=> 0.0` даёт `0`. NaN равен любому NaN и больше любого числа, включая `inf`: `<=>` упорядочивает все значения,
и сортировка через `Comparable`, в том числе сортировка std, ставит NaN в конец (Edmond, 2026-11-02).

```efen
1.0 <=> nan       // -1
nan <=> nan       // 0
nan <=> inf       // 1
```

`totalOrder(a, b)` упорядочивает все значения, как требует IEEE 754 для сортировки: `-NaN < -inf < … < -0.0 < 0.0
< … < inf < NaN`. Вещественное число, в котором NaN не бывает, — отдельный тип, и в языке его пока нет.

`min` и `max` — операции `minimum` и `maximum` IEEE 754-2019: NaN в любом аргументе даёт NaN, а `-0.0` меньше
`0.0`. Поэтому они ассоциативны и коммутативны, и свёртка `best = min(best, x)` даёт одно значение в любом порядке,
кроме знака и содержимого NaN ([циклы](../blocks/loops.md#порядок-вещественной-свёртки-accumulatorsn)). На AArch64
это одна команда `fmin`; на x86-64 такой команды нет, и LLVM 18 строит `minimum` для четырёх `Float32` из 5 команд
на `x86-64-v3` и из 10 на `x86-64-v2`.

### Остаток

`a % b` — остаток деления с отброшенной дробной частью частного, как `fmod` в C: знак у него как у `a`, и результат
точный, без округления. `x % 0.0` и `inf % x` дают NaN.

```efen
5.5 % 2.0     // 1.5
-5.5 % 2.0    // -1.5
```

Остаток IEEE 754, при котором частное округляется до ближайшего целого, даёт функция std. Как печатаются вещественные числа, тоже решает std.

### Преобразования

- `Int(f)` отбрасывает дробную часть, то есть округляет к нулю: `Int(2.9) == 2`, `Int(-2.9) == -2`. Диапазон
  проверяется после этого: `Int8(-128.9) == -128`. NaN и число вне диапазона `Int` бросают `OverflowError`, и
  сообщение называет причину: NaN или выход за диапазон. Так же преобразуется в любой другой целый тип:
  `UInt8(300.0)` бросает. Округление другим способом — отдельная функция std.
- `Float(i)` округляет целое до ближайшего `Float`, как любая операция, и не бросает: `Float(9_007_199_254_740_993)`
  равно `9_007_199_254_740_992.0`, потому что `Float` хранит 53 бита мантиссы. `Float(exactly: i) -> Float?` даёт
  `null`, если целое не представимо точно. `Float32(i)` и `Float32(exactly: i)` устроены так же.
- `Float(x)` из `Float32` точно. `Float32(f)` из `Float` округляет, число вне диапазона `Float32` становится `inf`
  или `-inf` (Edmond, 2026-11-02).

## Числовые литералы

Целый литерал пишется в десятичной, шестнадцатеричной или двоичной записи: `1_000`, `0xFF`, `0b1010`. Дробный
литерал — цифры, точка и цифры: `2.5`, `1_000.25`. `_` между цифрами ничего не значит.

Вещественный литерал с порядком пишется через `e` или `E` и степень десяти, со знаком или без (Edmond 2026-11-02):

```efen
let avogadro = 6.022e23
let tiny = 1.0e-9
let billion = 1e9          // Float: литерал с порядком вещественный и без точки
```

Шестнадцатеричный вещественный литерал задаёт биты точно: мантисса в шестнадцатеричной записи, после `p` или `P` —
степень двойки в десятичной записи. `p` в нём обязательна: без неё точка после шестнадцатеричного числа начинает
обращение к члену, `0xFF.description`. Литерал, мантисса которого не помещается в тип без округления
(`0x1.00000000000001p0` для `Float`), — ошибка (Edmond, 2026-11-02).

```efen
let three = 0x1.8p1        // 1.5 × 2¹ = 3.0
let least = 0x1p-1074      // наименьшее положительное Float
```

Тип вещественного литерала — `Float`. Там, где ожидается `Float32`, литерал получает тип `Float32` и округляется до
него один раз, из своей записи, а не через `Float`. Литерал ожидает тип:

- переменной, поля или результата, которому присваивается;
- параметра вызова, после выбора перегрузки; целый литерал никогда не выбирает перегрузку с вещественным параметром;
- другого операнда бинарного оператора: в `x * 0.1` при `x: Float32` литерал — `Float32`, а `2 * width` при
  `width: Float` — ошибка, как `let b: Float = 2` (Edmond, 2026-11-02).


```efen
let x: Float32 = 0.1       // ближайшее к 0.1 число Float32
let b: Float = 2           // ошибка: целый литерал там, где ожидается Float; пишут 2.0
```

- Целый литерал там, где ожидается вещественный тип, — ошибка (Edmond 2026-11-02).
- Литерал, который округлился бы до бесконечности в своём типе (`1e400`), — ошибка. Литерал не ноль, который
  округлился бы до нуля (`1e-400`), — тоже ошибка (Edmond, 2026-11-02). Оба правила проверяются в окончательном типе литерала:
  `let x: Float32 = 1e-50` — ошибка.
- Литерал с порядком там, где ожидается целый тип, — ошибка: `let n: Int = 1e9` не собирается.
- После десятичных цифр `e` или `E`, за которыми идёт цифра или знак с цифрой, всегда начинают порядок, поэтому
  [суффикс литерала](../type-aliases.md) так не начинается: `2e5` — число, а не `2` с суффиксом `e5`. В
  шестнадцатеричном `0x1e5` буква `e` — цифра.
- `_` разрешён и между цифрами порядка: `1e1_0`.
- Литерал с суффиксом подчиняется тем же правилам: для `type Meters: Float { suffix m }` пишут `5.0m`, а `5m` —
  ошибка (Edmond, 2026-11-02).

## Область видимости констант

### Глобальные константы

Константы, объявленные на уровне модуля, доступны везде в модуле:

```efen
// В файле config.efen
const API_URL = "https://api.example.com"
const API_VERSION = "v1"
const MAX_RETRIES = 3

fn makeRequest {
    let url = API_URL + "/" + API_VERSION
    // Константы доступны
}
```

### Локальные константы

Константы могут быть объявлены внутри функций и блоков:

```efen
fn calculate {
    const PI = 3.14159
    const RADIUS = 10.0

    let area = PI * RADIUS * RADIUS
    return area
}

// Вне функции PI недоступна
```

### Константы в классах

Константы класса уже принадлежат самому классу и не требуют `static`:

```efen
class MathConstants {
    const PI: Float = 3.14159265359
    const E: Float = 2.71828182846
    const GOLDEN_RATIO: Float = 1.61803398875
}

// Использование
let circumference = 2.0 * MathConstants.PI * radius
```

### Константы в контрактах и интерфейсах

Контракты и интерфейсы могут определять константы:

```efen
contract NetworkConfig {
    const DEFAULT_PORT: Int = 8080
    const TIMEOUT_MS: Int = 5000
}

interface HttpClient {
    const MAX_REDIRECTS: Int = 10
    const USER_AGENT: String = "EfenClient/1.0"

    fn get(url: String) -> Response
}
```

## Compile-time константы

`const` требует, чтобы compiler вычислил значение при компиляции и
materialized его в продукте. Если вычислить и зашить значение нельзя, это
ошибка компиляции; `const` не превращается молча в runtime `let`.

```efen
const SECONDS_PER_DAY = 60 * 60 * 24        // Вычислено в compile-time
const CONFIG_PATH = "/etc/" + "app.conf"    // Вычислено в compile-time
const IS_PRODUCTION = true && !false        // Вычислено в compile-time

// Компилятор встроит готовые значения в бинарник
```

### Compile-time выражения

В константах можно использовать compile-time выражения:

```efen
const BUFFER_SIZE = 1024 * 1024              // 1 МБ
const MAX_USERS = BUFFER_SIZE / 16           // Вычислено из другой константы
const VERSION_STRING = "v" + "1.0.0"         // Конкатенация строк

// Условные выражения
const LOG_LEVEL = if DEBUG_MODE { "debug" } else { "info" }
```

## Константные массивы и коллекции

Можно создавать неизменяемые коллекции:

```efen
const SUPPORTED_FORMATS = ["json", "xml", "yaml"]
const ERROR_CODES = [400, 401, 403, 404, 500]
const CONFIG_MAP = ["host": "localhost", "port": 8080]

// Элементы нельзя изменить
// ERROR_CODES[0] = 200  // Ошибка компиляции!
```

## Константы и ссылочные типы

При работе со ссылочными типами константа означает, что сама ссылка не может быть изменена, но объект может быть изменяемым:

```efen
class Config {
    var port: Int
    var host: String
}

const config = Config(port: 8080, host: "localhost")

// Можно изменить свойства объекта
config.port = 9000  // OK

// Но нельзя заменить саму ссылку
config = Config(port: 3000, host: "127.0.0.1")  // Ошибка!
```

Для полной неизменяемости используйте `let` с неизменяемыми свойствами:

```efen
class ImmutableConfig {
    let port: Int
    let host: String
}

const config = ImmutableConfig(port: 8080, host: "localhost")

// Нельзя изменить ни ссылку, ни свойства
config.port = 9000   // Ошибка!
config = ...         // Ошибка!
```

## Публичные и приватные константы

Константы могут иметь модификаторы доступа:

```efen
// Публичная константа - доступна из других модулей
public const API_VERSION = "v2"

// Приватная константа - только внутри модуля
private const INTERNAL_BUFFER_SIZE = 4096

// Защищённая константа - доступна в подклассах
protected const DEFAULT_TIMEOUT = 30000
```

## Именование констант

Рекомендации по именованию:

```efen
// Глобальные константы - UPPER_CASE
const MAX_CONNECTIONS = 100
const API_BASE_URL = "https://api.example.com"
const DEFAULT_TIMEOUT = 5000

// Математические константы - PascalCase или lowercase
const Pi = 3.14159
const pi = 3.14159
const GoldenRatio = 1.618

// Конфигурационные значения - UPPER_CASE
const DATABASE_HOST = "localhost"
const DATABASE_PORT = 5432
```

## Константы в модулях

Организация констант в отдельных модулях:

```efen
// constants/network.efen — модуль constants::network
const DEFAULT_PORT = 8080
const TIMEOUT_MS = 5000
const MAX_RETRIES = 3

// constants/limits.efen — модуль constants::limits
const MAX_FILE_SIZE = 10 * 1024 * 1024  // 10 МБ
const MAX_USERS = 1000
const MAX_CONCURRENT_REQUESTS = 100

// Использование в другом модуле пакета
use constants::network as network
use constants::limits as limits

fn startServer {
    listen(network::DEFAULT_PORT)
    setMaxUsers(limits::MAX_USERS)
}
```

## Перечисления как группы констант

Для связанных констант используйте перечисления:

```efen
enum HttpStatus {
    OK = 200,
    NOT_FOUND = 404,
    SERVER_ERROR = 500
}

enum LogLevel {
    DEBUG = 0,
    INFO = 1,
    WARNING = 2,
    ERROR = 3
}

// Использование
if status == HttpStatus.OK {
    // ...
}
```

## Константы vs let

Различия между `const` и `let`:

| Характеристика | const | let |
|----------------|-------|-----|
| Время вычисления | Compile-time, обязательно | Runtime |
| Область видимости | Глобальная или локальная | Локальная |
| Использование | Значения, известные заранее | Вычисляемые значения |
| Оптимизация | Встраивается в код | Хранится в памяти |

```efen
// const - значение известно заранее
const MAX_SIZE = 1024

// let - значение вычисляется в runtime
let currentSize = calculateSize()

// let для неизменяемых локальных переменных
fn process {
    let input = readInput()  // Вычислено в runtime
    let result = input * 2   // Неизменяемая переменная
}
```

## Лучшие практики

1. **Используйте UPPER_CASE для глобальных констант**
   ```efen
   const MAX_RETRIES = 3
   const API_ENDPOINT = "https://api.example.com"
   ```

2. **Группируйте связанные константы** в свой модуль-файл
   ```efen
   // database/config.efen — модуль database::config
   const HOST = "localhost"
   const PORT = 5432
   const MAX_CONNECTIONS = 10
   ```

3. **Предпочитайте константы magic numbers**
   ```efen
   // Плохо
   if status == 200 { }

   // Хорошо
   const HTTP_OK = 200
   if status == HTTP_OK { }
   ```

4. **Используйте константы для конфигурации**
   ```efen
   const DEBUG_MODE = true
   const LOG_TO_FILE = false
   const CACHE_ENABLED = true
   ```

5. **Документируйте неочевидные константы**
   ```efen
   // Максимальное количество попыток переподключения
   // перед выбросом исключения
   const MAX_RECONNECT_ATTEMPTS = 5

   // Таймаут в миллисекундах для HTTP-запросов
   const HTTP_TIMEOUT_MS = 30000
   ```

## Ограничения

1. Константы должны быть инициализированы при объявлении
2. Значение константы нельзя изменить после инициализации
3. Константы не могут быть reassigned
4. Для compile-time констант значение должно быть вычислимо во время компиляции
