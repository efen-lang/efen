# Псевдонимы и новые типы

Псевдоним даёт существующему типу другое имя. Объявление `type`, в отличие
от псевдонима, создаёт новый отдельный тип.

## Синтаксис

```efen
alias NewTypeName = ExistingType
alias StringMap = [String: Int]
```

Псевдоним и исходный тип взаимозаменяемы. Псевдоним можно объявить в модуле,
функции или блоке; его имя подчиняется обычным правилам области видимости.

```efen
module

alias UserID = Int
alias UserName = String

```

## Новый тип

`type` создаёт отдельную номинальную идентичность на основе существующего типа:

```efen
type UserId: Int

type Percentage: Float {
    value >= 0.0 && value <= 100.0
}
```

Блок предиката необязателен. Проверяемое значение называется `value`. Базовый
тип и новый тип не взаимозаменяемы: обычное присваивание требует точного совпадения.
Явный `.refine()` проверяет предикат, а автоматический переход возможен только
через отдельно объявленную прямую стратегию `Coerce<Source>`.

## Типы со скрытой реализацией: `opaque`

`opaque` скрывает связь с внутренним конкретным типом за опубликованным
набором требований. Модификатор ставится перед видом объявления; сегодня это
`type` или именованная `projection`:

```efen
public opaque type Buffer<T>:
    Iterable<Item: T>
= Array<T>
```

Снаружи области раскрытия `Buffer<T>` является отдельным именованным типом,
соответствующим `Iterable<Item: T>`. Внутри области раскрытия компилятор знает,
что это `Array<T>`, и разрешает операции с внутренним типом напрямую.

Вне области раскрытия модуль публикует для компилятора представление для двоичного интерфейса (ABI), правила
владения и реализации требований контракта, но не раскрывает программе имя
внутреннего типа. Вызов метода контракта связывается с опубликованной реализацией и
может быть прямым вызовом или функцией-посредником; обязательная таблица виртуальных методов не требуется.

Область раскрытия задаётся отдельно от видимости имени:

```efen
public opaque(private) type LocalBuffer<T>:
    Iterable<Item: T>
= Array<T>

public opaque(internal) type PackageBuffer<T>:
    Iterable<Item: T>
= Array<T>
```

`private` раскрывает внутренний тип только объявившему модулю, `internal` — всем
модулям текущего пакета. По умолчанию используется `opaque(private)`. Более
широкая область раскрытия, чем `internal`, запрещена. Начальный `public` в
примерах управляет доступностью имени и не раскрывает представление.

Стратегия для `opaque type` может объявлять публичные функции: внешний код вызывает их у значения опубликованного
типа, как функции контракта.

Для `opaque projection` опубликованный набор членов состоит из её объявленных
полей и доступных методов, а скрытая связь — из исходного типа после `for`.
Сама проекция по-прежнему предоставляет доступ к той же памяти без копирования; подробнее
см. [проекции](projection.md#opaque-projection).

Тип `opaque` может иметь параметры. Его внутренний тип может зависеть от параметров,
но для каждой инстанциации обязан удовлетворять всем опубликованным контрактам.

`opaque type` не предоставляет бинарную совместимость при замене внутреннего
типа. Такое изменение инвалидирует зависимые продукты и требует их
перекомпиляции. Компилятор не обязан применять упаковку или косвенное хранение.

<a id="opaque-результат"></a>

### Результат со скрытым типом

Функция может скрыть конкретный тип результата без объявления общего имени:

```efen
fn tokens(text: String) -> opaque ValueIterator<Item: Token> {
    return TokenScanner(text: text)
}
```

Вызывающий код видит только соответствие `ValueIterator<Item: Token>`, а компилятор
сохраняет скрытый конкретный тип и может использовать статическую
диспетчеризацию.

Разные пути возврата могут производить разные конкретные типы, если каждый из
них удовлетворяет опубликованным контрактам:

```efen
fn tokens(fast: Bool) -> opaque ValueIterator<Item: Token> {
    if fast {
        return FastScanner()
    }

    return CompactScanner()
}
```

В этом случае скрытым конкретным типом результата становится синтезированный
структурное объединение `FastScanner | CompactScanner`. Это законно, только когда
связанные параметры контракта совпадают для всех составляющих типов и компилятор может
синтезировать каждую требуемую операцию структурного объединения. Иначе разные типы
возврата являются ошибкой. Синтезированное объединение хранит метку активного типа и направляет
операции контракта к его реализации. Этот выбор при выполнении возникает
из-за разных путей возврата; сам контракт не становится интерфейсом времени
выполнения.

Именованный тип со скрытой реализацией нужен, когда несколько объявлений должны назвать один и
тот же скрытый тип:

```efen
opaque type TokenStream:
    ValueIterator<Item: Token>
= TokenScanner

fn tokens(text: String) -> TokenStream
fn emptyTokens -> TokenStream
```

Каждое отдельное `-> opaque Contract` вводит собственную идентичность
скрытого результата. Она не совпадает со скрытым типом результата другого объявления,
даже если их внутренние типы одинаковы.

## Структуры данных

Время жизни владеющих свойств (`own`) структуры данных считается равным времени жизни самой структуры.

## Циклические связи

Ссылка в Efen бывает только внутри тела функции ([владение](ownership.md#ссылки-только-внутри-функции)), поэтому поле структуры не может указывать
на чужое значение, например на родителя. Связи, которые образуют цикл, — родитель и дети, соседи в
двусвязном списке, рёбра графа — строятся указателями [`layout`](../memory/layout/README.md#справочник-правил): указатель знает
своё множество, а компилятор проверяет, что элемент жив и права есть.

Прежняя запись `parent: Node anchored` из языка убрана вместе со ссылками.
