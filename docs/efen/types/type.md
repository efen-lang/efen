# Алиасы и новые типы

Алиасы типов позволяют создавать новые имена для существующих типов, что может улучшить читаемость и понимание кода.

## Синтаксис

```efen
alias NewTypeName = ExistingType
alias StringMap = [String: Int]
```

Алиасы не создают новые типы, а лишь предоставляют альтернативные имена для уже существующих.
Алиас действет в текущем scope видимости, и может быть определён на уровне модуля, функции или блока кода.

```efen
module

alias UserID = Int
alias UserName = String

```

## Новый тип

`type` создаёт отдельную номинальную идентичность на основе существующего типа:

```efen
type UserId: Int

type Percentage: Float {
    value >= 0.0 && value <= 100.0
}
```

Блок предиката необязателен. Проверяемое значение называется `value`. Базовый
тип и новый тип не взаимозаменяемы: обычное присваивание требует точного совпадения.
Явный `.refine()` проверяет предикат, а автоматический переход возможен только
через отдельно объявленную прямую стратегию `Coerce<Source>`.

## Opaque-типы

`opaque` скрывает связь с внутренним конкретным типом за опубликованной
поверхностью. Модификатор ставится перед видом объявления; сегодня это
`type` или именованная `projection`:

```efen
public opaque type Buffer<T>:
    Iterable<Item: T>
= Array<T>
```

Снаружи области раскрытия `Buffer<T>` является отдельным именованным типом,
соответствующим `Iterable<Item: T>`. Внутри области раскрытия компилятор знает,
что это `Array<T>`, и разрешает операции с внутренним типом напрямую.

Вне области раскрытия модуль публикует для компилятора ABI-layout, правила
владения и реализации требований contract, но не раскрывает программе имя
внутреннего типа. Вызов по contract связывается с опубликованной реализацией и
может быть прямым вызовом или forwarding-функцией; обязательной VTBL нет.

Область раскрытия задаётся отдельно от видимости имени:

```efen
public opaque(private) type LocalBuffer<T>:
    Iterable<Item: T>
= Array<T>

public opaque(internal) type PackageBuffer<T>:
    Iterable<Item: T>
= Array<T>
```

`private` раскрывает внутренний тип только объявившему модулю, `internal` — всем
модулям текущего пакета. По умолчанию используется `opaque(private)`. Более
широкая область раскрытия, чем `internal`, запрещена. Начальный `public` в
примерах управляет доступностью имени и не раскрывает представление.

Для `opaque projection` опубликованная поверхность состоит из её объявленных
полей и доступных методов, а скрытая связь — из исходного типа после `for`.
Сама projection по-прежнему является zero-cost видом той же памяти; подробнее
см. [проекции](projection.md#opaque-projection).

Opaque-тип может быть generic. Его внутренний тип может зависеть от параметров,
но для каждой инстанциации обязан удовлетворять всем опубликованным контрактам.

`opaque type` не предоставляет бинарную совместимость при замене внутреннего
типа. Такое изменение инвалидирует зависимые продукты и требует их
перекомпиляции. Компилятор не обязан применять упаковку или косвенное хранение.

### Opaque-результат

Функция может скрыть конкретный тип результата без объявления общего имени:

```efen
fn tokens(text: String) -> opaque Iterator<Item: Token> {
    return TokenScanner(text: text)
}
```

Вызывающий код видит только соответствие `Iterator<Item: Token>`, а компилятор
сохраняет скрытый конкретный тип и может использовать статическую
диспетчеризацию.

Разные пути возврата могут производить разные конкретные типы, если каждый из
них удовлетворяет опубликованным контрактам:

```efen
fn tokens(fast: Bool) -> opaque Iterator<Item: Token> {
    if fast {
        return FastScanner()
    }

    return CompactScanner()
}
```

В этом случае скрытым конкретным типом результата становится синтезированный
structural union `FastScanner | CompactScanner`. Это законно, только когда
связанные параметры contract совпадают для всех member types и компилятор может
синтезировать каждую требуемую операцию structural union. Иначе разные типы
возврата являются ошибкой. Синтезированный union хранит runtime-тег и направляет
операции контракта к активному member type. Этот dispatch является следствием
разных runtime-путей, но contract по-прежнему не становится runtime-интерфейсом.

Именованный opaque-тип нужен, когда несколько объявлений должны назвать один и
тот же скрытый тип:

```efen
opaque type TokenStream:
    Iterator<Item: Token>
= TokenScanner

fn tokens(text: String) -> TokenStream
fn emptyTokens -> TokenStream
```

Каждое самостоятельное `-> opaque Contract` вводит собственную идентичность
скрытого результата. Она не совпадает с opaque-результатом другого объявления,
даже если их внутренние типы одинаковы.

## Структуры данных

Время жизни own-свойств структуры данных считается равным времени жизни самой структуры.

## Циклические ссылки

С точки зрения `Efen` важно не то, является ли ссылка циклической, а то, какой цели она служит.
Для иерархических структур данных циклические ссылки обычно отражают отношение от родителя к ребёнку.
В этом случае время жизни родителя должно быть больше времени жизни ребёнка.

Пример:

```efen
struct Node {
    children: NodeList
    parent: Node anchored
}
```

Специальный атрибут `anchored` указывает, что `parent` ссылка живёт как минимум столько же, сколько и `Node`, 
или больше.

Если же это не так, тогда проверка own невозможна. Нужно использовать ссылочные типы.
