# Уточняющие типы

[Документация](../README.md) · [Условия](../conditions.md) · [Типы с параметрами-значениями](value-parameterized-types.md)

Уточняющий тип — базовый тип и условие на его значение. `Int` — целое в диапазоне этого типа, `Nat` — только неотрицательное:

```efen
type Nat: Int { value >= 0 }
type Port: Int { value >= 1 && value <= 65535 }

let port: Port = 8080        // константа: условие доказано при сборке
```

Компилятор доказывает условие у каждого значения, которое становится `Nat`. Если анализ потока выполнения (FLOW) не смог доказать условие, оно проверяется
при выполнении. Нарушение обрабатывается так же, как нарушение [условие](../conditions.md#обычная-сборка-и-диагностики).

## Запись

```efen
type Имя: БазовыйТип { условие }
```

- Условие читает только `value` — значение этого типа — и константы; параметр обобщённого объявления — тоже константа, известная
  при сборке. Вызвать в нём можно чистую функцию, которая читает только свои параметры и константы
  ([вызов функции в условии](../conditions.md#вызов-функции-в-условии)): `{ isValidEmail(value) }`.
- Без `{ }` объявление — новый тип с той же основой и без условия. Прозрачный псевдоним пишется словом `alias`.
- Уточнение без имени пишется в типе: `[Int { value > 0 }]` — массив положительных чисел. Нового номинального типа
  оно не создаёт: элемент остаётся `Int`, а условие проверяется при каждой записи.
- Условие в конце строки-объявления — то же уточнение типа этого значения
  ([условия значений](../conditions.md#условия-значений-и-invariants)): `var age: Int = 0 { value >= 0 && value <= 150 }`.
  Порядок частей один: `= значение`, затем `{ условие }`.
- Условие, которое читает что-то кроме `value` и констант, — ошибка: связь нескольких значений пишется строкой
  `invariants` в теле типа.

Что можно писать в условии:

- сравнения `==`, `!=`, `<`, `<=`, `>`, `>=` и `&&`, `||`, `!`;
- поля и свойства значения: `value.count > 0`;
- вызовы чистых функций;
- `forall` по конечному домену: `forall i in 0 ..< value.count - 1: value[i] <= value[i + 1]`;
- параметры обобщённого объявления: `type Below<Limit: Int>: Int { value >= 0 && value < Limit }`
  ([типы с параметрами-значениями](value-parameterized-types.md)).

## Совместимость

Новый `type` — свой номинальный тип. Базовый и новый тип не подставляются друг вместо друга молча:

```efen
fn printInt(x: Int) {
    // тело не важно для примера
}

let n: Nat = 5
printInt(x: n)          // ошибка: ожидается Int, передан Nat
```

Переход пишется явно: `.refine()` из базового типа в уточнённый или одна прямая видимая стратегия `Coerce<Source>`
в любую сторону ([стратегии](../strategies.md)). Без них переходит только константа: `let port: Port = 8080`
принимается, если условие для этого значения доказано при сборке, иначе это ошибка.

Литерал рядом с уточнённым значением в операции или сравнении — значение базового типа, а не уточнённого:

```efen
type Year: Int {
    value >= 1900 && value <= 2100
    inherit +, >
}

fn next(year: Year) -> Year {
    if year > 0 {   // 0 — значение Int: условие Year к нему не относится
        // тело не важно для примера
    }
    return year + 1         // результат становится Year и проверяется
}
```

Результат унаследованной операции — значение уточнённого типа. Компилятор проверяет его там, где операция может
нарушить условие; где не может (сумма двух `Nat`), проверки нет. `inherit -` даёт и вычитание, и унарный минус;
`+=` и другие составные присваивания наследуются отдельно, своим знаком.

## `.refine()`

`.refine()` превращает значение базового типа в уточнённый. Каждое объявление `type Port: Int { value > 0 }` даёт базовому
типу функцию `refine`, которая возвращает `Имя`, и `.refine()` выбирается среди них по типу, который ожидается в
этом выражении. Компилятор обязан знать этот тип при сборке; если он неизвестен или подходят несколько функций
(перегруженный вызов, параметр обобщённого объявления до подстановки), это ошибка:

```efen
fn takeAge(age: Nat) {
    // тело не важно для примера
}

let input: Int = readNumber()
let age: Nat = input.refine()     // ожидается Nat
takeAge(age: input.refine())      // ожидается Nat: тип параметра
let guess = input.refine()        // ошибка: ожидаемый тип неизвестен
```

- Если FLOW доказал условие, проверки нет: в `if x >= 0 { let n: Nat = x.refine() }` условие следует из ветки.
- Иначе — заметка `Proof` и проверка при выполнении.
- Нарушение — нарушенное условие, и исход у него тот же: по умолчанию программа останавливается и пишет, какое
  условие и где нарушено; в сборке с `fault` бросается `ConditionError` ([исходы](../conditions.md#обычная-сборка-и-диагностики)).
  Своего исключения у уточнения нет.

```efen
fn abs(x: Int) -> Nat
    requires x != Int.MIN
{
    if x >= 0 {
        return x.refine()      // доказано: x >= 0
    }
    return (-x).refine()       // доказано: x < 0, поэтому -x > 0
}
```

## Фрагмент сравнений

Фрагмент сравнений — разрешимая часть условий: `value` сравнивается с константами (`==`, `!=`, `<`, `<=`, `>`,
`>=`), сравнения соединяются `&&`, `||`, `!`. Для такого условия компилятор точно решает, входит ли значение в
уточнение, пересекаются ли два уточнения и пусто ли уточнение.

Фрагментом пользуются две проверки при объявлении: диапазоны случаев варианта
[`Packed`](variant.md#представление-packed) не пересекаются, и пустое значение `null: c` в объявлении
Блок хранения `type Option<T>` не входит в уточнение `T` ([опциональные типы](optional.md#внутреннее-представление)). Условие вне
фрагмента в этих объявлениях — ошибка.

## Примеры

```efen
type NonEmptyArray<T>: [T] { value.count > 0 }

fn first<T>(items: NonEmptyArray<T>) -> T {
    return items[0]           // индекс доказан: count > 0
}

type SortedArray: [Int] { forall i in 0 ..< value.count - 1: value[i] <= value[i + 1] }

class ServerConfig {
    var host: String { value.count > 0 }
    var port: Port
}
```

Стиль: свойство одного значения, которое нужно многим функциям, — уточняющий тип; связь параметров и результат
функции — `requires` и `ensures` ([условия](../conditions.md)).
