# Векторные вычисления внутри стандартной библиотеки

[Типы](README.md) · [Циклы: `@accumulators`](../blocks/loops.md#порядок-вещественной-свёртки-accumulatorsn) · [Конфигурация сборки](../build-config.md) · [Системные вставки](../memory/system.md)

SIMD-вектор содержит фиксированное количество чисел одного типа.
Одинаковая операция применяется сразу ко всем его элементам. Это позволяет
использовать векторные инструкции процессора.

Векторные типы предназначены для стандартной библиотеки (`std`) и среды
выполнения. Прикладная программа использует обычные циклы, которые компилятор
может векторизовать, и библиотечные функции для массивов и строк. Порядок
суммирования вещественных чисел задаёт
[`@accumulators(N)`](../blocks/loops.md#порядок-вещественной-свёртки-accumulatorsn).

Эта статья описывает внутренний механизм: типы векторов и масок, их хранение,
операции и версии функций для разных процессоров. Использование векторных
типов, `@levels`, `@target` и `@intrinsic` за пределами `std` и среды выполнения
не допускается. Возможность открыть векторный тип для прикладных программ
остаётся отдельным вопросом; его имя и некоторые операции ещё не выбраны.

> Статус: проект. Приведённые имена предложены в плане Amber
> `dev/plans/S93.md`, §6.5, §7 и §8.3; они ещё не утверждены.

## Объявление

Файл `lang`, который идёт вместе с компилятором, объявляет:

```efen
/// A fixed number of numbers of one type, operated on together.
struct Simd {
    generic Element: SimdElement
    generic Lanes: Int { value > 0 }

    representation vector
}

/// One truth value per lane.
struct Mask {
    generic Lanes: Int { value > 0 }

    representation vectorMask
}
```

- Элемент вектора — одно число вектора, `v[i]` при `0 <= i < Lanes`.
- `vector` и `vectorMask` — имена из списка `lang` представлений, которые знает компилятор. Генератор кода читает
  представление, а не имя `Simd`. Свои представления библиотек (`SoA`) — другой список.
- `SimdElement` закрыт: ему соответствуют только встроенные от `Int8` до `Int64`, от `UInt8` до `UInt64`, `Float32`, `Float`.
  Объявление соответствия в своём типе — ошибка. `Bool` не элемент: вектор истинностных значений — `Mask`.
- Наибольшую ширину задаёт цель, а не тип: на процессорах до 64 элементов.
- Ширина 1 — вектор, а не скаляр.
- Короткие имена (`Float32x8`) — `alias` в std.

<a id="раскладка-и-передача"></a>

## Представление в памяти и передача аргументов

- Размер равен числу элементов, умноженному на размер одного элемента. Выравнивание — степень двойки не меньше размера, но не больше 16 байт на
  процессорах. `Simd<Float32, 3>` занимает 12 байт с выравниванием 16, поэтому массив таких векторов идёт с шагом 16.
  Геометрия в обычных структурах `(x, y, z)` и загрузка трёх элементов сохраняют шаг 12.
- Каждая векторная загрузка и запись пишет выравнивание явно; раскладку структуры решает компилятор, а не правило
  LLVM для векторов.
- Контракт аллокатора получает аргумент выравнивания (efen-lang/mm): буфер векторов загружается с выравниванием 16.
- Собственное соглашение о вызовах Efen передаёт и возвращает вектор и любое значение, которое его содержит, по
  адресу временного слота вызывающего; встраивание этот слот убирает. По значению вектор идёт только через границу
  `@abi(c)`, и там обе стороны собраны для одной цели. Причина: на x86-64 вектор `<8 x float>` передаётся одним
  регистром YMM в функции с AVX и двумя XMM без него, по цели каждой стороны. Вызов из базовой версии в версию AVX2
  иначе дал бы неверный результат без ошибки.

<a id="операции-над-дорожками"></a>

## Операции над элементами

Каждая операция задана формулой для `0 <= i < Lanes`. Спецификация задаёт эти формулы; система доказательств использует их
как исходные правила.

- Арифметика, битовые операции и сдвиги элемента: `(a + b)[i] == a[i] + b[i]`. Правила элемента действуют на каждом
  элементе: переполнение элемента `Int32` бросает `OverflowError`, если FLOW не доказал обратного. `addWrapping`,
  `addSaturating` и остальные называются по элементам.
- Сравнение даёт маску: `(a < b)[i] == (a[i] < b[i])`. `Simd` не соблюдает `Equatable`: `if a == b` — ошибка
  типа, равенство целиком — `(a == b).all()`.
- `mask.select(a, b)[i] == if mask[i] then a[i] else b[i]`.
- Скаляр рядом с вектором не расширяется сам: `v * Simd(2.0)`.
- `Simd<Element, Lanes>.iota` — номер элемента, от `0` до `Lanes - 1`.

## Маски

- Маска — `<Lanes x i1>`; регистры выбирает LLVM (`k` в AVX-512, предикаты SVE, полный вектор). Тип элемента маски
  Efen не фиксирует.
- `all()`, `any()`, `none()`, `count()`, `firstSet() -> Int?`; `&`, `|`, `^`, `!` по элементам.
- `bits() -> UInt64` (элемент `i` — бит `i`) есть только при `Lanes <= 64`, через условное соответствие
  ([параметры типов](../generics.md)).

## Память, свёртки, перестановки, преобразования

| Операция | Форма | Формула |
|---|---|---|
| Загрузка | `Simd<Float32, 8>(from: values[i ..< i + 8])` | `r[k] == values[i + k]`; диапазон проверяется, если не доказан |
| Запись | `values[i ..< i + 8] = v` | та же проверка |
| Частичная загрузка и запись | `Simd(from: values[i..<n], rest: 0.0)`, `store(v, into: values[i..<n])` | элементы после `n - i` равны `rest` или не трогаются |
| Сбор и рассеяние | `Simd(gather: values, at: indices)` | `r[k] == values[indices[k]]`; каждый номер проверяется, если не доказан |
| Заполнение, чтение и замена элемента | `Simd(2.0)`, `v[k]`, `v.replacing(lane: k, with: x)` | |
| Преобразование | `Simd<Int32, 8>(converting: f)` | правило преобразования элемента на каждом элементе: вне диапазона — исключение, если не доказано |
| Вещественная сумма | `v.sum()` | слева направо, `((v[0] + v[1]) + v[2])` и далее, начиная с `-0.0` |
| Целая сумма, произведение | `v.sum() -> Int64` | точно: элементы 8–32 бит складываются в `Int64`; элементы `Int64` считаются в 128 битах и бросают `OverflowError`, если точный результат не помещается |
| Минимум, максимум | `v.min()`, `v.max()` | NaN и ±0 как у скалярных `min` и `max` ([вещественные типы](constants.md)) |
| Битовые свёртки | `v.and()`, `v.or()`, `v.xor()` | |
| Перестановка | `v.shuffled([3, 2, 1, 0])`, `a.interleaved(b)`, `v.lowHalf()`, `v.highHalf()`, `concat(a, b)` | номера известны при компиляции и проверяются |
| Умножение со сложением | `a.mulAdd(b, c)` | `fma(a[k], b[k], c[k])` с одним округлением |

- Операция с памятью берёт срез массива, а не адрес: векторная загрузка так же безопасна, как индекс.
- `mulAdd` на уровне без FMA вызывает `fma` рантайма; так же вещественный `%` вызывает `fmod`. Обе функции рантайма
  округляют правильно, без библиотеки C.
- Выборки по таблице во время выполнения (`pshufb`, `tbl`) нет: размер таблицы и ответ на номер вне таблицы у x86 и
  AArch64 разные. Их дают встроенные функции платформы.

## Вещественные числа

Одна и та же вещественная операция даёт одни и те же биты на всех уровнях процессора одной программы, кроме знака и
содержимого NaN: версия для AVX-512 даёт результат базовой.

- Компилятор не сливает умножение со сложением сам; слияние пишется явно, `mulAdd`.
- `sum()` складывает в порядке элементов. Суммы в любом порядке нет.
- `preferredLanes` (ниже) шириной вещественного накопителя — предупреждение: результат зависел бы от уровня.
  Вспомогательные функции std суммируют фиксированной шириной 8.
- Векторная математика (`sin` по элементам) — отдельные функции со своими именами, а не выбор по процессору внутри
  скалярной.

## Обход массива частями

```efen
fn scale(values: edit [Float32], factor: Float32) {
    let f = Simd<Float32, 8>(factor)

    for chunk in edit values.chunks(of: 8) {
        chunk.store(chunk.load() * f)
    }
}
```

`chunks(of:)` даёт полные части, затем одну неполную. Тело цикла компилируется дважды: для полной части (обычные
загрузки и записи) и для неполной (с маской). Границы — контракт итератора. `edit` делает части изменяемыми
([области доступа](access-regions.md)).

<a id="ширина-по-цели"></a>

## Ширина вектора для целевой платформы

`Simd<Float32>.preferredLanes` — постоянная той копии функции, которая компилируется: 4 на базовом уровне x86-64, 8 в
версии x86-64-v3. В сигнатуре эта константа не используется: иначе разные версии функции
получили бы разные сигнатуры. Запись обобщённого типа с одним
аргументом из двух — предложение.

## Версии функции

```efen
@levels("x86-64-v3", "x86-64-v4+avx512vbmi")
fn encodeBase64(input: [UInt8], output: edit [UInt8]) {
    // тело не важно для примера
}
```

- Каждая запись — цель: уровень или имя процессора, к которому `+` добавляет возможности. Функция компилируется по
  разу на запись и один раз для базового уровня программы ([`cpu` в `target`](../build-config.md)). Запись, все флаги
  которой есть у базового уровня программы с её `features`, пропускается с замечанием; запись другой архитектуры не действует.
- Версия — срез по цели: копия функции и всех непубличных функций, до которых она дотягивается, собранная для
  цели записи. Вызов из версии в другую функцию с версиями идёт прямо в её копию для той же цели.
- Вызывающий пишет `encodeBase64` как обычно и попадает в версию первой записи, все возможности которой есть у
  процессора, иначе в базовую. Как выбор сделан и запомнен, решает компилятор (amber dev/plans/S93.md §7.3).
- Функция как значение — заглушка. Замыкание, созданное в версии, компилируется в её срезе.
- Тело, разное на разных уровнях, — отдельная функция того же имени с `@target("x86-64-v4")`; она входит в ту же
  заглушку.
- Копия содержит только команды своей цели. Код выше базового уровня достижим только через заглушку, а базовый
  уровень программа проверяет при старте.

Возможности процессора даёт роль рантайма `CpuFeatures` с функцией `features() -> CpuFeatureSet`: набор битов в
порядке списка `lang`. Возможность входит в набор, только если её поддерживают и процессор, и система (сохраняет её
регистры). Настройка для тестов ограничивает найденный набор, и одна машина проверяет ядро на каждом своём уровне.

## Встроенные функции платформы

```efen
@intrinsic("llvm.x86.aesni.aesenc", target: "x86-64-v2+aes")
fn aesEncode(state: Simd<UInt8, 16>, key: Simd<UInt8, 16>) -> Simd<UInt8, 16>
```

- Объявление без тела в модуле std для одной архитектуры. Компилятор берёт сигнатуру встроенной функции у LLVM и
  принимает объявление, если размеры аргументов и результата в битах совпадают; иначе — ошибка на объявлении.
- Как `@abi(c)` и `@asm`, `@intrinsic` входит в список доверия: её `ensures` принимаются на веру
  ([условия](../conditions.md)).
- Вызов вне копии, цель которой имеет нужные возможности, — ошибка с цепочкой вызовов.
