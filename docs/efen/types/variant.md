# Размеченные объединения: `variant`

[Документация](../README.md) · [Контракты](../contracts.md) · [Runtime языка Efen](../runtime/README.md) · [Память](../memory/README.md)

`variant` объявляет размеченное объединение: значение принадлежит ровно одному
из перечисленных случаев. Каждый случай имеет имя и может хранить собственный
набор именованных полей. Например, один случай ответа хранит строку,
а другой — код ошибки. Если собственных полей ни у одного случая нет,
используйте [перечисление `enum`](enum.md).

Тип является **номинальным**: его определяет объявление, поэтому два типа
с одинаковыми случаями и полями остаются разными типами. По умолчанию набор случаев
**закрыт**: все они перечислены в объявлении. Для добавления случаев из других
объявлений нужен [`open variant`](#расширение).

```efen
variant ServerResponse {
    pending
    success { let data: String }
    failure { let code: Int, let message: String }
}

let response = ServerResponse.failure(code: 404, message: "Not Found")
```

В этом примере `ServerResponse` — тип с тремя случаями: `pending`, `success`
и `failure`. Запись `ServerResponse.failure(code: 404, message: "Not Found")`
создаёт значение случая `failure` и задаёт его поля.

<a id="семантика-sum-of-products"></a>

## Алгебраический тип данных

Размеченное объединение относится к алгебраическим типам данных. Выбор одного
из случаев называют **суммой типов**, а набор полей одного случая —
**произведением типов**. В примере ниже результат содержит либо значение `T`,
либо ошибку `E`:

```efen
variant Result<T, E> {
    ok { let value: T }
    err { let error: E }
}
```

Здесь `ok` и `err` различаются не только полями, но и именами случаев.
Имя случая определяет, как следует понимать данные. Даже если два случая
хранят одинаковые поля, их значения остаются различными:

```efen
variant Side {
    left { let value: Int }
    right { let value: Int }
}

let a = Side.left(value: 1)
let b = Side.right(value: 1) // b отличается от a
```

Различие случаев должно сохраняться при любом представлении в памяти.
Компилятор может хранить отдельную **метку случая** (тег) вместе с данными,
размещать данные косвенно, через указатель, или использовать другое
равнозначное представление. Обычный код работает со случаями и полями,
не обращаясь к этому внутреннему устройству. У открытого типа схему хранения
задаёт корневое объявление ([схемы хранения](#схемы-хранения)).

<a id="constructors"></a>

## Случаи и создание значений

Каждый случай задаёт **конструктор значения**: например, `Barcode.upc(...)`
создаёт значение случая `upc`. У всех полей есть имена; при создании значения
они указываются в метках аргументов:

```efen
variant Barcode {
    upc { let system: Int, let manufacturer: Int, let product: Int, let check: Int }
    qrCode { let code: String }
}

let product = Barcode.upc(
    system: 8,
    manufacturer: 85909,
    product: 51226,
    check: 3
)
let website = Barcode.qrCode(code: "https://example.com")
```

В одном типе могут быть случаи с полями и без полей. Если полей нет ни
у одного случая, используйте [перечисление `enum`](enum.md).

<a id="pattern-matching"></a>

## Сопоставление с образцом

Имя случая в образце пишется с точкой. Его поля извлекаются
[оператором проекции `.{ }`](projection.md):

```efen
match response {
    .pending: print("Ожидание")
    .success.{ let data }: print("Получены данные: ${data}")
    .failure.{ let code, let message }:
        print("Ошибка ${code}: ${message}")
}
```

Ненужные поля можно опустить, а нужные — переименовать:

```efen
match product {
    .upc.{ let system }: print("Система: ${system}")
    .qrCode.{ code: let url }: print(url)
}
```

В образце `.{ }` поле типа `ImplicitlyCopyable` (`Int`, `Float`) связывается копией, любое
другое — псевдонимом того же значения, а не копией: копию
даёт только `copy`, передачу владения — `take` ([связывание существующего значения](../types/ownership.md#связывание-существующего-значения)). Образец не создаёт отдельного представления данных.

Сопоставление должно быть **исчерпывающим**: `match` без `_` обязан
обработать все случаи, известные при компиляции. Условие `where` позволяет
выделить часть значений одного случая:

```efen
match response {
    .success.{ let data } where data.length > 0: use(data)
    .success: reportEmpty()
    .failure.{ let code } where code >= 500: retry()
    .failure.{ let code, let message }: report(code, message)
    .pending: wait()
}
```

<a id="generic-variant-types"></a>

## Параметры типов

```efen
variant Result<T, E> {
    ok { let value: T }
    err { let error: E }
}

fn divide(a: Int, b: Int) -> Result<Float, String> {
    if b == 0 {
        return .err(error: "Division by zero")
    }
    return .ok(value: Float(a) / Float(b))
}
```

Тип значения, которое может отсутствовать, записывается как `T?`.
`Option<T>` — стандартный псевдоним того же типа. Эта запись не создаёт
дополнительный объект или контейнер:

```efen
alias Option<T> = T?
```

<a id="рекурсивные-variant-types"></a>

## Рекурсивные типы

Если случай содержит значение того же типа, его данные нельзя целиком
разместить внутри самого значения: размер получился бы бесконечным.
Модификатор `indirect` задаёт косвенное хранение. Его указывают у всего типа
или у отдельных рекурсивных случаев:

```efen
indirect variant Expression {
    number { let value: Int }
    addition { let left: Expression, let right: Expression }
    multiplication { let left: Expression, let right: Expression }
}
```

```efen
variant Expression {
    number { let value: Int }
    indirect addition { let left: Expression, let right: Expression }
    indirect multiplication { let left: Expression, let right: Expression }
}
```

Данные случая с `indirect` размещаются в куче. В самом значении остаются
метка случая и указатель на данные:

- Создание такого значения выделяет память и может бросить `AllocationError`, как любой конструктор, который
  выделяет память. При ошибке внутренний указатель получает нулевое значение C (`NULL`).
  Конструктор работает с проекцией, в которой это допустимое незавершённое состояние.
  Затем частично созданное значение уничтожается.
- `copy e` — глубокая копия: каждый блок выделяется заново, копия может бросить `AllocationError`. `clone e` для типа
  `variant` с `indirect` без счётчика ссылок — ошибка ([`clone`](../runtime/value-operations.md#оператор-clone)).

```efen
let e = Expression.addition(left: take a, right: take b)   // выделяет; может бросить AllocationError
let f = copy e                                    // глубокая копия дерева
evaluate(e)                                       // параметр read: значение одолжено, копии нет
```

Пример обхода:

```efen
fn evaluate(expr: Expression) -> Int {
    return match expr {
        .number.{ let value }: value
        .addition.{ let left, let right }: evaluate(left) + evaluate(right)
        .multiplication.{ let left, let right }: evaluate(left) * evaluate(right)
    }
}
```

## Методы, свойства и равенство

Тип `variant` может объявлять методы и вычисляемые свойства. Компилятор
может автоматически построить проверку равенства, если её поддерживают
поля всех случаев:

```efen
variant Message {
    conforms Equatable

    text { let content: String }
    image { let url: String, let width: Int, let height: Int }
}
```

## Вложенные типы

Как и другой номинальный тип, `variant` может содержать вложенные объявления:

```efen
variant Character {
    enum Weapon {
        sword
        bow
        staff
    }

    enum Armor {
        light
        medium
        heavy
    }

    warrior { let weapon: Weapon, let armor: Armor }
    mage { let weapon: Weapon }
    archer { let weapon: Weapon }
}
```

## Расширение

`open variant` расширяется так же, как [`open enum`](enum.md#расширение): расширение добавляет новые случаи.
Значения расширения можно использовать там, где ожидается базовый тип.
Правила перечислений действуют и здесь: сокращённая запись имён, обработка
в `match` через `_` или `@extended _`, перезапись значений, методы, контракты,
параметры типов, представление метки и сборка программы. Расширение не
добавляет поддержку внешних значений (`rawValue`) или `CaseIterable`.

```efen
open indirect variant Expression {
    number { let value: Int }
    addition { let left: Expression, let right: Expression }
}

variant ExtraExpression: Expression {
    negation { let operand: Expression }
}

fn evaluate(expr: Expression) -> Int {
    return match expr {
        .number.{ let value }: value
        .addition.{ let left, let right }: evaluate(left) + evaluate(right)
        ExtraExpression.negation.{ let operand }: -evaluate(operand)
        @extended _: 0
    }
}
```

Расширение не меняет поля случаев базового типа и расширяет только `variant`, не `enum`.

### Схемы хранения

Для хранения значения с меткой требуется слот под метку и данные самого
большого случая, с учётом выравнивания. У открытого типа такой случай может
быть объявлен в расширении из другого пакета. Корневой тип выбирает одну
из двух схем хранения:

- **В значении** (по умолчанию). Размер открытого типа определяется при сборке программы по всей иерархии.
  Эта схема не требует отдельного выделения памяти под данные случая.
- **В куче** — `conforms IndirectExtensions` у корня. Данные каждого случая, объявленного не в корневом типе, лежат в
  куче, как у `indirect`; размер корня известен в его пакете.

```efen
open variant Shape {
    conforms IndirectExtensions
    dot
}
```

Правила схем:

- Все типы иерархии, включая закрытые расширения, имеют представление корневого типа. Поэтому значение расширения копируется
  в слот базового типа без изменения представления.
- `IndirectExtensions` пишет только корень, безусловно и прямо в своём теле: не под `#if`, не через уточняющий
  контракт; использовать этот контракт как ограничение параметра обобщённого объявления нельзя. Это контракт `lang::` без требований.
- В схеме «в куче» создание значения расширения выделяет память и может бросить `AllocationError`. Копия тоже
  выделяет: она пишется `copy s`, и
  `AllocationError` стоит в сводке каждого `copy` этого типа. `let s as B` в `match` заимствует значение, а не
  копирует. В программе без кучи создание значения расширения с данными — ошибка сборки с именем случая.
- В схеме «в значении» размер корня известен в его пакете, только если его случаи не содержат по значению
  другой открытый тип `variant` в той же схеме.
- Сборка программы предупреждает, когда данные случая расширения больше данных самого большого случая корневого типа, и называет
  этот случай: размер каждого значения корневого типа в программе увеличивается (группа диагностик `VariantSize`). Для уменьшения размера можно указать `indirect` у этого случая.
- Цикл размеров между расширениями (`A` содержит `B` через расширение, `B` содержит `A`) — ошибка сборки программы.
  Ошибка перечисляет все случаи в цикле; основное место диагностики — случай с наибольшим полным путём, по сравнению из
  раздела [о представлении перечислений](enum.md#представление). Цикл можно разорвать, указав `indirect` у одного из этих случаев.
- `indirect` у корня покрывает и случаи расширений; `indirect` у объявления расширения покрывает его случаи.
- Перевод корня на `IndirectExtensions` или обратно — изменение, нарушающее совместимость: меняются сводки исключений.
- Файлы `lang::` не объявляют открытый тип `variant`: представление типов `lang` — часть версии среды выполнения, а куча в `lang` запрещена.

<a id="соответствия-полей"></a>

### Требования к полям

Поля случаев расширения должны поддерживать контракты корневого типа,
выполнение которых зависит от полей: `Equatable`,
`Copyable`, `Movable`. Иначе ошибка в расширении:

```efen
open variant Shape {
    conforms Copyable              // ImplicitlyCopyable объявляют только модули языка
    dot
}

variant FileShape: Shape {
    file { let handle: File }      // ошибка: File не Copyable, а Shape объявил Copyable
}
```

`@abi(c)` у открытого типа `variant` и у его расширения — ошибка: представление C фиксировано объявлением.

## Закрытость и `@unknown _`

Все случаи закрытого типа известны в пределах одной версии его объявления.
В следующей версии библиотека может добавить новый случай. Ветка `@unknown _`
позволяет сохранить совместимость исходного кода с таким изменением:

```efen
match response {
    .success.{ let data }: use(data)
    .failure.{ let code, let message }: report(code, message)
    @unknown _: reportUnknown()
}
```

`@unknown _` относится к закрытому типу `variant`. Открытый тип `variant` («Расширение») требует `_` или `@extended _`.
`Family<Base>` — открытый носитель видов хранения для компоновки памяти (`layout`), а не тип значения.

<a id="отличие-от-enum-и-structural-union"></a>

## Отличие от перечисления и структурного объединения

```efen
enum Direction {
    north
    south
}

variant Side {
    left { let value: Int }
    right { let value: Int }
}

alias Scalar = Int | Float
```

- `enum` объявляет именованные значения без собственных полей. Каждому
  значению можно сопоставить число или строку для внешнего представления.
- `variant` объявляет новый тип с именованными случаями и их полями.
- `T | U` — структурное объединение уже существующих типов. Оно не объявляет
  именованных случаев.

В частности, `Side.left(value: 1)` и `Side.right(value: 1)` различны благодаря
именам случаев; `T | U` таких имён не создаёт.

<a id="раскладка-c-abic-variant"></a>

## Представление C: `@abi(c) variant`

`@abi(c)` задаёт представление как у объединения `union` в C: данные всех
случаев начинаются по одному адресу, отдельная метка случая не хранится.
Поэтому для `match` и `==` компилятору нужно доказательство того, какой случай
активен. Такое доказательство может следовать из условия на внешней структуре,
состояния объекта или контракта функции C. Без него разрешено читать только
случаи с целочисленными или вещественными данными. Подробно — [библиотеки на C](../foreign.md#union).

## Представление `Packed`

`representation Packed<I>` хранит значение объединения в одном значении
целого типа `I`. Успех и ошибка различаются диапазонами значений. Например,
системный вызов Linux может возвращать результат при успехе и отрицательный
код `-errno` при ошибке.

- У каждого случая не больше одного поля. Его тип — `I`, уточнение `I`, класс над внешним значением над `I` или его
  уточнением, или `T?` из таких типов с объявленным пустым значением `c`: диапазон этого поля — диапазон `T` вместе
  с `c`.
- Для случая без поля явно задаётся внешнее значение: `name = c`. Это есть только у `Packed`.
- Диапазон каждого случая записан во [фрагменте сравнений](refinement-types.md#фрагмент-сравнений); другое — ошибка.
  Диапазоны попарно не пересекаются, это проверяется при объявлении. `match` проверяет диапазоны.
- Представление `Result<T, E>` выбирает компилятор. Этот тип нельзя использовать как
  результат функции `@asm` или `@abi(c)`: у конкретного экземпляра параметризованного
  типа нельзя задать `representation`. Для такого результата объявляется отдельный
  номинальный тип с представлением `Packed`.

```efen
type Descriptor: Int32 { value >= 0 }
type Errno: Int32 { value >= -4095 && value <= -1 }

public variant OpenResult {
    representation Packed<Int32>              // одно слово, диапазоны не пересекаются
    opened { let file: own File }                 // диапазон Descriptor
    failed { let code: Errno }
}

match File.openX86(dir: AT_FDCWD, path: "log".cString, flags: O_RDONLY, mode: 0) {
    .failed.{ let code }: throw IoError(code: code)
    .opened.{ let file }: return file.readAll()   // closeX86 вызывается в конце области file
}
```

`MapResult` ([вариант в одно слово](../memory/system.md#вариант-в-одно-слово)) — выведенная форма той же схемы хранения;
`Packed` делает её явной и проверенной. Значение вне всех диапазонов, которое вернула внешняя функция, ловит
проверочная сборка.

## Ограничения

- Внешние значения (`rawValue`) разрешены у `enum`. У `variant` их можно задать только для случая без поля в представлении [`Packed`](#представление-packed).
- `CaseIterable` не синтезируется для `variant`.
- Расширяется только `open variant` и только другим `variant` («Расширение»).
- Все поля случаев должны иметь имена.
