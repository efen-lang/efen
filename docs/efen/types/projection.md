# Проекции: `projection`

<a id="1-определение"></a>

## Что такое проекция

**Проекция** предоставляет доступ к выбранным полям существующей структуры
через отдельный тип. Данные остаются в той же памяти.

Проекция:

- предоставляет доступ только к выбранным полям;
- может уточнять наличие значения и ограничивать права чтения или записи;
- **бинарно совместим** с базовой структурой;
- является **отдельным типом** для системы типов;
- может использоваться вместе с уточняющими типами.

Проекция не создаёт копию исходной структуры.

Применение проекции к конкретному значению не является неявным
преобразованием. Оно допустимо, только когда код уже обеспечил её условия либо
компилятор доказал их из типов и пути выполнения; иначе применение — ошибка.

Это обещание относится к именованному `projection` существующего физического
представления. Проекция колоночного хранилища устроена иначе: один логический слот может объединять данные из нескольких
столбцов. Они не обязаны лежать в одном непрерывном участке памяти. Этот
механизм не объявляется словом `projection` и не гарантирует бинарную
совместимость всей логической структуры.

<a id="именованная-projection"></a>

## Именованная проекция

Именованная проекция задаёт отдельный тип для доступа к той же памяти:

```efen
projection UserWithEmail for User {
    let email: String
}
```

Поле, тип которого не меняется, пишется без типа: тип берётся из базовой
структуры. Тип пишут только там, где проекция его сужает,
например `String?` до `String`. Несколько полей одного вида перечисляются через
запятую:

```efen
projection Contact for User {
    let name, phone
    let email: String                    // в User — String?
}
```

Её можно применить к конкретному значению только при обеспеченных условиях:

```efen
let view: UserWithEmail = user
```

Эта строка ошибочна, пока код не обеспечил условия `UserWithEmail` либо
компилятор не доказал их.

Условия, которые не следуют из типов полей, записывают отдельным блоком `{ }`
после объявления проекции, как [условия вида](../memory/pointer.md#условия-вида) в `layout`,
а применяют проекцию приведением `as`. Так устроен доступ к
[общей памяти](../shared.md#доступ-через-projection):

```efen
projection PoolEditor for Pool {
    var idle, openCount
    let maxConnections
    invariants { mutex is Mutex.Held }
}

with pool.mutex {
    let editor = pool as PoolEditor      // доказано: мьютекс захвачен
}
```

Полученный вид живёт, пока верно условие: после выхода из `with` обращение к
`editor` — ошибка.

<a id="opaque-projection"></a>

## Проекция со скрытым исходным типом: `opaque`

Именованная проекция может быть `opaque`. Она сохраняет обычную для
проекции бинарную совместимость с исходным типом и объявленный набор
полей, но скрывает саму связь с исходным типом вне области раскрытия:

```efen
public opaque(private) projection HirNodeForResolver for HirNode {
    let kind: NodeKind
    let range: SourceRange
    let operands: [HirNodeId]
}
```

Снаружи `HirNodeForResolver` — отдельный тип: код может использовать только
поля этой проекции и её доступные методы стратегии, но не может превратить
её значение в `HirNode`. Внутри области раскрытия её тип проверяется как
`HirNode`. Поэтому реализация, объявленная вместе с проекцией, может
использовать полный исходный тип, не открывая его клиенту.

`opaque(private)` раскрывает исходный тип только модулю, объявившему
проекцию; `opaque(internal)` — всем модулям текущего пакета. Как и у
`opaque type`, начальный `public` управляет доступностью имени
`HirNodeForResolver`, а не областью раскрытия. Видимость членов самого
`HirNode` остаётся обычной: раскрытие проекции не отменяет `private` и
другие правила доступа.

Такой тип позволяет ограничить доступ внешнего кода, сохранив полные права
у реализации в модуле, который его объявил. Например, внешнему модулю можно
передать `HirNodeForResolver` и разрешить вызвать `resolve`, но не дать ему
ни записать внутренний результат разрешения, ни получить исходный тип. Стратегия
`ResolveCall`, объявленная в модуле проекции, использует тип получателя
`HirNodeForResolver` для выбора метода, однако её тело видит `HirNode` и
проверяет инварианты перед изменением. Пример находится в
[стратегиях](../strategies.md#стратегия-для-opaque-projection).

## Анонимные проекции

Оператор `.{...}` создаёт анонимную проекцию типа или типа коллекции без
предварительного объявления именованного типа проекции:

```efen
let movement = Particles.{position, velocity}
```

Такая проекция:

- предоставляет только перечисленные поля;
- не копирует и не преобразует данные;
- наследует права чтения и изменения исходного значения;
- не создаёт именованный тип вроде `Particle::Movement`;
- для коллекции логически представляет выбранные колонки всех элементов.

```efen
let positions = Particles.{position}
let movement = Particles.{position, velocity}
```

Физический доступ к выбранным полям обеспечивает выбранное представление
коллекции. Для SoA это могут быть отдельные непрерывные колонки, а для AoS —
представление полей внутри последовательности записей. Создание анонимной
проекции само по себе не меняет представление в памяти.

### `.{ }` в образце

Та же запись служит образцом в `let`, `if let`, `while let`, `match`, `is` и между
`for` и `in`, но результат у неё другой. Проекция создаёт представление на те же
данные; образец связывает поле типа `ImplicitlyCopyable`
(`Int`, `Float`) копией, любое другое — псевдонимом того же значения, а не копией: копию даёт
только `copy`, передачу владения — `take` ([связывание существующего значения](../types/ownership.md#связывание-существующего-значения)). Представления образец
не создаёт. После `is` запись `Type.{ … }` — всегда образец, а не проекционный тип. Разбор образцов
описан в [«Деструктуризация»](../destructuring.md).

Именованные проекции используются, когда представление является частью API или
требует отдельной проверки типа. `.{...}` предназначен для локального выбора
данных.

Анонимному проекционному типу можно дать имя обычным `alias`:

```efen
alias Movement = [Particle].{position, velocity}
```

Псевдоним даёт имя проекционному типу, например `[Particle].{position, velocity}`.
Он определяется через тип, а не через конкретное значение, и не меняет
представление данных в памяти.

## Проекция в параметре

Место этого правила среди остальных — в [сводной таблице](../memory/memory-rules.md#два-доступа-сразу).

**Правило.** Параметр типа проекции обращается только к полям проекции. Вызывающий считает аргумент набором путей к этим
полям, а не значением целиком: поля `var` получают право параметра, поля `let` только читаются.

```efen
projection Contact for User {
    var name, phone
    let id
}

fn rename(contact: mut Contact) { contact.name = "Ada" }

let orders = &read user.orders
rename(user)                  // для вызывающего: mut на user.name и user.phone, чтение user.id
print(orders.count)           // можно: user.orders вызов не касается
```

- Ссылки в поля, которых в проекции нет, после вызова действительны, даже когда тела функции не видно: функция из другого
  пакета, тип функции, метод интерфейса. Худший случай по сигнатуре ограничен полями проекции
  ([отношение между параметрами](access-regions.md#отношение-между-параметрами)).
- Аргументы одного вызова сравниваются по тем же путям. Две проекции одного значения не пересекаются, если поля,
  которые пишет одна, не входят в другую: `sync(contact: user, billing: user)` допустим, когда ни одно поле `var`
  проекции `Contact` не входит в `Billing` и наоборот.
- Условия проекции проверяются при вызове, как при любом её применении.
- Поля сравниваются по путям: путь, который начинает другой путь, с ним пересекается. `var address` в одной проекции
  и поле `address.city` в другой пересекаются.
- Когда не доказано, что два аргумента-проекции взяты из разных значений (`sync(contact: users[i], billing: users[j])`),
  проверка при выполнении сравнивает адреса по полям, а не по значениям целиком: при `i == j` поля двух проекций не
  пересекаются, и вызов проходит.
- У анонимной проекции `T.{a, b}` в типе параметра каждое поле берёт `var` или `let` из объявления `T`.

**Правило.** Значение типа проекции приводится только к более узкой проекции: каждое её поле есть в исходной, поле
`let` остаётся `let`, а тип поля тот же или шире. К исходному типу, к проекции с полем, которого в нём нет, и к
проекции, где его поле `let` объявлено `var`, оно не приводится. Это относится и к анонимной проекции `T.{a, b}`.
Запрет действует в любой области, и тело в другом пакете его тоже соблюдает; поэтому худший случай по сигнатуре и
ограничен полями проекции. Единственное исключение — область раскрытия проекции `opaque`.

```efen
fn rename(contact: mut Contact) {
    let u: mut User = contact as User      // ошибка: проекция не приводится к исходному типу
}
```

**Правило.** Поле `let`, тип которого проекция сужает или которое названо в её `invariants`, на время вызова держится
как записываемое: другой аргумент и захват замыкания писать его не могут. Иначе колбэк нарушил бы условие, по которому
тело уже работает. Ошибка выдаётся в строке вызова.

**Правило.** Значение типа проекции (`let view: UserWithEmail = user`) держит такие поля как записываемые, пока
существует, а не только на время вызова. Запись такого поля по другому пути заканчивает проекцию: использование
значения проекции после этой записи вызывает ошибку. Компилятор показывает её в строке записи и отдельно показывает
строку использования.

```efen
guard user.email != null else { return }          // user: mut User
let view: UserWithEmail = user                   // email: String
user.email = null                                // запись поля, которое проекция сужает: view недействительна
print(view.email.count)                          // ошибка: view используется после записи user.email
```

```efen
projection Sized for Buffer { let length: PositiveInt }     // в Buffer это Int

fn chunk(b: read Sized, each: () -> Void) { each(); let n = 4096 / b.length }

chunk(buf) => { buf.length = 0 }           // ошибка: length держит проекция Sized
```

**Правило.** Через проекцию коллекции, `[Particle].{position}`, право параметра действует внутри выбранных полей
каждого элемента. Структура самой коллекции при этом не меняется: `mut` на такой параметр не даёт добавлять и удалять
элементы, и ссылки вызывающего в невыбранные поля действуют.

**Правило.** Поле, которое инвариант или условие компоновки исходного типа связывает с полем вне проекции, в проекции
не бывает `var`: `projection Len for Vector<T> { var length }` — ошибка в объявлении проекции.

**Правило.** Поле проекции может называть диапазон области, которая стоит в поле структуры из `layout`:
`var store.cells[tail ..< head + store.capacity]`. Сначала пишется путь к области, затем диапазон. Путь проходит
только через поля-значения и поля `own`. Опциональное владеющее поле на пути добавляет проекции условие «поле не
равно `null`», которое доказывается в приведении `as`. Предыдущее правило действует и по слотам: поля, которые
читает инвариант над двумя слотами, в такой проекции не бывают `var`. Остальные условия перечисляет
[справочник `layout`](../memory/layout/threads.md#роли).

**Правило.** Параметр типа проекции бывает `read`, `edit` и `mut`. `own`, `out` и аргумент `take` с типом проекции —
ошибки: значение перемещается и создаётся только целиком.

**Что не допускается.** Правило о полях не действует для проекции `opaque`, когда тела функции не видно: в области раскрытия
тело работает с исходным типом и может писать поля вне проекции. Вызывающий тогда считает изменённым исходное значение
целиком.

<a id="2-цели"></a>

## Для чего нужны проекции

- Безопасные стадии **инициализации** и **уничтожения**.
- Ограничение видимости: передать только часть полей.
- Работа с полями, которые временно могут быть `null`.
- Низкоуровневые оптимизации без копирования памяти.
