# Тип функции

[Документация](../README.md) · [Контракты](../contracts.md) · [Runtime языка Efen](../runtime/README.md) · [Память](../memory/README.md)

Тип функции задаёт типы её параметров и результата. Он также может
ограничивать эффекты вызова, права доступа и переходы состояний.

## Синтаксис

```efen
(ParameterType1, ParameterType2) -> ReturnType
```

Примеры:

```efen
// Функция без параметров, возвращающая Int
let getNumber: () -> Int

// Функция с двумя параметрами Int, возвращающая Int
let add: (Int, Int) -> Int

// Функция с одним параметром String, возвращающая Bool
let validate: (String) -> Bool

// Функция без возвращаемого значения
let print: (String) -> Void
```

## Использование в объявлениях переменных

Типы функций можно использовать для объявления переменных, которые хранят функцию как значение:

```efen
// Объявление сразу инициализирует let
let f: (Int, Int) -> Int = (a: Int, b: Int) => a + b

// Использование
echo f(5, 3)  // Выведет: 8
```

## Опциональные типы функций

Тип функции может быть опциональным:

```efen
let optionalFunc: ((Int) -> Int)? = null
```

`?` в конце типа функции относится к её результату: `(Int) -> Int?` — функция с результатом `Int?`. Опциональную
функцию, держатель и ссылку на них берут в скобки, которые только группируют: `((Int) -> Int)?`,
`(holds mut<log> (Int) -> Void)?`.

## Функции высшего порядка

Типы функций позволяют создавать функции высшего порядка - функции, 
которые принимают другие функции в качестве параметров или возвращают функции:

```efen
fn apply(x: Int, operation: (Int) -> Int) -> Int {
    return operation(x)
}

fn double(n: Int) -> Int {
    return n * 2
}

echo apply(5, double)  // Выведет: 10
```

## Права вызова замыкания

Сигнатура `(P) -> R` задаёт параметры и результат. Полный тип значения также
сохраняет права, необходимые для вызова конкретной функции или замыкания:

- `read` — тело только читает захваты и допускает повторные вызовы;
- `mut` — тело изменяет захваты и допускает повторные последовательные
  вызовы;
- `own` — тело извлекает захваченное значение, поэтому вызов требует
  передачи владения всем замыканием.

В типе вид пишут между скобками параметров и стрелкой: `(T) mut -> U`, `() own -> Void`; без слова — `read`.
Право перед типом относится к аргументу, а не к вызову: `own () -> Void` — функция может сохранить замыкание
([замыкания](../closure.md#вид-замыкания-в-типе)).

```efen
fn runOnce(task: () own -> Void) {
    (take task)()
}
```

Право вызова зависит от операций тела над захватами. Захват значения по
владению сам по себе не делает замыкание одноразовым. Отдельных типов `Fn`,
`FnMut` и `FnOnce` язык не вводит; их различие выражается обычными правами Efen.
Подробнее см. [«Замыкания»](../closure.md#права-вызова-замыкания).

## Сводка вызова, вычисляемая компилятором

У каждой функции есть обычная сигнатура и отдельная сводка
исключений (`throws`), контекстов и состояний. Автор может объявить требования в сигнатуре;
компилятор дополняет их требованиями, найденными в теле и по графу вызовов.
Тип без `in` у переменной с выведенным типом сводку не стирает:

```efen
fn load -> Int in Database

let callback = load          // тип выведен: () -> Int in Database

fn caller {
    callback() // caller получает требование `in Database`
}
```

Явный тип функции — предел: функция с бо́льшими контекстами или правами на пути контекста, чем в нём, — ошибка
(`let plain: () -> Int = load` — ошибка, см. [эффекты в типе функции](../context-and-effects.md#эффекты-в-типе-функции));
с меньшими — можно. Косвенный вызов распространяет требование так же, как прямой.

При выборе между функциями или замыканиями компилятор строит общую сводку: объединяет `throws` и
`in`, а право вызова усиливает в порядке `read < mut < own`. У `var`, поля,
параметра и публичного символа функционального типа эта верхняя граница фиксирована: присваивание,
которое требовало бы её расширить, является ошибкой. Исключение — эффекты ожидания у параметра:
их функция получает от переданного замыкания в месте вызова (см. [Общая память](../shared.md#эффекты-ожидания)).
Параметр `under` (`condition: () -> T? under self`) их не передаёт: тело такого замыкания проверяется как тело
блока `with`; аргумент такого параметра — только литерал замыкания на устойчивом пути получателя (см.
[Ожидание условия](../shared.md#ожидание-условия)). Сводка живёт только в
HIR времени компиляции и используется при статической проверке.
Представление функции или замыкания при выполнении и их ABI не хранят
сведения об исключениях, контекстах или состояниях.

Состояния входят в эту границу так же, как `throws`: граница — то, что написано
в скобках типа. Если в типе параметра нет `state`, переданная функция или замыкание
не может менять состояния своих аргументов, даже при праве `mut`. Функция, которая меняет состояние, передаётся только туда, где переход
записан в самом типе: так изменение состояния видно в сигнатуре.

```efen
fn apply(file: mut File, f: (mut File) -> Void) {
    f(file)
}

fn closeIt(file: mut File) {
    file.close()             // выведено: file Lifecycle.Open >> Lifecycle.Closed
}

apply(file, closeIt)         // ошибка: тип `f` не пишет `state`, а closeIt
                             // меняет состояние file
```

Изменение структуры памяти входит в границу по тому же правилу (см.
[«Что делает ссылку недействительной»](ownership.md#что-делает-ссылку-недействительной)).
Если тип параметра не допускает изменение структуры памяти, переданная функция
или замыкание не может менять структуру своих аргументов. Ссылки на их память
остаются действительными после вызова. Функция, которая может изменить структуру, передаётся только туда, где
это записано в самом типе: записью `holds` перед типом функции, `holds mut<items> (Int) -> Void`
([отношение между параметрами](access-regions.md#отношение-между-параметрами),
[сохранённый колбэк](access-regions.md#сохранённый-колбэк)).

```efen
fn apply(values: mut Vector<Int>, f: (mut Vector<Int>) -> Void) {
    let first = &values[0]
    f(values)
    print(first)             // допустимо: тип `f` не пишет изменение структуры
}

fn grow(values: mut Vector<Int>) {
    values.append(1)         // выведено: может изменить структуру values
}

apply(values, grow)          // ошибка: тип `f` не пишет изменение структуры,
                             // а grow её меняет
```

Параметр `claim` входит в границу так же
([право на элемент](../memory/layout/functions.md#82-право-на-элемент), правило 6). Функция, которая может
привести аргумент к `own`, передаётся только туда, где тип пишет `claim` у того же параметра. Совместимость
параметров:

- `mut` или `read<p>` подходит туда, где ждут `claim<p>`; `mut T` подходит туда, где ждут `claim T`: такая функция
  делает меньше, чем разрешает тип;
- `claim` не подходит туда, где ждут `mut` или `read<p>`: вызывающий через такой тип не пишет `claim` и держит
  указатели после вызова;
- `claim<p>` и `claim T` несравнимы: ни один не подходит туда, где ждут другой.

Функция, которая передаёт `claim y` аргумента, полученного не параметром `claim` (инициатор, `free` менеджера
памяти), значением функции не передаётся вовсе: её `claim` не выражен ни одним параметром
([сводка функции](../memory/layout/functions.md#как-flow-вычисляет-время-жизни), правило 8).

```efen
fn release(pool: mut Pool, block: claim<pool> SlotBlock)
fn keep(pool: mut Pool, block: read<pool> SlotBlock)

let a: (pool: mut Pool, block: claim<pool> SlotBlock) -> Void = keep     // допустимо: keep к own не приводит
let b: (pool: mut Pool, block: read<pool> SlotBlock) -> Void = release   // ошибка: тип не пишет claim
```

## Примеры с замыканиями

```efen
// Функция, возвращающая функцию
fn makeMultiplier(factor: Int) -> (Int) -> Int {
    return (n: Int) -> Int {
        capture factor = copy factor   // замыкание переживает параметр: копия пишется явно
        return n * factor
    }
}

let multiplyBy3 = makeMultiplier(3)
echo multiplyBy3(4)  // Выведет: 12
```

## Эффекты возвращаемой функции

Хвост сигнатуры `state`, `in`, `throws` относится к объявляемой функции. Эффекты
функционального типа, который функция возвращает, пишутся внутри скобок:

```efen
fn load -> Int in Database             // in у load
fn make -> () -> Int throws E          // throws у make
fn map -> ((T) -> U throws E)          // throws у возвращаемой функции
```

Тип функции, записанный в результате без скобок, кончается на своём типе результата: слова хвоста и строки
`requires` и `ensures` после него принадлежат объявляемой функции. Свой хвост и свои условия такой тип несёт только
в скобках.

Возвращаемое замыкание, которое что-то держит, пишет слово `holds`: `fn counter(items: mut Vector<Int>) -> holds
mut<items> () -> Int`. Тип без скобок кончается и здесь на своём результате: `-> holds mut<items> () -> Int throws E`
отдаёт `throws` объявляемой функции. Скобки только группируют. Без `holds` `право<x>` перед типом результата значит
заимствование (`-> edit<list> Shape?`), и `-> edit<list> () -> Void` — заимствование замыкания, которое лежит в
`list`.

## Ссылка в результате типа функции

Тип функции пишет результат в одной из трёх форм, как сигнатура
([ссылка в результате функции](ownership.md#место-в-результате-функции)): значение (`-> Shape?`), заимствование
(`-> edit<list> Shape?`) или ссылка (`-> &edit<list[_]> Shape?`). Функция с заимствованием или ссылкой в результате
передаётся как значение, только если тип называет источник. Источник называют именем параметра самого типа:

```efen
fn find(list: edit Vector<Shape>, id: Int) -> &edit<list[_]> Shape? {
    // тело не важно для примера
}

let pick: (list: edit Vector<Shape>, id: Int) -> &edit<list[_]> Shape? = find
pick(list: shapes, id: 7)!.color = .red          // на месте: пишет в shapes
let s = &pick(list: shapes, id: 8)!              // ссылку держат: & у вызова

let bad: (edit Vector<Shape>, Int) -> &edit Shape? = find   // ошибка: источник ссылки не назван
```

- Имя только указывает на параметр. В тождество типа входит номер параметра, поэтому
  `(items: edit Vector<Shape>, key: Int) -> &edit<items[_]> Shape?` — тот же тип.
- Источник — путь от параметра самого типа по общим правилам пути: поле, часть контракта, `!`, `[index]`,
  `[a ..< b]`, имя множества, `[_]` (`-> &edit<doc.title> String`). Захват замыкания источником не бывает.
- Имя источника не совпадает с внешним именем, которое видно в этом месте: `fn apply(list: mut Vector<Shape>,
  f: (list: edit Vector<Shape>) -> &edit<list[_]> Shape?)` — ошибка. То же правило действует для источника в записи
  `holds` внутри типа функции: `(log: mut Vector<Int>) -> holds mut<log> () -> Void` называет параметр `log` самого
  типа.
- Значение не подставляется вместо заимствования или ссылки, и обратно. Функция со ссылкой в результате подходит к
  типу с заимствованием из того же параметра, обратное — ошибка:
  `let lend: (list: edit Vector<Shape>, id: Int) -> edit<list> Shape? = find` допустимо. Право результата можно
  только сузить: `find` подходит к типу с `-> &read<list[_]> Shape?`.
- Формы параметров совпадают точно: `fn reset(x: &edit Int)` не подходит к `(edit Int) -> Void`, а функция с
  параметром `x: edit Int` — к `(x: &edit Int) -> Void`.
- Право результата не шире права параметра: `(list: Vector<Shape>) -> &edit<list[_]> Shape?` — ошибка, `list`
  только читается.
- Форму результата решает написанное: `fn call<R>(f: (edit Vector<Shape>, Int) -> R)` пишет результат значением и
  не принимает `find`. Весь результат другого типа функции, с его формой, приносит только `F.result`
  ([тип функции](../generics.md#тип-функции)).
- У функционального типа `@abi(c)` ссылки и заимствования в результате нет.
- Функция или замыкание, [модель](../models.md#модель-model) или сводка которой кладёт псевдоним, не записанный в
  сигнатуре, между параметрами или из параметра в результат, не подходит ни к одному типу функции: ошибка при
  преобразовании, как у ссылки в результате без названного источника. Псевдоним в `self` кладёт метод, а не
  значение-функция.

## Что держит замыкание

Что держит значение типа — какие места и с каким правом, — пишется словом `holds` и записью перед типом, в каждой
позиции. Запись построена, как пометка метода ([части объекта](parts.md#пометка-метода)), с двумя отличиями. Слово
`read` пишется и перед `<`, и у источника: у метода путь пишут только для `edit` и `mut`. Источником служит не только
часть `self`.

```efen
holds mut<log, read cfg> (Int) -> Void          // держит log с правом mut и cfg только для чтения
holds mut<self.firstFree> () own -> Void        // в поле: держит часть firstFree своего объекта
holds edit<items> (Int, Int) -> Bool            // параметр: может пересекаться с аргументом items в пределах edit
holds read<%Logger> () -> Void                  // держит контекст Logger
```

- Слово перед `<` — самое широкое право; оно действует на каждый источник без своего слова.
- Слово у источника только сужает: равное общему или шире него — ошибка. Источник стоит один раз. Часть внутри
  другого источника той же записи пишется только со своим более узким словом: `holds mut<self, read self.cfg>`.
- Источник — переменная, параметр, их часть, параметр `Origin`, контекст `%Name` или `self` с частью. Где какой
  источник допустим, сказано в [сохранении замыкания](../closure.md#сохранение-замыкания-после-вызова). Каждый
  источник пишется: `holds mut () -> Void` — ошибка; в методе пишут `<self>`.
- Источники записи — ссылки на места: они читают то, что лежит там сейчас, и кончаются по правилам ссылки
  ([что делает ссылку недействительной](ownership.md#что-делает-ссылку-недействительной)), а не псевдонима.
- `holds` стоит перед типом функции, типом генератора, параметром типа или связанным типом и номинальным типом,
  который несёт `Src`: `-> holds mut<items> generator yield Int`, `it: mut holds mut<Src> I`,
  `-> holds read<self> KeyCursor`. Перед типом, который сам говорит, что держит (тип с `Src`, параметр типа,
  связанный с держателем), запись — верхняя граница, и компилятор её сверяет: две записи молча не сливаются. Перед
  типом, который ничего не держит, запись ничего не меняет: `holds read<c> T` при `T = Int` — `Int`, поэтому
  обобщённый код законен для каждого `T`.
- Без `holds` `право<x> T` — заимствование, у типа функции тоже: `f: read<c.onClick> (Int) -> Void` — заимствование
  функции, которая лежит в `c.onClick`; так пишут, только когда `onClick` ничего не держит. Заимствование или ссылка
  на поле с держателем пишет обе записи: `f: read<p.onClick> holds mut<p.log> (Int) -> Void`. Запись называет объект
  так же, как источник (`p.log`), и читается как объектная форма типа поля (`self.log`); источник вне этого объекта —
  ошибка.
- `read` перед `<` допустим: замыкание держит то, что читает. `holds own<x> T` ничего не держит и равно `T`, как у
  генератора. `claim` и `out` не пишутся: право забрать элемент в значении не хранится.
- Запись — не вид: `holds mut<log> () -> Void` держит `log` для записи и своё окружение не меняет; `() mut -> Void`
  меняет своё окружение и ничего снаружи не держит.
- Тип с записью в результате пишется без скобок: `-> holds mut<items> () -> Void`. Скобки только группируют.
- Та же запись стоит перед литералом замыкания: `holds mut<log> (x: Int) -> Void { log.append(x) }`. Она
  необязательна. Написанная, она сверяется с телом, как на месте хранения: выведенное должно поместиться в
  написанное. Затем она становится держанием собственного типа литерала вместо выведенного, и право каждого
  захвата — то, которое запись даёт его источнику, а не то, которое применяет тело. Так же пишется и вид литерала,
  словом после скобок параметров ([вид замыкания в типе](../closure.md#вид-замыкания-в-типе)). Поэтому два литерала с
  одной записью, одним прототипом и одними захватами — один тип.
- `holds` — слово по месту, как `read` и `edit`, которые бывают и именами функций: в типе оно стоит перед словом
  права, в выражении — перед словом права и литералом. `holds(` — вызов функции с именем `holds`. Без `holds` запись
  перед литералом не пишется: `read<Int>(from: s)` — всегда вызов обобщённой функции с именем `read`.
- Параметр права (`holds Access<items>`) перед литералом не пишется. Слово права перед `(` без `<` — ошибка: вид
  пишут после скобок.
- Литерал в объектной форме (`self`, `self.часть`) бывает только там, где он стоит прямо в месте объектной формы:
  в поле или параметре метода такого типа. Литерал в переменной держит `self` в форме слота. Держание, записанное
  перед литералом в месте объектной формы, называет объект так же, как тело (`self` в методе объекта, `pool` в
  `pool.on(cb: holds mut<pool.firstFree> () own -> Void { … })`), и читается как объектная форма этого места.
- `let` с записанным типом функции и литералом справа — не вторая запись держания, а другой смысл: тип переменной
  прячет захваты (`Function<F>`), и такое значение только перемещается. Обе формы законны.

```efen
let f = holds mut<log> (x: Int) -> Void { log.append(x) }              // держание на литерале
let g: holds mut<log> (Int) -> Void = (x: Int) -> Void { log.append(x) } // захваты спрятаны: copy g нельзя
let h = holds read<log> (x: Int) -> Void { log.append(x) }             // ошибка: тело пишет log
var k = holds mut<log> (x: Int) -> Void { log.append(x) }
k = holds mut<log> (x: Int) -> Void { print(log.count + x) }           // тот же тип: запись, прототип и захваты те же
var onTick: holds mut<log> (Int) -> Void = (x: Int) -> Void { log.append(x) }
onTick = (x: Int) -> Void { capture n = 2; log.append(x * n) }         // тип функции принимает и другие захваты
```

## Условия в типе функции

После результата тип функции может нести строки `requires` и `ensures`, как сигнатура функции
([условия](../conditions.md)):

```efen
fn run(pool: mut Pool, job: holds mut<pool> () -> Void ensures pool.firstFree == null) {
    job()                    // здесь известно: pool.firstFree == null
}

var pending: Vector<(holds mut<self.firstFree> () own -> Void throws IOError
                     ensures throws IOError ==> taken(firstFree))>
```

- Строка называет источники записи `holds` (в типе поля — поля объекта без `self`, как в методе), именованные
  параметры типа и `result`; `previous(x)` — значение до вызова. Захваты не называются: тип о них не знает.
- Строка без `==>` действует на обычном возврате и на выходе исключением, у которого нет своих строк.
  `ensures throws E ==> taken(путь)` называет часть источника, которая может остаться пустой на этом выходе, как у
  части параметра `mut` ([условия](../conditions.md#часть-параметра-пустая-на-выходе-исключением)). Поле, которое
  не опционально, к обычному возврату записано, поэтому `== null` у него — ошибка типа.
- Своих строк `requires` и `ensures` литерал не пишет. Литерал, который стоит прямо в месте с типом функции или в
  параметре обобщённого типа `C: Callable<F>`, берёт строки этого типа в собственный тип. Тело доказывает строки
  `ensures` на каждом выходе, как функция свою сигнатуру; недоказанная строка — ошибка у литерала. `requires`
  доказывает тот, кто вызывает значение.
- У литерала в переменной без типа строк нет, и к типу со строкой `ensures` он не подходит: вызов идёт по адресу
  кода, и тела в этом месте не видно. Такой литерал пишут прямо в месте с типом.
- Значение подходит к типу по каждому выходу отдельно. На обычном выходе все строки `ensures` типа есть среди строк
  значения. На выходе исключением `E` строки типа для `E` есть среди строк значения для `E`, а части, которые
  значение может оставить пустыми (`taken` части), разрешены строками типа: строка `taken` части — разрешение, а не обещание,
  и тип без неё не разрешает ничего. Строки `requires` значения есть среди строк типа. Иначе — ошибка.
- Внутри угловых скобок тип функции с условиями берут в скобки, как в результате: `>` после условия читался бы как
  сравнение.

## Псевдонимы типов функций

Можно объявлять псевдонимы для сложных типов функций:

```efen
alias BinaryOperation = (Int, Int) -> Int
alias UnaryPredicate = (Int) -> Bool

let operation: BinaryOperation = (a: Int, b: Int) => a + b
let isEven: UnaryPredicate = (n: Int) => n % 2 == 0
```

## Грамматика

В грамматике Efen тип функции определяется как:

```antlr
functionValueType
    : holding? functionType
    ;

holding                                    // перед типом функции, генератора, параметром типа, типом с Src
    : 'holds' right '<' heldSource (',' heldSource)* '>'
    ;

heldSource
    : right? ('self' ('.' identifier)* | identifier ('.' identifier)* | '%' identifier)
    ;

functionType
    : functionSignature signatureTail? condition*
    ;

functionSignature
    : '(' (parameterType (',' parameterType)*)? ')' kind? '->' resultType
    ;

resultType
    : holding? functionSignature           // без скобок: хвост и условия после него — у объявляемой функции
    | '(' functionValueType ')'            // скобки только группируют
    | formType                             // `?` в конце — у результата
    ;

closureLiteral
    : holding? '(' (parameter (',' parameter)*)? ')' kind? ('->' type block | '=>' expression)
    ;

parameterType
    : (identifier ':')? formType
    ;

formType
    : '&' right sources? type              // ссылка: &edit Int, &out Int, &edit<list[_]> Shape?
    | right sources? type                  // заимствование, `out` не бывает; у копируемого типа без & — копия
    | type                                 // значение
    ;

sources
    : '<' sourcePath (',' sourcePath)* '>' // путь: поле, часть контракта, !, [index], [a ..< b], имя множества, [_]; `?` после источника
    ;
```

Имена параметров необязательны: `(accumulator: Int, item: Int) -> Int`. Они
не меняют идентичность типа, но задают неявные параметры хвостового замыкания:
`accumulator`, `item`. В одном типе имена либо есть у всех параметров, либо ни
у одного. Если ожидаемый тип не даёт имён, хвостовая форма `=>` недоступна и
замыкание объявляет параметры явно.

Это правило поддерживает:
- Функции без параметров: `() -> Int`
- Функции с одним параметром: `(Int) -> String`
- Функции с несколькими параметрами: `(Int, String, Bool) -> Void`
