# Тип функции

[Документация](../README.md) · [Контракты](../contracts.md) · [Runtime языка Efen](../runtime/README.md) · [Память](../memory/README.md)

Тип функции задаёт типы её параметров и результата. Он также может
ограничивать эффекты вызова, права доступа и переходы состояний.

## Синтаксис

```efen
(ParameterType1, ParameterType2, ...) -> ReturnType
```

Примеры:

```efen
// Функция без параметров, возвращающая Int
let getNumber: () -> Int

// Функция с двумя параметрами Int, возвращающая Int
let add: (Int, Int) -> Int

// Функция с одним параметром String, возвращающая Bool
let validate: (String) -> Bool

// Функция без возвращаемого значения
let print: (String) -> Void
```

## Использование в объявлениях переменных

Типы функций можно использовать для объявления переменных, которые хранят функцию как значение:

```efen
// Объявление сразу инициализирует let
let f: (Int, Int) -> Int = (a: Int, b: Int) => a + b

// Использование
echo f(5, 3)  // Выведет: 8
```

## Опциональные типы функций

Тип функции может быть опциональным:

```efen
let optionalFunc: ((Int) -> Int)? = null
```

## Функции высшего порядка

Типы функций позволяют создавать функции высшего порядка - функции, 
которые принимают другие функции в качестве параметров или возвращают функции:

```efen
fn apply(x: Int, operation: (Int) -> Int) -> Int {
    return operation(x)
}

fn double(n: Int) -> Int {
    return n * 2
}

echo apply(5, double)  // Выведет: 10
```

## Права вызова замыкания

Сигнатура `(P) -> R` задаёт параметры и результат. Полный тип значения также
сохраняет права, необходимые для вызова конкретной функции или замыкания:

- `read` — тело только читает захваты и допускает повторные вызовы;
- `mut` — тело изменяет захваты и допускает повторные последовательные
  вызовы;
- `own` — тело извлекает захваченное значение, поэтому вызов требует
  передачи владения всем замыканием.

В типе вид пишут между скобками параметров и стрелкой: `(T) mut -> U`, `() own -> Void`; без слова — `read`.
Право перед типом относится к аргументу, а не к вызову: `own () -> Void` — функция может сохранить замыкание
([замыкания](../closure.md#вид-замыкания-в-типе)).

```efen
fn runOnce(task: () own -> Void) {
    (take task)()
}
```

Право вызова зависит от операций тела над захватами. Захват значения по
владению сам по себе не делает замыкание одноразовым. Отдельных типов `Fn`,
`FnMut` и `FnOnce` язык не вводит; их различие выражается обычными правами Efen.
Подробнее см. [«Замыкания»](../closure.md#права-вызова-замыкания).

## Сводка вызова, вычисляемая компилятором

У каждой функции есть обычная сигнатура и отдельная сводка
исключений (`throws`), контекстов и состояний. Автор может объявить требования в сигнатуре;
компилятор дополняет их требованиями, найденными в теле и по графу вызовов.
Тип без `in` у переменной с выведенным типом сводку не стирает:

```efen
fn load -> Int in Database

let callback = load          // тип выведен: () -> Int in Database

fn caller {
    callback() // caller получает требование `in Database`
}
```

Явный тип функции — предел: функция с бо́льшими контекстами или правами на пути контекста, чем в нём, — ошибка
(`let plain: () -> Int = load` — ошибка, см. [эффекты в типе функции](../context-and-effects.md#эффекты-в-типе-функции));
с меньшими — можно. Косвенный вызов распространяет требование так же, как прямой.

При выборе между функциями или замыканиями компилятор строит общую сводку: объединяет `throws` и
`in`, а право вызова усиливает в порядке `read < mut < own`. У `var`, поля,
параметра и публичного символа функционального типа эта верхняя граница фиксирована: присваивание,
которое требовало бы её расширить, является ошибкой. Исключение — эффекты ожидания у параметра:
их функция получает от переданного замыкания в месте вызова (см. [Общая память](../shared.md#эффекты-ожидания)).
Параметр `under` (`condition: () -> T? under self`) их не передаёт: тело такого замыкания проверяется как тело
блока `with`; аргумент такого параметра — только литерал замыкания на устойчивом пути получателя (см.
[Ожидание условия](../shared.md#ожидание-условия)). Сводка живёт только в
HIR времени компиляции и используется при статической проверке.
Представление функции или замыкания при выполнении и их ABI не хранят
сведения об исключениях, контекстах или состояниях.

Состояния входят в эту границу так же, как `throws`: граница — то, что написано
в скобках типа. Если в типе параметра нет `state`, переданная функция или замыкание
не может менять состояния своих аргументов, даже при праве `mut`. Функция, которая меняет состояние, передаётся только туда, где переход
записан в самом типе: так изменение состояния видно в сигнатуре.

```efen
fn apply(file: mut File, f: (mut File) -> Void) {
    f(file)
}

fn closeIt(file: mut File) {
    file.close()             // выведено: file Lifecycle.Open >> Lifecycle.Closed
}

apply(file, closeIt)         // ошибка: тип `f` не пишет `state`, а closeIt
                             // меняет состояние file
```

Изменение структуры памяти входит в границу по тому же правилу (см.
[«Что делает ссылку недействительной»](ownership.md#что-делает-ссылку-недействительной)).
Если тип параметра не допускает изменение структуры памяти, переданная функция
или замыкание не может менять структуру своих аргументов. Ссылки на их память
остаются действительными после вызова. Функция, которая может изменить структуру, передаётся только туда, где
это записано в самом типе: пометкой перед типом функции, `mut<items> (Int) -> Void`
([отношение между параметрами](access-regions.md#отношение-между-параметрами),
[сохранённый колбэк](access-regions.md#сохранённый-колбэк)).

```efen
fn apply(values: mut Vector<Int>, f: (mut Vector<Int>) -> Void) {
    let first = &values[0]
    f(values)
    print(first)             // допустимо: тип `f` не пишет изменение структуры
}

fn grow(values: mut Vector<Int>) {
    values.append(1)         // выведено: может изменить структуру values
}

apply(values, grow)          // ошибка: тип `f` не пишет изменение структуры,
                             // а grow её меняет
```

## Примеры с замыканиями

```efen
// Функция, возвращающая функцию
fn makeMultiplier(factor: Int) -> (Int) -> Int {
    return (n: Int) -> Int {
        capture factor = copy factor   // замыкание переживает параметр: копия пишется явно
        return n * factor
    }
}

let multiplyBy3 = makeMultiplier(3)
echo multiplyBy3(4)  // Выведет: 12
```

## Эффекты возвращаемой функции

Хвост сигнатуры `state`, `in`, `throws` относится к объявляемой функции. Эффекты
функционального типа, который функция возвращает, пишутся внутри скобок:

```efen
fn load -> Int in Database             // in у load
fn make -> () -> Int throws E          // throws у make
fn map -> ((T) -> U throws E)          // throws у возвращаемой функции
```

Так же в скобки берут возвращаемое замыкание с заимствованиями: `fn counter(items: mut Vector<Int>) -> (mut<items>
() -> Int)`. Скобки здесь меняют смысл: без них `право<x>` перед типом результата значит ссылку в результате
(`-> edit<list> Shape?`), и `-> edit<list> () -> Void` — ссылка на замыкание, которое лежит в `list`.

## Ссылка в результате типа функции

Функция, которая возвращает ссылку внутрь своего параметра
([ссылка в результате функции](ownership.md#место-в-результате-функции)), передаётся как значение, только если
тип называет источник ссылки. Источник называют именем параметра самого типа:

```efen
fn find(list: edit Vector<Shape>, id: Int) -> edit<list> Shape? { … }

let pick: (list: edit Vector<Shape>, id: Int) -> edit<list> Shape? = find
pick(list: shapes, id: 7)!.color = .red          // пишет в shapes

let bad: (edit Vector<Shape>, Int) -> edit Shape? = find   // ошибка: источник ссылки не назван
```

- Имя только указывает на параметр. В тождество типа входит номер параметра, поэтому
  `(items: edit Vector<Shape>, key: Int) -> edit<items> Shape?` — тот же тип.
- Источник — параметр целиком: путь внутрь параметра (`edit<doc.title>`) и захват замыкания источником ссылки
  не бывают.
- Имя источника не совпадает с внешним именем, которое видно в этом месте: `fn apply(list: mut Vector<Shape>,
  f: (list: edit Vector<Shape>) -> edit<list> Shape?)` — ошибка.
- Результат-значение и результат-ссылка друг вместо друга не подставляются. Право ссылки можно только сузить:
  функцию с `-> edit<list> Shape?` можно положить в тип с `-> read<list> Shape?`, обратное — ошибка.
- Право результата не шире права параметра: `(list: Vector<Shape>) -> edit<list> Shape?` — ошибка, `list`
  только читается.
- Параметр обобщённого объявления результата не бывает ссылкой: `fn call<R>(f: (edit Vector<Shape>, Int) -> R)` не принимает
  `find`.
- У функционального типа `@abi(c)` ссылки в результате нет.
- Функция или замыкание, [модель](../models.md#модель-model) или сводка которой кладёт заимствование между
  параметрами или из параметра в результат, не подходит ни к одному типу функции: ошибка при преобразовании, как у
  ссылки в результате без названного источника. Заимствование в `self` кладёт метод, а не значение-функция.

<a id="алиасы-для-типов-функций"></a>

## Псевдонимы типов функций

Можно объявлять псевдонимы для сложных типов функций:

```efen
alias BinaryOperation = (Int, Int) -> Int
alias UnaryPredicate = (Int) -> Bool

let operation: BinaryOperation = (a: Int, b: Int) => a + b
let isEven: UnaryPredicate = (n: Int) => n % 2 == 0
```

## Грамматика

В грамматике Efen тип функции определяется как:

```antlr
functionType
    : '(' (parameterType (',' parameterType)*)? ')' '->' type
    ;

parameterType
    : (identifier ':')? type
    ;
```

Имена параметров необязательны: `(accumulator: Int, item: Int) -> Int`. Они
не меняют идентичность типа, но задают неявные параметры хвостового замыкания:
`accumulator`, `item`. В одном типе имена либо есть у всех параметров, либо ни
у одного. Если ожидаемый тип не даёт имён, хвостовая форма `=>` недоступна и
замыкание объявляет параметры явно.

Это правило поддерживает:
- Функции без параметров: `() -> Int`
- Функции с одним параметром: `(Int) -> String`
- Функции с несколькими параметрами: `(Int, String, Bool) -> Void`
