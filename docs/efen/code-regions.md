# Области кода и гарантии состояния

> Статус: проект спецификации. Грамматика и проверка компилятором ещё не реализованы.

Область кода (`region`) задаёт локальную границу для статических гарантий.
Гарантия `preserve` требует, чтобы объект покинул область в том же typestate,
которое было объявлено или выведено при входе.

Идея близка к `focus` в языке Vault и state guarantees в Plaid, но в Efen
выражается как явный контракт лексической области.

## Основной синтаксис

```efen
region preserve file: Open {
    file.close()
    file.open()
}
```

Компилятор проверяет:

1. при входе `file` находится в `Open`;
2. внутри области разрешены любые корректные переходы;
3. на каждом выходе из области `file` снова находится в `Open`.

Гарантия относится к состоянию объекта, а не к его данным: содержимое полей
может измениться, если это разрешено типом и правами владения.

## Вывод входного состояния

Если состояние не указано, компилятор фиксирует состояние, известное при входе:

```efen
region preserve file {
    file.close()
    file.open()
}
```

Если при входе известно объединение состояний, например `Open | Closed`, вывод
недопустим. Программист должен сначала уточнить состояние или указать гарантию
явно.

## Несколько гарантий

Краткая запись подходит для одного объекта. Несколько объектов перечисляются в
блоке гарантий:

```efen
region preserve {
    file: Open
    socket: Connected
} {
    file.close()
    socket.disconnect()

    socket.connect()
    file.open()
}
```

Все гарантии проверяются независимо на каждом пути выхода.

## Пути выхода

`preserve` действует для любого выхода из области:

- достижение конца блока;
- `return`;
- `break` и `continue`;
- `throw`;
- переход управления из вложенного блока.

Следующий код не компилируется:

```efen
region preserve file: Open {
    file.close()

    if cancelled {
        return // ошибка: file находится в Closed
    }

    file.open()
}
```

Диагностика должна указывать путь, на котором гарантия нарушена:

```text
error[region.unpreserved-state]: region must preserve `file: Open`
  found state at return: `Closed`
  note: `file` changed to `Closed` after calling `close`
```

## Исключения

Если операция может завершиться исключением до восстановления состояния,
компилятор требует обработать исключение внутри региона либо доказать, что
состояние при `throw` уже восстановлено:

```efen
region preserve file: Open {
    file.close()

    try {
        updateMetadata()
        file.open()
    } catch error: IOError {
        file.open()
        throw error
    }
}
```

Гарантия `preserve` не выполняет откат автоматически. Она только проверяет код.

## Взаимодействие с defer

`defer` можно использовать для восстановления состояния:

```efen
region preserve file: Open {
    file.close()
    defer {
        file.open()
    }

    replaceFileContents()
}
```

При анализе выхода компилятор учитывает все активные `defer` в порядке LIFO.
Если отложенная операция может не восстановить состояние, гарантия не считается
доказанной.

## Владение и псевдонимы

Регион не выдаёт дополнительных прав. Для перехода состояния объект по-прежнему
должен иметь `own` или допустимое эксклюзивное `write`.

На время региона компилятор должен исключить изменение отслеживаемого состояния
через неизвестный псевдоним. Поэтому:

- `read` и `inspect` ссылки можно использовать параллельно, если переходы не
  изменяют доступное им представление;
- изменяемый псевдоним нельзя вынести за границы региона;
- замыкание не может захватить эксклюзивное право и пережить регион;
- конкурентное изменение требует отдельной синхронизированной гарантии.

## Вложенные регионы

Регионы можно вкладывать:

```efen
region preserve file: Open {
    region preserve socket: Connected {
        sendFile(file, socket)
    }
}
```

Внутренняя гарантия проверяется раньше внешней. Внешний регион может временно
изменять состояние объекта только тогда, когда это не нарушает требования входа
внутреннего региона.

## Композиция свойств региона

`region` является общей конструкцией области, а `preserve` — одним из её свойств.
В будущем свойства можно комбинировать:

```efen
region isolated preserve file: Open {
    // Все внешние эффекты области объявлены её свойствами или поглощены внутри.
}
```

Порядок модификаторов не меняет семантику, но каноническая запись начинается с
`region`, затем перечисляет свойства, после чего задаёт объект гарантии.
`isolated` закрывает набор неявных эффектов области. Запрет обратного вызова или
повторного входа требует отдельного контракта и из `isolated` не следует.

## Гарантии по исключениям

`handles` перечисляет исключения, которые область обязана обработать сама: ни
одно из них не покидает её границу.

```efen
region handles IOError {
    try {
        let data = readFile(path)
        parse(data)
    } catch e: IOError {
        reportAndSkip(e)
    }
}
```

Без обработчика компилятор сообщает о нарушении на том выходе, через который
`IOError` способно пройти.

`nothrows` запрещает области выбрасывать что-либо:

```efen
region nothrows {
    releaseHandles()
    resetCounters()
}
```

Обе гарантии проверяются на каждом выходе из области, по тому же списку выходов,
что и `preserve`: конец блока, `return`, `break`, `continue`, `throw`, переход
управления из вложенного блока и исключение, вышедшее из вызова внутри области.

Свойства комбинируются по правилу из раздела «Композиция свойств региона»:

```efen
region handles IOError preserve file: Open {
    file.close()

    try {
        updateMetadata()
        file.open()
    } catch e: IOError {
        file.open()
        report(e)
    }
}
```

Порядок здесь канонический: сначала перечислены свойства области, а объект
гарантии — `file: Open` — стоит последним.

Здесь `IOError` обязано быть обработано внутри области, а `file` на каждом выходе
снова находится в `Open`. Объявление обязанности у типа и у функции описано в
разделе «Must-handle исключения» документа [«Исключения»](throws.md).

## Связь с сигнатурами typestate

Метод описывает локальный переход:

```efen
fn close state Open >> Closed
fn open state Closed >> Open
```

Регион описывает композиционную гарантию для последовательности переходов:

```efen
region preserve file: Open {
    file.close() // Open >> Closed
    file.open()  // Closed >> Open
}
```

Таким образом, методы определяют рёбра автомата состояний, а регион проверяет,
что путь внутри него заканчивается в требуемой вершине.

## Изменения компилятора

Для реализации потребуется:

1. добавить `region`, `preserve`, `handles` и `nothrows` в грамматику операторов;
2. представить гарантии региона в AST;
3. сохранить входное состояние каждого отслеживаемого слота;
4. проверить состояние после применения `defer` на каждом ребре выхода;
5. интегрировать проверку с ownership и анализом псевдонимов;
6. добавить диагностику с указанием нарушающего пути управления.
