# Видимость определений между пакетами и модулями

Видимость определений — важная часть организации кода в `Efen`.  
Она определяет, какие функции, классы, переменные и другие сущности доступны в различных частях программы.

## Комбинированный контроль видимости

В `Efen` применяется принцип комбинированного контроля видимости.  
Он сочетает преимущества явной видимости на уровне объявлений и централизованных правил на уровне пакета.

Подход `"visibility is part of the declaration"` остаётся допустимым —  
разработчик может явно указать видимость каждого определения (`public`, `internal`, `private`).  
Однако для крупных пакетов этот метод усложняет сопровождение.

Поэтому `Efen` вводит **многоуровневую модель управления видимостью**, где правила могут задаваться:
- на уровне пакета (в главном модуле);
- на уровне пространства имён (определяется только в пакете);
- на уровне модуля;
- на уровне отдельного определения.

## Базовые теги видимости

`Efen` использует три базовых тега:

| Тег         | Описание                                            |
|-------------|-----------------------------------------------------|
| `public`    | Определение доступно из любого пакета.              |
| `internal`  | Определение доступно только внутри текущего пакета. |
| `private`   | Определение доступно только внутри текущего модуля. |

`internal` является значением по умолчанию и может применяться на любом уровне.

## Правила по умолчанию

1. Все определения внутри модуля являются внутренними (`internal`) и недоступны за пределами пакета.
2. Все модули пакета являются внутренними (`internal`) и недоступны за пределами пакета.
3. Пространства имён (`namespace`) не имеют собственной видимости — их уровень доступа задаётся
   **только в главном модуле пакета**.

## Правила вычисления видимости

Видимость определяется комбинацией правил на разных уровнях:
1. Правила на уровне пакета.
2. Правила на уровне пространства имён (определённые в главном модуле пакета).
3. Правила на уровне модуля.
4. Правила на уровне определения.

Результирующая видимость определяется наиболее ограничительным правилом:
- Если пакет определён как `private`, все его модули и определения внутри него будут `private`.
- Если пакет определён как `internal`, все его модули и определения внутри него будут `internal` или `private`.
- Если модуль определён как `public`, его определения могут быть `public`, `internal` или `private`.

Компилятор `Efen` проверяет видимость на каждом уровне и выдаёт предупреждения или ошибки,  
если попытка доступа нарушает правила. Например:

```efen
private module

public fn myFunction() {
    // Предупреждение: попытка сделать публичную функцию в приватном модуле
}
```

Только публичный модуль может содержать публичные определения,  
и при этом он должен находиться внутри публичного namespace, объявленного в главном модуле пакета.

## Централизованное управление видимостью

Видимость пакета и его пространств имён задаётся **только в главном модуле** пакета.  
Это упрощает анализ и делает структуру доступа предсказуемой.

Пример:
```efen
package MyPackage

visibility {

    public {
        namespace services/logging
        namespace services/authentication
    }

    public namespace api    
    internal namespace core
    public namespace services/logging    
    internal namespace utils
}
```

## Атрибуты видимости на уровне пакета

`Efen` поддерживает механизм атрибутов, задающих поведение и уровень доступа элементов.

```efen
package MyPackage

attributes {
    api: visibility(public), fastcall, dllexport
    internalApi: visibility(internal)
    ffi: abi(c), dllimport
}
```

Атрибуты определяются только в главном модуле пакета и могут применяться к любым сущностям:

```efen
api fn myApiFunction() {
    // доступно в модулях и пакетах, указанных в атрибуте видимости
}
```

Таким образом, `Efen` объединяет два подхода:
- **Локальное управление** (через теги `public`, `internal`, `private` в объявлениях);
- **Централизованное управление** (через декларации `visibility {}` и `attributes {}` в главном модуле пакета).

Такой подход сохраняет простоту и предсказуемость системы видимости даже в больших проектах.
