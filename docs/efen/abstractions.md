# Программируемые языковые абстракции

Часто языки программирования предоставляют фиксированный набор абстракций, которые жёстко вшиты в компилятор. 
Например, в `C++` есть классы, шаблоны и исключения. 
Программист не имеет возможности изменить поведение класса или механизм обработки исключений.

С другой стороны, есть языки программирования предоставляющие нулевой уровень абстракций или
стремящиеся к нему, однако ценой за это является сложность и низкая выразительность. Например работа с ARC-объектами
в `RUST` несёт дополнительную цену по сравнению с работой в Swift.

`Efen` разработан с целью предоставить программисту полный контроль над абстракциями языка, разделяя сам процесс программирования
на несколько уровней. Поэтому `Efen` можно назвать многоуровневым языком программирования.
Каждый уровень даёт власть над реализацией, скрывая детали от следующего уровня.
Можно сказать, что программа на `Efen` это многослойный проект, созданный на **едином** языке программирования
и вместе с тем декомпозируемый на несколько уровней абстракции, каждый из которых имеет свои правила и возможности.

Выделяются следующие уровни абстракции:
1. **Уровень этапа компиляции** - набор возможностей, которые позволяют управлять компилятором и его поведением.
2. **Низкий уровень представления** - структуры данных и код, которые обеспечивают работы самых базовых возможностей языка.
3. **Библиотечный уровень** - набор библиотек, которые предоставляют готовые решения для работы с данными и ресурсами.
4. **Бизнес уровень приложения** - высокоуровневый код, который решает конкретные задачи приложения, используя возможности предыдущих уровней.
5. **DSL уровень** - узкий набор возможностей под конкретную задачу.

```mermaid
тут диаграмма уровней от управления компилятором, управления низким уровнем представления,
и бизнес уровнем приложения
``` 

Этап компиляции представлен в виде мета-кода ([Аспекты](aspects/README.md)), а так же плагинов языка, которые могут расширять возможности компилятора 
и его поведение. Мета-код может быть использован как для генерации кода, так и проверки его корректности, оптимизации.
Низкий уровень представления реализуется как runtime-библиотека, поставляемая вместе с компилятором.
Она реализует такие возможности как раскрутку стека, ... (тут дописать).

[Контракты](contracts.md) выражают высший уровень абстракции и предназначены для создания правил, 
которые как правило проверяются на этапе компиляции.
