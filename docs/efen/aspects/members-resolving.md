# Разрешение компонента абстракции

Выражение типа `obj.field` будем называть *процессом разрешения компонента абстракции*.
Результатом выражения должен стать реальный код ассемблера.

Чтобы построить код, компилятор должен:
1. Знать что такое `obj` (его тип)
2. Уметь найти `field` относительно `obj`
3. Решить какой именно код должен быть генерирован.

Все этапы этого процесса могут быть определены программистом.

## Простая структура

Пусть есть структура данных `Point`:
```efen
struct Point {
    var x: Float
    var y: Float
}
```

Где выражения `p.x` и `p.y` должны быть разрешены компилятором как смещения относительно начала структуры `Point`.

В случае наследования структур, например:
```efen
struct ColoredPoint : Point {
    var color: Int
}
``` 

Структура `ColoredPoint` последовательно определяет поле `color` после полей `x` и `y` структуры Point.
Таким образом, код, который написан только для структуры Point, будет работать и для ColoredPoint.

Если методы для таких классов статические, и их адреса могут быть вычислены на этапе компиляции, 
то выражение `obj.method()` будет разрешено как прямой вызов функции по известному адресу.
К тому же эффекту приводит свойство `final` у методов класса.

## Сложные случаи

Все другие случаи разрешения компонентов предполагают процесс вычисления адресов в runtime.
Если `obj` является классом с динамическими методами, 
тогда `obj.method()` должен быть разрешен как поиск метода в виртуальной таблице методов.
Если класс может иметь свойства-методы, тогда перед обращением к свойством `obj.prop` нужно сперва проверить, 
есть ли геттер для свойства `prop`.

Программист может реализовать и более сложные алгоритмы, 
например, перед вызовом метода `method` вызвать другой метод `beforeMethod`.

`Efen` не имеет ограничений на то, как именно должен быть реализован процесс разрешения компонента абстракции, 
программист сам может найти баланс между гибкостью и производительностью.
