# Разрешение компонента абстракции

Выражения `obj.field` и `obj.method()` требуют разрешить компонент относительно
типа получателя и построить HIR, который реализует доступ или вызов. Физическая
форма результата определяется позднее выбранным backend; resolver не обязан и
не должен возвращать assembler.

## Стандартное разрешение

Для обычной структуры компилятор связывает поле с соответствующим местом:

```efen
struct Point {
    var x: Float
    var y: Float
}
```

Вызов final-метода может стать прямым вызовом известной функции. Динамический
метод класса может потребовать таблицу методов или другую форму dispatch,
выбранную определением класса. Эти различия не меняют исходную форму обращения.

## Пользовательский resolver

Аспект участвует в разрешении, реализуя контракт соответствующего вида доступа.
Для одной операции допускается один основной resolver. Несколько обычных
основных реализаций являются ошибкой компиляции.

Дополнительные аспекты могут участвовать через предусмотренные методы
`before...` и `after...`:

- `before` получает запрос разрешения и может предоставить результат вместо
  основного resolver;
- основной resolver, если он нужен, возвращает фрагмент HIR;
- `after` получает выбранный фрагмент и может его изменить.

Возвращённый HIR не обязан быть заранее типизированным. Компилятор обрабатывает
его вместе с окружающим телом: разрешает вложенные обращения, проверяет типы,
строит CFG, учитывает эффекты и выполняет анализ владения. Порождённый фрагмент
не получает права обойти обычные проверки языка.

Default resolver остаётся доступен как стандартная реализация конкретной
операции. Его вызов не означает, что пользовательские resolver-ы отключены во
всём порождённом поддереве: вложенное обращение может относиться к другому типу
со своей моделью разрешения.

## Открытые вопросы

- порядок нескольких `before` и `after`;
- прекращаются ли следующие `before`, когда один из них уже вернул результат;
- какие `after` выполняются, если основной resolver был пропущен;
- точная форма явного продолжения исходной операции через default resolver.

Resolver работает после фиксации структуры класса. Он может порождать локальный
HIR тела, но не добавляет новые члены и не открывает заново
`ClassDefinitionPlan`.
