# Метаданные в языке Efen

Язык **Efen** позволяет работать с метаданными.  
Метаданные — это данные, которые могут быть ассоциированы с любой сущностью Efen, 
будь то класс, структура, трейт, стратегия и т.д.

При желании программист может в любом месте программы извлечь эти метаданные и использовать их во время выполнения (runtime).

Различаются два вида метаданных:
- **Метаданные времени компиляции**
- **Метаданные времени выполнения**

Метаданные времени компиляции, по желанию, могут быть перенесены в метаданные времени выполнения.  
В таком случае эти данные попадут в исходный исполняемый файл.  
Это означает, что программисты могут управлять формированием метаданных, а также определять, какие именно метаданные будут включены в итоговый исполняемый файл.

## Формат значения

Metadata может содержать произвольную бинарную структуру. Расширение, которое
создаёт значение, определяет его типовой ключ, версию схемы, сериализацию и
проверку. Это позволяет хранить пользовательские структуры и расширять данные
HIR без добавления их смысла в ядро Amber.

Amber рассматривает payload как непрозрачный диапазон байтов. Он сохраняет,
копирует и хеширует диапазон вместе с владельцем и проверяет только целостность
контейнера. Неизвестный тип или версия metadata не мешают чтению и компиляции
HIR.

## API для управления метаданными

Язык Efen определяет иерархию объектов, которые он компилирует и анализирует.  
Эта иерархия начинается от **модуля**, продолжается через **классы**, **стратегии**, **структуры**, **трейты**, **определения**, **переменные** и т.д.,  
и может быть извлечена в любой момент.

Любые определения, переменные, включая определения типов, интерфейсы и прочие
элементы, доступны метакоду через типизированный compile-time API. API отдаёт
опубликованный либо рабочий HIR-view согласно стадии вызывающего кода; доступные
изменения ограничены правами этой стадии и контракта преобразования.

При помощи специальных функций можно указать, какие метаданные должны быть добавлены к определённым сущностям уже в исходный исполняемый файл.

Сам язык Efen предоставляет возможность сделать это при помощи **атрибутов**.  
Атрибуты — это специальные абстракции, которые позволяют добавлять метаданные к абстракциям языка.

Применение записывается перед целью:

```efen
@route("/users")
@cached
public fn users -> [User]
```

Исходное применение атрибута является неизменяемым фактом исходной программы.
Amber сохраняет его в compile-time продукте: выполнение атрибута не потребляет и
не удаляет запись. Сам атрибут является обычным метакодом над помеченной целью.
Он может добавить metadata или породить и изменить HIR в пределах тех же прав,
стадий и проверок, что соответствующая метафункция.

Несколько атрибутов выполняются сверху вниз, в порядке записи. Если два
атрибута добавляют к одной цели metadata с одним типовым ключом, это конфликт,
как две записи одного свойства. Множественное значение выражается одним
metadata-значением коллекционного типа, а не повторением ключа.

Атрибут может изменить сигнатуру до её публикации. Такое преобразование заранее
объявляет право изменять сигнатуру; итоговая сигнатура входит в публичный
fingerprint и видна потребителям. После публикации она неизменяема.
Порождённый HIR проходит обычные проверки типов, управления потоком, эффектов,
владения и инициализации. Некорректный результат является ошибкой компиляции с
origin, указывающим на применение атрибута; отдельной ослабленной семантики для
generated-кода нет.
