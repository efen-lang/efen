# Аспекты

Аспекты — это инструмент метапрограммирования, 
который позволяет программисту описывать свойства абстракций на этапе компиляции.

**Возможности аспектов:**

 * Аспекты могут быть применены к классам, интерфейсам, стратегиям и другим аспектам.
 * Аспекты могут требовать от кода реализации определённых методов и свойств.
 * Аспекты могут требовать от кода реализации контрактов или интерфейсов.
 * Аспекты могут добавлять приватные вспомогательные методы. Изменение остальной
   поверхности целевого кода требует права, предоставленного явным контрактом.
 * Аспекты могут добавлять к целевому коду контракты и интерфейсы, если право на
   такое изменение входит в применённый контракт.
 * Аспекты могут изменять поведение компилятора при разрешении компонентов абстракции.
 * Аспекты могут работать как шаблоны для генерации кода.
 * Аспекты имеют полный доступ к этапу компиляции целевого кода.
 * Аспекты могут взаимодействовать с других аспектов на этапе компиляции, производя вычисления.
 * Аспекты могут управлять метаданными целевого кода. Добавлять или изменять атрибуты.
 * Аспекты могут подмешивать поведение в целевой код.

## Синтаксис

```efen
aspect AspectName
{
    meta {
        // Метаданные аспекта
        // Например, атрибуты, описание и т.д.
        // А так же код времени компиляции
        strategy for Class {
            fn addMethod {
                // Алгоритм добавление нового метода к классу
            }
        }
    }

    // Aspect can be
    applied for classes, interfaces, strategies, aspects;

    // Requirements
    
    required aspect AnotherAspect
    required contract ContractName
    required interface InterfaceName
    required property PropertyName: PropertyType
    optional method MethodName(Param1: Type1, Param2: Type2) -> ReturnType
    
    // Mixins
    property NewProperty: PropertyType = InitialValue
    
    method NewMethod(Param: Type) -> ReturnType {
        // Implementation
    }    
}
```

`required method` является обязательным требованием: аспект нельзя применить к
типу без подходящего метода. `optional method` объявляет необязательную точку
расширения, которую аспект использует только при её наличии. Обе формы являются
частью языка и не заменяют друг друга.

По умолчанию аспект изменяет только тип, указанный как его цель применения.
Видимость аспекта не даёт права изменять остальные объявления модуля.
Возможное исключение для чужого класса требует явного разрешения аспекта,
принадлежащего целевому классу; точный протокол такого разрешения пока не
определён.

Само наличие метода `ClassBuilder` не предоставляет право выполнить операцию.
Без разрешающего контракта аспект может физически добавить только приватный
метод. Неприватный метод и другое изменение поверхности требуют явного
контракта. [Стратегия](../strategies.md) предоставляет публичное поведение
отдельным механизмом разрешения и не добавляет свой метод в физический список
членов класса.

Применение аспекта:

```efen
class MyClass {
    use AspectName;
    // Class implementation
}
```

Пример generic аспекта:

```efen
aspect Queue<Item> {
    array items: Item[] = [];
    required method enqueue(item: Item);
    required method dequeue -> Item;
}

class IntQueue {
    use Queue<Int>;
    
    method enqueue(item: Int) {
        items.push(item);
    }
    
    method dequeue -> Int {
        return items.pop();
    }
}
```

Это генерик с мономорфизацией.
Аспект `Queue` определяет обобщённую очередь для элементов типа `Item`, а 
класс `IntQueue` реализует очередь для целых чисел, используя аспект `Queue<Int>`.

## Совместимость с аспектами

Часто бывает так, что аспекту нужно чётко обозначить, с какими другими аспектами его можно или не можно
смешивать. Это важно, так как аспект может определять базовую структуру данных или интерфейс либо 
сама логика аспекта глубоко не совместима.

Для этого используются конструкции: `compatibility` `incompatibility`.

```efen
aspect AspectName {
    compatibility Module::*
    compatibility AspectName
    incompatibility Module::*
    incompatibility AspectName
    compatibility by ContractName
    incompatibility by ContractName
    compatibility by LayerName
    incompatibility by LayerName
}
```

Конструкция позволяет задавать правило совместимости аспекта по:
* по модулю или пакету. Разрешено смешивать аспект с другими аспектами только из этого модуля
* явно по имени аспекта
* только те аспекты, которые реализуют контракт
* только те аспекты, которые находятся в слое

Независимо от этих правил язык допускает ровно один аспект с контрактом
`ClassDefinition` на корне иерархии. Явный аспект имеет приоритет над
реализацией по умолчанию из `provide`, а производный класс не может заменить
определение корня. Полная модель описана в
[построении класса](compile-time/class.md).
