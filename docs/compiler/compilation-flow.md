# Алгоритм порядка компиляции

В отличие от классических компиляторов, где компилятор обрабатывает код независимо по отдельным файлам, 
`Phx` необходимо уметь компилировать код частями в определённом порядке.
Это связано с тем, что `Phx` выполняет часть кода на этапе компиляции.
Из-за этого ему приходиться компилировать только некоторые функции в первую очередь, 
а другие функции компилировать позже, когда все зависимости уже будут доступны.

Поэтому минимальной целью компиляции в `Phx` является не файл, а функция.
Такая логика характерна для JIT-компиляторов, которые компилируют код по мере необходимости.
`Phx` именно так и работает, он рассматривает код проекта как потенциальный JIT-код,
который может быть скомпилирован в любой момент времени.

## CompilationPlan

Представляет Copy-On-Write коллекцию этапов компиляции, которые необходимо выполнить
со списком обработчиков для каждого этапа.
Обычное такие этапы являются общими для всех задач компиляции в рамках одного процесса компиляции,
например: лексический анализ, синтаксический анализ, семантический анализ, оптимизация, генерация кода и т.д.

`CompilationTask` хранит ссылку на `CompilationPlan`,
и запускает этапы компиляции в том порядке, в котором они определены в `CompilationPlan`.
`CompilationTask` позволяет изменять `CompilationPlan` во время выполнения,
добавляя или удаляя этапы компиляции по мере необходимости, но в этом случае
он клонирует `CompilationPlan`, чтобы избежать влияния на другие задачи компиляции.

## CompilationTask

Класс `CompilationTask` отвечает за процесс компиляции отдельного узла.
Он принимает на вход 
 * AST-узел, 
 * Контекст компиляции,
 * `CompilationPlan`
 * Обработчики этапов компиляции (`CompilationStageHandlers`),

AST-узлом может быть как весь модуль, класс, аспект, интерфейс, структура данных, функция или даже блок кода.

`CompilationTask` изменяет состояние AST-узла, отмечая его как скомпилированный, 
ожидающий зависимости или требующий повторной компиляции.
`CompilationTask` так же может изменять элементы `TranslationUnit`, отмечая сущности как скомпилированные 
или требующие разрешения зависимостей.

Результатом работы `CompilationTask` является `IR`-код, который может быть использован как для создания объектного кода, 
так и для выполнения `JIT`-компиляции.

`CompilationTask` может остановить работу на любом этапе по нескольким причинам:
 * Ошибки компиляции
 * Отсутствие зависимостей

`CompilationTask` различает два этапа компиляции:
 * Мета-компиляция (meta-compilation) - запускает код compile-time
 * Основная компиляция (main compilation) - компилирует основной код

## Компилятор

Главный модуль компилятора является оркестровщиком, который управляет задачами компиляции.
Он принимает на вход `CompilationPlan`, `ProjectManager` и `VFS`.

Компилятор создаёт задачи компиляции по мере необходимости и распределяет их выполнение
между доступными потоками (пока игнорируется).

Компилятор так же отслеживает циклические ссылки между зависимостями, возобновляет задачи компиляции,
если они ожидают зависимости, и собирает результаты компиляции.

Компилятор умеет правильно упорядочить задачи компиляции, чтобы гарантировать,
что все зависимости будут разрешены. Часть функций модуля может быть никогда не скомпилирована,
если они не используются в коде или не требуются для выполнения compile-time кода.

Компилятор может выполнять задачи типа `meta-compilation` и `main compilation` в любом порядке,
но гарантирует, что все задачи `meta-compilation` будут выполнены до начала задач `main compilation`.

Например, для модуля `A`, который зависит от модуля `B`, 
компилятор 
1. сначала выполнит задачи `meta-compilation` для модуля `B` (если они требуются), 
2. затем задачи `meta-compilation` для модуля `A`, 
3. затем задачи `main compilation` для модуля `B`, 
4. и наконец задачи `main compilation` для модуля `A`.

## Взаимодействие с менеджером проекта

Компилятор взаимодействует с менеджером проекта для получения информации о структуре проекта,
поиска точек входа и доступа к исходным файлам через VFS.

Когда компилятор сталкивается с зависимостью, он запрашивает менеджера проекта
для получения соответствующего модуля или файла. Менеджер проекта возвращает модуль или файл,
который компилятор затем обрабатывает.

Компилятор так же обладает возможностью запрашивать не только модули, но и отдельные функции или абстракции,
если менеджер проекта поддерживает такую функциональность.
Это может быть полезно для JIT-компиляции, когда требуется скомпилировать код в режиме sandbox.
На вход подаётся блок кода, а менеджер проекта предоставляет необходимые зависимости
или нет.

Режим sandbox используется для выполнения compile-time кода в изолированной среде,
где компилятор может безопасно выполнять код без риска повлиять на оперативную среду.
