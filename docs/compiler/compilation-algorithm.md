# Алгоритм компиляции PHX

## Обзор

Компилятор работает в несколько фаз, обрабатывая модули в порядке их зависимостей:
1. Препроцессинг. Построение AST, формирование графа зависимостей, построение общей БД идентификаторов
2. Компиляция и выполнение compile-time кода
3. Предварительная компиляция (завершающий семантический анализ, вычисление типов, borrow checking, вывод ошибок)
4. Основная компиляция (семантический анализ, генерация MLIR, IR)
5. Кодогенерация (LLVM IR, объектный код, линковка)

Процессом компиляции управляет **менеджер проекта**, который:
1. Понимает структуру проекта
2. Находит точку входа
3. Предоставляет VFS с доступом к исходным файлам

Менеджер проекта представляет собой независимый от компилятора модуль, 
который можно заменить для поддержки различных структур проектов (монорепо, микросервисы, пакеты, библиотеки).

Для удобства работы, в компилятор встроен менеджер проекта по умолчанию,
который поддерживает проекты с точками входа `main.phx` (исполняемый файл) и `lib.phx` (библиотека).

Однако, компилятор можно использовать и без менеджера проекта,
предоставляя ему VFS с корнем проекта и точку входа вручную.

Программист может указать компилятору кастомный менеджер проекта,
реализующий интерфейс `ProjectManager`, для поддержки своей структуры проекта.

## Препроцессинг

На этой фазе компилятор:
1. Строит AST дерево
2. Проводит первичный синтаксический анализ:
   1. Определяет список зависимостей
   2. Строит общую БД идентификаторов (глобальную таблицу символов) (опционально)
   3. Отмечает абстракции, требующие компиляции для compile-time

Какие абстракции попадают под внимание компилятора на этой фазе:
- пакеты
- модули
- классы, интерфейсы, структуры, контракты, функции, аспекты, стратегии и другие абстракции первого уровня
- глобальные константы и иммутабельные переменные
- алиасы типов
- use/include директивы
- декораторы (атрибуты)
- диалекты

Компилятор пытается найти среди этих абстракций те, которые имплементируют интерфейс или контракт
времени компиляции (compile-time). Такие абстракции помечаются как compile-time и компилируются на следующей фазе, 
после того как зависимости будут разрешены.
Если у этих абстракций есть вложенные абстракции, они помечаются как связанные с compile-time,
так как их вид может быть изменён compile-time кодом.

Если не все зависимости были разрешены, компилятор отмечает модуль как ожидающий зависимости (pending dependencies).

> Обратите внимание, что публичные функции контракта, а именно их имена
> не могут быть переопределены compile-time кодом, а код интерфейса может!

## Компиляция и выполнение compile-time кода

Если на предыдущей фазе были найдены абстракции compile-time, и не было ошибок,
компилятор переходит к их компиляции и выполнению.
На этом этапе код compile-time компилируется и выполняется,
изменяя состояние компилятора (глобальная БД идентификаторов, граф зависимостей, AST и т.д.).
compile-time код не может создавать другой compile-time код.
